# UILib 动态虚拟列表首版目标与能力提案

状态：规划稿。用户已选择“UILib 自身的新能力”的单仓方向；本文提出的列表语义与公共扩展尚未作为正式合同确认。

## 1. 用户目标与交付范围

业务作者声明完整条目数据、稳定业务键、展示文字和选择/确认动作，UILib 提供可滚动、可搜索筛选接入、可键盘操作的长列表。行视图按当前视口建立，业务不用维护可见索引、占位节点、行坐标或手动刷新布局。

首版服务档案浏览、材料候选和记录选择等“浏览—单选—确认”流程。交付公开控件、正式使用场景及同内容普通列表对照。场景以本地业务模型表达完整操作，不依赖 Architect、Miner 或网络服务，也不把示例称为下游 Mod 已接入。

首版展示行由标准文字与普通纵向布局组成，支持标题、说明及自然换行高度；列表整体是一个焦点目标。搜索、筛选、排序、选中值和最终业务动作归页面。行内编辑、多选、拖拽、交互子控件、图像异步尺寸和虚拟网格是独立扩展专题，不在本次首版交付中。

沿[核心职责规格](<2026-10-07-uilib-core-contract-design.md>)、[布局规格](<2026-10-13-uilib-layout-spec.md>)、[动态结构规格](<uilib-dynamic-structure-spec.md>)与[页面接入规格](<2026-10-07-uilib-page-host-spec.md>)组织实现。虚拟化是本模块新增的能力，不能直接把普通 repeat 的数据退出、折叠或裁剪解释为离开视口。

## 2. 责任与身份

| 主体 | 决定或提供的事实 |
| --- | --- |
| 业务/页面 | 条目数据、稳定键、搜索筛选排序、当前选择及最终业务动作 |
| 列表控件 | 展示文字、行高索引、按需行视图、内部选择导航与虚拟化高度校正 |
| 唯一运行时 | 声明结算、视口相关行建立/释放、正式滚动偏移及输入资格 |
| 布局与呈现管线 | 本批测量、排列、完整内容范围、共同几何与 PaintPlan |
| 宿主 | 实际可用空间、字体资源代际、真实输入与呈现 |

声明区分条目序列与各条目的可追踪当前值，局部值变化无需重发完整序列；来源仍由业务拥有。业务键标识列表内的逻辑条目，节点 UUID 标识当前行视图，两者不同。数据仍在列表中而行视图离开实例化范围时，逻辑条目和业务选择仍可存在；行视图及所属资源释放。再次进入时建立新视图和新 UUID，不恢复旧按压或输入联系。在持续实例化范围内保留的同键行，数据变化与重排更新当前数据并延续该行视图。

同一列表拒绝重复键、null 键和 null 条目；null 选择表示未选中。过滤后不可见或真实删除的选择如何处理由业务决定；控件只对当前集合中的有效选择执行确认，没有目标时不激活任意邻行。首版行视图没有独立草稿、焦点和交互子控件，因此不新增编辑状态迁移或离屏焦点保留政策。

## 3. 内容高度与按需行视图

### 3.1 已测量高度与估算高度

行的最终自然高度取自当前宽度、文字、主题和字体下的正式测量。尚未测量或尺寸依赖已失效的行使用显式、可动态更新的正估算高度；估算仅用于定位候选范围和表达暂时的完整滚动范围，不作为可见行的真实排版结果。

列表在后续输入路由与最终绘制前，实例化候选行，使用正式测量校正高度索引，并由框架结算需要的视口范围变化。最终可见行使用已测量高度，绘制、裁剪与指针命中消费同一有效几何。不能将只有估算位置的行作为有效点击对象，也不能在 paint/measure/arrange 中创建或销毁控件。

完整滚动范围在未测量行仍存在时允许按估算变化；首版不承诺打开时已得到全部自然高度。最后一个逻辑条目可通过正常滚动或 End 到达；末尾校正后没有幽灵空白或需要先耗尽额外滚轮积累的区域。不得把估算总高包装成精确总高。

### 3.2 校正时的视口连续性

本模块明确新增虚拟化高度校正的锚定：以当前视口中的首个实际可见条目键及其行内偏移维持位置，仅抵消“估算被真实测量替换”造成的跳动。用户滚轮意图先于校正保留；不能因高度校正追随业务选择或夺取焦点。

若视口处在逻辑末尾，校正维持最后一项的末端可达状态，再按新范围限制偏移。纯数据增删、筛选、重排和普通内容变化沿既有范围限制行为，不自动增加通用滚动锚定；主动键盘导航只最小显露目标条目。锚点已真实删除时，以当前有效范围限制位置，不选择替代业务条目。

高度索引与可见范围需要在相同数据/环境条件下收敛。校正循环没有新尺寸事实却重复切换同一范围时，给出列表及条目上下文并走既有错误通道；不能发布不一致几何、悄悄改成全量挂载或吞掉错误。

### 3.3 工作量与生命周期

实例化范围由实际视口及有限的前后预取距离决定。滚动离开该范围的行视图销毁，重复进入不累加节点、绑定或行作用域。已测量的标量高度可以按当前逻辑条目保留，不保留离屏 SceneNode、TextLayout 或当批子测量服务。

条目元数据及高度索引的容量以当前逻辑集合为界；结构变动允许整理索引。稳定滚动不逐帧遍历全部条目重建文字或节点；局部变化使相关高度失效。来源若发布整份新列表，匹配与校验可以扫描这份列表，须与真实行测量、挂载工作分开统计。

列表默认填充父级分配的有限视口并纵向滚动，不以全部内容的自然高度撑开父级。视口、预取距离、行间距和估算高度都可变化，不能绑定构造期窗口或字号。索引计算使用可检查的整数范围，超过当前 scene 可表达范围时给出可定位诊断，不以溢出、截断或缩小内容掩盖。

## 4. 输入与选择

列表整体参与既有 Tab/Shift+Tab 顺序，展示行不建立第二套焦点目标。正式主键完整点击按当前共同几何选择条目；按下后条目退出实例化范围或真实删除，释放尾部不能选中后来占据旧位置的行。仅同键数据更新的有效操作使用当前业务数据。

列表持焦点时 Up/Down 按当前逻辑顺序选择相邻条目，Home/End 选择首末条目；无有效选择时正向取首项、反向取末项。主动导航最小显露目标，超高目标行优先显示起始边缘。Enter 确认当前有效选择。Space 在没有有效选择时选择首项，已有有效选择时仅消费事件，不重复确认或发布相同选择。Tab 离开列表，ESC 沿既有页面策略，不另建键盘消费者。

数据、窗口、主题变化和普通用户滚动不反复追随选择。初次进入列表焦点也不强制滚动到外部选择。搜索框继续是正式编辑控件，只有当前焦点接收文字；列表不接收组字或普通文字编辑。

回调发布业务选择或动作，由业务决定权威值和效果。测量、排列与高度校正不写业务选择，不执行确认回调。页面关闭释放 UI 所属资源，不销毁外部数据、选择状态或共享字体服务。

## 5. 动态失效与错误

当前条目展示文字变化、可用宽度、字号、字体资源、语言所生成的文字、主题尺寸、行间距和估算策略变化，按实际依赖使对应索引与呈现失效。纯颜色或选择高亮变化只更新绘制；同语言资源重载不能仅因语言码相同继续使用旧高度。

文字提取是基于条目当前值的纯函数，不加载字体或构造节点。首版不允许在提取函数里隐藏外部尺寸依赖；业务将翻译后的当前文字或明确的内容变化发布到条目来源。宽度及字体/主题尺寸代际失效后，离屏行在重新进入时使用当前事实，不需要重开页面。

重复键、非法策略、非法尺寸、文字提取或控件建立失败沿既有可定位诊断及生命周期清理处理。本能力不新增自动重试、旧画面保留或回滚政策。

## 6. 正式使用场景

统一功能广场增加“档案选择”场景：输入查询、切换分类、浏览标题和多行说明、单选条目、确认打开详情，并能发布新增、修改、删除和排序变化。空结果给出清晰状态且不确认；确认使用当前数据，不捕获旧对象。页面外部详情可以使用既有标准控件，行内保持首版只读展示。

场景同时提供主题/字号变化与窄窗口检查，体现重新可见行使用新条件。一次人工验收只安排短小的“查找并确认”“离屏更新并滚回”“末尾删除再反向滚动”操作。该场景验证公开接入方式，性能计数留在专用压测页，不进入产品操作流。

## 7. 有限验收

| 场景 | 可观察结果 |
| --- | --- |
| 相同视口与行内容下扩大逻辑集合 | 挂载的昂贵行视图由视口及预取范围决定，元数据规模单列 |
| 无变化稳定呈现 | 不重复建立行、接绑定或使有效行高度失效 |
| 长短混合自然行高及超高单行 | 可见行按真实高度排列，部分裁剪与命中一致 |
| 更新视口外标题/说明，再滚回 | 当前内容和当前自然高度生效，操作使用当前数据 |
| 同键更新、重排、筛选和真实删除 | 同键持续视图延续，离屏视图释放，业务选择不按位置转移 |
| 按下甲、使甲离开或删除、让乙占旧位置、释放 | 不选中乙；下一次完整点击乙才选择乙 |
| 键盘到未实例化目标、Home/End、Tab 离开 | 全部逻辑条目可达，必要滚动发生，列表不能困住焦点 |
| 估算显著偏高/偏低、接近末尾、往返滚动 | 校正锚点稳定，末端可达，反向滚动立即响应 |
| 宽度、字号、主题尺寸及同语言资源重载 | 可见行及时更新，离屏行返回时无旧高度 |
| 纯选择/颜色变化 | 仅更新需要的绘制，不把选择变成重新测量来源 |
| 页面切出、重挂、停止和关闭 | 卸载释放挂载订阅；调用方明确保留的逻辑树沿核心合同保留，重挂读取当前来源；页面销毁释放全部所属行视图，外部业务数据仍可使用 |
| 重复键、null 键、非法策略与尺寸不收敛 | 报出列表/键/依赖上下文，完成必要清理，不产出伪成功 |

反馈复用正式 session、真实字体、软件 replay、正式物理 down/up/scroll 以及 Desktop 输入。新增自动场景只保护本能力和实际受影响回归，不读内部字段作完成判据，不为测试增加生产接缝。

## 8. 性能与交付判据

新能力用独立成对负载比较“普通完整列表”与“虚拟列表”，两者使用同一逻辑条目、标题/说明、自然行高、主题、视口、数据更新序列及业务选择结果。既有压测广场的六项负载保留原内容与动作，不把删除行内按钮或改成固定行高后的结果与旧基线直接配对。

核心和 Desktop 各自验收 IDLE、SCROLL、UPDATE 与宽度重排。规模沿现有 200 和 1000；1000 的普通/虚拟模式各至少两轮，预热和采样沿[性能压测规格](<2026-10-14-uilib-performance-testing-spec.md>)。主目标为 SCROLL 与 UPDATE，修改后 p95 重复范围上界低于普通模式下界，方可声称本负载的明确时间收益。区间重叠则报告未证明收益并定位受影响组合，不改动作或降低行为门槛。

同时记录实际逻辑量、实例化量、可见量、行构造/释放、测量/排列及高度校正轮次；首次进入、首次访问未测量区域、全局尺寸失效和元数据匹配单列。稳态收益不能靠把全量昂贵工作藏到首次打开或重复滚回阶段取得。所有统计从原始样本经保留代码计算。

正式 core 制品公开调用、行为回归、同内容处理量和时间收益、完整 build 及独立审查通过后才作为功能增量交付。MC 实机另按明确授权执行，Desktop 结果不外推 MC。

## 9. 后续顺序

首版交付后，以实际使用需要选择“行内交互/编辑”“可变媒体尺寸”或下游页面接入，不把本期扩成完整增量布局和全客户端迁移。对外依赖坐标、兼容区间、发布和跨仓迁移单独按用户授权处理。
