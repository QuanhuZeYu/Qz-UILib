# UILib 虚拟集合候选专题

状态：候选技术专题。[真实应用案例目标](<2026-10-14-uilib-modern-app-cases-spec.md>)是当前新能力规划入口。此前“只读标题/说明、单焦点、单选确认”的首版设想已经被真实案例方向替代，不作为待执行公共合同。

## 1. 定位

虚拟化支撑收件箱、内容浏览等真实页面，目标是让昂贵节点、挂载绑定、测量与呈现围绕可见内容发生，同时保留全部业务条目的可达性。业务提供完整数据、稳定身份及 UI 声明，不计算可见范围或维护占位节点。

采用[核心职责](<2026-10-07-uilib-core-contract-design.md>)、[动态结构](<uilib-dynamic-structure-spec.md>)与[布局](<2026-10-13-uilib-layout-spec.md>)合同。普通 repeat 的数据退出、折叠和裁剪不能直接当成虚拟化的离屏语义。

## 2. 必须由案例回答的行为

| 触发情景 | 能力设计需要明确的结果 |
| --- | --- |
| 行内复选、星标、主体阅读及独立菜单 | 维持各自操作与合法焦点，不强制把交互行变为单一 listbox |
| 条目离开视口、回来或真实删除 | 区分业务数据、逻辑条目、节点视图与挂载代际；独立业务状态去留由业务决定 |
| 未测量自然行高、宽度/字体变化、到达末尾 | 明确完整范围是否估算、何时校正及可见几何如何闭合，不伪称精确总高 |
| 高度校正或数据重排 | 分别决定是否需要锚定及其作用范围；不隐含新增追焦点或恢复政策 |
| Tab 或主动导航到未实例化的条目动作 | 明确可达顺序与显露，不把未挂载控件静默从用户流程删去 |
| 目标失活、行视图更换和物理输入尾部 | 旧手势不能激活后来占据相同位置的对象 |
| 局部变化、整份列表发布与全局资源变化 | 分开统计匹配/索引和昂贵行工作，依赖可失效且资源可释放 |

这里列的是专项设计的输入；估算/校正锚定、公共工厂形状和视口结算扩展不因旧提案存在而自动确定。选定具体机制后形成有限能力合同及实施计划，再进入生产实现。

## 3. 机制选择与验收

先完成代表性案例的操作参照，再从实际挂载量、可见量、测量/排列、输入、绘制及宿主成本选择改进。若行内控件是使用流程的一部分，对照必须保留它们；不能通过固定行高、删除按钮/图片或缩短文案制造收益。

高度索引及按需实例化是候选机制。仅当它们服务已观察到的成本与明确规模需要时实施；稳定帧、首次进入、首次访问新区域、宽度/资源失效和反复往返分别报告。比例与区间从原始数据经代码重算。

行为与处理量、同宿主时间收益、完整 build、独立审查及实际释放通过后交付。公开 API 不冻结为 RowText 或指定列表焦点模式；实现复用自有 scene、Signal、Owner、正式控件、共同几何和 PaintPlan。
