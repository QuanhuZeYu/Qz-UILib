# UILib 字体渲染器规格

状态：正式模块规格。共同平台与资源边界遵循[核心规格](<2026-10-07-uilib-core-contract-design.md>)。

## 1. 目标与边界

UILib 是现代字体引擎：文本样式表达字族、字重和字姿等排版意图，字体匹配选择实际 face，整形、度量和光栅共同使用选择结果。Minecraft 适配仅解释调用与格式语义，不将原版位图字体的增粗、倾斜或宽度补偿算法作为核心样式模型。

业务提交文本、样式和空间约束，UILib 自行负责字体选择、整形、度量、光栅及 GL 回放。正式路径不调用原版 FontRenderer 测量或绘制，并提供可接管原版字体调用的 MC 适配入口。

坐标与平台遵循[核心规格第 9 节](<2026-10-07-uilib-core-contract-design.md>)，内容模式与共同几何遵循[文本规格第 1.1—1.2 节](<2026-10-07-uilib-text-content-spec.md>)。

默认字体资源包含 Minecraft 使用的开源 Unifont，并补齐复杂脚本和彩色 emoji；允许配置系统字体。默认有效优先级列表能覆盖本规格内容，基础显示不要求用户安装字体。数学能力遵循[文本规格第 1.4 节](<2026-10-07-uilib-text-content-spec.md#14-数学排版职责>)。具名数学字体提供 OpenType MATH 常量和真实伸缩字形，按当前来源、字号及资源代际复用同一整形/光栅与字形缓存；其候选链单独声明，不覆盖普通文字默认链。字体与原许可证随包，不依赖用户系统安装商业数学字体。

LWJGL2/LWJGL3 宿主共享排版、格式语义与需求缓存，native 整形/光栅绑定及 GPU 操作归适配。纯 Forge 1.7.10 及 LWJGL3ify/Angelica 兼容、无平台核心和各宿主独立取证，统一按核心第 9 节验收。

## 2. 已裁定显示合同

### 2.1 控制字符

| 字符 | 效果 |
| --- | --- |
| LF、CRLF、独立 CR | 换行；CRLF 合为一次换行 |
| Tab | 到下一制表位，间距由样式声明 |
| Bidi 标记、嵌入、覆盖、隔离及结束符 | 按 Unicode 双向算法处理，自身不画字形 |
| ZWJ、ZWNJ、VS | 影响连接/字形选择，自身不画独立字形 |
| 零宽空格、Word Joiner、软连字符 | 允许断行、阻止断行、仅采用该断点时显示连字符 |
| BS、ESC 及其他无显示语义的 C0/C1 | 显示可辨识控制符标记并诊断，不执行终端/宿主动作 |

§ 格式码只在 Minecraft 宿主转换边界解释，UILib 不提供 Minecraft 内容模式。宿主转换产生中性内容样式，普通文本、富文本 DSL 和 Markdown 不猜测模式。

### 2.2 输入与文字整形

- 正式接受 UTF-8 字节及 Java 字符串。无效 UTF-8 按 Unicode maximal subpart 替代为 U+FFFD；不成对 UTF-16 代理项同样替代。诊断能定位原输入范围，后续有效文本继续显示；不改业务原文。
- 支持中文、拉丁、阿拉伯、希伯来双向混排及泰文；印度脚本覆盖天城文、孟加拉文、古尔穆基文、古吉拉特文、奥里亚文、泰米尔文、泰卢固文、卡纳达文、马拉雅拉姆文与僧伽罗文。
- 真实整形处理上下文连接、标记定位、重排、连字和字距；不能逐码点摆放。段落方向可声明 auto/LTR/RTL，语言可声明并继承主题。泰文采用语言断行。
- 源文保持逻辑顺序，布局保存视觉位置到源文范围的关系；不拆代理对、字素簇或 emoji 序列。阿拉伯文按最终行边界重新整形。

### 2.3 emoji

采用 Unicode 默认呈现；默认 emoji 用彩色，默认文本呈现用文字字形；VS15/VS16 显式选择。默认包覆盖选定 Unicode/Emoji 版本的完整 RGI 集，包括肤色、旗帜、键帽和 ZWJ 序列。Emoji 数据锁定正式 17.0 属性、标准变体、RGI 普通及 ZWJ 序列；随包来源为 NotoColorEmoji v2.051 与固定单色 NotoEmoji 资源。一般 Unicode 算法采用 ICU76.1 的 Unicode16 数据，不将 Emoji 数据版本等同于全部 UAX 版本。更新通过资源换代生效。

彩色字形保留原色，文本颜色不染色；整体透明度和裁剪生效。非 RGI 序列按实际整形能力显示。受支持序列缺失属于覆盖缺陷，不能拆成独立符号冒充成功。

### 2.4 字体优先级

配置一份有序候选列表；内置字体和系统字体都是同等候选。按顺序尝试，选择第一个能够正确生成目标文本的字体；不区分主字体、备用字体，不另加隐藏兜底链。未声明列表的文本继承主题列表，文本可显式指定自身列表；不同列表的结果互不污染。

普通独立字符逐字符匹配；组合标记、连写脚本和 emoji 按保证正确整形的最小完整范围匹配，尝试顺序仍是同一列表。“能够生成”包括正确呈现所要求的脚本连接或彩色序列，不能仅以 cmap 有码点认定成功。

匹配在整形/度量时确定实际 face；光栅复用该结果。列表和资源不变时复用匹配缓存，不为每次绘制重走全部候选。列表调整、字体增删与重载使相关缓存失效并自动更新。

列表中的缺失/损坏字体由资源入口诊断，不参与有效匹配。存在有效候选但目标文字均无法显示时，沿缺字合同使用所属候选中的稳定替代并诊断，保留原文；这是未匹配结果，不追加新的候选字体或错误恢复策略。显式空列表或全部来源无效属于无可用字体，须准确报告该资源边界，不能承诺从不存在的字体生成替代字形，也不追加隐藏来源；错误传递通道由正式资源接口设计。候选内的字族与样式匹配按第 2.8 节执行；它不改变这里的跨候选顺序。

**配置接入：** 字体模块通过[无平台配置核心](<2026-10-11-uilib-config-spec.md>)声明完整候选列表；内置来源身份与系统文件路径在同一列表中排序，显式空列表不追加来源。MC 调用核心配置会话，旧 `systemFontFiles` 的一次迁移按配置规格执行；格式、重载与来源解析机制从所属配置和源码入口核对，不再将旧前缀视为完整列表合同。

### 2.5 字号与行高

字号指定 em 像素尺寸；默认行高覆盖本行实际字体 ascent/descent 及行距，包括回退文字和 emoji。显式行高按声明布局，超出部分遵循溢出/裁剪声明。字形可见墨迹高度不等于字号，不偷偷缩小回退字体。

### 2.6 GPU 等待

未就绪字形暂留空白，保留真实 advance、基线和行高；缓存已就绪则直接显示。上传完成只通知相关绘制失效，不重新换行、不要求业务刷新。没有临时轮廓或等待字形的额外渲染路径。全部缺字的稳定替代结果与 GPU 等待状态区分。

### 2.7 性能

等价中英场景，热缓存每帧文本 CPU、GPU 耗时的 p95 各自不超过原版的 1.25 倍；原版该项低于 0.20 ms 时，绝对增量不超过 0.05 ms。整体帧时间 p95/p99 增量各不超过 1 ms。门槛已获裁定，是否达到由实测决定。

同实例、机器、framebuffer、像素字号、可见字量与裁剪条件比较静态热缓存、首次大量新字形、滚动和切字体。报告文本 CPU/GPU、整体帧分位数、内存、生成量与上传量；复杂脚本/emoji 另列，不削减功能制造等价比较。字体载入和整形同样计入观测，GPU 查询异步收集。

字形等待时限先实测后提出，报告首屏最后字形就绪、滚动新行等待及主线程慢帧；基准表写明输入规模。当前可见需求优先，不被预取长期阻塞。需求超预算时报告资源不足并维持空白，不无限增长或反复淘汰当前可见资源。

### 2.8 字族、字重、字姿与实际 face

字体样式合同适用于 scene、原版替代及其他正式文本入口。粗体、斜体是字体选择请求；下划线、删除线、颜色、阴影和混淆分别属于装饰或呈现，不代替字体样式选择。

**样式声明与候选解析。** 文本可声明字族候选、字重和字姿。字重表达轻重程度，不以合成偏移量表达；字姿区分正常、italic 与 oblique，不将所有非正常字姿等同于统一剪切。常规与粗体采用常见的 normal/bold 字重语义，原版 §l 映射为 bold，§o 映射为 italic，二者组合请求 bold italic。§r 及颜色码的样式重置由 Minecraft 宿主转换边界解释，不改变 UILib 内容模式。

来源标识与字族成员分开：配置文件路径、TTC 内 face 索引、系统 family 名称均须解析为实际字体身份及元数据。一个候选可以表达字族及其可用成员，也可以明确限定一个 face；不能把 TTC 的某个索引猜作粗体，也不能把文件名或显示名称当作样式元数据。显式限定单个 face 时尊重其边界，不能静默扫描并追加其他系统字体。字族声明如何关联文件、集合内成员或系统字体由正式来源接口设计确定，来源解析可按需枚举并缓存，普通帧不重新扫描。

**匹配主流程。** 沿第 2.4 节的有序候选逐项尝试。在当前候选内，先按请求字姿和字重解析真实样式成员，再核验目标完整范围的字符覆盖、脚本整形及呈现能力。请求样式无法覆盖时，可继续检查同候选的其他有效成员；同候选均无法正确生成目标范围时才进入下一候选。按保证正确整形的最小完整范围选择，不逐字符拆散连写或序列。

同字族优先使用请求的真实粗体、斜体或粗斜体成员；缺少精确字重时采用明确且稳定的最近可用字重匹配，字姿按明确规则降级。匹配规则以 CSS Fonts 的 font matching 语义作为实现参照，具体对齐版本、字姿替代顺序及等距字重选择在实现设计中固定，不要求引入浏览器。样式近似不能越过候选顺序：较早候选内能够正确生成文字的可用成员，不因较晚候选存在精确粗体而被隐式跳过。缺少请求样式与缺字、损坏资源是不同结果，解析结果保留请求样式、实际样式和降级原因，供诊断与验收核对。

**真实样式与合成边界。** 默认禁止合成粗体和合成斜体：不得以重复偏移绘制、位图膨胀、固定剪切、固定 advance 加值或 shader 扩张代替实际样式匹配。缺少与请求匹配的真实样式时使用匹配规则选出的真实可用成员并报告样式降级，不能把普通 face 的合成结果标为真实粗体或真实斜体。将来若提供合成样式能力，必须由独立显式策略启用，并统一建立其整形、度量、墨迹与光栅合同；历史路径中的合成参数不构成默认启用授权。已经匹配真实样式的 face 不再次合成增粗或倾斜。

具备可变样式能力的字体，通过实际支持的字重及字姿轴解析请求，限制在字体公布的范围内，所选轴值属于实际字体实例身份；不能在整形后仅为光栅另选轴值。后端不支持相应可变能力时明确报告能力边界，沿已声明候选及真实成员匹配，不以固定剪切伪装轴支持。此处不扩展为任意自定义轴的业务承诺。

**测绘及缓存一致。** 解析后的实际 face、字重／字姿实例及资源代际在整形时确定，advance、kerning、连字、ascent/descent 和墨迹来自该实例。粗体或斜体可能改变字宽与换行，测量、截取、省略、命中与绘制消费同一结果；不复用常规 face 的几何后只替换粗体图片，也不为模仿原版字宽统一加一个常数。光栅及采样沿用确定的实例，仅改变采样密度；阴影复用同一字体事实，不引入另一套样式匹配。

样式请求、候选成员集合、实际实例及合成策略（若显式启用）进入相关匹配、布局与字形缓存身份。主题字重／字姿改变、字族成员增删、系统字体配置变化及资源重载使实际依赖失效，相关文本自动更新；稳定内容不重复解析字族或重走字体匹配。

### 2.9. 数学字形部件构建

[数学伸缩结构](<2026-10-07-uilib-text-content-spec.md#142-数学伸缩结构>)由具名数学字体提供竖向完整变体及 OpenType MATH GlyphAssembly 部件事实。部件保留真实 glyph ID、横向 advance、轮廓与同一字体实例身份；构建按字体记录的底到顶顺序、连接长度、最小连接重叠和 extender 重复规则生成不可变定位。部件排列与光栅使用同一来源、字号和资源代际，不持有跨调用 native 地址，不新建独立数学光栅/GL 管线。

完整变体达到内容目标时优先使用完整字形；部件构建不得任意缩放轮廓来补高度，不能以 MATH 竖向 advance 充当横向字宽。部件字形需求、等待、上传、缓存和卸载继续遵循现有字体生命周期；数学布局只消费构建结果。连接处实际像素须取得 GPU 证据，盒高度断言不能单独证明拼接无裂缝。不可构建时向数学调用方报告字体身份/能力及原因，沿数学整式诊断合同处理。

### 2.10. 数学完整字形能力

[数学完整交付](<2026-10-07-uilib-text-content-spec.md#143-数学完整交付与集中验收>)继续使用同一具名数学字体，将竖向构建推广为明确的横/竖轴请求。采用字体字形的横向完整变体与 GlyphAssembly 按字体左到右记录、原始 fullAdvance 和 connector 定位，竖向仍为底到顶；两者复用同一连接算法，不能在页面按字符手工拼图或拉伸字体轮廓。已确认的数学路径饰件及箭头布局形式归文本第 1.4.3 节，不作为字体字形构建。横向 advance 与 ink 包络分别保留，不能将竖向度量误用作横向宽度。

采用字体字形的重音沿真实 MATH top-accent attachment、倾斜修正、数学常量及原字形度量定位；单字形附件点与多原子数学盒的整体定位是不同事实。无对应数学数据/字形能力时由数学调用方报告准确边界，不伪称真实字形。所有请求、布局及光栅使用同一 source、em 和 generation，native facts复制为不可变快照后结束 native 生命周期。常规数学字母样式使用字体实际字形或真实成员，不启用默认合成样式。固定参照明确支持的显式数学命令 \pmb 是调用方请求的 poor-man-bold 绘制效果，与默认字体样式匹配分开表达；仅该命令允许按其已声明效果构造附加字形绘制，保留实际 source/实例/代际，不把结果标为真实 bold face，不改变普通 \mathbf 或文本字重的真实样式策略。其几何包络与像素必须单独验收。

根号顶部横线采用以下局部延伸：延长根号原字形的横线素材，保持其厚度、抗锯齿与右端形状；仅横线中段沿水平方向延长，钩部、竖段和字体记录的竖向构件定位不变。该局部横线延伸复用原字形资源、缓存和绘制管线，不扩展为任意数学符号轮廓缩放，其他采用字体字形或部件的结构继续遵守 MATH 合同；数学路径饰件与箭头布局形式按[文本第 1.4.3 节](<2026-10-07-uilib-text-content-spec.md#143-数学完整交付与集中验收>)维护。

实际 GPU 图像分别验证字体横向宽目标、连接连续性，以及数学饰件/箭头与嵌入盒净空、多字号及重载；字体构建与数学路径分别标明，同时回归竖向 assembly、大算子与普通文本候选链。数学验收授权与最终宿主取证按[文本规格第 1.4.3 节](<2026-10-07-uilib-text-content-spec.md#143-数学完整交付与集中验收>)执行。

## 3. 组件排版策略

换行、超宽时的应急断行、省略、裁剪和滚动由组件声明；默认值属于具体组件合同。字体渲染器不决定页面遇到长单词时如何显示，不设一份覆盖所有组件的全局 A/B 策略。

共享文本排版服务接收组件提供的宽度、语言和断行/省略策略，返回行、字形定位及源文映射。它负责执行 Unicode 合法断点、字素/整形边界与最终行整形，避免组件自行实现复杂文字算法。光栅与 GL 回放只消费定位结果。

组件可声明不换行、正常换行或应急断行；超宽单簇仍保持完整。裁剪和滚动由 scene 执行，不因排版超宽自动创建滚动条或缩字号。省略同样由组件指定，排版服务生成完整簇范围及正确视觉位置，不改业务原文。

原版适配层从所调用方法取得策略：drawString 不自动换行，split/wrap 按参数排版，trim 按宽度截取；不创建一个临时组件猜测策略。

## 4. 原版字体引擎替代

目标：原版 GUI/HUD 及通过标准 FontRenderer 方法绘制的 Mod 文本，可由 UILib 接管；接入者沿用原版调用，不需重写 scene。度量、截取、换行和绘制全部进入同一个字体服务，不只替换 drawString。

| 接口类别 | 替代行为 |
| --- | --- |
| drawString／阴影／多行绘制 | 同源布局，执行显式 Minecraft 格式语义、颜色、阴影及样式；接管后不重复执行原版绘制 |
| getStringWidth／字符宽度 | 和实际绘制相同字体事实；字符串按完整 Unicode 整形，char 接口仅承担其可表达的单字符范围 |
| 正向/反向 trim／格式化换行／多行高度 | 返回符合原方法语义的文本或高度，截取不拆簇，保留格式继承和源文关系 |
| 字高、Unicode/Bidi 设置、资源重载 | 适配原版可观察设置与尺寸查询，更新实际依赖；不维护独立旧宽度表 |
| 返回坐标及 GL 状态 | 遵循调用点的返回值/状态合同；不以自有布局结果改变原调用者的坐标单位 |

原版调用坐标沿用调用者提供的 GUI/世界坐标与变换，适配层转换到字体引擎所需单位；UILib scene 仍采用原生像素。原版 GUI Scale 继续作用于原版布局，不能仅把文字改为原生像素却保留旧按钮与命中尺寸。此处是宿主兼容转换，GUI Scale 不进入文本核心。

原版格式码保留样式意图及其作用域，样式实现统一按第 2.8 节选择实际字体，不复刻原版合成算法。原版返回值及坐标兼容不要求保留旧粗体的固定宽度增量；宽度、截取及换行使用实际选中样式的度量。

原版字体替代默认开启，可配置关闭；关闭时原版路径原样执行，开启时标准入口接管。提交范围与宿主兼容见[MC宿主渲染优化规格](2026-10-07-mc-host-render-optimization-spec.md)。默认像素观感和原版常用格式/阴影样例需实测对齐，不承诺更换字体后每个字宽完全等于原版。绕过标准入口的第三方自定义字体须显式接入，不宣称自动覆盖。

## 5. 运行职责与验收

### 5.1 职责与主流程

scene 组件与原版适配器共同调用平台无关的字体/文本排版服务，共享不可变定位、字形资源、批次构建及 backend。scene 仍独占节点、布局树、依赖追踪和输入生命周期；原版 drawString 不创建 SceneNode、ReactiveDomain 或 SceneRuntime，直接按方法语义生成文本绘制载荷。现有 TextLayout/PaintCommand 文本载荷可复用或在字体专项扩充，backend 不以存在 scene 为前提。GL 对象只在 backend，业务不接触字形队列、纹理或上传时机。

流程：

输入/显式内容与样式请求转换 → Unicode 分段与 Bidi → 有序候选内的真实样式匹配与脚本整形 → 按宽度断行并修正行边界 → 不可变行/字形定位及来源映射 → 可见字形需求 → 后台光栅 → GL 增量上传 → 同一定位回放

度量取得实际字体的 metrics/advance，不依赖 GPU 是否就绪。测量和绘制消费同一排版产物；视觉命中返回源文逻辑范围，字素内部不返回半个代理对/组合标记位置。Bidi 的边界位置保留方向归属，供编辑器处理光标与选区，不在字体层另建编辑状态。

优先复用在目标环境可确认有效的成熟字体实现，Java 或 native 均可；不强制自研 Java 读取、OpenType 整形与软件光栅，也不要求为语言纯粹性保留两套引擎。Unicode/Bidi/语言断行可复用 ICU4J，FreeType/HarfBuzz 及 LWJGL/JNI/FFM 可作为正式字体后端，须分别验证实际 Java、操作系统、架构、ABI、绑定与 native 版本组合。Java2D/AWT 的桌面与隐含 native 依赖也需核查，不作为 Android 可移植性的依据。候选实现的脚本、字体格式、彩色 emoji、分发方式与许可证在采用前通过真实样例确认；没有可用实现的目标环境属于需解决的兼容缺口，不能以空实现、逐码点绘制或缩减文字范围冒充支持。先保证目标环境的正确显示，再实施有实测收益的平台加速。

默认资源方向：Unifont 承担中英及广泛字符补充；Noto 系列补充复杂脚本，Noto Color Emoji 承担彩色序列。具体文件与版本以真实覆盖探针选定，随包保存上游来源和完整许可。配置系统字体按 family/style 解析实际 face，选择界面按需枚举，普通帧不扫描系统字体目录。

存在多个字体后端时复用同一字体来源、候选规则、文本布局及资源生命周期合同，不另建排版引擎。实现选择在明确的引擎/资源作用域完成；既有计划保持所属字体事实，不能在光栅时临时改用另一实现而混用度量与字形。后端能力检查与初始化归适配；替代实现必须真实存在、满足所需能力并验证后才能选择，不假设任意失败都有可用 Java fallback。内部算法错误保留原始异常，不逐字 catch 后隐藏。不同实现可以有允许的像素差异，但须满足同一脚本、簇、来源映射、颜色与测绘一致合同，不能靠删减功能获得速度。

Android/FCL 的潜在兼容与独立验收遵循核心第 9 节。字体后端须真实读取随包字体，验证复杂文字整形与彩色光栅并记录环境；核心逻辑、后端正确性、GPU 回放与平台性能分别取证。

### 5.2 按需增量与效率

- **按实际 glyph 建稀疏缓存。** 身份包括实际 face/资源代际、glyph ID、像素字号及影响光栅的样式；整形位置和来源映射不写进共享字形。无需 Unicode 全集索引或启动全字体预生成。
- **合并需求。** 同一字形的等待者共享一次生成/上传；可见片段申请字形，有限预取排在可见需求后。关闭、滚动和字体换代撤销过期需求；后台任务完成时按代际检查发布。
- **分离任务。** 字体元数据、整形和光栅属于 CPU 服务，GL 仅由上下文线程执行。单次光栅有输入尺寸上限，不能假设可在字形内部随意抢占；异步运行防止其阻塞渲染线程。
- **控制上传。** 每帧使用时间、字节和提交数预算；超大区域按行块上传，完整字形上传完成后才发布就绪。驱动调用耗时实测，时间预算是提交边界。
- **采用实际格式。** 单色覆盖率与 RGBA 彩色图集分开存储；合并同页脏区域，但合并额外上传量也计入预算。连续可合并绘制使用批量顶点，不跨遮挡/裁剪边界重排序。
- **有界复用。** CPU 字形、排版、等待数据和 GPU 页分别有可配置预算。当前有效回放资源固定引用到 replay 完成；淘汰非使用资源，资源不足按第 2.7 节处理。页面释放引用，运行时释放其拥有的共享资源；资源关闭中单项失败仍尝试其余所属清理，保留首个异常及后续清理错误。

以相同输入比较稀疏字形缓存、请求合并、单色存储与区域批量更新的生成/上传吞吐、重复工作、慢帧及内存，不把基线已有能力计作新增收益。

### 5.3 动态更新与失败归属

| 变化/失败 | 处理 |
| --- | --- |
| 文本、候选、字族成员、字重／字姿、字号、语言、宽度 | 相关排版失效；最终行位置更新，按新结果请求字形 |
| 单色文本颜色、整体透明度 | 只更新绘制，不重新整形或光栅 |
| GPU 字形就绪 | 在呈现 prepare 边界通知相关绘制失效；不在 replay 中改节点或计划 |
| 字体/资源重载 | 代际换新，旧有效计划维持完整引用直到不再使用，不能混用旧度量和新字形 |
| 有效候选全部缺字 | 显示稳定替代字形，保留源文范围并诊断 |
| 字体文件读取/解析失败 | 统一资源入口报告字体身份与原因，不等同缺字；不增加静默系统替换或无限重试 |
| 节点关闭、运行时关闭 | 取消相关需求/订阅，释放引用；GL 删除在上下文线程完成 |

后台只递交完成结果；主呈现流程统一发布。文本布局、图集位置与资源生命期不能由不同线程各自修改。scene backend 恢复其触碰的 GL 状态；原版替代入口的可观察尾状态沿第 4 节及 MC 渲染规格。字体图集与 shader 不污染其他 Mod。

### 5.5 无平台测试机优先

沿[测试应用规格](<2026-10-07-uilib-testing-spec.md>)复用无需 Minecraft/Forge 启动的真实集成环境，支持修改样例、执行、采集图像和耗时；启动、生命周期与报告不另建运行器。使用正式字体、整形、光栅、缓存、排版、合批流程；软件输出用于定位，独立 GL 上下文用于 GPU 验证，均不能用 mock 正式流程替代。

默认减少方法级单元测试，重点覆盖真实多语言样例、动态字体列表、GPU 空白等待、资源代际和批次顺序。无平台运行不证明 MC 注入兼容和其他 Mod 共存，最后在指定实例短小人工批次验证。
