# UILib 大列表更新与滚动的性能收敛目标

状态：规划稿；推进方向已认可，本稿供目标审阅。具体优化机制由本任务的热点证据选定。

## 1. 目标与范围

降低大列表局部内容更新及持续滚动中的主要剩余成本，使稳定条件下的昂贵工作围绕实际变化和可见内容发生。页面继续通过数据、信号和公开声明表达条目；框架维护布局、绘制、滚动和输入的一致结果。业务作者无需维护可见行范围、补偿行位置或手动刷新布局。

上一期[增量更新目标](<2026-10-14-uilib-incremental-update-spec.md>)覆盖局部失效来源、有效文字请求复用及缓存生命周期。本任务继续处理文字请求复用后仍存在的大列表成本，保留已成立的动态性、内容完整性和释放行为。

主负载为列表局部更新和列表滚动；静止、宽度重排、文档和编辑作为受影响行为与性能回归。交付包含热点定位、证据支持的有限结构改进、真实列表使用示例及同宿主前后结果。仅有热点报告属于阶段成果，完整任务还须交付有效改进。

状态、共同几何和平台边界沿[核心规格](<2026-10-07-uilib-core-contract-design.md>)；尺寸与扩展沿[布局规格](<2026-10-13-uilib-layout-spec.md>)；条目连续性沿[动态结构规格](<uilib-dynamic-structure-spec.md>)；内部协作沿[职责规格](<2026-10-14-uilib-internal-responsibilities-spec.md>)；测量口径沿[性能压测规格](<2026-10-14-uilib-performance-testing-spec.md>)。

## 2. 职责与不变量

| 主体 | 本任务中的职责 |
| --- | --- |
| 页面与业务 | 提供条目数据、稳定对应关系、控件声明和业务动作，持有独立业务及编辑状态 |
| 呈现运行时 | 跟踪变化、维护归属和绑定，协调当前有效的呈现及输入 |
| 布局与绘制协作者 | 根据当前依赖和约束减少重复工作，向绘制与输入提供共同事实 |
| 控件作者 | 使用正式测量、排列、绘制及依赖通知能力，遵守所属生命周期 |
| 宿主与测试侧 | 提供真实环境和输入，运行正式管线，保留可核验的观测 |

内容、行高、字号、字体、语言、主题、窗口及资源代际均为可变条件。有效复用须响应实际依赖；缓存有容量边界、失效来源和释放来源。真实全局变化允许必要的全局处理，首次建立内容与索引的成本单独报告。

可见内容、位置、裁剪、滚动范围和业务命中保持一致。局部内容变化导致的自然高度、兄弟位移及范围变化按当前事实更新；业务不读回几何补偿普通排版。优化后的滚动仍保留全部逻辑内容及其可达性。

条目数据身份、节点身份和挂载生命周期分别按所属合同处理。普通重排、合法交互连续性、失效手势结束及独立草稿归属沿既有合同。减少可见工作不隐含新增焦点恢复、滚动锚定或业务提交行为。

实现复用 UILib 的 scene、Signal、Owner、正式控件、共同几何和 PaintPlan。正式子测量入口仍归当批；需要跨批复用的内容事实须有完整的有效性依据。

## 3. 阶段目标与机制选择

### 3.1 定位当前版本的剩余成本

从当前已完成增量更新的版本建立未插桩基线。用正式列表的局部更新和滚轮输入，观测状态与绑定结算、测量、排列及共同几何、输入协调、绘制收集和宿主 replay 的耗时、调用次数与实际处理量。

诊断记录逻辑条目数、实际挂载量、可见量及所选热点的处理量；测量、排列或绘制次数使用各自含义，不以文字委托请求数冒充 native 整形次数。若观测到多次布局，须指出各次调用的触发来源和必要性。

阶段耗时明确包含关系，避免把嵌套阶段重复相加。临时探针与最终性能采样分开，记录其影响；诊断采用能区分当前假设的最小观测，不将一次性探针扩展为新的生产监控系统。

阶段成果说明：主要成本在哪里、由何种输入触发、处理量随什么增长、哪些工作属于必要求解，以及所选改进针对哪项重复工作。已有调查可作定位线索，运行结论对应当前版本重新取得。

### 3.2 选择并交付有限结构改进

按证据选择主线，优先消除重复工作产生的结构原因。候选方向与选择依据如下：

| 方向 | 适用证据 | 需要解决的主要问题 |
| --- | --- | --- |
| 列表可见范围组织或行级虚拟化 | 大量不可见行的构造、绑定、测量、排列或绘制占主要成本 | 限制昂贵行工作，保留全部逻辑条目的内容、尺寸关系与可达性 |
| 有效内容或子树测量复用 | 未变内容在相同有效依赖和约束下反复求解 | 复用完整度量事实，正确更新受影响父布局和兄弟位置 |
| 绘制或宿主处理优化 | 当前几何正确，主要成本落在绘制收集或实际 replay | 减少重复收集或提交，保留内容、顺序、裁剪和宿主状态 |

进入实现前明确所选主线、目标宿主与负载、需要减少的处理量、动态失效和有限验收。接口及算法服务该主线；大规模完整增量布局和无关框架重写另行规划。

虚拟化当前不属于已确认的布局或动态结构合同。若证据支持新增虚拟列表能力，先形成可审阅的能力合同，明确业务键与节点身份、可变行高和滚动范围、视口离开时的生命周期、焦点与键盘导航，再落实接口设计。不能把裁剪、折叠或删除的既有语义直接当作虚拟化语义。

若所选方案的运行反馈否定收益，回到当前热点证据修正主线；阶段记录保留被否定的原因。目标仍是交付有效改进，避免把试过一种方案作为完成依据。

### 3.3 用公开声明验证使用方式

复用统一测试应用提供一个可运行的列表示例，组合真实文字、按钮及动态条目，通过正式信号更新、滚轮输入和点击观察结果。示例承担真实使用验证，业务部分只表达逻辑内容与动作。

所选能力若涉及行内编辑或节点挂载变化，示例补充独立编辑状态及对应输入场景。新业务页面作为后续任务；本期用已有列表需求验证改进的通用接入方式。

## 4. 行为验收

| 场景 | 可观察结果 |
| --- | --- |
| 无变化连续呈现 | 有效呈现保持，不重复构造条目、建立绑定或启动无来源的昂贵求解 |
| 只更新可见行 | 当前文案真实出现；点击使用当前条目数据；未变内容的有效文字请求继续复用 |
| 更新视口外条目，再滚回该行 | 当前内容和真实高度生效，没有旧文案、旧命中或业务手动刷新 |
| 不同行高、换行及局部自然高度变化 | 当前行与兄弟位置、裁剪和滚动范围正确，末尾可达且反向滚动立即响应 |
| 连续往返滚动与点击 | 画面所见行和实际业务对象一致，裁掉部分不命中，无幽灵行或重复动作 |
| 动态增删、重排和末段删除 | 按当前顺序显示与导航，范围收缩正确；失效按压的物理尾部不激活后来条目 |
| 字号、字体、语言资料、主题及窗口变化 | 依赖内容按新条件自动更新，重新可见的行也使用当前事实，无需重开页面 |
| 所选改进涉及编辑、焦点或挂载 | 普通更新的合法交互及草稿沿既有合同；失效联系结束，后续输入不误落到邻行 |
| 所选改进涉及自定义测量或子树缓存 | 正式依赖变化正确生效，同批入口不跨批保留；已声明备用捕获仍消费有效事实 |
| 重跑、切换、停止、退出及重新打开 | 状态不串轮，所属资源与缓存释放，业务共享状态和服务继续可用 |

行为证据来自正式 session、真实字体、正式输入、可见内容和业务动作。仅为所选结构改进及受影响的真实回归补充必要场景；实际节点释放和绑定释放按所有权核验。

## 5. 性能与工作量验收

基线和修改后在相同宿主、环境、视口、内容、动作及采样参数下配对。复用核心自动机与真实 Desktop；主要规模使用现有 200 和 1000，采样沿性能压测规格。1000 规模前后各至少取得两轮，用重复结果区间判断收益与回归。

原有局部更新动作会依次修改全列表条目，包含视口外更新。前后比较保留相同条目数量、文字内容、更新对象序列及正式滚动动作；优化不能通过缩短内容、减少更新或替换为固定行高负载取得结果。确需新增代表性场景时单列报告，并保留原负载对照。

正式验收分别回答以下问题：

- **结构收益：** 所选热点的重复工作实际减少，报告前后处理量。相同可见量和局部变化下，增加逻辑条目时的昂贵工作增长得到改善；必要的元数据、索引及全局变化成本单列解释。
- **时间收益：** 实现前选定的目标宿主与负载，其未插桩处理耗时 p95 改善超出本次重复运行波动。以修改后重复轮次 p95 的上界低于基线重复轮次 p95 的下界作为保守判据；区间重叠时尚不足以满足此项，先核对环境与路径，再按需要补充受影响组合。p50、p99、慢帧及帧开始间隔同时报告。阶段收益须落实到该目标的整体处理耗时。
- **回归：** 核心与 Desktop 均复测列表滚动及局部更新，并检查静止、文档、编辑和宽度重排。若结果表明稳定退化，定位并修正后再验收；无法区分波动与退化时只复测受影响组合。
- **进入与释放成本：** 声明构造、首次帧、重跑及所属资源释放单独说明，避免把稳定帧工作移到频繁创建或关闭阶段后遗漏。

计时边界、原始样本、分位数、字体与图形环境、完整路径命中及 GC/堆观测均沿性能压测规格。比例、区间和增长结论由保留的计算代码从原始输入重算。观察阈值保持原有用途，本任务不新增跨机器帧预算承诺。

MC 实机沿会话授权使用 /qzperf。核心自动机和 Desktop 各自提供所属证据；尚未取得的 MC 结果明确列为未实测。

## 6. 完成与后续边界

主要热点有当前版本的证据，所选结构改进通过行为及处理量验收，目标负载取得超过重复波动的实际时间收益，受影响回归、完整 build 与独立审查通过后，本任务完成。

具体源码诊断、接口草案、施工步骤、采样参数清单和运行证据归临时计划与验证记录。新增能力合同在机制选定后归所属正式规格维护，本目标稿不替代对应模块合同。

完成后以真实功能需求进入下一任务。后续热点各自按证据选题，不将本期扩大为全部布局、文本编辑和宿主渲染的全面优化。
