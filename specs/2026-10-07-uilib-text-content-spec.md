# UILib 文本内容与排版规格

状态：已确认模块规格；与核心规格共同构成项目规格体系，仅定义本模块职责。

共同状态、布局、生命周期、输入与平台边界遵循[核心职责规格](<2026-10-07-uilib-core-contract-design.md>)；按职责选择规格见[规格入口](<README.md>)。

## 0. 最终目标与阶段交付

用户已确认最终方向：文本内容呈现及数学公式能力尽可能完整接近固定版本 VS Code 内置 Markdown 预览。参照为稳定版本、默认设置及无第三方 Markdown 扩展；Markdown 文档解释、主要阅读行为与其数学插件/引擎支持范围共同定义对照目标。最终能力须按实际参照的语法、命令、环境、宏行为及排版质量建立支持矩阵与独立对照语料，不能以“常用子集”或当前实现能力代替最终范围。完整 LaTeX 文档编译、任意宏包及第三方 VS Code 扩展不因该目标自动纳入；参照中实际支持的数学能力不得据本节的阶段范围永久排除。

语义一致、功能范围及视觉质量分别验收：文档结构/语法与公式解释使用相同输入对照；公式基线、间距、数学样式与伸缩字形须有实际呈现证据；页面字体、主题、空间适配由 UILib 声明系统管理，不要求像素复制浏览器页面。允许差异逐项登记原因及可观察结果，旧有刻意差异须在相应阶段重新对照，不因已实现而自动保留。固定版本、依赖及默认配置以可核实的参照证据为准，升级参照需同步对照记录。

UILib 自有富文本 DSL 的语法仍由本规格定义，它与 Markdown/HTML 是独立输入转换入口；各入口生成共同内容，复用同一文本、数学、图像、布局、绘制与输入职责。共同内容的扩展按已知能力组织，不因最终范围而先造通用执行框架或第二套排版。数学后端已按用户要求评估：宿主 Item 嵌入需要可扩展数学内容与尺寸/基线协议，成熟引擎并非原则上无法扩展；选择 UILib 自有解析和数学盒算法，是为了将中性嵌入内容作为数学能力的一部分。算法以成熟 TeX/OpenType MATH 规则与固定 KaTeX 参照对照，字形整形、光栅、资源及绘制仍复用现有字体/场景管线，不另造字体或输入体系。最终目标不因自制后端而缩减，支持矩阵逐阶段补齐。

基础属性文本及链接的合同如下：显式 PLAIN、RICH_TAGS 输入；RICH_TAGS 支持 b/i/u/s/color/size/br/a、正常嵌套及重复样式、具名双引号属性、lt/gt/amp 实体及序列化语义往返。内容/主题/字号/可用宽度变化自动重排；多行链接仅在当前排版的可见片段内命中并遵守祖先裁剪、滚动及有效挂载/交互资格，激活只发布声明目标给业务。没有基准位置解析声明时目标保持原值，业务不用为局部命中补节点或几何。同节点内不同链接声明有独立身份；正常嵌套的链接在内层内容范围采用内层目标，闭合后恢复外层声明。同一声明的身份不因仅重新排版或基础样式变化而改变，新内容声明即使源码与目标相同也使用新身份。按下与释放须命中同一有效链接，内容声明替换、失活、卸载或取消后不复活原手势。链接按完整文字簇参与片段命中，不切分 Unicode 字形簇；簇跨声明边界时归属其起始逻辑位置，边界冲突提供诊断。

当前生产入口包含基础属性文本/链接、自有数学、DSL 的 `<latex>`/`<img/>` 与声明式共同文档混排；数学后续阶段按第 1.4.2–1.4.3 节扩展，不能用第 1.4.1 节首个切片的排除项限制现有能力。Markdown 显式 `MarkdownDocument.parse(String/TextInput)` 已转换到共同文档：段落、标题、分隔线、引用、嵌套及松紧有序/无序列表、围栏/缩进代码，行内强调/粗体/等宽代码/删除线/实体/转义/软硬换行/引用及自动链接、图片和数学入口。转换复用 Java8 CommonMark 0.21.0 及其删除线扩展、autolink 0.10.0；解析库由核心私有重定位供给，宿主不携带第二份。代码使用已有等宽字体与局部横向视口。每个段落保留完整输入来源，实体展开可共享原范围，UTF-16/byte 单位沿共同映射。HTML/表格转换以及 DSL 的 mark/sup/sub/spacing 尚未接入，保留为后续目标；当前 Markdown 中识别到的 HTML/管道表格保留可读源内容及定位诊断，此阶段降级不代替最终 HTML 合同。[固定数学支持矩阵](<../src/test/resources/math/reference/support-matrix.json>)及生产场景是实现证据，不另立行为合同。UILib 的公开内容体系面向现代文本能力，不提供 Minecraft 格式输入模式。PLAIN 不解释 DSL/Markdown 语法，保持标记字面内容；§ 及其后字符在 PLAIN 和 RICH_TAGS 中均为普通文本，不消费、转换或生成样式。换行、Tab 及 Unicode 控制语义沿字体规格。既有原版字体替换所需的格式转换仅用于宿主适配，不进入通用 TextContent 声明。富文本正常语法按第 1.5 节。RICH_TAGS 首次非法语法或未知声明产生可定位诊断后，整段原文按 PLAIN 呈现且不生成链接；不发布半解析内容，不自动补闭合、吞错配标签或修复属性。诊断保持 UTF-16/byte 来源单位及原范围，不声称兼容任意 HTML。

每个呈现/交互阶段均须自动验证与实机验收分别取证：自动场景验证生产解析、状态、排版、绘制及输入路径；交付正式/人工包部署到目标实例后，实机检查样式、动态重排、裁剪与命中。用户对数学部分进一步明确：无需逐阶段人工筛查，代理用集成测试平台的真实字体与实际 GPU 输出图像自主验收，完整数学交付后由用户一次实机验收。数学阶段据此持续推进，不把缺少阶段用户筛查视为阻塞；最终宿主实机记录仍独立取证，不能把平台图像冒称 Minecraft/GTNH 实机。其他呈现模块沿原有阶段约定。

## 1. 字体、文本与数学排版

### 1.1. 模块职责与数据流

文本调用方提供内容、显式内容模式、样式和可用约束；解析层生成内容结构，排版层结合字体与约束生成行、块及公式几何，绘制层消费同一结果。标准控件和自定义控件共用这一流程，不通过字符串长度、手算字宽或控件内部节点拼装另建文本布局。

原始文本、自有富文本标签与后续 Markdown 是明确选择的内容输入，不按文本中出现某个符号猜测模式。Minecraft § 格式不属于 UILib 公开内容体系；原版行为适配停留在宿主职责，不改变这些内容模式的语义。解析不调用宿主绘制、修改业务状态或触发链接行为。

内容结构与显示几何分开：窗口、字号或字体改变可以重新排版，不要求业务重新提交源码。稳定源结构、来源和声明身份与基础样式派生分开；宿主可提交中性属性意图，未声明字体、字号及颜色分量继承当前基础样式，不保留宿主格式规则。内容、样式和资源变化按实际依赖失效；稳定内容不需要每帧重新解析。同一呈现批次的测量与最终布局共享对应请求的文字事实，内部模型及缓存接缝不形成冻结的公共 API。

### 1.2. 文本几何与交互

测量、换行、省略、基线、绘制及链接区域使用同一次排版的文本与字体事实，遵循[核心规格第 3.4 节](<2026-10-07-uilib-core-contract-design.md>)渲染批次更新。多行链接按实际可见片段命中，祖先裁剪仍有效；点击发布链接目标或动作给调用方，不由解析器代替业务执行外部行为。

Unicode 内容处理不能以 UTF-16 单个 char 作为任意可切割字符，把代理对截成半个字符。编辑与排版共用纯 Unicode 字素规则和版本来源，字形簇可因整形更大，编辑不依赖字体或字形资源。布局记录最终方向与逻辑—视觉边缘，控件消费这些事实，不重新以另一方向或显示投影解释。自定义规则来源提供稳定不可变快照，调用方协调替换并经现有字体失效入口通知呈现；局部字体规则重载不更改其他独立消费者。文本编辑沿[编辑规格](<2026-10-07-uilib-editing-spec.md>)处理光标与选区；只读显示的切行、省略及复制应保留可解释的原内容关系，不把画面省略号写回业务原文。复杂字形与平台字体支持边界须在字体能力设计中明确，不凭已有测量函数声称全部脚本完整支持。

文本内容及样式的原文由调用方持有；框架负责其排版和呈现。缺字、无效内容或不支持语法的处理必须有明确结果，不能静默截断整段内容。具体语法集合及降级合同按第 1.5 节继续裁决。

### 1.3. 字体专项入口

字体选择、缺字回退、资源生命周期和自有渲染器的权威合同独立维护在[字体渲染器专有规格](2026-10-07-uilib-font-renderer-spec.md)。本节只登记入口；共同文本流程仍按第 1.1—1.2 节，原生坐标按[核心规格第 9 节](<2026-10-07-uilib-core-contract-design.md>)，专项字体约束不在此重复。宿主合批、原版字体替代的提交范围及无平台渲染验证另见[MC宿主渲染优化专题](2026-10-07-mc-host-render-optimization-spec.md)。

### 1.4. 数学排版职责

数学能力解析并排版明确支持的公式子集，作为可测量内容参与行内或块布局，字体度量、数学盒与实际字形保持一致。文本和公式混排由共同排版过程协调基线及行高，不由业务补算公式高度。

首期支持常用公式能力：分组、上下标、分式、根式、伸缩定界符、矩阵/分段、数学字体样式、常用符号与算子。它是明确的数学子集，不承诺完整 TeX 宏定义、包加载或外部 TeX 执行。各能力的作用域及其余明细由本 spec 继续细化，不能仅引用旧命令清单或测试作为新权威。

用户已认可的首期核心命令范围如下；符号明细、重音及具体字形质量边界暂缓深入，不据当前源码的容错或历史排版规则扩大合同。

| 类别 | 命令或结构 |
| --- | --- |
| 分组与脚本 | `{…}`、`^`、`_` |
| 分式及二项式 | `\frac`、`\dfrac`、`\tfrac`、`\binom` |
| 根式 | `\sqrt{…}`、`\sqrt[index]{…}` |
| 伸缩定界符 | `\left`、`\middle`、`\right` |
| 矩阵/分段/数组 | matrix、pmatrix、bmatrix、vmatrix、cases；array 支持 l/c/r 列声明 |
| 数学样式 | `\displaystyle`、`\textstyle`、`\scriptstyle`、`\scriptscriptstyle` |
| 数学字体及文本 | `\mathrm`、`\mathit`、`\mathbf`、`\mathnormal`、`\text` |
| 算子及上下限 | 常用函数、大运算符、`\operatorname` 及星号形式、`\limits`、`\nolimits` |
| 显式间距 | `\,`、`\:`、`\;`、`\!`、`\quad`、`\qquad`、反斜杠空格 |

数学源文与排版结果分开，动态字号和资源变化不丢源文；绘制继续走 UILib 管线。未知命令、无效结构或无法完成排版时，保留并呈现该公式源文，提供可定位到公式及错误位置/阶段的提示；其他有效内容继续解析和排版，不因一条公式失败使整篇文档消失。错误提示属于框架内容呈现，不由业务补写解析异常处理来维持文档。

伸缩符号及字体样式由数学度量与字形能力协调；准确支持、字体缺失下的近似或降级应有明确边界。不能把忽略未知命令、显示残缺公式或使用近似字形包装成完全支持。具体字形构建、数学盒算法及字体选择留给设计，支持范围及可观察降级在本 spec 补齐。

### 1.4.1. 自有数学与中性嵌入内容阶段

用户要求公式可具有创造性的内容，例如积分的被积项、分子或上下标中显示宿主 Item。核心数学内容使用中性嵌入标识、尺寸和基线事实，不依赖 ItemStack、Minecraft 格式或宿主绘制入口。宿主将标识绑定到已有 SceneImage/图像来源；图像 pending/ready/failed、数量、耐久及提示继续归既有图像控件与资源协议。数学布局分配同一已挂载子节点的几何，输入、祖先裁剪、滚动、tooltip 和生命周期仍由唯一 scene/router 消费，不能用绘制回调偷偷创建宿主 GUI、第二树或第二几何。

首个实现闭环明确支持：普通数学符号/数字及字母、分组、上下标、\frac/\dfrac/\tfrac、\sqrt（含可选根指数）、\int/\sum/\prod、\limits/\nolimits、四种数学样式、\mathrm/\mathit/\mathbf/\mathnormal/\text、常用函数及显式间距，并新增 UILib 扩展 \embed{标识}。嵌入标识引用稳定直属子节点；同一公式中一个标识只能出现一次，重复或缺失绑定产生来源诊断并显示完整原公式，避免同一 Mount 拥有多个空间身份。多个图标使用独立标识/节点，可共享同一图像资源 identity。嵌入尺寸以当前数学 em 表示宽、高及从顶部到基线的距离，随数学样式/脚本字号缩放；本阶段为明确分配的内联盒，不承诺任意节点的自然尺寸/min/max 自动求解。

数学源码解析一次得到不可变结构及 UTF-16 来源区间；动态主题、字号、字体和资源变化只重算布局。自有算法维护宽度、基线上下尺寸、数学轴、原子类别间距、脚本层级、分式净空与根式规则。正式字体必须有 OpenType MATH 数据；使用其常量、字形倾斜修正和真实伸缩字形，不能把普通字体的积分符号任意拉伸当作完整数学支持。根式等需要覆盖内容的伸缩目标超出本阶段可用字形/拼接能力、缺数学字体或字形时，诊断指出布局/字体阶段并呈现完整源文。显示型大算子按 `DisplayOperatorMinHeight` 优先选择满足建议高度的最小真实完整变体；若字体不提供满足该高度的完整变体，则使用最大的真实完整变体，并保持其原有墨迹及横向 advance。大算子选择与按内容定高的伸缩是不同职责，不非等比拉伸、不把整个建议高度冒充字形实际高度。完整原文呈现以既有普通文字候选可用为前提；显式排除全部字体时沿字体服务既有失败合同，不追加隐藏默认候选。普通文字按正常字体能力呈现；数学字体单独具名注册，不覆盖默认文本字体链；字体文件与许可均随包可核实。

首个阶段可以作为独立数学控件及正式页面内容交付，暴露不可变数学布局的尺寸、基线和嵌入盒，后续共同文档行内/块布局消费同一事实。此阶段不声明已经交付任意文本和公式跨行混排、数学编辑、矩阵/分段/array、binom、left/middle/right、重音及完整 KaTeX 命令/宏范围。这些是第 1.4 节及第 0 节的后续能力，不能永久从最终目标删除；命令是否受支持以明示矩阵为准，未知输入不得半解析显示。

验收使用真实数学字体与 UILib PaintPlan：积分含图像嵌入，嵌入位于分式和上下标，嵌套分式/根式与双脚本不相交；改变主题、字号和内容后基线/尺寸/资源一致更新；窄 viewport 裁剪/滚动及可见图像提示走既有输入；错误公式显示源文且相邻公式不受影响；卸载后绑定与资源资格释放。离线纯盒断言不代替真实字形/GL，也不声称游戏物品与模组组合已实机通过。

### 1.4.2. 数学伸缩结构阶段

本阶段沿第 1.4.1 节同一数学内容与嵌入协议扩展字形部件拼接、伸缩定界符和二项式，字形构建归字体服务，语法与盒布局归自有数学引擎；不改变核心树、平台、输入或宿主 Item 边界。

支持 \left 定界符 … \middle 定界符 … \right 定界符，允许嵌套及多个 middle，整个围合结构作为 inner 数学原子参与外侧间距，middle 在本层内容中按 relation 参与间距。left/right 必须在同一数学分组内配对；middle 的资格继承当前活动 left/right，普通花括号子组、分式参数和数组单元格内也可使用，right 仍不能穿过子组补配对。定界目标替换仅作用于围合本层及透明样式片段中的 middle；普通分组、分式和单元格内部的 middle 保留固定 size1 的真实字形盒，并以自身墨迹参与外层测量；合法的左右字符可不相同，点号 \left.、\middle. 或 \right. 表示不可见边界，不产生墨迹，保留 TeX null-delimiter 的布局间距，按根主题字号的 .12em 计算，数学 script 样式不再次缩小该空间。支持圆括号、方括号、转义花括号、竖线/双竖线、角括号、floor/ceil 及竖向单/双箭头的明确命令别名；定界参数为一个有效 token，不把任意普通字母当伸缩字符。错误位置保留 UTF-16 来源，沿既有整式原文呈现合同。定界 token 的支持表见下方，字符与命令名称大小写分别保持各自语义。

| 字形 | 定界 token |
| --- | --- |
| 不可见 | `.` |
| 圆/方括号 | `(`、`)`、`[`、`]`、`\lparen` / `\rparen`、`\lbrack` / `\rbrack` |
| 花括号 | `\{` / `\}`、`\lbrace` / `\rbrace`，未转义的 `{}` 保留分组含义 |
| 单/双竖线 | 字面 U+007C（单线）、`\vert` / `\lvert` / `\rvert`；`‖`、反斜杠加 U+007C（转义双线）、`\Vert` / `\lVert` / `\rVert` |
| 角括号 | `<` / `>`、`⟨` / `⟩`、`\langle` / `\rangle`、`\lt` / `\gt` |

新增 \binom{上部}{下部}，按当前 display/text/script 数学样式生成居中无分式横线的上下堆叠，净空使用 MATH stack 常量，圆括号覆盖堆叠内容；两部分均允许既有数学内容及独立 Item 标识。外侧按 ordinary 原子间距处理，字号随既有数学样式规则变化。本阶段不扩为 d/binom/t/binom、矩阵/分段/array、横向重音构建、宏执行或文档混排。

用户进一步确认：对齐 VS Code 内置 Markdown 预览的文档解释及主要阅读行为，排版、绘制和资源管理仍完全使用 UILib。参照环境固定为选定 VS Code 稳定版本、默认预览设置、未安装第三方 Markdown 扩展；本轮固定参照为 VS Code 1.140.0（commit 07f806f999227108933c2e30515b26eecc1fda74），内置 Markdown 依赖 markdown-it 14.2.0，内置数学扩展依赖 @vscode/markdown-it-katex 1.1.2，其数学扩展锁文件及实际安装 bundle 使用 KaTeX 0.16.21（不以其他扩展或根工程的 KaTeX 版本替代）。[固定数学扩展依赖证据](https://raw.githubusercontent.com/microsoft/vscode/07f806f999227108933c2e30515b26eecc1fda74/extensions/markdown-math/package-lock.json)。记录默认设置，不将持续变化的 main 分支或插件输出作为漂移的验收标准。选定版本是对照环境，首期范围按第 0 节；其完整内容与数学能力作为最终对照目标，尚未纳入阶段的能力须在后续支持矩阵中追踪。

对齐覆盖文档结构、语法解释、主要换行行为、链接、图片及公式；字体、主题、间距等由 UILib 声明系统协调，不承诺像素级复制 VS Code 页面。HTML/CSS、公式命令、来源解析等能力差异须在本 spec 明确列出，最终数学范围对照该参照实际采用的引擎能力，阶段子集须明确登记差距；“对齐 VS Code”不自动承诺完整浏览器或任意 TeX 执行环境。受支持 HTML 转换为 UILib 内容结构，不自动改走 RICH_TAGS 模式；已认可的标签类别见下文；不支持内容按下文已确定的降级规则处理。

文档可声明基准位置，框架负责相对图片来源和链接目标解析；业务不拼接路径或接管图片下载。环境适配提供基准位置的解析能力；此前首期来源承诺保持不变，本条不自动开放任意文件路径。链接激活仍发布解析后的目标或动作给调用方，执行归业务/宿主，解析不执行动作。

基础文档能力包含段落、软/硬换行、标题、分隔线、引用、有序/无序及嵌套列表、围栏/缩进代码块；行内包含强调、粗体、代码、转义及链接。代码内容按代码语义保留，不再解析成公式、富文本或动作。列表层级和引用等结构由排版体现，不用向业务字符串插入固定空格代替结构布局。

表格扩展提供表头、正文行、单元格及列对齐，单元格参与统一行内解析与排版；列宽、行高、换行和溢出处理由框架按可用约束及页面策略协调，不要求业务手算表格几何。它不自动成为可编辑 DataTable，文档展示与编辑控件的业务职责分开。采用管道表格语法：表头之后紧接分隔行，分隔单元格以连字符及可选冒号表达列对齐；左冒号为左对齐，右冒号为右对齐，两侧冒号为居中，无冒号使用默认对齐。表头与分隔行的列数必须匹配，不能匹配时不识别为表格，按正常文档规则解释。正文行缺少的单元格补空，超过表头列数的单元格不进入显示表格，不扩展列数；源文仍由调用方保留。这是已认可的表格语法规则，不将超出的单元格作为解析故障或未知 HTML 字面降级。转义管道、首尾管道及块结束边界按固定 VS Code 参照版本核对。

框架默认根据可用空间和内容求列宽，协调单元格换行及行高；内容仍超宽时提供表格自身的横向滚动视口，不将整篇文档撑宽。图像/字体/公式及窗口变化自动更新列布局和滚动范围；框架不把不可拆分内容强行切断以满足宽度。横向滚动遵守共同几何、裁剪和输入范围合同，业务无需设置列宽公式或维护横向偏移。具体列分配算法及滚动控件样式由设计完成。

数学扩展使用 `$…$` 表达行内公式，独立 `$$…$$` 表达公式块；内容交给 UILib 数学能力，排版参与统一几何。行内公式随所在文本行协调基线和行高，独立公式块作为文档块参与布局。不能因不同调用出口而对同一源文采用两套默认定界解释。

行内代码、代码块以及明确转义的定界符保持字面内容。单美元定界按固定数学插件识别：开定界前不为美元、反斜杠或 ASCII 字母/数字/下划线，闭定界后不为美元或 ASCII 字母/数字/下划线；转义优先于公式识别，公式内部转义美元不作为闭合。`$x$`、`$ x $` 及同段内跨源码换行的配对可识别为行内公式；`a$x$b`、`$5 and $10`、不配对 `$x` 保持普通内容，中文紧邻 `$x$` 可混排。输入输出对照语料使用上述固定参照，不从旧聊天特例或解析器实现继承规则。不构成公式的文本按普通文档内容保留，不静默删掉。已识别公式内部的未知命令或排版失败属于数学内容能力及其降级合同，不退回另一套 Markdown 词法猜测。

Minecraft 的 § 格式码不作为 Markdown 解析核心语义；宿主若需保留颜色或其他来源样式，先明确转换为内容样式，再以统一规则参与解析及呈现。样式片段分割不是 Markdown 文档边界，相同内容不会因宿主分成多个片段而改变语法解释。

Markdown 支持图片语法与内嵌显示，图片来源、替代文字及尺寸/适配意图进入[图像规格](<2026-10-07-uilib-image-spec.md>) UILib 专有图像系统，与普通图片控件共用加载、测量及资源管理；业务不自行下载、补算尺寸或手动触发重排。完整浏览器 HTML/CSS 不在本次已认可范围内；HTML 采用下述内容子集，其超出部分的显示差异须明确，不采用全部 HTML 默认字面显示的独立提议。按固定参照，默认支持 `~~…~~` 删除线、完整 URL 及邮箱自动链接；关闭模糊裸域名识别，`example.com` 与 `www.example.com` 不自行变为链接。默认 breaks=false，段落内软换行不强制形成硬换行；显式硬换行保持原语义。默认 typographer=false，不自动美化引号或替换普通标点。自动链接复用既有链接目标及激活合同，不隐含自动打开外部程序。未支持内容不能被静默丢弃，失败或字面显示须具有明确合同。脚注、任务列表等未认可扩展不因 Markdown 名称而自动承诺，也不依据旧代码排除将来的正式扩展。

当前基础阅读切片的独立语义对照见[固定 Markdown 阅读语料](<../src/test/resources/markdown/reference/reading-corpus.json>)：由上述固定 markdown-it 与数学插件实际解析生成，而非由生产转换器生成期望；它不等于 VS Code Webview 或宿主实机。已明确的阶段差异：不为缺少原终换行的代码块伪造 parser 合成 LF 的来源；未闭合 `$$` 按正常文档呈现而不吞后续内容（详见数学块边界）；固定 VS Code 的 YAML frontmatter 默认表格呈现随表格切片后续对齐。列表中合法 Tab 缩进的完整 `$$` 配对按 CommonMark 容器解释为一个公式块；固定数学插件在此输入上生成空公式并吞掉部分正文，UILib 保留全部公式内容，具体输入及实际参照 tokens 登记在上述独立语料的允许差异。普通行内数学首尾紧邻且内容长度大于二的 backtick 按固定插件入口剥去一对；DISPLAY、公式块及 math 围栏不采用该处理，不增加数学命令范围。

script、style 等非正文内容不执行，其内容也不作为正文显示；这是明确的非正文处理，不适用于未知普通容器的正文。未知内容、被忽略属性及非正文处理与 VS Code 的实际差异应记录在对照验收中。语法嵌套及容错的具体实现由解析器设计确定，遵守保留可读内容和可定位失败的合同。

#### UILib 富文本 DSL：标签分类与职责

UILib 富文本是一套显式选择的独立 DSL，不等同于 HTML 元素集合，也不将其解析器定义为 HTML parser。部分标签借用 HTML 命名或语义，部分为 UILib 自定义扩展；全部 DSL 标签的格式、属性和行为以本 spec 为规范来源，不因同名而自动获得 HTML 全部语义或属性。它与 Markdown 中的 HTML 子集分别解释；相同排版能力复用不意味着输入语法混用。

| 分类 | 本次讨论涉及的标签 | 规范边界 |
| --- | --- | --- |
| 借用 HTML 命名或语义 | b、i、u、s、mark、sup、sub、a、br | DSL 的内容/样式行为和属性独立定义，不以 HTML 元素存在推导完整支持 |
| UILib 扩展 | color、size、spacing、latex | 属于 UILib 富文本语言，不是标准 HTML 元素 |
| 专用图像能力入口 | img | HTML 中存在此元素，但 DSL 支持及属性须独立定义并接入[图像规格](<2026-10-07-uilib-image-spec.md>)；不混入普通文本样式标签集合 |

以上分类确定规范来源；下文正常内容合同的标签及属性写法已获认可，图片入口独立定义。标准 HTML 中存在元素、规格目标包含图像能力、某阶段已经交付支持是不同事实；阶段范围按第 0 节，不能从旧解析器或旧指南推导当前生产能力。解析生成带样式的内容，样式作用于所属片段及嵌套范围，不修改调用方的基础样式对象或其他内容。颜色、字体样式及字号变化按[核心规格第 3 节](<2026-10-07-uilib-core-contract-design.md>)实际依赖协调测量和绘制，字号使用 logical px。

富文本中的公式和图像能力接入同一数学与图像系统；平台来源由正式适配解析，不允许标签解析器自行上传纹理或维护第二套公式布局。解析、布局及宿主绘制仍按第 1.1 节分工。用于源码编辑或内容持久化的序列化应保存支持内容的文字及样式语义，不要求输出与输入字节完全一致。标签集合和正常词法按下文已确认合同执行，不将现有解析器的宽容修复或默认回退升级为要求。

#### 富文本 DSL 正常内容合同

用户已认可：统一使用小写标签、具名属性和双引号属性值；各属性只按下面的 DSL 合同解释，不接受任意 HTML 属性。

| 声明 | 正常内容含义 |
| --- | --- |
| `<b>…</b>`、`<i>…</i>`、`<u>…</u>`、`<s>…</s>` | DSL 中分别声明粗体、斜体、下划线及删除线样式，局部作用于内容 |
| `<color value="颜色">…</color>` | 声明文字颜色，颜色值采用 #RRGGBB（不透明 RGB）或 #AARRGGBB（显式 alpha）表示 |
| `<mark>…</mark>`、`<mark color="颜色">…</mark>` | 声明文字背景高亮，未声明颜色时使用主题高亮色 |
| `<sup>…</sup>`、`<sub>…</sub>` | 上/下标内容，由排版协调字号、基线及行高，不固定旧倍率 |
| `<size value="字号">…</size>` | 声明绝对 logical px 字号，有效范围沿统一字号能力 |
| `<spacing value="字距">…</spacing>` | 声明 logical px 字距，允许表达有效负字距；有效范围在统一样式能力中定义 |
| `<a href="目标">…</a>` | 声明链接内容，复用目标解析及激活合同，不导入浏览器事件或任意属性 |
| `<br/>` | 显式硬换行 |
| `<latex>源文</latex>`、`<latex math-style="模式">源文</latex>` | 公式内容捕获到对应闭合，不解析内部 DSL 标签；模式为 text/display/script/scriptscript，缺省为 text，模式决定数学排版样式，不自动改变外层文档块结构 |

成对标签按正常嵌套组织内容，内层只覆盖声明的样式属性，闭合后恢复外层；重复相同样式仍保持独立作用域。源码显式使用 `&lt;`、`&gt;`、`&amp;` 表达字面尖括号及与号，解码后作为内容，不重新识别为标签。序列化重新解析应保持已支持内容和样式语义。

旧 `<color=…>`、`<size=…>`、`<a=…>`、通用 `</>` 等写法是否兼容不由本合同承诺；不为兼容预建双语法解析。图片入口沿[图像规格](<2026-10-07-uilib-image-spec.md>)专用能力单独定义，不在此表增加 img 属性合同。未知/无效 DSL 输入只沿统一诊断职责处理，本合同不增加自动补闭合、错配吞标签、属性截断或失败恢复策略。

#### 富文本 DSL 图像入口

用户已认可：用无正文的 `<img src="来源" alt="替代文字"/>` 声明行内图像；src 为必需来源引用，alt 可选，省略时不编造替代文字。图像是独立内容项，不是修改后续文字的样式标签，不要求闭合内容或嵌套子节点。

| 属性 | 进入统一图像系统的意图 |
| --- | --- |
| src | 文本来源引用，由文档基准位置及环境正式适配解析为[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.5 节来源 |
| alt | 可选替代文字，使用[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.4 节已确认状态呈现 |
| width、height | 可选 logical px 尺寸；未声明时自然测量，单边声明按有效比例求另一边 |
| fit | 可选 contain/cover/stretch/original，分别映射[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.6 节等比完整显示/等比铺满裁剪/拉伸/原尺寸；缺省 contain |

远程地址、资源标识及相对来源使用现有来源解析职责。运行时位图、纹理区域和物品等结构化来源由调用方正式声明并通过引用关联，不将位图字节、纹理句柄或 ItemStack/NBT 编进标签；具体关联接口由设计明确。来源更新自动影响图像内容与排版，不要求业务改写整篇字符串以更新已引用数据。

图像度量、行高、裁剪及输入由统一内容布局协调，尺寸和适配仅映射既有图像合同。物品动态渲染及宿主原版 API 路径保持[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.7 节合同。此入口不新增自动链接、物品覆盖层/提示或独立加载/重试机制；无效输入沿既有诊断职责处理，图像状态沿[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.4 节处理。

#### 公式块配对边界与参照差异

用户已认可：UILib 仅将完整配对的 `$$` 识别为公式块；未闭合时按普通文档解释并保留内容，不将后续正文收为公式。固定参照插件会将未闭合 `$$` 后的内容收为公式块，本合同明确记录该差异。这是语法识别范围，不增设自动补闭合、修复或恢复流程。math 围栏及裸数学环境的入口边界按下文合同执行；其他特殊内容入口不因固定版本包含它们自动承诺。

#### 额外数学入口范围

用户已认可：首期支持信息字符串为 math 的围栏作为公式块入口，复用第 1.4 节数学子集及既有块排版；其他围栏按代码处理。此处 math 标识按固定参照去除首尾空白并忽略大小写，带其他参数的信息字符串不自动当作 math。

裸 `\begin{…}` / `\end{…}` 不自动启动数学解析；作为公式内部的数学环境按明确支持的命令/环境范围处理。这样外层识别入口与内部数学语言分别定义，不扩展 TeX 执行能力。本入口复用已确认数学能力，不引入完整 TeX 执行或额外恢复机制。

### 1.6. 当前覆盖与必要边界

本节已覆盖职责、数据流、统一几何、变化失效及资源归属。Markdown 基础、表格、图片、HTML 子集与降级、数学定界方向已确认；字体多字体共存、有序候选及统一资源错误诊断已确定。数学首期结构与源文错误降级已确认。公式块配对边界及参照差异已确认。math 围栏及裸数学环境边界已确认。剩余范围为其他未认可扩展范围及数学具体命令/字形边界，不声称文本专项已经完全覆盖。现有解析代码和旧指南仅是能力证据，不具有独立规范效力。
