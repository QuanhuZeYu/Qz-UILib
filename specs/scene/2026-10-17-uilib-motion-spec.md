# UILib 声明式弹性 UI 动效规格

状态：用户已授权按本设计实施完整动效体系；标准控件按主题默认，布局、进出场和手势回弹显式声明。本规格维护通用动效合同，运行验收按实际证据记录。

## 1. 目标与职责

界面根据目标状态自然运动，连续操作、中途反向和环境变化均从当前呈现继续。业务立即获得新的权威状态；动效表达该状态如何呈现，不延迟操作，不维护另一份业务值。

本专题统一属性过渡、弹簧运动、布局变化、显隐进出及手势释放。默认体感沿现有现代视觉取向，克制、清晰，页面可明确选择更明显的回弹。

遵循[核心职责规格](<../2026-10-07-uilib-core-contract-design.md>)的声明式、共同几何、生命周期与平台边界。业务不编写逐帧推进、坐标补偿、手工失效或第二条输入路径。

| 责任主体 | 决定什么 | 执行与持有什么 |
| --- | --- | --- |
| 页面与业务 | 目标状态、动效策略、布局/存在性/手势动效的启用范围 | 业务值与动作；不持有运动进度或布局快照 |
| 主题与标准控件 | 控件各交互状态的动效角色与默认质感 | 当前主题来源与明确的局部覆盖 |
| 动效运行时 | 当前呈现值、速度、续接与结束 | 所属活跃轨迹、来源观察及有限呈现资源 |
| 布局与呈现协调 | 当前内容的目标布局、实际呈现几何及裁剪 | 向绘制、命中、锚定和导航发布同批事实 |
| 唯一输入路由与手势控件 | 输入所有权、直接操纵与释放意图 | 向动效提供正式输入事实；不复制捕获或焦点权威 |
| 宿主 | 单调时间、窗口与实际输入事实 | 通过既有页面入口推进同一核心 |

## 2. 声明与默认策略

页面声明“目标 + 运动方式 + 呈现用途”。常见属性提供有明确失效归属的正式入口；已有绑定的呈现映射可作为扩展能力，不要求普通页面为每个属性重复编写推进逻辑。常用声明见下例及共享动效页面。

业务状态与纯派生继续遵守同步可读合同。呈现值是框架拥有的结果；读取结果不隐含推进时间或执行副作用，也不把业务 Computed 变成带时间状态的求解器。

标准按钮、复选框及其他标准控件消费主题的动效角色。颜色、阴影和透明度默认采用短而平稳的过渡；位置与形状可采用克制的弹簧策略。布局重排、存在性进出，以及新引入的弹性释放、惯性和滚动回弹均须明确启用；既有拖拽回槽、排序让位和有限落下过渡继续沿所属控件合同，不因新增动效策略而撤销。已有明确曲线或参考行为的页面继续使用其声明，不由新默认覆盖，例如[邮箱动效](<../examples/2026-10-15-uilib-mailbox-motion-spec.md>)。

策略优先级为用户的动效限制、局部明确声明、主题默认。主题及策略来源均可动态替换，按来源变化通知失效，不在构造期冻结。局部覆盖通过明确来源表达，不新增隐式的主题继承或全局节点注册表。

提供正常、减少动效和关闭三种响应式策略。减少动效取消明显的空间往返和回弹，允许必要的平稳反馈；关闭时立即落到当前目标并结束退场保留。策略变化不修改业务值、焦点策略或动作次数。系统偏好若由宿主提供，通过同一来源接入，不在核心查询平台 API。

### 2.1 常用声明

展开面板仍声明自然高度；绑定尺寸动效后，正文变化自动进入当前实际排版：

```java
MotionSpec spring = MotionSpec.spring(.3, .85);
SceneNode panel = new SceneNode().size(Size.fill(1), Size.natural())
        .bind(SceneMotion.layoutSize(() -> spring));
panel.add(SceneLabel.create(context, bodyText, context.theme()));
```

| 用途 | 入口 |
| --- | --- |
| 属性目标 | `SceneMotion.opacity / background / translateX / translateY` |
| 布局变化 | 容器 `SceneMotion.layoutPositions`；节点 `SceneMotion.layoutSize` |
| 显隐与结构退场 | `SceneMotion.presence`；带 `PresenceOptions` 的 `NodeBinding.repeat / ownedChildren` |
| 手势释放 | `SceneDraggable.Options.releaseMotion`；`SceneMotion.scroll` 或 `SceneScrollArea.Options.motion` |
| 动效限制 | `ScenePageContext.motionPolicy`，来源值为 `MotionPolicy.NORMAL / REDUCED / OFF` |

## 3. 运动语义

统一提供即时、有限曲线和阻尼弹簧三种目标跟随方式。惯性衰减属于明确启用的手势释放策略，与同一动效运行时协调。

有限曲线保留现有时长、反向续接和精确端点合同。弹簧表达响应速度与阻尼质感，运行时持有实际位置和速度；中途改变目标或弹簧策略时先取同一时刻的当前状态，再继续运动，不把速度清零，也不重新从旧端点起步。弹簧是有状态的运动过程，不作为一条固定时长的弹跳 easing 曲线代入现有有限过渡。

弹簧的普通连续续接保持位置和速度连续；有限曲线承诺当前值续接及既有反向缩时，不承诺反向瞬间的速度连续。明确的即时跳转、硬约束变化和动效关闭属于直接服从新合法状态的边界；运行时不得为了连续而发布非法值。颜色与透明度使用各自的合法插值，几何尺寸始终遵守所属尺寸边界，弹簧内部状态与属性约束投影由框架协调。

初次及重新挂载默认直接消费当前目标，与现有有限过渡一致；需要首次入场时在存在性声明中明确选择。持续挂载期间的变化才自动续接已有运动。

同一呈现通道同时只有一个运动驱动者。直接操纵期间由手势持有该通道，释放后交给所选运动策略；布局动效不同时为同一位移再加一段轨迹。不同用途的位移可以组合，但组合次序与坐标归属由框架确定，页面不叠加绝对坐标补偿。

弹簧与衰减在当前值及速度满足结束精度后精确落到合法目标，停止所属推进。精度与属性单位相符，由实现及实际反馈校准。静止不靠永久 tick 维持；时间跨越较大间隔时按实际经过时间求当前结果，不追赶重放业务动作。

## 4. 统一时间、失效与生命周期

复用现有帧协调与活跃绑定调度：同一宿主帧及输入批次使用同一单调时刻，重复准备不重复积分。时间推进、声明结算、目标布局求解与当前几何发布由帧协调统一组织，布局、绘制及纯派生保持只读。

只推进已挂载且活跃的运动。仅颜色等绘制变化不触发测量；位置变化更新共同几何；尺寸或真实内容变化执行必要的测量和排列，不承诺免除真实重排。文字、字体与其他内容缓存按实际依赖复用，不为弹性每帧全量重建页面。

运动归明确的挂载或存在性作用域。普通卸载立即结束运动并解除观察，重新挂载从当前目标开始；明确移动依既有身份与挂载连续性，按新归属重定目标。页面关闭、祖先卸载或永久销毁直接释放所属资源，不等待离场播放。

不建立逐控件线程、宿主专用动画管线或额外逻辑树。核心维护平台中立的运动与几何，绘制继续经过正式 PaintPlan；两个宿主消费同一算法源。

## 5. 布局变化与共同几何

布局动效由页面或组件明确声明作用范围，并区分“位置重排”与“尺寸参与排版”。框架从当前内容、尺寸意图及环境求目标，再形成当前呈现；目标计算不读回动画中间结果作为新的业务尺寸。

位置重排适用于列表、网格和同页明确移动。稳定 UUID 与声明键延续已有节点的运动；新增节点按入场声明处理，删除节点按存在性声明处理。兄弟的目标顺序立即反映当前业务，途中位置从当前呈现续接，Tab 顺序仍沿逻辑声明。

尺寸参与排版适用于面板展开、收起及自然内容变化。当前动画尺寸进入正式父子分配，周边内容随实际空间变化；子内容按实际分配重新排版，不能用缩放既有文字画面代替真实换行。自然目标测量与中间分配由布局协作者区分，不让页面先测高度再写回尺寸。动效不隐含新增裁剪或突破硬尺寸边界；需要遮住展开中的溢出内容时，组件明确声明其裁剪。

父子同时有运动时，在明确的局部坐标中组合，避免父位移被孩子重复计入。滚动是当前视口事实，不因为子树声明了重排就被再次当作条目位移动画；窗口、字号、语言、主题及资源变化则使实际依赖目标重新求值。

绘制、命中、悬停、有效裁剪、文本内部定位及所属层锚定只消费同批当前呈现几何。运动中的按钮在可见位置可点击，旧位置不留目标；来源运动时浮层按当前来源锚定。布局目标是求解输入，不是另一套可供输入路由选择的几何权威。

## 6. 手势、惯性与回弹

拖拽继续使用[Draggable](<2026-10-15-uilib-draggable-spec.md>)及[Droppable/Sortable](<2026-10-15-uilib-drop-sort-spec.md>)的所有权、约束和业务意图。直接拖动默认跟手，不为了弹性给指针增加滞后；明确启用的释放策略使用当前呈现及正式输入估计的速度，回到当前合法槽位、吸附点或业务接受的位置。

正常放下只按所属控件规则发出一次业务意图，运动结束不再次提交。取消不提交；失去交互资格仍立即终止原手势，有限的回位呈现不得恢复 capture、旧焦点或迟到尾部。

滚动沿[滚动区规格](<2026-10-16-uilib-scroll-area-spec.md>)保留唯一有效偏移与连续滚轮接续。有效偏移始终在当前合法范围；显式启用的边界弹性是暂态呈现位移，随同一几何和裁剪更新，不把越界距离积存在有效滚动状态中。反向输入立即作用于当前事实。

实际滚轮输入先按既有内层/祖先及所属层边界选择接收者，不让子区回弹抢走本应交给祖先的有效滚动。释放后的惯性只在其当前所属视口内推进，到边界进入所声明的停止或回弹，不虚构新的输入事件移交其他范围。新输入接管时结束旧释放轨迹。

普通滚轮不额外叠加一份未经声明的惯性；宿主已提供动量时不重复合成。输入来源能力由宿主明确表达，当前鼠标接入不外推触摸或触控板支持。内容范围或窗口变化即时限制有效偏移，并按新的合法目标处理暂态运动。

## 7. 存在性与进出场

新增显式存在性声明，负责“目标存在性已经变化、画面仍在有限过渡”的资源归属。未使用该声明的 visible、折叠、repeat 和 ownedChildren 继续按[动态结构规格](<uilib-dynamic-structure-spec.md>)即时结算，不偷偷延长生命周期。

逻辑退出生效时立即结束该分支的输入、焦点与模态范围；退场只保留被动呈现，不能挡住或接收输入。退场是框架管理的呈现状态，不把原模态改挂到 PASSIVE 层，也不继续发布其已退出的模态范围，现有所属层声明合法性规则保持。

退场从退出时的当前呈现出发，从目标普通流退出；空间收缩或邻项让位由已声明的布局动效协调，不保留旧尺寸的静态占位。退场继续服从所属视口及祖先可用性，祖先结束时立即释放。

显隐目标反向而逻辑节点仍被持有时，使用同一节点从当前呈现续接，不能恢复已经结束的手势或焦点。拥有集合中的结构删除则结束该条目的活跃身份，退场作用域仅临时持有其资源；同键返回创建新的 UUID 与生命周期，旧退场不得被当作撤销删除复活。

退场作用域明确限制并发保留量；达到预算时先结束最早的退场并释放其所属资源，业务退出仍立即生效。同一拥有声明中的同键只保留最新一代退场，较旧代立即释放。该预算是显式退场能力的资源规则，不改变普通动态结构。

退场完成后按原拥有关系销毁或解除挂载，外部业务状态与共享服务仍归原持有者。初始入场、普通显隐反向和结构删除分别表达，不以动画完成回调驱动业务状态机。

## 8. 错误与动态策略

无效运动参数、非有限目标、冲突驱动及非法归属沿既有可定位错误通道暴露，完成所属资源清理，不静默替换曲线、吞错或重建页面。硬约束与关闭动效属于正常策略，直接服从当前合法目标。

动效运行时维护运动状态；布局维护合法空间；输入路由维护资格。策略变化只在所属层产生所需失效，不让多个协作者分别取消并重建同一轨迹。具体数值求解、属性类型、端点精度与资源预算参数在相应实现设计中落实，不能改变上述职责。

## 9. 可观察验收

复用[统一测试应用](<../verification/2026-10-07-uilib-testing-spec.md>)，建立共享动效案例：状态切换、可自然展开的面板、可重排集合、拖拽回槽、滚动边界及显式存在性。案例本身只声明状态和动效，不持有进度、坐标补偿或手工 frame。

| 场景 | 预期反馈 |
| --- | --- |
| 连续切换目标、途中反向及修改阻尼 | 弹簧位置和速度按当前状态续接，有限曲线保持既有反向语义，无旧端点跳回 |
| 同一经过时间使用不同帧间隔，穿插重复 prepare | 当前结果在求解精度内一致，无重复推进；较大时间间隔不产生非有限值或业务动作重放 |
| 面板自然高度、文案、字号或窗口在途中变化 | 目标自动更新，子内容按真实尺寸排版，页面无读回高度或重建补偿 |
| 动画中点击条目、移动浮层来源及编辑文字 | 所见对象与命中、锚定、裁剪、文字定位一致；合法草稿和节点身份保持 |
| 父子同时重排并在过程中滚动 | 位移不重复计算，滚动立即响应，Tab 沿逻辑顺序 |
| 拖放、取消及接管释放轨迹 | 正常结束只发所属业务意图；取消无提交，新的输入不被旧运动抢回 |
| 嵌套滚动到边界、反向及范围缩小 | 祖先接续和范围隔离保持，有效偏移不越界、不积压虚假距离 |
| 显隐快速反向、删除后同键返回及达到退场预算 | 合法显隐续接；已删除身份不复活；退出立即失去输入，资源按声明释放 |
| 途中关闭动效、卸载、重挂与结束页面 | 立即服从当前策略，无旧回调、幽灵命中、迟到焦点或持续调度 |
| 运动结束后连续静止呈现 | 活跃轨迹与退场记录清空，恢复几何及 PaintPlan 的静态复用 |

稳定运动求解用实际代码和可复现时序验证，关键集成经生产 PageSession、布局、路由和软件回放验证；视觉质感还须在真实桌面窗口观察连续画面。记录实际执行的环境与证据，不把数值用例等同于体感，不把桌面结果外推为 MC 或原生设备验收。

## 10. 合同归属与落地顺序

通用运动、统一时间及存在性动效归本专题；主题只维护默认角色与被动悬停，布局/动态结构/滚动/拖放模块维护各自约束并引用动效合同。现有有限过渡的通用条文迁入唯一归属，邮箱等明确参考行为继续保留，不形成两套并行时间或身份规则。

落地先打通目标声明、弹簧推进和主题策略，再接入布局共同几何与自然尺寸；随后落实存在性、拖拽释放及滚动回弹。各阶段使用同一共享案例取得反馈，最终覆盖完整体系。每阶段的接口、施工拆分与验证命令另放临时实现计划；规格只维护共同语义与可观察验收。
