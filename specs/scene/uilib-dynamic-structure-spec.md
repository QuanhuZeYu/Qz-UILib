# UILib 动态节点结构与交互身份规格

状态：正式模块规格。

## 1. 范围、职责与效力

业务通过状态和声明表达节点增删、重排、替换、折叠及明确移动；Core 协调节点生命周期、绑定、布局、绘制和有效输入目标，业务不手动同步这些机制。

本模块维护动态声明如何对应持续存在的节点，以及何时结束或迁移对应关系。既有生命周期与输入总合同在[核心规格](<../2026-10-07-uilib-core-contract-design.md>)维护；草稿与组字目标在[编辑规格](<2026-10-07-uilib-editing-spec.md#2-动态结构中的编辑目标连续性>)维护；打开、关闭和宿主装配在[页面接入规格](<../host/2026-10-07-uilib-page-host-spec.md>)维护；主题及标准控件默认行为在[主题规格](<../content/2026-10-07-uilib-theme-spec.md>)维护。

公开接口、所有权表达、差异算法、Owner 组织、输入联系、缓存和调度由实现设计选择，须满足本规格行为，不冻结现有字段或签名。

实现优先复用 scene、响应式、标准控件与 PaintCommand。范围限于无平台 Core；Minecraft、GLFW、SDL、原生 IME、剪贴板和 GPU 事实归宿主。虚拟列表、离场动画、撤销删除、节点池、全局键注册表、跨页面连续挂载、业务任务取消及失败回滚不属于本合同。

## 2. 动态声明与节点连续性

### 2.1 条目匹配

**业务提供稳定的条目对应关系；Core 据此延续节点，不凭位置或外观猜测身份。**

动态数据列表以所属声明集合内的稳定业务键匹配条目；键不替代节点 UUID，不同集合的相同键不代表同一节点。明确提供既有节点的序列可以按节点身份表达连续性，不强制所有声明都提供业务键。

同一集合内持续存在的键，数据更新或重排延续原节点；条目绑定及业务操作使用当前数据，不捕获并继续操作过时数据。改变键或明确替换条目开启新节点生命周期。同键下改变内部内容不等于替换整行；需要替换时明确声明，框架不通过控件类型或文案相似度决定继承状态。

重复键、重复节点身份、双重归属、环或使用已销毁节点属于无效声明，诊断应定位所属声明与冲突对象。键的表示及校验实现由设计选择；业务不能在同一条目存续期间改变其匹配含义。

### 2.2 退出、保留与销毁

**业务声明节点的拥有、保留或转移；Core 在节点退出拥有作用域且未被明确保留或转移时，自动销毁节点及其所属子树，释放所属资源。**

声明创建并拥有的条目退出生效后，相同键再次出现是新条目。显式引用并由调用方保留的节点移出时，只解除归属和挂载，逻辑生命周期由其持有者管理。公开声明必须能区分两类归属，不能由普通对象引用、调用栈或 GC 推测。

条件分支使用同一生命周期规则，不要求新增条件 DSL。页面关闭按页面与核心规格结束接入、释放所属资源，不永久删除调用方明确保留的逻辑树。

**业务或上层模板决定高级筛选需要保留哪些节点和状态；Core 执行明确声明，不默认缓存已退出条目。** 保留可以通过折叠仍存在的条目、明确持有子树或持有独立业务/编辑状态表达。独立状态与共享服务不随行控件销毁。

### 2.3 折叠

**业务声明折叠及需要的占位容器；Core 将折叠子树移出布局、绘制和命中，展开后按当前条件重新布局。**

折叠保留逻辑节点及所属状态，不贡献兄弟间距或滚动内容范围。展开使用当前内容、主题、字体及可用空间。折叠不提供隐藏但占位语义，不冻结最后可见尺寸；需要空白空间时使用明确外层容器与尺寸声明。

交互释放、草稿不被隐含提交或取消、普通展开不恢复旧交互、真实模态进入与返回策略，统一引用[核心第 5—6 节](<../2026-10-07-uilib-core-contract-design.md#5-控件身份归属与生命周期>)。

### 2.4 同页明确移动

**业务通过状态和声明明确移动同一节点；Core 迁移归属、保持节点与挂载连续性，并按新归属核验交互资格。**

同一打开页面内，明确移动可改变节点逻辑父节点或位置，不通过先卸载再挂载实现，不重复建立已有绑定。新位置的布局、祖先显隐/禁用/裁剪及有效输入范围成为后续呈现与输入依据。持续合法的交互沿核心合同保留；不再合法的交互终止。主题与内容沿实际声明依赖更新，不增加隐式环境注入。

移动完成后，节点及所属子树归新作用域管理，结束原容器不销毁已迁移节点。不同集合的同键不自动推断移动，同一实例同时声明到两个位置仍是冲突。业务不手工 detach、补焦点或 capture 来维持连续性。

连续移动合同限于同一打开页面。跨页面的编辑状态选择、保留、共享及迁移由业务决定，引用[编辑规格](<2026-10-07-uilib-editing-spec.md#11-草稿提交与会话>)；已有明确保留、卸载和重挂能力按核心合同使用。

### 2.5 编辑目标

业务管理独立草稿、Core 终止失效组字联系、宿主提供组字来源与联系事实的合同，唯一维护于[编辑规格第 2 节](<2026-10-07-uilib-editing-spec.md#2-动态结构中的编辑目标连续性>)。本模块落实结构变化，不另定义编辑状态去留或组字恢复策略。

## 3. 结构变化的一致性

### 3.1 结算与事件顺序

**业务发布状态或意图；Core 决定结构结算与呈现合批，并在处理后续输入前使用有效结构及一致几何。**

纯状态/派生读取不隐含创建、挂载或销毁节点。结构声明由呈现协调落实；稳定来源不反复调用条目构造、重建绑定或全量布局。业务不调用 flush、layout 或 paint。

沿用核心第 3 节，尚未结算生效的连续声明写入允许合并成最终结果。例如一次结算前移除又加回甲，框架可以不落实中间退出；不承诺每次状态写入都触发节点生命周期通知。已经生效的退出、销毁或手势终止不能被后来返回抹掉；有顺序意义的输入、编辑和业务通知不得借合批丢弃。具体结算时机和调度由实现设计决定。

### 3.2 共同结构与几何

结构结算同时决定逻辑顺序、挂载关系、依赖绑定及交互资格；绘制、裁剪、命中和滚动消费核心维护的共同几何。范围缩小时按核心限制偏移，不附加滚动锚定或自动追焦点。

普通增删不重跑范围进入策略，也不把焦点交给占据原位置的新条目；真正的范围进入/返回与后续 Tab 按核心合同。手势 owner、capture、cancel 和物理尾部沿核心路由，不为动态节点另建恢复机制。

### 3.3 资源、诊断与效率

挂载绑定随卸载解除，移动不叠加，永久销毁释放真正所属的逻辑资源；外部业务 Effect 和共享资源仍归原持有者。节点逻辑资源的归属及释放入口是退出销毁合同的必要实现前提，不能以丢引用或挂载关闭代替。

无效声明、构造或绑定失败沿可定位诊断及页面既有错误通道暴露，完成必要所属资源清理。本合同不承诺事务回滚、上一结果保留、自动重试或替代节点。

优先框架正确，其次动态化、运行效率和内存占用。稳定状态不为动态能力每帧重建节点、重接绑定或全量布局。变化按实际依赖失效，允许必要的容器/子树求解，不承诺每次仅重算一个节点。缓存可失效、可释放且有明确生命周期。

## 4. 可观察验收条件

使用 [ScenePageSession.open](<../../src/core/java/club/heiqi/uilib/ui/scene/host/ScenePageSession.java#L24>) 创建正式页面，页面只声明状态、标准控件与业务动作。测试宿主供给窗口、度量、软件绘制和输入；通过 session 的 pointer/navigation/edit/frame/close 执行。frame 是宿主正常推进，页面业务不调用管线。复用[测试应用规格](<../verification/2026-10-07-uilib-testing-spec.md>)，不用测试专用树或生产接缝。

验收输出以业务动作记录、独立编辑状态、可见内容、实际位置与输入结果为主。

| 场景 | 独立业务期望 |
| --- | --- |
| 正在编辑订单甲时更新金额并交换甲乙顺序 | 甲的新金额出现在新位置；继续输入仍修改甲的原草稿和选区，乙不变；操作甲使用当前数据；Tab 按新逻辑顺序 |
| 按下甲按钮，移除甲并让乙占据原位置，再释放指针 | 甲、乙都不被这次尾部激活；下一次完整点击乙才执行乙业务 |
| 保留甲的合法按压，重排后移动指针到甲新位置再释放 | 按标准按钮规则只执行甲的动作；乙不会因旧坐标或新位置继承按压 |
| 将当前编辑字段替换为文案相同的新对象 | 新对象不自动获得旧焦点、选区、手势；旧编辑状态由业务继续持有且不提交；明确绑定同一状态时仅复用该状态 |
| 声明拥有的甲退出真实生效，后来同键甲返回 | 所属释放动作发生，返回是新控件；业务保留的草稿仍可显式绑定，不恢复旧输入联系 |
| 显式保留子树移出、外部数据变化、再挂入 | 离开时无输入和挂载回调；返回显示当前数据；新操作只响应一次，外部共享服务仍可用 |
| 折叠含焦点/按压目标的区域，再更新主题并展开 | 区域不占空白间距，不绘制或接收输入；展开使用当前主题/数据，不夺焦点、不续接旧按压 |
| 删除滚动列表末段，再反向滚动并点击可见行 | 视口按新内容范围限制，无幽灵行或额外滚动积累；画面所见行与业务点击对象一致 |
| 同一批次前一按钮动作移除编辑目标，后续文本事件到达 | 旧目标不被修改；无新合法焦点时文本不落到任意邻行。组字关联另按编辑规格场景 |
| 同页将甲明确移入另一个有效容器，再释放旧容器 | 甲继续呈现并只接收一次有效更新；释放旧容器不误释放已迁移甲。移入禁用或隔离范围的变体终止交互 |
| 不同列表各用键甲，且各自绑定独立编辑状态；同列表重复键甲 | 前者互不串草稿或事件；后者明确报声明冲突，不合并或默默覆盖 |
| 甲数据值更新但键不变；随后更换键或明确替换 | 数据更新继续使用原甲及其编辑状态，业务操作使用当前数据；更换键或替换后不继承旧交互 |
| 一次结算前移除又加回甲；另一轮先使退出生效，再加回 | 前者允许保持原甲而不承诺中间生命周期动作；后者必须释放旧甲，新甲不能接续旧输入 |
| 无状态/环境变化连续呈现，再只改一条业务内容 | 稳定期间无条目重建、绑定重接或布局求解；变化后目标内容自动更新，未变条目的编辑/交互状态连续 |

资源与稳定性观测可使用已有 NodeBinding/Owner 扩展的挂载建立/释放行为、正式 SceneControl.measure/arrange 调用、现有度量服务调用及常规 profiler；单看文字度量次数不能证明没有布局，需结合排列调用或布局入口观测。永久逻辑资源的释放验收使用正式生命周期能力，不以页面 own 或挂载关闭冒充永久销毁观测；不添加测试专用计数器或读取内部缓存快照。软件画面与输入结合验证命中，须使用实际软件光栅 replay；仅记录 PaintPlan 的宿主只证明计划与路由，不能冒充像素证据。业务预期不从待测布局算法复制出来。

注入组字/物理事件仅验证 Core 语义；Windows、SDL、GLFW、Minecraft 原生输入及 GPU 各按实际环境取证，记录提交、执行命令和结果。
