# Droppable 与 Sortable 规格

状态：已确认模块规格。

在既有 Draggable 上补齐 dnd-kit 风格接收与排序能力。参考为同一新版 [Droppable](https://main--5fc05e08a4a65d0021ae0bf2.chromatic.com/?path=/docs/react-droppable--docs) 与 [Sortable](https://main--5fc05e08a4a65d0021ae0bf2.chromatic.com/?path=/docs/react-sortable--docs)。实现使用 UILib 自有声明、信号、布局及输入，不引入 Web 库。

## 目的与职责

页面声明稳定的来源键、接收区、接收规则与权威集合；框架维护拖动会话、当前有效候选与临时呈现。放下只发布一次明确业务意图，调用方决定数据、顺序及归属如何变化。取消只结束临时交互，不写入业务集合。既有 [Draggable](<2026-10-15-uilib-draggable-spec.md>) 的激活、把手、位移约束、预览与生命周期保持。

本模块落实两个通用原生控件及广场案例：单/多接收区；纵向、横向、响应网格和多容器排序，包含空容器、变尺寸、把手、禁用项、接收过滤及键盘操作。参考站中的第三方虚拟列表、树、表格及跨文档集成各有独立承载语义；这些集成不属于本模块已确认范围。

## 会话与接收区

显式拖放作用域归页面或组件拥有，不使用进程全局注册表。来源与目标注册归当前挂载，卸载释放，重挂不叠加。键在所属注册集合内唯一，重复声明给出可定位冲突；来源和目标可共享同一业务键以组成 sortable，来源本身不作为自己的接收目标。

接收区提供只读拖中/当前命中反馈。接收规则读取当前声明；隐藏、禁用、销毁、卸载、有效范围外、PASSIVE 层及裁剪后无可见区域的目标不参与。判定消费同批 SceneGeometry 的盒、裁剪和视口，不保存独立几何树。重叠目标按明确优先级、当前几何与绘制次序稳定选择；指针命中、矩形交叠及最近中心为可选择的碰撞策略，具体接口归实现。

正常放下在当前有效几何及接收规则上再确认目标；先清理临时会话，再发布来源/目标与落点意图，无目标不提交接收动作。等待阶段释放、ESC、失焦、来源失格、范围结束、卸载及异常清理不提交；迟到 MOVE/UP 不复活。目标动态退出只移除候选，不将旧目标带入下一次放下。键盘沿正式焦点与编辑命令移动，可选择有效接收目标；不新增原生监听器或捕获所有者。

## 纵向列表排序（SceneSortableList）

本节维护原有纵向列表组件；下节的多容器通用排序有独立的呈现合同与意图形状，两者不互相覆盖。

SceneSortableList 以独立条目键和行声明组成列表。拖动把手或键盘拾取时保留原节点/挂载/焦点及条目数据，只显示纯视觉预览和候选插入标记；排序目标根据当批真实变高行几何判断，不能用固定行高或显示序号代替身份。键盘上下选择相邻插入位置，正常 Space/Enter 或指针释放时只发一次 Move(key,beforeKey) 意图，beforeKey 为空表示末尾；候选位置未改变时不发布 Move。ESC、失焦、移除活动条目、范围结束或失格只结束临时交互，不更改权威顺序。

排序过程中靠近最近声明滚动视口边缘，按时间在正式 ScrollPosition 内连续滚动；指针停边仍继续，到边界/离开/结束停止。滚动使原槽离开可见范围时，预览来源仍为持续有效的列表容器。容器或所属范围失活仍按既有来源合同结束。自动滚动不制造业务 wheel 回调、不滚穿 modal/所属层到后台。无活动手势时不启动输入帧扫描或重建列表。

其字体来源页面消费只发布草稿移动意图，具体行身份、应用与持久化由[配置页面规格](<../config/2026-10-12-uilib-settings-page-design.md#31-字体与排版>)维护。

## 通用排序（SceneSortable）

排序使用稳定条目键与当前数据；原节点 UUID、持续挂载、编辑状态和合法焦点在同容器重排与同页跨容器移动中延续。多容器由同一个集合声明持有条目对应关系，不能用两个独立 repeat 的同键推断迁移。节点退出销毁、明确移动及输入资格继续遵循[动态结构规格](<uilib-dynamic-structure-spec.md>)，不改变其核心边界。

框架按当前真实盒求目标插入位置，支持纵向、横向、响应网格以及不同容器布局；不得以显示序号代替身份，或假定等宽/等高。拖中保留业务顺序，框架按临时候选顺序排列实际条目，邻项沿当前真实尺寸让位，来源只保留不可见的目标插槽，独立 PASSIVE 层呈现同尺寸条目反馈；不得以静止列表加插入线替代排序效果。让位与落下分别选择策略：原 `Transition / dropAnimation` 继续提供可自定义或关闭的有限过渡；显式 `reorderMotion / dropMotion` 非 null 时使用统一目标运动，优先于对应有限声明，null 交回原通道。弹簧从当前可见位置及速度向新插槽续接；减少模式使用短时单调过渡，关闭即时落到当前目标。放下/取消反馈进入当前业务实际位置，取消不写集合。动画的排列与命中仍消费共同几何，快速反向从当前可见位置续接，结束恢复静态复用。放下只发一次 Move(key, containerKey, beforeKey)，beforeKey 为空表示容器末尾，位置不变不提交。业务接受后沿正式结构声明更新；拒绝或未更新时仍按当前业务顺序显示。

普通子按钮/编辑器保持优先输入；声明把手后只有把手起拖。禁用条目不拾取，禁用容器不接收；接收规则决定跨容器资格。键盘 Space/Enter 拾取及确认，方向键按当前布局选择位置，ESC 取消，Tab/失焦结束手势；空容器仍可作为目标。

活动指针靠近当前有效目标容器的最近滚动视口边缘时，以正式输入帧及 ScrollPosition 连续滚动；静止仍推进，到边界/离开/取消/放下停止，不制造 wheel 业务动作或越过所属层到后台。可声明关闭或调整滚动速度；无活动会话不逐帧扫描候选或重建节点。窗口、字号、内容、主题及集合变化沿正式依赖重新测量或判定。

## 共享案例与验收

[共享测试广场](<../verification/2026-10-07-uilib-testing-spec.md#2-共享测试广场>)提供 Droppable 与 Sortable 独立入口，各宿主引用同一内容；页面只组合公共控件、状态与业务意图，接收/排序算法不藏在页面。案例运行不依赖公网。
