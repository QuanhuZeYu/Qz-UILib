# UILib 文本内容与富文本规格

状态：已确认模块规格；与核心规格共同构成项目规格体系，仅定义本模块职责。

共同状态、布局、生命周期、输入与平台边界遵循[核心职责规格](<../2026-10-07-uilib-core-contract-design.md>)；按职责选择规格见[规格入口](<../README.md>)。

本模块维护共同内容、文本几何、链接身份与 UILib 富文本 DSL；[Markdown 文档](<uilib-markdown-spec.md>)、[数学内容](<uilib-math-content-spec.md>)与[字体](<2026-10-07-uilib-font-renderer-spec.md>)分别维护所属合同。

## 0. 最终目标与职责

用户已确认最终方向：文本内容呈现及数学公式能力尽可能完整接近固定版本 VS Code 内置 Markdown 预览。参照为稳定版本、默认设置及无第三方 Markdown 扩展；Markdown 文档解释、主要阅读行为与其数学插件/引擎支持范围共同定义对照目标。最终能力须按实际参照的语法、命令、环境、宏行为及排版质量建立支持矩阵与独立对照语料，不能以“常用子集”或当前实现能力代替最终范围。完整 LaTeX 文档编译、任意宏包及第三方 VS Code 扩展不因该目标自动纳入；参照中实际支持的数学能力不得据本节的阶段范围永久排除。

语义一致、功能范围及视觉质量分别验收：文档结构/语法与公式解释使用相同输入对照；公式基线、间距、数学样式与伸缩字形须有实际呈现证据；页面字体、主题、空间适配由 UILib 声明系统管理，不要求像素复制浏览器页面。允许差异逐项登记原因及可观察结果，旧有刻意差异须在相应阶段重新对照，不因已实现而自动保留。固定版本、依赖及默认配置以可核实的参照证据为准，升级参照需同步对照记录。

UILib 自有富文本 DSL 的语法仍由本规格定义，它与 Markdown/HTML 是独立输入转换入口；各入口生成共同内容，复用同一文本、数学、图像、布局、绘制与输入职责。共同内容的扩展按已知能力组织，不因最终范围而先造通用执行框架或第二套排版。

公开输入包含显式 PLAIN、RICH_TAGS、Markdown 及声明式共同文档。PLAIN 保持标记字面内容，§ 在 PLAIN/RICH_TAGS 中均为普通文字；平台旧格式转换只归宿主适配。

## 1. 字体、文本与数学排版

### 1.1. 模块职责与数据流

文本调用方提供内容、显式内容模式、样式和可用约束；解析层生成内容结构，排版层结合字体与约束生成行、块及公式几何，绘制层消费同一结果。标准控件和自定义控件共用这一流程，不通过字符串长度、手算字宽或控件内部节点拼装另建文本布局。

原始文本、自有富文本标签与 Markdown 是明确选择的内容输入，不按文本中出现某个符号猜测模式。Minecraft § 格式不属于 UILib 公开内容体系；原版行为适配停留在宿主职责，不改变这些内容模式的语义。解析不调用宿主绘制、修改业务状态或触发链接行为。

内容结构与显示几何分开：窗口、字号或字体改变可以重新排版，不要求业务重新提交源码。稳定源结构、来源和声明身份与基础样式派生分开；宿主可提交中性属性意图，未声明字体、字号及颜色分量继承当前基础样式，不保留宿主格式规则。内容、样式和资源变化按实际依赖失效；稳定内容不需要每帧重新解析。同一呈现批次的测量与最终布局共享对应请求的文字事实，内部模型及缓存接缝不形成冻结的公共 API。

### 1.2. 文本几何与交互

测量、换行、省略、基线、绘制及链接区域使用同一次排版的文本与字体事实，遵循[核心规格第 3.4 节](<../2026-10-07-uilib-core-contract-design.md>)渲染批次更新。多行链接按实际可见片段命中，祖先裁剪仍有效；点击发布链接目标或动作给调用方，不由解析器代替业务执行外部行为。

链接的内容/主题/字号/可用宽度变化自动重排；多行链接仅在当前排版的可见片段内命中并遵守祖先裁剪、滚动及有效挂载/交互资格，激活只发布声明目标给业务。没有基准位置解析声明时目标保持原值，业务不用为局部命中补节点或几何。同节点内不同链接声明有独立身份；正常嵌套的链接在内层内容范围采用内层目标，闭合后恢复外层声明。同一声明的身份不因仅重新排版或基础样式变化而改变，新内容声明即使源码与目标相同也使用新身份。按下与释放须命中同一有效链接，内容声明替换、失活、卸载或取消后不复活原手势。链接按完整文字簇参与片段命中，不切分 Unicode 字形簇；簇跨声明边界时归属其起始逻辑位置，边界冲突提供诊断。

Unicode 内容处理不能以 UTF-16 单个 char 作为任意可切割字符，把代理对截成半个字符。编辑与排版共用纯 Unicode 字素规则和版本来源，字形簇可因整形更大，编辑不依赖字体或字形资源。布局记录最终方向与逻辑—视觉边缘，控件消费这些事实，不重新以另一方向或显示投影解释。自定义规则来源提供稳定不可变快照，调用方协调替换并经现有字体失效入口通知呈现；局部字体规则重载不更改其他独立消费者。文本编辑沿[编辑规格](<../scene/2026-10-07-uilib-editing-spec.md>)处理光标与选区；只读显示的切行、省略及复制应保留可解释的原内容关系，不把画面省略号写回业务原文。复杂字形与平台字体支持边界须在字体能力设计中明确，不凭已有测量函数声称全部脚本完整支持。

文本内容及样式的原文由调用方持有；框架负责其排版和呈现。缺字、无效内容或不支持语法的处理必须有明确结果，不能静默截断整段内容。具体语法集合及降级合同由本规格第 2 节、[Markdown](<uilib-markdown-spec.md>)与[数学规格](<uilib-math-content-spec.md>)维护。

### 1.3. 字体专项入口

字体选择、缺字回退、资源生命周期和自有渲染器的权威合同独立维护在[字体渲染器专有规格](<2026-10-07-uilib-font-renderer-spec.md>)。本节只登记入口；共同文本流程仍按第 1.1—1.2 节，原生坐标按[核心规格第 9 节](<../2026-10-07-uilib-core-contract-design.md>)，专项字体约束不在此重复。宿主合批、原版字体替代的提交范围及无平台渲染验证另见[MC宿主渲染优化专题](<../host/2026-10-07-mc-host-render-optimization-spec.md>)。

### 1.4. 数学内容入口

公式语法、盒布局、嵌入内容、完整交付与验收统一由[数学规格](<uilib-math-content-spec.md>)维护。

### 1.5. Markdown 文档入口

文档解释、固定 VS Code 参照、HTML 子集、frontmatter 与公式定界统一由[Markdown 规格](<uilib-markdown-spec.md>)维护；UILib DSL 由下节独立定义。

## 2. UILib 富文本 DSL

UILib 富文本是独立 DSL，与 Markdown 的 HTML 子集分别解释；同名标签不自动获得 HTML 属性。下表定义标签、属性及正常内容语义，图像沿专用合同。解析只生成共同内容与样式意图，不修改基础样式或其他内容；字号使用 logical px，变化传播遵循[核心规格第 3 节](<../2026-10-07-uilib-core-contract-design.md>)。公式和图像复用既有系统，不在解析器上传纹理或另建布局。序列化保存文字及样式语义，不要求与输入字节一致。

### 2.1 正常内容合同

RICH_TAGS 首次非法语法或未知声明产生可定位诊断后，整段按 PLAIN 呈现且不生成链接，不发布半解析内容、不修复语法。诊断保留 UTF-16/byte 来源单位及原范围。正常 DSL 合同见本节，Markdown 与数学分别由所属规格维护。

用户已认可：统一使用小写标签、具名属性和双引号属性值；各属性只按下面的 DSL 合同解释，不接受任意 HTML 属性。

| 声明 | 正常内容含义 |
| --- | --- |
| `<b>…</b>`、`<i>…</i>`、`<u>…</u>`、`<s>…</s>` | DSL 中分别声明粗体、斜体、下划线及删除线样式，局部作用于内容 |
| `<color value="颜色">…</color>` | 声明文字颜色，颜色值采用 #RRGGBB（不透明 RGB）或 #AARRGGBB（显式 alpha）表示 |
| `<mark>…</mark>`、`<mark color="颜色">…</mark>` | 声明文字背景高亮，未声明颜色时使用主题高亮色 |
| `<sup>…</sup>`、`<sub>…</sub>` | 上/下标内容，由排版协调字号、基线及行高，不固定旧倍率 |
| `<size value="字号">…</size>` | 声明绝对 logical px 字号，有效范围沿统一字号能力 |
| `<spacing value="字距">…</spacing>` | 声明 logical px 字距，允许表达有效负字距；有效范围在统一样式能力中定义 |
| `<a href="目标">…</a>` | 声明链接内容，复用目标解析及激活合同，不导入浏览器事件或任意属性 |
| `<br/>` | 显式硬换行 |
| `<latex>源文</latex>`、`<latex math-style="模式">源文</latex>` | 公式内容捕获到对应闭合，不解析内部 DSL 标签；模式为 text/display/script/scriptscript，缺省为 text，模式决定数学排版样式，不自动改变外层文档块结构 |

成对标签按正常嵌套组织内容，内层只覆盖声明的样式属性，闭合后恢复外层；重复相同样式仍保持独立作用域。源码显式使用 `&lt;`、`&gt;`、`&amp;` 表达字面尖括号及与号，解码后作为内容，不重新识别为标签。序列化重新解析应保持已支持内容和样式语义。

旧 `<color=…>`、`<size=…>`、`<a=…>`、通用 `</>` 等写法是否兼容不由本合同承诺；不为兼容预建双语法解析。图片入口沿[图像规格](<2026-10-07-uilib-image-spec.md>)专用能力单独定义，不在此表增加 img 属性合同。未知/无效 DSL 输入只沿统一诊断职责处理，本合同不增加自动补闭合、错配吞标签、属性截断或失败恢复策略。

### 2.2 图像入口

用户已认可：用无正文的 `<img src="来源" alt="替代文字"/>` 声明行内图像；src 为必需来源引用，alt 可选，省略时不编造替代文字。图像是独立内容项，不是修改后续文字的样式标签，不要求闭合内容或嵌套子节点。

| 属性 | 进入统一图像系统的意图 |
| --- | --- |
| src | 文本来源引用，由文档基准位置及环境正式适配解析为[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.5 节来源 |
| alt | 可选替代文字，使用[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.4 节已确认状态呈现 |
| width、height | 可选 logical px 尺寸；未声明时自然测量，单边声明按有效比例求另一边 |
| fit | 可选 contain/cover/stretch/original，分别映射[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.6 节等比完整显示/等比铺满裁剪/拉伸/原尺寸；缺省 contain |

远程地址、资源标识及相对来源使用现有来源解析职责。运行时位图、纹理区域和物品等结构化来源由调用方正式声明并通过引用关联，不将位图字节、纹理句柄或 ItemStack/NBT 编进标签；具体关联接口由设计明确。来源更新自动影响图像内容与排版，不要求业务改写整篇字符串以更新已引用数据。

图像度量、行高、裁剪及输入由统一内容布局协调，尺寸和适配仅映射既有图像合同。物品动态渲染及宿主原版 API 路径保持[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.7 节合同。此入口不新增自动链接、物品覆盖层/提示或独立加载/重试机制；无效输入沿既有诊断职责处理，图像状态沿[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.4 节处理。

## 3. 共同内容与 DSL 验收

| 场景 | 可观察结果 |
| --- | --- |
| DSL img 来源、尺寸与适配 | src/alt/width/height/fit 按独立图像合同解释，单边尺寸保持比例，图像参与行高及共同裁剪 |
| DSL img 结构化来源动态更新 | 正式引用关联的位图/区域/物品变化自动影响排版与呈现，业务无需改写整篇字符串 |
| DSL 具名属性与嵌套重复样式 | 按正式语法解释，内层覆盖声明属性，闭合恢复外层，重复样式保持独立作用域 |
| DSL 字面实体及序列化往返 | 解码内容不重新识别为标签，重新解析保留内容及样式语义 |
| 相同标签名在 HTML 与 UILib DSL 中 | 按显式输入模式及各自合同解释；DSL 自定义标签不自动进入 HTML 子集，同名不导入全部 HTML 属性 |
| 同一内容切换明确输入模式 | 内容按所选模式解释，其他模式的控制符不混入解析 |
| 字体来源、候选或资源变化进入共同内容 | 字体结果按[候选合同](<2026-10-07-uilib-font-renderer-spec.md#24-字体优先级>)及[字体验收](<2026-10-07-uilib-font-renderer-spec.md#54-验收对应表>)核验；本模块验证共同内容自动更新，相关几何与输入一致 |
| 字体、字号及可用宽度变化 | 同源内容自动重排，测量、行高和实际画面一致，无业务字宽补偿 |
| 多行链接及嵌套裁剪 | 只在本批次可见链接片段内命中，激活发布当前解析目标；未声明基准位置时保留原值 |
| 字体资源更新与控件卸载 | 无旧度量/新字形混用，无有效绘制访问释放资源，共享字体不被单控件卸载销毁 |

自动场景验证生产解析、状态、排版、绘制与输入；宿主实机分别核验实际画面、裁剪与命中，记录对应版本、实例及操作。数学使用集成平台真实字体和 GPU 图像自主验收、完整交付后统一用户实机验收的约定由数学规格第 4 节维护。

输入/输出验收按已确认语法、降级合同及支持矩阵持续维护，不以本表替代语法覆盖。
