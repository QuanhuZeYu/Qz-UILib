# UILib Markdown 文档规格

状态：已确认模块规格；从文本内容规格拆出既有文档合同。

本模块维护 Markdown、HTML 内容子集、frontmatter 与文档中的数学入口；共同内容及链接身份归[文本规格](<2026-10-07-uilib-text-content-spec.md>)，公式内部语法与布局归[数学规格](<uilib-math-content-spec.md>)，图像来源与适配归[图像规格](<2026-10-07-uilib-image-spec.md>)。共同几何与生命周期遵循[核心规格](<../2026-10-07-uilib-core-contract-design.md>)。

## 1. 目标与固定参照

用户已确认：Markdown 以 CommonMark 为基础，明确增加表格和数学公式扩展，不承诺完整浏览器 HTML 或脚注等所有扩展。CommonMark 是基础语法的语义对齐依据，不凭旧实现子集、聊天防误伤特例或旧测试结果替换其规则，也不凭采用本方向宣称生产实现已通过一致性验证。具体对齐版本和采用库由实现设计明确。

用户进一步确认：对齐 VS Code 内置 Markdown 预览的文档解释及主要阅读行为，排版、绘制和资源管理仍完全使用 UILib。参照环境固定为选定 VS Code 稳定版本、默认预览设置、未安装第三方 Markdown 扩展；固定参照为 VS Code 1.140.0（commit 07f806f999227108933c2e30515b26eecc1fda74），内置 Markdown 依赖 markdown-it 14.2.0，内置数学扩展依赖 @vscode/markdown-it-katex 1.1.2，其数学扩展锁文件及实际安装 bundle 使用 KaTeX 0.16.21（不以其他扩展或根工程的 KaTeX 版本替代）。[固定数学扩展依赖证据](https://raw.githubusercontent.com/microsoft/vscode/07f806f999227108933c2e30515b26eecc1fda74/extensions/markdown-math/package-lock.json)。记录默认设置，不将持续变化的 main 分支或插件输出作为漂移的验收标准。选定版本是对照环境，阶段范围沿[文本规格的最终目标](<2026-10-07-uilib-text-content-spec.md#0-最终目标与职责>)；其完整内容与数学能力作为最终对照目标，尚未纳入阶段的能力须在后续支持矩阵中追踪。

对齐覆盖文档结构、语法解释、主要换行行为、链接、图片及公式；字体、主题、间距等由 UILib 声明系统协调，不承诺像素级复制 VS Code 页面。HTML/CSS、公式命令、来源解析等能力差异须在本 spec 明确列出，最终数学范围对照该参照实际采用的引擎能力，阶段子集须明确登记差距；“对齐 VS Code”不自动承诺完整浏览器或任意 TeX 执行环境。受支持 HTML 转换为 UILib 内容结构，不自动改走 RICH_TAGS 模式；已认可的标签类别见下文；不支持内容按下文已确定的降级规则处理。

## 2. 文档解释与来源

文档可声明基准位置，框架负责相对图片来源和链接目标解析；业务不拼接路径或接管图片下载。环境适配提供基准位置的解析能力；来源能力仍遵循[图像规格第 1.5 节](<2026-10-07-uilib-image-spec.md#15-已确认的来源范围>)，本条不自动开放任意文件路径。链接激活仍发布解析后的目标或动作给调用方，执行归业务/宿主，解析不执行动作。

基础文档能力包含段落、软/硬换行、标题、分隔线、引用、有序/无序及嵌套列表、围栏/缩进代码块；行内包含强调、粗体、代码、转义及链接。代码内容按代码语义保留，不再解析成公式、富文本或动作。列表层级和引用等结构由排版体现，不用向业务字符串插入固定空格代替结构布局。

表格扩展提供表头、正文行、单元格及列对齐，单元格参与统一行内解析与排版；列宽、行高、换行和溢出处理由框架按可用约束及页面策略协调，不要求业务手算表格几何。它不自动成为可编辑 DataTable，文档展示与编辑控件的业务职责分开。采用管道表格语法：表头之后紧接分隔行，分隔单元格以连字符及可选冒号表达列对齐；左冒号为左对齐，右冒号为右对齐，两侧冒号为居中，无冒号使用默认对齐。表头与分隔行的列数必须匹配，不能匹配时不识别为表格，按正常文档规则解释。正文行缺少的单元格补空，超过表头列数的单元格不进入显示表格，不扩展列数；源文仍由调用方保留。这是已认可的表格语法规则，不将超出的单元格作为解析故障或未知 HTML 字面降级。转义管道、首尾管道及块结束边界按固定 VS Code 参照版本核对。

框架默认根据可用空间和内容求列宽，协调单元格换行及行高；内容仍超宽时提供表格自身的横向滚动视口，不将整篇文档撑宽。图像/字体/公式及窗口变化自动更新列布局和滚动范围；框架不把不可拆分内容强行切断以满足宽度。横向滚动遵守共同几何、裁剪和输入范围合同，业务无需设置列宽公式或维护横向偏移。具体列分配算法及滚动控件样式由设计完成。

Minecraft 的 § 格式码不作为 Markdown 解析核心语义；宿主若需保留颜色或其他来源样式，先明确转换为内容样式，再以统一规则参与解析及呈现。样式片段分割不是 Markdown 文档边界，相同内容不会因宿主分成多个片段而改变语法解释。

Markdown 支持图片语法与内嵌显示，图片来源、替代文字及尺寸/适配意图进入[图像规格](<2026-10-07-uilib-image-spec.md>) UILib 专有图像系统，与普通图片控件共用加载、测量及资源管理；业务不自行下载、补算尺寸或手动触发重排。完整浏览器 HTML/CSS 不在本次已认可范围内；HTML 采用下述内容子集，其超出部分的显示差异须明确，不采用全部 HTML 默认字面显示的独立提议。按固定参照，默认支持 `~~…~~` 删除线、完整 URL 及邮箱自动链接；关闭模糊裸域名识别，`example.com` 与 `www.example.com` 不自行变为链接。默认 breaks=false，段落内软换行不强制形成硬换行；显式硬换行保持原语义。默认 typographer=false，不自动美化引号或替换普通标点。自动链接复用既有链接目标及激活合同，不隐含自动打开外部程序。未支持内容不能被静默丢弃，失败或字面显示须具有明确合同。脚注、任务列表等未认可扩展不因 Markdown 名称而自动承诺，也不依据旧代码排除将来的正式扩展。

基础阅读的独立语义对照使用[固定 Markdown 阅读语料](<../../src/test/resources/markdown/reference/reading-corpus.json>)：由上述固定 markdown-it 与数学插件实际解析生成，而非由生产转换器生成期望；它不等于 VS Code Webview 或宿主实机。已明确的阶段差异：不为缺少原终换行的代码块伪造 parser 合成 LF 的来源；未闭合 `$$` 按正常文档呈现而不吞后续内容（详见数学块边界）；固定 VS Code 的 YAML frontmatter 默认表格按第 3 节转换为共同内容；固定扩展与 YAML 2.9.0 的独立语料见[frontmatter 对照](<../../src/test/resources/markdown/reference/frontmatter-corpus.json>)，识别、转换与明确差异见第 3 节。列表中合法 Tab 缩进的完整 `$$` 配对按 CommonMark 容器解释为一个公式块；固定数学插件在此输入上生成空公式并吞掉部分正文，UILib 保留全部公式内容，具体输入及实际参照 tokens 登记在上述独立语料的允许差异。普通行内数学首尾紧邻且内容长度大于二的 backtick 按固定插件入口剥去一对；DISPLAY、公式块及 math 围栏不采用该处理，不增加数学命令范围。

## 3. YAML frontmatter 默认阅读

文档首行无缩进 `---` 开始，后续无缩进 `---` 结束；分隔行可有尾部空白，首行 BOM 或前置空行不自动移除，`...` 不作为本入口的闭分隔。没有闭分隔时继续正常 Markdown，不吞正文。默认把映射的每个属性转换成一行共同表格，第一列为行头、第二列为值，不另造表头行；根标量或序列是一行空行头，根空值和空映射不呈现表格。数组递归为列表，对象为等宽 YAML 表示；标量与生成内容保持字面，不再解释 Markdown、链接、图片或数学。默认 YAML 1.2 core 与有效 YAML 1.1 指令、数字显示和属性顺序按固定参照实际运行核对，词法、节点与原位置采用成熟 YAML 能力。

错误由框架定位诊断并保留前缀源码呈现，后续有效 Markdown 继续解析；表格与生成内容保留完整输入身份、UTF16/BYTE 来源，别名内容关联引用位置。已认可的参照差异：固定扩展会把首行引用容器内部误认成 frontmatter 并以含容器前缀的 YAML 报错，UILib 保留正常引用正文；部分原始控制字符由所选成熟 YAML 解析器拒绝时，UILib 定位该字符并保留原前缀，不自行修补词法；这是明确的参照差异，不能据此任意扩大拒绝范围。循环序列无法展开为有限阅读列表时诊断并保留原文，循环映射仍沿成熟序列化展示。上述差异属于本模块合同，不将默认表格能力扩展为 hide/codeBlock 配置 API 或任意 YAML 对象执行。

## 4. HTML 内容子集

支持常用内容标签及相应必要属性，统一转换为 UILib 文档内容结构。业务不用把 HTML 拆成控件或自行写 HTML 几何；HTML 与 Markdown 内容共同参与[文本几何与交互](<2026-10-07-uilib-text-content-spec.md#12-文本几何与交互>)排版、链接命中及[图像规格](<2026-10-07-uilib-image-spec.md>)图像系统。

| 内容类别 | 支持标签 | 必要内容属性与职责 |
| --- | --- | --- |
| 行内文字语义 | strong、b、em、i、u、s、del | 保留所支持元素的内容语义，具体外观由 UILib 样式系统呈现；b/i/u 不仅作为视觉样式开关解释 |
| 换行与段落 | br、p、hr | 表达换行、段落及分隔结构，不靠固定空格排版 |
| 标题 | h1 至 h6 | 表达标题层级，由主题及排版处理尺寸和间距 |
| 列表与引用 | ul、ol、li、blockquote | 保留嵌套结构；ol 的 start 表达起始编号 |
| 代码 | pre、code | 保留代码内容及空白语义，不把代码内符号再解释为 Markdown 或公式 |
| 链接 | a | href 为目标，title 为可选说明；来源解析沿[文档来源合同](<#2-文档解释与来源>)，身份与激活沿[文本交互合同](<2026-10-07-uilib-text-content-spec.md#12-文本几何与交互>) |
| 图片 | img | src、alt、title 及有效 width/height 尺寸意图进入统一图像系统；不引入另一套加载器 |
| 表格 | table、thead、tbody、tfoot、tr、th、td | 表达表格结构，由共同表格排版能力测量、布局及绘制 |

属性值经内容转换验证，不将任意 HTML 属性当节点 setter；图片的尺寸属性按 logical px 尺寸声明参与[图像规格](<2026-10-07-uilib-image-spec.md>)第 1.6 节，属性无效时应有明确降级。属性未列入支持范围不自动获得浏览器语义；表格跨行/跨列、任意 class/style、额外标签等须有明确能力合同后纳入。

任意 CSS、脚本执行及浏览器交互不纳入本子集。链接及图片通过 UILib 正式能力处理，HTML 不建立独立输入系统。内嵌 HTML 的识别边界及与 Markdown 混合解析按固定 VS Code 参照核对；代码块或明确转义的 HTML 保持字面内容，不走 HTML 转换。不将所有 HTML 标签交给 RICH_TAGS 解析器猜测。

未知的普通容器标签忽略标签本身，保留其内部内容并按有效内容继续呈现；不支持的属性忽略，不破坏其他有效属性及正文。无法解释的内容保留为可见字面文本，并提供能关联源内容位置的诊断，不因局部问题截断后续文档。属性无效时不传入非法布局值，按未采用该属性处理并提供诊断。

script、style 等非正文内容不执行，其内容也不作为正文显示；这是明确的非正文处理，不适用于未知普通容器的正文。未知内容、被忽略属性及非正文处理与 VS Code 的实际差异应记录在对照验收中。语法嵌套及容错的具体实现由解析器设计确定，遵守保留可读内容和可定位失败的合同。

## 5. 数学内容入口

数学扩展使用 `$…$` 表达行内公式，独立 `$$…$$` 表达公式块；内容交给 UILib 数学能力，排版参与统一几何。行内公式随所在文本行协调基线和行高，独立公式块作为文档块参与布局。不能因不同调用出口而对同一源文采用两套默认定界解释。

行内代码、代码块以及明确转义的定界符保持字面内容。单美元定界按固定数学插件识别：开定界前不为美元、反斜杠或 ASCII 字母/数字/下划线，闭定界后不为美元或 ASCII 字母/数字/下划线；转义优先于公式识别，公式内部转义美元不作为闭合。`$x$`、`$ x $` 及同段内跨源码换行的配对可识别为行内公式；`a$x$b`、`$5 and $10`、不配对 `$x` 保持普通内容，中文紧邻 `$x$` 可混排。输入输出对照语料使用上述固定参照，不从旧聊天特例或解析器实现继承规则。不构成公式的文本按普通文档内容保留，不静默删掉。已识别公式内部的未知命令或排版失败属于数学内容能力及其降级合同，不退回另一套 Markdown 词法猜测。

### 5.1 公式块配对边界与参照差异

用户已认可：UILib 仅将完整配对的 `$$` 识别为公式块；未闭合时按普通文档解释并保留内容，不将后续正文收为公式。固定参照插件会将未闭合 `$$` 后的内容收为公式块，本合同明确记录该差异。这是语法识别范围，不增设自动补闭合、修复或恢复流程。math 围栏及裸数学环境的入口边界按下文合同执行；其他特殊内容入口不因固定版本包含它们自动承诺。

### 5.2 额外数学入口范围

用户已认可：首期支持信息字符串为 math 的围栏作为公式块入口，复用[数学规格](<uilib-math-content-spec.md>)能力及既有块排版；其他围栏按代码处理。此处 math 标识按固定参照去除首尾空白并忽略大小写，带其他参数的信息字符串不自动当作 math。

裸 `\begin{…}` / `\end{…}` 不自动启动数学解析；作为公式内部的数学环境按明确支持的命令/环境范围处理。这样外层识别入口与内部数学语言分别定义，不扩展 TeX 执行能力。本入口复用已确认数学能力，不引入完整 TeX 执行或额外恢复机制。

## 6. 文档验收

| 场景 | 可观察结果 |
| --- | --- |
| 未知 HTML 容器与不支持属性 | 内部有效正文保留，未支持属性不破坏其余内容，局部无法解释内容字面可见且诊断可定位 |
| 非正文 script/style 与后续正文 | 不执行、不将其内容显示为正文，后续有效文档仍完整呈现 |
| 常用 HTML 内容与 Markdown 混排 | 支持标签转换为共同内容结构，链接/图片复用正式能力；代码内标签字面保留，主题或窗口变化自动重排 |
| 固定 VS Code 内置预览对照语料 | 记录稳定版本及默认设置；同源文档对照结构、换行、链接、图片和公式，明确 HTML/CSS 等差异，不用旧实现自证 |
| 相对图片及链接与基准位置变化 | 框架解析当前目标并自动更新相关内容，无业务路径拼接；缺少解析适配有明确结果 |
| CommonMark 基础结构与行内组合 | 依据选定标准版本核对嵌套、定界和代码语义，不以旧解析器输出作为唯一 oracle |
| 同内容不同样式片段分割 | 语法解释一致，样式来源保留；片段边界不打断定界配对 |
| 行内公式、独立公式块及代码内美元符号 | 行内/块结构明确，公式交给共同数学排版；代码内定界符不启动公式解析 |
| math 围栏与其他语言围栏 | math 按公式块参与共同排版，其他围栏保持代码语义，代码内符号不启动数学解析 |
| 裸数学环境及公式内环境 | 裸 begin/end 不启动数学解析；公式内部只按明确支持范围解释环境 |
| 未闭合 $$ 与后续正文 | 按普通文档解释并保留内容，不收为公式块，不自动补闭合；记录与固定参照的差异 |
| 删除线、自动链接、软换行与标点 | 对齐固定默认设置，裸域名不自动链接，普通标点保持原内容 |
| 转义、不配对及金额歧义对照 | 以固定 VS Code 版本记录输入/输出，不构成公式内容保留，无旧出口词法分歧 |
| 管道表格列对齐及不规则正文行 | 冒号决定列对齐，缺列补空、超列不增加显示列；表头与分隔行不匹配按正常文档解释 |
| 超宽表格及动态资源变化 | 默认自动列宽/换行/行高；仍超宽时仅表格横向滚动，画面、裁剪及命中同步更新 |
| 表格与文本/公式混合 | 表头、正文、对齐与单元格统一排版；窗口变化无需业务重算列宽 |

输入/输出按本规格语法、明确差异及数学支持矩阵维护，不以本表替代语法覆盖。
