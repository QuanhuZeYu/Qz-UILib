# UILib 通用媒体播放规格

状态：用户已确认 core 通用能力及首期“稳定播放”目标；维护媒体语义与量化验收。

共同状态、布局、输入、生命周期与平台边界遵循[核心职责规格](<../2026-10-07-uilib-core-contract-design.md>)。本模块负责播放，不以媒体案例定义公共能力。

## 1. 目标与范围

业务声明媒体来源并表达播放意图，UILib 提供跨宿主一致的播放会话、时间轴、音视频同步和通用播放控件。首期覆盖受控 HTTP HLS 点播及滑动窗口直播、音视频和纯音频；播放、暂停、音量、静音及当前来源允许范围内的定位。

通用主线以 Java21 为目标；Minecraft 1.7.10 通过独立编译与装配接入，并继续满足核心第9节已确认的 Java8 运行组合。两种目标共用媒体语义与算法源，不复制一套旧版播放器，也不把新字节码混入旧运行组合。平台无关核心的加载与逻辑不初始化解码库、音频设备、GL、Minecraft、Forge 或 java.desktop。

core 播放会话不承担网页平台解析；平台接入通过第8节的独立来源适配提供事实。账户鉴权、DRM、低延迟直播、自动码率切换和自动重连不在本期。网络、解码与设备失败仍须可定位，并结束所属失败操作及释放资源。

## 2. 职责与资源归属

| 责任主体 | 所属能力 |
| --- | --- |
| 业务 | 选择来源、播放或暂停、有效定位目标、音量和静音；选择共享会话或由页面独占拥有 |
| core 媒体会话 | 共同状态、媒体时间与播放意图、播放代际、队列预算、同步决策、后台任务、取消和会话释放 |
| 媒体解码适配 | 读取、解封装、解码、颜色/格式归一化，提供真实媒体信息、带时间戳的音视频数据及读取取消能力 |
| 音频输出适配 | 本播放流的设备、context、PCM 队列及实际消费位置；可取得的设备输出延迟与采样时刻 |
| 呈现运行时与 GPU 适配 | 同批布局/裁剪/输入、有序视频命令、纹理上传/复用与实际帧提交记录 |

会话独立于 UI 挂载推进；业务不调用 layout、paint 或手动刷新才能使音频或状态成立。后台不直接访问节点或 GL；呈现绑定通过既有受控域/宿主资源入口接受变化。卸载视图只释放所属订阅和呈现联系，不擅自关闭外部共享会话。页面明确拥有会话时，页面结束释放会话。多个独立视图可以消费同一会话，各自保持布局身份。

## 3. 媒体事实与状态

媒体事实明确区分有无视频轨、有无音频轨、已知或未知时长、当前可定位区间、已缓冲区间与有效展示尺寸。未知时长不等于零时长或无限点播；纯音频不伪造透明视频帧。直播窗口、尺寸与能力变化通过通知更新，不能固定为打开时的快照。

播放意图与加载、就绪、播放、暂停、定位、缓冲、结束、失败、关闭等实际状态分别表达。打开尚无可用数据时显示加载；播放中供应不足时显示缓冲，不以进度继续增长冒充输出。

播放和暂停控制本会话真实输出。暂停冻结媒体时间并暂停设备出声，恢复不重放已消费 PCM。音量、静音只作用本会话，不修改系统或游戏全局音量。正常 EOF 待末尾音频与视频完成消费后结束，不因 demux 结束提前丢弃尾部。

错误保留来源、处理阶段及原始原因；失败状态和关闭可区分，不以空帧、零位置或自动选择另一后端隐藏问题。只在业务明确选择新来源/定位/重新打开时开始新的操作，不增加失败自动重试。

## 4. 时间轴、定位和同步

每个会话有独立身份；打开新来源、换源及定位更新输出代际。旧代视频、PCM、解码结果和迟到输出回执不能进入新代。暂停和普通控制不制造新代，也不取消其他共享视图。

媒体时间由真实输出驱动。有音频时以该代设备实际播放位置为主时钟，计入已从设备队列移除的数据基准、source offset 和可取得的输出延迟；无音频时使用单调时钟映射媒体时间。不能以已写入字节、已解码帧或 UI 累计 tick 代替设备消费。source 结束时 raw offset 归零不能使播放位置倒退。

定位只接受当前可定位范围内目标。有效请求使旧输出失效，清除旧待展示和设备队列；后端从可解码锚点预滚至目标，丢弃目标前数据。定位完成以目标画面实际提交及对应音频恢复为准，不能以底层 seek 返回成功算作恢复。目标附近允许的误差由实际完整帧时间范围解释，不硬编码只支持 30fps。

直播列表滑动更新当前窗口与时间线。暂停位置已退出窗口时，明确报告当前位置不再有效，并保留当前可定位范围供业务选择；不自动跳往新位置或重复请求过期片段。正常列表刷新与失败重连分别处理。

同步按媒体 PTS 选择需要展示的视频帧，对错过展示期限的帧作有界丢弃；不能靠播放过时画面维持表面上的零丢帧。每个应呈现帧最终计为实际提交或丢帧，重复回放同一帧不重复计数；主动定位、换源及关闭跳过的帧另列，不混入稳定播放丢帧率。

## 5. 帧内容、呈现与动态更新

视频内容具有不可变的会话/代际/帧身份、PTS、有效尺寸及像素事实。解码器不得覆盖已发布快照的底层数据。首期可复制到私有不可变展示存储；复用 native/池化缓冲前必须有覆盖计划缓存与重放的持有/退休合同，只读 ByteBuffer 不能代替底层不可变性。

视频控件复用 scene 正式测量、排列、绘制依赖与输入，外层盒及裁剪仍由框架维护。普通新帧只使绘制失效；实际尺寸/比例变化才使相关测量失效。完整显示、铺满裁剪和拉伸在已分配盒内执行，不扩大命中范围，不逐帧重建树或手工修正坐标。

播放案例优先将当前视口的可用空间分配给实际观看画面，来源编辑可收拢、精确数值控制为次级展开，主要播放操作与画面相邻。画布不以界面字号乘常数限制高度，实际视频默认保持比例完整显示。同页放大、来源展开、主题和窗口变化只改变正式布局，不重开会话、定位或覆盖地址草稿；当前播放来源与尚在编辑的来源区分。

视频通过同一 PaintCommand/PaintPlan 有序流和共享呈现输出；不把每帧声明成新静态图像来源加入共享图像缓存。纹理上传与执行恢复触碰的 GL 状态；同一个 Prepared 中精确帧身份对应的纹理内容保持固定，不能用后一次上传改变前一条命令。

首帧与实际提交以含该帧的正式回放完成提交为界，明确对应宿主交换边界。decode、纹理上传及 collector 入队不是实际呈现。统计中保留 frame identity 与单调时间，不能把同帧反复绘制算作持续新画面；该口径不冒充物理屏幕扫描或声学输出测量。

时间轴与音量消费正式通用Slider：外部值、拖动预览和最终提交分开；拖动时间轴不制造解码代际，释放按最新有效范围提交一次，范围/来源代际失效或ESC取消不能提交旧手势。缓冲范围与当前媒体位置分别绘制；音量滑杆只调本会话，精确字段在编辑/组字时保持草稿，外部同步不覆盖活动输入。

正常结束主操作为按当前起点重新播放；不可定位时明确重新打开来源。轨道确认纯音频后以紧凑来源/时间轴/控制替代黑色视频盒，加载期不提前假定无视频。直播正文表达当前有限窗口及落后边缘位置，过期暂停保持原位置并提供明确恢复，恢复选择当前窗口内留有播放余量的位置。

观看区只有取得自身合法焦点才处理Space播放暂停、左右相对5秒、上下音量与M静音；原按钮、slider、编辑框及前台模态维持自己的处理，普通重排不抢观看焦点。提示声明真实快捷键，不使用宿主全局监听。

## 6. 有界资源与关闭

对会话、解码队列的帧数/字节/时长、设备 PCM、当前展示存储及 GPU 纹理声明明确上限。背压控制读取，不无限累积；暂停时保持有界，缓冲预算不随播放时长增长。保存纯值旧计划的外部调用方拥有其引用，内部不得因自身复用改变旧计划内容；框架自身不累积历史计划。

关闭先拒绝新工作并使输出代际失效，再取消读取、结束所属 worker、清除队列、停止输出并释放 native/设备/GPU 资源。在所属合法线程与 context 执行，异常仍尝试其余必要清理，保留首错和 suppressed；重复关闭幂等。清理不关闭共享字体/图像服务、宿主音频 context 或其他会话。

## 7. 稳定播放量化验收

行为语义参照 [WHATWG 媒体模型](https://html.spec.whatwg.org/multipage/media.html)，总帧数/丢帧口径参照 [W3C 播放质量](https://w3c.github.io/media-playback-quality/)，HLS 参照 [RFC8216](https://www.rfc-editor.org/rfc/rfc8216)。不要求复刻浏览器 DOM API。

性能门槛绑定记录完整的参考机器、固定素材与受控服务；保留源码/产物版本、Java、OS/架构、GPU/音频设备、网络条件、样片哈希及原始样本。公开直播源仅作额外兼容性反馈，不替代受控基准。分位数与帧耗时统计沿[性能规格](<../verification/2026-10-14-uilib-performance-testing-spec.md>)，原始观测不在高频路径无界打印。

| 验收 | 门槛和口径 |
| --- | --- |
| 连续播放 | 固定 1920×1080、30fps 的 H.264/AAC HLS 音视频连续 600 秒；稳定阶段非预期缓冲 0、丢帧率 ≤0.1%；18000 个应呈现视频帧对应最多 18 个丢帧 |
| 音画同步 | 稳定播放绝对误差 p95≤80ms，最大≤150ms；视频实际提交 PTS 对比同单调时间采样下的设备播放位置；定位/主动暂停/缓冲区间单列，不能删除非预期缓冲掩盖连续播放失败 |
| 点播启动 | 从公开打开请求到首个有效视频帧实际提交≤2 秒；音频启动结果同时记录 |
| 定位恢复 | 固定目标序列恢复播放耗时 p95≤1 秒，从公开定位请求到目标帧实际提交与对应音频恢复；目标、原始时间和误差独立记录 |
| 控制 | 暂停时间轴与实际输出停止；恢复连续；换源/定位后旧代画面/音频不进入新播放；音量和静音仅影响本会话 |
| 直播与动态事实 | 正常滑动刷新可定位范围，长于初始窗口的真实播放无串代；当前窗口定位与过期暂停位置行为正确，尺寸变化只触发必要重测 |
| 生命周期 | 队列/字节/时长峰值均不超过所声明预算；连续开关20次后所属会话/任务/句柄/纹理回到基线；进程内存另作趋势数据，不伪称精确会话分配 |
| 平台边界 | 无平台 core 加载与逻辑不初始化媒体 native/GL/java.desktop；主线 Java21 与 1.7.10 独立产物分别验证，宿主证据不互相冒充 |

测试复用统一 TestApplication、真实生产会话和正式回放；纯核心行为反例与真实解码/设备/GPU 结果分别报告。MC 游戏实机按会话授权执行，不以 Desktop 通过替代；未执行项目准确保留其范围。

## 8. 网络平台来源与 Bilibili 接入

用户提交平台地址，独立来源适配解析内容身份、标题、作者、封面、分P、实际可用清晰度与媒体来源；core只定义共同结果，不识别BV或房间规则。解析和网络读取在后台执行，取消、切源、停止和页面结束后迟到结果不能恢复旧播放；后台不读写节点、GL或页面响应式状态，结果在正式输入帧接收。

通用来源表达不可变请求头及同一时间线的独立音视频输入。列表读取、片段读取、Range和定位重新打开均使用所属输入的请求信息；拒绝带换行的HTTP字段，不将请求头写入来源展示。两个输入仍归同一MediaSession、输出代际和音频主时钟；根据真实PTS返回音视频，统一暂停、定位、换源、EOF和清理。一轨先结束不终止另一轨；只要一轨打开失败便结束所属操作并释放已开资源。

首版 Bilibili 支持公开视频链接、BV号、b23.tv短链接和直播间地址；匿名读取当前允许观看的内容。点播选择实际返回的H.264与AAC输入，展示当前分P和清晰度；清晰度不以平台宣传的完整档位冒充匿名可用。直播优先HLS-TS/H.264，保留实际签名查询，并沿第4节维护当前窗口；未开播、权限限制、API拒绝和网络错误提供明确原因。接口变化由平台适配负责，构造与本地地址识别不联网、不加载native。

共享播放器展示标题/作者和来源封面，按剩余视口安排观看区；分P与清晰度选择复用正式控件。用户切清晰度时保留当前位置、播放或暂停意图、音量与静音；切分P从起点开始。用户可显式重新解析当前内容取得新播放地址，失败不自动重试。地址草稿与正在播放来源分开，异步返回不覆盖活动草稿。

来源解析限制并发、排队、结果、重定向及响应字节/结构深度，生命周期结束取消请求并释放所属worker。日常build使用受控网络验证必需头、分轨、定位、末尾、分P/清晰度、过时结果、失败与释放；Bilibili公网独立实测真实点播画面/PCM、暂停恢复/定位及直播新帧与列表刷新，公网可用性不作为可重复build的先决条件。
