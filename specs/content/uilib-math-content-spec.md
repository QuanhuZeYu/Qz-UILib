# UILib 数学内容与排版规格

状态：已确认模块规格；从文本内容规格拆出既有数学合同。

本模块维护公式语法、数学盒、嵌入及诊断；共同内容与链接归[文本规格](<2026-10-07-uilib-text-content-spec.md>)，文档入口与固定参照归[Markdown 规格](<uilib-markdown-spec.md>)，字形构建与资源归[字体规格](<2026-10-07-uilib-font-renderer-spec.md>)。状态、共同几何和生命周期遵循[核心规格](<../2026-10-07-uilib-core-contract-design.md>)。

数学后端的既有选择：宿主 Item 嵌入需要可扩展数学内容与尺寸/基线协议，成熟引擎并非原则上无法扩展；选择 UILib 自有解析和数学盒算法，是为了将中性嵌入内容作为数学能力的一部分。算法以成熟 TeX/OpenType MATH 规则与固定 KaTeX 参照对照，字形整形、光栅、资源及绘制仍复用现有字体/场景管线，不另造字体或输入体系。最终目标不因自制后端而缩减，支持矩阵逐阶段补齐。

## 1. 目标与职责

数学能力解析并排版明确支持的公式子集，作为可测量内容参与行内或块布局，字体度量、数学盒与实际字形保持一致。文本和公式混排由共同排版过程协调基线及行高，不由业务补算公式高度。

数学基础能力包括：分组、上下标、分式、根式、伸缩定界符、矩阵/分段、数学字体样式、常用符号与算子。基础能力不替代第 4 节固定参照内的数学宏合同；完整 TeX 文档编译、任意宏包加载与外部 TeX 执行不在范围内。具体命令与扩展范围由本节下属合同维护，完整交付范围见第 4 节；不能仅引用旧命令清单或测试作为新权威。

已确认的基础命令范围如下；符号、重音与扩展命令继续遵循第 4 节的完整支持矩阵，不据当前源码的容错或历史排版规则扩大合同。

| 类别 | 命令或结构 |
| --- | --- |
| 分组与脚本 | `{…}`、`^`、`_` |
| 分式及二项式 | `\frac`、`\dfrac`、`\tfrac`、`\binom` |
| 根式 | `\sqrt{…}`、`\sqrt[index]{…}` |
| 伸缩定界符 | `\left`、`\middle`、`\right` |
| 矩阵/分段/数组 | matrix、pmatrix、bmatrix、vmatrix、cases；array 支持 l/c/r 列声明 |
| 数学样式 | `\displaystyle`、`\textstyle`、`\scriptstyle`、`\scriptscriptstyle` |
| 数学字体及文本 | `\mathrm`、`\mathit`、`\mathbf`、`\mathnormal`、`\text` |
| 算子及上下限 | 常用函数、大运算符、`\operatorname` 及星号形式、`\limits`、`\nolimits` |
| 显式间距 | `\,`、`\:`、`\;`、`\!`、`\quad`、`\qquad`、反斜杠空格 |

数学源文与排版结果分开，动态字号和资源变化不丢源文；绘制继续走 UILib 管线。未知命令、无效结构或无法完成排版时，保留并呈现该公式源文，提供可定位到公式及错误位置/阶段的提示；其他有效内容继续解析和排版，不因一条公式失败使整篇文档消失。错误提示属于框架内容呈现，不由业务补写解析异常处理来维持文档。

伸缩符号及字体样式由数学度量与字形能力协调；准确支持、字体缺失下的近似或降级应有明确边界。不能把忽略未知命令、显示残缺公式或使用近似字形包装成完全支持。具体字形构建、数学盒算法及字体选择留给设计，支持范围及可观察降级在本 spec 补齐。

## 2. 自有数学与中性嵌入内容

用户要求公式可具有创造性的内容，例如积分的被积项、分子或上下标中显示宿主 Item。核心数学内容使用中性嵌入标识、尺寸和基线事实，不依赖 ItemStack、Minecraft 格式或宿主绘制入口。宿主将标识绑定到已有 SceneImage/图像来源；图像 pending/ready/failed、数量、耐久及提示继续归既有图像控件与资源协议。数学布局分配同一已挂载子节点的几何，输入、祖先裁剪、滚动、tooltip 和生命周期仍由唯一 scene/router 消费，不能用绘制回调偷偷创建宿主 GUI、第二树或第二几何。

基础数学命令沿第 1 节，嵌入协议增加 UILib 扩展 \embed{标识}。嵌入标识引用稳定直属子节点；同一公式中一个标识只能出现一次，重复或缺失绑定产生来源诊断并显示完整原公式，避免同一 Mount 拥有多个空间身份。多个图标使用独立标识/节点，可共享同一图像资源 identity。嵌入尺寸以当前数学 em 表示宽、高及从顶部到基线的距离，随数学样式/脚本字号缩放；嵌入协议使用明确分配的内联盒，不承诺任意节点的自然尺寸/min/max 自动求解。

数学源码解析一次得到不可变结构及 UTF-16 来源区间；动态主题、字号、字体和资源变化只重算布局。自有算法维护宽度、基线上下尺寸、数学轴、原子类别间距、脚本层级、分式净空与根式规则。正式字体必须有 OpenType MATH 数据；使用其常量、字形倾斜修正和真实伸缩字形，不能把普通字体的积分符号任意拉伸当作完整数学支持。根式等需要覆盖内容的伸缩目标超出实际可用字形/拼接能力、缺数学字体或字形时，诊断指出布局/字体阶段并呈现完整源文。显示型大算子按 `DisplayOperatorMinHeight` 优先选择满足建议高度的最小真实完整变体；若字体不提供满足该高度的完整变体，则使用最大的真实完整变体，并保持其原有墨迹及横向 advance。大算子选择与按内容定高的伸缩是不同职责，不非等比拉伸、不把整个建议高度冒充字形实际高度。完整原文呈现以既有普通文字候选可用为前提；显式排除全部字体时沿字体服务既有失败合同，不追加隐藏默认候选。普通文字按正常字体能力呈现；数学字体单独具名注册，不覆盖默认文本字体链；字体文件与许可均随包可核实。

独立数学控件及共同文档的行内/块布局消费同一不可变数学尺寸、基线和嵌入盒事实；文档与数学混排归[Markdown 规格](<uilib-markdown-spec.md>)，数学扩展能力归第 3—4 节。基础协议不以历史阶段范围排除已确认的矩阵、定界符、重音或宏；支持范围与已实现状态分别核验，未知输入不得半解析显示。数学编辑不因内容呈现能力自动纳入。

验收使用真实数学字体与 UILib PaintPlan：积分含图像嵌入，嵌入位于分式和上下标，嵌套分式/根式与双脚本不相交；改变主题、字号和内容后基线/尺寸/资源一致更新；窄 viewport 裁剪/滚动及可见图像提示走既有输入；错误公式显示源文且相邻公式不受影响；卸载后绑定与资源资格释放。离线纯盒断言不代替真实字形/GL，也不声称游戏物品与模组组合已实机通过。

## 3. 数学伸缩结构

伸缩结构沿第 2 节同一数学内容与嵌入协议扩展字形部件拼接、伸缩定界符和二项式，字形构建归字体服务，语法与盒布局归自有数学引擎；不改变核心树、平台、输入或宿主 Item 边界。

支持 \left 定界符 … \middle 定界符 … \right 定界符，允许嵌套及多个 middle，整个围合结构作为 inner 数学原子参与外侧间距，middle 在本层内容中按 relation 参与间距。left/right 必须在同一数学分组内配对；middle 的资格继承当前活动 left/right，普通花括号子组、分式参数和数组单元格内也可使用，right 仍不能穿过子组补配对。定界目标替换仅作用于围合本层及透明样式片段中的 middle；普通分组、分式和单元格内部的 middle 保留固定 size1 的真实字形盒，并以自身墨迹参与外层测量；合法的左右字符可不相同，点号 \left.、\middle. 或 \right. 表示不可见边界，不产生墨迹，保留 TeX null-delimiter 的布局间距，按根主题字号的 .12em 计算，数学 script 样式不再次缩小该空间。支持圆括号、方括号、转义花括号、竖线/双竖线、角括号、floor/ceil 及竖向单/双箭头的明确命令别名；定界参数为一个有效 token，不把任意普通字母当伸缩字符。错误位置保留 UTF-16 来源，沿既有整式原文呈现合同。定界 token 的支持表见下方，字符与命令名称大小写分别保持各自语义。

| 字形 | 定界 token |
| --- | --- |
| 不可见 | `.` |
| 圆/方括号 | `(`、`)`、`[`、`]`、`\lparen` / `\rparen`、`\lbrack` / `\rbrack` |
| 花括号 | `\{` / `\}`、`\lbrace` / `\rbrace`，未转义的 `{}` 保留分组含义 |
| 单/双竖线 | 字面 U+007C（单线）、`\vert` / `\lvert` / `\rvert`；`‖`、反斜杠加 U+007C（转义双线）、`\Vert` / `\lVert` / `\rVert` |
| 角括号 | `<` / `>`、`⟨` / `⟩`、`\langle` / `\rangle`、`\lt` / `\gt` |
| floor/ceil | `⌊` / `⌋`、`⌈` / `⌉`、`\lfloor` / `\rfloor`、`\lceil` / `\rceil` |
| 竖向箭头 | `↑` / `↓` / `↕`、`⇑` / `⇓` / `⇕`、`\uparrow` / `\downarrow` / `\updownarrow`、`\Uparrow` / `\Downarrow` / `\Updownarrow` |

同层定界符根据内部实际数学盒（含 Item、分式、根式和脚本）围绕数学轴选择共同目标高度，不参与计算自身目标；嵌套围合结构独立求解。字号、数学样式、字体及资源变化重新布局，原文结构保持不变。给字体服务提交该目标，完整变体选择、GlyphAssembly 部件与连接、轮廓和真实横向度量统一遵循[字体规格第 2.9—2.10 节](<2026-10-07-uilib-font-renderer-spec.md#29-数学字形部件构建>)；数学层消费不可变构建结果，不另维护字形拼接规则。

\binom{上部}{下部}，按当前 display/text/script 数学样式生成居中无分式横线的上下堆叠，净空使用 MATH stack 常量，圆括号覆盖堆叠内容；两部分均允许既有数学内容及独立 Item 标识。外侧按 ordinary 原子间距处理，字号随既有数学样式规则变化。分式变体、矩阵/分段/array、横向重音和宏范围由第 4 节完整支持矩阵维护；共同文档混排归[Markdown 规格](<uilib-markdown-spec.md>)。

验收覆盖超过最大完整变体的大型根式和圆/花括号、非对称高度内容、多 middle/嵌套/不可见边界、binom 无横线且上下间隙有效、内部 Item 盒和数量正常、外侧脚本及间距；真实字体部件与连接边界、实际 GL 拼接连续性、动态字号/字体重载与祖先裁剪；错配/缺少定界 token 的整式诊断及相邻有效公式。没有可用部件或目标超出实际资源/几何能力时，继续既有定位诊断及整式原文呈现，不新增重试、旧结果保留或其他字体替代策略。显示型大算子仍使用第 2 节完整变体策略。

## 4. 完整交付与集中验收

数学完整交付已获授权：由代理检查集成测试平台真实字体与 GPU 输出图像，最后统一用户实机验收；证据按实际环境和操作范围记录，不从局部截图推断未展示的主题、重载或模组组合通过。

完整交付范围沿[Markdown 规格第 1 节](<uilib-markdown-spec.md#1-目标与固定参照>)锁定的 KaTeX 对照目标，不能将此前逐阶段暂缓项当作最终排除项。逐命令、符号、环境及宏行为建立支持矩阵，区分可用实现、参照默认配置下被拒绝的行为和实际未完成能力；未完成能力不计入完成。数学解析与盒布局继续自有实现，字形整形、真实 OpenType MATH 构建和光栅/资源复用既有字体管线，公式继续作为同一 SceneMath 内容，Item 延续中性独立嵌入协议。

完成范围包含二维数学环境及其行列/对齐/分隔规则、数学符号与原子类别、字体/样式及文字作用域、分式/广义分式/固定定界尺寸、重音/上下载体/箭头和横向伸缩构建、间距/尺寸/颜色/框与幻影盒、算子和脚本变体、参照内置及用户定义数学宏与分组作用域。固定默认 strict=warn 下，顶层显式换行在行内和显示公式中均生效；样式、颜色和字号等透明片段保留顶层资格，普通分组、分式参数及围合内部不产生顶层换行。可选行距保留正负尺寸，连续空换行不额外创建空白行，相邻空换行的间距按最大正值与最小负值合并；各行的基线和墨迹来自当前真实字体及数学布局。行内及块公式是可测量数学内容；Markdown 段落解释与跨文本换行的共同文档排版继续归[Markdown 规格](<uilib-markdown-spec.md>)，不在数学内部另建文档树。完整 TeX 文档执行、任意宏包加载和外部执行仍不属于参照数学引擎范围；Web/HTML 专属命令按固定插件默认配置的实际结果逐项对照，不静默忽略内容或伪称支持。

宏扩展必须保留原始输入与可定位来源，动态布局不重做宏解析、不执行外部代码、不读取文件；定义、展开次数与嵌套采用明确资源边界。固定插件允许宏定义在同文档公式间延续、开始新文档时重置，数学入口以显式不可变宏上下文输入和解析结果的下一上下文表示；单公式默认新上下文，不共享隐藏全局、不修改业务状态。文字与 raw/url/color/size 参数按其模式处理，不在统一预展开阶段破坏参数字面语义。多次嵌入同一标识仍按唯一空间身份合同诊断，宏不能破坏该约束。字形与绘制扩展须复用同一字体代际和 PaintCommand，不增加第二数学后端或宿主回调。宽帽/宽倒帽/宽波浪等定义为可参数化的数学饰件，其完整宽度语义使用自有数学路径几何并沿通用 PaintCommand 图元绘制；路径不标为字体 glyph、不改字体轮廓或位图。箭头布局族可按其明确结构生成杆、箭头和标签净空，复合箭头分别表达各向线与头；这是对应命令的布局形式，不按字体构建失败触发隐式替代或重试。已有根号、围合定界符与采用字体部件的上下括号仍使用真实 MATH 字形构建。数学路径的尺寸/净空/墨迹进入同一 MathLayout，来源和实际GPU图像单独验收，不把数学几何包装成字体真实 glyph。

验收用独立固定参照语料覆盖支持矩阵，真实字体与 GPU 图像覆盖各布局族、内嵌 Item、动态字号/主题、字体重载、裁剪与非法输入整式诊断；仅解析接受或命令别名存在不代表视觉语义已完成。最终交付完整能力表、统一人工验收入口及实际测试/图像证据；宿主实机反馈与自动证据分别记录，缺少实例和逐项操作时不补称双实例完整通过。

## 5. 组合验收

| 场景 | 可观察结果 |
| --- | --- |
| 常用数学结构及动态字号混排 | 分组、脚本、分式、根式、定界符、矩阵/分段、样式、符号及算子按支持范围排版，测量与绘制一致 |
| 未知命令、无效公式及后续文档 | 失败公式源文可见，错误位置/阶段可定位，其他公式及正文继续呈现 |

各结构的具体场景沿第 2—4 节；组合验收不替代完整支持矩阵。
