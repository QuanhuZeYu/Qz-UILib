# UILib 测试应用规格

状态：已确认模块规格；与核心规格共同构成项目规格体系，仅定义本模块职责。

共同状态、布局、生命周期、输入与平台边界遵循[核心职责规格](<../2026-10-07-uilib-core-contract-design.md>)；按职责选择规格见[规格入口](<../README.md>)。

## 1. 统一测试自动化应用

测试作者通过继承统一测试应用基类定义具名场景，复用启动、初始化、执行、资源释放与结果报告。各入口仅启动具体测试应用；不再各自实现一套运行器。应用向子类提供参数、行为断言及资源归属能力，新增场景主要表达输入、生产链路和可观察预期。

统一的是运行生命周期与使用方式。基类本身只依赖 Java8，不引用 Minecraft、Forge、LWJGL 或自动创建 native/GL 环境。纯逻辑、软件光栅、真实字体、LWJGL2/LWJGL3 与游戏集成通过按需组合的环境组件取得能力；组件维护所属资源与前置条件。字体来源读取及同类宿主初始化集中复用，具体测试保留自己的数据、算法观测和断言。不存在环境时如实失败，不静默跳过或切换宿主。

应用按声明顺序执行场景。初始化、场景或清理失败时保留原始异常及场景身份，以非成功退出暴露；资源按所属作用域逆序释放，清理失败作为附加原因，不覆盖原始失败。只有实际执行且清理成功的场景和应用报告通过；空应用不得报告通过。既有真实回归迁移至此模型，结果仍按对应宿主区分，不把统一运行器的通过外推为游戏、GPU 或性能验收。

测试应用、共享组件与其回归代码位于测试编译单元，不进入正式 UILib 发行或核心 API。重写不得以基类便利为由修改生产职责、替换真实核心机制，或修复原版游戏自身内容。

专用性能压测的负载、采样口径与基线验收归[性能压测广场规格](<2026-10-14-uilib-performance-testing-spec.md>)。

## 2. 三宿主共享测试广场

测试广场只收录用户指定且有真实参考的新版案例：Gmail 收件箱、Shadcn Admin 正式配置、dnd-kit 的 Draggable、Droppable 与 Sortable 交互案例、[SimpleBar 滚动区示例](https://grsmto.github.io/simplebar/examples/)，以及遵循[媒体规格](<../content/2026-10-16-uilib-media-spec.md>)与 WHATWG 媒体模型的媒体播放页。共享目录列出这些实际入口；旧知识库、生产计划、项目表单、活动中心、数据报告与旧文本/媒体/结构/语言操作页连同专属实现和样本移除，不用隐藏入口保留并行页面。新的媒体播放页直接组合已实现的正式媒体能力，不恢复旧操作页。底层能力的有效回归继续留在所属测试编译单元。

每次广场运行持有独立状态与逻辑树，页面切换通过正式动态子树声明保留本次运行的页面状态，取消失活页面的输入联系；结束广场释放所有页面和资源，不使用进程静态字段保存编辑状态。导航、初始语言、图像服务及平台专项来源在明确边界接入；共享内容不直接读游戏设置、构造 ItemStack 或调用平台窗口。

参考网址只用于行为与视觉取证，案例运行不依赖公网服务。正式图像、语言、文本与宿主专项能力仍在所属模块验收，样本只归实际消费者的测试资源，不为旧页面继续放入广场附加包。

共享交互场景通过宿主驱动递交正式输入，断言可观察业务结果与内容变化，不直接调用控件回调或修改其内部状态。自动化可组合软件宿主、真实字体与 GL 环境；桌面通过实际 GLFW 窗口、已安装输入回调与 GL 取证。MC 使用同一广场声明，经游戏入口部署；启动游戏及实机操作按会话授权执行。结果标明宿主、能力与证据，不把一个宿主的通过外推至其他宿主。

广场默认进入参考案例目录，各宿主使用同一份页面声明和正式信号、控件、输入路由与 PaintPlan。配置案例直接组合正式 SettingsPage，借用当前宿主的真实 SettingsConfiguration 与同一状态域，不另造模拟配置或第二份表单。媒体播放页组合正式 SceneVideo、SceneMediaControls 与宿主提供的中性媒体服务，提供来源输入、UILib 自有本地文件选择器和随测试应用携带的示例。用户可选择任意本地视频文件，或输入本地绝对路径、file URI、HTTP/HLS 地址；不以扩展名白名单限制选择，实际无法解码的文件显示原有播放失败反馈。文件选择遵循[标准控件规格](<../content/2026-10-07-uilib-theme-spec.md#5-本地文件选择>)，在当前广场窗口使用共同场景及模态输入，不依赖外部 UI 工具包或系统文件弹窗。打开选择器期间当前播放继续，取消或 ESC 保留当前会话与来源，确认文件后才换源；宿主只接入初始目录、路径身份及正式媒体服务。打开来源前不创建播放会话，停止、换源、离开媒体页及结束广场时释放本页拥有的播放资源。来源编辑等本次运行状态继续保留，重新进入后由用户明确打开播放。共享编译单元只依赖无平台核心，宿主分别供给正式配置、媒体后端与示例来源，测试资源不进入生产包。专用性能负载仪器继续由性能规格管理，独立于参考案例目录。

测试广场按应用提供统一构建、人工启动与验证入口。构建一次装配 Desktop 测试消费者及其运行依赖和独立 MC 人工附加包，测试附加包仍不进入正式 assemble/publish；人工启动进入广场目录，邮箱、配置、交互与媒体页面从目录选择，不按页面另注册启动任务或直接进入页面的命令行分支。专项自动场景保留可独立定位的任务，由统一广场验证聚合后继续纳入完整 check，聚合不删减既有验证。正式桌面设置发行入口及专用性能广场遵循各自模块范围。

验收包括共享编译与产物隔离、三入口引用同一输出、参考案例的自动化与真实桌面交互、页面切换后的状态保留与输入隔离、运行实例间状态独立、图像实际像素及关闭释放。MC /qzcore统一进入新工作台；未执行的 MC 画面和专项验收如实说明。
