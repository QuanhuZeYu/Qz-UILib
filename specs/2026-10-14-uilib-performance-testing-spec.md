# 性能压测广场规格

状态：已确认模块规格；维护性能广场的负载、采样与报告合同。

## 1. 目标与职责

专用压测广场提供可重复的静止、滚动、局部更新、文档、编辑与重排负载，以同宿主同负载的证据选择和验证优化。性能结论不能由代码阅读、平均 FPS 或单次无卡顿推断。

共享测试声明决定内容、规模和业务状态；宿主提供真实帧边界、输入和运行环境；采样器保留单调时钟的原始样本并在采样结束后计算结果。沿用[核心职责](<2026-10-07-uilib-core-contract-design.md>)及[测试应用规格](<2026-10-07-uilib-testing-spec.md>)的 scene、信号、正式控件、输入路由和 PaintPlan；不建立第二套布局或渲染实现，不以测试需求改变公共核心职责。

## 2. 入口与运行边界

无平台自动机、真实 Desktop 窗口与 MC 人工入口使用同一 PerformanceGallery 页面和负载声明。性能广场独立于功能广场的大量驻留页面；MC 用 /qzperf 打开，原 /qzcore 保持功能广场入口。Desktop 提供人工入口和有限自动基线任务；人工保持 vsync=1，自动测量明确设置 vsync=0；MC 滚动和编辑由操作者在正式输入路径持续进行，没有动作的结果记为未命中。自动机用真实字体和正式管线，不把无 GL 的测量记为 GPU 或 MC 结果。

打开页面默认空闲，不自动加载大规模压力。操作者可选择负载、规模，开始、停止、重跑；每次运行拥有独立样本、负载状态与节点。停止或关闭使本轮不再采样，释放所属资源。中断结果标明未完成，不把部分样本作为完整通过。

## 3. 负载与可观察结果

| 场景 | 真实路径 | 目标观测 |
| --- | --- | --- |
| 静止控件列表 | 正式控件与长列表，完成预热后不发布内容变化 | 稳定帧的重复处理与回放成本 |
| 列表滚动 | 与静止列表相同内容，通过正式指针滚轮事件持续往返 | 滚动生效、命中与裁剪协调，不能只修改滚动字段 |
| 局部内容更新 | 固定节点集合，每帧仅改变一个条目的文案信号 | 显示值变化，未变内容的重复测量成本 |
| 文档滚动 | 包含中文、Latin、双向文字、表格与公式的本地长 Markdown | 文档实际排版与滚动；无公网依赖 |
| 连续编辑 | 真实多行编辑控件，混合文字长草稿，经正式输入递交插入/删除/光标命令 | 草稿实际变化、焦点有效，不能直接改编辑状态冒充输入 |
| 宽度重排 | 同一列表声明在宽、窄可用宽度间切换 | 动态尺寸使正式引擎重排，不能读回布局补偿 |

规模可选 50、200、1000；列表以条目数、文档和编辑以明确的样本单元数解释，并在报告记录实际内容长度。首次默认使用 200，允许以较小规模验证路径，以较大规模观察增长趋势。规模是压测输入，不是生产容量承诺。稳定采样阶段的正式滚动偏移、草稿文案、更新文案或已呈现宽度变化以 observedChanges 记录；只在预热期间操作不算稳定命中，往返回原位仍保留变化证据。各负载需有独立检查，未命中目标路径的运行失败，不输出成功基线。

独立拖拽任务复用相同采样器，使用隐藏真实 GLFW/OpenGL 窗口及已安装回调，避免影响当前桌面使用。普通长列表轨迹为持续 DOWN/MOVE/UP 后重抓，稳定阶段须观测实际共同几何位移、active 变化和释放回槽；排序负载使用字体来源风格的独立身份、长路径变高行与通用 SceneSortableList，每个正常放下须由真实输入发布一次顺序变化并保持原行身份，取消不得重排。停止在边缘的自动滚动单列轨迹与报告，不混入普通拖动前后对照。规模表示列表条目数，不表示同时活动的手势。

改动前的普通拖动与扩展后以同负载、输入轨迹、采样参数和隐藏模式对照；原版无排序能力时仅报告首个正确实现的排序数据，不伪造旧版本排序基线。窗口隐藏仍有真实 GPU 回放，但 actions+完整 frame 的墙钟不等于独立 GPU 时间；不存在正式工作次数或阶段计时探针时明确标为不可取得，不将失效代际、缓存条目或零值替代。视频等并行桌面负载的竞争影响只作为该运行环境边界，不从有限样本推断优化归因。

## 4. 测量口径

每轮分为负载进入、预热和稳定采样。负载构造与声明发布（declarationNanos）、首次正式挂载/布局/呈现（firstFrameNanos）分别计时，不混入稳定分位数；不将已有进程字体缓存称为冷进程。默认预热 30 帧、稳定采样 120 帧，有限自动任务可以显式传参并在报告记录实际值。

保留每帧宿主处理耗时和相邻帧开始间隔的纳秒原始样本。各口径独立输出样本数、平均、p50/p95/p99、最大值及超过 16.667 / 33.333 / 50 ms 的数量；分位数采用排序后的 nearest-rank，索引为 ceil(p*n)-1。这些阈值用于观察，不作为跨机器硬性性能通过线；[字体规格第 2.7 节](<2026-10-07-uilib-font-renderer-spec.md#27-性能>)已确认的同实例原版对照门槛仍在其所属范围适用。

宿主处理耗时必须标明计时边界：自动机为负载动作与 session.frame；Desktop 为负载动作与完整 window.frame（含 GLFW 事件和 swap 等待）；MC 为测试页负载动作与 drawScreen（不含游戏世界 tick 和最终交换）。帧开始间隔包含宿主在两次回调之间的其他工作，不可称为纯 UI CPU 或 GPU 时间。没有独立阶段探针时，不把总耗时解释为布局、整形或 GPU 耗时。

采样区只写预分配有界数组，不逐帧排序、文件写入或刷新统计文案。预热结束后开始计数；统计面板在运行边界更新。已应用状态的稳定路径观测、报告导出、可见结果校验和截图在宿主处理计时区外执行；帧开始间隔仍包含测试侧观测和循环管理开销。报告含场景、规模、预热/目标/实际帧数、完成/中断状态、宿主与边界、JVM/OS、视口尺寸、版本标识和原始样本；字体与图形环境信息由能取得事实的宿主补充。GC 次数/时间与堆变化在运行前后取快照，标明为进程指标，不能直接断言为本轮分配量或根因。

## 5. 验收与优化闭环

- 独立数值输入验证分位数、阈值、单位和样本上限；零样本与中断不得冒充完整结果。
- 自动机和 Desktop 有限运行覆盖全部场景；实际滚动、文案、编辑和重排有可观察变化。静止负载完成预热后不主动制造内容更新。大规模至少取得一轮测量，性能长耗时不当作功能失败隐藏。
- 同一进程中连续重跑、切换负载与停止后恢复，验证状态不串轮；关闭释放，测试类和资源保持发行隔离。
- 优化前保存原始基线。只有证据定位到具体重复工作或热点才修改生产代码；相同宿主、规模、内容、采样参数复测，并运行正确性回归与完整 build。改变语义、静态假设、删除功能或绕过正式机制不能作为性能优化。
- MC 的启动与实机操作遵循会话授权；尚未执行时报告未实测。Desktop 结果不能外推到游戏，压测工具和证据支持的热点排序本身可作为独立交付；性能工具验收不等于已消除实际页面卡顿。
