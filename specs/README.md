# 规格入口

先读[核心职责与交互规格](<2026-10-07-uilib-core-contract-design.md>)，再按下面的责任目录选择所属规格。核心维护跨模块边界，模块维护所属能力与验收，案例维护具体应用目标；同一要求只在其归属规格维护。

本文是唯一规格目录。文件开头的“状态”说明认可范围，文件名中的日期是标识，不是实现版本或验收结果。“已确认 / 正式 / 已授权”不表示代码、构建或实机已通过；规划方向获认可也不等于候选机制成为正式公共合同。

## 如何维护单一权威

- **修改归属正文。** 先按目录找到责任，修改同一份规格；跨模块只保留职责摘要和链接，不复制要求、清单或另一套默认值。文件日期不用于创建持续并行的“新版母本”。
- **区分要求与事实。** 规格维护目标、边界、固定参照、明确差异及可观察验收；实现机制从[源码](<../src/>)、接口注释和可运行场景核对，构建命令与依赖从[Gradle 任务声明](<../gradle/>)核对。实现不足记录为偏差，不能反向改写已确认合同。
- **分开认可与验证。** 不在“状态”维护已实现、已通过、尚未运行等随版本变化的台账。运行结论记录源码提交、实际产物、环境、输入和原始反馈；临时计划、调查与验证沿[协作入口](<../AGENTS.md>)归忽略的 Superpowers 目录。
- **让参照自足。** 已认可的参照版本、身份、规则与允许差异留在所属规格；对照语料和截图是证据，当前源码、测试输出、现场浏览器或忽略记录不补足另一套要求。后续确认替代旧目标时，合并为一套有效正文，历史演变留 Git 或任务记录。
- **变更时同步入口与引用。** 新职责在本页登记；移动或拆分正文后检查相对路径、标题锚点、源码注释及构建注释中的引用。完整目录只维护于本页，子目录不再复制目录或维护状态表。

权限、提交、发布与编排遵循[AGENTS.md](<../AGENTS.md>)及会话授权，不在模块规格增加施工流程。现有能力不因规格未覆盖而自动删除；新增目标或核心边界缺口沿核心及协作入口补齐。
