# UILib 无平台配置规格

状态：已授权模块规格。共同状态、生命周期与平台边界遵循[核心规格](<2026-10-07-uilib-core-contract-design.md>)。

## 1. 配置声明与权威值

配置声明是类型化字段或对象、编解码、默认值、字段说明和明确校验。模块声明自己的选项和对象结构，通用配置核心不认识 MC、字体或页面含义。配置实例由应用持有，不要求 UI 挂载或宿主类型；业务读取经过类型绑定与校验的值，也可通过既有响应式能力订阅变化，不自行解析 YAML 节点。声明路径唯一，重复或相互占用对象路径的声明须定位报错。

默认值属于声明；缺少字段使用声明默认值，显式空字符串、空列表、空映射与缺少字段区分。显式 null 仅在声明允许时有效，不隐含解释为缺失或默认值。正式类型能力覆盖 boolean、string、整数与浮点数、嵌套对象、类型化列表（包括对象列表）、映射及模块自定义对象；数值范围、对象必填字段与跨字段约束由声明校验，不能仅因 YAML 可解析就接受。

须能将完整复杂对象从 YAML 绑定到模块声明的类型，并作为一个值读取、修改、持久化与观察；不要求业务将其拆成平铺字符串键或把复杂内容塞入字符串。对象内可组合其他对象、列表和映射。向外发布的复合值保持深层不可变，修改通过配置正式写入口提交新值，外部修改不能绕过校验及通知。对象编解码属于核心扩展能力，通用声明不依赖 Forge 类型；具体 Java 类型绑定方式和库选择由实现设计决定，不预定反射框架、配置编辑器、层级覆盖或通用事务框架。

一次加载先读取、解析和校验全部声明值，再在同一状态操作中发布；通知观察者获得同一批次的新值，直接值与派生读取保持一致。非法值定位完整字段路径（包括列表索引）并报错，不部分发布，不默默改回默认值。解析失败前尚未发布属于本次操作未完成，不引入额外重试、回滚、旧结果恢复或降级策略。普通 set 同样校验、发布变化；相同值不重复通知。

## 2. YAML 文档、注释与环境边界

正式持久化格式采用 UTF-8 YAML 对象文档：根为映射，嵌套字段表达对象，序列表达列表，映射表达键值集合，不使用 Properties 的 count/索引平铺编码。核心提供文件及 Reader/Writer 存取，宿主选择文件路径、调用时机和资源归属。解析、类型绑定、默认值、对象校验与值发布沿同一核心主流程完成，宿主不另建配置语义。

配置文件支持字段前说明注释和行尾注释。声明可提供字段及对象说明，首次生成配置时输出为对应节点附近的注释；用户可补充自己的注释。程序加载后保存或修改配置值，应保留未修改节点及对应注释，不以重新序列化整个对象的方式清空用户注释。用户注释与声明说明可共同存在，更新声明说明不能覆盖用户注释；具体注释归属和编辑机制由实现设计确定。注释属于文档表示，不参与业务值比较，不触发配置值变化通知；不要求字节级排版完全一致。

语法错误、重复映射键、未知字段、类型不符与非法对象结构明确报错。语法和绑定错误提供文件或输入来源、节点路径及可取得的行列位置；对象校验错误提供完整路径。模块自定义类型通过声明的转换读取，YAML 内容不决定任意 Java 类的实例化。读写错误沿调用通道报告，不吞错、不增加自动监视或恢复策略。持久化显式调用，不将每次内存修改隐含解释为磁盘保存。

配置观察复用现有 ReactiveDomain/Signal/Owner；订阅的释放归订阅持有者。核心不安装宿主事件监听器，不创建后台线程，不每帧读取文件。文件不存在时，首次初始化由调用方明确使用默认值并创建文件，不与加载失败混同。

## 3. 字体接入与旧来源迁移

字体模块声明完整有序候选列表，遵循[字体规格第 2.4 节](<2026-10-07-uilib-font-renderer-spec.md>)。候选通过内置来源标识或系统文件路径明确表达；它们在同一列表中排序，不自动追加未声明来源。未配置采用模块默认列表，显式空列表保持空。解析到实际 face、字族及样式仍复用字体来源与适配，不建立第二套字体引擎。YAML 中的字体候选使用实际序列，具体节点结构由字体声明决定，不因格式变化改写完整列表合同。

MC 宿主调用核心配置实例。通用字体候选归字体模块；replaceVanillaFont 等 MC 专有选项归 MC 模块。配置变更和资源重载沿既有资源换代更新，页面不需要关闭重开。

旧 Forge systemFontFiles 只作为一次迁移输入：旧前缀转换为显式 file 候选，再接入当次实际默认内置顺序，得到等效完整列表；旧 replaceVanillaFont 同时迁移。正式 YAML 文件存在后以它为权威，不持续读取或合并旧来源。现有 Properties 到 YAML 的迁移也必须保持当前有效值、完整候选顺序以及显式空值；转换成功并持久化后才采用 YAML 来源，原文件保留。MC 使用原配置同目录、同基本名的 .yaml 文件；已有 YAML 为权威，否则先迁移现有 .properties，再否则读取旧 Forge 配置，无旧来源才生成默认 YAML。各来源不叠加，转换和目标保存成功后才启用该 YAML 来源。非法旧配置迁移明确失败，不默默跳过；不把原前缀字段改成完整列表，也不建立长期双写兼容层。

## 4. 产物与验收

配置类归独立核心产物，产物加载及配置读写不要求 MC/Forge/LWJGL/native 存在。宿主通过核心产物调用配置，平台来源解析和事件监听留在宿主。

验收沿真实生产路径覆盖：默认、显式空值及 null 区分；嵌套对象、对象列表与映射的类型绑定和文件往返；数值与跨字段约束；复合值深层不可变；加载前全量校验与批次通知；错误路径及语法位置定位；订阅释放；完整字体候选排序/排除；旧来源迁移后的有效值，以及现有字体换代。复杂对象验收至少包含对象内嵌套对象和对象列表，业务直接读取声明类型，修改后保存、重新加载得到等效对象。

注释验收使用带字段前注释和行尾注释的真实 YAML：修改一个值并保存后，未修改节点的用户注释保留；首次生成的声明说明可读；仅修改注释再加载不触发业务值通知。用真实产物独立运行核心对象配置与状态流程；MC 宿主效果由实际发行组合验收，不以核心测试冒称游戏通过。

## 5. 类型绑定与表示边界

核心通过显式对象字段声明和模块工厂绑定业务类型，组合列表、映射与 nullable；公共配置接口不暴露 YAML 库节点，不从文件推断任意 Java 类型。对象工厂基于已冻结子值构造不可变业务对象，自定义编解码承担同样的快照责任；业务对象按配置语义实现 equals/hashCode，保证同值不通知。键的点分声明对应真正的 YAML 嵌套映射，不接受点分字面键替代嵌套对象；已声明映射内部允许合法 string 键。

声明说明按实际对象、列表索引与映射项生成。保存时保留未修改内容的注释，并保持共享 alias 表示的各配置值独立；不要求原 anchor 写法或 flow/block 排版保持不变。序列化库无法在特定容器位置保持行尾注释时，允许将说明移到同一容器附近的前置注释，保留文本及归属。

正式读写使用 YAML，Properties 只提供显式读取迁移入口，其范围为已交付旧格式的 boolean、string、count/索引 string-list；不扩展旧格式复杂对象、不提供 Properties 写入口。YAML 依赖通过 shadow 私有重定位嵌入独立核心产物，MC 使用该核心且不重复携带 YAML 定义。
