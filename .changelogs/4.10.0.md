# Qz-UILib 4.10.0

**本版要点**

- 选择器（SearchPicker）重写收口：候选源由「全量拉取 + 宿主自行过滤」改为查询式只读 SPI，结果区由「全量挂载」改为窗口化渲染，面板生命周期由「打开仍算」改为「打开即算 / 关闭即停」。
- 尺寸与密度改为动态派生：网格 stride、图标边长、面板盒、成员卡、分类行、徽章内边距等全部按「逻辑盒 + 字号 + 密度档」派生，并新增配置项 `general.pickerDensity`（auto / compact / standard / roomy，默认 auto）。
- 分级键与图标缓存收敛为候选域键唯一真源，并补齐内容、注册表、图标、资源与语言代际失效通道。
- 新增配置项 `general.backdropQuality`（`full` 完整 / `eco` 省电 / `solid` 关闭）与 `general.configPageTheme`（缺键回落 `flat`），收敛玻璃成本并修复配置页滚动卡顿。
- 修复世界空间文字（告示牌等）不显示、或「被物体挡住才可见」：把宿主批量窗口内的世界文字捕获后改到宿主几何提交之后回放，失败时整体退回即时绘制。
- 新增通用颜色字段能力 `config.schema.ColorSpec` / `HexColorCodec` / `config.ui.field.ColorFieldRenderer`，并补齐键盘翻页、删除即生效 + 5s 撤销条、常驻信息条等交互与诊断设施。

## 兼容性与升级动作

- 兼容边界：本版与 4.9.x **不承诺混用**（含删除），需成对升级；FML 远端范围保持 `[4.9.0,4.11.0)`，已包含本版构建版本 4.10.0，覆盖 4.9.x / 4.10.x。
- 依赖配对：下游声明的 UILib 区间以其**编译所用制品**为准；升级到本版时需与 4.10.0 制品成对换件。
- 契约不变：未实现新 SPI 的 provider 仍走 4.9.1 的旧路径；主 `NetEnvelope` v2 与 Realtime v1 不变，不提供运行时协议协商或降级路径。

### 删除项（共 8 项 = 1 个公共类 + 7 个公共成员）

1. `club.heiqi.uilib.ui.scene.control.search.SearchResultList$Row`（公共嵌套 record，整类删除）。原签名：`public final class SearchResultList$Row`，成员 `Row(int, List<SceneVirtualGrid$Item>)`、`int firstIndex()`、`List<SceneVirtualGrid$Item> items()`（record 自带 `equals/hashCode/toString`）。理由：窗口化后「一行」不再由宿主自行推导，行区间改用 `SceneGridWindow.RowRange`（`firstIndex()` / `count()`）；持有 `Row` 的宿主即「第二份窗口数学」的载体。**迁移**：改用 `SceneGridWindow.RowRange`，需要行内单元请经 `Result.windowModel()` 取切片，不要自行按行聚合。风险：编译期仍引用 `Row` 的外部代码在运行期会 `NoClassDefFoundError`，**必须随本版升级**。
2. `club.heiqi.config.ui.editor.SearchPickerPresentation.currentMember(SearchPickerData$CurrentMember)`（公共实例方法）。原签名：`public java.lang.String currentMember(club.heiqi.config.ui.editor.SearchPickerData$CurrentMember);`。理由：真死键（无注入、无消费者），成员文案已由 `currentMemberPrimary(member)` / `currentMemberSecondary(member)` 承载。**迁移**：改用 `currentMemberPrimary(m)`（主行，通常是名称）+ `currentMemberSecondary(m)`（次行，通常是 ID / 附加信息）；「当前成员」概念本身由 `SearchPickerData$CurrentMember` 携带。风险：低（无生产消费者，仅编译期引用者受影响）。
3. `club.heiqi.uilib.ui.scene.control.search.ItemRenderFallbackKeys.splitRegistryKey(String)`（公共静态方法，**无替代者**）。原签名：`public static java.lang.String[] splitRegistryKey(java.lang.String);`。理由：该方法按最后一个冒号切分，对 `minecraft:stone` 返回 `{"minecraft","stone"}`（把方块名当 meta），`parts[0]` 与候选键比较必不相等，导致回退集合恒空、UNRENDERABLE **静默失效**；分级键统一为候选域键后解析端不复存在，保留它即保留一条会把回退集合打成恒空的错误解析路径。**迁移**：**不要解析键**——把 `PickerIconKey.candidate(registryKey)` / `PickerIconKey.variant(registryKey, meta)` 的返回值**原样**当分级 / 图标键使用。风险：低（外部若自行拆键，其回退本就恒空）。
4. `club.heiqi.config.schema.SearchPickerSpec.maxItems()`（公共实例方法）。原签名：`public int maxItems();`（4.9.1 语义 = 兼容提示值，javadoc 自述「搜索返回完整结果」）。理由：搜索 lane **不再有窗口上限**，窗口总量 = 候选源真实命中数 `matchCount(query)`，可见性 = 惰性分页；保留该方法即保留「上限」这一已废弃概念的第二真值来源。**迁移**：需要展示规模时读 `ScenePickerPanel$Result.windowModel().totalItems()` 或候选源 `matchCount(query)`；需要分片时按窗口几何调用 `PickerCandidateSource.page(query, offset, limit)`。风险：低——`Values.searchPicker(...)` 与 `SearchPickerSpec` 构造器同步收敛，编译期即暴露。
5. `SearchPickerSpec(String editorId, int maxItems)` 与 `SearchPickerSpec(String editorId, int maxItems, BindingMode bindingMode)`（两个公共构造器）。理由：widget 元数据不再携带窗口上限（该上限在装配层已无消费者）。**迁移**：改用 `new SearchPickerSpec(editorId)` / `new SearchPickerSpec(editorId, bindingMode)`。
6. `Values.searchPicker(String editorId, int maxItems)` 与 `Values.searchPicker(String editorId, int maxItems, BindingMode bindingMode)`（两个公共静态方法）。理由同上：DSL 不再接收上限参数，避免「接收但忽略」的兼容壳。**迁移**：改用 `Values.searchPicker(editorId)` / `Values.searchPicker(editorId, BindingMode.LIST_MEMBERS)`。

### 行为变化（必须知晓）

- 搜索 lane 不再有窗口上限：窗口总量 = 候选源真实命中数 `matchCount(query)`，可见性 = 惰性分页（`pageProvider` 按 `WindowRequest(offset, limit)` 拉片，单次物化量 ∝ 窗口行数 × 列数，与命中总数 N 无关），SPI 路径 `truncated` 恒 false（截断通道保留给旧全量结果路径，信息条优先级不变）。若你此前为配合「64 窗口」给 `searchPicker` / `SearchPickerSpec` 传过上限或覆写过 `searchMaxItems()`，按「迁移指引」第 6 条改签名即可；迁移后搜索返回全部命中、可滚到底、无截断提示。
- 窗口化与生命周期：`Props.items()` 变为窗口切片；`pageProvider` 由控件按窗口模型调用（宿主不得自算 offset）；面板关闭后不再做任何候选派生与数据读取（旧行为是关闭仍在算）。
- 面板信息条改为常驻占位；1080p auto 档可见项 75 → **100**；密度档位新增三档 + auto 阶梯（只降不升），切换经 `Props.densityPreference`（`ReadableSignal<PickerDensityPreference>`）注入、无需重建面板。
- 已配置候选语义：SPI 路径**不再排除**「已配置成员」，改为结果单元右上角主题色圆点标记 + 信息条徽章，点击走完全相同路径（重复由成员徽章如实呈现）。若下游依赖旧的「排除」行为（例如自行过滤），需同步移除。
- 库默认主题按背景滤镜档位动态解析：`general.backdropQuality=solid` 时未显式安装主题的 runtime 读到实色替代配方；`SceneThemes.DEFAULT` 常量**不随档位变化**。
- `picker.lookup.comparisons` 计数退役；`picker.list.totalRows` / `rows` / `cells` 口径重定义；`picker.candidates` 口径 = 真实命中数。
- 折叠（`setCollapsed(true)`）的已知取舍：折叠节点自身仍占一个零尺寸槽（gap / margin 照旧）；折叠子树内「已持焦点」需调用方释放（Tab 环已排除）。

### 迁移指引

1. **版本与依赖**：本版 tag = `4.10.0`（次版本号），但相对 4.9.1 含 8 项公共面删除（breaking），与 4.9.x 不承诺混用，需成对升级（本地制品同步换件）。FML 远端范围 `[4.9.0,4.11.0)` 已包含本版构建版本；下游声明的 UILib 区间以其编译所用制品为准，实际编译面为 4.10.0 时下界应相应抬到 4.10.0。
2. **文案注入**：本版新增 **15** 个注入键，不注入会回落**英文默认值**，下游需补齐本地化。
   - `SearchPickerPanelPresentation`：`truncatedResults`、`hoverHint`、`keyboardHint`、`scrollHint`、`densityLabel`、`memberAddingBanner`、`memberEditingBanner`、`removedToast`、`undoAction`、`alreadyConfiguredBadge`、`infoBarIdPattern`（读取访问器 `infoBarIdLabel(label, id)`）、`infoBarCopiedPattern`（`infoBarCopied(id)`）。
   - `SearchPickerPresentation`：`emptyVariants`、`modeReadOnlyHint`、`emptyCategoryResults`。
   - 建议同时加一个反射式注入完整性守卫：UILib 侧新增键而未注入时直接变红。
3. **已配置候选**：SPI 路径不再排除「已配置成员」，改为显示 + 标记（见「行为变化」）。
4. **图标源**：实现 `PickerIconSource` 必须返回**候选域键**对应的图像源；`HostImageSource.itemIcon(ItemStack, String explicitRegistryKey)` 是显式键工厂（键优先、null / 空白回落自算）；变体级第二参数是 meta 令牌（不含 `@`），完整键 `candidateKey@meta` 也接受。
5. **候选源**：实现 `PickerCandidateSource` 时保证「同一 `(query, revision)` 下 `page()` 顺序稳定、分片拼接等于整取、key 无重复」，且所有入口在主线程调用（非主线程必须在入口 fail-fast，不得返回空数据）。环境代际**只经** `onEnvironmentChanged` 下行（不推送则 `version()` 必须恒等）。
6. **按新签名迁移**：`new SearchPickerSpec(id, n)` / `(id, n, mode)` → `(id)` / `(id, mode)`；`Values.searchPicker(id, n)` / `(id, n, mode)` → `(id)` / `(id, mode)`；`registry.register(provider, n)` → `registry.register(provider)`。
   同时删除实现类里的 `CandidateSourceValueEditorProvider#searchMaxItems()` override 与 `Props.searchMaxItems()` 用法（规模改读 `Result.windowModel().totalItems()`），`Builder.candidateSource(source, n, query, version)` 改为 `Builder.candidateSource(source, query, version)`。
7. **删除项迁移**：持有 `SearchResultList$Row` 改用 `SceneGridWindow.RowRange`；调用 `SearchPickerPresentation.currentMember(...)` 改用 `currentMemberPrimary/Secondary`；调用 `ItemRenderFallbackKeys.splitRegistryKey(...)` 改为直接使用候选域键（本版起不存在解析端）。
8. **面板接线（可选）**：提供 `Props.pageProvider`（窗口切片）+ `totalItemsSignal`（动态总量）+ `densityPreference`（密度档位）+ `configuredKeys`（已配置标记）+ `onRestoreCurrent` / `onDiscardRemoved`（防误删闸口），即可获得完整的窗口化 / 动态化 / 撤销体验；不接线时保持向后兼容的默认行为。

### 已知限制

- 输入框聚焦时占位仍隐藏；Tab 焦点环没有显式顺序守卫；键盘「加 3 删 1」全路径缺端到端守卫；徽章 hover 原因未做。
- `SceneSimpleList` / `SceneDialog` 等**通用控件**的硬编码中文未外置（本版只覆盖选择器家族）。
- `priorKnownChildWidth` 对「无文本叶 / 空容器」的 padding 口径不一致（已裁定保留并文档化）；折叠节点仍占零尺寸槽；折叠子树内已持焦点需调用方释放。
- `SceneScrollbar.Props.barWidth`（构造期常量）与新的 `barWidthSignal` 并存，两者的语义分工需下游知晓。

### 候选源 SPI 与失效通道

- 新增查询式只读候选源 SPI：`config.ui.editor.PickerCandidateSource`（`size()` / 三段版本号 `version()` / `matchCount(PickerQuery)` / `page(PickerQuery, offset, limit)` / `exact(key)` / `categories(dimension)` / `release()`），配套 `PickerQuery` / `PickerSourceVersion` / `PickerEnvironment`，以及 provider 侧直通接缝 `CandidateSourceValueEditorProvider` 与图标源 `PickerIconSource`。
- 旧路径「一次全量 + 宿主侧过滤」在千级候选集上把成本压给每一帧；查询式只读把「谁持有数据、谁回答切片」定为唯一责任面。
- 实现方契约：同一 `(query, revision)` 下 `page()` 顺序稳定、分片拼接等于整取、key 无重复；全部入口只在客户端主线程调用，非主线程入口 fail-fast（`PickerSourceGuard`）。旧 `ValueEditorProvider` / `CategorizedValueEditorProvider` / `VisualAdapter` / `SearchPickerData` / `SearchPickerCategories` / `SceneVirtualGrid` 的既有成员零删除、零改签名；未实现新 SPI 的 provider 走旧路径，行为与 4.9.1 一致。
- 四代际失效通道：内容代际 `PickerGeneration`、注册表代际、图标代际经 `PickerRevisionBridge` 汇成 SPI 可读的 revision；`ResourceReloadService`（资源重载广播，F3+T 等）与 `LanguageEpochService`（语言纪元）把资源 / 语言热更变成可订阅信号；`MinecraftMainThreadOracle` 提供主线程判定真源。图标、语言、资源包三者独立变化，缺一条通道就会出现「换了资源包但图标仍是旧图」的静默陈旧。环境代际**只经** `onEnvironmentChanged` 下行，不推送则 `version()` 必须恒等；下游不需要自己轮询资源包或语言状态。
- 分级键收敛为候选域键：`PickerIconKey`（`candidate(key)` / `variant(key, meta)`）是分级键唯一生成处；`PickerIconResolver`（候选域键 → 图标，屏级缓存、`release()` 幂等）与 `PickerIconCache`（有界：512 活跃 + 1024 tombstone）；`HostImageSource.itemIcon(ItemStack, String explicitRegistryKey)` 是显式键工厂（键优先，null / 空白回落自算）。实现 `PickerIconSource` 必须返回候选域键对应的图像源，**不得**覆写 `registryKey()`；变体级第二参数是 meta 令牌（不含 `@`），完整键 `candidateKey@meta` 也接受。
- 会话释放账本 `club.heiqi.config.ui.field.PickerSourceLifecycle`（弱引用集合、同实例去重）：`track(source)` 由字段装配点登记，`releaseAll(reason)` 是**唯一释放点**，接在 `ClientProxy.onClientDisconnect` 的断连路径上（经主线程派发）。候选源按契约属进程级会话对象，不得在关屏时释放（否则每次关闭选择器即丢分片 / 清单快照）；下游自定义 `PickerCandidateSource` 若在 `release()` 里持有可释放资源，退出世界时会被自动调用一次，无需自行接线。
- 分级缓存可失效：`ItemRenderTierRegistry.invalidateAll(String)` / `tierGeneration()` / `size()` / `tombstoneSize()` + `$Listener.onInvalidated(String)`，配合有界缓存（`MAX_ACTIVE_ENTRIES` / `MAX_TOMBSTONES`）。渲染分级会随资源包与渲染器状态变化，缺失效入口只能重启，缺上界则随候选集无界增长；下游拿到 icon 后不要长期持有引用跨代际使用，代际变化后应重新解析。

### 窗口化与面板生命周期

- 新增 `ui.scene.control.SceneGridWindow`（**窗口数学唯一实现**：`compute` / `viewportHeight` / `visibleRowsForViewport` / `windowStartRowForScroll` / `scrollForAnchor`，值对象 `$WindowModel` 与行区间 `$RowRange`）、`SceneItemIndex`（key → 全局下标 O(1)）、`SceneGridSnapshot`；`SearchResultList` 与 `SceneVirtualGrid` 共用同一内核。旧路径由宿主各自推导窗口偏移，等于在每个宿主里各写一份窗口数学，两份实现迟早漂移。
- `Props.items()` 语义由「全量数据」变为「**窗口切片**」：挂载量与绘制命令数与数据规模 N **无关**（只与可视行数 + overscan 有关）；新增 `pageProvider` / `totalItems` / `windowOffset` / `availableWidth` / `visibleRows` / `totalItemsSignal` / `metrics` / `configuredKeys` / `onExitUp` 分量，**全部旧构造器保留**（11 / 16 / 17 / 18 参兼容面）。宿主**不得自行推导窗口偏移**；`Result.windowModel()` 是窗口状态唯一回读通道。
- 窗口不变式：`windowOffset == windowStartRow * columns`；切片长度 == `min(rows*columns, totalItems - windowOffset)`；`windowOffset % columns == 0`；`totalRows == ceil(totalItems / columns)`（`totalRows` 由 `totalItems` 派生，不得由切片长度派生）。
- 面板在行构建期只建 Signal 骨架 + open 状态机 + portal 句柄；全部候选派生计算（filtered / gridItems / categoryRows / memberIssues / clampHighlight / VariantChooser）移入内容 Owner，随关闭释放；`StructuredListFieldRenderer` 折叠态改为惰性构建。关闭后不再读取候选源、不再产出任何 `picker.*` 派生计数，重复打开复用进程级候选源与缓存、不重建数据面。常驻复用范围 = **同屏 open 开合之间** + 候选源进程级常驻，**跨屏不成立**——不要依赖跨屏缓存。

### 动态尺寸、密度与主题

- 新增 `ui.screen.HostViewportScale`（宿主逻辑盒边界，GUI Scale **只在 host 边界成对换算**）、`ui.scene.layout.LogicalBox`、密度三档 `PickerDensity`（`compact32` / `standard40` / `roomy48`）与 `PickerDensityTokens`（比例 / 夹取边界唯一常量表）、`PickerMetrics`（含 `$PanelBox`）、`PickerChrome`、`GridMetrics`；网格 stride、图标边长、面板盒、成员卡、变体行、分类行、徽章内边距、触发器图标**全部按「逻辑盒 + 字号 + 密度档」派生**。旧实现把布局常量与 6 / 8 位色值散落在 picker 家族各处，改一档分辨率或字号就会出现「盒子变了、格子没变」的错位。

- 主题与协议色：`SceneRenderProtocolTokens` 集中非主题静态协议色（「无图」占位色 `0xFF454B54`、hover / 选中 alpha、SCRIM 等），SCRIM 两值冲突收敛为 `0xCC121016`；「UNRENDERABLE」与「无图」改为**两种可区分令牌**（前者主题派生 `ItemRenderFallbackKeys.unrenderableTint(rt)`，随主题即时重派生；后者固定协议色）；新增主题语义槽 `SceneTheme.warningSubtle` / `SceneThemes.warningSubtle`（重复徽章）。读主题色的下游请用 `SceneThemes.warningSubtle()`，不要自己抄色值；picker 家族内不再有硬编码 6 / 8 位色值与布局常量，改用 `PickerMetrics` / `PickerChrome`。

### 框架侧正确性与性能修复

- `measuredTextNodes` 登记表生命周期收口：结构版本号（`SceneNode.__structureVersion()`）+ 确定性剪枝 + 已知根 LRU（容量 8）+ 入口 epoch 快路径，剪枝时同时作废「断开子树 叶→顶」路径的布局缓存。此前登记表保强引用且无确定剪枝，反复挂载 / 卸载后条目只增不减（内存泄漏 + 每帧扫描）。无公共语义变化；`SceneNode` 的「禁止重写 `equals/hashCode`」禁令在类注释锚定（identity 语义是登记表前提）。
- `layoutEpoch` 语义拆分：保留 `layoutEpoch()` 为**批计数**（每批 +1，签名与调用方零改动），新增 `SceneLayoutEngine.layoutChangeEpoch()`（仅在 `relayoutCount > 0` 或存在约束重布局节点时自增）；`SceneFramePipeline` 的桥接改指变更纪元并对主树与各 overlay 引擎**求和**聚合（用 `max` 会在「主树纪元高、某 overlay 首次变化」时吞掉变化）。`layoutDoneSignal` / `__setLayoutDoneEpoch` 的语义边界改述为「布局发布」（零几何变化帧不变更，**不是**「画面已更新」）；依赖旧语义（每批必发）的下游需改指批计数 `layoutEpoch()`。
- 每帧分配优化：`ReactiveScheduler` 三处 scratch 化 + `dirtyEffectCount` 早退；`PaintPlan` 内部由「绝对坐标命令列表」改为「条目序列」（单命令直接回放、片段回放期叠加偏移）+ `getCommands()` 按需物化缓存 + 公开新增 `PaintPlan.addPlan(PaintPlan)`。`getCommands()` 返回类型与内容逐位不变、`size()` 口径不变、回放调用序列不变；新增 `addPlan` 为纯加法。
- 静止帧剔除：L0 干净批 O(1) 快路径（返回共享常量零变化结果，不建探针集合、不建布局结果、不下潜）；裁剪窗口子树整棵剔除（本节点 `isClipWindow()` + 无 transform + 窗口绝对盒与有效祖先裁剪矩形无交集三者同时成立）。保守优先（有 transform 一律继续下降）；被剔除时**不清脏标记**，回到可见区按脏标记重发射。下游自定义 clip window 无需改动。
- 新增 `SceneNode.setCollapsed(boolean)` / `isCollapsed()`：**折叠 = 本节点内容退出布局域，自身按零内容叶留在父流中**，折叠子树在布局 / 绘制 / 命中 / 焦点四面同步退出。`ConstraintResolver.priorKnownChildHeight` 对有子容器返回 `UNCONSTRAINED` 是「严禁读子 `cachedLayout`」这条先验铁律的正确代价，根除方式不是放宽闸门（放宽即在未知量上做算术），而是给固定兄弟一条**声明的可知通道**：折叠节点的内容高与先验高同为零内容叶口径，先验 == 实际由构造保证。纯加法：默认 `false` 时未声明节点在四个遍历面零参与、逐位不变。

### 背景滤镜档位与玻璃成本优化

- 新增配置项 `general.backdropQuality`：`full` 完整液态玻璃（默认）/ `eco` 省电 9 抽头变体 / `solid` 关闭改用实色替代底；配套公共枚举 `ui.render.BackdropQuality`（`FULL` / `ECO` / `OFF`，含 `configValue()` / `tapBudget()` / `parse(String)`）与进程级信号 `ui.render.BackdropQualityService`。
- 回灌单点：`ConfigValueBridge.applyGeneral` 是唯一回灌点，**不是** `Config` 静态字段（静态镜像会被配置面守卫判成「有键、有回灌、零读取者」的假开关）。三档取值都不是 YAML 1.1 布尔词，手改 YAML 写裸词可正常读写（第三档原名 `off` 已因此改名）。
- 库默认主题改按档位动态解析：`SceneThemes.resolve` 的回落级在 `solid` 档取 `SceneTheme.liquidGlassDark().withoutBackdrop()`（实色可读替代），其余档取 `SceneThemes.DEFAULT`，`SceneThemes.DEFAULT` 常量本身不动（仍是液态玻璃语义锚）；未显式安装主题的 runtime 经 `SceneThemes.resolve` / `surface` / `derivedSurface` / 语义色入口读到替代配方，切档只重派生配方与语义色、**不重建节点**。
- 优化面来自真机根因：配置页每帧玻璃规模 26 表面 / 约 365 万 px（≈1.76 屏），每像素 13 次采样且抽头数与半径无关；快照跨帧必不复用、每帧重捕；采样因子为 1 时 mip 链无人读；玻璃无可见性短路；诊断串每表面每帧无条件构造。相应收口：下调采样因子为 1 时不再走 mip 链、屏外玻璃片段整链早退、诊断串按需构造；`PaintFragment` 记录自身纵向绘制范围，`ScenePaintEngine` 滚动重放时与裁剪窗口判交、屏外片段不再重放（段流等无可靠边界的命令保持原样重放，不按节点盒猜测）。同批修复字体纹理矩阵恢复路径。

### 世界空间文字与配置页滚动修复（#74）

- 修世界空间文字（告示牌等）不显示、或「被物体挡住才可见」：宿主（Angelica）把 TESR 几何排队到遍历结束后统一提交，而替换字体后的字形在 `drawString` 调用点内立即提交——两条通道不同源，落屏顺序不保证。
- 根因：木板晚于字形落屏时，按原版「世界文字不写深度」的语义，木板会在自身轮廓内整块覆盖字形，只在深度缓冲已有更近几何处留下字形。
- 修复：新增内部 `TesrTextReplayCoordinator`，把宿主批量窗口内的世界文字捕获后改到宿主几何提交之后回放（用捕获时刻的投影 / 模型视图矩阵作 uniform 覆盖，并临时关闭深度写入），宿主侧由可选 Mixin 围栏 `MixinAngelicaTesrBatchReplay` 挂在 `TesrBatchRenderer.flush()` / `flushAfterDeferred()` 两个提交点驱动。
- 失败语义：无 Angelica、版本不匹配或 Mixin 未应用时协调器整体停用，世界文字退回即时绘制；宿主未在帧内提交批次时，帧边界丢弃滞留项并留一次 WARN，不静默永久丢字。观测面（`fontRuntimeDebug`）记录捕获 / 回放 / 丢弃事件与事件两端的宿主 pass 身份。
- 配置页默认主题改为**平面**：新增 `general.configPageTheme`，缺键 / 非法值回落 `flat`，需要半透明可切 `glass`，不再默认走半透明背景采样——这是配置页滚动卡顿修复的另一半（屏外片段剔除见「背景滤镜档位与玻璃成本优化」）。同批修复字体纹理矩阵恢复路径。
