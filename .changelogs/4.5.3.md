## 本次更新

**4.5.3** 是 4.5.2 之后的修订补丁，修复配置草稿 stale / 并发冲突的易用性：结构化冲突类型、事务 base 独立、stale 显式恢复、presentation seed 不落盘。

### 新增

- `SaveOutcome.ConflictType`（`NONE` / `STALE_DRAFT_BASE` / `DRAFT_MODIFIED_DURING_SAVE` / `AUTHORITY_MODIFIED_DURING_SAVE` / `SAVE_DURING_NOTIFICATION`）
- `SaveOutcome.isConflict()` / `requiresReload()`：UI 禁止英文诊断串匹配
- `DraftBuffer` 独立事务 `baseValues`：open 时深拷贝 Authority；capture 只比 base；成功 commit 推进 base/current/draft
- `DraftSignalAdapter.replaceDraft`：保持 Signal/Computed identity 替换底层草稿（schema 路径/类型校验）
- `DraftSignalAdapter.seedPresentation`：发现态只展示、不写 DraftBuffer；`seedFieldBaseline` 委托并 deprecated
- ConfigScreen「丢弃编辑并重新加载」按钮（Signal/Computed + `rt.show`，守 I1/I3/I9）
- 中文友好冲突反馈（`SaveFeedback.forConflict`）

### 行为

- 冲突仍为 `Status.INVALID` 并保留 `ValidationResult`；`requiresReload` 时不注入字段 error/errorCount，保存禁用，普通编辑不清冲突
- 非 reload 冲突（`DRAFT_MODIFIED_DURING_SAVE` / `SAVE_DURING_NOTIFICATION`）保留草稿可重试
- **不得**自动 reload / 自动重试 / 静默覆盖 Authority；reload 显式丢弃编辑
- SIMPLE_LIST / FontSort Authority 为空时 prefill 只进展示；用户首次编辑/删除/拖拽才写 draft 并 dirty=true
- 内部诊断至少 WARN/DEBUG 含 `conflictType`，避免敏感值与逐字段噪声

### 兼容性说明

- 公共 API **仅新增/扩展**；`Status` 三态与既有工厂方法保持兼容
- `setDraftAndCurrent` / `seedFieldBaseline` 保留但 deprecated（不再改事务 base）
- 源码版本号仍由 Git tag / GTNH Gradle 推导
