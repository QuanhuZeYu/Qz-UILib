# Qz-UILib 4.5.0

**本版要点**

- UI 主路径从 document / CSS 语义栈整体切换为声明式 scene 栈（signal → 脏标 → layout → Display List → GL）：控件改为纯静态工厂 + `SceneNode` 组合，无 Widget 继承树，更新粒度到属性级。
- scene 分层与入口落地：节点与脏标、布局、绘制、运行时、输入、浮层、控件、表单壳与宿主各就各位，Display List（`PaintCommand` / `PaintPlan`）是数据层与渲染层之间的唯一契约。
- 控件契约与样板收敛：静态工厂、create 体一次、样式经 bind 派生等契约集中在 `control/package-info` 与 `NORTH_STAR.md`，`SceneControlChrome`、`SceneAutocomplete`、`DraftListBridge` 收敛重复样板。
- 配置页现代化：通用框架 `club.heiqi.config`（schema / runtime 三态）+ `club.heiqi.config.ui`（`ConfigUI` / `ConfigScreen` / FieldRenderer），本 mod 接入 `uilib.config.modern` 并改走 YAML schema。
- 新增诊断入口 `/qzuilib test`（scene 新栈 test hub）与 `/qzuilib modernconfig`，并累积字体硬裁切与 mipmap 羽化约束、fontSort 拖拽手感与 scene 输入链修复。

## 兼容性与升级动作

- 破坏性变更：HTML-like `UiDocument` / `ElementNode` 业务建页主路径已移除，替代 = scene：`SceneRuntime` + `Scene*` 控件 + `AbstractSceneHostWidget` / `McScreenBridge`。
- 破坏性变更：`ForgeConfigTemplateScreen` 及 Spec / 网络同步 API 已移除，替代 = `ConfigUI.buildScreen` + 自写 GuiScreen 桥（本 mod 见 `ModernConfigEntry`）。
- 破坏性变更：远程配置同步 API 整支移除（`ConfigTemplateSyncManager` / `RemoteConfigDocumentPages` 等），能力移除、重建需新设计；通用远程 HTML 门面（`RemoteDocumentPages` / `RemoteHudOverlays` / `ui.remote`）不在源树。
- 破坏性变更：旧 Forge `.cfg` 不再是本 mod 配置权威源，改用 YAML schema 驱动（`qzuilib-modern.yaml`）；`.cfg` 废弃且不互通。
- 仍可用：网络层 `NetService` 等普通业务网络 API（与已删远程 UI 门面无关）；字体 `FontService` 等 API（配置写入路径已走 modern 回灌）。
- 迁移指引：① 声明 `ConfigSchema` → `ConfigManager.bootstrap(file, schema)`；② `ConfigUI.buildScreen(manager, input, registryCustomizer, restorePolicyCustomizer)`；③ 用 `McScreenBridge`（或等价）把 `ConfigScreen` 包成 MC `GuiScreen`；④ 业务 UI 页面改用 scene 控件与 `AbstractSceneHostWidget` 建屏，不要再依赖 document 栈。
- 已知限制：4.1 / 4.2 时期的文档中 LTS 清单仍含大量旧栈与远程 UI 条目，**不能**当作 4.5.0 的可用 API 清单，以源码与配置页使用文档为准。
- 发布渠道仍为 JitPack + GTNH Maven；版本号由 Git tag / GTNH Gradle 推导。
