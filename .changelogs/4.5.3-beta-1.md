# Qz-UILib 4.5.3-beta-1

## 更新

- 本版在 4.5.2 之上收紧配置草稿所有权，纳入参与式写前检测、UI 主线程契约、从磁盘显式 reload（完整校验 + RELOAD 事件）、通知期事务封锁、配置回灌全局协调器与 disk 严格 NodeType、批次交换派发、简化线性化协调器与 section raw overlay 保留。
- 新增 `ConfigFileSnapshot`：canonical 路径 + 一次读取的不可变原始字节，状态 `MISSING` / `REGULAR` / `NON_REGULAR`，精确字节等价（不依赖 mtime / hash）；写域仅覆盖 canonical path 语法别名（**不**保证硬链接 / inode）。
- 新增 `ConflictType.CONFIG_FILE_CHANGED_SINCE_LOAD`（`requiresReload=true`）与 `ConfigConflictException`（兼容 `flushRaw throws ConfigException`）。
- `ConfigManager` / `Persistence` 持 expected 磁盘快照：save / flushRaw 冻结 expected 基线，commit 复核 manager expected 仍等基线且 disk compare 用该基线——reload 推进 expected 后旧 prepared 结构化冲突，禁止拿新 expected 写旧 prepared。
- 新增 `ConfigManager.reloadDraftFromDisk()`：三阶段 capture → 锁外完整校验 → 写域 commit，成功发布 `ChangeType.RELOAD`，结构化 `ConfigReloadException.Reason`；新增 `ConfigManager.owns(DraftBuffer)`，`DraftSignalAdapter` owner 线程封闭（含 `seedFieldBaseline`）。
- 新增 `SchemaReplaceCompatibility` 与 `Persistence` 包级 fault injector；通知期封锁覆盖 BATCH_SAVE **与** RELOAD 期间的 save / flushRaw / reload + Legacy mutation（fail-closed）。
- 新增 `ModernConfigApplyCoordinator` + `ConfigSaveListener`：单一 monitor 线性化（generation++ 在锁内；register 同线程 apply 中 fail-fast `IllegalStateException`；其他线程因 monitor 自然阻塞；apply 同锁复核后受控执行；无 wait / condition / lease），no-spin，tick `retryPendingOnce`；register 返回后旧 apply 不得写，生产 apply 回调不得反向 register。
- `MainThreadDispatcher` 改为真正批次交换（每 side lock + `ArrayDeque`；drain 原子 swap 旧 batch，锁外消费；swap 后 enqueue 仅进新队列 / next-drain），带 per-side drain owner CAS（第二 drainer 返回 0，不可双消费）、FIFO + `RuntimeException` 隔离；任务体或 ErrorSink 抛 `AssertionError` 时，锁内把旧 batch 未消费尾部按原顺序前置到 next batch 再 rethrow；禁止 `CLQ.size` / `queue.size` 快照。
- 新增 `ConfigException.Category`（VALIDATION / IO / CONFLICT / UNSPECIFIED），reload / UI 禁止英文 substring 匹配。
- section raw overlay：schema section 内未知字段 / 子树在 load 时保留（**仅 MAP**）；`prepareWrite` 以 raw 为底再覆盖 schema typed（路径冲突 schema 优先）；**scalar / list section 的 bootstrap / reload fail-closed**，禁止静默默认覆盖；`ConfigEventBus.subscribe` 改用 `addIfAbsent`。
- disk / legacy raw 严格类型：STRING / CHOICE 仅 STRING；BOOLEAN 仅 BOOLEAN；NUMBER 仅 NUMBER（quoted `"80"` 拒绝）；SIMPLE_LIST 仅 LIST 且每项非 null STRING（严格拒绝 null 元素）；schema 字段 `setRawJson` 错型抛异常且零变化。UI 侧 NUMBER 字符串解析**仅**限 DraftBuffer 提交边界，与 disk 路径分离。

## 兼容性与升级动作

- 公共签名保留但保存行为收紧：`DraftBuffer.from(authority)` 是 unowned，任意 `manager.save` 返回 `DRAFT_OWNER_MISMATCH` 且 Authority / 磁盘 / 事件零副作用；保存调用方需迁移到 `manager.openDraft()`（唯一受支持的草稿获取路径）。
- `flushRaw` 仍 throws `ConfigException`（配置冲突为其子类）。
- `Persistence.writeAll` 已 deprecated：低级入口、无 expected 比较、**不**走参与式写前检测；生产 `ConfigManager` 不调用它。
- 已知限制：写前检测**不是** OS 级跨进程 CAS，只保证**同 classloader 的参与式 writer**；原子写（temp + move）**不**承诺 fsync / 掉电持久化。
- 迁移 / 恢复语义：move 失败后 draft base / current 保持旧值、proposed 保留、dirty 为 true，清 hook 后可重试。
- 对比基线 4.5.2。本标签面向连续 beta 验证，不是稳定 4.5.3；稳定公共能力目标归入 4.6.0。
