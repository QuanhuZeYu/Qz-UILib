# Qz-UILib 4.9.1 版本说明

状态：草案（本轮只登记增量，发布前回填 CI 证据与运行态验证边界）。

## 本次更新

- 公开 HUD 编辑契约：新增 `club.heiqi.uilib.ui.hud.api.HudEditTarget`（不可变目标值对象：hudId + 预览内容工厂 + 默认放置 + 可选外接工具栏规格）与 `HudEditService`（可编辑目标注册表 + 编辑意图），第三方 Mod 不再需要依赖 `internal/chat3` 即可把自己的 HUD 接入聊天屏的拖动布局编辑。
- 编辑意图与宿主生命周期：`requestEdit(hudId)` 只发布「进入编辑并聚焦该目标」意图，由**当前打开**的聊天输入屏消费；聊天屏关闭时意图静默丢弃，不排队、不抛异常，`isEditing()` 不受影响。`revision()` 在目标增删时 +1，宿主据此重建预览；`clear()` 只清注册表、不动宿主绑定。
- 聊天输入屏编辑态通用化：编辑子模式为每个已注册目标渲染预览浮层（内容由 `HudEditTarget.getPreviewFactory()` 构建，**统一装配 - / 1:1 / + 缩放入口**；`getToolbarSpec()` 降级为可选的额外自定义工具），左键命中拖动写 `HudLayoutService` 草稿，clamp 口径 = 外框尺寸（内容 + 工具行 gap + thickness，并按该 HUD 的统一倍率换算），与既有 `applyOuterPlacement` 同源；Esc 在拖动中先回滚手势、再次 Esc 取消会话；保存/取消/恢复当前（作用聚焦目标）/恢复全部沿用既有工具栏按钮语义，不新增按钮。
- HUD 缩放内聚化（用户反馈修复）：每 HUD 倍率从「外接工具栏注册项」提升为**统一缩放状态**——`HudToolbarService.scale(hudId)` 惰性创建、独立于工具栏注册（注销工具栏不重置倍率），宿主 `SceneHudHost` 与打开态聊天屏都读它；未注册外接工具栏的 HUD 也能被缩放（此前不注册工具栏则倍率恒 1.0，这是 Miner HUD 调不了缩放的根因）。
- 缩放入口只在编辑态：非编辑态（关闭态 HUD）不挂任何缩放控件，缩放只按统一倍率呈现；下游不再需要为了拿到倍率而塞一个空槽工具栏。`HudToolbarService.scale(String)` 签名未变、语义升级为「该 HUD 的统一缩放状态」。
- 零回归边界：`qzuilib:chat3` 自身编辑路径（内置「编辑 HUD」动作、拖动、重置、开合动画、关闭清理）语义与 4.9.0 基线一致；非编辑态不注册任何预览浮层、不拦截输入。既有公开签名只新增不修改。

## 兼容面（4.9.0 → 4.9.1）

- **纯增量**：`club.heiqi.uilib` 下非 internal / shadow / mixin 的类文件 1048 → 1057，零类删除、零 public / protected 成员删除或签名（含方法修饰符）变更。其中新增**公开**类 8 个：`HudEditService`、`HudEditService$1`、`HudEditService$2`、`HudEditService$Host`、`HudEditService$Registration`、`HudEditTarget`、`HudEditTarget$1`、`HudEditTarget$Builder`；另有 1 个包内实现类 `HudScaleRegistry`（统一缩放注册表，非公开 API）。
  - 工具：`javap -public` 全量逐类对比；基线 = 4.9.0 正式 Release dev 资产 `qz_uilib-4.9.0-dev.jar`。
  - 实测结论：`oldPublicClasses 1048 / newPublicClasses 1057 / missingClasses [] / removedOrChangedMembers {}`；`addedClasses` 9 项 = 上述 8 个公开类 + `club.heiqi.uilib.ui.hud.api.HudScaleRegistry`。
  - 可复现命令：`python D:\Code\MC\Qz工作站\temp\uilib_public_api_diff.py` —— 脚本内 `NEW` 常量指向**当前交付件**（本轮指向消费方 Miner 侧 `libs/qz_uilib-4.9.1-dev.jar`，与 UILib `build/libs/qz_uilib-4.9.1-dev.jar` 字节一致，同一 sha256 `57bab4c2d03822ba5ca375b26353b90af37edb2658859cdce80eda7eaba5e610`（3778638 bytes，「缩放内聚化」后的重建件）；换基线时只改该常量），`OLD` 指向 4.9.0 正式 Release dev 资产；脚本逐类 `javap -public` 对比后打印上述 JSON（按本文命令原样执行即得该结论）。
- **远端版本范围不变**：`MyMod.acceptableRemoteVersions` 保持 `[4.9.0,4.10.0)` —— 4.9.0 与 4.9.1 双端互相接受、可混用。这正是选择 4.9.1 的关键收益：新版本落在既有区间内，既不用改常量、也不用双端协调升级（若按原 4.10.0 口径发布，旧 4.9.0 端会被拒，必须同步升级；R2 由此自动消解）。
- **消费方范围建议**：只用既有 API 的调用方可继续声明 `[4.9.0,…)`；使用 `HudEditService` / `HudEditTarget` 新 API 的调用方必须声明 `≥ 4.9.1`（旧版本不含这些类型，运行期会 NoClassDefFoundError）。
- **行为面**：① internal 编辑态——`ChatInputSurface` 的 `focus` 参与「恢复当前默认」的目标选择，无第三方注册目标时逐位回退既有行为；② HUD 缩放归属调整（修复性）——未注册外接工具栏的 HUD 现在按统一倍率缩放（此前恒 1.0），`HudToolbarService.scale(String)` 对未注册工具栏的 HUD 返回惰性创建的统一状态、注销工具栏不再重置倍率（签名未变）；不使用缩放的调用方行为不变。网络协议、配置持久数据、公共类与公开签名均无变化。

## 兼容性说明

- 全部为新增 API：`HudEditTarget` / `HudEditService` 与既有的 `ClientHudService` / `HudToolbarService` / `HudLayoutService` 并存；不注册 `HudEditTarget` 的调用方行为完全不变（编辑态不出现其预览）。
- `HudEditService.Host`（`requestEnterEdit(String)` / `isEditing()` / `focus()` + `attachHost` / `detachHost`）是 UILib 内部聊天屏的接线端口，属实现接缝：第三方调用方不实现、不调用；语义变化只在 major 版本发生。
- 编辑会话仍是会话内内存（草稿 / 提交 / 取消），跨重启持久化仍属后续版本。
