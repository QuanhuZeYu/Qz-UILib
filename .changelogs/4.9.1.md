# Qz-UILib 4.9.1 版本说明

状态：**发布定稿**（发布日期 2026-09-11；4.9.1 全部 9 个提交入库，本机完整构建、javap 全量兼容对比与两轮独立验证均已回填，仅分支 CI run 链接待 Lead 推分支后补入）。

## 本次更新

- 公开 HUD 编辑契约：新增 `club.heiqi.uilib.ui.hud.api.HudEditTarget`（不可变目标值对象：hudId + 预览内容工厂 + 默认放置 + 可选外接工具栏规格）与 `HudEditService`（可编辑目标注册表 + 编辑意图），第三方 Mod 不再需要依赖 `internal/chat3` 即可把自己的 HUD 接入聊天屏的拖动布局编辑。
- 编辑意图与宿主生命周期：`requestEdit(hudId)` 只发布「进入编辑并聚焦该目标」意图，由**当前打开**的聊天输入屏消费；聊天屏关闭时意图静默丢弃，不排队、不抛异常，`isEditing()` 不受影响。`revision()` 在目标增删时 +1，宿主据此重建预览；`clear()` 只清注册表、不动宿主绑定。
- 聊天输入屏编辑态通用化：编辑子模式为每个已注册目标渲染预览浮层（内容由 `HudEditTarget.getPreviewFactory()` 构建，**统一装配 - / 1:1 / + 缩放入口**；`getToolbarSpec()` 降级为可选的额外自定义工具），左键命中拖动写 `HudLayoutService` 草稿，clamp 口径 = 外框尺寸（内容 + 工具行 gap + thickness，并按该 HUD 的统一倍率换算），与既有 `applyOuterPlacement` 同源；Esc 在拖动中先回滚手势、再次 Esc 取消会话；保存/取消/恢复当前（作用聚焦目标）/恢复全部沿用既有工具栏按钮语义，不新增按钮。
- HUD 缩放内聚化（用户反馈修复）：每 HUD 倍率从「外接工具栏注册项」提升为**统一缩放状态**——`HudToolbarService.scale(hudId)` 惰性创建、独立于工具栏注册（注销工具栏不重置倍率），宿主 `SceneHudHost` 与打开态聊天屏都读它；未注册外接工具栏的 HUD 也能被缩放（此前不注册工具栏则倍率恒 1.0，这是 Miner HUD 调不了缩放的根因）。
- 缩放入口只在编辑态：非编辑态（关闭态 HUD）不挂任何缩放控件，缩放只按统一倍率呈现；下游不再需要为了拿到倍率而塞一个空槽工具栏。`HudToolbarService.scale(String)` 签名未变、语义升级为「该 HUD 的统一缩放状态」。
- 编辑态预览缩放自持（用户反馈修复）：预览浮层此前与聊天屏共用同一个绘制倍率——自身倍率只进 placement/clamp 盒、不进实绘，于是点 `-` / `1:1` / `+` 看不到尺寸变化（左/上锚点目标连位置都不动），而聊天屏倍率会把**全部** HUD 预览一起缩放。本轮新增 **overlay 相对渲染倍率**（`SceneOverlayHost.Entry.getRelativeScale() / setRelativeScale(float)`、`OverlayHandle.setRelativeScale(float)`，默认 `1.0F` = 跟随宿主），帧管线按该倍率换算回放后端与布局视口、输入路由按同一倍率换算命中/派发坐标；`ChatHudEditPreviews` 每帧写入 `target / hostScale`，每个 HUD 预览因此按自身统一倍率渲染与命中，聊天屏（`qzuilib:chat3`）倍率只作用于聊天屏自身。放置盒、实绘、命中、夹取四口径同源（盒 = 逻辑外框 × 自身倍率，margin = 物理位置 ÷ 自身倍率）。
- 零回归边界：`qzuilib:chat3` 自身编辑路径（内置「编辑 HUD」动作、拖动、重置、开合动画、关闭清理）语义与 4.9.0 基线一致；非编辑态不注册任何预览浮层、不拦截输入。既有公开签名只新增不修改。
- 缩放后 tooltip / 锚定浮层位置错（用户实机：编辑预览外框 - / 1:1 / + 按钮的悬停提示偏位，task-10 修复）：根因在 `SceneFramePipeline.layoutOverlays` 的锚定分支——`AnchorProvider.forNode` 返回的是「触发节点所在树」的绝对盒，此前被直接当成宿主局部盒、与宿主 w/h 一起参与 `SceneAnchorResolver` 解析；触发节点位于相对倍率 s != 1 的非锚定 overlay（HUD 编辑预览）内时，触发盒属于「该 overlay 逻辑空间 = 宿主逻辑 ÷ s」，而锚定浮层自身 s 恒为 `1.0F`、在宿主逻辑空间回放，跨树坐标缺一次 ×s 换算，浮层物理位置随 s 错位（s > 1 偏左上、s < 1 偏右下，偏差随触发坐标线性放大）。现于锚定分支前置 `toHostLogicalBox`：沿触发节点父链定位所属 overlay entry，换算为 `宿主逻辑 = round(overlay 逻辑 × s) + 该 overlay 锚点偏移`（取整与 `phaseReplay` / `SceneInputRouter` 同口径）；主树触发、`s == 1F` 且无锚点偏移的触发、矩形探针（`getNode() == null`，契约已是宿主坐标）与未挂载/未知节点全部原样返回（零分配、零乘除）。无公共 API 变更。
- HUD 布局与缩放持久化（用户需求：Miner 编辑后的位置与缩放跨重启保留，且不能存绝对坐标）：位置改落「四角锚点 + 该轴行程百分比 + 缩放百分比」的 `schemaVersion=1` 文本，百分比分母 = 可用空间 − 内容物理盒（与 `HudLayoutResolver.clamp` 的可行区间逐点同源：fraction = 0/1 即贴锚点侧/对侧安全边，内容超出可用空间时行程为 0）；新增公共 `ui.hud.api.HudLayoutStore`（宿主唯一实现面：`String load()` / `void save(String text)`，纯文本 IO，不解析 schema、不做坐标数学、不引用 UI/缩放类型）、`HudLayoutMetrics`（每帧度量值对象）与 `HudLayoutPersistence`（窄入口 `install / uninstall / isInstalled`），`HudLayoutService` 新增 `attachStore / detachStore / hasStore / reload / save / observe`。编辑提交时按内容盒中心所在象限自动选最近角锚点（平局取 LEFT/TOP，重锚定不改变用户看到的盒）；宿主每帧 `observe(metrics)` 上报后，视口/内容变化按已保存百分比还原；缩放与位置同一条记录、同一次落盘（缩放变更先置脏、下一次 `observe` 合并写一次，渲染路径不无条件写盘）；损坏或未知 `schemaVersion` 数据降级为默认布局且本次会话不自动写回（不覆写无法识别的数据、同一快照里其它 hudId 的有效记录不受影响）。未安装端口 / 未上报度量时全部路径直通：`observe` 首行 volatile 直返，提交与重置保持既有内存语义（不自动改锚、不写盘），行为与 4.9.0 逐位一致。

## 兼容性说明

- 全部为新增 API：`HudEditTarget` / `HudEditService` 与既有的 `ClientHudService` / `HudToolbarService` / `HudLayoutService` 并存；不注册 `HudEditTarget` 的调用方行为完全不变（编辑态不出现其预览）。
- `HudEditService.Host`（`requestEnterEdit(String)` / `isEditing()` / `focus()` + `attachHost` / `detachHost`）是 UILib 内部聊天屏的接线端口，属实现接缝：第三方调用方不实现、不调用；语义变化只在 major 版本发生。
- 编辑会话仍是会话内内存（草稿 / 提交 / 取消）；跨重启持久化已由本轮 `HudLayoutStore` 端口提供，但**必须宿主显式接线**：实现端口并从客户端初始化点调用 `HudLayoutPersistence.install(store)`。未安装端口的调用方（只读布局、只用编辑草稿）行为与 4.9.0 逐位一致；安装后由宿主实现文件 IO（原子写由宿主保证），UILib 负责格式、schemaVersion 与降级判定，宿主不需要 flush。
