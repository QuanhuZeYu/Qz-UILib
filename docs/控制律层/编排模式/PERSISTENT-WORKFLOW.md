# 持久工作流

## 1. 记忆分层

- **L0 会话缓存**：当前聊天、工具输出和模型上下文。它易失、可截断且不具权威性；不得让后续动作只依赖 L0。
- **L1 任务工作记忆**：`.opencode/tasks/<id>.md` 与 `INDEX.md`。保存单项工作的目标、决定、假设、范围、状态、证据、阻断、唯一下一步和结果。
- **L2 项目语义记忆**：`AGENTS.md`、`NORTH_STAR.md` 与 `docs/` 各层权威文件。保存跨任务长期有效的规则、契约、业务状态、决策和错误预防。
- **L3 情景档案**：状态为 `DONE`、`CANCELLED` 的任务文件，以及历史审查/规格等可追溯记录。用于解释特定任务当时的范围和证据，不覆盖 L2 现行规则。

实时分支、HEAD 与工作区以 Git 为准。发生冲突时先核对实时 Git，再以 L2 现行规则约束 L1；L3 只作历史证据。任务中新形成的长期事实应归并到 L2，而不是长期滞留在 L1。

## 2. 三种入口

### CHAT

简单问答、只读定位或可在当前轮闭环的轻量工作不创建任务。若结论将影响后续动作，必须转入 DESIGN 或写回已有任务，不能只留在聊天中。

### DESIGN

需要跨轮澄清、设计或等待决定时，创建 `DRAFT` 任务并登记到 `INDEX.md`。目标、非目标、已确认设计、写集和验收均确认后转为 `READY`；公共 API、依赖版本、发布取舍或写集仍未决时不得进入执行。

### EXECUTE

从 `READY` 进入执行时改为 `ACTIVE`，由一个明确所有者负责规划、实施、静态核对、自审、提交和结果写回。默认所有者为 OpenCode 内置 `build`。不得让多个会话同时拥有同一 `ACTIVE` 任务；交接前先释放旧所有权并写明新所有者。

## 3. 状态机

- `DRAFT`：目标或设计仍在形成，不得写 production 改动。
- `READY`：目标、范围、写集和验收已确认，尚未开始写盘。
- `ACTIVE`：唯一所有者正在实施或核对。
- `BLOCKED`：存在明确阻断；必须记录阻断证据与解除阻断后的唯一下一步。
- `DONE`：验收完成，结果和证据已写回；唯一下一步为“无”或明确的仓外后续。
- `CANCELLED`：任务明确终止；记录原因和已产生改动的处置。

允许的主要流转为 `DRAFT → READY → ACTIVE → DONE`。信息不足可由 `ACTIVE → BLOCKED → READY/ACTIVE`；范围变化使验收失效时退回 `DRAFT`。任意未完成状态可在记录原因后进入 `CANCELLED`。

## 4. 持久化与恢复

影响后续动作的目标、决定、假设、状态、证据、阻断和下一步必须写入 L1 或归属的 L2。至少在以下边界覆盖式写回任务正文与索引：

1. 创建任务、确认设计、开始执行或改变状态时；
2. 写集、验收、风险或所有权发生变化时；
3. 获得关键证据、发现工作区漂移或进入阻断时；
4. 提交前完成自审时；
5. 完成、取消、暂停或准备结束会话时。

恢复工作时只需读取 `AGENTS.md`、权威文档、`INDEX.md`、目标任务和实时 Git。先验证任务中的分支/HEAD/工作区事实，再执行“唯一下一步”；事实漂移时先写回任务，不凭旧聊天猜测。

每个未完成任务必须只有一个可立即执行的下一步。并列计划应留在动作或风险中，不得伪装成多个“下一步”。简单问答不为追求形式完整而建任务。

## 5. 验证与提交

内置 `build` 只按任务写集实施，提交前对照目标、非目标、验收、风险与 `git diff` 自审。UILib agent 本机仍禁止 Gradle、编译、构建、测试、运行态和 verify；任务必需的此类实证交 CI 或用户，缺少时任务保持 `BLOCKED` 或结果标记 `INCOMPLETE`。

Git、环境所有权、不可逆操作和发布边界继续以 `AGENTS.md` 为准。关键发布或高风险变更需要额外隔离审查时，由用户另开新会话或安排外部 review，不恢复仓内自定义 agent 编排。
