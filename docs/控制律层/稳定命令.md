# 稳定命令

本文件记录项目可长期复用的构建、检查、测试和运行命令。

## 环境前提

- Windows 环境，PowerShell
- 环境所有权遵循 `AGENTS.md`「控制律层·环境所有权」：本机归用户、CI 归 runner，agent 只读核验，禁止赋值、持久修复或用 Gradle home/JDK 参数绕过。
- `GRADLE_USER_HOME` 由用户在 agent 外部预先配置为纯 ASCII 路径。执行 Gradle 前，agent 仅逐项只读核验其非空与路径形态；缺失或异常时停止 Gradle，返回 `INCOMPLETE` 并询问用户。
- 不要并行执行多个 Gradle 构建命令，尤其不要同时运行 `compileJava`、`test`、`build`

## 常用命令

> 以下原始 Gradle Wrapper 命令仅供用户、维护者或 CI，并假定已在 agent 外部正确配置 `GRADLE_USER_HOME`；agent 必须使用下方 OpenCode 有界协议。

- 编译：`./gradlew.bat --no-configuration-cache compileJava`
- 测试：`./gradlew.bat --no-configuration-cache test`
- 离线测试（依赖已缓存、GitHub manifest 不可达时回退）：`./gradlew.bat --offline --no-configuration-cache "-Pgtnh.settings.blowdryerTag=" test --tests "<类名>"`
- 离线编译（GitHub manifest 不可达时回退）：`./gradlew.bat --offline --no-configuration-cache "-Pgtnh.settings.blowdryerTag=" compileJava`
- 客户端：`./gradlew.bat --no-configuration-cache runClient21`，启动前会自动写入 `run/client/config/CodeChickenLib.cfg` 的 `mappingDir`
- Git 空白检查：`git diff --check`
- scene 边界门禁：`pwsh scripts/check-scene-boundaries.ps1`（评审 scene 改动前必跑，断言清单见 `docs/传感层/门禁脚本说明.md`）
- publication 分类器与 Remote 收敛判定自测（不调用 Gradle、不访问远端）：`& .\scripts\check-publication.ps1 -SelfTest`
- GitHub Release 合同自测（隔离 fixture，不调用 Gradle、不访问 GitHub）：`& .\scripts\check-github-release.ps1 -SelfTest`
- GitHub Release workflow 静态检查：`& .\scripts\check-github-release.ps1 -Static -WorkflowRoot .github/workflows`

## OpenCode 有界 Gradle 协议

- 唯一入口为 `qz-gradle-opencode/v1`，合同见 [`Windows-Gradle执行协议.md`](Windows-Gradle执行协议.md)。fixer 用脚本 `Start/Poll/Wait`，SUBAGENT 验收统一 `Start/Wait`，不得直接 wrapper；reviewer 仅按合同复验，explorer 仅诊断既有 RunId，其他 agent 禁止。协议允许稳定离线回退所需的空 `-Pgtnh.settings.blowdryerTag=`。
- 普通编译 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('--no-configuration-cache', 'compileJava')`
- 普通测试 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('--no-configuration-cache', 'test')`
- 离线编译 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('--offline', '--no-configuration-cache', '-Pgtnh.settings.blowdryerTag=', 'compileJava')`
- 离线目标测试 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('--offline', '--no-configuration-cache', '-Pgtnh.settings.blowdryerTag=', 'test', '--tests', '<类名或类名.方法>')`
- 启用 configuration cache 的完整构建 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('build')`；验证缓存复用时须在前一次 RunId 到达终态后再启动第二次同命令
- 发布到本地 Maven Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('publishToMavenLocal')`
- 查询：`& .\scripts\run-gradle-opencode.ps1 -Action Poll -RunId '<RunId>'`
- 等待：`& .\scripts\run-gradle-opencode.ps1 -Action Wait -RunId '<RunId>' -WaitSeconds 30`
- `GradleArgs` 多项参数必须在当前 PowerShell 进程中用调用运算符 `&` 传数组；不得使用外层 `pwsh -File ... -GradleArgs @(...)`，以免数组绑定丢失。
- 自测（不调用 Gradle）：`& .\scripts\run-gradle-opencode.ps1 -SelfTest`。
- `runClient*`/`runServer*` 交用户执行；verify 类脚本暂不授权给 agent。

## Publication 本地检查

- 普通 publication 必须先通过上方协议启动 `publishToMavenLocal`，等待对应 RunId 成功终态后，再执行以下只读分类检查；不得并行启动第二个 Gradle：

```powershell
& .\scripts\check-publication.ps1 -Local `
  -RepositoryRoot (Join-Path $HOME '.m2/repository') `
  -BuildMainJar 'build/libs/qz_uilib-4.6.2.jar' `
  -BuildDevJar 'build/libs/qz_uilib-4.6.2-dev.jar' `
  -BuildSourcesJar 'build/libs/qz_uilib-4.6.2-sources.jar' `
  -GroupId 'club.heiqi.uilib' -ArtifactId 'Qz-UILib' -Version '4.6.2' `
  -ModuleMetadata RequiredCorrect
```

- `RequiredCorrect` 是普通 publication 的固定策略，要求正确 GMM；JitPack 模拟使用的 `Forbidden` 策略与 `JITPACK`、`GROUP`、`ARTIFACT`、`VERSION` 只允许由 CI runner 在 workflow 中声明。agent 本地禁止设置或清空这些变量来模拟 JitPack，也不得把 runner 权限解释为本地授权。
- `check-publication.ps1 -SelfTest` 还覆盖 Remote 整体收敛分类：202/404/408/425/429/5xx、building、未完成日志或制品可保持 pending；权限错误、非零退出、错误/缺失身份、GAV/hash 冲突、module 污染等确定性错误立即 fail-closed，不能被同时存在的 pending 遮蔽。
- `check-publication.ps1 -Remote` 与 clean consumer 仅由独立 `jitpack-advisory.yml` runner 执行，不是本地 agent 的远端验证授权；其结果只确认 JitPack 渠道，不是 GitHub Release 前置。

## GitHub Release 本地传感

- `check-github-release.ps1 -SelfTest` 使用隔离 bundle 与 workflow mutation fixture 覆盖四资产、身份/manifest、远端状态、control/target 双 checkout 和 recovery 默认分支 guard；权限 split 负例另覆盖 read caller 误调 write graph、wrapper 额外写权限或复制 gate、output/白名单接线、同 run artifact 一次上传两次下载、跨 run 参数及 concurrency 错位。保留权限 quoted/flow/block-scalar 与 shell 诱饵测试，不调用 Gradle、不访问 GitHub。
- `check-github-release.ps1 -Static -WorkflowRoot .github/workflows` 只读检查当前 workflow：read contract job 集合精确为 `gate/preflight` 且零写，write wrapper 精确为 `verify/publish-release` 且仅后者写；verify-only 直调 read contract，tag/recovery publish 只调 wrapper；两个 reusable 保持 control/target 边界、同 run artifact 与 release status 输出合同，并禁止 reusable concurrency。
- `-Identity`、`-Local`、`-Remote` 是 GitHub-hosted workflow 的合同阶段，不是本地 agent 授权；尤其 `-Remote` 需要 runner token，dispatch、Remote、创建/编辑 Release、移动 tag、push 均必须由用户授权并由相应 runner/维护者执行。本地 SelfTest/Static 通过不等于 GitHub-hosted verify-only、publish 或正式 Release 已成功。
- Gradle 仍只能走 `qz-gradle-opencode/v1`；Release workflow 内 runner 的 wrapper、环境与写权限不构成本地 agent 绕过协议的授权。
- `runClient*`、`runServer*` 与 verify 类脚本的既有边界不变。

## CI gate 语义

- Ubuntu gate 使用 `./gradlew --no-configuration-cache test`，不是 Windows 专用的 `gradlew.bat`。
- Ubuntu gate 使用项目约定的 JDK 25（Gradle 9.3.1 运行时要求 JVM 17+）。
- CI gate 可由 runner 在 workflow 中声明 ASCII `GRADLE_USER_HOME`；不得打印敏感变量。该 runner 权限不构成本地 agent 的环境修改授权。

## 验证边界

- 纯 JVM 测试不要直接实例化继承 `GuiScreen` / `BaseScreen` 的页面类
- 每批开发应至少保持 `git diff --check`、相关测试、`compileJava` 可通过
- `runClient21` 若弹出 MCP 映射目录选择窗口，优先确认 `GRADLE_USER_HOME` 是否已指向纯 ASCII 路径，以及 `configureCodeChickenMappings` 是否已生成 `run/client/config/CodeChickenLib.cfg`
- 涉及游戏内 UI、HUD、输入、命令入口、远程页面或网络 smoke 的能力，需要使用 `runClient21` 进入游戏内验证
- `/qzuilib test` 当前打开 scene 新栈 test hub；`/qzuilib scene_test` 是同一入口的过渡别名
- 网络、远程页面、远程 HUD 与配置同步自检是后续 test 页面重建目标；恢复后仍需要提交按钮完成表单回传验证
- `verifyRunClasspathIsolation` 已接入 `check` 与标准 `runServer`：要求 `runServer` / `runVanillaServer` / `runObfServer` 最终 classpath 不含 LWJGL3ify 自身 artifact，同时要求 `runClient` / `runClient21` 仍保留；`runServer17` / `runServer21` / `runServer25` 不在隔离范围。该门禁通过只证明类路径构造正确，dedicated server 启动仍须由 CI smoke 证明
- Forge 网络回退仍需单独切换 `netTransport=forge` 或 `-Dqzuilib.net.transport=forge` 验证
- `gtnhconvention` manifest 不可达时，单独 `--offline` 仍可能在 Blowdryer 配置阶段失败；需要同时传入 `"-Pgtnh.settings.blowdryerTag="` 临时禁用远端设置 tag 拉取。

- 命令或环境前提变化后及时更新本文件
