# 稳定命令

本文件记录用户、agent 与 CI 的长期入口。代码改动由 agent 默认执行完整 build；运行态仍由用户或 CI 完成。

## 用户入口

以下命令可由用户在 agent 外部配置好 `GRADLE_USER_HOME` 后执行：

- 编译：`./gradlew.bat --no-configuration-cache compileJava`
- 测试：`./gradlew.bat --no-configuration-cache test`
- 完整构建：`./gradlew.bat --no-configuration-cache build`
- 客户端：`./gradlew.bat --no-configuration-cache runClient21`
- Git 空白检查：`git diff --check`

不要并行执行多个 Gradle 构建。环境异常由用户处理；agent 禁止赋值、持久修复或用 Gradle/JDK home 参数绕过。

## Agent 终端入口

- 除下述固定 Gradle batch 入口外，agent 只通过 `python scripts/run-agent-command.py -- <executable> <args...>` 执行 Git 等获准外部命令，不直接使用 PowerShell/CMD/Bash。
- 代码改动的默认验证是从仓根执行 `call gradlew.bat --no-configuration-cache build`；构建成功后才可提交，失败时继续修复并重跑。不得并行运行多个 Gradle 构建，也不得设置或持久修改用户环境来绕过失败。
- Python runner 使用参数列表、固定仓库 cwd、`shell=False`、300 秒超时与退出码传播；它继续用于 Git 等非 batch 外部命令。
- 复杂逻辑写成可审计 Python 文件，禁止复杂 `python -c`、命令字符串拼接、管道、重定向与 shell 插值。
- 纯文档或不影响构建输入的协作规则改动可跳过 Gradle，但仍须执行 `git diff --check`；`runClient*`、`runServer*` 与其他运行态不因本地 build 授权而自动开放。

## CI 入口

- `.github/workflows/build-and-test.yml` 调用固定 SHA 的 GTNH reusable workflow，并并行检查仓库零 PowerShell 约束。
- 固定 `4.6.2` recovery workflow 已完成并删除；其历史 runner 曾使用 Java 25 执行 `./gradlew --no-configuration-cache --no-daemon test build`。
- workflow dispatch、push、tag 与 Release 写入均须另有用户授权；CI runner 的环境和权限不构成本地 agent 授权。

## 验证边界

- 纯 JVM 测试不要直接实例化继承 `GuiScreen` / `BaseScreen` 的页面类。
- 游戏内 UI、HUD、输入、网络与渲染 smoke 由用户运行 `runClient21` 验证。
- `/qzuilib test` 打开 scene test hub；`/qzuilib scene_test` 是过渡别名。
- 每批代码改动至少保持完整 build 与 `git diff --check`，并明确记录运行态是否已有 CI/用户结果。
- agent 核对空白错误时使用 `python scripts/run-agent-command.py -- git diff --check`。
