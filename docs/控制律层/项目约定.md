# 项目约定

本文件记录项目级、长期有效、且不适合直接塞进 `AGENTS.md` 的具体约定。

## 文档约定

- 文档分层职责与写回纪律以 `AGENTS.md` 反馈层·文档协作为权威源，本文件不重复目录职责清单
- **Markdown 正文不写超长行**：建议每行 ≤ 200 字符，段落正文用换行分句，不把多个要点堆在一行。
  超长行会导致 Read 工具截断、Grep 难定位、Agent 难以精确引用行号。表格行因 Markdown 语法限制
  天然为长行，属结构例外，但应控制单元格内内容长度，单格不堆叠过多信息；偏离登记等需长描述的
  场景优先拆短句换行而非连写

## 协作约定

- 本次迁移只借鉴 Harmes-Rust 的仓库内分层记忆框架，不迁移其 Rust / egui 桌面 Agent 产品架构
- commit、merge、push、tag 和 release 只在用户明确要求时执行
- GitHub release 标题统一使用 tag 名；`.changelogs/<tag>.md` 只负责 release 正文，不负责标题，详细流程见 `docs/控制律层/发布流程.md`
- 需要具体类、入口和目录位置时，用 Glob/Grep/Read 现查，不在记忆文档维护易过期清单
- 当前 MCP 工具链可接入 jetbrains（见 `.opencode/opencode.json`），但 agent 终端命令统一经 `python scripts/run-agent-command.py` 参数列表执行；本机 Gradle、编译、构建、测试、运行态与 verify 仍禁止，必需实证交 CI 或用户，文件操作优先专用工具
- 临时调试记录和一次性试验结论不沉淀到长期记忆
- 发现长期事实已经能稳定归属到使用文档、开发者文档、错误记录或审查记录时，应写回原文档，不复制到总导航

## 任务笔记

复杂、跨轮或需等待外部决定的工作可在 `.opencode/tasks/` 写简短笔记。是否创建、采用何种结构以及何时更新，按实际恢复价值决定。

## 适合写入本文件的内容

- 项目特有的模块拆分约定
- 特定错误处理口径
- 配置文件组织方式
- 测试目录和命名口径
- 文档命名和示例维护约定

## 不适合写入的内容

- 通用 Git 规范、提交规范、Java 通用规范
- 当前任务状态或阶段计划
- 一次性试验结论
