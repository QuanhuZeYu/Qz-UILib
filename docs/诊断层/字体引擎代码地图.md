> 控制论定位：**诊断层·agent 代码地图**。本文用于快速建立源码心智模型、定位改动面和选择验证证据，

> `NORTH_STAR.md`、`docs/设定值层/边界.md` 与 `docs/反馈层/错误预防.md` 为准。

## 2. 总体心智模型

`FontService` 是字体运行时的 singleton composition root。它持有并协调：

| 成员 | 职责 | 是否直接拥有 GL 资源 |
|---|---|---|
| `FontCatalog` | 当前有序 AWT 字体的不可变快照和 catalog version | 否 |
| `FontGenerationRegistry` | 只消费冻结的资源 snapshot，prepare/validate catalog candidate，commit 后 publish | 否 |
| `FontRuntimeSettings` | 单代字符规则、排序、字号、spacing 与 sampling 配置的不可变快照 | 否 |
| `ActiveFontGeneration` | 单引用统一 version、measure epoch、settings、catalog、metrics、唯一 tables 与 lifecycle | 否 |
| `DerivedFontCache` | `(fontIndex, FontType, glyphSize)` → AWT 派生字体 | 否 |
| `FontMatcher` | 规则优先 + catalog fallback 的码点字体匹配 | 否 |
| `GlyphPageManager` | 当前代字形状态表、有界 upload mailbox、atlas transaction/pressure | page 在 upload transaction 内创建纹理 |
| `GlyphGenerationDispatcher` | 单 worker、有界 demand admission、promotion/aging 和 reload 屏障 | 否 |
| `FontGenerationCandidateScheduler` | 独立单 worker、单排队槽，后台构建 generation candidate | 否 |
| `TextLayoutService` | formatted/raw 解析、measure、trim、wrap、行指标 | 否 |
| `FontBatchRenderer` | 按字体页收集 quad，管理 VAO/VBO/EBO | 是，首次绘制时惰性创建 |
| `FontShaderProgram` | 编译、链接、绑定字体 shader | 是，首次 flush 时惰性创建 |

核心数据流：

```text
Authority / YAML
  -> ConfigValueBridge
  -> FontConfig static runtime snapshot
  -> FontService desired reload signal
  -> render owner: immutable FontGenerationBuildRequest
  -> candidate worker: FontResourceSnapshot + FontResourceFingerprint
  -> CPU-only FontGenerationCandidate (catalog + metrics)
  -> ActiveFontGeneration (settings + catalog + metrics + tables + lifecycle)
  -> FontMatcher / TextLayoutService
  -> DefaultFontRendererAdapter
  -> [glyph missing] GlyphGenerationDispatcher -> GlyphGenerator(AWT)
  -> immutable GlyphUploadPlan -> PendingGlyphUpload
  -> render thread: GlyphPageManager -> GlyphPage(GL texture)
  -> FontBatchRenderer -> FontShaderProgram -> FontRenderTool -> glDrawElements
```

不要把“测量运行时”“完整字体运行时”和“GL 资源已创建”混为一个状态：

| 状态 | 建立入口 | 已具备 | 尚未保证 |
|---|---|---|---|
| layout runtime ready | `FontService.ensureLayoutRuntimeReady()` | CPU candidate、active generation、matcher、稳定 line metrics、宽度测量、`textMeasureEpoch` | worker、pending upload、atlas texture、batch/shader |
| initialized | `FontService.initialize()` | layout 能力、page manager 规格、glyph worker | 具体页纹理、VAO/VBO/EBO、shader program 仍可未创建 |
| first ready visible glyph | worker 完成且 render thread flush upload 后 | 对应码点 metrics、slot、texture 内容；空白 glyph 仅有 metrics | 其他码点仍按需生成 |

## 3. 启动与配置链

### 3.1 启动顺序

```text
CommonProxy.preInit
  1. ModernConfigBootstrap.bootstrapAndApply
     -> ConfigManager.bootstrap
     -> Authority
     -> ConfigValueBridge.applyFromAuthority
     -> FontConfig.onConfigReload
  2. FontService.initialize
  3. NetTransportFactory.create
```

关键事实：

- `CommonProxy.preInit` 在 common proxy 中调用 `FontService.initialize()`；当前源码因此会在两侧建立非 GL 字体骨架。
- `EarlyMixins.buildMixinsForSide` 只在 `Side.CLIENT` 返回 `MixinFontRenderer`；dedicated server 不接管原版渲染。
- `ClientProxy.preInit` 才注册 `FontRenderTickListener` 和 JVM shutdown hook。实际 atlas upload、batch、shader 仍必须留在有 context 的客户端渲染线程。
- 冷启动的 `ensureLayoutRuntimeReady()` 必须在返回前具备测量能力，因此同步建立首个 CPU candidate；后续完整 reload 才由独立 candidate worker 读取 `<mcDir>/fonts` 下的 TTF/OTF/TTC，并枚举 `GraphicsEnvironment` 系统字体。测试或早期阶段无法取得 `Minecraft.mcDataDir` 时回退 `user.dir`；candidate prepare 不发布 active catalog。

### 3.2 配置保存/磁盘重载

```text
ConfigManager event: BATCH_SAVE / RELOAD
  -> ConfigSaveListener
  -> ModernConfigApplyCoordinator.submit
  -> MainThreadDispatcher CLIENT queue, latest-wins
  -> ConfigValueBridge.applyFromAuthority
  -> FontConfig.affectsFontRuntime
  -> FontService.reload (仅发布 desired signal)
  -> FontConfig.onConfigReload

后续 RenderTick.END
  -> FontService.tickMainThread
  -> FontReloadSignal stable ticket
  -> commit runtime generation
```

`ConfigValueBridge` 只负责从 `Authority` 写入 `Config` / `FontConfig` 静态运行时字段，并在写完
`characterFontRules` 后调用 `FontConfig.refreshDerivedRuleSet()`。是否发布 reload signal、何时推进 `last*` 快照由调用方负责。
`reload()` 返回只代表 signal 已接收，不代表 runtimeVersion、atlas 或布局 epoch 已在当前调用栈更新。

`FontConfig.affectsFontRuntime()` 当前会比较：

- `lerpMode`、`awtCharSize`、`charSize`、`spaceWidth`、`characterSpacing`
- `replaceOrigin`、`customInvCountFont`
- `fontSort`、`characterFontRules`

AA、亮度、阴影偏移、`renderOffset`、smooth range、upload 限速等字段不在该比较中；它们由绘制或上传路径实时读取。修改字段时先判断它属于“必须重建 atlas/layout”还是“可实时读取”，不要机械扩大 reload 集合。

### 3.3 配置页的两个专用字段

`ModernConfigEntry.configureFieldRenderers` 按 path 注册：

| path | renderer | 当前语义 |
|---|---|---|
| `fontSystem.fontSort` | `club.heiqi.config.ui.field.FontSortFieldRenderer` | screen-open 冻结 discovered snapshot；筛选只读；拖拽/索引移动提交完整顺序；不可增删改名 |
| `fontSystem.characterFontRules` | `config/modern/CharacterRuleFieldRenderer` | YAML 仍是 `List<String>`；UI 拆为 enabled/selector/fontName；可增删、不可重排 |

`fontSort` 的 screen snapshot 必须在 listener/coordinator initial apply 前捕获。generation commit 后的
`FontGenerationRegistry.completePublication()` 会把 resolved order 写回 `FontConfig.fontSort`；因此配置
`Authority/Draft`、screen presentation snapshot 与运行时 resolved order 是三个生命周期不同的值，不要选错真值。

字符规则当前有三项容易误判的源码事实：

- `FontCharacterRuleSet.resolveFontName()` 按列表顺序返回首个 active match；规则顺序有运行时优先级。
- `CharacterRuleFieldRenderer` 没有重排控件，也没有范围重叠检测/提示。允许重叠不代表 UI 已能诊断重叠。
- 带 `=` 但 selector/fontName 无效的行通常可按拆分字段投影；完全缺少 `=` 的 raw 行会被 `parseLine()` 拆成空 selector/fontName，并在列表下一次整体投影提交时规范化为空串。不要声称所有 malformed raw 都逐字保留。

## 4. 字体发现、排序与匹配

### 4.1 发现和排序

```text
request owner: FontGenerationBuildRequest.capture（reload 为 render owner；cold bootstrap 同步）
  -> desired sequence + active base version/epoch
  -> immutable FontRuntimeSettings + font directory + platform hints（不执行目录 I/O）

candidate worker: FontResourceSnapshot.capture
  -> asset font immutable bytes（按相对文件名稳定排序）
  -> installed Font descriptors（稳定排序）
  -> FontResourceFingerprint（与 catalog 消费同一 snapshot）
  -> FontGenerationRegistry.prepare
       -> asset fonts + installed fonts
       -> settings.fontSort 或 frozen platform hints
       -> FontOrderPlanner.plan
       -> FontCatalog.prepareSnapshot + validate
  -> FontRuntimeMetrics.prepare
  -> immutable FontGenerationCandidate

commit generation write scope
  -> FontGenerationRegistry.publish
  -> FontConfig.applyFontOrderSnapshot (post-publication compatibility state)
```

`FontOrderPlanner` 的稳定规则：

- 字体名按 `trim + Locale.ENGLISH lowercase` 建 identity；同名字体实例归为一组并全部保留。
- 配置项先按给定顺序消费，重复 identity 首项胜；未发现项仅在用户已配置分支记录为 missing。
- 未被配置消费的字体组按 display name natural order 追加。
- 默认平台 hints 只控制优先级，不把未安装的 hint 记入 missing。

request capture 不创建或探测目录。仅 `current == null` 的 cold snapshot 可创建首次字体目录；已有 active 的 reload/reinitialize
遇到目录缺失、枚举或文件读取失败时保留旧 active，不会重建空目录或把瞬时 I/O 故障提交为空字体集。asset snapshot 最多接纳
256 个字体文件、单文件 128 MiB、总计 256 MiB；每个文件按捕获长度读取，再核对 file key/size/mtime 并逐 byte 二次读取，
截断、增长或并发改写均 fail-closed。fingerprint digest 与 AWT parser 直接消费同一 immutable byte array，不各自复制整份内容。
格式确实无效且稳定的单个字体仍按既有语义记录并跳过。candidate 先生成 catalog 的不可变 `Snapshot` 并验证其 next-version；
只有 generation commit 才原子 publish。
`DerivedFontCache` 绑定 active catalog snapshot，换代后清空旧派生字体。

### 4.2 单码点匹配顺序

`FontMatcher.matchFontIndex(runtimeVersion, codepoint, fontType)` 的决策顺序：

1. 若当前 `GlyphRuntimeTables.matchedFont*` 已有结果，直接返回字体索引或 `FONT_INDEX_NONE`。
2. 从当前 generation 的 `FontRuntimeSettings.characterRuleSet` 取首个命中规则，只在目标字体名存在且确实可显示该码点时采用。
3. 规则目标失败后继续自动 fallback，不把规则当硬错误。
4. 按 `FontCatalog` 顺序检查 `Font.canDisplay`、AWT `GlyphVector` missing glyph/outline，再优先匹配 NORMAL/BOLD。
5. 没有严格字重匹配时，回退首个严格可显示字体；再不行回退首个 `Font.canDisplay` 字体；最终为 none。

block hint 与 last-font hint 不改变 catalog 的优先顺序；当前 hint 分支仍执行与普通候选相同的严格检查，不能把它当作
已生效的性能优化。候选匹配可在 generation 锁外计算，但 direct cache 最终写入会短持 generation read lock，并在锁内
重新核对 runtime version、binding identity 与 lifecycle；旧代调用不能在 storage 转移后回写当前代。

## 5. 测量与 scene 接缝

### 5.1 `TextLayoutService`

两种文本模式必须显式区分：

| 模式 | `§` 语义 | 主要消费者 |
|---|---|---|
| `MINECRAFT_FORMATTED` | 解析颜色、粗体、随机、下划线、删除线、斜体和 reset | 原版 `FontRenderer` 接管路径 |
| `UILIB_RAW` | `§` 是普通可见字符 | UILib/scene 文本和文本编辑控件 |

`parseSegments` 只负责文本和 `TextStyle` 分段；`getStringWidth`、trim、wrap、split 最终都复用单码点推进宽度。
宽度查找顺序是：空格使用当前 generation 的 `settings.spaceWidth` → 当前 `GlyphRuntimeTables.width*` → AWT `TextLayout.advance`。
glyph upload 只发布 residency、flags 与 atlas geometry，不回填宽度或 aggregate line metrics；同代 advance 在异步像素完成前后保持不变。

`awtCharSize` 是 atlas/AWT 烘焙量纲，`charSize` 是默认显示量纲。单码点显示 advance 为：

```text
(AWT advance / settings.glyphSize) * settings.charSize + settings.characterSpacing
```

指定 UI 像素字号时，再按 `fontSizePx / charSize` 缩放。排查尺寸问题时必须同时核对这两个比例，不能只看 quad。

### 5.2 scene 测量链

```text
AbstractSceneHostWidget
  -> TextMeasureServiceSceneAdapter
  -> DefaultTextMeasureService (默认 UILIB_RAW)
  -> FontService.ensureLayoutRuntimeReady
  -> TextLayoutService
```

生产 HUD 不继承 `AbstractSceneHostWidget`，其并行入口为：

```text
UiHudRenderListener
  -> SceneHudHost
  -> TextMeasureServiceSceneAdapter(DefaultTextMeasureService)
  -> SceneLayoutEngine / ScenePaintEngine / ScenePaintReplayer
  -> UiRenderContext
```

`ActiveFontGeneration.textMeasureEpoch` 在 settings 语义变化或完整换代时递增。`TextLayoutService` 的一次完整 public measure/trim/wrap
调用持 generation read scope；`SceneLayoutEngine.layout()` 遍历曾测量过的文本叶，
发现节点 `lastMeasuredEpoch` 落后时只将该叶及祖先链标脏，避免字体 reload 后干净子树永久复用旧尺寸。

### 5.3 scene 绘制链

```text
ScenePaintEngine
  -> immutable PaintCommand.TEXT(text, position, color, fontSize)
  -> ScenePaintReplayer
  -> UiRenderBackend.drawText
  -> UiRenderContext.drawText
  -> DefaultFontRendererAdapter.drawBaselineAlignedStringPx
```

scene core 不持有 `FontService`、Minecraft 或 GL 类型。真实字体只在 `TextMeasureServiceSceneAdapter` 和
`UiRenderContext` 两条装配/后端接缝进入。

`UiRenderContext` 已暴露 deferred text batch scope，并会在 clip push/pop 前 flush；当前生产源码没有
`beginDeferredTextBatch(...)` 调用点。除非新增并验证 composition owner，不要假定多个 scene `TEXT` 命令已跨命令合批。

## 6. 原版接管与回退

```text
EarlyMixins (CLIENT only)
  -> MixinFontRenderer @Inject(HEAD, cancellable)
  -> FontRendererFallbackInvoker
  -> DefaultFontRendererAdapter
```

`MixinFontRenderer` 当前覆盖 `drawString` / `drawStringWithShadow` / `drawSplitString`、`getStringWidth`、
`listFormattedStringToWidth`、`splitStringWidth` 和 trim，并在 `onResourceManagerReload` 返回后请求字体 reload。
`TextLayoutService` / adapter 虽提供 `wrapFormattedStringToWidth`，当前 mixin 没有注入原版同名方法，也没有接管
`getCharWidth`；这两个原版入口仍走 vanilla 实现。
resource callback 总是发布 reload signal。SplashProgress 活跃时，`FontSplashReloadGuard` 只延后完整 reconcile，
不丢 signal；当前为避免来源交错破坏 worker/atlas/GL，所有 pending 完整 reload 都等 Splash 结束后再收敛。

接管裁决：

- `FontConfig.replaceOrigin == false`：invoker 返回 unhandled，原版方法继续执行。
- UILib 调用成功：mixin 设置返回值/取消原调用；draw 额外恢复原版可观察到的 alpha-test enable 副作用。
- UILib 抛 `RuntimeException`：只记录一次错误并返回 unhandled，当前调用回退原版。
- `Error` 不属于该窄回退合同，不能把 JVM/native/断言级失败描述成自动回退。

resource reload 是否真正应用 mixin、目标方法签名是否匹配以及回退后视觉是否正确，都需要游戏运行态证据。

## 7. 异步 glyph 与 atlas 状态机

### 7.1 首次绘制

`DefaultFontRendererAdapter` 在 direct draw 的 GL guard 前先解析整串 formatted/raw segments，冻结 `§k` 替代码点、
style 与 advance，并按 `(codepoint, FontType)` 去重提交 visible demand；首次或 shutdown 后恢复 initialize 若可能退休旧
GL 资源，会单独经过 `FontRenderStateGuard`，随后退出 guard 再做 CPU prepare。draw 阶段从当前
`GlyphRuntimeTables` 直索引读取 location/geometry：

| location/state | 当前 draw 行为 |
|---|---|
| ready bitmap | 收集 atlas quad |
| `LOCATION_NO_BITMAP` | 不收集 quad，但按 advance 推进；典型为 whitespace |
| not ready 或 page/slot/current-page/尺寸 metadata 不完整 | 已在整串 prepare 阶段提交 `VISIBLE` demand；本次不阻塞等待，仍按冻结宽度推进 |

因此“首次出现某字符时空一帧、随后出现”可能是按需异步设计，不应先当 shader 缺陷。

### 7.2 worker 链

```text
DefaultFontRendererAdapter
  -> GlyphGenerationDispatcher.submit
  -> GlyphPageManager.claimRequest（原子返回 GlyphRequestToken）
  -> QzFontWorker-0（当前有效并发度 1）
  -> FontMatcher.matchFontIndex
  -> GlyphGenerator.generate (AWT only)
  -> GlyphGenerationResult（保留同一 token）
  -> GlyphPageManager.queueUpload（有界 result mailbox）
```

`GlyphGenerator` 分离两种几何事实：

- `advance` 决定光标推进。
- 实际非透明像素扫描得到 ink bounds、bearing 和 atlas baseline，决定变长 slot 与屏幕 quad。

空白 glyph 保留 advance，但 `hasBitmap=false`。可见 glyph 的 slot 包含 padding；彩色像素会设置 colored flag，shader
保留纹理 RGB，而普通字形只使用纹理 alpha 乘调用方颜色。

dispatcher 固定为单 worker，demand admission 默认上限 1024 requests，并为 `VISIBLE` 保留 256 个名额。内部四级为
`VISIBLE/FOREGROUND/PREFETCH/WARMUP`；既有公开 `HIGH/NORMAL/LOW` 分别映射前三档，reload recovery 使用
`FOREGROUND`。同 key 重复提交只提升原 token/task priority；queued promotion 与 dequeue 共用选择锁。每 500ms aging
提升一个有效等级，达到 `VISIBLE` 后封顶；不要根据线程名前缀推断多 worker 并发。

### 7.3 render-thread upload

```text
worker: bounded queueUpload
  -> FontRenderTickListener.onRenderTick(END)
  -> FontService.tickMainThread(64)
  -> GlyphPageManager.flushPendingUploads
  -> GlyphPage.reserveSlot (shelf packing reservation)
  -> GlyphPage.upload (glTexSubImage2D + mipmap)
  -> token/epoch recheck -> slot/page/metadata commit
```

每次 draw 还会调用 `FontService.tickDrawStage(drawStageUploadBatchSize)`，只在 render tick 已绑定的同一 owner 线程上，
按 interval 和每秒上限补充低批量上传；draw-stage 不领取 reload ticket，也不能提交新 generation。
`GlyphPage` 构造不创建 texture；只有 upload transaction 执行 GL 分配。只读 `GlyphRuntimeTablesView` 只返回已提交
texture，不会为预建空页惰性创建资源。

result mailbox 默认同时限制为 256 records 与 16 MiB immutable RGBA bytes，并为 `VISIBLE` 保留 32 records / 4 MiB。
非 visible 结果触及其分区时，在 manager 锁内重验并发 promotion 后立即把当前 token 结算为 `FAILED`，让唯一 worker
继续处理后续 visible demand；visible publisher 在总容量满时可中断等待 render drain。drain 每次按当前 priority、500ms
aging 与 enqueue sequence 重选，不做常态跨 key eviction。record/bytes reservation 同时覆盖 queued 与 render in-flight，
并通过 mailbox epoch 在 discard/reset 路径成对回收。render drain 另受 attempt、默认 2ms monotonic time 与 2 MiB bitmap
bytes 三重预算；首个超 byte 项允许推进，避免永久卡住队首。

atlas slot、GL texture/pixels 与 residency metadata 是单一可回滚事务。GL 成功后仍须再次核对 mailbox epoch 与完整 token；
stale 时先把同一 slot 透明重写并重建 mipmap，再回滚 allocator。post-write 或 state restore 后无法可信清槽时，该页进入
quarantine：allocator 与只读 texture view fail-closed，manager 清除整页 residency；成功删除 texture 后重置 allocator 和
resident accounting，已有缺字可重新 claim。

atlas 默认同时限制 8 个 resident/retained ownership pages 与 512 MiB texture bytes，byte 估算逐级包含完整 mip chain。
容量不足的 glyph 不保留 bitmap/mailbox lease，而是回到 `ABSENT` 并进入 NORMAL/BOLD 独立 pressure ledger；reload snapshot
会恢复该 intent。quarantine 释放共享容量后会解除旧 pressure，避免 glyph 必须等待下一次完整 reload。

`GlyphRuntimeTables` 为 NORMAL/BOLD 各持一组覆盖全部 Unicode codepoint 的 primitive arrays，并且只在
`GlyphPageManager` 构造时分配一次：

- width、matched font、state、request id、packed location、flags
- slot x/y/width/height、atlas baseline、line baseline、ink size、bearing
- 当前 page arrays、page count、字体 ascent/descent/leading

candidate 不构造第二份完整 tables。完整换代在 generation write scope 内退休旧 pages、原地清理 storage 并把同一
tables identity 转移给新 `ActiveFontGeneration`；layout read scope 与 matcher 最终 cache write 共同阻止转移中读写。
line metrics 在 candidate 阶段冻结为 `FontRuntimeMetrics`，glyph upload 不再改变同代行高。

`FontService` 在每个 render interval 持有当前 generation 的 frame lease：下一次 `RenderTick.END` 开始时，仅当 batch 已
flush/clear 才释放；仍有 quad 时继续持有旧 lease。换代先关闭旧代 lease admission，并要求 lease count 为零；generation
write lock 两次都只用 `tryLock`，layout read scope 或旧 batch 尚未结束时保留已完成 candidate 到后续 tick，render owner
不等待也不重复 CPU prepare。

成功路径为 `ABSENT -> QUEUED -> RASTERIZING -> UPLOAD_QUEUED -> UPLOADING -> RESIDENT/NO_BITMAP`。
manager 原子 claim 产生 `generation + requestId + codepoint + FontType` 完整 token；task、result 与 pending upload 共享同一
token，fail/cancel/queue/commit 还必须匹配 expected state。`FAILED` 与 `CANCELLED_STALE` 是本次 token 的明确终态，后续 draw
可重新 claim 新 requestId。worker 的 matcher/rasterizer/result handler 未检查异常会先结算 token，in-flight finally 只按
exact task 删除；upload 的 stale、成功与异常 record 都消费预算，异常不发布 location/flags/geometry 并在结算后继续传播。

`FontRuntimeStats` 另暴露 active/max/high-water/rejected/promoted demand，以及 pending/max/high-water bitmap bytes、
blocked publisher、mailbox backpressure/rejected。`directTableSlotsPerPage` 来自 page 几何的理论格数；当前 atlas 使用
变长 shelf slot，不能把该统计当作真实可分配 glyph 数或容量上限。

## 8. reload、authority 与缓存

### 8.1 reload 触发点

| 触发 | reason | 线程收口 |
|---|---|---|
| 配置页首次注册 | `modern_config_register` | coordinator → CLIENT main queue → signal |
| 配置保存 | `modern_config_saved` | coordinator → CLIENT main queue → signal |
| 磁盘重载 | `modern_config_reloaded` | coordinator → CLIENT main queue → signal |
| Minecraft resource reload | `resource_manager_reload` | mixin 任意调用线程只 signal；Splash 只延后执行 |
| 启动 bootstrap | `modern_config_loaded` | 正常在 initialize 前直接刷新配置；已初始化的特殊路径发布 signal |

`FontReloadSignal` 是 package-private desired/applied authority：任意线程发布只推进 monotonic desired sequence；
150ms quiet window 内持续抖动只覆盖最新 reason 并累计数量，没有会在风暴中强制执行的 max delay。只有
`RenderTick.END -> tickMainThread` 可领取 single-flight ticket；成功 commit 才推进 applied sequence，flight 中的新 signal
留给下一帧。`RuntimeException` 不确认 ticket并按 250ms 起步、最大 5s 的指数 backoff 重试；`Error` 在释放 ticket 后继续传播。
signal 使用 `System.nanoTime()` 单调时钟，不依赖墙钟。

signal authority 仍以 sequence 合并事件；稳定后 candidate 对一次性资源 snapshot 计算内容 fingerprint。若 active settings
语义与 fingerprint 都未变化，render owner 取得最新 ticket 的 commit admission 后直接确认，不推进 runtime version/measure
epoch，也不重建 worker/atlas。自定义字体 identity 使用相对名称与完整 bytes，不依赖绝对路径、mtime 或文件长度；系统字体
使用稳定排序的 AWT descriptor，平台默认 hints 也进入 fingerprint。

### 8.2 candidate flight 与 commit 顺序

```text
RenderTick.END
  -> release previous frame lease only when batch is empty
  -> retry retiring atlas page ownership
  -> poll stable FontReloadSignal ticket
  -> freeze FontGenerationBuildRequest
  -> submit bounded background candidate flight; current tick continues

later RenderTick.END
  -> reject/cancel flight if ticket is no longer latest
  -> non-blocking poll CandidateResult
  -> validate request identity + active base version/epoch
  -> unchanged settings/fingerprint:
       admitCommit(ticket) -> ack only; keep current generation
  -> changed candidate:
       close old lease admission only when lease count == 0
       generation write tryLock preflight
       reloadState = RELOADING
       dispatcher.pause
       snapshot recoverable active/pressure codepoints + durable tail
       dispatcher.reset -> shutdownNow + awaitTermination(2s bounded)
       generation write tryLock
         -> admitCommit(ticket) immediately before irreversible publication
         -> discard pending uploads + clear frame batch
         -> retire old lifecycle/pages
         -> clear and transfer the single GlyphRuntimeTables storage
         -> publish prepared catalog + one ActiveFontGeneration reference
       reinitialize dispatcher; failure leaves durable worker recovery intent
       complete config presentation publication best-effort
       reloadState = RUNNING
       ack ticket + drain recoverable glyph tail + invalidate layout best-effort
  -> acquire lease for the next render interval
```

candidate scheduler 固定单 worker + 单排队槽；render owner 只 poll，不等待。旧 signal 会取消 queued/running future 并主动
remove/purge，latest replacement 至多占一个 queue slot。candidate I/O/AWT/validation 失败保持旧 active/table，ticket 不确认
并进入 backoff。dispatcher reset 首次执行 `shutdownNow()` 后最多等待 2 秒；只有确认 terminated 才清除 executor owner，
否则保留 retiring executor 并在后续 tick 非阻塞探测，不能创建并行 glyph worker。

retiring atlas ownership 只把发生资源变化的 publication defer；settings + fingerprint no-op 仍可取得 admission 并确认 ticket。
若 shutdown 后 candidate executor 尚未终止，reinitialize 会先用旧 active generation 恢复 layout/glyph worker。任何已有 active
的 reinitialize 都为新 lifecycle 发布 fresh settings/resource 复核 signal；后续 tick 等旧 executor quiescent 后再 reconcile，
initialize 调用线程不做同步 prepare/publish，也不并行构建 replacement。

`GlyphPageManager` 还会在 service-owned render tick 重试旧 page 删除。只要唯一 retiring ownership 尚未释放，就拒绝再退休
当前 active pages，因此 atlas ownership 正常硬上限为 active + retiring。进入不可逆 core 后，单页 GL retire 的
`RuntimeException` 被隔离并保留 retry ownership；commit 后 demand 恢复使用当前 generation 的 durable tail，不反向重做
整代 reload。主动布局失效失败只记录。

线程约束：`reload()` 可由任意线程发布 signal，但不执行重载。`tickMainThread` 首次调用绑定 `renderThread`，之后只有同一
owner 能 reconcile/upload；错误线程调用 fail-closed。draw-stage 不绑定 owner，只能沿用已捕获线程。shutdown 关闭 signal
lifecycle、停 worker；非渲染线程不会删除 VAO/VBO/shader，后续 initialize 才开启干净的新 signal lifecycle。
`FontService` 暴露的 manager/matcher/layout/dispatcher 诊断对象绑定不可伪造 owner token；外部直接调用 generation mutator、
dispatcher lifecycle control、raw table/page getter 会 fail-closed。渲染路径改用只读 `GlyphRuntimeTablesView`，诊断面板优先用
`FontRuntimeDiagnosticsView` / `FontRuntimeStats`。

### 8.3 真值与失效表

| 数据 | 当前真值 | 失效/代际锚 |
|---|---|---|
| 持久配置 | `Authority` + YAML | BATCH_SAVE / RELOAD 事务 |
| 字体运行时配置/资源身份 | `ActiveFontGeneration` 的 `FontRuntimeSettings` + resource fingerprint | active generation identity + settings/resource semantics |
| 字符规则派生集 | active settings 的 `FontCharacterRuleSet` | generation publication |
| 有序字体目录 | active generation 的 `FontCatalog.Snapshot` | generation identity + catalog version |
| AWT 派生字体 | `DerivedFontCache` | catalog version + explicit clear |
| runtime version / measure epoch | 单个 `ActiveFontGeneration` 引用 | full commit / measure-only envelope publication |
| 单码点匹配/宽度/字形 | `GlyphPageManager` 唯一 `GlyphRuntimeTables` storage | generation write scope 内原地清理转移 |
| worker 请求 | manager token ledger + dispatcher exact in-flight handle | generation、requestId、codepoint、FontType、expected state、generationEpoch |
| reload desired/applied | `FontReloadSignal` | signal lifecycle + desired/applied sequence + single-flight ticket |
| generation candidate flight | `FontService.CandidateFlight` | desired sequence + active base version/epoch + immutable build request |
| scene 文本尺寸缓存 | scene node / text control cache | `textMeasureEpoch` |
| 当前帧 quad | `FontBatchRenderer` page batches | 每次 flush/clearFrame |
| GL page/batch/shader | `GlyphPage` / renderer / program | page 随 generation commit 退休；batch/shader 仅清帧并在安全 shutdown/context lifecycle 释放 |

## 9. GL 提交边界

`DefaultFontRendererAdapter` 收集 glyph 时按 atlas page 分 batch；shadow 先收集，主字形后收集，下划线/删除线进入独立
decoration batch 并在字形页之后提交。

`FontBatchRenderer.flushWithinActiveState` 的顺序：

```text
FontRenderStateSupport.prepareTextRenderState
FontShaderProgram.bind
set matrices + AA/brightness uniforms
for each active atlas page: bind texture if changed -> FontRenderTool.render
render decoration batch
FontShaderProgram.unbind
clearFrame
```

必须维持的宿主合同：

- `FontRenderStateSupport` 只准备 cull/light/alpha/texture/blend/color，不修改 depth test、depth mask、depth func。
- screen/HUD 的无深度二维状态由 `UiHostRenderSupport.prepareMainUiRenderState()` 建立；世界文字继承调用阶段深度。
- `FontRenderStateGuard` 保存/恢复 attrib、pixel store、可选矩阵栈、program、active texture 及 texture0/active-unit binding、VAO、VBO/EBO、viewport。
- `GlyphPage.upload` 也有独立 attrib + pixel-store 保存/恢复边界。
- `FontRenderTool` 只负责 VAO/VBO/EBO 的容量增长、数据上传和 `glDrawElements`。
- shader attribute 0..4 分别为 position、UV、color、UV bounds、glyph flag；fragment shader 区分 mono、colored glyph、solid decoration。

修改 GL 路径时，纯 JVM 的源码字符串检查和 quad 数学测试不能证明真实 context 下状态已恢复。

## 11. 排障路径

| 现象 | 先查 | 再查 |
|---|---|---|
| 原版文字未被替换 | `FontConfig.replaceOrigin`、`EarlyMixins` CLIENT 列表 | `FontRendererFallbackInvoker` 一次性失败日志、mixin 运行态 |
| 字体选择不符合预期 | `FontConfig.characterRuleSet` 首命中、`fontSort` resolved order | `FontMatcher.resolveConfiguredFontIndex` 与 strict display/weight fallback |
| 宽度、trim、wrap 不一致 | `TextContentMode`、`spaceWidth`、`characterSpacing` | `TextLayoutService` direct width table 与 AWT fallback 是否同代 |
| 新字符先空后出现 | `GlyphRuntimeTables.state*`、active demand 与 pending record/bytes | worker 生成日志、render tick/draw-stage upload 是否推进 |
| 字符永久不出现 | token 的 generation/requestId/codepoint/type、当前 `GlyphState`、demand/mailbox capacity 与 reject 计数 | 首条 token stage/reason 异常、upload thread/context、page allocation、shader/texture diagnostics |
| reload 后仍是旧字体或旧布局 | coordinator reason、`runtimeVersion`、`textMeasureEpoch` | matcher binding、新 runtime table、scene epoch 标脏与 `invalidateAll` |
| reload signal 长期 pending | signal 是否持续抖动、Splash 是否仍活跃、失败 backoff | 最新 reason、reconcile 首次失败日志、render owner/tick 是否推进 |
| atlas 字被切边/偏移 | `GlyphGenerator` actual pixel bounds/bearing/baseline | `resolveGlyphQuadMetrics`、ink bleed、shader UV bounds |
| 世界文字穿透或消失 | 调用阶段原有 depth + `FontRenderStateSupport` | host/pass scope 与游戏内真实遮挡矩阵 |
| 后续宿主渲染被污染 | `FontRenderStateGuard` push/pop 配对 | upload 独立 guard、异常路径、真实 GL 状态抓取 |
| 字体队列或 draw call 异常 | `FontService.getRuntimeStats()` | `fontRuntimeDebug` 的生成/上传/绘制/每秒统计日志 |

`fontRuntimeDebug` 默认关闭。启用后，生成和上传各最多记录 16 条、绘制状态与 token event 各最多 32 条；render tick 与
batch stats 按约 1 秒采样。glyph 异常首条无论 debug 开关都会记录完整 token/stage/expected/actual/reason，同 fingerprint
重复只在 debug 下按 2 的幂次输出累计摘要。诊断日志是定位线索，不等同于像素或状态恢复证明。

## 12. 当前已知口径陷阱

- 字符规则有顺序优先级；“characterFontRules 无序”是错误心智模型。
- 配置页当前没有字符规则重排和重叠提示；不要把允许重叠写成 UI 已提示。
- 缺 `=` 的 malformed 字符规则不能逐字 round-trip；现有 renderer/test 注释中的“无效规则不丢输入”只对部分无效形态成立。
- `UiRenderContext` 的 deferred text batch 是已存在但当前未接入 production owner 的能力，不要据 API 存在推断 scene 已跨命令合批。
- `FontRuntimeStats.directTableSlotsPerPage` 不是变长 shelf atlas 的真实容量。
- Phase E 已把 slot、GL upload 与 residency 收口为事务，并以 fake `GlApi` 覆盖错误检查点、透明清槽和 quarantine；
  fake GL 仍不能证明真实 driver/context 下的 error、mipmap、状态栈或像素结果。
- `FontService.reload()` 返回不表示 reload 已执行；调用方不得紧邻读取 runtimeVersion/atlas 并假定新状态已生效。
- reload signal 没有 max-delay 强制 flush；持续资源风暴期间保留旧代是预期行为，稳定后才 latest-wins 收敛。
- Phase A-F 已具备 signal reload、immutable settings、异步 CPU candidate、resource fingerprint、单 active envelope、frame
  lease、唯一 tables 转移、完整 glyph request token、有界 priority/result mailbox、事务化 upload 与 atlas pressure；这仍不
  等于已获得真实 resource-pack/Splash/GL context 运行态证据。
- `FontService.initialize()` 不等于 GL 资源已经创建；同样，完整 `build` 通过不等于 GL 路径已运行。

直接更新对应表，不追加会话流水账。
