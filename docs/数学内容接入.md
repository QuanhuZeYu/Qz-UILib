# 数学内容接入

行为范围与验收以[文本规格](<superpowers/specs/2026-10-07-uilib-text-content-spec.md>)及其引用的字体、图像规格为准，本页仅说明当前生产入口。数学内容使用 UILib 自有的 token/宏展开、不可变数学结构、数学盒和 SceneMath。正式文字与数学字形通过同一字体服务布局；公式内图片和 Item 使用同一 Scene 树及 PaintPlan。固定 VS Code 1.140.0、@vscode/markdown-it-katex 1.1.2、KaTeX 0.16.21 是行为参照，不是运行时依赖。

## 创建公式

源码变更时创建新的 MathContent，字号或主题变更时复用原内容。将内容与主题信号交给当前页面上下文：

```java
import java.util.Collections;
import club.heiqi.uilib.ui.reactive.ReadableSignal;
import club.heiqi.uilib.ui.scene.control.SceneMath;
import club.heiqi.uilib.ui.scene.control.SceneTheme;
import club.heiqi.uilib.ui.scene.host.ScenePageContext;
import club.heiqi.uilib.ui.scene.node.SceneNode;
import club.heiqi.uilib.ui.scene.text.math.MathContent;
import club.heiqi.uilib.ui.scene.text.math.MathStyle;

public final class MathExample {
    public static SceneNode formula(ScenePageContext page,
            ReadableSignal<MathContent> content, ReadableSignal<SceneTheme> theme) {
        return SceneMath.create(page, content, theme, MathStyle.DISPLAY,
                Collections.<String, SceneMath.Embed>emptyMap());
    }
}
```

调用方的内容信号可保存 `MathContent.parse("\\frac{a}{b}+\\sqrt{x}")`。源码中的反斜线需要 Java 字符串转义。DISPLAY/TEXT/SCRIPT/SCRIPT_SCRIPT 决定入口数学样式；在 TEXT 公式内，固定插件的整串检测规则会把含未加星 align、equation、gather、CD 或 alignat 环境的公式提升为 DISPLAY。此规则与大小写、精确环境拼写有关，不会自动放宽星号环境或显式 SCRIPT 入口。

## 公式内 Item 或图片

宿主创建一个未挂载、无焦点及点击行为的 SceneImage，将其作为 `SceneMath.Embed` 注册。数学核心接收标识和 em 度量，不接收 ItemStack、宿主 GL callback 或图片下载逻辑。

```java
Map<String, SceneMath.Embed> embeds = new LinkedHashMap<>();
embeds.put("ore", new SceneMath.Embed(itemImage, new MathEmbedMetrics(1, 1, 0.8f)));
SceneNode node = SceneMath.create(page, content, theme, MathStyle.DISPLAY, embeds);
// content 中的源码：\frac{\embed{ore}+1}{2}
```

上例补充导入 `java.util.Map`、`java.util.LinkedHashMap` 和 `club.heiqi.uilib.ui.scene.text.math.MathEmbedMetrics`；itemImage 由宿主正式图像服务创建。widthEm/heightEm 必须为有限正数，baselineEm 从盒顶测量且位于高度范围内；实际尺寸随所在数学样式的 em 缩放。

每个标识和 SceneNode 身份必须唯一。同一个标识不能在一条已布局公式内拥有多个空间；宏展开或数组插入列导致重复时仍执行此检查。需要重复显示同一物品时，注册两个不同标识及两个不同 SceneImage，二者可以使用同一个 ImageSource。未使用及被隐藏的插槽不取得可见几何或额外交互资格。图片资源、quantity、tooltip、裁剪及资源重载沿既有图像与页面生命周期。

`SceneMath.layout(node)` 返回数学逻辑坐标和诊断；smash、重叠盒及字形墨迹可以越过逻辑占位，独立控件按完整呈现包络分配自然尺寸并平移外层原点。场景定位使用同代 `SceneGeometryView` 和文字投影，不将逻辑坐标直接加到节点位置，也不在绘制中把结果写回信号。物品原对象变化应发布新的 `MinecraftItemSource`，来源持有 ItemStack 副本，不轮询可变 NBT。

## 文档宏和编号

默认 `MathContent.parse(source)` 使用新的显式宏上下文。文档需要续定义时，按文档顺序保存 `nextMacros`，不要在每帧重新执行定义：

```java
MathContent first = MathContent.parse("\\newcommand{\\half}[1]{\\frac{#1}{2}}", MathMacros.empty());
MathContent second = MathContent.parse("\\half{x}", first.nextMacros);
```

`MathMacros.of(Map<String,String>)` 也能提交调用方的初始定义；宏上下文不可变，不存在隐藏全局文档状态。局部分组和环境作用域按数学语义处理，宏生成的环境使用独立身份；两个来源相同的展开环境不会共享空间。

编号同样是显式文档输入。`SceneMath.create` 的六参数入口接收 `ReadableSignal<Integer> initialEquationNumber`；旧入口默认从 1 开始。编号变化会重新测量，重排不会偷偷递增文档计数。首次呈现后读取 `SceneMath.layout(node)`，用其 `nextEquationNumber` 为下一公式提供输入。该接口首次呈现前及卸载后返回 null，结果不是可直接订阅的输出 Signal；上层在自己的文档编排阶段串联，避免在测量回调中创建反馈循环。自动标签消耗编号，手工 tag、不编号行及星号环境不消耗自动计数。无效或溢出的编号有明确错误。

仅需要中性布局时，可调用 `MathLayoutEngine.layout(content, textStyle, mathStyle, measurer, embedMetrics, initialEquationNumber)`，消费不可变 MathLayout；不要建立第二套宿主字形测量或绘制路径。

## 字体与布局能力

数学字体使用正式 STIX Two Math 与真实 OpenType MATH 度量。完整变体及合法 assembly 保留原字形尺度；宽帽、波浪及具名箭头使用声明的数学路径结构。正文默认采用 Noto Serif；textsf、texttt 分别使用 Noto Sans、IBM Plex Mono，三个字族各自提供真实 Regular/Bold/Italic/BoldItalic。显式根候选及自定义字体名优先，普通页面默认候选不受影响。

字族覆盖有限，公开候选尾链负责未覆盖脚本。字族没有某个样式时，字体服务使用真实可用成员并报告 STYLE_FALLBACK，不默认合成粗体或斜体。例如等宽 Greek 和中文可能使用 Unifont；不能把实际常规成员解释为真实粗体。数学宽 Unicode 字母及标准关系变体按其固有数学字族处理，不把整串正文强制改为数学字体。pmb 是明确的附加文字绘制效果，不是真实粗体字体，也不重复 Item。

支持分式、根式、脚本、定界、重音、宽构建、上下说明、矩阵/数组/分段/对齐环境、正文与数学字族、颜色/边框/取消线、尺寸盒及文档宏等固定参照能力。支持范围按文本规格定义，固定参照的[支持矩阵](<../src/test/resources/math/reference/support-matrix.json>)与运行场景提供实现证据，不用一般 LaTeX 的命令集合推定；固定参照不含 multline。array 的 `@{内容}` 插入列是 UILib 明确扩展，应与固定 KaTeX 本身拒绝该语法的事实区分。显式负行距允许内容重叠，lap/smash 的逻辑尺寸不等于真实墨迹范围。固定默认 `strict=warn` 下，显式 `\\` 或 `\newline` 对行内和独立公式都产生换行，可用 `[1pt]` 指定附加行距；不应按一般 LaTeX 的 display 习惯推定忽略。`\middle` 可出现在活动 left/right 内的分组及参数中；分组仍保持自身原子边界，right 不能穿过分组补配对。

## 诊断与默认拒绝

MathContent 保留完整原 source。MathLayout 的诊断标明阶段与原文 UTF-16 区间；宏参数及合字仍使用原 token 范围并集，不能将展开索引当原文索引。未知命令、无效结构、数学字体能力错误及非法嵌入度量使用整式来源降级，`fallback` 与诊断必须同时向调用方可见。匿名正文字符的稳定替代及 STYLE_FALLBACK 保留真实字体诊断，不伪装为数学成功或真实请求样式。

默认 trust=false 下，合法 href/url/html* 或 includegraphics 命令只局部显示红色命令名；不显示被拒绝的参数、不激活 URL、不挂载隐含图片。邻近有效数学与 Item 保留。参数格式错误仍产生解析诊断。

宿主集中演示入口为 `/qzcore math`，可轮换数学家族、真实 Item、字号和主题并查看源文/诊断。依次检查公式与物品的共同排列，悬停提示、数量/耐久及附魔效果；切换字号、主题和窗口后检查重排与裁剪；切换非法源再恢复，最后 F3+T 重载及关闭重开检查资源和输入。共同混排另见[共同文档接入](<开发者文档/共同文档接入.md>)。集成平台的真实字体/GPU验证与宿主实机反馈按实际环境分别记录，指南不保存阶段通过数或施工状态。
