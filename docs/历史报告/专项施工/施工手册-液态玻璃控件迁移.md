# 液态玻璃控件迁移施工手册（叶子实例通用）

> 配套：[G00 契约](契约-全库默认液态玻璃样式.md)（接口唯一权威）、[实施规划](规划-全库默认液态玻璃样式.md)、[任务单](任务单-全库默认液态玻璃样式.md)。
> 本手册只讲「怎么做」，接口语义以契约为准；发现契约缺能力，报告主代理，不自行新建 API。

## 1. 标准迁移四步

以 `SceneButton`（参考实现）与 `SceneSurfaceBinder` 为准：

```java
// ① 取配方：未显式传样式时跟随主题
ReadableSignal<SceneSurfaceStyle> surface = props.surface() != null
        ? props.surface()
        : SceneThemes.surface(rt, SceneTheme.Role.<角色>);

// ② 绑表面：唯一写入者，独占 background/border/borderWidth/cornerRadius/backdrop/surfaceElevation
SceneSurfaceBinder.bind(rt, root, motionRootOrNull, surface, props.enabled(), interaction);

// ③ 绑前景（需要时）：配方 foreground 优先，否则回落主题正文色
SceneSurfaceBinder.bindForeground(rt, textNode, surface, SceneThemes.DEFAULT.foreground());

// ④ 光标保持既有 SceneControlChrome.bindCursor
```

必须删除的旧写入者：`root.setBorderWidth/setCornerRadius/setBorderColor` 静态设值、
`rt.__bindAnimatedColor(SceneStateColors.xxxBackground, root::setBackgroundColor, ...)`、
`SceneControlChrome.bindStandardBorder(...)`、`SceneChromeTokens.applyPanelChrome(...)`。
**同一个属性不能留两个绑定**（禁止靠执行顺序覆盖）。

## 2. 常见模式

| 场景 | 做法 |
| --- | --- |
| 选中/未选中 | `SceneThemes.selectableSurface(rt, Role.INDICATOR, selected)`；选中不能只靠透明度 |
| 输入表面 | `Role.INPUT` + `SceneThemes.foreground/mutedForeground/disabledForeground(rt)` + `borderFocus/selectionBackground/selectionForeground(rt)` |
| 列表行/轻量项 | 一组共享表面（`Role.GROUP`）画在容器上，行只做轻量状态覆盖（hover/选中），行内不各自采样背景 |
| 浮层（菜单/对话框/提示） | `Role.OVERLAY` 画在浮层根；遮罩只负责遮罩，不重复覆盖玻璃；保留既有出现/离场时序 |
| 小控件（滑块/开关/指示） | `Role.INDICATOR` + `SceneThemes.accent(rt)` 表达进度/选中，`Role.INPUT` 表达轨道凹陷 |
| 无滤镜替代 | 主题 `SceneTheme.withoutBackdrop()`；不要自己写死实色 |

## 3. 构造期纪律（既有缺陷，必守）

1. **不在构造期解引用未求值的 Computed**：`Computed.create(derivation)` 的初值是 null，首次 flush 才求值。绑定器一律「构造期不读值，effect 里应用」。
2. **构造期捕获主题信号**：`SceneThemes.surface/selectableSurface/foreground` 等必须在 builder 内调用（此时 `Owner.current()` 是来源作用域）；不要在 effect 体内调用 `resolve`。
3. **不写每帧样本**：动画只改「当前配方的透镜强度/透明度」，不向信号写每帧值。
4. **卸载即回收**：绑定必须归属当前 Owner；用 `ReactiveTestProbe.registeredEffectCount()` 断言卸载后回到基线。

## 4. 绘制语义陷阱

- 配方 `idle.elevation > 0` 时走 `SceneSurfaceReliefPainter` 浮雕路径：**没有独立 BORDER 命令**，边框由方向性 `ROUNDED_BAND` 表达，`BACKGROUND` 四角半径按厚度内缩 1px。测试断言要按浮雕语义写。
- `backdrop == null` 时 `PaintPlan` 不得出现 `BACKDROP` 命令；有 backdrop 时一颗表面只采样一次。
- 半透明 tint 叠在玻璃之上；关闭滤镜时 tint 必须不透明可读。
- 位图图标不受 `textColor` 染色。

## 5. 测试模板

每个实例至少覆盖：

```text
1) 默认工厂路径：不传样式参数 → 属性等于 SceneThemes.DEFAULT.surface(role) 的对应值
2) 显式覆盖：传入自定义配方 → 完全覆盖主题（含 foreground）
3) 状态优先级：disabled > pressed > hovered > idle；focus 只覆盖非禁用态缘色
4) 主题更新：pageTheme.set(另一主题) + flush → 属性更新、节点身份不变、effect 数不增长
5) 卸载清理：handle.dispose() + flush → effect 数回到基线
6) 行为保持：该控件原有输入/值/焦点/滚动/回调测试继续通过（不得删除失败断言）
```

主题切换测试用：

```java
Signal<SceneTheme> pageTheme = Signal.create(SceneTheme.liquidGlassDark());
rt.mount(root, () -> {
    SceneNode page = new SceneNode();
    SceneThemes.withTheme(pageTheme, () -> { /* 构建被测控件 */ });
    return page;
});
```

注意 `Computed` 按值记忆化：两个主题若某角色配方相等，切换不会传播（这是期望行为，测试要显式构造不同的配方值）。
