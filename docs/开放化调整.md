# 开放化调整

本文档记录 Qz UILib 从内部验证工程转向第一版开发者入口时需要固化的调整范围、文档分级与执行顺序。

## 目标

- 面向其他开发者提供清晰、低侵入的 HTML-like UI 使用入口。
- 将测试期入口从默认热键和原版背包注入按钮迁移为显式指令触发。
- 把诊断页、示例页和未来稳定 API 边界分开，避免外部开发者依赖内部测试结构。
- 先固化文档与调整方案，再按方案做代码收口。

## 文档结构

- `docs/开放化调整/使用文档/README.md`：使用文档总览。
- `docs/开放化调整/使用文档/01-入门/项目定位与能力边界.md`：首版能力边界和非目标。
- `docs/开放化调整/使用文档/01-入门/最小文档页面.md`：创建 `UiDocument` 与 `HtmlLikeDocumentWidget` 的最小示例。

## 首版开放范围

- 公开推荐入口以 HTML-like 文档树为主：`UiDocument`、`ElementNode`、`TextNode`、`HtmlLikeDocumentWidget`。
- 控件优先开放 `DocumentButtonControl`、`DocumentTextInputControl`、`DocumentToggleSwitchControl`、`DocumentSegmentedSelectorControl`、`DocumentTableControl`。
- 背包槽位能力可作为 Minecraft 宿主示例能力开放，但不应成为普通 UI 的唯一示例。
- `UiDocumentScreens` 当前仍是内置页面创建入口，首版文档应把它描述为示例和诊断页面入口，而不是长期稳定 API 门面。

## 入口调整

- 停止默认注册原版背包页注入按钮，避免其他开发者或玩家在普通背包中看到测试入口。
- 停止右 Shift 全局打开诊断菜单，避免占用用户按键和干扰其他 Mod。
- 新增客户端指令作为显式开发者入口，建议使用 `/qzuilib` 命令组。
- 诊断页仍保留，但只通过指令或显式开发环境入口打开。

## 建议指令

- `/qzuilib ui`：打开诊断菜单。
- `/qzuilib smoke`：打开 HTML-like Smoke 页。
- `/qzuilib layout`：打开布局诊断页。
- `/qzuilib glass`：打开 Glass Lab。
- `/qzuilib inventory`：打开背包概览示例页。
- `/qzuilib help`：展示可用子命令。

## 执行顺序

1. 固化开放化文档和使用文档。
2. 新增客户端指令入口。
3. 停止默认注册 `InventoryScreenEntryListener`。
4. 移除或禁用 `UiScreenManager` 中的右 Shift 全局诊断热键。
5. 更新 `docs/AI记忆文档.md` 中的游戏内入口和下一步边界。
6. 运行 `git diff --check`、`test`、`compileJava`。
7. 游戏内验证 `/qzuilib ui` 与 `/qzuilib inventory`。
