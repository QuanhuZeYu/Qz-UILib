# 文档导航

本目录按信息保质期与面向读者分层组织。按"需要什么"对号入座，不要把本文件当知识仓库。

> **最高准绳**：根目录 [NORTH_STAR.md](../NORTH_STAR.md) 是 UI 系统中心思想宪章，凌驾于以下所有文档。任何架构决策、性能优化、API 取舍都须先与它对照；冲突时按其《修订纪律》登记偏离。

## 分层与入口

| 层 | 入口 | 保质期 | 装什么 |
|---|---|---|---|
| 架构宪章 | [../NORTH_STAR.md](../NORTH_STAR.md) | 长期 | 中心思想、信条、关键不变量 I1-I12 |
| 项目架构 | [架构/](架构/) | 长期 | 项目设计真相：边界、硬约束、技术债、测试体系、结构、命令 |
| 设计决策 | [决策/README.md](决策/README.md) | 长期 | 关键取舍的背景、候选、理由（为什么这么做） |
| 当前进展 | [进展/](进展/) | 短期 | 现状、计划、交接（现在在干嘛、下一步、接力） |
| 使用文档 | [使用文档/README.md](使用文档/README.md) | 对外 | 接入方怎么用 |
| 开发者资料 | [开发者文档/README.md](开发者文档/README.md) | 内部 | 错误预防、发布流程、规格 |
| 用户 README | [../README.md](../README.md) | — | 项目第一印象 |

## 读取顺序

1. 先确认任务性质，进对应分层（见上表"装什么"）
2. 架构性改动前先对照 `NORTH_STAR.md` 信条与不变量
3. 涉及具体类、方法、调用链、依赖图时，用 Glob/Grep/Read 和源码缩小范围，不在文档维护易过期清单
4. 对外接入以 `使用文档/` 为准，内部资料见 `开发者文档/`
5. 实现细节始终以源码为准，不从历史文档推断

## 写回纪律

权威源为 [AGENTS.md](../AGENTS.md) 第 4 节，本文件不重复。要点：

- 进展变化（目标/阻塞/进度）→ `进展/`
- 稳定下来的边界、结构、命令 → `架构/`
- 关键取舍 → `决策/`
- 对外能力变化 → `使用文档/`
- 错误预防通则 → `开发者文档/错误预防.md`
- 临时调试、一次性试验结论不沉淀
