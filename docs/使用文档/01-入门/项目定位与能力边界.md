# 项目定位与能力边界

Qz UILib 首版面向 Minecraft 1.7.10 / GTNH / LWJGL3ify 环境提供 HTML-like UI 框架能力。

## 项目定位

- Qz UILib 是 Java UI 框架，不是浏览器内核。
- UI 作者通过 Java API 创建文档树、声明样式、注册事件和组装控件。
- 运行时负责把文档树转换为布局盒、paint command 和 `UiRenderContext` 绘制调用。
- Minecraft 宿主集成保留在外层，页面作者不应直接处理 OpenGL/FBO/shader/stencil 细节。
- HTML-like 文本默认是原始文本语义，不把 Minecraft `§` 格式码当作页面作者层的隐式样式系统。

## 当前可用能力

- DOM-like 文档树：`UiDocument`、`ElementNode`、`TextNode`、`DocumentFragmentNode`。
- 宿主业务入口：`UiDocumentScreens.createDocumentScreen(...)`。
- 内建诊断/示例入口：仅保留内部开发工具命令入口，不构成对外页面 API。
- 常用样式：块布局、flex、table、px/%/auto 长度、`UiStyleLength.calc(percent, pixelOffset)` 混合长度、margin、padding、border、分边 border-width / border-color、分角圆角、`box-sizing`、颜色、背景图、文本色、`font-weight`、`font-style`、`text-transform`、`text-indent`、`text-shadow`、overflow、relative/absolute/fixed/sticky 定位、`transform`、`box-shadow`、`outline`、`border-style`、`border-collapse`、`animation-direction`。
- 样式表规则：支持 tag/class/id/通配符/复合选择器、后代选择器 `A B`、子代选择器 `A > B`、交互伪类 `:hover` / `:focus` / `:focus-visible` / `:active` / `:disabled`、结构伪类 `:first-child` / `:last-child` / `:nth-child(...)`、伪元素 `::before` / `::after`、按属性 `!important`、以及 `inherit` / `initial` / `unset` 级联关键字。
- 文本排版：`white-space:normal/nowrap/pre/pre-wrap/pre-line`、`text-overflow:clip/ellipsis`、`word-break:normal/break-all/keep-all`、`overflow-wrap:normal/break-word/anywhere`、`text-transform:none/uppercase/lowercase/capitalize`、`text-indent` 已在布局阶段生效。`nowrap` 与 `pre` 优先禁止软换行；`pre` / `pre-wrap` 保留连续空白与显式换行；`pre-line` 折叠连续空白但保留显式换行；ellipsis 仅在 `nowrap` 且宽度受限时生效；`anywhere` 与 `break-all` 会影响 auto 宽固有尺寸，`break-word` 只在受限宽度溢出时断长 token。
- flex 布局约束保持 HTML-like 直觉：`flex-direction:column` 下非 `stretch` 子项的 `width:auto` 会按内容收缩，而不是自动占满整行；auto 高文本块会按真实换行高度参与纵向排布，需要整行宽度时请显式设置 `width:100%`；`order` 已参与 flex item 的主轴布局、盒树视觉顺序、绘制与命中顺序。
- 默认盒模型接近浏览器 `content-box`：`width:100%` 只约束内容宽，自身 padding/border 会叠加并可能溢出父内容盒；需要把 padding/border 收进指定宽度时显式使用 `box-sizing:border-box`。
- `position:absolute` 相对最近 positioned ancestor 的 padding box 定位；`position:relative` 的 `top/bottom:%` 按 containing block 高度解析；`position:sticky` 保留普通流占位，并在最近 overflow 非 visible 祖先的滚动视口内按 inset 产生绘制和命中偏移。
- 输入事件：hover、active、click、dblclick、contextmenu、focus、key、text input、transitionend、animationend，以及作者可手动创建/派发的 `DocumentCustomEvent`。
- 控件：按钮、单行文本输入、多行文本输入、下拉选择、开关、分段选择器、表格、背包槽位网格。
- 绘制：背景、背景图、边框、虚线/点线/双线边框、box-shadow、text-shadow、outline、文本、clip、scrollbar、custom renderer、group opacity、backdrop filter。
- 动画：颜色、透明度、圆角、transform 子属性、box-shadow 子属性、`top/left/right/bottom`、backdrop blur，以及受控 layout 属性的 transition/keyframe；缓动函数已支持标准 cubic-bezier，keyframe animation 已支持 `animation-direction` 与无限迭代。
- DOM 结构遍历：`getPreviousSibling()` / `getNextSibling()` 可按当前树结构直接读取相邻兄弟节点。
- DOM 操作与复制：`appendChild` / `insertBefore` / `replaceChild` 已支持 `DocumentFragmentNode` 展开插入；`cloneNode()` / `cloneNode(true)` 可复制元素/文本/文档片段结构。
- 程序化交互：已公开 `ElementNode.focus()`、`blur()`、`scrollTo(scrollLeft, scrollTop)`、`scrollIntoView()`。
- HTML-like 语义元素：`document.a()`、`document.ul()`、`document.ol()`、`document.li()`、`document.img()`、`document.table()` 已提供最小可用语义闭环。

## 程序化焦点与滚动

- `focus()` 只对已挂载到当前文档、可聚焦、未 disabled 且处于可见布局中的元素生效；成功后会接入现有焦点链路，并在需要时自动滚入可视区域。
- `blur()` 只会清除当前已经获得文档焦点的同一元素；如果元素当前没有焦点，返回 `false`。
- `scrollTo(scrollLeft, scrollTop)` 只对当前文档中存在滚动范围的元素生效，偏移会按当前最大滚动范围夹取。
- `scrollIntoView()` 会滚动最近的可滚祖先，使目标元素尽量进入可视区域；目标已可见时通常不改变滚动值，但仍视为成功调用。
- `getScrollLeft()` / `getScrollTop()` / `getMaxScrollLeft()` / `getMaxScrollTop()` 可读取当前运行态滚动位置与可滚范围；元素未挂载或无滚动运行态时返回 `0`。
- 以上调用在元素未挂载、元素隐藏、不可聚焦或不具备滚动范围时保持无副作用并返回 `false`。

## 自定义事件与文档片段

- `ElementNode.addEventListener(type, handler)` / `addEventListener(type, handler, true)` 可注册自定义事件 listener；`true` 表示捕获阶段。
- `dispatchEvent(new DocumentCustomEvent(type, detail, bubbles, cancelable))` 走现有 DOM 三阶段传播链路（capture → target → bubble），不会绕开现有传播模型。
- `DocumentCustomEvent.preventDefault()` 仅在事件声明为 `cancelable=true` 时生效；`dispatchEvent(...)` 返回值与浏览器一致，表示默认行为是否未被阻止。
- `createDocumentFragment()` 用于批量 DOM 操作；片段在 `appendChild` / `insertBefore` / `replaceChild` 时会展开其子节点，片段自身不会进入最终文档树。
- `cloneNode` 当前复制节点结构、属性、class、inline style 和文本内容；不复制运行时事件监听器、现有 `setClickHandler(...)` 等交互 handler、自定义渲染回调或挂载后的滚动/焦点运行态。

## 链接、列表与图片回退

- `document.a()` / `a[href]` 提供最小链接语义：默认可点击、可聚焦、默认下划线、默认 `cursor:pointer`；当前默认语义只在存在非空 `href` 时生效，`a` 仅是链接元素工厂。
- 链接 click 若未被 `preventDefault()` 阻止，会先尝试处理 `#id` 片段跳转（滚动目标元素进入可见区），再通过 `UiDocument.setLinkActivationHandler(...)` 把激活事件交给业务方处理外部跳转、回调或埋点。
- `document.ul()` / `document.ol()` / `document.li()` 提供最小真实列表语义：`li` 会生成真实可见的项目符号或序号标记，而不是要求业务手写缩进模板。
- `border-collapse` 当前支持 `SEPARATE` 与 `COLLAPSE`：`COLLAPSE` 会去掉 table 自身 row/column gap，并在绘制阶段合并相邻单元格共享边线；当前仍不补完整浏览器 table 冲突解决算法。
- `img` 远程或本地资源解析失败时，不再静默空白；若声明了 `alt`，当前会在图片内容区内绘制最小文本回退。

## 样式属性的已知边界

以下能力仍有已知边界，不应视为浏览器同名能力已完整覆盖：

- **`font-family`**：当前仍未向作者层开放为 CSS-like 样式属性；已补齐 `font-weight` / `font-style`，但没有扩到字体族声明、fallback 列表或声明式字体资源。
- **`background-image`**：当前已支持 `UiBackgroundImage` 单图值，绘制阶段会把宿主图片源拉伸填充元素 border box，并参与圆角裁剪；不提供 CSS `url(...)` 字符串解析、渐变、多背景、repeat/position/size 等完整 CSS 背景模型。
- **阴影边界**：`box-shadow` 与 `text-shadow` 当前均为单值模型，不支持 CSS 逗号分隔多重阴影；`text-shadow` 的 blur 当前是小半径 halo 模拟，不等同完整高斯模糊。
- **`transform` 边界**：当前通过 `UiTransform` 支持 translate / scale / rotate 与 transform-origin，transform 只影响绘制和命中测试，不触发布局重排；不支持 skew、matrix、3D transform 或 CSS 字符串解析。
- **`box-shadow` 边界**：当前以 `UiBoxShadow` 单值模型为主，子属性可参与动画，但不支持 CSS 字符串语法、多重阴影或渐变阴影。
- **渐变边界**：尚未接入 `linear-gradient` / `radial-gradient` 等背景渐变。
- **`textarea` 软换行**：`DocumentTextAreaControl` 当前按“每个 `\n` 形成一条逻辑行”的最小模型实现，已支持多行输入、键盘光标移动、选区编辑和元素滚动，但还没有补浏览器 `pre-wrap` 式软换行；超长单行主要依赖横向滚动。
- **样式表规则边界**：当前 Java API 样式表不解析 CSS 文件，也不支持逗号分组、兄弟组合器、属性选择器或 `@media`。`@media` 未纳入本轮，是因为当前样式表没有媒体环境宿主模型（视口尺寸、输入类型、宿主状态等）和重算触发契约；建议后续单独切分为“文档媒体环境对象 + media rule 容器 + 视口变化重算”的小专题。
- **布局模型边界**：`display:grid` 与 `float` 尚未接入真实布局计算；`position:sticky` 当前是首阶段闭环，覆盖普通流占位、top/left/right/bottom 粘滞偏移、绘制和命中，不承诺完整浏览器 sticky 的所有滚动条交互与复杂 containing block 边界。
- **状态伪类组合器边界**：`:hover` / `:focus` / `:active` 等交互伪类只基于当前计算目标传入的 `activeStates`。`.parent:hover .child` 这类依赖祖先运行时状态的选择器还没有完整状态传播模型，不应视为已支持。
- **伪元素边界**：当前 `::before` / `::after` 仅支持最小文本 `content`，可参与样式匹配、布局、绘制和命中，但不支持 `attr()` / `counter()` / 图片内容、自定义替换内容、嵌套伪元素，也不会作为独立 DOM 查询结果或独立事件 target 暴露给页面作者；命中伪元素区域时事件仍回落到来源元素。
- **链接默认行为边界**：当前只补了片段跳转和文档级激活回调，不提供浏览器历史栈、页面装载器、`window.location` 或宿主默认外链确认框。
- **列表样式边界**：当前已支持 `list-style-type`（`NONE/DISC/CIRCLE/SQUARE/DECIMAL`），可在 `ul`/`ol`/`li` 上声明并继承；不支持 `list-style-position`、`list-style-image`、多级编号格式或自定义 marker 内容。
- **滚动条样式边界**：当前已支持 `scrollbar-color`（自定义滑块与轨道颜色）和 `scrollbar-width`（`AUTO/THIN/NONE`）；不支持 `::-webkit-scrollbar` 伪元素或更细粒度的滚动条部件样式。

## 事件与字体样式边界

- `dblclick` 是独立 DOM 事件，会在主按钮两次近距离、短时间内的连续命中 click 之后额外派发；单击事件不会因此被取消。
- `contextmenu` 作为独立右键菜单事件暴露，右键不会先派发普通 click；当前只负责事件语义与冒泡，不提供浏览器原生菜单系统、菜单项模型或宿主默认菜单接管。
- 链接默认激活同样走现有 click 事件语义：业务方若要阻止默认片段跳转或文档级激活回调，可在 click handler 中调用 `preventDefault()`。
- `transitionend` 按单个动画属性派发；`animationend` 按单个声明式 animation 名称派发；二者当前均为最小可用实现，只提供 target+bubble，不提供 capture 专用注册入口。
- `font-weight` 当前支持 `NORMAL` / `BOLD`；粗体会进入文本测量与换行计算。
- `font-style` 当前支持 `NORMAL` / `ITALIC`；斜体已进入文本绘制，但当前主要体现为渲染差异，不额外扩大 auto 宽测量。
- `font-weight` / `font-style` 的默认 `NORMAL` 样式与显式样式走同一最终文本绘制入口；文档层可把它们视为已接通属性，不需要为普通文本避开这两个声明。

## `cursor` 当前范围

- 运行时已把常用 `cursor` 值映射到 Minecraft 1.7.10 / LWJGL3ify / SDL 的真实系统光标：`default`、`pointer`、`text`、`move`、`not-allowed`、`wait`、`crosshair`、`ew-resize`、`ns-resize`、`none`。
- `grab` 与 `grabbing` 当前降级为 `move`，因为宿主标准系统光标集中没有独立的抓取手形。
- `help` 当前降级为 `default`，因为宿主标准系统光标集中没有独立的帮助问号光标。
- 鼠标离开命中元素、没有命中任何元素，或命中链（命中元素及其祖先）都未声明 `cursor` 时，会恢复默认箭头光标。
- 当前只支持宿主标准系统光标，不支持 CSS 自定义图片光标；`DocumentCursorOverlayControl` 仍然只是页面级图片覆层，不等同于系统光标。

详细差距分析见 [`docs/reviews/REVIEW-20260518-browser-capability-gap-audit.md`](../../reviews/REVIEW-20260518-browser-capability-gap-audit.md)。

## 当前非目标

- 不提供 HTML 文件解析。
- 不提供 CSS 文件解析（`@import`、`@media` 媒体查询）；Java API 已支持 CSS-like 选择器匹配（tag/class/id/复合/后代/子代/常用伪类）与样式表级联。
- 不提供 JavaScript DOM API。
- 不承诺 HTML5 全量语义。
- 不把 Minecraft GUI 生命周期或渲染底层暴露为页面作者 API。

## 开放化边界

- 首版文档应优先引导开发者使用 `createDocumentScreen(...)` 和 HTML-like 文档入口。
- 诊断页、Smoke 页和 Glass Lab 是开发工具，不是业务 UI 模板。
- 旧 retained `Widget` 树仍是后端基础，但不建议作为新业务页面的作者入口。
- 外部开发者需要的正式 API 门面后续可单独建立，不应直接把内部控制器作为稳定 API。
