# 指令触发方案

首版面向其他开发者时，测试期入口应从默认 UI 注入和全局热键迁移到显式客户端指令。

本文只描述诊断入口约束；业务 UI 打开方式以 `03-宿主集成/Minecraft界面入口.md` 为准。

## 不会注入的默认入口

为避免与宿主自有界面冲突，本库不会向原版界面或全局热键注入入口：

- 不在原版背包页插入 `背包UI` 按钮。
- 不会绑定全局热键打开或关闭诊断菜单。

内部 test 入口只能通过本节的 `/qzuilib test` 客户端指令打开。

## 当前诊断入口状态

- 旧 `/qzuilib test` 子页已清空。
- 当前 `/qzuilib test` 打开 test 页面重构规划页。
- 新 test 页面体系将按 DOM、CSS、布局、绘制、事件、控件、文本字体、动画、宿主运行时、远程与网络语义重建。
- 新运行时测试页必须直接展示 `预期结果：...` 人工验收文本。
- 详细规划以 `docs/开发者文档/specs/qzuilib-test-page-rebuild-plan.md` 为准。

## 指令入口

```text
/qzuilib test
/qzuilib hud_demo
```

命令语义：

- `/qzuilib test` 打开 test 页面重构规划页。
- `/qzuilib hud_demo` 开关 HUD 双层示例。
- 旧诊断跳转菜单入口已删除，后续按 test 页面重构规划逐组恢复运行时测试页。

## 代码调整点

- 在客户端侧注册内部开发工具命令。
- 在 `ClientProxy` 中调用内部开发工具 bootstrap 注册客户端命令。
- `/qzuilib test` 当前只由内部开发工具链调起单一 test 页面重构规划页。
- 后续新增运行时测试页时，仍应挂在内部开发工具链下，不暴露为稳定业务 API。
- 内部开发工具命令不在 `processCommand(...)` 中直接 `displayGuiScreen(...)`，而是通过 `UiScreenManager.getInstance().enqueue(...)` 延后开屏。
- `ClientProxy` 不再默认注册 `InventoryScreenEntryListener`。
- `UiScreenManager` 删除或禁用 `Keyboard.KEY_RSHIFT` 打开诊断菜单逻辑。
- `UiInputTickListener` 保留，只负责输入 tick、`UiScreenManager` tick 与延后任务冲刷。

## 时序约束

- 聊天命令执行结束后，聊天界面仍会继续关闭当前 `GuiScreen`。
- 因此 `/qzuilib test` 这类客户端命令不能在 `processCommand(...)` 中直接打开新界面。
- 正确做法是先入队到 `UiScreenManager`，再在当前帧输入分发结束后统一执行。

## 验收

- 普通打开原版背包时不出现 `背包UI` 测试按钮。
- 按右 Shift 不打开诊断菜单。
- `/qzuilib test` 能打开 test 页面重构规划页。
- 规划页能展示语义分组、重建顺序和 `预期结果：...` 人工验收文本样例。
- 后续重建的运行时测试页中的输入、hover、click、scroll 和键盘焦点仍需正常。
