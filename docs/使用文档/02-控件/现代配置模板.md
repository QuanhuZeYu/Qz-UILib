# 现代配置模板

本文件面向准备接入 Qz UILib 现代配置模板页的 Mod 开发者，说明可选依赖机制、回退边界、模板选择规则与复杂结构兼容建议。

> 12 个模板入口的完整 JSON/YAML 示例与 `FieldSpec` 声明见 [现代配置模板示例](./现代配置模板示例.md)。

## 可选依赖与运行时检测

UILib 的现代配置模板页依赖 `club.heiqi.config` 模块（支持 JSON/YAML、嵌套 map/list、路径访问与可变配置）。该模块未来计划独立为新 Mod，因此 UILib 入口采用**运行时能力检测**，而非编译期硬依赖。

### 检测策略

- `ModConfigGui` 通过 `Class.forName("club.heiqi.config.Config")` 与 `Class.forName("club.heiqi.config.MutableConfig")` 检测模块是否存在。
- **检测的是模块能力是否存在，不是检测配置文件是否存在**。避免把「是否安装模块」和「是否创建配置文件」混为一谈。
- 检测到模块时通过桥接类 `ModernConfigBridge` 创建 `ModernConfigTemplateScreen`。
- 检测不到时回退到现有 `ForgeConfigTemplateScreen`，继续使用 Forge Configuration。

### 桥接边界

- 入口类 `ModConfigGui` **不直接引用** `club.heiqi.config` 类型，避免 config 模块缺失时类加载失败。
- `ModernConfigTemplateScreen` 及其协作者允许直接引用 config 模块类型，但只在 `ModernConfigBridge` 之后加载。
- 接入方只需组装 `ModernConfigTemplateScreen.Spec` 并调用 `ModConfigGui` 提供的入口方法，无需关心检测细节。

## 回退边界（重要）

UILib **不提供** Forge Configuration 到 config 模块的迁移工具，也不在页面内添加迁移按钮。这一边界出于以下考虑：

- config 模块未来会独立成 Mod，配置页入口必须与其运行时存在性解耦。
- 双向适配会把复杂结构回退兼容压力放到 UILib 内部，增加模板页复杂度和长期维护成本。
- 不做迁移工具可以保持配置页职责清爽，避免引入数据迁移、版本冲突和不可逆写回问题。

### 接入方自行承担的回退兼容

如果接入方需要同一配置同时兼容 Forge 回退，应**自行设计回退模型**。推荐做法：

- **复杂结构推荐存 JSON 字符串属性**：把嵌套 map/list/表格等复杂结构序列化为 JSON 字符串，存入 Forge cfg 的字符串属性，由业务侧自行解析。这样 Forge 回退页只需展示一个文本框，现代页则可用 `RAW_EDITOR` 模板解析同一字符串。
- **简单类型直接共用**：string/number/boolean 等扁平 key-value 在两端可一一对应，无需额外兼容层。
- **不要依赖 UILib 做结构转换**：UILib 不内置 Forge↔config 模型互转。

## 模板选择规则

`ModernConfigTypeInference` 按固定优先级推断每个配置路径应使用的模板。`FieldSpec.templateHint` 是最高优先级的覆盖入口。

### templateHint 取值表

| hint 取值（小写、去空格） | 推断模板 TemplateType | 附加字段 |
|---|---|---|
| `dynamic-map` `dynamic_map` `map-dynamic` `key-value` `key_value` `keyvalue` `key-value-map` `key_value_map` `kv-map` | `KEY_VALUE_MAP` | — |
| `json` `json-editor` | `RAW_EDITOR` | `rawFormat = JSON` |
| `yaml` `yaml-editor` | `RAW_EDITOR` | `rawFormat = YAML` |
| `raw` `raw-editor` `code` `source` | `RAW_EDITOR` | `rawFormat` 取 `fallbackFormat`（默认 JSON） |
| `color` `colour` `hex` | `ENHANCED_PICKER` | `pickerKind = COLOR` |
| `resource` `asset` | `ENHANCED_PICKER` | `pickerKind = RESOURCE` |
| `sound` `audio` | `ENHANCED_PICKER` | `pickerKind = SOUND` |
| `longtext` `long-text` `multiline` `textarea` `text-area` | （作用于 STRING/NULL 节点）`LONG_TEXT` | — |

### 推断优先级（从高到低）

1. **dynamic-map hint** → `KEY_VALUE_MAP`（早返回）。
2. **明确格式 raw hint**（json/json-editor/yaml/yaml-editor）→ `RAW_EDITOR`（早返回）。
3. **通用 raw hint**（raw/raw-editor/code/source）→ `RAW_EDITOR`，rawFormat 取 `fallbackFormat`（默认 JSON）。
4. **enhanced picker hint**（color/colour/hex/resource/asset/sound/audio）→ `ENHANCED_PICKER`（早返回）。
5. **validValues 非空** → `CHOICE`（选项来自 FieldSpec）。
6. **按节点类型推断**：
   - STRING → `STRING`（含换行 / ≥160 字符 / long-text hint → `LONG_TEXT`）
   - NUMBER → `NUMBER`（无小数点 → `integerNumber=true`）
   - BOOLEAN → `BOOLEAN`
   - NULL → 按 `defaultValue` 类型或 hint 推断（默认 `NULL`）
   - LIST → 同构 primitive 元素 → `SIMPLE_LIST`；同构 MAP 元素且列稳定 → `TABLE`；混合 → `READ_ONLY`
   - MAP → 含 `_presets`/`presets`（非空 MAP/LIST）→ `PRESET_SELECTOR`；否则 → `OBJECT`

> 接入方可通过 `FieldSpec.templateHint` 强制覆盖默认节点类型推断；hint 大小写不敏感、自动 trim。

### 三参 infer 向后兼容

`ModernConfigTypeInference.infer(path, node, fieldSpec)` 等价于 `infer(path, node, fieldSpec, null)`。raw hint 且未传 `fallbackFormat` 时 rawFormat 默认 JSON。需要按 config 模块当前格式决定 raw 编辑器格式时，调用方应传 `config.getFormat()` 作为 fallback。

## 复杂结构兼容建议

### 嵌套 map（OBJECT）

- **适用场景**：固定 schema 的对象，如 `database.credentials.{username,password}`。
- **FieldSpec 配置**：可不声明，自动推断为 OBJECT；递归深度默认 5 层。
- **超深层级**：通过「展开编辑」跳转树形导航，避免无限内联撑爆页面。

### 树形导航（NestedCategoryBinding）

- **适用场景**：多层嵌套 map，需要左侧树 + 面包屑定位。
- **UI 表现**：MAP 根节点自动走 `ModernNestedCategoryBinding`，提供树形导航、面包屑、当前对象内联编辑。
- **搜索集成**：嵌套子项脏状态通过 `resolveDescendantBindings` 展开到搜索索引，「只看已修改」能反映嵌套子项。

### primitive list（SIMPLE_LIST）

- **适用场景**：端口列表、标签列表、ID 列表等一维数据。
- **FieldSpec 配置**：`setDefaultValue(Arrays.asList(...))` 提供默认值。
- **批量导入**：多行文本按行拆分，空行按 `keepEmptyLines` 选项决定保留或过滤。

### 同构对象列表（TABLE）

- **适用场景**：服务器列表、规则列表等列集合稳定的 list of map。
- **FieldSpec 配置**：可不声明，按元素结构自动推断；列集合由首个元素的 key 决定。
- **混合 list 退化**：元素类型不一致（如 map 与 primitive 混合）→ `READ_ONLY`，仅展示不可编辑。

### 动态 map（KEY_VALUE_MAP）

- **适用场景**：键集合不固定的映射，如自定义标签、动态翻译表。
- **FieldSpec 配置**：必须声明 `templateHint("dynamic-map")` 才会走 KEY_VALUE_MAP；否则按 OBJECT 内联编辑。
- **类型支持**：每个 value 可选 STRING/NUMBER/BOOLEAN/NULL 类型；重复 key 报错。

### 预设批量应用（PRESET_SELECTOR）

- **适用场景**：档位切换、主题预设等需要批量写入多个字段的场景。
- **识别规则**：MAP 节点含 `_presets` 或 `presets` 子键（非空 MAP 或 LIST）自动识别，无需 hint。
- **存储保留**：applyDraft 时 `_presets`/`presets` 键会被保留，不会被业务字段覆盖。
- **偏离展示**：选择预设后修改任一字段，显示「已偏离预设」标记。

### 源码编辑（RAW_EDITOR）

- **适用场景**：需要整体编辑 JSON/YAML 子树的场景，或复杂结构在 Forge 回退时存为字符串属性。
- **FieldSpec 配置**：`templateHint("json")` / `("yaml")` / `("raw")`。
- **语法安全**：语法错误不污染当前草稿，applyDraft 写最后一次合法解析值；错误行通过 `DocumentCodeEditorControl.setErrorLines` 高亮。

### 增强选择器（ENHANCED_PICKER）

- **适用场景**：颜色字段（HEX/ARGB）、资源路径、声音路径。
- **COLOR**：`DocumentColorPickerControl` 提供色块、HEX/RGB 输入与预览，支持 6 位（不透明）与 8 位（含 alpha）形式。
- **RESOURCE/SOUND**：当前退回文本输入，占位文案体现 hint；后续可扩展为资源/声音浏览选择器。

## 入口组装

接入方通过 `ModernConfigTemplateScreen.Spec` 组装页面规格，交由 `ModConfigGui` 的入口方法创建屏幕：

```java
ModernConfigTemplateScreen.Spec spec = new ModernConfigTemplateScreen.Spec(
        "mymod", "我的模组配置", mutableConfig)
        .setSubtitle("副标题")
        .setDescription("描述说明")
        .setConfigPath("config/mymod.json")
        .addField(new ModernConfigTemplateScreen.FieldSpec("player.name")
                .setLabel("玩家名称"))
        .addField(new ModernConfigTemplateScreen.FieldSpec("render.mode")
                .setValidValues("fast", "balanced", "safe"));
```

`Spec` 复用 `ForgeConfigTemplateScreen.Theme` 与 `ForgeConfigTemplateScreen.TextSet`，保持视觉与文案口径一致。`SaveHandler` 默认调用 `config.save()`，可自定义。
