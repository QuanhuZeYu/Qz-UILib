# 网络层入门

Qz UILib 4.1LTS 提供实验性网络层，面向双端 Mod 代码提供五类 API：

- `NetChannel`：类似 WebSocket 的双向消息。
- `NetFetchEndpoint`：客户端到服务端的请求-响应。
- `NetStreamEndpoint`：客户端请求、服务端返回大内容的流式下载。
- `NetStore`：服务端状态快照同步到客户端视图。
- `NetRealtimeChannel`：面向高频小二进制帧的实验性低延迟通道。

网络层的心智模型是 HTTP-like 内容语义：`route/key + contentType + headers + body`。框架不按 Java 类分配协议消息类型，也不要求每种请求写一个 `IMessage` 类；业务可以发送 JSON、文本、二进制或自定义 MIME-like 内容类型，并在自己的 handler 内解析 body。

默认传输走 vanilla custom payload early mixin 适配器，上层 API 不需要使用 `SimpleNetworkWrapper`。排障时可把配置项 `netTransport` 或 JVM 参数 `-Dqzuilib.net.transport=forge` 设为 `forge`，切到 FML 回退适配器。

## Channel

```java
NetChannel chat = NetService.getInstance()
        .channel(NetChannelId.of("mymod", "chat"))
        .onReceive(new NetChannel.NetChannelHandler() {
            @Override
            public void onReceive(final NetMessage message, final NetReceiveContext context) {
                context.runOnMainThread(new Runnable() {
                    @Override
                    public void run() {
                        String json = message.getBody().asUtf8String();
                        // 业务在这里解析 JSON，例如读取 text 字段并刷新 UI。
                    }
                });
            }
        })
        .register();

chat.toServer().sendJson("{\"text\":\"hello\"}");
chat.toPlayer(player).send(NetMessage.json("{\"text\":\"server reply\"}")
        .withHeader("x-message-kind", "chat"));
chat.toAll().sendBinary(new byte[] { 1, 2, 3 });
```

## Fetch

```java
NetFetchEndpoint getUser = NetService.getInstance()
        .fetch(NetEndpointId.of("mymod", "getUser"))
        .timeout(java.time.Duration.ofSeconds(5))
        .onRequest(new NetFetchEndpoint.NetFetchHandler() {
            @Override
            public void onRequest(NetRequest request,
                    NetFetchEndpoint.NetFetchRequestContext context) {
                String requestJson = request.getBody().asUtf8String();
                // 业务解析 requestJson 后组装响应。
                context.reply(NetResponse.json("{\"name\":\"Alex\"}")
                        .withHeader("x-cache", "miss"));
            }
        })
        .register();

java.util.concurrent.CompletableFuture<NetResponse> future =
        getUser.callJson("{\"id\":\"player-1\"}");
```

`Fetch` 当前按 C2S 设计；服务端主动推送请使用 `Channel` 或 `Store`。`NetResponse` 带 `statusCode`，业务可按 `isOk()` 或具体状态码处理。调用方可以对返回的 `CompletableFuture` 执行 `cancel(false)` 做本地取消；取消会从 pending 表移除，远端迟到响应会被忽略。`Fetch` endpoint 还可以配置滑动窗口限流，超限后返回 429 并带 `retry-after-ms`。

## Stream

```java
NetStreamEndpoint downloadAsset = NetService.getInstance()
        .stream(NetEndpointId.of("mymod", "downloadAsset"))
        .timeout(java.time.Duration.ofSeconds(60))
        .maxBytes(256L * 1024 * 1024)
        .onRequest(new NetStreamEndpoint.NetStreamHandler() {
            @Override
            public void onRequest(NetRequest request,
                    NetStreamEndpoint.NetStreamRequestContext context) {
                context.reply(NetResponse.ok(NetBody.binary(loadLargePayload()))
                        .withHeader("x-stream-kind", "asset"));
            }
        })
        .register();

NetStreamCall call = downloadAsset.callJson("{\"path\":\"assets/ui.zip\"}");
call.onProgress(new NetStreamProgressListener() {
    @Override
    public void onProgress(NetStreamProgress progress) {
        // 业务在这里更新进度条。
    }
});
```

Stream 适合超过 16 MiB 的资源、文件或大快照。请求仍是轻量 `NetRequest`，响应 body 走独立 chunk 生命周期，支持进度回调和取消；普通 Channel / Fetch / Store 不再承载这类内容。

## Store

```java
NetStore counter = NetService.getInstance()
        .store(NetStoreId.of("mymod", "counter"))
        .scope(NetStoreScope.GLOBAL)
        .initialJson("{\"value\":0}")
        .register();

counter.mutate(new NetStore.StoreMutator() {
    @Override
    public NetBody mutate(NetBody current) {
        int nextValue = parseAndIncrement(current.asUtf8String());
        return NetBody.json("{\"value\":" + nextValue + "}");
    }
});

counter.view().subscribe(new NetStoreView.NetStoreSubscriber() {
    @Override
    public void onSnapshot(NetBody snapshot) {
        String json = snapshot.asUtf8String();
        // 客户端收到快照后解析 JSON 并刷新 UI。
    }
});
```

`GLOBAL` scope 默认向所有玩家同步；配置 `.accessControl(...)` 后会逐个在线玩家过滤，不会盲目广播给无权限玩家。需要玩家或维度隔离状态时可使用 `PER_PLAYER` / `DIMENSION`：

```java
NetStore playerState = NetService.getInstance()
        .store(NetStoreId.of("mymod", "playerState"))
        .scope(NetStoreScope.PER_PLAYER)
        .initialJson("{\"value\":0}")
        .accessControl(new NetStore.AccessControl() {
            @Override
            public boolean canAccess(Object player, NetStore store) {
                return player != null;
            }
        })
        .register();

playerState.setForPlayer(player, NetBody.json("{\"value\":7}"));
```

客户端 DOM 绑定可通过 `NetStoreUiBridge.getInstance().bind(view, element, renderer)` 完成，renderer 接收的同样是 `NetBody`，并会被投递到客户端主线程队列执行。

`Store` 也支持业务自定义增量：先在 builder 上注册 `.deltaApplier(...)`，再调用 `applyDelta(...)`、`applyDeltaForPlayer(...)` 或 `applyDeltaForDimension(...)`。客户端收到 `STORE_DELTA` 后会交给同一个 applier 计算新快照，再通知订阅者。

## Realtime Channel

`NetRealtimeChannel` 面向高频、小包、强调新鲜度的二进制帧，例如语音帧、实时输入采样或临场状态广播：

```java
NetRealtimeChannel voice = NetService.getInstance()
        .realtime(NetRealtimeChannelId.of("mymod", "voice"))
        .maxFrameBytes(1200)
        .maxQueuedFrames(3)
        .maxLatency(java.time.Duration.ofMillis(250))
        .dropPolicy(NetRealtimeDropPolicy.DROP_OLDEST)
        .onReceive(new NetRealtimeChannel.NetRealtimeHandler() {
            @Override
            public void onReceive(NetRealtimeMessage message, NetReceiveContext context) {
                byte[] opusFrame = message.getPayload();
                // 业务自行做 jitter buffer、解码与播放。
            }
        })
        .register();

voice.toServer().sendFrame(1L, 42, System.currentTimeMillis(), opusFrameBytes);
```

注意边界：

- 仍运行在 Minecraft 现有 TCP/custom payload 底座上，不等价于 UDP 实时媒体链路。
- 走专用 `QZRT` 小帧协议，不复用 `route/key + contentType + headers + body` 通用 envelope。
- 单帧禁止自动分片；超过 `maxFrameBytes(...)` 或物理帧上限会直接失败。
- 队列满时按 `NetRealtimeDropPolicy` 丢弃，优先保证新鲜度，不保证完整送达。
- 适合作为语音等实时业务的数据面；会话、权限、配置等控制面仍建议继续使用 `Fetch` / `Channel` / `Store`。

## 内容类型与可选 codec

- JSON：`NetBody.json(...)` / `NetMessage.json(...)` / `NetRequest.json(...)` / `NetResponse.json(...)`
- 文本：`NetBody.text(...)`
- 二进制：`NetBody.binary(...)`
- 自定义：`NetBody.of(NetContentType.of("application/vnd.mymod.state+json"), bytes)`

`club.heiqi.uilib.net.codec.NetCodec` 仍可作为业务内部的紧凑二进制 POJO 编码辅助：先把对象编码成 `byte[]`，再用 `NetBody.of(customContentType, bytes)` 发送。它不是网络协议的路由身份，也不参与主路径握手。

## Headers

Header 只适合轻量元数据，不应用来承载大内容：

- header 名大小写不敏感，发送前会归一成小写 token，例如 `X-Qz-Trace` 会变成 `x-qz-trace`。
- 单帧最多 32 个 header。
- 单个 header 名最多 64 字节，单个值最多 1024 字节。
- 单帧 header 名和值合计最多 8192 字节。
- header 值不允许包含 CR/LF。

## 大小边界

- 32KB 是兼容物理帧下限，不是普通业务消息上限。
- 8 MiB 以上会进入大消息提示。
- 16 MiB 是普通 Channel / Fetch / Store 逻辑消息默认上限。
- GTNH/Hodgepodge 物理能力按 256 MiB 默认、1 GiB 硬上限理解。
- C2S 超过 32KB 时会自动分片；超过 16 MiB 的普通消息应改走 Stream/chunk 大内容路径。
- Stream 默认大内容上限为 256 MiB，硬上限为 1 GiB。
- Realtime Channel 的小帧不会自动分片，建议业务负载保持在约 1 KiB 量级。

## 注册时机

下游 Mod 应在 `preInit` 注册 Channel / RealtimeChannel / Fetch / Stream / Store。Qz UILib 会在 `postInit` 冻结注册表，冻结后再注册会抛 `IllegalStateException`。

## 运行时自检

开发环境可通过 `/qzuilib test` 打开网络层自检页，可逐项执行，也可用“全部执行”一次跑完。页面中的本地断言可直接执行；运行时 Channel / Fetch / Store 往返、C2S 分片、Fetch 错误、超时、取消和玩家 Store 检查需要客户端已连接到本地或测试服务器。

自检页还包含 `运行时远程页面` 和 `运行时远程 HUD` 交互 smoke：前者通过 `RemoteDocumentPages.open(...)`
下发整页安全子集 HTML，后者通过 `RemoteHudOverlays.open(...)` 下发 HUD 浮层；两者都会通过 Stream 拉取
HTML，并在页面或 HUD 内提交按钮后验证表单收集、C2S 提交回调和服务端回复结果。
