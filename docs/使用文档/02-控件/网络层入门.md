# 网络层入门

Qz UILib 4.1LTS 提供实验性网络层，面向双端 Mod 代码提供三类 web 语义 API：

- `NetChannel`：类似 WebSocket 的双向消息。
- `NetFetchEndpoint`：客户端到服务端的请求-响应。
- `NetStore`：服务端状态快照同步到客户端视图。

默认传输走 vanilla custom payload early mixin 适配器，上层 API 不需要使用 `SimpleNetworkWrapper`。

## Channel

```java
public final class ChatMsg {
    public String text;
}

NetChannel<ChatMsg> chat = NetService.getInstance()
        .channel(NetChannelId.of("mymod", "chat"), ChatMsg.class)
        .onReceive(new NetChannel.NetChannelHandler<ChatMsg>() {
            @Override
            public void onReceive(ChatMsg message, NetReceiveContext context) {
                context.runOnMainThread(new Runnable() {
                    @Override
                    public void run() {
                        // 在主线程读写世界或 UI 状态。
                    }
                });
            }
        })
        .register();

chat.toServer().send(new ChatMsg());
chat.toPlayer(player).send(new ChatMsg());
chat.toAll().send(new ChatMsg());
```

## Fetch

```java
public final class GetUserReq {
    public String id;
}

public final class GetUserResp {
    public String name;
}

NetFetchEndpoint<GetUserReq, GetUserResp> getUser = NetService.getInstance()
        .fetch(NetEndpointId.of("mymod", "getUser"), GetUserReq.class, GetUserResp.class)
        .timeout(java.time.Duration.ofSeconds(5))
        .onRequest(new NetFetchEndpoint.NetFetchHandler<GetUserReq, GetUserResp>() {
            @Override
            public void onRequest(GetUserReq request,
                    NetFetchEndpoint.NetFetchRequestContext<GetUserResp> context) {
                GetUserResp response = new GetUserResp();
                response.name = "Alex";
                context.reply(response);
            }
        })
        .register();

java.util.concurrent.CompletableFuture<GetUserResp> future = getUser.call(new GetUserReq());
```

`Fetch` 当前按 C2S 设计；服务端主动推送请使用 `Channel` 或 `Store`。

## Store

```java
public final class Counter {
    public int value;
}

NetStore<Counter> counter = NetService.getInstance()
        .store(NetStoreId.of("mymod", "counter"), Counter.class)
        .scope(NetStoreScope.GLOBAL)
        .initial(new Counter())
        .register();

counter.mutate(new NetStore.StoreMutator<Counter>() {
    @Override
    public void mutate(Counter state) {
        state.value++;
    }
});

counter.view().subscribe(new NetStoreView.NetStoreSubscriber<Counter>() {
    @Override
    public void onSnapshot(Counter snapshot) {
        // 客户端收到快照后刷新 UI。
    }
});
```

客户端 DOM 绑定可通过 `NetStoreUiBridge.getInstance().bind(view, element, renderer)` 完成。

## 大小边界

- 32KB 是兼容物理帧下限，不是普通业务消息上限。
- 8 MiB 以上会进入大消息提示。
- 16 MiB 是普通 Channel / Fetch / Store 逻辑消息默认上限。
- GTNH/Hodgepodge 物理能力按 256 MiB 默认、1 GiB 硬上限理解。
- C2S 超过 32KB 时会自动分片；超过 16 MiB 的普通消息应改走后续 stream/chunk 大内容路径。

## 注册时机

下游 Mod 应在 `preInit` 注册 Channel / Fetch / Store。Qz UILib 会在 `postInit` 冻结注册表，冻结后再注册会抛 `IllegalStateException`。
