# 服务端下发远程页面

`RemoteDocumentPages` 用于让服务端把一段安全子集 HTML 发送给指定玩家，客户端拉取内容后打开
`GuiScreen` 显示。它适合任务面板、向导、表单确认页、服务端生成的说明页等场景。
如果需要显示为 HUD 弹窗、自动提示或弹幕，请使用 [远程 HUD 浮窗](远程HUD浮窗.md)。

Qz UILib 现已把“服务端权威配置远程页”做成该入口的标准用例：远程页本身只负责展示和采集表单，
字段定义、默认值、草稿、校验和显式保存都来自同一个服务端配置会话。

远程页面不是完整浏览器：客户端不会执行 JavaScript，也不会嵌入系统浏览器。HTML/CSS 会被解析为
Qz UILib 的 `UiDocument`、样式表和 `Document*Control` 控件。

## 最小示例

```java
RemoteDocumentPage page = RemoteDocumentPage.builder("example-profile")
        .title("玩家资料")
        .html("<h1>玩家资料</h1><p>欢迎回来。</p>")
        .build();

RemoteDocumentPages.open(player, page);
```

需要表单回调时传入 `RemoteDocumentSubmitHandler`：

```java
RemoteDocumentPage page = RemoteDocumentPage.builder("rename")
        .title("修改名称")
        .html("<form action=\"rename\" id=\"rename-form\">"
                + "<input type=\"text\" name=\"name\" placeholder=\"新名称\" maxlength=\"32\">"
                + "<button type=\"submit\" name=\"submit\" value=\"save\">保存</button>"
                + "</form>")
        .build();

RemoteDocumentPages.open(player, page, new RemoteDocumentSubmitHandler() {
    @Override
    public void onSubmit(RemoteDocumentSubmitEvent event) {
        String name = event.getFirstValue("name");
        event.reply(RemoteDocumentPage.of("rename-result", "已提交",
                "<h1>已收到</h1><p>" + escapeForHtml(name) + "</p>"));
    }
});
```

## 页面模型

- `RemoteDocumentPage.pageId`：业务页面标识，会随提交回传。
- `RemoteDocumentPage.title`：加载页标题和业务展示标题的默认来源。
- `RemoteDocumentPage.html`：安全子集 HTML 文本。
- `RemoteDocumentPage.resourcePolicy`：图片与外链策略，默认 `FULL_EXTERNAL_LINKS`。
- `RemoteDocumentPage.metadata(...)`：业务元数据，会随 open offer 发送给客户端。

HTML 内容通过内置 Stream endpoint 按 `sessionId` 拉取，适合大页面；表单提交走轻量 Channel。
客户端会校验 session、pageId、大小和 SHA-256，失败时显示错误页。

## 服务端权威配置页

如果要让服务端直接下发一个配置页面，而不是本地模板页自己渲染，可使用
`RemoteConfigDocumentPages.open(player, screenId)`：

```java
RemoteConfigDocumentPages.open(player, "example-mod-config");
```

前提是服务端已经通过 `ConfigTemplateSyncManager.registerTarget(...)` 注册了同名配置目标。

这类远程配置页的边界如下：

- 远程页复用 `ConfigTemplateSyncManager` 的 `screenId -> session -> save` 模型，不额外发明独立 wire shape。
- 页面首屏字段、默认值和当前草稿都来自服务端权威配置会话。
- 提交按钮只做“显式保存/刷新/放弃草稿”三类动作；真正保存仍由服务端配置会话执行。
- 当页面 HTML 或配置元数据较大时，内容拉取仍由 `RemoteDocumentPages` 自己的 Stream 通道承载。
- 远程页没有浏览器 JavaScript，因此它更适合“表单草稿 + 显式保存”语义，而不是逐按键的实时交互脚本。

## 支持的 HTML 子集

可用标签包括：

`html`、`head`、`body`、`title`、`style`、`div`、`span`、`p`、`h1`-`h6`、`ul`、`ol`、`li`、
`table`、`thead`、`tbody`、`tfoot`、`tr`、`th`、`td`、`a`、`img`、`form`、`input`、`textarea`、
`select`、`option`、`button`、`br`、`hr`。

`script`、`iframe`、`object`、`embed` 等危险标签会被忽略并记录日志。`on*` 事件属性不会生效。

## CSS 子集

支持 inline `style` 和 `<style>`，选择器复用现有 `UiSelector` 能力。常用白名单属性包括：

- 布局：`display`、`width`、`height`、`min-*`、`max-*`、`box-sizing`、`position`、`top/right/bottom/left`、`z-index`
- 间距与边框：`margin`、`padding`、`border`、`border-width`、`border-style`、`border-color`、`border-radius`
- 滚动与 flex：`overflow`、`overflow-x/y`、`flex-direction`、`flex-wrap`、`flex-grow`、`flex-shrink`、`flex-basis`、`align-items`、`align-self`、`justify-content`、`gap`
- 文字与视觉：`color`、`background-color`、`background-image:url(namespace:path)`、`opacity`、`line-height`、`text-align`、`white-space`、`text-overflow`、`visibility`、`font-weight`、`font-style`、`cursor`、`text-decoration`、`object-fit`、`aspect-ratio`

长度支持 `px`、`%`、`auto`，以及最小形态 `calc(100% - 16px)`。颜色支持
`#RGB`、`#RRGGBB`、`#AARRGGBB`、`rgb()`、`rgba()` 和基础命名色。
`background-image` 当前仅支持 Minecraft `ResourceLocation` 纹理 URL 与 `none`，不支持 HTTP 背景图、渐变、多背景或 repeat/position/size 模型。

## 表单行为

支持字段：

- `input type="text"` / `hidden` / `checkbox` / `radio` / `submit`
- `textarea`
- `select` / `option`
- `button type="submit"`

客户端只提交启用且带 `name` 的控件；同名字段以 `Map<String, List<String>>` 保留多值。
文本框回车会提交最近的表单，提交按钮自身的 `name/value` 会作为 submitter 一起提交。

## 资源策略

`RemoteDocumentResourcePolicy` 有三档：

- `LOCAL_RESOURCES_ONLY`：只允许 Minecraft `ResourceLocation` 图片和页内 `#id` 锚点。
- `HTTP_IMAGES`：允许 HTTP/HTTPS 图片，但不打开外部链接。
- `FULL_EXTERNAL_LINKS`：允许 HTTP/HTTPS 图片，外部 HTTP/HTTPS 链接会先弹出客户端确认，再调用系统浏览器。

`javascript:`、`data:`、`vbscript:` 等可执行或内联协议始终禁止。
