# 表格与背包槽位

表格和背包槽位是首版开放化中最容易被混用的两类能力，需要明确普通 UI 与 Minecraft 宿主能力的边界。

## 普通表格

`DocumentTableControl` 使用真实 `table/tbody/tr/td` 与按需 `thead/tr/th` 元素表达表格。

能力边界：

- 支持表头和表体。
- 支持列宽、自动列、行列 gap。
- 支持单元格 padding、border、background 和 text。
- 支持 `border-collapse: collapse` 的最小闭环：去掉 table 内部 row/column gap，并在绘制阶段合并共享边线。
- 无表头时不保留空 `thead`。
- 绘制走标准 background、border 和 text paint command。

当前不覆盖：

- `colspan`。
- `rowspan`。
- `caption`。
- 完整 CSS table 算法。

`border-collapse` 当前边界：

- 仅支持 `SEPARATE` / `COLLAPSE` 两种模式。
- `COLLAPSE` 以“单条共享边线”的最小视觉闭环为目标，不补浏览器完整的冲突优先级规则、不同边框样式冲突解决或复杂跨行跨列边线合并。

## 背包槽位网格

当前 Breaking major **不提供** `SlotContentSnapshot`、`InventorySlotSnapshot`、`DocumentSlotControl`、
`DocumentSlotGridControl`、inventory click/tooltip 或原版 `GuiContainer` bridge。旧槽位章节只保留在本文件作为迁移提示，
不要在新业务代码中引用这些类型。

普通 UI 如果只需要展示一个物品图标，应把它当作普通 `SceneImageSource` 使用：

```java
SceneImageSource icon = HostImageSource.itemIcon(stack);
```

`itemIcon` 创建时复制完整 `ItemStack`（含 metadata/NBT），之后不再读取调用方 mutable stack；只绘制 icon，
不承载数量、耐久、tooltip、carried 或槽位交互。库存/容器交互属于业务 Mod 或专用宿主，不由 UILib 通用 scene 负责。

## 边界约定

- 普通表格不应依赖背包 slot 专用逻辑。
- 不要重新添加已删除的 Slot/inventory public seam；需要新的通用能力时优先扩展 scene node、input 或普通 image contract。
- table 布局层不得加入 slot 专用分支。
- slot 半透明底板应叠在 UI 底图上，不应改成不透明来掩盖穿透问题。
- Minecraft 物品图标在作者侧心智上应被视为普通 scene 图片源；底层宿主绘制细节由 `HostImageSource.itemIcon` 与 item coordinator 封装。
- 鼠标携带物品、tooltip 和容器交互不属于该普通 icon contract。
