# 决策：textarea 软换行暂不实现，归为行模型重构专项

> 后续状态：该历史决策已被 `feat/textarea-soft-wrap` 的工程化实现取代。当前 `DocumentTextAreaControl` 已新增“逻辑行 + 视觉行”两级模型，软换行、caret、选区、点击命中、上下方向键与滚动揭示都按视觉行工作。本文件保留用于说明为什么不能在旧单级模型上打补丁。

## 背景

- 浏览器能力缺口复核把 textarea 软换行列为 B 类"高性价比"候选。
- 深入 `DocumentTextAreaControl` 源码后发现，软换行不是局部增强，而是控件核心行模型的重构。

## 核实结论：当前为单级"逻辑行=视觉行"硬模型

`DocumentTextAreaControl` 整体建立在"逻辑行（由 `\n` 切分）与视觉行一对一"的假设上：

- 每个逻辑行建固定高度 `DEFAULT_LINE_HEIGHT=18` 的 div，文本 span 强制 `white-space:NOWRAP`，明确不折行
- caret Y 坐标 = `lineIndex * DEFAULT_LINE_HEIGHT`
- 上下方向键 `moveCaretVertically` 在逻辑行之间移动
- 点击命中 `documentY → lineIndex = (y - top) / 18`
- 选区渲染、滚动揭示全部基于该一对一映射

软换行会把一个逻辑行按容器宽度折成多个视觉行（一对多），击穿上述每一处几何计算，需要从"单级逻辑行"重构为"逻辑行 + 视觉行两级模型"，且软换行依赖渲染期才可得的容器宽度，时序更复杂。

## 候选方案

1. 现在投入重构两级行模型，打通软换行。
2. 跳过，归为独立的 textarea 行模型重构专项。

## 最终选择

- 选择方案 2：暂不实现 textarea 软换行，归为独立重构专项。

## 选择原因

- 改动会触及 caret 定位、选区、上下移动、点击命中、滚动揭示的全部几何，回归风险高，不属于"照样板小步填缺口"的粒度。
- 与本批其他能扩展的轻量缺口相比，性价比明显更低，应单独立项并配套大量回归测试。
- textarea 当前的多行（按 `\n`）编辑能力本身可用，软换行缺失是体验增强而非功能缺陷。

## 影响范围与后续注意事项

- 本轮 B 类缺口集中填补不包含 textarea 软换行。
- 后续若实现，必须先把行模型升级为"逻辑行 + 视觉行两级"，再统一改 caret/选区/命中/滚动几何，并补齐两级映射的回归测试，不要在单级模型上打补丁。
- 经此项与 font-family 两次复核，确认缺口复核文档的"高性价比"分级仍可能低估隐藏工程量；后续每项动手前仍需先核实实现复杂度。
