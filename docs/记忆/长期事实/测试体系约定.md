# 测试体系约定（防错收口）

> 本文档是 scene 测试体系的**长期事实层**约定：分层规则、L2 防错清单、断言库速查、
> 各包职责与反例锚点。新建测试前必读；评审测试 PR 时逐条核对。
>
> 代码侧镜像：`scene/layout/package-info.java`（L2 纪律）、`scene/package-info.java`
> （分层总纲）、`LayoutAssertions` 类 javadoc（速查表）。

## 1. 分层总纲

scene 测试按子系统依赖深度分两层，其余子包按各自归属：

- **L2 纯数学（`scene/layout/`）**：仅 `new SceneNode` + `SceneLayoutEngine.layout` + 数值/失效
  断言。零 runtime / signal / input / paint 依赖。确定、快速、可重入，是 **CI 硬门禁**——
  任何 PR 必须先过 L2 全绿。
- **L3 集成（`scene/integration/`）**：跨子系统协作（runtime + signal + input + paint），
  端到端行为验证。运行宽松，非 CI 硬门禁。
- **其余子包**（node / control / input / paint / overlay / runtime / text）：按各自子系统归属，
  不强制纯数学，但同样应优先复用共享设施（FixedTextMeasurer / LayoutAssertions）。

**准入判据**：测试触到 `SceneRuntime` / `ReactiveScheduler` / signal / 输入路由 / paint 引擎
任一，即属 L3，必须进 `integration/`，**不进 `layout/`**。

## 2. L2 防错清单（核心，7 条）

1. **文本度量**：新写 L2 测试必用 `FixedTextMeasurer(8,16)`（scene 测试根目录的确定性桩），
   禁依赖真机字体 / font renderer——保证跨环境一致。
2. **几何 / 失效断言**：必复用 `LayoutAssertions`，勿在测试里裸 `assertEquals` 断坐标 / 尺寸 /
   失效位。
3. **例外白名单**：**例外**：grow 主轴分配（只断主轴尺寸，交叉轴受 STRETCH 影响难预期，见
   GrowAllocationTableTest）、缓存计数/并行池等非全维几何量允许裸 assertEquals。
4. **engine 实例**：每个测试用例用独立 engine 实例（per-field final 或 per-test new 均可），
   禁跨用例复用同一 engine。
5. **import 禁区**：L2 测试禁 import reactive / runtime / input / paint 包，违者即应下沉 L3。
6. **I4 矩阵**：新增任何 setter，其失效级别必须补进 `scene/node/InvalidationLevelMatrixTest`
   的矩阵表。
7. **grow 场景**：grow 分配新场景必须补进 `GrowAllocationTableTest` 的 Case builder，
   期望值需 Oracle 手算并交叉校验。

## 3. LayoutAssertions 速查

| 你要断言什么 | 用哪个 helper |
|---|---|
| 某 setter 只触发某一级失效（I4 矩阵） | assertOnlyInvalidation(node, level) |
| 遍历后节点完全清脏 | assertClean(node) |
| 局部坐标全 4 维（x/y/w/h） | assertLocalBox(node, x, y, w, h) |
| 绝对坐标累加（I12/§4.5，只 x/y） | assertAbsoluteBox(node, rootX, rootY, x, y) |
| COLUMN shrink-to-fit 高度求和 | assertColumnHeightSum(container) |
| ROW SHRINK 宽度求和 | assertRowWidthSum(container, availW) |
| 增量失效恰好重算某集合（I7） | assertRelayoutSet(result, nodes...) |
| 干净帧零重算（I7） | assertNoRelayout(result) |

不在此表的几何/失效断言，优先扩充本库而非在测试里裸写 assertEquals；纯缓存计数/并行池等
非几何量除外。

## 4. 各包职责一句话表

| 子包 | 测什么 | 准入判据 |
|---|---|---|
| `layout/` | L2 布局数学（I4/I7/I12/§4.5 不变量） | 纯数学，零 runtime/signal/input/paint |
| `node/` | SceneNode 脏标记 / 失效传播（含 I4 矩阵） | 节点级状态，可独立于 runtime |
| `control/` | 控件装配结构（按钮/列表/表格/滑块的 SceneNode 装配） | 结构断言，可不接 runtime |
| `integration/` | 跨子系统 L3（runtime+signal+input+paint 端到端） | 触到多子系统 |
| `input/` | 输入路由（hit-test/focus/cursor/overlay dismiss） | input 子系统 |
| `paint/` | paint 引擎（fragment/composite replay/transform） | paint 子系统 |
| `overlay/` | overlay 锚定与 host | overlay 子系统 |
| `runtime/` | 声明式运行时（SceneRuntime/portal） | runtime 子系统 |
| `text/` | 文本度量并发性（measure 幂等） | text 子系统 |

## 5. 反例锚点（防错最有效）

> 历史踩过的坑，评审时直接对照这几条否决。

- **"需要 SceneRuntime 的控件装配 → 属 L3，不进 `layout/`"**
  L2 测试只 new 裸 SceneNode + layout 引擎，凡要 SceneRuntime / signal 订阅的，下沉
  `integration/`。否则破坏 L2「确定、零依赖」前提。
- **"断 grow 交叉轴 → 不需要，grow 算法与交叉轴正交"**
  grow 只分配主轴尺寸，交叉轴受 STRETCH / align 影响、难预期。grow 测试只断主轴，
  用裸 assertEquals 即可（见白名单第 3 条）；勿为凑 `assertLocalBox` 伪造交叉轴期望值。
- **"找 stackHost 结构 → 控件结构探针，不放 LayoutAssertions"**
  LayoutAssertions 是布局数学断言库，不放控件结构 / stackHost 查找这类装配探针。
  装配结构断言归 `control/` 包内的局部工具。

## 6. 架构纪律（评审守卫，非编译守卫）

> L2/L3 分层与 L2 纯数学边界**不由自动化测试守卫**（曾用 ArchUnit，已于
> 2026-07 移除）。这些边界靠**评审纪律 + package-info 声明**维持，
> PR 评审时逐条核对，破坏即阻断合并。

- **L2 纯数学边界（最高优先级）**：`scene/layout/` 下任何类**禁止**依赖
  `scene/runtime`、`scene/input`、`ui/reactive`、`scene/paint` 四个包
  （NORTH_STAR I4/I7/I12）。**双重守卫**：产品侧——`scene/layout/` 包的生产类
  import 段禁出现上述四包（评审时直接查）；测试侧——见 §2 第 5 条「import 禁区」。
- **准入分层**：测试触到 SceneRuntime / ReactiveScheduler / signal / 输入路由 / paint
  引擎任一，必须进 `integration/`，不进 `layout/`（同 §1 准入判据）。
- **为何移除自动守卫**：ArchUnit 规则维护成本（jar 依赖 + 规则同步）超过
  收益；scene 包结构稳定、评审已能覆盖，改由文档纪律承载。

## 7. 统一测试入口（testkit）

scene 测试搭台设施（testkit）收口跨 L2/L3、跨 input/paint 子系统的可复用 helper，
对应代码 `src/test/java/club/heiqi/uilib/ui/scene/testkit/`，镜像说明见该包 `package-info.java`。

### 7.1 输入侧两入口边界

scene 输入测试有两条正交入口，务必按场景选择，不要混用：

| 入口 | 用什么 | 测什么 | 备注 |
|---|---|---|---|
| A「编程注入帧」（默认） | `SceneInteractionHarness`（首选）/ 裸 `InputFrameBuilder`（白盒回退）→ `SceneRuntime.route` | 交互路由 + 状态机（click / hover / scroll / key） | 交互测试一律走此入口 |
| B「桥封板契约」 | `MockPlatformInputSource`（`scene/input/mock/`，**非 testkit**） | 封板状态机 / 键映射 / 不可变性 | 现存 3 文件，不用于交互测试 |

**入口 A 内部选择判据（重要，统一收口）**：

- **默认用 `SceneInteractionHarness`**：`harness.click/moveTo/scroll/press/
  pressKey/typeText(node)` 自动取节点中心 + route，消除坐标硬编码与 11 参
  `RawInputEvent` 样板。凡 harness 能覆盖的交互，**必须**用 harness，不得裸建。
- **仅以下白盒场景回退裸 `InputFrameBuilder`**（harness 结构性覆盖不了）：
  1. **overlay 树外路由**：点击/键盘目标在 overlay 弹层内，harness.mountRoot
     只 layout 主树、不接管 overlay 路由（如 Select/Combo 下拉项、DataTable
     内嵌 Select）。
  2. **精确 localX / 自定义坐标**：需投递非节点中心的精确坐标（如 Slider 轨道
     某比例点、Scrollbar 拖拽增量）。
  3. **自定义 native code / 修饰键**：需 `RawInputEvent.NATIVE_NONE` 或特定
     scancode/modifier，harness 固定用 0,0。
  4. **host margin / rootAbsX,Y**：需模拟 GUI 居中偏移的绝对坐标 route
     （如 Scrollbar 的 rootAbsX/Y 参数）。
  5. **多 runtime / host runtime**：单测需多个独立 runtime 实例。
- **裸建时的注释纪律（消除散乱）**：回退裸 `InputFrameBuilder` 的 helper，
  javadoc 首句统一写明**回退原因归属上述哪一类**，格式：
  `// 白盒回退（overlay 树外路由）：harness 不接管 overlay 路由`
  不再各写各的即兴理由。

- 明确：`MockPlatformInputSource` ≡ `InputFrameBuilder` 壳，交互测试不必经它（「绕过桥」非缺陷，澄清历史疑问）。
- 桥内部差分（`LwjglInputSource` + `PlatformStateReader`）属独立桥单测范畴，与本入口正交。

### 7.2 渲染侧顶点断言边界

- `ScenePaintCapture.paintAndCapture` 是渲染出口顶点验证唯一入口
  （layout → paint → `ScenePaintReplayer#replay` → `RecordingRenderBackend`）。
- 断言口径：**变换前 box + transform 分量分离**（与 hit-test 同口径）——box 顶点（`fillRect` 的
  left/top/right/bottom）反映 layout 几何，transform 仅出现在 `pushTransform` 的 7 个浮点分量里，
  二者分离不叠加。
- **不做「变换后顶点」**：变换后的最终像素位置属 GPU 顶点层，纯 JUnit mock backend 不可观测。
  该边界登记为偏离（见偏离登记 `2026-06-26-hit-test` + `DECISION-20260620`）。
- 控件顶点断言按需：仅独特自绘结构才补，默认复用 `SceneBackendContractTest` 8 场景 + L2 坐标不变量。

### 7.3 testkit 速查表

| 你要测什么 | 用哪个 |
|---|---|
| 点 / 移 / 滚在某控件上 + 断交互状态 | `SceneInteractionHarness.click/moveTo/scroll(node)` |
| 控件最终渲染顶点区域 | `ScenePaintCapture.paintAndCapture(root, w)` + `firstFill` / `assertFillBox` |
| 封板状态机 / key 映射 | `MockPlatformInputSource`（input/mock，非 testkit） |

### 7.4 准入判据

跨包复用的搭台 helper 进 testkit；单包私有探针留原文件（如 `LayoutAssertions` 留 `layout/`、
控件结构探针留 `control/`）。
