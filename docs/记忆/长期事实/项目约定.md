# 项目约定

本文件记录项目级、长期有效、且不适合直接塞进 `AGENTS.md` 的具体约定。

## 文档约定

- `docs/AI记忆文档.md` 只作为总导航，不承载阶段流水账、类清单、修复日志或大段项目事实
- `docs/记忆/当前态/` 记录当前阶段、状态、计划和交接，可频繁覆盖
- `docs/记忆/长期事实/` 记录目录结构、架构边界、稳定命令和长期约定
- `docs/记忆/决策/` 记录关键技术取舍和重要边界决定
- `docs/使用文档/` 记录对外接入方式，内容必须与实现一致，不能比实现更乐观
- `docs/开发者文档/errors/` 记录可复现错误和教训，`docs/开发者文档/reviews/` 记录审查结论
- **Markdown 正文不写超长行**：建议每行 ≤ 200 字符，段落正文用换行分句，不把多个要点堆在一行。超长行会导致 Read 工具截断、Grep 难定位、Agent 难以精确引用行号。表格行因 Markdown 语法限制天然为长行，属结构例外，但应控制单元格内内容长度，单格不堆叠过多信息；偏离登记等需长描述的场景优先拆短句换行而非连写

## 协作约定

- 本次迁移只借鉴 Harmes-Rust 的仓库内分层记忆框架，不迁移其 Rust / egui 桌面 Agent 产品架构
- 用户已授权：后续在本项目中，除非用户明确说明“不提交”或“不合并”，Agent 应按任务完成情况自动判断是否提交以及是否合并回主分支，并可自动执行相应 Git 操作
- GitHub release 标题统一使用 tag 名；`.changelogs/<tag>.md` 只负责 release 正文，不负责标题，详细流程见 `docs/开发者文档/发布流程.md`
- 需要具体类、入口和目录位置时，用 Glob/Grep/Read 现查，不在记忆文档维护易过期清单
- 当前 MCP 工具链仅接入 jetbrains（见根目录 `opencode.json`）；编译、构建、测试、文件操作优先走 JetBrains MCP，详见 `AGENTS.md` 第 8 节
- 临时调试记录和一次性试验结论不沉淀到长期记忆
- 发现长期事实已经能稳定归属到使用文档、开发者文档、错误记录或审查记录时，应写回原文档，不复制到总导航

## Subagent 协作与 token 成本约定

- 为降低主 Agent 上下文与 token 成本，优先把可外包的工作派给专职 subagent，主 Agent 聚焦规划、裁决、整合与验证，不做默认实现工人
- 优先派发：代码侦察/定位/"X 在哪"派 explorer（返回压缩上下文，勿让主 Agent 全量读文件）；库用法/官方文档/版本行为/疑难 bug 外部调研派 librarian；架构裁决/方案深评/反复修不好的问题/代码与简化审查派 oracle；明确范围的实现、测试编写、机械改动派 fixer（可按目录拆多个并行）；UI/UX 设计与视觉实现、设计走查派 designer
- 主 Agent 直接做：单文件单点小改（小于 20 行）、信息已在上下文、调度开销明显大于收益的活；以及最终结论整合、跨 lane 冲突裁决、面向用户的中文答复与提问
- 派发时只传路径/行号、不贴整文件（如 `HtmlLikeDocumentWidget.java:495`），独立无依赖的侦察/调研/实现可并行派发，写盘范围不得重叠
- 优先复用交接记录里登记的可复用专家 session（如 `ora-1`/`exp-2`/`fix-2`），省去重复建上下文的 token；复用时必须在 task 的 `task_id` 显式传该 session 别名，仅在正文写"复用"无效
- 真机日志排查（`run/client/logs/fml-client-latest.log`）、批量文件检索一律派 subagent，主 Agent 不亲自全量读
- 与既有纪律衔接：决策点仍优先用中文 question 向用户拍板，subagent 不替用户做架构决定；帧率/真机实测必交用户跑，沙箱无 GUI

## 适合写入本文件的内容

- 项目特有的模块拆分约定
- 特定错误处理口径
- 配置文件组织方式
- 测试目录和命名口径
- 文档命名和示例维护约定

## 不适合写入的内容

- 通用 Git 规范、提交规范、Java 通用规范
- 当前任务状态或阶段计划
- 一次性试验结论
