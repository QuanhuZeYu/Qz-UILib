## 重要纪律（长期沿用）

- 帧率/真机实测必交用户跑，沙箱无 GUI
- scene 新栈改动对照 NORTH_STAR 不变量自检，偏离按《修订纪律》登记
- 完成独立任务后检查是否需更新 `当前态/`、`长期事实/`、`决策/`、`errors/`、`reviews/`
- 子代理任务中断必须用原 task_id 恢复 session 保留进度，不得新开 session 空跑重做；
  但 opencode 重启后原 session 失效，按"调度开销明显大于收益 + 信息已在上下文"
  白名单主 Agent 可亲自做单点排错
- Markdown 正文不写超长行（≤200 字符），表格行结构例外但控制单格长度
- 并行 fixer 只并行写代码，build 统一由主 Agent 串行跑，避免并行 Gradle 竞争 build/ 目录
- 侦察报告的「推测/未验证」项 = 必须补查项；同类修复后全量 grep 兜底确认无残留旧模式
- fixer 只写代码，记忆文档（docs/记忆/）由主 Agent 统一管理
- demo 页是控件真机验证的前提，控件完成后必须建 demo 页接入 hub
- fixer → build → test → review → commit 是硬性链路，build/test 通过不等于 review 通过，
  改动简单不是跳过 review 的借口（ERROR-20260624-skip-review-before-commit.md）
- wrapper 延迟建树（return () -> {}）是 B1 教训硬约束，bind 必须在 Supplier 体内执行才能
  登记到正确 Owner
- token 实际值以 SceneChromeTokens.java 源码为准，不依赖过期文档清单
- oracle 裁决架构方案后，如方案涉及长期可引用的设计决策，建议补写
  `docs/记忆/决策/` 文档沉淀
- I11 逃生舱②扩张纪律：扩之前证明它确实是一类新的权威交互真值，
  而非可以用现有机制表达的东西（B8 验证了 hover 重算不需要扩②）
- 诚实记录 oracle 方案缺口：oracle 不是神谕，发现 bug 诚实记录修复
- **I7 数值求解器边界**：父级数值求解器内多轮迭代（freeze do-while）≠ 多 pass，
  单 pass 约束的是父→子约束下沉次数；判据是「求解器若需要先 layout 子、读子结果、
  再回头改父分配即违反 I7；若全程父级数值迭代、子在收到最终约束后才首次 layout，则守 I7」
- **margin 五处联动纪律**：改 margin 任一处需同步审视 SizingCalculator/
  ConstraintResolver/FlexLayouter/SceneGeometry 四协作者
