### SceneDataTable 设计要点
- 新建 `SceneDataTable`，SceneTable 原样保留为静态只读版
- 数据源 `Signal<List<Row>>`，Row 带 rowId（AtomicLong）+ withCell 同 id 复制（守 I5）
- cell 值用 `Computed.create(() -> currentRow(rows.get(), row).cellValue(col))`
  包裹，bindText 订阅，单 cell 改值只该 cell effect 重跑（守 I7）
- 常驻编辑器范式（复刻 KeyValueMap/SimpleList），无显示/编辑态切换
- 三种列便利构造：Column.text / Column.textInput / Column.select
- CellRenderer 函数式接口 + CellContext（value/onChange/editable）开放自定义扩展
- onChange 提交链：currentRow.withCell → updateRowInList → rows.set（守 I1）
- 行高对齐：cell setCrossAxisAlign(CENTER) + renderer 子项 setPreferredHeight
  (rowHeight - 2*CELL_PADDING)，与 KeyValueMap 范式一致
- 斑马纹：ScenePalette.ROW_BG_EVEN/ODD + rowBg(rowIndex) 便利方法，
  SceneDataTable/SceneTable/SceneScrollHostWidget 3 处统一引用

- 帧率/真机实测必交用户跑，沙箱无 GUI。

- 完成独立任务后检查是否需更新 `当前态/`、`长期事实/`、`决策/`、`errors/`、`reviews/`。
- 子代理任务中断必须用原 task_id 恢复 session 保留进度，不得新开 session 空跑重做。
- Markdown 正文不写超长行（≤200 字符），表格行结构例外但控制单格长度。
- **并行 fixer 只并行写代码，build 统一由主 Agent 串行跑**（ERROR-20260624 教训）。

  同类修复后全量 grep 兜底确认无残留旧模式（ERROR-20260624-scene-scroll 教训）。
