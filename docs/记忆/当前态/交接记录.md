## 给下一个 agent 的治本层施工提示词（方向B 治本）

> ModernConfigTemplateScreen 方向B 治本层续接：保底层已实测达标（~20ms/46fps → ~13ms/75fps），现做治本层消除残留 4.7ms。
>
> **背景（已坐实，勿重复探针）**：第 7 次交接已用外科探针 `BoundsProbe`（已删）一击定位：custom renderer（`DocumentTextAreaControl` 选区/光标层、`DocumentCodeEditorControl` 行号层）在绘制命令**回放期**每帧十余次调 `element.getDocumentBounds()` 取 viewport/text/layer 边界，每次都经 `HtmlLikeDocumentWidget.resolveInteractiveLayoutBox()` 推进整棵动画时间线。保底层 `resolveLayoutBoxForBoundsQuery()` 已让稳态走只读路径不推进时间线，但残留 `interactive` 段仍占单帧 ~4.7ms（35%），残因是只读路径里 `hasLayoutRuntimeValue()` 每次仍 6 次遍历 `animationTimeline.states`。
>
> **治本目标**：让 custom renderer 回放期**完全不调 `getDocumentBounds()`**，所需边界在命令构建期固化进 CUSTOM 命令。预期再压到 ~8ms/帧。
>
> **施工要点（已勘探的关键事实）**：
> 1. CUSTOM 命令构建处：`DocumentPaintEngine.appendCustomCommand(DocumentLayoutBox box, List<DocumentPaintCommand> commands, int offsetX, int offsetY)`（约 466 行）。此处**已持有 box 及 contentLeft/Top/Right/Bottom（含 offset 的文档坐标）**，正是要固化的 viewport/layer 几何来源。命令经 `new DocumentPaintCommand(CUSTOM, element, contentLeft, contentTop, contentRight, contentBottom, 0,0,0, null, customRenderer)` 构造。
> 2. renderer 接口：`DocumentCustomRenderer.render(UiRenderContext context, int contentLeft, int contentTop, int contentRight, int contentBottom)`（仅 5 参，无 bounds）。回放期 `DocumentPaintRenderer` 调它。
> 3. renderer 内部读边界点：`DocumentTextAreaControl.updateRenderedLineMetrics`（约 840 行，调 `contentElement.getDocumentBounds()` + `element.getDocumentBounds()` + `renderLayer.getDocumentBounds()` 三处）；`DocumentCodeEditorControl.updateRenderedViewportMetrics`（约 1049 行）+ `renderGutter`（约 1063 行）。
> 4. **坑**：`DocumentLayoutBox` 无 `getParent()`。renderer 需要的 contentElement（文本内容子元素）/layer（渲染层子元素）的 box 不在当前 box 的祖先链上，须在 `appendCustomCommand`（或其调用栈 `appendBoxCommands` 递归）里从 box 子树定位并固化传入——要改 `appendCustomCommand` 签名/CUSTOM 命令字段，或扩展 `DocumentCustomRenderer` 增加「接收固化 bounds」的入口。
>
> **建议方案**（自行评估更优解）：扩展 CUSTOM 命令携带一个「预解析边界包」（viewport bounds + contentElement bounds + layer bounds，均文档坐标），构建期一次性算好；renderer 改读该包、删除 `getDocumentBounds()` 调用。renderer 与命令的 bounds 约定需新增字段或 payload 对象。
>
> **硬约束**：
> - 任何跳过/合并/重排命令的优化必须保证 clip/paint-context/transform 栈配对（见 `RenderReplayState`），加专门测试。
> - 决策点（方案选择/签名变更/风险）优先用**中文**提问工具确认。
> - 帧率/探针实测必须交用户跑（沙箱无 GUI），让用户跑 `./gradlew.bat --no-configuration-cache runClient21` 打开 ModernConfigTemplateScreen 稳态静置 ~10s，读 `run/client/logs/fml-client-latest.log` 的 `UI 运行统计[ModernConfigTemplateScreen]` 行看 `frame=`/`fps=`。
