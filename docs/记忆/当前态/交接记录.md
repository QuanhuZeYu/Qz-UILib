## 最近一次交接（2026-06-22 第 65 次）—— SceneTable 进入页 POINTER 残留最终修复（已完成，待真机复验）

### 一句话现状
用户真机复测后确认进入 `SceneTable` 页仍保持上一个页面的手型 `POINTER`。最终根因已定位并修复：旧 HTML-like 按钮页把共享宿主真实光标设为 `POINTER`，关闭时未复位；新 `SceneTable` 页期望光标是 `DEFAULT`，但 `cursorSignal` 初值同为 `DEFAULT`，`ReactiveScheduler` 同值去重导致 cursor effect 不重跑，宿主真实状态无法回到默认。现在修复为旧栈 document 关闭边界强制同步 `DEFAULT`，并把共享系统光标宿主抽成中性 `UiCursorHost` / `SystemUiCursorHost`，新栈不再引用旧栈 `Document...` 光标命名。当前仍待用户真机复验。

### 本次改动范围
- **真实根因**：`SceneInputRouter.cursorSignal` 初值为 `DEFAULT`，`SceneTable` 页面无任何非默认 cursor 节点；旧页残留 `POINTER` 后，新页 `cursorSignal.set(DEFAULT)` 被同值去重吸收，不会触发 `backend.apply(DEFAULT)`。
- **宿主同步修复**：新增中性 `UiCursorHost.forceApplyCursor(...)`，`SystemUiCursorHost.forceApplyCursor(...)` 绕过宿主同值短路，专用于宿主原生状态与响应式/宿主缓存漂移时的边界收口。
- **关闭边界复位**：`HtmlLikeDocumentWidget.close()` 在释放 runtime/interaction owner 后强制 `forceApplyCursor(UiCursor.DEFAULT)`；同时补齐 `ForgeConfigTemplateScreen.onGuiClosed()` 与 `UiTestDocumentPageController.onDocumentClosed()` 的 widget close 漏接。
- **命名清理**：真实系统光标实现迁入 `SystemUiCursorHost`，旧 `SystemDocumentCursorHost` 退为 deprecated 兼容入口并委托同一个 `SystemUiCursorHost` 单例；`LwjglCursorBackend` 改用 `UiCursorHost.system()`，新栈与该适配层不再出现 `DocumentCursorHost` / `SystemDocumentCursorHost`。
- **热路径收窄**：已否决 `SceneRuntime.flush()` 每帧 `forceApply` 方案，保留 scene cursor signal→effect 派生模型，仅在旧栈关闭边界做强制宿主同步。
