### 本次结论（按提交时序）
- **根因（explorer 侦察验证）**：
  - 问题1：`SceneSelectHostWidget:87` maxScroll = `contentBox.height - viewportBox.height`，viewport 有 padding14，content 起点在 padTop=14、CLIP 含 paddingBottom=14，滚到底时 content 底部超出 CLIP 底 14px（一个 paddingBottom 被吃）。内层 listbox 用另一套口径（`child.getY()+height` 最大值），隐患。
  - 问题2：`SceneAnchorResolver` 只有 `resolveDown`，`AbstractSceneHostWidget:120` 硬编码调它。trigger 在底部时 `h - trigger.bottom` 很小，listbox 被 maxHeight cap 压成窄缝，无翻转向上逻辑。
- **oracle 裁决**：
  - 问题1 用方案 B 闭式 `max(0, maxChildBottom + padBottom - boxH)`（maxChildBottom=子节点 getY()+getHeight() 最大值含 padTop 偏移），单函数统一外/内层口径，padBottom 显式参与根治。只读 I11 逃生舱①。
  - 问题2 方向 a（先量内容高再定位）I7 安全——per-root layout engine 隔离 + selfConsumesConstraint 闸门，`SceneLayoutEngineTest:618` 反证。否决"始终 UNCONSTRAINED + 手算绘制偏移"替代（破坏 scrollable cap/clip）。关键易错点：两次 layout 宽度必须一致（=triggerBox.width）。向上展开下游 hit-test/clip/paint/dismiss 全透明（anchorY 单一来源红利）。不输出 direction 字段（YAGNI）。
- **commit 1 `faefb192` 统一滚动最大偏移口径**：新增 `SceneGeometry.maxScrollY(SceneNode scrollable)` 闭式；`SceneSelectHostWidget:88` 和 `SceneSelect:235` 改调 helper，删除 `SceneSelect` 私有 maxScrollY；`SceneScrollViewportTest` 补 padding/listbox 零回归/内容不足/box null 测试。
- **commit 2 `e2d436d8` 支持锚定浮层上下择优展开**：`SceneAnchorResolver` 新增 `resolveAuto`（保留 resolveDown），选侧逻辑四分支（向下够→DOWN / 向下不够向上够→UP 紧贴 trigger 上沿 / 两侧不够→选大侧 cap / 相等默认向下）；`AbstractSceneHostWidget.layoutOverlays` 改二次布局（第一次宽=triggerBox.width + UNCONSTRAINED 量 contentH → resolveAuto → 第二次同宽 + cap）；anchorProvider==null 分支保持原样。下游全部未改。`SceneAnchorResolverTest`/`SceneAnchoredOverlayPipelineTest` 补翻转/I7 反证/hit-test/长列表滚动测试。
- **commit 3 `3ca8fe62` 登记与约定**：NORTH_STAR `:247` 补注 maxScrollY 口径统一、`:248` 补注 anchor 上下择优；`docs/记忆/长期事实/项目约定.md` 文档约定新增「Markdown 正文不写超长行」规则（≤200 字符，表格行结构例外）。
