### 实现要点

- TextVerticalAlign{TOP/CENTER/BOTTOM} 默认 CENTER，calculateTextTop 用 lineHeight 行框居中
- TextHorizontalAlign{LEFT/CENTER/RIGHT} 默认 LEFT 零回归，calculateTextLeft 镜像 calculateTextTop
- ascent/descent 链路：GlyphGenerator 取 LineMetrics.getAscent/getDescent → GlyphInfo（atlas 像素）→
  GlyphRuntimeTables 4 个 font-level 标量 → TextLayoutService.getAscent（×fontSizePx/awtCharSize 缩放）→
  SceneTextMeasurer default 方法 → TextMeasureServiceSceneAdapter override
- P0 量纲修复：TextLayoutService 缩放分母从 charSize(9) 改为 awtCharSize(64)，避免 7.1x 偏差
- 量纲 javadoc：GlyphInfo/GlyphRuntimeTables/FontBatchRenderer/FontConfig 字段补 atlas 像素 vs UI 像素注释
- 三线 debug：ScenePaintEngine.DEBUG_TEXT_LAYOUT 静态开关（默认 false），盒中心红 + 行框顶/底黄

### Oracle 研究结论（DECISION-20260625 + 二次裁决）

## 重要纪律（长期沿用）
- 帧率/真机实测必交用户跑，沙箱无 GUI。
- scene 新栈改动对照 NORTH_STAR 不变量自检，偏离按《修订纪律》登记。
- 完成独立任务后检查是否需更新 `当前态/`、`长期事实/`、`决策/`、`errors/`、`reviews/`。
- 子代理任务中断必须用原 task_id 恢复 session 保留进度，不得新开 session 空跑重做。
- Markdown 正文不写超长行（≤200 字符），表格行结构例外但控制单格长度。
- 并行 fixer 只并行写代码，build 统一由主 Agent 串行跑。
- 侦察报告的「推测/未验证」项 = 必须补查项；同类修复后全量 grep 兜底确认无残留旧模式。
- fixer 只写代码，记忆文档（docs/记忆/）由主 Agent 统一管理。
- demo 页是控件真机验证的前提，控件完成后必须建 demo 页接入 hub。
- fixer → build → test → review → commit 是硬性链路，build/test 通过不等于 review 通过，改动简单不是跳过 review 的借口（ERROR-20260624-skip-review-before-commit.md）。
- wrapper 延迟建树（return () -> {}）是 B1 教训硬约束，bind 必须在 Supplier 体内执行才能登记到正确 Owner。
