## 重要纪律（长期沿用）
- 帧率/真机实测必交用户跑，沙箱无 GUI。
- 编译/测试优先走 JetBrains MCP（见 `AGENTS.md` 第 8 节，shell gradle 曾卡死）；仍需 shell 时用 `$env:GRADLE_USER_HOME="D:\.MyApps\.ENV\gradle-home"; ./gradlew.bat ...`（.MyApps 双 p）。**注意：jetbrainsBuildProject 因 gtnhconvention 插件配置阶段需联网拉 GitHub manifest，沙箱 DNS 污染时会失败；编译验证优先用 jetbrainsBuildProject（IDE 内置 classpath 不走该插件配置）。**
- PowerShell 不支持 `&&` 与 heredoc（`<<`）；链式用 `;` 或 `cmd1; if ($?) { cmd2 }`；提交信息必须先 write 到临时文件再 `git commit -F <文件>`。
- 提交/合并用 UTF8 无 BOM；PowerShell 5.1 `Set-Content -Encoding utf8` 会写 BOM，必须用 .NET `[System.IO.File]::WriteAllText($f,$c,(New-Object System.Text.UTF8Encoding $false))` 写无 BOM。
- git 操作必须如实读取 EXIT 码 + 真实 stdout，不预判、不编造命令成功输出。
- LSP 报 `java.lang.Record cannot be resolved` 是 IDE 用 Java8 解析 Jabel record 的固有误报，jetbrainsBuildProject 编译通过即可忽略。
