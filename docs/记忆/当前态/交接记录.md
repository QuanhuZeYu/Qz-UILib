### **5-C 产出契约（5-D 必须遵守）**

- **`ConfigSerializer` 入口**：
  - `toString(ConfigNode, ConfigFormat)` —— 5-A 既有，序列化子树为 JSON/YAML 文本，null 节点返回 `"null"`（JSON）或空串（YAML）。
  - `parse(String, ConfigFormat) throws ConfigException` —— **5-C 新增**，反向解析文本为 ConfigNode；format 为 null 抛 `IllegalArgumentException`，文本语法错误抛 `ConfigException`，调用方需捕获。SearchFilter 不直接用 parse，但若提供「在结果列表预览源码」功能时可调用。
- **`ModernConfigPropertyBindings.createBinding()` 已支持 7 类 templateType + RAW_EDITOR + ENHANCED_PICKER**：5-D 的 SearchFilter **不需要** 再为 binding 加分支；若 SearchFilter 需要「点击结果跳转到对应 binding」的能力，可直接通过 `binding.getDisplayName()` / `binding.getPath()` 与 SearchIndex 的 `SearchEntry` 对齐（path 字段）。
- **`RawEditorPropertyBinding` 关键 API（package-private）**：`getCodeEditor()` 拿控件、`getLastValidNode()` 拿最近合法 ConfigNode、`processUserText(text)` 模拟用户编辑（测试用）、`getRawFormat()` 拿当前 JSON/YAML 格式。
- **`EnhancedPickerPropertyBinding` 关键 API（package-private）**：`getColorControl()` / `getTextControl()` 拿内部控件、`getDraftValue()` 拿当前 draft 字符串、`simulateColorChange(argb)` / `simulateTextChange(text)` 模拟用户编辑（测试用）；static util `formatArgbAsHex(argb)` / `parseHexQuiet(hex)` 为 package-private，5-D 若需要在 SearchFilter 显示颜色预览可复用。
- **5-B 控件契约要点（保留前轮，仍生效）**：
  - `DocumentCodeEditorControl.setText` 是程序化设置，**不触发** changeHandler；`setLanguage` 会触发一次 changeHandler。
  - `DocumentCodeEditorControl.setErrorLines(Set)` / `setError(String)` 仅在实际变化时触发 errorHandler；相同集合重复调用不重复触发。
  - `DocumentCodeEditorControl.getSyntaxResult()` 仅用于高亮，**不能**作为最终语法校验依据；5-C 的 RawEditorPropertyBinding 已通过 `ConfigSerializer.parse` 做最终校验。
  - `DocumentColorPickerControl.setColor/setHex/setRgb` 是程序化设置，**会**触发 changeHandler（与 CodeEditor 不同）。5-C 的 EnhancedPickerPropertyBinding 通过「字段持有 handler + 初始化前置 / restore 临时置 null」规避了初始化误判脏。
  - 两控件 API 全部接受 null/非法输入做兜底，**不抛异常**。
