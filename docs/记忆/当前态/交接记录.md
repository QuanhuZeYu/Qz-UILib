### 主线：滚动条全面修复（commit `0160e4df`）

修复 SceneScrollbar 在 B1/B2/B3/C2/C3/C5/C6 七个维度的缺陷，并引入 layoutDoneSignal 零滞后桥接。

**B1 无溢出隐藏 + 颜色三态中性灰**：
- 无溢出（maxScroll<=0）时 thumb 高=0、颜色透明、column 宽派生为 0（整条滚动条不占布局宽）
- thumb 默认色改为中性灰 idle（`SCROLLBAR_THUMB_IDLE`，Slate-400 @ 40%），不再用 ACCENT
- 三态：idle / hover（`SCROLLBAR_THUMB_HOVER`）/ pressed-drag（`SCROLLBAR_THUMB_DRAG`），pressed 优先于 hover

**B2 拖动 + track page（行业公式等价简化版 + requestPointerCapture）**：
- thumb 拖动按行业公式 `scrollDelta = pointerDelta * maxScroll / trackRange`（`content - viewport = maxScroll` 等价简化）
- DOWN 时 `ctx.requestPointerCapture()` 捕获指针，MOVE/UP 强制投递给 thumb
- track page：点击 thumb 视觉上/下方按 viewportHeight 翻页（手动叠加 transform 算视觉位置，hit tester 用布局位置）
- POINTER_UP / POINTER_CANCEL 均清除 `dragging` 状态 + 释放 capture

**B3 layoutDoneSignal 方案 A（int epoch + host 桥接 + 零滞后路径）**：
- `SceneLayoutEngine` 新增 `layoutEpoch`（int，每次 layout 末尾自增）+ `layoutEpoch()` 读方法
- `AbstractSceneHostWidget` 持 `layoutDoneSignal`（Signal<Integer>）+ `lastSeenLayoutEpoch`，第一次 layout 后比对 epoch 不等则 `set(epoch)`，使订阅方在同帧 flush 内读到最新 LayoutBox
- SceneScrollbar `Props` 新增 `contentChangedSignal`（只读 signal），LAYOUT/COMPOSITE/PAINT bind 订阅它，消除「content 高度变化滞后一帧」缺陷
- 守 I6：layout 层只持 int epoch，signal 在 host 桥接，paint 层不持 signal

**C2 浮点 / C3 DRY / C5 首帧 / C6 ConfigScreen 保留手写**：
- C2：thumb 高用 long 中间量防 vpHeight² 溢出；thumb Y 用浮点中间量防 int 截断
- C3：`computeThumbHeight` 抽公共方法（DRY，LAYOUT bind 2 与 COMPOSITE bind 共用）
- C5：thumb 首帧初始高=0（effect 物化前不闪烁）
- C6：ConfigScreen 滚动条保留手写（Oracle C 评定工厂供新场景用，迁移改动范围大、收益边际，登记后续可选）

### Oracle C 复审结论

**通过，无阻断项**。3 个可选优化（非阻断）：
1. **layoutEpoch 几何变化才自增**（减少干净帧 Computed 重算）—— 登记后续可选不做：当前 Computed 记忆化已过滤 signal 值不变的重算，优化收益边际；改动涉及 layout 引擎核心（需 LayoutResult 携带几何变化标志），漏判一处会导致 scrollbar 不更新，风险高于收益
2. **ConfigScreen 迁移 SceneScrollContainer 工厂**（DRY）—— 登记后续可选不做：Oracle C 已评定保留手写合理，工厂供新场景用
3. **补 POINTER_CANCEL / 拖动结束状态测试** —— 已做（本次 fixer D）

拖动公式等价性确认：`content - viewport = maxScroll`（闭式），行业公式 `pointerDelta * (content - viewport) / (track - thumb)` 与实现 `pointerDelta * maxScroll / trackRange` 等价。
