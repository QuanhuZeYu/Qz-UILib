### 本轮进度详情（5-B 高级编辑 UI 控件层）

- 新增 `DocumentCodeEditorControl`：基于 `DocumentTextAreaControl` 结构复制（不继承内部私有状态），叠加：行号 gutter（左 48px 默认宽，custom renderer 渲染带 padding 的右对齐行号 + 错误行变色）、Tab 插入（默认 4 空格，`setTabSize` 可调）、错误行集合（`setErrorLines(Set<Integer>)` / `setError(String)`，仅在集合或文案实际变化时触发 handler）、基础语法高亮（每行按 token 切 span 染色，KEY/STRING/NUMBER/BOOLEAN/NULL/PUNCT/COMMENT/PLAIN 8 类配色可调）。
- 新增 `DocumentCodeEditorSyntaxSupport`：同包，定义 `Language` 枚举（JSON/YAML/PLAIN）、`TokenKind`、`SyntaxToken`、`SyntaxResult`、`SyntaxSupport` 接口，内置 JSON/YAML/PLAIN 三种轻量词法实现。**核心合约：分析失败返回空集合，不抛异常**（构造方包了 try/catch 防御）；扫描器在 `readWord` 返回 0 长度时强制消费 1 字符，避免 column 不前进导致死循环。
- 新增事件三元组与 handler：`DocumentCodeEditorChangeEvent` + `DocumentCodeEditorChangeHandler`（文本/语言变化）、`DocumentCodeEditorErrorUpdateEvent` + `DocumentCodeEditorErrorHandler`（错误行集合/文案变化）。事件构造器 package-private，仅由控件触发。
- 新增 `DocumentColorPickerControl`：组合使用 `DocumentTextInputControl`（HEX + R/G/B 三通道），叠加色块预览（custom renderer fillRect）与错误提示文本。HEX 解析接受 `#RRGGBB` / `#AARRGGBB`（# 可选，不区分大小写）；RGB 通道 0-255；HEX 与 RGB 双向同步（输入框 changeHandler 互推）；非法输入显示错误文案但 **不抛异常**，ARGB 保留旧值。
- 新增 `DocumentColorPickerChangeEvent/Handler`（颜色变化）、`DocumentColorPickerConfirmEvent/Handler`（按 RETURN 或 `commitNow()` 触发；事件带 `isValid` 标志）。
- 测试：`DocumentCodeEditorControlTest` 18 项（Tab 插入默认/自定义/只读、行号计算、错误行集合去重/归一化、JSON 合法/未闭合字符串/裸单词错误行、YAML key/comment、PLAIN 空分析、changeHandler 在 setLanguage/textInput 触发而 setText 不触发、setLanguage null 兜底）；`DocumentColorPickerControlTest` 13 项（初始颜色、setColor 同步 HEX/RGB、6 位/8 位/无# HEX、非法 HEX 错误、setRgb 同步 HEX、超界 RGB 错误、change/confirm 事件、isValid 标志）。

### 重要约束（保留前轮 + 本轮补充）

- 入口检测的是 `club.heiqi.config` 模块能力是否存在，不是检测配置文件是否存在。
- `ModConfigGui` 不直接引用 `club.heiqi.config` 类型；现代页相关类型只在 `ModernConfigBridge` 之后加载。
- 不做 Forge 到 config 模块迁移工具，不在页面内添加迁移按钮。
- Forge 回退不需要理解复杂 config 模型；接入方自己决定复杂结构如何在 Forge cfg 下兼容，推荐 JSON 字符串属性。
- UI 风格沿用当前 Forge 配置模板页，不另起视觉体系。
- `MutableConfig` 裸值本身不包含 schema；choice、默认值、数值范围等 UI 语义依赖 `ModernConfigTemplateScreen.FieldSpec`。
- Batch 5 拆 4 个接力阶段（详见 `docs/记忆/当前态/Batch5接力计划.md`），每阶段独立提交、独立交接，**不要跨阶段做**。
- 5-A 已完成：ConfigSerializer、ModernConfigSearchIndex、TypeInference 扩展、formatType 标签。
- **5-B 已完成（本轮）**：DocumentCodeEditorControl + SyntaxSupport + 事件三元组、DocumentColorPickerControl + 事件三元组，配套 31 项测试。
- `ModernConfigSearchIndex` 不参与 draft/dirty；只读 rootSnapshot + 通过 binding.isDirty() 查询脏标记。
- `infer` 三参重载保留向后兼容；需要 rawFormat 正确时调用方应传 `config.getFormat()` 作为 fallbackFormat（5-C 阶段 createBinding 会用到）。
- `ModernConfigPropertyBindings.createBinding()` 当前**未**对 RAW_EDITOR/ENHANCED_PICKER 分支；5-C 必须加 binding 类与工厂分支。
- **5-B 控件契约要点（5-C 必须遵守）**：
  - `DocumentCodeEditorControl.setText` 是程序化设置，**不触发** `DocumentCodeEditorChangeHandler`；binding 想监听用户编辑请直接 `setChangeHandler`。
  - `DocumentCodeEditorControl.setLanguage(Language.JSON/YAML/PLAIN)` 会触发一次 `DocumentCodeEditorChangeHandler`。
  - `DocumentCodeEditorControl.setErrorLines(Set<Integer>)` / `setError(String)` 仅在集合或文案实际变化时触发 `DocumentCodeEditorErrorHandler`；相同集合重复调用不重复触发，binding 不需要自己做去重。
  - `DocumentCodeEditorControl.getSyntaxResult()` 返回最近一次轻量词法分析结果（仅用于高亮与粗略错误行提示），**不能**作为最终语法校验依据；5-C 必须用 `ConfigSerializer` / 真正的 JSON/YAML 解析器做最终校验。
  - `DocumentColorPickerControl.setColor/setHex/setRgb` 是程序化设置，**会**触发 `DocumentColorPickerChangeHandler`（与 CodeEditor 不同，因为颜色是单一标量，programmatic 设置也视为变更）；binding 监听用户编辑请直接 `setChangeHandler`。
  - `DocumentColorPickerControl.commitNow()` 主动触发 `DocumentColorPickerConfirmHandler`；用户在任一输入框按 RETURN 也会触发。事件 `isValid=false` 时表示当前 HEX/RGB 输入非法，binding 应保留旧值不写回 draft。
  - 两控件 API 全部接受 null/非法输入做兜底，**不抛异常**；binding 不需要做防御性 try/catch。
