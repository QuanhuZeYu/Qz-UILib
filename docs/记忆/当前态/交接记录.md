### 根因与修复要点

- **根因**：ink 子区 UV 精确贴字符像素 + shader `fontF.frag:51-54,23-25` uvBounds 硬墙把 ink 子区外采样判 0
  + padding 区纯透明无过渡带，mipmap 高 mip 级 texel 跨 slot 混合，边缘 AA 被 smoothstep 阈值化放大成硬边
- **方案①**（FontBatchRenderer）：`INK_BLEED=1.0F`，`resolveGlyphQuadMetrics` UV 四边各外扩 `INK_BLEED/texSize`，
  几何 `quadX/Y -= INK_BLEED*glyphScale`、`renderW/H += 2*INK_BLEED*glyphScale`，uvBounds 自动跟随
- **方案②**（GlyphGenerator）：`INK_PADDING` 6→8，新增 `bakeInkEdgeFeather` 在 ink 子区外 ≤1 像素 padding 圈
  烘焙半透明白色（alpha=127 单层羽化），彩色字形跳过避免 emoji 白边
- **不改动**：GlyphInfo/GlyphRuntimeTables/DefaultFontRendererAdapter，度量链路零破坏

## 重要纪律（长期沿用）
- 帧率/真机实测必交用户跑，沙箱无 GUI。
- scene 新栈改动对照 NORTH_STAR 不变量自检，偏离按《修订纪律》登记。
- 完成独立任务后检查是否需更新 `当前态/`、`长期事实/`、`决策/`、`errors/`、`reviews/`。
- 子代理任务中断必须用原 task_id 恢复 session 保留进度，不得新开 session 空跑重做。
- Markdown 正文不写超长行（≤200 字符），表格行结构例外但控制单格长度。
- 并行 fixer 只并行写代码，build 统一由主 Agent 串行跑。
- 侦察报告的「推测/未验证」项 = 必须补查项；同类修复后全量 grep 兜底确认无残留旧模式。
- fixer 只写代码，记忆文档（docs/记忆/）由主 Agent 统一管理。
- demo 页是控件真机验证的前提，控件完成后必须建 demo 页接入 hub。
- fixer → build → test → review → commit 是硬性链路，build/test 通过不等于 review 通过，改动简单不是跳过 review 的借口（ERROR-20260624-skip-review-before-commit.md）。
