### 主线：坐标系错位系统性修复（对齐 Flutter 三件套）

**问题**：BUG1 滚动条两次回归后，复查发现坐标系错位是系统性问题，不止 scrollbar——slider/textInput/textArea 同款 `pointerX/Y`（raw 屏幕绝对，含 rootAbs）与 `absoluteBox(0,0)`（host 局部）混比，rootAbs≠0 时点击定位 / 拖动提交值偏移。根因不止在控件层：SceneEvent 注释误导（标"不叠加 rootAbs"但实际含 rootAbs），多个控件作者按注释写混比代码。单测默认 rootAbs=0,0 假绿。

**行业调研**（Librarian）：Flutter/Compose/Android View/Web DOM/SwiftUI 五大框架 handler 默认拿节点局部坐标，框架自动注入，业务 handler 几乎不手动减 rootAbs。

**决策**：对齐 Flutter 三件套（raw/host/local 三层 + 框架自动注入 local），分 3 轮落地。决策文档：`docs/记忆/决策/DECISION-20260630-coordinate-system-flutter-alignment.md`。

**第 1 轮范围**（commit `0da919b6`）：
- SceneEvent 主树新增 `hostPointerX/Y` 字段（= `pointerX/Y - rootAbsX/Y`，host 局部，与 `absoluteBox` 同系）
- I12 不变量写入 NORTH_STAR：坐标系三层 + handler 默认 local + raw 与 `absoluteBox(0,0)` 禁止混比
- 3 控件同系修正：
  - `SceneTextInput`：点击定位改 `hostPointerX` 与 `absoluteBox` 同系
  - `SceneSlider`：拖动提交值改 `hostPointerX` 与 `absoluteBox` 同系
  - `SceneTextAreaPrimitive`：点击行号 + 行内 X 改 `hostPointerX/Y` 与 `absoluteBox` 同系
- SceneEvent 注释修正：`pointerX/Y` 明确标"屏幕绝对、含 rootAbs"，删除"不叠加 rootAbs"误导
- 受影响文件：`SceneEvent` / `SceneInputRouter` / `SceneTextInput` / `SceneSlider` / `SceneTextAreaPrimitive` / `NORTH_STAR.md`

**fixer D 收尾**（本次 commit 待提交）：
- TextArea absoluteBox 合并小优化（Oracle C 非阻断建议）：`SceneTextAreaPrimitive.java:238-248` 两次 `SceneGeometry.absoluteBox(content, 0, 0)` 合并为一次局部变量 `contentBox` 复用
