### 本会话改动（4 项）

**1. 接口 Javadoc 平台耦合修正**
`PlatformStateReader.java` 的 `dWheelDelta()` Javadoc 原直接写"对应 LWJGL `Mouse.getDWheel()`"，把 LWJGL 名字写进了适配层接口契约。已弱化为"对应平台原生滚轮增量 API（如 LWJGL `Mouse.getDWheel()`）"，并把"具体平台 API 名见实现类 Javadoc"写入接口，LWJGL 名字只保留在 `LwjglStateReader.java` 实现类 Javadoc（合适）。

**2. commit message 表述精确化（以注释形式补在代码层）**
历史 commit 不改。在 `LwjglInputSource.java` 滚轮段补一段注释 `★路径互斥精确语义`，精确说明：路径 1 有效（scrollDiff != 0）时不触发路径 2 的破坏性读取，避免在滚轮活跃帧偷走旧层 UiInputService 的 getDWheel 增量——旧层若同帧调 Mouse.next()/getEventDWheel() 消费同一队列，路径 2 的 getDWheel() 会清零内部计数导致旧层读 0 丢事件。

**3. 诊断日志技术债登记**
4 处诊断日志（均带 `TODO(bug1-scroll-cleanup)` 标记）已登记为跟踪项，避免被遗忘：
- `LwjglInputSource.java` 滚轮差分段 `[scroll-diag]`
- `SceneInputRouter.java` SCROLL 路由段 `[scroll-route]`
- `SceneScrolls.java` handler 段 `[scroll-handler]`
- `LwjglStateReader.java` 反射取值最前端 `[scroll-probe]`

**4. 路径 2 触发阈值边缘修正**
`LwjglInputSource.java` 滚轮段阈值由 `Math.abs(scrollDiff) > 0.0001` 改为 `scrollDiff != 0`（即 `> 0` 语义）。原阈值下若 totalScrollAmount 正常更新但单帧增量落在 `(0, 0.0001]` 区间，会误走路径 2 清零 getDWheel。改后任何非零差分都走路径 1，只在累计值完全无更新时才 fallback 到路径 2。诊断日志的 path 判定同步改为 `scrollDiff != 0`。
