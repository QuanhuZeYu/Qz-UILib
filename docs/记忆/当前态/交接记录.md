### Bug2「数字小键盘无法输入」根因（已确定）
对比 `SceneDemoScreen`(Demo1，正确范例) 与 `SceneControlsDemoScreen`(Demo2)：Demo1 在 `initGui` 注册 `SceneLwjgl3ifyTextBridge` 并 `setExternalTextMode(true)`、`onGuiClosed` 注销；**Demo2 完全缺这套接线**（无 textBridge 字段、无 initGui/onGuiClosed override），故 `LwjglInputSource.externalTextMode` 恒为 false，文本退化到 MC `keyTyped` char 降级路径。GTNH lwjgl3ify(LWJGL3/GLFW) 下该路径对小键盘数字键拿不到 typedChar（为 0），故小键盘输不进、主键盘正常（吻合用户描述）。注：`SceneControlsHostWidget` 的 onKeyTyped/pushText/setExternalTextMode 三方法已由 905461d0 补好，只差 demo 壳没接线驱动。
**修复方案**：`SceneControlsDemoScreen` 比照 `SceneDemoScreen` 加 textBridge 字段 + getHostWidget() 强转 + initGui(register→setExternalTextMode(true)，失败降级 false) + onGuiClosed(unregister + setExternalTextMode(false))。

### Bug1「光标位置严重不对」根因（已确定）
`SceneTextInput.displayText()`（:275-291）在 value 为空时返回 placeholder，textNode 显示「请输入名称/密码」；而 caret 是 textNode 的 ROW 兄弟、恒排在其右侧（档位 A 设计：caret 位置 = f(value 长度)，靠 ROW 自然定位到文本末尾，见类注释）。→ **聚焦空输入框时光标落在 placeholder 文字末尾而非开头**（中文 placeholder 偏移约 60px，故"严重不对"）；一旦输入真实值 placeholder 消失、caret 回到真实文本末尾即正常。已排除 scaleFactor 度量/渲染不一致——`UiRenderContext` 的 `UI_TEXT_SCALE=2.0` 是旧栈 Document 控件同款 measure+render 组合，已被 VIS-CTRL 系列测试覆盖、一致。
**修复方案**：`displayText` 增 focused 参数——聚焦时 value 空返回空串（不显示 placeholder，caret 回开头）、失焦时 value 空才返回 placeholder（灰）；其 LAYOUT bind（:177-179）增加 `is.focused().get()` 依赖。符合标准文本框行为、改动最小，不破坏「caret 靠 ROW 自然定位」哲学。

### 渲染资源生命周期（关键，曾踩 FBO 泄漏坑）
- **背景**：旧 scene demo 借旧栈 `UiScreenHostSession.render` 完整管线（含离屏 FBO + 跨帧复用 compositor）渲染。新壳若每帧 `new UiRenderContext(5参)` → 内部每帧 new `PaintContextCompositor`，opacity 帧（`0<opacity<0.999` 且区域有效）会 `borrowLayer→new UiRenderTarget()` 借 FBO，而被 GC 的 compositor 不释放 GL 句柄 → **opacity 帧每帧泄漏 FBO**。
- **修复（资源放 GuiScreen 侧）**：`McScreenBridge` 跨帧 final 字段持有 `paintContextCompositor` + `mainLayerSnapshotService`；`drawScreen` 用 **7 参构造** `new UiRenderContext(w,h,mouseX,mouseY,partialTicks, compositor, snapshotService)`，render 前 `beginFrame()` 配对、`finally` 内逆序 `finishFrame()`（snapshot 先收 compositor 后收）；`onGuiClosed` 嵌套 finally 确保两资源 `close()` 都执行（即使 dispose 抛异常也释放 GL 句柄）。
- **诚实标注**：FBO 泄漏修复是源码推理确认的资源生命周期正确性，**opacity 帧真机视觉一致性未验证（沙箱无 GUI）**。transform 走纯 GL matrix（pushTransform 直接 glPushMatrix）不依赖注入服务，新壳下正确。
