### 重要约束（保留前轮 + 本轮补充）

- 入口检测的是 `club.heiqi.config` 模块能力是否存在，不是检测配置文件是否存在。
- `ModConfigGui` 不直接引用 `club.heiqi.config` 类型；现代页相关类型只在 `ModernConfigBridge` 之后加载。
- 不做 Forge 到 config 模块迁移工具，不在页面内添加迁移按钮。
- Forge 回退不需要理解复杂 config 模型；接入方自己决定复杂结构如何在 Forge cfg 下兼容，推荐 JSON 字符串属性。
- UI 风格沿用当前 Forge 配置模板页，不另起视觉体系。
- `MutableConfig` 裸值本身不包含 schema；choice、默认值、数值范围等 UI 语义依赖 `ModernConfigTemplateScreen.FieldSpec`。
- `ModernConfigSearchIndex` 不参与 draft/dirty；只读 rootSnapshot + 通过 binding.isDirty() 查询脏标记，支持 refreshDirtyMarkers/rebuild。
- `infer` 三参重载保留向后兼容；需要 rawFormat 正确时调用方应传 `config.getFormat()` 作为 fallbackFormat（5-C 工厂实际未传 fallbackFormat，raw hint 默认走 JSON）。

### **5-D 产出契约（Batch 6 必须遵守）**

- **`ModernConfigSearchFilter` 关键 API（public）**：`applyQuery(String)`、`applyTypeFilter(Set<TemplateCategory>)`（null/空=不限，支持多选）、`applyModifiedOnly(boolean)`、`refresh()`、`getResults()`、`getResultCount()`、`getQuery()`、`getTypeFilter()`、`isModifiedOnly()`、`jumpTo(int)`（越界忽略）、`getElement()`、`setSelectedCategory(TemplateCategory)`。构造：`(UiDocument, ModernConfigSearchIndex, Consumer<String> onJumpToPath)`。**纯 JVM 可构造**（不依赖 Minecraft/GuiScreen），所有控件创建在构造内、查询逻辑在 apply* 纯方法。
- **`ModernConfigDocumentBuilder` 构造签名已变**：末参新增 `ModernConfigSearchFilter searchFilter`（可 null）；`appendSearchFilter(ElementNode parent, ModernConfigSearchFilter filter)` 在 build 流程的 toolbar 之后、字段卡片之前调用。
- **`ModernConfigTemplateScreen` 集成点**：`document` / `searchIndex` / `searchFilter` 为 private final 字段；`changeListener` 统一走 `onDraftChangedInternal()`（Batch 6 若再加草稿副作用，挂在这里）；`collectIndexBindings()` 展开 `ModernNestedCategoryBinding.resolveDescendantBindings("")` 以覆盖嵌套子项脏状态；`onJumpToPath` 用 `data-modern-config-path` 属性 + `documentWidget.requestScrollIntoView` 定位。
- **TemplateType 共 14 个枚举值**：STRING/NUMBER/BOOLEAN/CHOICE/LONG_TEXT/SIMPLE_LIST/TABLE/OBJECT/KEY_VALUE_MAP/PRESET_SELECTOR/RAW_EDITOR/ENHANCED_PICKER 为 12 个用户入口；NULL/READ_ONLY 为系统 fallback。
- **控件契约（保留前轮，仍生效）**：`DocumentCodeEditorControl.setText` 程序化不触发 changeHandler，`setLanguage` 触发一次；`DocumentColorPickerControl.setColor/setHex/setRgb` 程序化**会**触发 changeHandler；两控件 API 接受 null/非法输入做兜底、不抛异常；`DocumentToggleSwitchControl.setToggled` 程序化不触发 handler。
- **ConfigSerializer 入口**：`toString(ConfigNode, ConfigFormat)`（序列化，null 节点→"null"/空串）、`parse(String, ConfigFormat) throws ConfigException`（反向解析，format null 抛 IllegalArgumentException）。
