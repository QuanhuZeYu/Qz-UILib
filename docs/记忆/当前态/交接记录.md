### 主线：WidgetSpec 方案 D（commit `9eab9baa`）

解决 `NumberFieldRenderer` slider `step=1.0` 写死导致小数字段无法用 slider 表达的遗留问题。

**设计**：
- 新增 `WidgetSpec` 接口（原计划 Java 17 密封接口，因 Jabel desugar 不支持 `sealed` 关键字，退为普通接口 + record 实现，语义等价）
- `SliderSpec(double step)`：record，`step=0` 连续不量化，`step>0` 量化步进，`step<0` 构造抛异常
- `InputSpec`：record，单例 `INSTANCE`
- `FieldSpec` 新增第 7 字段 `WidgetSpec widget`（null = 默认 input）
- `FieldSpec.Builder` 新增 `.slider()` / `.slider(double step)` / `.input()` 便捷方法

**渲染层分发**：`NumberFieldRenderer.render` 按 `spec.widget()` 分发：
- `widget=null` 或 `InputSpec` → input（有 range 不再自动 slider）
- `widget=SliderSpec` → slider，step 由 `SliderSpec.step()` 透传

**用户拍板决策**：
- widget 声明载体：WidgetSpec 接口（Jabel 限制退为普通接口，非密封）
- widget=null 默认：input（有 range 不再自动 slider）
- drawStage* 三字段(0,1000)：input（不写 `.slider()`）

**受影响字段**（`QzUiLibModernSchema`）：见 `docs/记忆/决策/DECISION-20260630-number-field-step-integer-quantization.md` 第 2 节表。

### Oracle C 复审结论

**通过，无阻断项**。4 项建议项处理如下：

1. **注释语义修正**（已做）：
   - `SliderSpec.java:7`：`step <= 0 表示连续不量化` → `step=0 表示连续不量化，step>0 表示量化步进`（消除与构造器拒绝负 step 的矛盾）
   - `FieldSpec.java:175`：`≤0 表示连续不量化，不能为负` → `step=0 表示连续不量化，step>0 表示量化步进，不能为负`
2. **DECISION 标题修正**（已做）：`docs/记忆/决策/DECISION-20260630-number-field-step-integer-quantization.md:3` `WidgetSpec 密封接口` → `WidgetSpec 接口`
3. **测试区分力增强**（已做）：`NumberFieldRendererWidgetTest` 的 `findTextInputRoot`/`findControlRoot` 原实现相同（都取 card 倒数第二个子节点），无法区分 slider ROW 与 TextInput。本次按控件 root 子节点数区分：
   - slider control root（ROW）：2 子 = [sliderRoot, readout]
   - input control root（SceneTextInputPrimitive root，ROW）：3 子 = [prefixText, caret, suffixText]
   - `findTextInputRoot` 要求控件 root 子节点数 = 3，`findControlRoot` 要求 = 2，两者有真区分力
4. **step 透传渲染层测试**（低优先，跳过）：需暴露 SceneSlider.Props 才能断言 step 实际值，实现成本高，本次跳过
