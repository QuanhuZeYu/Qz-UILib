## ink mipmap 边缘硬裁边修复（已完成，真机验收通过）

- 已合回 `4.0`（merge commit），分支 `fix/ink-mipmap-bleed` 已清理
- 根因：ink 子区 UV 精确贴字符 + shader `fontF.frag` uvBounds 硬墙 + padding 纯透明无过渡带，
  mipmap 降采样下边缘 AA 被 smoothstep 阈值化放大成硬边
- 最终方案：仅保留方案①（UV/几何/uvBounds 协同外扩 `INK_BLEED=1.0`）+ `INK_PADDING` 6→8
- 曾试方案②（烘焙 alpha 羽化）但真机发现所有字符出现白边，已回退删除
- 原理：不烘焙时 padding 纯透明，mipmap 降采样时 ink 边缘 AA 像素自然渗透到 padding 生成
  半透明 texel，UV 外扩 + uvBounds 放宽让 shader 采到这些渗透 texel，边缘过渡自然且无白边
- GlyphInfo/GlyphRuntimeTables/DefaultFontRendererAdapter 零改动，度量链路未破坏

## I6 + B2 技术债清理（2026-06-25，已合回 4.0）

### I6：切断 scene replayer 对 ui.style 反向依赖
- **根因**：`UiRenderBackend.drawSurface` 第 7 参类型是 `ui.style` 包的 `ResolvedCornerRadii`，强制 replayer import ui.style
- **方案**：第 7 参降级为 `int cornerRadius`（replayer 本就只传 uniform 单值，零信息损失）；render 层 `UiRenderContext` 保留 `ResolvedCornerRadii` 重载供 backdrop-filter 等需要分角圆角的调用方使用
- **守线增强**：`ScenePackageIsolationTest` 新增 ui.style 禁令正则，覆盖 layout/paint/node/overlay 四目录 + scene 顶层 + replayer import 行专项
- commit `c9c53208`，reviewer 审核通过，scene 层零 ui.style import 残留

### B2：TextArea O(N²) 文本几何消除
- **问题**：SceneTextAreaPrimitive 行定位方法每次调 splitLines 全量切分，N 行 × N 次调用 = O(N²)
- **oracle 裁决**：选方案 B(R1) scene 内自建轻量缓存；否决整包复用旧栈 TextLayoutEngine（撞 I6/I10，scene 核心严禁认识 ui.text）和混合复用单行 PrefixWidthCache（单行 cache 不降单次复杂度）
- **关键发现**：scene `measureWidth` 含 `ceil`+`round` 双取整，"逐码点 UI 宽相加"会漂移，且 FixedTextMeasurer 线性导致测试假绿——绝不能用逐码点相加替代整前缀测量
- **Step1**（`ae263575`）：实例级 `LineStructureCache`（int[] lineStartCp/lineLenCp + lines，失效键 value.equals），7 个行定位方法改查表，O(N²)→O(N)。新增 6 个边界测试
- **Step2**（`7b7b1722`）：实例级 `ClickPrefixWidthCache`（失效键三元组：行文本+fontSize+textMeasureEpoch），点击路径跨帧复用整前缀宽数组。buildPrefixWidths 函数体禁改（保像素一致）。新增 1 个缓存复用/失效测试
