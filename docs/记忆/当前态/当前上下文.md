## 三批真机缺陷修复（均已完成，部分待真机复验）

### 第一批：下拉不显示 / 范围太大 / resize 不更新
- `590cee56` SceneSelectHostWidget 补全 overlay 布局与绘制管线
- `aaf7c661` 抽取 AbstractSceneHostWidget 统一 render pipeline（净减 929 行）
- `86f69d81` listbox 高度 shrink-to-fit 并补 scrollable 分支3 maxHeight cap
- `9d588cb5` 补 selfConsumesConstraint I8 缺口并更新偏离登记
- `b444b883` 修复 I7 叶节点宽度约束闸门缺口导致 resize 不更新

### 第二批：滚动后 hit/绘制不跟随 / 滚出不 dismiss
根因：`scrollOffsetY` 是 paint-only 偏移，hit-test 与 `absoluteBox` 只读 LayoutBox 对滚动零感知。
- `a62da1d6` 对齐滚动偏移几何探针：抽 `SceneGeometry.childYBase(parent, parentAbsY)` 单层注入原子
  （判 `parent.isScrollable()` 而非 self），paint/hit-test/absoluteBox 三方共用同一原子定义。
- `7c814926` 裁剪滚动视口命中区域：hit-test 新增 clip bounds 递归参数传递（null=无裁剪），
  进入 scrollable 子树用其 LayoutBox 绝对盒作 clip，嵌套取交集，类保持无状态。
- `18143ecf` 关闭不可见锚点浮层：`dismissOverlaysWithInvisibleAnchor` 独立步骤，
  trigger 滚出所有 scrollable 祖先视口零交集时 `entry.requestDismiss()` 走 signal（I11 逃生舱②）。
  有交集即保持防半遮闪关。单帧绘制延迟可接受不特判。

### 第三批：矮窗滚不到底 / 底部下拉翻转
根因1：maxScroll 少算 viewport 上下 padding。根因2：resolver 只有 resolveDown 无翻转。
- `faefb192` 统一滚动最大偏移口径：新增 `SceneGeometry.maxScrollY(scrollable)` 闭式
  `max(0, maxChildBottom + padBottom - boxH)`，外层 viewport 与内层 listbox 同一调用。
- `e2d436d8` 支持锚定浮层上下择优展开：`SceneAnchorResolver` 新增 `resolveAuto`
  （选侧四分支：向下够→DOWN / 向下不够向上够→UP 紧贴 trigger 上沿 /
  两侧不够→选大侧 cap / 相等默认向下）；`layoutOverlays` 改二次布局
  （第一次宽=triggerBox.width + UNCONSTRAINED 量 contentH → resolveAuto → 第二次同宽 + cap）。
  两次宽度三次同源 `triggerBox.getWidth()`。下游 hit-test/clip/paint/dismiss 全部未改。
- `3ca8fe62` NORTH_STAR `:247` 补注 maxScrollY 口径统一、`:248` 补注 anchor 上下择优；
  `docs/记忆/长期事实/项目约定.md` 文档约定新增「Markdown 正文不写超长行」规则。

## SceneTable 行内编辑侦察结论（2026-06-24，explorer 产出）

为「TABLE 行内编辑」任务做决策地基。SceneTable 是 **243 行纯静态工具类**
（`SceneTable.java`），业务零依赖（仅 demo/test 引用），改造对外零破坏面。

**三个核心包袱（阻碍行内编辑，需推翻）**：
- 数据静态不可变 `List<List<String>>`（`SceneTable.java:99-101`）→ 需响应式数据源
- 裸 for 建行无 key（`:156-159`）→ 违 I5，须迁 forEach+keyed
- `createCell` 写死 label（`:211-226`）→ 需可插拔编辑器

**可直接复用骨架**：viewport/content 滚动管线（signal-first 合规，`:144-177`）、
固定列宽/行高 LayoutBox 对齐（`SceneTableTest.java:134` 已验证）、clipChildren 裁剪。

**行内编辑范式已存在**：`SceneKeyValueMap.java:650` 已用
forEach+keyed+SceneSelect/Segmented 行内编辑，SceneTable 落后于此范式。
`SceneTextInput`（`:122`）、`SceneSelect`（`:138`）可直接复用为编辑器。

**关键风险**：
- I5/I7 硬约束：行须迁 forEach+keyed，单元格改值须走 bindText 局部失效
- overlay+表格滚动 anchor 联动：SceneSelect 作下拉编辑器时 viewport 可滚，
  anchor 跟随是已知风险区（NORTH_STAR `:371-375` 记载）
- 行数膨胀：预计 400-600+（参照 KeyValueMap 650 行），宜按 registry/builder/cell 拆分

**待决策（需 oracle 裁决 + 用户拍板）**：扩展 SceneTable vs 新建 SceneDataTable。
explorer 工程判断：扩展≈重写 70% 核心，倾向新建 SceneDataTable，
现 SceneTable 留作轻量静态只读版。未经 oracle 复核。
