# 当前计划

本文件记录“接下来做什么”，只保留短期内真正会执行的步骤。

## 当前计划

1. **ModernConfig 配置页面系统性性能优化**（已完成核心项，已合并回 `4.0`）：
   - ✅ P0：防抖草稿变更回调、搜索索引增量更新、列表视图差量更新
   - ✅ P1：分批渐进式 DOM 构建（每批 10 卡片）、延迟初始化搜索索引
   - ✅ P2：Binding 生命周期协议（canReuse/reset/dispose）
   - ⏸️ P1-3 嵌套分类延迟加载（风险高，暂不实施）
   - ⏸️ P2-1 虚拟化字段列表（需 DOM 结构重构，暂不实施）
   - 如需后续实施 P1-3/P2-1，从 `4.0` 创建新分支 `perf/modern-config-optimization-phase2`
2. 继续保持可选 `club.heiqi.config` 模块主用入口，检测不到模块时回退现有 `ForgeConfigTemplateScreen`。
3. 不做 Forge 到 config 模块的配置迁移；复杂结构的 Forge 回退兼容由接入方自行设计，建议用 JSON 字符串 cfg 承载。
4. 若 `ModernConfigTemplateScreen.java` 接近 1000 行或 `FieldSpec` 被包外模块直接引用，可重新评估拆分（当前不拆分决策见 `docs/记忆/决策/DECISION-20260614-modern-config-template-screen-no-split.md`）。

## 每步完成标准

- 总导航保持精简，不重新堆积长期事实和进度流水账
- 长期事实只记录中长期仍有效的目录、边界、命令和项目约定
- 当前态可频繁覆盖，但必须服务下一位接手者快速恢复现场
- 决策记录写清背景、候选方案、最终选择、影响范围和后续注意事项
- 验证命令和运行前提以 `docs/记忆/长期事实/稳定命令.md` 为准
- 每批 Modern Config 施工至少通过 `git diff --check`；涉及生产 Java 代码时至少补相关测试或运行 `compileJava`
- 本地验证命令和结果只记录在协作交接、提交说明或开发者文档中，不写入远端 GitHub Release 正文
