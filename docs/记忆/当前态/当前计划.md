# 当前计划

本文件记录“接下来做什么”，只保留短期内真正会执行的步骤。

## 当前计划

1. 当前从 `4.0` 创建 `release/4.2.4`，准备 4.2.4 小版本发布。
2. 4.2.4 版本号由最终 Git tag 推导；仓库内发布准备以 `.changelogs/4.2.4.md` 作为 Release 正文覆盖文件。
3. 本地发布准备完成后，下一步推送 `release/4.2.4` 分支与 `4.2.4` tag，触发 Release workflow。
4. 发布后检查 GitHub Release 标题是否为 `4.2.4`，正文是否来自 `.changelogs/4.2.4.md`。

## 每步完成标准

- 总导航保持精简，不重新堆积长期事实和进度流水账
- 长期事实只记录中长期仍有效的目录、边界、命令和项目约定
- 当前态可频繁覆盖，但必须服务下一位接手者快速恢复现场
- 决策记录写清背景、候选方案、最终选择、影响范围和后续注意事项
- 验证命令和运行前提以 `docs/记忆/长期事实/稳定命令.md` 为准
- 发布说明必须在 tag 指向提交中存在，且文件名与 tag 完全一致
- 本地验证命令和结果只记录在协作交接、提交说明或开发者文档中，不写入远端 GitHub Release 正文

## 更新规则

- 只保留 3 到 7 个短期有效步骤
- 计划变化时直接改写，不保留历史版本
