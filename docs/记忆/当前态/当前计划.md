## 当前计划（基础控件 primitive 化 + 统一 primitive 样式，2026-06-24）

> 无样式 primitive 基础层重构（TextInput/Select/DataTable 迁移/flat 回收/overlay 保护节点治本）
> 已全部完成并真机验收。用户要求：第一步先把最基础的控件 primitive 化，并统一 primitive 样式。

1. **评估方案**：oracle 评估"最基础控件 primitive 化 + 统一 primitive 样式"的可行性、
   分批策略、primitive API 统一形态、wrapper chrome 统一规范。
2. **确定 primitive 化批次**：按 explorer 排查结果，候选基础控件分批：
   - 第一批（双向布尔）：Checkbox/Toggle → SceneToggleablePrimitive
   - 第二批（N选1受控头）：RadioGroup/Segmented/Tab → SceneSingleSelectPrimitive
   - 第三批（连续值拖拽）：Slider → SceneSliderPrimitive
   - 第四批（按钮交互）：Button → SceneButtonPrimitive（支撑 IconButton/Dialog 按钮）
3. **统一 primitive 样式**：所有 primitive 遵循统一 API 形态（Props 无 chrome/Result 暴露节点+派生态/create 返回）；
   wrapper 层默认 chrome 统一规范（颜色/边框/圆角/padding/hover/focus 配色一致）。
4. **每批 primitive 化流程**：explorer 侦察 → oracle 裁决（如需）→ fixer 实现 → build+test → reviewer 审核 → 真机复验。
5. **后续恢复主线**：嵌套分类树导航 / 字段引擎最小切片；高优先级缺口 TextArea 待 primitive 化完成后评估。

## 每步完成标准

- 涉及生产 Java 代码改动时至少通过 `compileJava`（优先 `jetbrainsBuildProject`）
  并补相关测试；提交前过 `git diff --check`。
- scene 新栈改动须对照 NORTH_STAR 不变量（尤其 I1/I4/I6/I7/I10/I11）自检，
  偏离按《修订纪律》登记。
- 实现完成后必须经一次独立子代理审核；代码实现审核默认使用 @reviewer，
  Oracle 仅用于架构方案裁决/复杂边界复核且默认新开 session。
- 帧率/真机实测交用户跑，本地验证结果只记录在交接、提交说明或开发者文档中，
  不写入远端 Release 正文。
- 完成独立任务后，检查是否需要更新 `当前态/`、`长期事实/`、`决策/`、`errors/`、`reviews/`。
- 控件完成后必须建 demo 页接入 hub，否则用户无法真机验证。
