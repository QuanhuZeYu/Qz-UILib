# 架构边界

> 控制论定位：**设定值层·边界现状锚**。`NORTH_STAR.md` 宪章 = 应当对齐的**目标边界**，
> 本文件 = 当前**真实边界**现状。二者冲突时以宪章为方向、以本文件为现状基线。

本文件记录项目的稳定架构边界、核心数据流和模块职责约束。

## 最高准绳

- 根目录 `NORTH_STAR.md` 是 UI 系统中心思想宪章，凌驾于本文件及其它所有架构文档之上；本文件记录的是「当前真实边界」，宪章记录的是「应当对齐的目标边界」，二者冲突时以宪章为方向、以本文件为现状
- 宪章核心结构：数据层（①signal ②reactive/effect ③组件）→ ④Element 树（DOM，交汇点）→ 渲染层（⑤Layout ⑥Paint/Display List ⑦GL Render），Display List 与分级脏标记是数据层与渲染层之间的唯一契约
- 采用本宪章的取舍背景见旧决策（已删除，宪章本身即权威源）

## scene 新栈与 strangler 共存边界

- 当前是「HTML-like 旧栈（`ui.dom` / `ui.layout` / `ui.paint` / `ui.component` / `ui.control` / `HtmlLikeDocumentWidget`）」与「按宪章重写的 scene 新栈（`ui.scene` 下 node / layout / paint / component / input）」物理隔离共存，
  两栈共用 `ui.reactive`（Signal/Effect/Computed 等）与 `ui.render`（UiRenderContext 等），共用包保持不动
- 旧 HTML-like / `ui.dom` 栈已退出实际业务接入；scene 新栈已承载内部 devtools 默认 test hub（`/qzuilib test`）
- scene 核心包受宪章 I10 约束：`ui.scene.input` 核心不得出现 `org.lwjgl(x)` / `GLFW` / `net.minecraft(forge)` import，平台输入只经 `PlatformInputSource` 契约线进入；键码在核心层只以平台无关枚举表达
- scene 输入 handler 受宪章 I11 约束：只能经 `signal.set(...)` 改 UI 状态，不得直接操作 SceneNode 属性槽或树结构，受控逃生舱仅限只读几何测量 / EventContext 受控命令 / 宿主层第三方桥接
- scene 排版地基优先补 layout 能力而非 token/theme；当前 `SceneNode.WidthSizing` 支持容器默认 `FILL` 与 opt-in `SHRINK` 内容宽回收，`preferredWidth` 仍最高优先级。
  `SHRINK` 只在子布局完成后读取本帧子 `LayoutBox` 缓存，下传约束阶段仍使用父级 available 宽，避免循环依赖和向下递归标脏。COLUMN 容器已支持多 `flexGrow` 子按权重一次性分配剩余高（Qt 语义，余数补末位），`fillParentHeight` 等价隐式 `flexGrow=1`，grow 子隐式 fill 主轴。已实现 min/max 高度 clamp（freeze do-while 上界+下界对称，守 I7 数值求解器边界）、align-self（独立 AlignSelf 枚举 + AUTO 回退父级）、margin 四向外边距（五处联动）、percent 百分比高/宽（父先验内高基准 + fallback shrink + grow 优先）。clamp 优先级 `max(preferredHeight, min(natural, maxHeight))`（min 赢 CSS 语义）。percentHeight 仅 COLUMN 主轴生效，ROW 下不生效。
- scene 浮层控件地基已落地：`ui.scene.overlay` 包 + `SceneRuntime.portal`/`portalAnchored` + `SceneInputRouter` overlay 优先命中/dismiss + `AbstractSceneHostWidget` 多 root layout/paint/replay + 保护节点机制（语义归属判 outside dismiss）。per-root layout engine 防约束串味。`SceneSelect` 是首个消费者与验收用例。已转正为宪章 §4/§4.5 一等能力。后续仍不允许做私有浮层绕过通用 overlay 地基。
- strangler 路线图：Phase 0-3（地基 / 端到端切片 / 声明式基石+keyed 列表 / 分级失效全链路+合成级动画）已合回 `4.0`；Phase 4（控件层逐组重建）已大批完成并合回 `4.0`（Checkbox/Radio/Slider/TextInput/Select/Tab/Table/DataTable/TextArea/SimpleList/KeyValueMap/ObjectField/Breadcrumb + primitive/wrapper 范式 + 统一 chrome + 滚动地基 + overlay 保护节点）；Phase 5（宿主粘合迁移+旧栈退役）阻塞中，旧栈退役须满足全部退役条件后才删

## 项目定位

- Minecraft 1.7.10 / GTNH 环境下的 UI 框架 Mod；当前是 HTML-like 旧栈（对外主路径）+ 按 `NORTH_STAR.md` 重写的 scene 声明式新栈（内部验证中）strangler 共存；存在 LWJGL3ify 时会接入其增强输入能力
- 当前开发依赖基线通过 Elytra manifest 锁定 GTNH `2.9.0-beta-1`，主要整合包依赖统一从 `dependencies.gradle` 的 `elytraModpackVersion` 解析
- 发布依赖边界：`lwjgl3ify` 不再作为 Maven 发布硬依赖，源码通过内部输入后端反射接入 `InputEvents`；键鼠输入运行时通过内部桥优先反射 `org.lwjglx`、缺失时降级 legacy `org.lwjgl`，OpenGL 依赖仍是客户端渲染基础链路
- 作者层暴露浏览器语义（DOM / CSS / 事件模型），不向页面作者暴露 Minecraft GUI 生命周期或底层渲染实现细节
- 页面内容通过 `UiDocument`、`ElementNode`、样式和控件组织，而不是编写真实 HTML/CSS 文件
- 背景模糊按 `BackdropBlurConfig` 全局默认、`BackdropBlurPolicy` 页面策略、`UiDocument.getBackdropBlurController()` 运行时覆盖、元素级样式逐层解析；页面级调整不得写回全局单例，也不得影响其它页面
- 内置弹出型控件（select、autocomplete 等）按浏览器 top-layer 语义处理：DOM 归属不变，布局、绘制、命中由文档运行时提升到视口顶层；top-layer 仍是内部能力，不作为业务作者 API

## 对外入口边界

- 业务文档入口：`UiDocumentScreens.createDocumentScreen(...)`
- 服务端生成的安全子集 HTML 远程页面入口：`RemoteDocumentPages.open(...)`
- HUD 浮窗入口：`RemoteHudOverlays.open(...)`
- 远程页面与远程 HUD 都不执行 JavaScript、不嵌入真实浏览器；内部远程 UI 层以 `RemoteUiProtocol`、`RemoteUiAssetStore`、`RemoteUiSessionManager`、`RemoteUiServerRuntime`、`RemoteUiClientRuntime` 承载 session、surface、contentRevision、
  asset 与 closeScope，公开 `RemoteDocumentPages` / `RemoteHudOverlays` 仍作为对外 facade
- 配置页本地模板入口优先通过 `ForgeConfigTemplateScreen.Spec.enableQzNetworkSync(...)` 绑定 Qz 网络配置会话；高级场景仍可用 `setRemoteSyncController(...)` / `setRemoteSyncScreenId(...)` 替换同步控制器
- 服务端远程配置页入口：`RemoteConfigDocumentPages.open(...)`
- 双端网络入口：`NetService.getInstance()`
- test 诊断能力只保留内部开发工具入口 `/qzuilib test`，当前默认入口为 scene 新栈 test hub；hub 以独立 screen 方式挂接 Scene / Controls / Scroll / Table / Layout / Form demo，其中 Layout demo 用固定标题条 +
  唯一 `fillParentHeight` scrollable viewport 可视化 P0 `WidthSizing.SHRINK` 与 P1-a COLUMN 剩余高度能力，Form demo 用硬编码假配置项验证 current/draft 双副本、dirty、校验和保存/恢复闭环。
  `/qzuilib scene_test` 是过渡别名。
  旧矩阵实现归入内部 devtools 路径，不对外暴露页面工厂，也不再作为实际业务入口扩展。

## HUD 与输入边界

- HUD 宿主内部为“单共享 `UiDocument` / `HtmlLikeDocumentWidget` + 每个 HUD 一棵挂载子树”
- `UiHudDocumentHost.register(...)` 的 builder 接收 `UiHudMountContext`，应只通过 `getMountRoot()` 操作当前 HUD 根，不再假设 `document.getRootElement()` 由当前 HUD 独占
- 交互 HUD 仅在容器态接通输入，必须先鼠标命中建立 HUD 焦点，键盘抢占只由 HUD 内有效焦点驱动
- `GuiChat` 打开时 HUD 可继续显示，但不会沿用旧 HUD 焦点继续抢占；必须在当前聊天界面里再次点击 HUD 才会重新接管
- 若 HUD 已从聊天框手里抢走输入，主键点击浮窗外部会显式恢复聊天框原生焦点
- `UiHostInputCoordinator` 只作为宿主原生输入链路上的协调桥，不承载 HUD 业务规则
- `UiInputService` 保持 facade 和调用点稳定，内部优先使用 `Lwjgl3ifyInputBackend` 反射订阅 `InputEvents`；无该 API 时回退 `LwjglxPollingInputBackend`，若 API 存在但监听注册失败则启用键盘轮询兜底；
  fallback 通过 `LwjglInputRuntime` 反射当前键鼠运行时，仅保证基础按键、鼠标和滚轮，文本输入/IME 需要 `InputEvents` 才能完整支持

## 配置与网络边界

- 远程配置同步共享 `ConfigTemplateSyncManager` 配置目标、草稿、显式保存模型
- 服务端配置同步目标可通过 `ForgeConfigTemplateScreen.Spec.createQzNetworkSyncTarget(...)` 复用模板规格生成，再交给 `ConfigTemplateSyncManager.registerTarget(...)` 注册，避免本地页面与服务端目标重复维护标题、分类和保存回调
- 现代配置模板页通过运行时检测 `club.heiqi.config` 模块能力启用，缺失时回退 Forge 配置页；当前模板覆盖基础类型、列表、普通对象嵌套、显式动态 map 和预设选择，其中动态 map 只由 `FieldSpec.templateHint` 明确声明触发，预设定义约定存放在同级 `_presets` 或 `presets`
- 配置分类名默认大小写敏感，只有通过 `CategorySpec.addAlias(...)` / `ConfigSyncCategorySpec.addAlias(...)` 显式声明的历史名称才参与兼容查找
- `NetService` 在 `preInit` 注册 Channel / RealtimeChannel / Fetch / Stream / Store，`postInit` 后注册表冻结
- 普通业务网络以 `route/key + contentType + headers + body` 为核心，不以 Java 类型作为协议身份
- 远程 UI 的 keepalive / renew / resume、lease、surface、asset 与关闭范围属于 `ui.remote` 内部协议，不写入 `NetService`；普通远程页面/HUD 默认仍固定 10 分钟 TTL 且不隐式续期
- 实验性 `NetRealtimeChannel` 走共享 `qz:0` 物理通道内的独立 `QZRT` 小帧协议，面向高频小二进制帧，不自动分片，强调新鲜度优先
- 普通逻辑消息默认 16 MiB，超过阈值走 Stream/chunk
- 出站优先级分为 realtime / control / bulk，允许 realtime 帧插队到后续 chunk/stream 之前
- Fetch endpoint 可配滑动窗口限流，Store 可注册业务 delta applier
- 默认传输为 vanilla custom payload early mixin 适配器，可用 Forge 配置 `netTransport` 或 JVM 参数 `-Dqzuilib.net.transport=forge` 切 Forge 回退

## 内部 API 边界

- `__` 双下划线 public 方法是内部协作君子协定：为特殊宿主、兼容层和诊断路径保留可见性，不属于稳定 API，未来可替换为 internal accessor 或 package-private bridge
- 不新增扩大直接 `Widget` 作者入口的 API
- 代码结构 P0-P3 整改已收口：input 包消费宿主注册抽象，远程图片缓存拆分 `clear()` / JVM 退出 `shutdown()`，`DocumentCustomRenderer` / `CUSTOM` 仅作为宿主级逃生口

## 字体系统边界

- `fontSystem.fontSort` 仍负责全局字体优先级和自动 fallback 顺序。
- `fontSystem.characterFontRules` 只作为字符码点级覆盖表接入 `FontMatcher`，首个启用且命中的规则优先；目标字体不存在或不能显示该字符时必须继续回退到自动匹配，不把失败规则视为硬错误。
- `characterFontRules` 的启用范围允许重叠，配置页只提示不阻断；运行时按配置顺序决定优先级。
- 远程配置同步若接入带专用编辑器的列表属性，应通过 `ConfigSyncTarget.DraftValidator` 复用字段级校验，避免绕过本地 `PropertyBinding.validateDraft()`。
- 字符字体覆盖规则不等同于 CSS `font-family`，不会向 `UiStyleDeclaration` 暴露字体族样式维度；页面作者侧字体族仍按既有决策保持暂缓。
- 字体 atlas 采用 AWT baseline + actual pixel bounds 契约：advance 负责光标推进，ink bounds 负责 bitmap 装箱，运行时按 codepoint 直索引保存可变 slot 与 atlas baseline；空白 glyph 保留 advance 但不上传 bitmap。
- `FontRendererAdapter.drawString(...)` 保留旧兼容入口；真实渲染语义由 `drawBaselineAlignedString(...)` 命名承接，默认实现仍委托旧入口以兼容外部适配器。

## 文档运行时语义边界

- `DocumentVisualTraversal` 是当前命中、滚动与绘制共享的视觉遍历层，统一负责 `fixed/sticky` 偏移、fixed containing block 继承、scroll offset、overflow clip 链、stacking phase 收集，以及普通树 + `top-layer` 根盒的根级顺序与共享定位查询
- `HtmlLikeDocumentWidget` 的动画时间线更新与 `requestAnimation(...)` 也必须把 `top-layer` 根盒作为共享运行态的一部分处理，不能只扫描普通树
- `DocumentEffectChain.createsStackingContext()` 表示 CSS 规范意义上的 stacking context 判定；`DocumentEffectChain.isStackingBoundary()` 仅表示共享遍历中的局部边界，包含 clip boundary 的工程收敛含义，不能直接等同于规范 stacking context
- `overflow:hidden/auto/scroll` 祖先会提供 clip 链，裁剪后代像素输出与命中/滚轮可达性，但不会仅因 clip 本身把后代提升为独立 stacking context
- `position:fixed` 后代默认脱离祖先 scroll offset 与 clip 链，按视口定位；若遇到 `transform` 祖先，则该祖先建立 fixed containing block，fixed 后代按该祖先 padding box 定位并继续受其 scroll/overflow clip 约束
