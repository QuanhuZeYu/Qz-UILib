## 1. 领取规则

- 一次只领取一个任务实例。带“/实例名”的任务族必须拆发，例如 G04/TextInput；不得一次承包整个任务族。
- 主代理在派发消息中填写检出目录、依赖提交、确切修改文件、相关测试类及冻结接口文档。卡片列出的目录只用于定位；它们不是整目录修改授权。
- 新 helper 必须由主代理提前指定文件名及归属。已有 primitive 可读，默认不可改；缺少稳定的样式部件访问器时先报告，不能按 child 索引猜结构。
- 每张卡都继承总规划第 3 节红线、第 7 节验证和第 8 节命令规则。未重复写出不表示豁免。
- 每个代码实例完成相关行为验证和完整 build 后交付本地提交。共享工作树由唯一写入执行者完成提交；分离检出由各实例提交，主代理集成后再完整 build。
- 若依赖没有交付，返回具体缺少的接口/测试/提交；主代理补齐后继续。不要新建伪实现或自行改任务范围。

## 4. 基础任务

### G00：冻结接口、材质角色和完整清单

- **目标**：让后续小模型不需要设计主题系统或猜 API。
- **负责者**：主代理；此卡不交给小模型自主扩展核心。
- **读取**：SceneRuntime/Owner 的 mount/show/forEach/portal，SceneLiquidGlassStyle，FormTheme，SceneChromeTokens，真实页面注册及字段工厂。
- **允许写入**：本计划配套的接口定案文档与逐实例台账；本卡不改生产代码。
- **交付**：精确包名、类型、方法签名、null/继承/关闭语义、旧 API 兼容路径、属性归属表、作用域及延迟构建方案、每类表面的默认配方和颜色；确定浅色/实色显式覆盖例子。为 Label 冻结默认前景与显式 color 的兼容表达，不通过比较色值猜默认。
- **示例要求**：列出普通按钮零配置、页面主题更新、控件显式覆盖、关闭滤镜、延迟 portal 五条完整调用路径。标为拟议代码；基础示例由 G01/G02 编译验证，普通按钮示例由 G03 验证，不可假称已编译。
- **通过条件**：逐实例文件白名单可生成；无双重外观写入；公共 API 变更后果已说明并按 AGENTS.md 核对已有授权。只在确有未授权高影响变更时向用户确认，不向用户询问一般实现细节。

### G01：主题值与作用域基础

- **目标**：实现 G00 冻结的唯一主题来源；所有现有工厂可以在不增加必填参数的情况下解析默认主题。
- **允许写入**：G00 指定的新主题文件、R/SceneRuntime.java 的指定接缝；Owner/ReactiveContext 仅在 G00 明确批准的最小范围内。不得修改全体控件。
- **实现**：不可变值＋值相等；默认/页面/控件优先级；明确关闭滤镜；Owner 生命周期；延迟 show/forEach/portal 捕获主题信号；独立 runtime 隔离。
- **禁止**：静态强引用页面、构造第二套响应式系统、只在同步 builder 临时设全局变量、把主题信号放到 paint 层。
- **验证**：无参数默认、显式覆盖、嵌套覆盖；两个 runtime；先隐藏再显示；后插入列表项；portal 重开及打开时更新主题；卸载后外观不再写入。
- **通过条件**：五条定案示例至少基础路径可编译执行；未带初值的 Computed 挂载不崩溃；完整 build。

### G02：通用表面与状态配方

- **目标**：提供页面、卡片、输入、工具栏、浮层与轻量行可消费的外观绑定，具备无滤镜替代。
- **允许写入**：G00 指定的新表面/状态配方与绑定文件；确需修改现有通用 chrome 时逐文件指定。renderer、shader、PaintCommand 核心只读。
- **实现**：按角色得到 backdrop、染色、圆角、边框、前景和状态；普通/hover/pressed/disabled 与选中、focus、error 分开组合；只消费控件已有状态，不制造加载或错误业务状态。
- **属性归属**：交互反馈 disabled 优先于 pressed/hover；selected/checked 控制选择指示；error/dirty/focus 在 G00 冻结的槽位表现，不用一个枚举互相覆盖。
- **验证**：实际 PaintPlan 有预期材质且无不透明底盖；角色切换保留节点；关闭滤镜可读；零动效立即应用；重复相同主题不重建；卸载清理。
- **通过条件**：大面板、窄输入、轻量列表行均有参考用例；无复制 shader；完整 build。

### G03：SceneButton 普通工厂参考实现

- **目标**：SceneButton.create 的原调用方式默认得到玻璃按钮，PRIMARY/DANGER 和旧参数保持有效。
- **允许写入**：C/SceneButton.java；C/SceneLiquidGlassStyle.java、SceneGlassButtonStyle.java 仅在派发白名单列出的共用接缝；对应测试。
- **实现**：复用 SceneButtonPrimitive 和现有玻璃绑定；唯一 motionRoot；移除原实色属性的竞争绑定；文字颜色显式绑定；显式实色主题仍可用。
- **禁止**：复制一个 SceneIOSButton 替代迁移普通工厂；改 onClick 触发时机；给位图套文字色。
- **验证**：三种 variant、旧构造器、默认和局部主题、键盘/指针按压、禁用、回调中卸载；内容 transform 不被覆盖；尺寸与命中不变。
- **通过条件**：主代理将其作为叶子任务参考实现，冻结共用入口后再发后续卡；完整 build。

## 11. 主代理验收动作

1. 对照实例白名单查看每个 diff，抽查有无原版 GUI/平台依赖绕路。
2. 对照属性归属，检查是否仍存在旧 chrome 与新玻璃绑定竞争。
3. 从旧工厂进入实际控件，不能只调用新增 helper 做演示。
4. 运行或核实对应源码版本的测试记录，集成后完整 build。
5. 更新逐实例台账，分别记录代码、GPU、宿主状态；代码验收通过即可派发依赖实例。视觉证据按同类表面或整页集中补齐，不要求用户逐控件确认。
6. 超范围或架构问题退回执行者修复；基础能力缺失则收回到共享负责人，叶子实例保持明确待续状态。
