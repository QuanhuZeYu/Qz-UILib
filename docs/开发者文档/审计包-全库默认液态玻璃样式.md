# 审计包：Qz-UILib 全库默认液态玻璃样式（G00→G19 交付外审）

> **本文档是自包含审计材料**：供无仓库访问的外部评审模型使用。所有代码节选为 `4.0` 分支提交 `7aeedc21`（代码头）逐字摘录；所有数值结论附计算口径，可供复算。评审只需本文档，不需要其他材料；文档未覆盖之处请标注「证据不足，无法判定」，不要臆测。

## 1. 仓库与背景

**Qz-UILib**：Minecraft 1.7.10（GTNH 生态、Java 8 语法基线、Gradle 9 + Jabel 编译）的 **Live2D 式 UI 框架库**——场景树（`SceneNode`/`ContainerNode`/`Transform`）、`SceneRuntime`（固定步进帧驱动 + `RenderSnapshot` 绘制计划 `PaintPlan`/`PaintCommand`）、**响应式信号层**（`ReadableSignal<T>`/`WritableSignal<T>`/`Computed`/`Effect`/`Owner` 作用域树/`Signal.inherited`）、声明式 builder、`UiBackdrop`（`UI_BLUR`/`UI_NOISE`/`UI_RIM_LIGHT`/`UI_TINT` 滤镜），**非内容 Mod**。

- 渲染后端：GLO/GL2 双后端 + headless。库代码禁触 GL 状态与 `GlStateManager` 缓存；颜色一律 int ARGB；度量单位逻辑像素 dp。
- 施工前痛点：「液态玻璃」观感只在测试样板页 `uilib/ui/playground/glass/GlassPlaygroundPage.java`（14 处手搭 backdrop 配方）；通用控件与配置框架默认材质是「旧深色纯色平面」，宿主（mod 配置界面，如 GTNH 类大型 mod 的列表面板/字段/搜索面板）不用玻璃就没有玻璃观感。

**工程目标**（用户裁决：全库默认，不做隔离样式包）：把液态玻璃升级为默认材质，让通用控件、配置框架与真实宿主页面「一构建就默认是」；显式局部配置与既有兼容入口继续有效。

## 3. 架构与冻结契约（核心裁决）

### 3.1 权威链与优先级
```
ThemeTokens（原始色板/token，唯一权威值来源）
  → SceneTheme（9 Roles 的不可变分量快照，逐字段校验值域：
      alpha ∈ [0,255]，blur ∈ [0,32]，cornerRadius ≥ 0，contentLift ∈ [0,8]，
      lensFactor ∈ [0,2]，transitionMillis ≥ 0，elevation ≥ 0，非法值回退安全默认并记一次日志）
  → SceneSurfaceStyle（控件配方，值对象）
  → SceneSurfaceBinder（全库唯一 surface 材质写入者）
```
解析优先级：**显式控件配方 > 局部/页面主题 > runtime 默认主题 > 库默认 `liquidGlassDark`**。主题沿 `Owner` 作用域树继承（`Inherited` 信号，子节点默认跟随祖先）；默认主题为静态常量 `DEFAULT_THEME`（零订阅成本），局部覆盖为信号。

### 3.2 双路径迁移承诺（既有 API 兼容的核心设计）
```java
// SceneSurfaceStyle.withTheme(rt, style, role)：style==null → 返回主题配方信号（订阅主题，切换跟随）
//                                        style!=null → 返回原 style（常量信号，不订阅主题）
// 既有 setter（setBackground/applyStyle/applyChrome 等）：null → 主题通道；非 null → 显式值（旧契约）
```
「显式优先」只在**配方选择层**实现一次；binder 内**不得**用 `focusEdge != 0` 一类条件判断做兜底（否则把「显式设 0」与「未设」混为一谈）。`ConfigTheme/FormThemes/DialogTheme/ToastTheme` 等旧宿主入口 = 兼容 bridge：旧宿主显式传值行为不变（互斥路径）；默认路径改读 `SceneThemes`，色值逐通道同源。`asFormTheme()` 等桥接出口保留但库内调用方已清零（护栏守卫钉住，§5）。

### 3.3 统一 binder 的写入面（节选，`SceneSurfaceBinder.bindCore` 实际代码）
```java
ReadableSignal<SceneSurfaceStyle.StateStyle> surface = Computed.create(
        () -> surface(recipe.get(), state.get()));
Supplier<Integer> duration = () -> recipe.get().getTransitionMillis();

rt.bindComputed(() -> recipe.get().getBorderWidth(), node::setBorderWidth);
rt.bindComputed(() -> recipe.get().getCornerRadius(), node::setCornerRadius);
rt.__bindAnimatedColor(() -> surface.get().getTint(), node::setBackgroundColor, duration);
rt.__bindAnimatedColor(() -> state.get() != State.DISABLED
                && Boolean.TRUE.equals(interaction.focused().get())
                ? recipe.get().getFocusEdge() : surface.get().getEdge(),
        node::setBorderColor, duration);
rt.__bindAnimatedFloat(() -> surface.get().getElevation(), node::__setSurfaceElevation, duration);

if (motionRoot != null) {   // 内容随 elevation 抬起；禁用压平透明度
    rt.__bindAnimatedFloat(() -> -recipe.get().getContentLift() * surface.get().getElevation(),
            value -> motionRoot.setTransform(Transform.translate(0.0F, value)), duration);
    rt.__bindAnimatedFloat(() -> state.get() == State.DISABLED
                    ? recipe.get().getDisabledOpacity() : 1.0F,
            motionRoot::setOpacity, duration);
}
// 两个独立失效来源：材质变化即刻重派生，动画样本只改变当前配方的透镜强度。
// 不向信号写每帧样本，不捕获旧材质，也不因配方切换重复创建订阅或动画轨道。
BackdropBinding backdrop = new BackdropBinding(node);
rt.bindComputed(() -> recipe.get().getBackdrop(), backdrop::setBase);
rt.__bindAnimatedFloat(() -> surface.get().getLensFactor(), backdrop::setFactor, duration);
```
前景绑定提供「null 回落 fallback」语义（配方不管理前景时用主题前景），不遍历子树。

### 3.4 关键角色裁决
- **9 个 surface Roles**：WINDOW/PANEL/GROUP 为容器族（无文本前景/无滤镜/无焦点环）；ROW（可交互行，含前景与 hover/selected 语义）；FIELD/ITEM/CARD/HANDLE/BUTTON/DECISION（`0x33FFFFFF` 三档同值）各有定义。
- **selection/hover 只走背景通道**：`SceneSurfaceStyle` 的 ROW 不声明焦点描边，选择态不改描边色——修复旧版「选中+focus 边同显」歧义。
- **虚拟化复用行轻量档**（契约 §4.1，G10 后补冻结）：回收复用的虚拟行（SimpleList 128 行/StructuredList/MemberGrid）默认档 `backgroundColor=0x592A1E68`（选中）/`0x1FFFFFFF`（hover）/**edge=0**/**零 BACKDROP 声明**，仅 ROW 配方信号驱动；理由：行级 backdrop 数量=内容长度（128 滤镜），轻量档把滤镜降到容器级 1 份。**非虚拟化**页面级导航/工具栏行不受本条约束（逐条目 backdrop 保留）。
- **危险/校验语义**：`danger()` 槽经 WCAG 实算（对 PANEL 名义底仅 1.43:1）**裁决为底图专用、禁作文本**；文本用 `errorText()`（8.46/8.66:1）；`successText()` 暂委托 `accent()`（单一绿值对双档名义底无 WCAG 解，见 §4.4 数学）。

## 4. 证据与验收方法（每个实例统一执行）

### 4.1 测试与构建
每实例：定向测试（正例+反例+生命周期）→ **变异测试 ≥2 处**（改坏 binder/配方/闭包并断言测试红，后回滚）→ 全量 `gradlew build` exit 0 → 白名单文件本地提交 → merge 主分支 → 主树全量重跑。变异实例（部分）：把 `lensFactor` 写成常量 1.0F → 6 红；binder 改普通 `bind()` 丢动画采样 → 1 红；`apply(null)` 误走显式路径 → 2 红；binder 删除 `elevation≥0` 守卫 → 5 红；删 `successText()` 委托只留 raw accent → 2 红。

### 4.2 主题跟随证明口径（踩坑后冻结）
**同值陷阱**：浅色档大量 RGB 与深色档相同（仅 alpha 分层不同），「切浅色 RGB 逐项相等」**不是**跟随证明，还可能是常量冒充。有效证明三件套：① 切换前冻结样本+断言「深色=契约预期值」；② 切换后 `assertNotEquals(冻结值)` + 逐通道新等式；③ 真实宿主组装链（经生产 `render()`/binder），非裸 runtime+手工 `__tickFrame`。该口径抓出 3 起「常量冒充跟随」（Input 测试自证、Dialog 假绿根因、renderer 漏切浅色）。

**写序吞没（P-03）**：binder 用 `Effect` 写节点，`bind()` 之后对同一属性的直接写被 effect 吸收（终态恒为信号值）。因此「默认外观变化」不能用「写后断言值」验证；对「binder 绑定后再直接写外观」的既有代码模式，以**源码守护测试**（正则断言生产文件不再含该类调用）替代行为测试。全仓该模式经普查销账：renderer 5 个 + NavRail/Toolbar + ConfigPageHeader（后者原实现**先写后绑**，顺序正确，从未构成吞没）。

### 4.3 数值复核（对自产数字全部重算）
多代理分头上报的色值统计出现过 4 类错误（漏 alpha 字节致误判 60 处「非法 alpha」、行计数偏差 43、双通道测试误计入「未收编」、把 `new int[]{...}` 误判为构造器），**全部以独立 Python 脚本重算纠正**，并据此修正裁决（如「14 字段全未收编」→ 实为 6 真未收编 + 8 已双通道收编）。仓库规范：**数值结论必须 Python 验算，禁心算**；行数/计数以 `wc -l`、正则计数为准。

### 4.4 关键 WCAG 实算（sRGB 相对亮度 + (L1+0.05)/(L2+0.05)，双端 alpha 合成，可复算）
| 量 | 值 | 结论 |
| --- | --- | --- |
| 选择行前景 `0xFFF0EDF8` 对三档合成底 | 9.71 / 10.41 / 10.72:1 | AA/AAA 过（非白名单，无需豁免） |
| `danger 0xFF7F1D1D` 对 PANEL 名义底 | 1.43:1 | **禁作文本**，只作底图/描边（已写入 javadoc） |
| `errorText` | 暗 8.46 / 浅 8.66:1 | 文本级可用 |
| `warningText` | 暗 8.60 / 浅 5.06:1 | 过 AA |
| `disabledForeground` | 暗 3.77 / 浅 3.15:1 | disabled 豁免口径（本分支既有口径） |
| `successText` 候选绿 | green80/40/500 过 dark 档（6.30~8.24:1）但对 light 名义底仅 1.66~2.17:1；深绿 `0xFF006C34` 反向（过 light 6.25 不过 dark 2.18） | **单一值对双档无解，双值=自造色板** → 委托 accent 临时借道，注释/台账/javadoc 三处留痕 |

## 6. 剩余风险与待验清单（整体状态=待验的构成）

### 6.1 真机/宿主待验（代码侧无法定档）
1. **V-3**：虚拟列表 ROW 轻量档 hover 差值极小（深色档 alpha 0x26 vs 0x1F；浅色档 hover ΔL≈0.002–0.009），实机可辨性待验。
2. **V-4**：玻璃对比度随世界背景亮度剧烈漂移（PANEL idle 对白/黑背景分别 11.94 / 1.46:1），浅色档文本可读性包络与「边缘高光+内描边双通道」的结构性充分性，实机待验。
3. Container 全默认档边缘暗边观感（P-05 待复验项）。
4. 聊天玻璃材质档（`0x66/0xB3` 自算 vs 原图 `0x7F` 灰底）、共享按钮 alpha 微差（`0xB3` vs 原图 `0xCC`）、`0x26FFFFFF` hover 语义撞色、HUD 四组缩放系数的真实视觉。
5. GROUP 行圆角带观感、NavRail 把手 idle 态、Toast「借道」CARD 配方、滚动条 thumb alpha=255 观感。
6. MotionDurationMills 250→180ms 统一后的体感。
7. 无玻璃滤镜兜底（禁滤镜/降级环境）：玻璃面退化为可读纯色面。
8. 性能：GlassLab 各档 `SceneProfiler` 帧耗时对比（**方案届时确定，未编造数字**）。

### 6.2 静态覆盖终扫账目（G19，347 处外观写入全分类）
136 主题/信号驱动 + 109 非 surface 域（文本色/relief 几何/overlay 材质等）+ 76 既有护栏钉死 + 20 `defaultDark()` 直接读取（受控兼容快照范式：仅取 int 常量、不触 theme 色值、全带计数护栏）+ 2 契约补录（HUD 屏级遮罩/调试文本，刻意静态并 javadoc 自述）。**真漏网 0**。`SceneColorAnimator` 60 处 `0xFF000000` 实为 32 位安全位移取通道运算（误报销账）。

### 6.3 Filter 预算（契约冻结值）
面板/弹窗/搜索/对象字段 ≤2；导航栏/工具栏 ≤3；列表页 ≤6；对象选择 ≤3；聊天页 ≤8（含消息流，**需实测复核**）；HUD ≤2（不含逐条目 backdrop 配方）；配置页根+首个 section ≤3；全页静态声明上限 ≤16（超出即架构问题）。回收复用行默认不声明 backdrop；逐条目/分组 backdrop 只在不虚拟化的页面级容器。

### 6.4 已知架构级张力（评审请重点攻击）
- **双通道并行**（theme 信号 vs 显式值互斥路径）以「配方选择层单点实现」控制，但兼容面大（67 处调用方、8 个旧主题入口），**回归网依赖护栏测试计数钉死**（如某文件 `defaultDark()` 调用数恰为 2 的断言）——钉数会阻碍合法演进，这是自觉接受的取舍。
- **源码守护测试**（正则断言生产文件不含某调用）替代了无法行为化的验证，脆弱性与行为测试的边界判断由人承担。
- **HUD「继承宿主页面主题」未实施**：裁决为「HUD 无页面 Owner 可继承，真实行为=runtime 默认+宿主显式覆盖」，若未来提供 HUD 主题桥接 API 需重新立契约。
- **renderer 收口后大量消费 `FormTheme.defaultDark()` 的 int 常量**（font/list 度量），护栏是「计数恰好为 N」——值稳定依赖 `defaultDark()` 常量不变这一契约外事实。
- 观感层面大量裁决（如 9 Roles 色值、材质档、V-1/V-2 类）源自 playground 样板页视觉基线，**样板页本身未经独立视觉评审**。

## 7. 术语速查
`runtime`=场景运行时；`Owner`=作用域树节点（信号继承载体）；`recipe/配方`=`SceneSurfaceStyle`；`state`（代码）/`state_style`（文档）=`SceneSurfaceStyle.StateStyle`（每实例新建+工厂方法，契约豁免）；`relief`=`Relief` 值对象（圆角矩形带缘高光+投影）；`tint/edge/lensFactor`=着色/描边/滤镜强度乘子；`portal`=视觉浮层仍属来源子树的合成机制；「收编」=私有色值改为消费公共主题入口；「销账」=逐项登记关闭；「同源同值」=兼容层与主题层取同一常量、行为等价；「双通道」=同一控件里 theme 信号通道与显式值通道并存互斥。
