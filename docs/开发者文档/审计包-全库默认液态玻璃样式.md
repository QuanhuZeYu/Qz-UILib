## 1. 仓库与背景

**Qz-UILib**：Minecraft 1.7.10（GTNH 生态、Java 8 语法基线、Gradle 9 + Jabel）的 **Live2D 式 UI 框架库**——场景树（`SceneNode`/`ContainerNode`/`Transform`）、`SceneRuntime`（固定步进 + `PaintPlan`/`PaintCommand`）、**响应式信号层**（`ReadableSignal`/`WritableSignal`/`Computed`/`Effect`/`Owner` 作用域树）、`UiBackdrop` 滤镜（`UI_BLUR`/`UI_NOISE`/`UI_RIM_LIGHT`/`UI_TINT`），**非内容 Mod**。GLO/GL2 双后端 + headless；颜色 int ARGB；逻辑像素 dp。

施工前痛点：玻璃观感只在测试样板页（14 处手搭配方）；通用控件与配置框架默认是旧深色纯色平面；宿主不用玻璃就没有玻璃观感。**工程目标**（用户裁决：全库默认）：液态玻璃成默认材质，「一构建就默认是」；显式配置与兼容入口继续有效。

## 3. 架构与冻结契约

### 3.1 权威链与优先级
`ThemeTokens`（原始色板唯一来源）→ `SceneTheme`（不可变快照，逐字段校验回退）→ `SceneSurfaceStyle`（配方值对象）→ `SceneSurfaceBinder`。解析优先级：**显式控件配方 > 局部/页面主题 > runtime 默认 > 库默认 liquidGlassDark**；主题沿 `Owner` 树继承，默认档静态常量零订阅。

**surface producer 身份（v2.1 按契约 §4/§6/§10.1 精确化，替代 v2「唯一 surface 材质写入者」的绝对化概述）**：
- **唯一通用实现** = `SceneSurfaceBinder`（契约 §10.1 原文；`SceneLiquidGlassStyle.bindButton/bindForeground` 仅适配委托，不独立写）；
- 属性写入契约表（契约 §4）：`backgroundColor/borderColor/borderWidth/cornerRadius/backdrop/elevation` 归表面绑定器；迁移实例内**删除**旧 `SceneStateColors.*Background`/`SceneChromeTokens.applyPanelChrome` 绑定；`cursor` 归 `SceneControlChrome.bindCursor`（不变项）；
- 旧 Chrome/StateColors 系**保留为公共兼容入口，生产调用点 0**（实证：`bindSelectableBackground(` 全 main 命中仅定义体与两条注释）；其类 javadoc 自述「纯静态查表，非主题引擎」——**不随主题切换是该系的显式兼容语义**，非疏漏；
- 最终 write-sink 是 `SceneNode` setter 这一点成立且被承认；「谁有资格在上游写 surface 属性」目前由**契约表 + 源码守护**双层执行，无类型级强制（弱点自认，§6.4；A 建议的 producer ownership test 列 §6.5）。
- **尺寸/间距/动效常量（PAD/RADIUS/GAP/MOTION）不属主题接管域**（契约 §6：非颜色语义）。

### 3.2 双路径迁移承诺
```java
// SceneSurfaceStyle.withTheme(rt, style, role)：
//   style==null → 主题配方信号（订阅主题）；style!=null → 原 style 常量信号（选择层不订阅）
// 既有 setter：null → 主题通道；非 null → 显式值（旧契约）
```
「不订阅主题」指**配方选择信号层**；`bindForeground` 在配方 `foreground=null` 时回落主题前景（不同层的刻意行为）。旧宿主入口（`ConfigTheme/FormThemes/DialogTheme/ToastTheme`）为兼容 bridge：显式传值行为不变，默认路径与主题同源。`asFormTheme()` 等出口库内调用方清零（守护方式与其效力边界见 §4.2）。

### 3.3 统一 binder 写入面（节选自 `SceneSurfaceBinder.bindCore`）
```java
ReadableSignal<SceneSurfaceStyle.StateStyle> surface = Computed.create(
        () -> surface(recipe.get(), state.get()));
rt.bindComputed(() -> recipe.get().getBorderWidth(), node::setBorderWidth);
rt.bindComputed(() -> recipe.get().getCornerRadius(), node::setCornerRadius);
rt.__bindAnimatedColor(() -> surface.get().getTint(), node::setBackgroundColor, duration);
rt.__bindAnimatedColor(() -> state.get() != State.DISABLED
                && Boolean.TRUE.equals(interaction.focused().get())
        ? recipe.get().getFocusEdge() : surface.get().getEdge(), node::setBorderColor, duration);
rt.__bindAnimatedFloat(() -> surface.get().getElevation(), node::__setSurfaceElevation, duration);
if (motionRoot != null) {
    rt.__bindAnimatedFloat(() -> -recipe.get().getContentLift() * surface.get().getElevation(),
            value -> motionRoot.setTransform(Transform.translate(0.0F, value)), duration);
    rt.__bindAnimatedFloat(() -> state.get() == State.DISABLED
                    ? recipe.get().getDisabledOpacity() : 1.0F, motionRoot::setOpacity, duration);
}
BackdropBinding backdrop = new BackdropBinding(node);
rt.bindComputed(() -> recipe.get().getBackdrop(), backdrop::setBase);
rt.__bindAnimatedFloat(() -> surface.get().getLensFactor(), backdrop::setFactor, duration);
```
**motionRoot 所有权契约（源码 javadoc 原文）**：「motionRoot 非 null 时其 transform/opacity 也归本绑定」；「motionRoot 归本绑定管理，业务内容应挂在其后代，保留自身属性写入权」。不传/null 的让位路径均有显式注释（Dialog/Toast 出入场动画独占、Slider thumb 布局定位独占）。审查者 A 建议将该 ownership 概念升格为全节点统一术语（SurfaceOwnership/MotionOwnership/…），列 §6.5。
生命周期：绑定注册于当前 `Owner`，随作用域释放；无 Owner 时 `__runRoot` 兜底（该兜底路径曾致 P-01 观察，已修）。**订阅释放/换主题动画连续/重复绑定去重的测试证据在套件内，未随包附源码，外审按「项目方报告」处理（§8）。**

### 3.4 材质角色（契约 §2.3 与源码逐字一致）
```java
public enum Role { PANEL, TOOLBAR, INPUT, GROUP, OVERLAY, INDICATOR,
                   BUTTON_STANDARD, BUTTON_PRIMARY, BUTTON_DANGER }
```
PANEL 页面主面板｜TOOLBAR 工具栏/导航底座｜INPUT 输入表面｜GROUP 分组底座｜OVERLAY 浮层｜INDICATOR 小尺度指示｜BUTTON_STANDARD/PRIMARY/DANGER 按钮三档。状态样式由 `darkSurface/lightSurface` 工厂从 idleTint/edge alpha 基推导（dark hover=+6/edge+0x40，pressed=−2/lens 0，disabled=0x06/opacity .65）。`solidDark()`/`withoutBackdrop()` 承担「无滤镜替代档」职责——A 建议将其显式化为材质模式枚举（LIQUID_GLASS/OPAQUE/REDUCED）并防止 `SceneSurfaceStyle` 继续膨胀为万能配方对象，列 §6.5；v2.1 同意「Role 有 material-semantic 与 action-semantic 混装趋势（BUTTON_*）」的观察，`SurfaceRole×ActionVariant` 拆分为待裁决提案。

## 4. 证据与验收方法

### 4.1 测试与构建
每实例：定向测试 → 变异 ≥2 红 → 全量 build → 白名单提交 → merge → 主树重跑（两次实证拦截分支盲区）。**边界（自认）**：变异是过程门槛非覆盖度量；全绿支持「高强度迁移与回归已实施」，不自动构成「所有路径充分证明」。补证：覆盖矩阵/未杀变异清单/构建报告/跳过项身份（§8）。

### 4.2 主题跟随证明口径
① 差异主题下验依赖跟随 + 默认档分别断言预期值（合法同值允许）两类拆分；② 撞色假阴性→几何配对计数法；③ 负向对照四项（显式不变/覆盖隔离/清除恢复/销毁断流）存在于套件；④ **写序吞没（P-03）**：binder Effect 吸收绑定后直接写 → 该模式用源码守护替代行为断言。**守护效力边界（自认）**：正则守护防「已知文件已知形式」再现，不证「无别名/间接/新增路径」；`defaultDark()` 钉数冻结数量不冻结用途。正面结构保证：契约 §4 属性表 + §10.1 唯一通用实现 + 兼容入口生产调用点 0（v2.1 新增实证行）。

### 4.3 数值纪律（v2.1 强化）
历轮代理数字出现 5 类错误 + **v2 自身 2 类（F-01/F-02：手抄未经脚本）→ 固化纪律：审计文档数值表只能由可执行脚本输出直接嵌入，模型与输入随数字同档**。

### 4.4 关键 WCAG 结论（全部指向附录 A 脚本输出）
- 正文/次要/错误/警告（dark 档 M1）：8.84 / 6.70 / 6.72 / 6.84:1 过 AA；`danger` 1.14/1.15:1 → 禁文本（比 v1 的 1.43 判据更强）；`disabled` 2.51/2.73 豁免口径。
- **successText 委托 accent 的重建档（v2.1，F-01 后）**：M1 域内 `#A5D6A7` **确实双档通过（6.95/4.57）**——v2「候选域无解」错。但 M2 显示其对纯白世界背景仅 **1.64:1**：玻璃正文色的合格域是「名义底 ∩ 世界包络」的交集，浅绿在 light 档亮世界场景塌方，**对完整声明域仍无稳定解**；且引入分档绿 token = 扩契约 §5 起步色板（治理决策，用户保留权）。故委托 accent 的**妥协继续成立，但论证由「无解」降格为「包络内无稳定解 + 治理未批准」**。真实使用面（色点/短反馈）可读性列入真机项。
- **M2 对称包络**（升为默认启用门槛，§6.1 第 0 条）：dark 档 over 纯白正文 1.28:1 / light 档 over 纯黑 1.36:1——玻璃是 `default rendering material policy` 而非 `default color palette`（A 语），正确性条件部分转嫁给宿主背景，必须以门槛约束。
- 虚拟化行态（dark，M1 底）：CR selected/idle **1.10**、selected/hover **1.59**、hover/idle **1.45**；ΔL%（统一口径 `(L_A−L_B)/L_B`）：selected−idle **−19.1%**、selected−hover **−59.4%**、hover−idle **+99.4%**（v2 所报「+129%」为手抄错，作废）；fg 于行底 9.69/6.08 ✓。**行态可辨性主要靠色相+选中变暗方向，真机判据用 CR 三值，不再使用无单位「ΔL<2」表述（F-02 采纳）。**
