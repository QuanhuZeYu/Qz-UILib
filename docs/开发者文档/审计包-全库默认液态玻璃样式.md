## 1. 仓库与背景

**Qz-UILib**：Minecraft 1.7.10（GTNH 生态、Java 8 语法基线、Gradle 9 + Jabel）的 **Live2D 式 UI 框架库**——场景树（`SceneNode`/`ContainerNode`/`Transform`）、`SceneRuntime`（固定步进 + `PaintPlan`/`PaintCommand` 绘制计划）、**响应式信号层**（`ReadableSignal`/`WritableSignal`/`Computed`/`Effect`/`Owner` 作用域树）、`UiBackdrop` 滤镜（`UI_BLUR`/`UI_NOISE`/`UI_RIM_LIGHT`/`UI_TINT`），**非内容 Mod**。GLO/GL2 双后端 + headless；颜色 int ARGB；逻辑像素 dp。

施工前痛点：玻璃观感只在测试样板页 `GlassPlaygroundPage.java`（14 处手搭配方）；通用控件与配置框架默认是旧深色纯色平面；宿主（mod 配置界面）不用玻璃就没有玻璃观感。

**工程目标**（用户裁决：全库默认，不做隔离样式包）：液态玻璃升级为默认材质，「一构建就默认是」；显式局部配置与既有兼容入口继续有效。

## 3. 架构与冻结契约（核心裁决）

### 3.1 权威链与优先级
`ThemeTokens`（原始色板唯一来源）→ `SceneTheme`（不可变快照，逐字段校验：alpha∈[0,255]、blur∈[0,32]、cornerRadius≥0、contentLift∈[0,8]、lensFactor∈[0,2]、transitionMillis≥0、elevation≥0，非法值回退安全默认并记一次日志）→ `SceneSurfaceStyle`（配方值对象）→ `SceneSurfaceBinder`（唯一 surface 材质写入者）。
解析优先级：**显式控件配方 > 局部/页面主题 > runtime 默认 > 库默认 liquidGlassDark**。主题沿 `Owner` 作用域树继承；默认主题为静态常量（零订阅成本），局部覆盖为信号。

### 3.2 双路径迁移承诺
```java
// SceneSurfaceStyle.withTheme(rt, style, role)：
//   style==null → 主题配方信号（订阅主题，切换跟随）
//   style!=null → 原 style 的常量信号（不订阅主题）
// 既有 setter：null → 主题通道；非 null → 显式值（旧契约）
```
**表述收窄（v2）**：「不订阅主题」指**配方选择信号层**；前景经 `bindForeground(style, fallback)` 绑定，当**配方 foreground=null 时回落主题前景**（即使配方本身是显式常量）——两者是不同层的刻意行为，评审不应由前者推后者。旧宿主入口（`ConfigTheme/FormThemes/DialogTheme/ToastTheme`）= 兼容 bridge：显式传值路径行为不变；默认路径读 `SceneThemes`，色值同源。`asFormTheme()` 等出口保留，库内调用方已清零（守护方式见 §4.2、外审攻击点 §6.4）。

### 3.3 统一 binder 写入面（节选自 `SceneSurfaceBinder.bindCore`）
```java
ReadableSignal<SceneSurfaceStyle.StateStyle> surface = Computed.create(
        () -> surface(recipe.get(), state.get()));
rt.bindComputed(() -> recipe.get().getBorderWidth(), node::setBorderWidth);
rt.bindComputed(() -> recipe.get().getCornerRadius(), node::setCornerRadius);
rt.__bindAnimatedColor(() -> surface.get().getTint(), node::setBackgroundColor, duration);
rt.__bindAnimatedColor(() -> state.get() != State.DISABLED
                && Boolean.TRUE.equals(interaction.focused().get())
        ? recipe.get().getFocusEdge() : surface.get().getEdge(),
        node::setBorderColor, duration);
rt.__bindAnimatedFloat(() -> surface.get().getElevation(), node::__setSurfaceElevation, duration);
if (motionRoot != null) {
    rt.__bindAnimatedFloat(() -> -recipe.get().getContentLift() * surface.get().getElevation(),
            value -> motionRoot.setTransform(Transform.translate(0.0F, value)), duration);
    rt.__bindAnimatedFloat(() -> state.get() == State.DISABLED
                    ? recipe.get().getDisabledOpacity() : 1.0F,
            motionRoot::setOpacity, duration);
}
BackdropBinding backdrop = new BackdropBinding(node);
rt.bindComputed(() -> recipe.get().getBackdrop(), backdrop::setBase);
rt.__bindAnimatedFloat(() -> surface.get().getLensFactor(), backdrop::setFactor, duration);
```
**motionRoot 所有权契约（v2 补，源码 javadoc 原文）**：binder 类注——「node 的 backgroundColor/borderColor/borderWidth/cornerRadius/surfaceElevation/backdrop 归本绑定；**motionRoot 非 null 时其 transform / opacity 也归本绑定**」；`SceneLiquidGlassStyle.bindButton`——「**motionRoot 归本绑定管理 transform/opacity，业务内容应挂在其后代，保留自身属性写入权**」。即 `setTransform` 替换是**独占包装节点契约**：motionRoot 必须是 binder 专属包装节点（各按钮实现的 `SceneNode.row().setHitTestable(false)` 中转层）；不传（Dialog/Toast 出入场动画独占）或传 null（Slider thumb 定位独占）均为显式让位路径。**宿主缩放/其他动画写入者与 binder 共写同一节点 = 违反该契约，守护边界承认此依赖。**
生命周期：绑定经 `rt.bind/bindComputed/__bindAnimated*` 注册于当前 `Owner` 作用域，节点销毁随作用域释放；无当前 Owner 时 binder `__runRoot` 挂根。**订阅释放/换主题续动画/重复绑定去重等行为的测试证据存在于测试套件，但本包未附测试源码，外审标记为「项目方报告，未独立核验」（§8）。**

### 3.4 材质角色（源码权威，契约 §2.3 逐字一致；**v1 此处名单为编写错误**）
```java
public enum Role { PANEL, TOOLBAR, INPUT, GROUP, OVERLAY, INDICATOR,
                   BUTTON_STANDARD, BUTTON_PRIMARY, BUTTON_DANGER }
```
各 Role javadoc：PANEL 页面主面板（温和折射/受控染色/稳定文字对比）；TOOLBAR 工具栏/导航底座（薄玻璃清晰轮廓）；INPUT 输入表面（弱光学/明确焦点）；GROUP 列表/表单分组（低干扰底座）；OVERLAY 菜单/对话框/提示（独立浮层稳定可读）；INDICATOR 滑块/开关/选中指示（小尺度高光）；BUTTON_STANDARD/PRIMARY/DANGER 标准/主操作/危险按钮。
表面配方状态样式由 `darkSurface/lightSurface` 工厂从 idleTint/edge **alpha 基推导** hover/pressed/disabled（如 dark：hover=alpha+6、edge+0x40，pressed=alpha−2、lens 0，disabled=alpha 0x06、opacity 0.65）。`solidDark()` 档全 Role 关滤镜，`withoutBackdrop()` 为派生替代档。**注**：v1 曾按 playground 旧配方名（WINDOW/ROW/FIELD/DECISION 等）描述角色体系并在 §4.4 引用其数值，该错误随 v2 全文订正；台账个别行沿用「ROW 配方」措辞（历史报告用语），语义对应工具栏/输入行族，以本包名单为准。

### 3.5 关键裁决
- 选择/hover 语义在行族默认配方中主要经背景通道表达（工厂 alpha 推导，§3.4）；「选中+focus 边同显」旧歧义由配方定义消解。
- **虚拟化复用行轻量档**（契约 §4.1）：回收复用的虚拟行默认 `backgroundColor=0x592A1E68`（选中）/`0x1FFFFFFF`（hover）/**edge=0**/**零 BACKDROP 声明**；非虚拟化页面级行不受约束（逐条目 backdrop 保留）。
- 语义色（G19/P02 收编为 `SceneThemes` 四公共入口）：`danger()` 为**底图专用槽禁作文本**（对附录 A 名义底仅 1.14:1，禁判比 v1 更强）；文本用 `errorText()`；`successText()` 现委托 `accent()`（推导链与候选域限制见 §4.4、§6.4）。

## 4. 证据与验收方法

### 4.1 测试与构建
每实例：定向测试 → 变异测试 ≥2 处（改坏断言红，回滚）→ 全量 build exit 0 → 白名单提交 → merge → **主树全量重跑**（两次拦截分支盲区的实证）。变异样本：`lensFactor` 常量化→6 红；binder 丢动画采样→1 红；`apply(null)` 误走显式→2 红；删 `elevation≥0` 守卫→5 红；删 successText 委托→2 红。**边界（v2 采纳外审）**：变异是过程门槛非覆盖度量；全绿支持「高强度迁移与回归已实施」的项目方声明，不自动构成「所有默认路径/显式路径/继承/生命周期充分证明」（覆盖矩阵与未杀变异清单列为补证，§8）。

### 4.2 主题跟随证明口径（两轮踩坑后修正）
- **同值假阳性**（P-04）：切换后值相等不能证伪常量冒充 → 要求「刻意拉开差异的测试主题下验证依赖跟随」+「默认档分别断言预期值（允许设计性同值）」**两类拆分**（v2 按外审 F-5 重述；v1 的「assertNotEquals 普遍必要」表述过强，合法同值允许存在，差异断言用于**该口径宣称跟随的属性**）。
- **同值假阴性**（G18 撞色）：不同来源同终值造成漏报 → 几何配对计数法（「tint 等于 X 的声明处数=配方数」）。
- **负向对照**（存在于测试套件）：显式配方不随主题变；局部覆盖不受祖先切换影响；清除覆盖恢复继承；销毁后不再接收更新。
- **写序吞没（P-03/P-02）**：binder 的 Effect 写吸收绑定后同属性直接写（终态恒为信号值）→ 该模式以源码守护测试替代，全仓普查销账（含「先写后绑」正确变体甄别一例）。**守护效力边界（外审 F-6 认同并收窄）**：正则守护只能防「已知文件的已知违规形式」再现，**不能证明**无别名/间接调用/新增路径绕过；「全库唯一写入者」的正面证明依赖 §3.3 结构（唯一公开 surface 写入 API）+ 代码评审，而非钉数。`defaultDark()` 计数钉（恰为 N）冻结数量不冻结用途，列为已知弱点。

### 4.3 数值复核纪律
多代理上报数字出现 5 类错误（漏 alpha 字节、行计数偏差、双通道误分类、构造器误判、**以及 v2 新认的「主代理未复核旧计算模型」——见 P-10**），全部或部分由独立 Python 重算纠正。仓库规范：数值结论必须脚本验算。

### 4.4 关键 WCAG 结论（**附录 A 权威重算为准；v1 表数字不可复现，作废留痕**）
- 正文/次要/错误/警告文本对**名义底模型**（定义见附录 A）：dark 档 8.84 / 6.70 / 6.72 / 6.84:1，全过 AA。
- **玻璃是背景依赖材质，浅色档无独立名义底可言**：附录 A 世界背景包络显示——dark 档薄 tint 在纯白背景下合成近白，正文前景仅 **1.28:1**；light 档在纯黑背景下前景仅 **1.36:1**。两档各在其不利背景下不可读，为**结构性对称风险**，非本次施工引入（配方透明度的既有设计属性）。**外审 F-11 处置（v2）**：升级为**默认启用门槛**（§6.1 第 0 条），不再仅作待验项——边缘描边不能替代文字对比度。
- `danger()` 双档对名义底 1.14/1.15:1：禁文本裁决成立且更强；作为**唯一状态提示的描边**用途仍需独立辨识性评估（采纳外审）。
- 选择行族（dark 档自洽模型）：foreground 于选中行底 9.69:1 ✓；selected vs hover 底 1.59:1、vs idle 1.10:1（差异含色相通道，ΔL 单项不可辨——真机 V-3 维持）。
- `selectionForeground/onAccent` 系：7.23/6.44:1 过。accent 对名义底 1.22:1 →「accent 不作正文色」既有裁决佐证。
- 「单一绿值对双档无解」（v2 收窄）：准确表述为**在列举的 5 个候选绿值内无同时通过双档名义底的值**（数据在附录 A）；「双值=自造色板」是**治理取舍**而非数学障碍，经批准的分档 token 是合法路径，是否采纳属用户裁决。`successText` 委托 accent 属**已披露妥协**，其真实使用面（色点/短反馈文本）可读性不借「无解」免除验证（列真机项）。

## 6. 剩余风险与放行门槛

### 6.1 真机/宿主验收（前置门槛 + 待验清单）
0. **（v2 升级）默认启用门槛**：真实宿主典型背景下正文/辅助/错误文本、状态可辨识性、控件边界、禁滤镜退化的通过标准**必须在见测量结果前冻结**（代表性页面、规模、双后端、判定阈值由用户/主代理在验收启动时定档，禁止事后选择口径）。若常见宿主背景下正文不可读：**默认启用应阻塞**，回退路径=宿主显式 `solidDark()`/覆盖 opaque 基。
1. V-3 行态可辨性（ΔL<2 且色相为主通道，§4.4）。
2. V-4 世界背景包络（附录 A 的 1.28–17.13 谱系实机复核；opaque 基/inter layer 两设计路线的裁决材料）。
3. Container 边缘暗边观感（P-05 判定输入）。
4. 聊天材质档/按钮 alpha 微差/`0x26FFFFFF` 撞色/HUD 缩放谱系。
5. GROUP 行圆角带、NavRail 把手 idle、Toast 借道 CARD、thumb alpha=255。
6. Motion 180ms 统一体感。
7. 无滤镜/降级环境可读性。
8. **性能测量方案先冻结后执行**：活跃滤镜数（运行时）、处理面积、帧耗时、双后端与降级路径；「届时确定」改为**验收启动会固定**（外审 F 表采纳）。

| `defaultDark()` 直读 | 20 | 受控兼容快照范式（仅 int 度量/色板常量、带计数护栏；弱点见 §4.2） |
