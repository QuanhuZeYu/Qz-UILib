# UILib 反向需求基线

状态：**反向整理草案，供需求审阅**。它提取已有要求、记录实现事实并提出缺口；不覆盖现行规范，不将待裁决建议变成公共兼容承诺。本轮只建立规格与查冲突，不改生产代码、不删测试。

## 1. 目标与依据

用户目标：以真实需求驱动代码，优先消除需求之间未取舍的矛盾；随后让测试只保护真实行为，不让测试里的历史实现反过来定义产品。

UILib 为 UI 作者提供可动态更新、可布局、可交互、可渲染的通用内容；宿主负责输入、投放与生命周期；业务负责意图的业务含义、权限和异步结果。Architect 的重构面板是当前真实消费者，不能把其业务规则搬进通用 UI 核心。

证据基线：UILib 分支 4.0，HEAD `c0b81132d1b0e0de2beb13a6c83f8d7ec6b0a1bb`；Architect 主仓 main，HEAD `2801924d220eb4dac12a1142d04b4dd1326a841c`；重构 worktree codex/rebuild-scratch，HEAD `376057c8e6e0e56ad72cf3d6aa164b7ff7ff9c18`。以上哈希仅作定位，文档链接指向工作目录。

UILib 原有规格索引及 uicore 施工规划存在协作者未提交改动，未修改它们。Architect 消费的开发 jar 标识为 `4.11.0-4-0.40+883888b20e-dirty`，与 UILib 当前 HEAD 不同。不能把本轮源码审查结果直接宣称为该 jar 的行为。

证据优先辨别其用途：

- **现行要求**：用户明确约定、目标仓现行语义母本、明确适用的类契约。发生相互矛盾时记录双方，不能凭代码或测试选胜者。
- **需求来源**：下游已认可交互、真实异常与操作日志。下游整理稿自述“未另行书面评审”，应保留该效力边界。
- **实现事实**：当前代码、接入补偿、数值或内部结构。只能描述现状，不能自动写成“必须”。
- **待裁决建议**：本轮提出的规则或取舍。未认可前不改变现有边界。
- **待观测**：有代码线索但无当前版本真实运行反馈。不能写“已复现/已修复”。

现行文档效力见 [规格索引](<D:/Code/MC/Qz-UILib/docs/开发者文档/规格文档/README.md#L3>)；已删投影组合与未来 HUD 能力的实施边界见 [投影宿主语义](<D:/Code/MC/Qz-UILib/docs/开发者文档/规格文档/UI投影宿主语义.md#L35>)。

## 3. 需求的表达方式

每条需求先给场景与可观察结果，再给责任和证据；“复用哪一个内部字段”“子节点必须位于第几个下标”不充当需求。未指定的极小窗口降级、滚动位置恢复、取整策略等保持为待裁决项，不擅自删能力或猜设计。

## 已确认裁定

### D-01：业务提交变化，框架负责调度与呈现

用户逐项确认选择 A。业务只提交状态变化或语义意图，UILib 负责调度并呈现结果；业务无需调用刷新、布局或绘制，也无需显式提交刷新批次。框架允许批处理，不要求每次调用立即重绘。

连续提交按语义处理：赋最终状态可以合并；文本编辑、通知追加等有顺序意义的操作必须依序保留，不能因合并丢失。这里确定责任与结果，不预定队列、缓存或 Signal.get 的实现。

验收：同一次业务响应连续追加通知，正常宿主刷新后全部保留；连续文本编辑按顺序作用，业务不调用 flush。文本权威、拒绝编辑和回调确认方式继续逐项裁定。C-04 的职责冲突已裁决，代码与旧指南尚待后续对齐。

## 5. 当前真实场景与责任边界

- **选区面板首次打开**：有主题派生值为空的原始异常堆栈。重点是标准控件与主题初始化协作，不把业务手写初值认定为上游永远正确的 API。
- **固定区 + 正文滚动**：业务用自算 fixedChromeHeight、访问按钮内部孩子等方式适配。它们是通用能力接入成本的证据；需求是内容可达和文案可读，不是要求上游复制这些公式。
- **实例编辑/权限变化**：业务决定占用、只读、pending、错误原因；控件保证显示与交互及时更新。关闭面板丢弃未提交编辑与释放占用是业务合同。
- **面板外右键临时控制视角**：下游已明确要求；宿主负责 UI/游戏输入切换与释放，业务禁止借此触发工具。是否需要通用宿主能力另裁决，不能由普通按钮 handler 偷接原版实现。
- **后台创建完成**：已有关闭后 matchedCreate=false 日志，可作为旧页面不重开的正面观测；它不能证明所有焦点/滚动/编辑状态保持。
