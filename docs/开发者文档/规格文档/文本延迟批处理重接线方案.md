# 文本延迟批处理重接线方案（G1）

> 状态：已立项未实施（2026-09-01 用户裁定「保留+重新接线」）。设计输入来自只读调研，行号基准 HEAD 前后实现前须重核。
> 背景：延迟文本批处理机制（DefaultFontRendererAdapter deferred-flush 全套 + UiRenderContext 门面，约 312 非空行）是 UI 必备能力；其唯一消费者 DocumentPaintRenderer 随 3bbdfa59（2026-07-08 删旧 document 栈）被删，机制原地待命（谓词恒 false）。本方案=接回 scene 栈，不是重写。

## 一、机制语义（调研实锤，实现直接采信）
- beginDeferredTextBatch(targetWidth,targetHeight) 的 target 唯一下游=FontBatchRenderer.configureInternalUiProjection（缓存正交投影，flush 时跳过 glGetFloat 矩阵回读）。语义=当前 framebuffer 的 native 尺寸；收集目标是当前主帧屏幕坐标直写，不是离屏层（旧调用传 getScreenWidth/Height 即证）。target 传 0（无参 begin）则矩阵缓存路径不启用，仅收批不合投影。
- 缓冲=单实例 GlyphBatchCollector（normal/bold×页 + decoration + markBackground，按页激活序提交）；非线程局部、无 per-scope 栈 → begin/end 配对是硬要求，异常路径必须 finally 兜 end。
- z 序模型：非文本命令（fillRect/drawSurface/drawImage/opacity/transform）即时落屏；scope 内文本 quad 滞留 CPU 直到 flush → 窗口内混排任何非文本都会盖错层。现成 flush 钩子只有 pushClip/popClip；fillRect/pushGroupOpacity/pushTransform/pushTransformLayer 均无。
- 重入：depth 计数天然支持嵌套，target/投影取最外层；end 缺 begin 抛 IllegalStateException；非 Default fontRenderer 时门面 instanceof 空转（headless fake 的天然护城河，勿破坏）。
- 收益本质：k 次连续文本 drawText 从 k×(守卫 push/pop + uniform 上传 + 矩阵回读 + 纹理重绑) 收敛为 1 组提交（上限每 flush 1+8 批）。最受益场景：逐行 label 密集页（配置页/debug HUD）、wrap 多行、chat3 类 SEGMENTS 密集页。

## 二、接线设计（方案 A：连续文本段小窗，复刻旧栈纪律）
- 窗口粒度：只在连续可批 TEXT/SEGMENTS 命令段开 begin/flush/end（旧 DocumentPaintRenderer 同款纪律）。禁止整帧/整 REPLAY 阶段大窗——scene Display List 命令交错密集，大窗内后画背景必穿透先收集的文字（B/C/D 三个大窗方案已因此否决）。
- run 边界标注：构建期（ScenePaintEngine）在命令上打自包含标记，或回放循环识别连续段——PaintCommand 保持自包含不可变（I6），不引入节点引用。
- begin/end 落点：UiRenderBackend 接口上没有 deferred 方法（契约线窄面，刻意）→ 接线需 host 层持有具体 context 能力；replayCommand 私有，拦截点放 replay() 主循环。
- transform 禁批：继承旧 !isTransformActive() 谓词——PUSH_TRANSFORM 区间与 TRANSFORM_LAYER（FBO 借层）段内文本不进窗口。
- 现成 bug 种子（G1-a 先修）：UiRenderContext.drawSegments 缺 drawTextResolved 同款 isDeferredFlushScopeActive() 分支——窗口一旦开启，SEGMENTS 直画与 TEXT 收集混排必错层；SEGMENTS 是富文本主路径，必须显式纳入。
- 双保险钩子：pushGroupOpacity/pushTransformLayer 补与 pushClip 同款前置 flush（防 deferred 文本提交进 FBO 层）。
- 投影恒等前提（真机必验）：begin 必须传 native 屏尺寸（context.getScreenWidth/Height）而非逻辑尺寸——HUD 的 guiScale 走 ScaledRenderBackend 坐标级乘法，GL 投影恒为满屏 native ortho。

## 三、headless 验收不变量（实现 PR 全覆盖；旧 BatchingRecordingUiRenderContext 合同形态可复刻）
1. 每个 begin 站点必有 finally end；end 无配对 begin → IllegalStateException 回归。
2. 窗口内文本不落屏直到 flush（flush 序列单调 + 合批计数）。
3. 窗口跨 pushClip/popClip 必拆段（clip 钩子不回归）。
4. 嵌套 depth++/--，target/投影取最外层，内层 begin 不改写 ThreadLocal。
5. transform / opacity FBO 段内文本不 collect（谓词测试）。
6. SEGMENTS 与 TEXT 同语义（针对 bug 种子）。
7. fake / 非 Default fontRenderer 下 begin/end/flush 全空转不抛。
8. 连续文本 run 恰 1 组 begin/flush/end；被非文本命令截断 → 计数=段数+clip 钩子数。
9. GlyphBatchCollector 纯 JVM 合批合同（同页合并、跨页激活序、mark<glyph<decoration）。
10. 既有源字符串门不动：FontRenderTailStateContractTest（deferred 宿主禁补 glColor4f/GL_ALPHA_TEST 负锁）、ClipStackHostBaselineTest flush 计数、DefaultFontRendererDemandOrderContractTest 三入口签名。

## 四、分期
- G1-a（先行，零行为变化）：drawSegments 补 scope 分支 + pushGroupOpacity/pushTransformLayer 补 flush 钩子 + 不变量 1/3/4/7 测试复刻。窗口仍无人开，纯加固。
- G1-b（接线本体）：run 边界标注 + replay 主循环小窗 + 不变量 2/5/6/8/9。
- G1-c（真机验收）：GUI scale≠1 文本缩放正确性、chat3/配置页帧时间对比（性能收益实证）、与 backdrop 主层快照协议（notifyMainLayerContentChanged）时序交叠。
- 边界声明：deferred-text-batch 是文本提交合批，与 backdrop/帧尾后处理两条兄弟预留零代码耦合（实测），可独立排期互不阻塞。
