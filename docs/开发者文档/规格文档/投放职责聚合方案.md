# 投放职责聚合方案（scene 投放层去重）

> 状态：**现行规范**（scene 投放层现行原则；2026-09-01 立项；B1/B2 批次已落地并经用户真机回归，B3/B4 未开工、待与下游 Miner 迁移合并成一次 breaking 窗口）。
> 目的：**抽象简化**。手段是「职责归一」（同一职责的多个实现点聚合成一处），**不是**「形态统一」（不把 HUD/主 UI/overlay 并成一个新抽象）。
> 立项前提、对抗论证、逐项聚合清单、施工批次与逐批实测记录已整体移入 [历史报告/专项施工/投放职责聚合方案-历史记录.md](../../历史报告/专项施工/投放职责聚合方案-历史记录.md)。本文只保留仍有效的判据与立法；编号定义以该记录为准，编号本身不构成现行要求。

## 现行判据

- **沿职责边界的拆是简化，跨越职责边界的并是复杂化。** HUD 与主 UI 是跨职责边界（有/无输入），故并不动；横跨两者的**同一职责**才并。
- **简化常常靠拆不靠并**：同一能力面被无差别继承时，按使用面拆窄接口也是简化。
- **需求不来，抽象不升**：不为「统一」而升格抽象，收益必须在「概念数 × 成本」两侧同时成立才立项；以「消灭 N 行重复」为由的重构，立项数必须来自当日实测，不得引用历史审查报告的行号与结论。

## 现行立法

- **宿主 render 栈外禁止 `runtime.flush()`**：flush 的唯一合法收口是帧管线相位；「每帧一次」定义为**每帧一个全局 flush 事务、事务内含多轮**（布局 observer 的有界收敛不算违规）。
- **空窗跳帧的宿主合同是「flush 照常、paint 跳过」**：窗口构造首刷后 effect 仍须物化，不得以消费者侧强制 flush 补丁绕过。
- **装配唯一**：scene 宿主五件套（runtime / layoutEngine / paintEngine / replayer / pipeline）由 `ui.scene.host.SceneHostAssembly` 唯一装配，宿主不手搭第二份；measurer 可注入（`defaultMeasurer()` 是全仓唯一度量装配点）。

## 挂账方向与复活触发条件

- **不做投影化（结论，非议题）**：投影抽象在「概念数」上的真实收益是 4→3，与「删掉投影抽象本身」打平，成本差一个数量级；其唯一实体生产消费者为 0。
- **投影化触发条件**：出现**第二个真实的多输入投放面**（H4 落地：HUD 窗口内 `SceneButton` 可点击且需与 `GuiScreen` 抢焦点）时，投影合同才有验证载体；届时从装配归一后的基线孵化重写版，且必须先解决 `SceneFramePipeline` 的 drain 独占冲突（见 `UI投影宿主语义.md`）。
- **B3（未开工，A6）**：宿主对内容外观无主权——`SceneHudHost` 现在仍按 `isChrome` 写 `HUD_SHELL_BG`；目标是把外壳视觉还给内容树（token 在 `SceneChromeTokens` 与主题层），宿主只保留 clip、放置、空窗隐藏三件事，`HudSpec` 随之瘦掉 `chrome`/`minWidth`/`maxWidth`。属 breaking，与 Miner 迁移合并。
- **B4（未开工，A7）**：输入能力面按使用面拆窄接口（render/dispose 与输入旁路分开），消费方按是否驱动输入取窄面。属 breaking，与 Miner 迁移合并。
- 上述两项时机已挂用户决策。
- **HudScaleSetting**：维持待启用现状，机制与 5 档护栏测试保留（该测试是「缩放只在 host 边界成对转换」契约的唯一可执行护栏）；接线与否由用户决定。
- **另案**：`SceneRuntime.flush()` 直托进程级 `ReactiveScheduler` 单例（`O(N²·E)` 与跨窗口物化顺序依赖）属 scene 内核 owner 分区，独立立项。
