# 编写测试应用

目标与验收以[测试应用规格](../superpowers/specs/2026-10-07-uilib-testing-spec.md)为准。这里说明实际接入方式。

在测试目录创建继承 `TestApplication` 的类，入口只启动应用；在 `runTests` 声明具名场景。继续调用生产 API，各场景保留能证伪真实错误的行为断言。

```java
import club.heiqi.uilib.testing.TestApplication;
import club.heiqi.uilib.ui.reactive.ReactiveDomain;
import club.heiqi.uilib.ui.reactive.Signal;

public final class ExampleScenario extends TestApplication {
    @Override protected void runTests() throws Exception {
        scenario("状态写后立即可读", () -> {
            ReactiveDomain domain = ReactiveDomain.direct();
            domain.execute(() -> {
                Signal<Integer> value = domain.signal(1);
                value.set(2);
                require(value.get() == 2, "状态写入没有立即可读");
            });
        });
    }
    public static void main(String[] args) throws Exception {
        new ExampleScenario().run(args);
    }
}
```

页面场景使用[正式声明式页面接入](<声明式页面接入.md>)：内容在 `ScenePage` 回调中声明，`ScenePageSession.open` 统一装配挂载、输入和帧管线。软件与 GPU 环境只提供宿主事实及度量/回放，`onClose(session::close)` 结束页面；排队域在清理后推进所属 executor。页面订阅与资源通过 context.scope/own 归属页面，外部业务状态与共享字体/窗口保持独立。底层挂载和多管线反例可以观察 session 的原 runtime/pipeline，不另建测试运行环境。

跨场景共享资源在 `setup` 中通过 `own(resource)` 注册，应用结束逆序关闭；场景内部注册的资源在该场景结束关闭。非 AutoCloseable 的资源通过 `onClose(() -> ...)` 登记释放动作。注册顺序应使 GPU/字体 worker 在所属窗口关闭前释放。初始化中途失败也清理已注册资源，清理失败附加到原异常，不覆盖原失败。没有场景、场景失败或资源清理失败都不会报告应用通过。

`arguments()` 提供启动参数副本；`TestResources` 复用路径和资源读取。基类及资源工具位于独立 `testSupport` 编译单元，只依赖 Java8，未放进生产 API 或发行包。真实 GL 测试选择测试目录中的 GLFW 环境组件；LWJGL2 使用自身 Display 组件。纯核心测试的 classpath 不包含这些组件。

新增构建入口使用 `gradle/verification.gradle.kts` 中的 `registerTestApplication`，声明测试类、实际 classpath、参数及环境依赖。Java8 launcher、编码、公共支持编译与运行路径由它统一配置。具体宿主证据仍分开记录。

通用命令在[文档首页](../README.md#稳定命令与排障)维护。运行器回归任务 `testApplicationScenario` 和既有 CPU 场景纳入 `check`；设备场景按需执行，不以 CPU 测试通过替代 GPU 或游戏验收。
