# 共同文档接入

能力边界由[文本规格](<../superpowers/specs/2026-10-07-uilib-text-content-spec.md>)与[图像规格](<../superpowers/specs/2026-10-07-uilib-image-spec.md>)定义。本入口把文字、公式和图像放入同一内容流；Markdown、HTML、表格的源码转换尚未接入。

## 段落与来源引用

在正式页面构造回调内声明，示例中的 page 为 ScenePageContext、images 为所属环境的正式 ImageService：

```java
Signal<SceneTheme> theme = page.domain().signal(SceneTheme.dark());
Signal<ImageSource> source = page.domain().signal(ImageSource.bitmap(bitmap));
Signal<ImageOptions> options = page.domain().signal(
    ImageOptions.defaults().tooltip(true));
Map<String, DocumentResources.ImageReference> refs = new LinkedHashMap<>();
refs.put("figure", new DocumentResources.ImageReference(source, options));
DocumentResources resources = new DocumentResources(images,
    page.domain().signal("https://example.test/docs/"), refs, null);
Signal<TextContent> content = page.domain().signal(TextContent.richTags(
    "正文 <a href=\"next\"><latex>\\frac{a}{b}</latex> "
    + "<img src=\"figure\" width=\"32\" alt=\"示意图\"/></a> 后续正文"));
SceneNode paragraph = SceneDocument.paragraph(page, content, theme, resources,
    target -> lastTarget.set(target)).size(Size.fill(1), Size.natural());
```

SceneRichText.create 也提供同参数 resources 的重载并使用同一段落控件。没有图像的段落可使用原有重载；含 img 的段落须提供所属图像服务。把段落放入正式父节点并 mount，参见[页面接入](<声明式页面接入.md>)。

src 先关联引用键；未关联时以基准位置解析为现有 HTTP/HTTPS、resource 或 item 来源。引用的 source/options 是只读信号，业务改来源就能更新图像和行高，无需改写整篇字符串。基准位置也是信号。最后的可选函数把 item URI 交给宿主产生结构化来源；物品、纹理区域、运行时位图不编码到 DSL 中。

DSL width/height 表达 logical px 意图，未声明使用自然尺寸，单边声明按来源比例求另一边；fit 缺省 contain，也支持 cover/stretch/original。图像继续原有加载、错误、替代文字和资源生命周期。引用 options 的数量、耐久及 tooltip 意图保留；DSL 尺寸/fit/alt 决定本文图像呈现。物品环境须使用正式宿主图像服务，本段示例位图不能代替物品绘制。

latex 捕获正文直到对应闭合，数学正文中的尖括号不解释成 DSL。math-style 支持 text/display/script/scriptscript，缺省 text；display 只改变数学样式，仍是行内对象。非法 DSL 整段原文呈现并诊断，且无链接或对象；合法 latex 中的数学错误由数学控件保留完整源文及诊断，后续正文继续排版。

文字布局给出同代行、簇和基线；公式/图像是其直属正式 scene 子项。窗口、主题、字号、字体代际变化会重新排版，纯滚动复用度量。链接可包含正文、公式和图像，激活回调仅接收解析后的目标，不自动开浏览器；图像提示、祖先裁剪、按下后替换声明取消旧手势沿唯一 router。

## 公式块

外层块结构通过 DocumentContent 明确声明，不把行内 display 样式猜成块：

```java
DocumentContent document = new DocumentContent(Arrays.asList(
    DocumentContent.Block.paragraph(TextContent.richTags("前段正文")),
    DocumentContent.Block.formula(MathContent.parse("\\frac{a}{b}"), MathStyle.DISPLAY),
    DocumentContent.Block.paragraph(TextContent.plain("后段正文"))));
SceneNode article = SceneDocument.create(page, page.domain().signal(document),
    theme, resources, target -> lastTarget.set(target))
    .size(Size.fill(1), Size.natural());
```

公式块复用 SceneMath 的数学子集、编号环境与整式失败呈现；此入口暂不解析 Markdown 的美元定界符或围栏。后续源码转换器可产生相同块声明而复用本层布局。

## 验证入口

自动验证任务 inlineBoxScenario（Unicode/Bidi/对象度量）、documentSceneScenario（正式帧与动态输入）、documentGlScenario（真实 GPU 输出）。前两者进入 check；GPU 任务需要本机设备。

在测试实例执行 /qzcore document：缩窄窗口，切换字号28/38与主题，悬停链接内物品并点击公式/物品，换铁锭/工具，切换错误公式，滚到底后 F3+T。正文、公式和物品应共同换行，错误公式后的正文完整，链接只显示目标，图像提示受当前裁剪限制。另执行 /qzcore rich 检查既有基础富文本。以上原生自动证据与 Minecraft/GTNH 实机反馈分别记录，不用 GPU 出图冒充游戏验收。
