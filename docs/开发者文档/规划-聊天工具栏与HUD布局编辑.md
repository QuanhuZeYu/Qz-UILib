# 聊天工具栏与 HUD 布局编辑路线

状态：P1/P2 已实现（容器内行版本 = 提交 6764c75a）；2026-09 增量把工具栏迁移为 HUD 级
外接挂载层（见文末「实施记录」）。候选类型名不是已发布 API。

## 目标与范围

用户目标：在聊天框附加 HUD 编辑入口，并允许以后继续添加按钮；HUD 编辑沿用统一编辑模式、宿主拖动、用户布局保存与恢复默认的方向。用户补充：聊天框自身作为第一个拖动布局实验对象，优先用它验证效果，再推广到外部 HUD。

实施主体为 Qz-UILib。业务 Mod 仅依赖公开注册能力，不依赖 internal/chat3。第一阶段规划与实现不要求改下游仓。所有实现优先复用 scene、Signal/Computed、通用控件、输入路由、PaintCommand 与现有宿主；原版仅作行为规格参考，不复制原版 GUI 内部逻辑。

## 已核实现状

- `ui/hud/api/ClientHudService` 提供窗口和安全区注册，`HudSpec` 提供四角锚点、堆叠、宽度约束、可见性与 chrome；没有拖动和用户布局字段。
- `client/hud/SceneHudHost` 为每个窗口持有独立 runtime，使用无输入源的 SceneFramePipeline；`placeAndFrame` 统一计算位置，`currentPlacement` 暴露实际放置盒。
- `GAMEPLAY_ONLY` 在打开任何普通 screen 时隐藏，编辑预览必须显式处理该策略。
- `internal/chat3/input/ChatInputSurface` 已持有输入源并装配 ChatContainer；ChatContainer 组合消息列表与 ChatInputBar。当前没有通用聊天动作注册区。
- `ChatInputScreen` 先拦截 Esc、Enter、历史与补全等按键；只改 scene 焦点不足以阻止编辑期间发送消息。
- `api/chat/ChatAccess` 当前公开能力面向消息、装饰器和接管状态，并不是工具栏入口。
- `qzuilib:chat3` 自身也是 HUD，同时具有独立聊天屏幕形态及开合动画；不能假定移动该 HUD 会自动移动聊天编辑容器。
- 输入规范母本：`规格文档/UI投影宿主语义.md`。旧 composition 实现已删除，不可引用为现成功能。
- 规划开始时 Git status 只有未跟踪 `temp/`；保留其内容。

## 推荐用户流程

1. 打开聊天框，在输入框上方、聊天容器内显示一条紧凑工具栏。首个内置动作是“编辑 HUD”。工具栏与输入框分行，保留输入宽度。
2. 点击后进入同一聊天屏幕的 HUD 编辑子模式。保留草稿、光标、选区与聊天滚动位置；暂停聊天输入、消息链接和历史滚动交互。
3. 编辑模式显示 HUD 轮廓与名称，整窗拖动；工具栏切换为“完成”“取消”“恢复当前默认”“恢复全部默认”。当前项不存在时禁用对应动作。
4. 松开鼠标更新本次会话草稿；点击“完成”保存并返回聊天输入态。点击“取消”丢弃整次会话位置修改；重置操作也属于草稿，可取消。
5. Esc 在拖动中先取消当前手势并恢复本次按下前的位置；再次 Esc 退出编辑、丢弃会话。无拖动时 Esc 直接取消会话。完成或取消后恢复原输入状态，下一次 Esc 才按聊天原有关闭流程处理。
6. 编辑时 Enter、历史和补全键不执行聊天命令；本阶段完成操作使用明确按钮，避免意外提交。

工具栏默认只在 UILib 聊天输入屏打开时出现。窄窗口或按钮较多时，按可用宽度把低优先级动作放入“更多”菜单；编辑会话的完成/取消始终可达，极窄布局允许编辑操作区另起一行。隐藏动作不占位，禁用动作仍可显示原因。

## 可扩展按钮合同（候选）

建立独立的聊天动作注册入口（暂称 `ChatActionService`），不要把按钮装配写死在 ChatInputBar，也不把 HUD 编辑逻辑塞进聊天消息 API。

| 信息 | 建议语义 |
|---|---|
| id | 全局唯一稳定 ID；重复注册明确拒绝，不静默覆盖 |
| label / tooltip | 可本地化名称与说明；首版文本按钮即可，图标为可选扩展 |
| order | 排序值，同值按注册顺序稳定排列 |
| visible / enabled | 主线程读取的响应式状态；打开聊天时可动态更新 |
| action | 发布语义动作，消费端在安全的主线程阶段执行 |
| registration | 幂等关闭注销；跨聊天开关保持注册，每次打开重新挂载 UI |

内置“编辑 HUD”使用同一动作注册链。首版提供受约束的按钮动作，不开放任意节点注入、任意 screen/runtime 引用或原生输入源；按钮仍由 SceneButton、Signal 和 keyed list 渲染，更多菜单优先复用 SceneContextMenu/SceneOverlayHost。自定义任意控件槽后续有真实需求再评估。

普通动作执行后默认保留聊天草稿并恢复输入焦点；进入 HUD 编辑则由会话接管焦点。事件 handler 只发布 intent，不直接改树或同步切换 screen；会关闭/切换屏幕的动作在输入派发及渲染栈退出后的安全阶段消费。注册与注销限定主线程。按钮执行失败仅影响当前动作，显示失败反馈，不能破坏输入屏。接管未启用时注册保留，但无工具栏；首版不注入原版 GuiChat。

## HUD 布局与预览合同（候选）

### 默认布局与用户布局

- `HudSpec` 保持默认规格；增加编辑能力描述候选字段：是否允许移动、显示名称。建议旧调用方默认不可编辑，避免已有特殊 HUD 被自动纳入；下游主动启用后即可移动。
- 用户布局独立保存为 `hudId -> placement`，至少包含布局模式、四角锚点和 logical px 偏移。采用客户端全局配置，不按服务器划分；配置带 schemaVersion。路径和序列化工具在实施时复用现有配置基础设施。
- `AUTO_STACK` 沿用现有堆叠；首次有效拖动释放后进入 `CUSTOM` 并脱离堆叠。按下或取消手势不会脱离。重置删除用户覆盖，恢复默认布局。
- 拖动期间冻结该自动堆叠组的其他成员位置，释放后才重新堆叠；取消恢复。自定义窗口不自动参与避碰，允许重叠，由实际绘制顺序决定命中。
- 以安全区矩形为锚定参考，偏移描述窗口对应角相对安全区对应角的距离。margin 只属于默认放置，不重复叠加到保存偏移。首版保留原锚点，不随拖动自动切换锚点。
- 视口、HUD scale、内容尺寸、安全区变化时统一重新约束；只限制有效显示位置，不把临时 clamp 结果覆盖为用户保存偏好。超大内容按宿主规则裁剪。
- 绘制、轮廓与命中消费同一帧权威放置数据；避免编辑器用上一帧位置命中本帧新画面。鼠标坐标通过宿主边界成对换算，不能混用聊天 scale、HUD scale 和 MC GUI scale。

### 编辑预览

- 仅编辑会话内允许预览可编辑的 GAMEPLAY_ONLY 注册项；不修改原 HudVisibility，退出立即恢复原策略。
- 空内容仍保持正常业务状态，编辑器用带名称的占位框表示；首版占位使用统一编辑尺寸，有最近有效尺寸时优先使用最近尺寸。保存锚点偏移，真实内容出现后重新约束。
- 不伪造业务 Signal，不额外调用业务工厂生成示例，不复用一棵 live SceneNode 到第二个 runtime。宿主沿用已有窗口内容，只额外绘制编辑外壳。
- chat3 是首个可编辑对象：打开时拖动整个聊天容器（消息区、工具栏、输入条），关闭后的聊天 HUD 使用同一份逻辑位置状态。两种形态分别保有自己的 scene/runtime 和尺寸；共享锚点偏移，不共享 live 节点或实际布局盒。默认保留左下锚点，打开/关闭时同一锚定角保持一致，内容高度差自然向上展开。
- 开合动画的位移叠加在权威布局位置之上，不写回保存位置。拖动仅在稳定打开态启用，开合阶段禁用；模式切换不重播动画。聊天屏幕从通用布局服务获取位置，HUD 宿主消费同一服务，禁止 chat3 自己维护第二套坐标算法。
- 首个实验就验证打开态拖动、返回聊天、关闭后 HUD 定位以及重新打开的连续性；该链通过后再扩大为全部可编辑 HUD。编辑时聊天容器只保留一个可见交互对象，关闭态聊天 HUD 不额外生成可拖动副本。
- 双形态共用宿主坐标转换与安全区事实；尺寸差异导致某一形态必须 clamp 时允许其有效位置不同，但不覆盖共享偏好。实验阶段重点验证缩放不同与屏幕边缘场景。容器内完成/取消等按钮优先命中，其余编辑外壳区域才开始拖动，移动容器不会使操作按钮失去可达性。
- 工厂失败项在编辑列表显示不可用且可重置保存位置；未注册 ID 的配置保留，便于 Mod 恢复安装。

### 会话与落盘

- 会话持有进入时快照和草稿；正常游戏宿主使用已提交布局，编辑宿主使用草稿。
- 完成时在主线程提交，采用现有持久化设施的安全替换能力；写入失败保留编辑草稿并提示重试，不宣称保存成功。鼠标 MOVE 不触发磁盘写入。
- 断线、世界卸载、screen 被替换、接管关闭时取消会话、释放 capture；已保存布局和注册按各自原生命周期保留。
- 拖动对象注销、变为不可编辑时发送一次 CANCEL；内容暂时变空则切换占位，不修改业务数据。

## 输入与渲染职责

聊天屏幕继续是唯一原生输入采集入口。首版 HUD 内容 runtime 仍被动；在聊天输入 scope 内挂载一个编辑交互层，统一承担所有 HUD 编辑外壳的命中与手势，不为各 HUD 新建 LwjglInputSource。只有出现真实的多输入 occurrence 需求才扩展 composition，必须先消除 drain 独占冲突。

交互层读取宿主权威放置与可见顺序；toolbar/弹层在其最终绘制层级先仲裁，其余窗口按实际视觉顺序 top-first。只读 claim，只有 winner dispatch；DOWN 的 winner 保持单一 gesture 到 UP/CANCEL，第二鼠标键不创建第二 owner，取消后的尾事件按现行规范吞到物理释放。空白点击不开始拖动。

`handler -> semantic intent -> editor controller -> layout Signal -> host placement -> existing paint/replay`。输入 handler 不直接改节点/树。单纯移动优先重用内容布局与绘制产物，只更新宿主位置/变换；内容尺寸发生变化时才从必要层重算。不新增无失效来源的缓存。

进入编辑时释放聊天 focus/capture 并暂停聊天键盘快捷路径；编辑层必须覆盖 screen 级键盘拦截。退出时恢复输入草稿与选区，不重播聊天开关动画。编辑操作区域与 HUD 重叠时按实际视觉层级处理；被遮挡窗口可通过编辑列表选择并重置，保证可恢复。

## 分阶段路线与完成条件

| 阶段 | 工作与产物 | 完成条件 |
|---|---|---|
| P0 合同与交互定稿 | 定稿工具栏位置、动作合同、movable 默认值、会话取消语义、预览和配置 schema；核对实际配置入口和帧顺序；绘制窄屏/多按钮/编辑态草图 | 有可审阅的公共 API 差异及行为表，明确批准后进入代码实施 |
| P1 聊天工具栏 | 动作注册表、生命周期、工具栏、更多菜单、焦点恢复；以测试动作验证扩展，不发布无功能编辑按钮 | 多个动作可增删、排序、隐藏、禁用；错误隔离；聊天输入/发送/补全回归通过 |
| P2 聊天框首个实验 | 实现最小通用位置状态与放置解析、编辑会话、capture/cancel；接入真实编辑按钮，以 chat3 打开容器和关闭 HUD 为首个消费者；先验证会话内完成/取消/重置 | 从聊天入口拖动聊天框；输入草稿保留；关闭后 HUD 与重新打开的容器锚定位置一致；动画不跳回原处；本阶段明确位置尚未跨重启持久化 |
| P3 通用化与持久化 | 基于 P2 已验证的通用能力接入外部 HUD；补全 AUTO_STACK/CUSTOM、可见性预览、空内容占位、选择列表、schema 与配置持久化 | 外部 HUD 无需拖动实现即可接入；聊天同样走公共布局机制；可保存、取消和重置；重启恢复；不同视口/scale/安全区下可恢复；配置异常有确定降级 |
| P4 集成与交付 | 示例 Mod 接入说明、按钮与 HUD API 文档、迁移说明、回归测试和真机清单 | 授权完整 build 成功；本地提交仅含本任务文件；真机结论单独记录，未运行不得记为通过 |

依赖顺序：P0 → P1 → P2（聊天框可见实验）→ P3（外部 HUD 与落盘）→ P4。工具栏是可独立交付的基础能力，HUD 编辑为其首个真实动作，聊天框为首个拖动对象。P2 即提供最短可观察闭环，不等待全部持久化和外部接入完成；其最小位置服务从开始就属于通用 HUD 布局能力，不在 chat3 内另起拖动实现。代码每个可交付增量遵循仓库完整 build 与本地提交规范；runClient/runServer 由用户或 CI 执行。

后续可选：吸附线/网格、多选、键盘微调、按服务器布局、任意工具栏控件。普通游戏态交互 HUD 是独立输入能力，不随拖动编辑自动开放。

## 重点验收场景

- 多按钮、长标签、窄屏、动态注销、更多菜单打开时动作消失；按钮失败后仍可继续聊天。
- 输入了一半消息并选择文字后进入编辑，完成/取消后恢复；编辑期间 Enter 不发送，Tab 不补全，滚轮不穿透到聊天。
- 重叠窗口只拖最上方；鼠标越界仍持有 capture；第二键、Esc、窗口失焦、断线、对象注销均正确取消，释放不触发下层点击。
- 默认堆叠窗口拖动时其他成员不抖动，释放后稳定补位；恢复默认后重入堆叠。
- GAMEPLAY_ONLY 预览、IN_WORLD、chrome=false、空内容转非空、内容尺寸变化、多个 avoidance provider。
- 改分辨率、HUD scale、MC GUI scale、缩小再放大窗口；视觉、轮廓与命中一致，保存偏好不被临时 clamp 污染。
- 保存失败、损坏/未知版本配置、未注册 ID、重启恢复、取消不落盘；全局重置作用于已保存覆盖并且在完成前可撤销。
- chat3 开关动画、消息链接、聊天 scrollbar、渲染 GL 状态隔离回归；拖动仅位置变化时不重建工厂或整棵内容树。

## 实施记录：HUD 级外接工具栏（2026-09 增量）

原 P1/P2 把工具栏做成 ChatContainer 内部一行。用户新需求：工具栏不应固定在聊天容器内部，
而应成为可复用的 HUD 外接挂载层，支持挂在 HUD 外侧上 / 下 / 左 / 右四边可选，聊天 HUD 是
首个使用者。已落地：

- **公共 API（`ui/hud/api`，候选）**：`HudToolbarSide`（TOP/BOTTOM/LEFT/RIGHT，
  `DEFAULT = BOTTOM`）、`HudToolbarSpec`（`gap` 默认 4、`thickness` 默认 28、`visible` 默认恒真；
  负 gap / 非正厚度立即拒绝）、`HudToolbarService`（`hudId -> spec + factory`，重复 id 拒绝，
  `revision()` 信号，`mountLayer` 未注册直通）、`HudToolbarLayer`（外框 = 内容 + 工具栏的
  flex 容器，并给出确定性 `outerWidth/outerHeight`）。
- **布局语义**：工具栏在内容盒外侧该边、间隙 = gap；沿边方向厚度 = thickness；
  **外框 = 内容盒 + 该边的 (gap + thickness)**，其中「沿边垂直方向」那一轴取内容与工具栏实测
  外尺寸的较大者（工具栏比内容宽/高时外框随之变宽/高）。外框参与测量 / placement / clamp / 裁剪，
  因此四边工具栏不遮挡主体，正常锚点下也不被视口裁掉；`visible=false` 时外框退化为内容尺寸。
  竖直边（LEFT/RIGHT）条宽由 thickness 决定，文本按钮需给足条宽（聊天工具栏取 128）。
- **宿主接入**：`SceneHudHost.RetainedWindow` 经 `HudToolbarService.mountLayer` 把外接层装进
  窗口外壳，`measure` 返回外框盒（`placeAndFrame` 数学无需改动）；注册表版本变化时重建该保留
  窗口；工具栏工厂失败只丢工具栏，HUD 主体照常。
- **聊天迁移**：`ChatContainer` 不再持有工具栏行（源码守卫测试钉死）；`ChatHudWindow` 为
  `qzuilib:chat3` 注册规格 + 工厂（默认下边，边位可经 `setToolbarSide` 配置），打开态聊天屏
  经 `HudToolbarLayer` 外接挂载并用外框做 placement；关闭态 HUD 因可见性信号为假而不挂载。
  **打开态容器与关闭态 HUD 仍共享 `HudLayoutService` 的同一份 `HudPlacement`**，位置状态未分裂。
- **事件**：拖动 handler 只挂在聊天内容根上，工具栏是内容盒之外的兄弟节点并自行
  `stopPropagation`，编辑态按钮与拖动区域互不抢占（`HudToolbarLayerTest` 用真实
  SceneInputRouter 路由覆盖）。
- **测试**：`HudToolbarLayerTest`（四边几何 / 外框放置 / 可见性挂摘 / 事件仲裁）、
  `HudToolbarServiceTest`（注册表与规格默认值）、`SceneHudPipelineTest` 新增四条宿主用例、
  `ChatToolbarTest` / `ChatContainerTest` 更新。
- **缺陷修复（2026-09-09，真机「工具栏与编辑 HUD 入口完全不可见」）**：根因是
  `SceneRuntime.show` 的零高 anchor 在 ROW 里吃满主轴宽（无文本叶宽度取父约束宽），把动作行
