### T1-4 [更正：本项是我自己的算术错误，结论作废，不是缺陷]

原判：「同一个 blur 值四层各钳一次，49..64 段被静默吃掉」。**作废。**用户裁 B3（抬高真实上限）之后我按整条式子复算，
发现我把跨行表达式抄断了：只抄了 :414 与 :415 的前半截，漏掉了除数。完整式子是

`UiBackdropFilterRenderer:415`  `max(1.0F, min(maxShaderRadius, blurRadius * 0.75F / max(1, downsampleFactor)))`
`UiMainLayerSnapshotGeometry:71-79`  `ds = (r < 18 ? 1 : r < 34 ? 2 : 4)`（阈值是本类 :14/:15 两个常量）

`0.75` 不是「打七五折」而是「用户 px -> 高斯半径」的换算；`/ds` 是「屏幕 px -> 快照 texel」的换算
（快照本身按 ds 缩，两者恰好互抵，屏幕等效半径恒等于 0.75r）。默认档 cap = min(56, 48) = 48。
Python 全域复算（r = 0..128，默认档）：
- cap 被触发的入口值：**r >= 257 才开始**（r=256 时 raw 恰为 48.00，r=257 才是 48.19 被削）；
- r=64 时 raw = 0.75*64/4 = **12.00**，距 cap 48 还差 4 倍；
- 屏幕等效半径在 0..128 全区间**单调不减**，ds 换挡处（17->18、33->34）也不回退：12.75->13.50、24.75->25.50。

=> 聊天声明的 0..64 全区间可达、无静默饱和。**B3 判定为空转，不做**：抬 `maxBlurRadius` 48->64 或去掉 `0.75` 
对任何聊天可达值都是零变化，却会改到外部传大半径的调用方（`UiRenderBackends:113` 那条按 scale 换算的路径），
属**纯风险零收益**。

残留两条真事实，都不是缺陷级：
1. `applyPerformancePreset`（`BackdropBlurConfig:339/341`）cap=32，r>42.67 起削——**预设语义**且非默认档；
   `applyQualityPreset:356/358` 本来就是 64/80，说明 48 只是默认档、不是墙（我原判把它当成体系上界）。
2. 「聊天 0..64 在默认档不饱和」这件事**没有任何测试钉住**——我能在笔记里写错，别人改码时就能真做错。
   归 R1 正向锚（成本 S）：断言 `resolveBackdropShaderRadius` 在 r=64、ds 各档均低于 cap，并锁住换算口径。

**病灶记档**：跨行表达式必须整条抄完再判。本节原四句结论全部由一次截断的引用生成；我在 §〇 刚写完「量具要自检」
的同一轮里犯了同族错——抄式子也是量具。

### 7-2 mixin 三份配置：**我说错了一句，本仓踩坑文档也说错了一半**
我先前说「另两份是死重复」并且「类列表由 `buildMixinsForSide()` 生成」。两条都不成立：

| 配置 | 真实状态 | 一手依据 |
|---|---|---|
| `mixins.qz_uilib.early.json` | **生效**，9 条实际注入 | `EarlyMixins:23-24` + 运行日志 `Preparing ... early.json (9)` 与逐条 `Mixing ...` |
| `mixins.qz_uilib.json`（center） | **活通道、零内容**：仓内 0 引用，但 jar manifest | `MixinConfigs: mixins.qz_uilib.json`（build.gradle 产物实测）把它注册进 Mixin 框架，日志 `Registering mixin config` + `Preparing (0)` |
| `mixins.qz_uilib.late.json` | **确实死**：`ILateMixinLoader` 0 命中、全部运行日志 0 命中 | 唯一文本引用是本仓 `docs/反馈层/errors/ERROR-20260904-…:191` |

三条发现通道是显式的（coremod 接口 / `@LateMixin` / manifest 属性），**不存在** `mixins.<modid>.json` 名字自动发现
（逐字节搜过 unimixins jar 常量池，只有它自己的 `mixins.gtnhmixins.json` 等）。
`buildMixinsForSide()`（`EarlyMixins:49-65`）是**运行时返回 mixin 类名列表**，不生成也不覆盖任何 json；
json 骨架的生成者是 GTNH 构建插件的 generateAssets 任务，且**只在文件不存在时**写出模板（模板里 `required: true`）。

**所以处置与先前说法相反**：`late.json` 可删（运行时零引用实测）；`mixins.qz_uilib.json` **不要删** —— 删了会被
构建插件按模板重新生成一份 `required: true` 的骨架，比现在的 `required: false` 更严格，属回归；
而且 manifest 仍指向它。它当前是「合法空转」，保留成本≈0。
本仓 `docs/反馈层/errors/ERROR-20260904-….md:191-192` 说 plain json「指向不存在的包且列表全空」是对的，
但据此把它与 late 一并算作死配置是错的 —— **已在本笔记更正，是否回改那份 errors 文档等你定**（它是事故记录，我不擅自改史）。
