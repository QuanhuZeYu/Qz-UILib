## 3. P0：adapter trimToWidth 丢字号（已修复）

**证据链**（审查中新发现，富文本省略号功能的口径缺陷）：

```text
SceneLineClamp.ellipsizeLast(fontSizePx)                    字号感知入口
  → SceneTextMeasurer.trimToWidth(text, fontSizePx, w, mode)
  → TextMeasureServiceSceneAdapter.trimToWidth              ✗ 丢弃 fontSizePx
  → trimStringToWidth(text, w, mode)                        无 style 重载
  → TextLayoutService.trimStringToWidth(text, w, mode, ...) RICH 分支按 currentSettings().getCharSize() 裁剪
```

`TextLayoutService` 无 style 重载的 RICH_TAGS 分支显式使用 `(int) currentSettings().getCharSize()`
作为裁剪字号；只有带 `TextMeasureStyle` 的重载才用 `resolvedStyle.getFontSizePx()`。
节点字号等于 charSize（默认演示恰好是 16px）时结果碰巧正确，非默认字号下省略号裁剪宽度错误。
`SceneTextMeasurer` 是字号感知契约（`trimToWidth` 签名带 `fontSizePx`），adapter 却选择丢弃它——
这是「三层测量接口 + 接口 default 算法」抽象问题的直接后果。

**修复**（`TextMeasureServiceSceneAdapter.trimToWidth`）：改走带 `TextMeasureStyle(fontSizePx, ...)` 的
style 重载，与同文件 `lineHeight(text,...)`、`linkRegions` 的字号传递方式对齐。
测试：`TextMeasureServiceSceneAdapterRichModeTest` 的 trim 委托断言改为 style 口径，
新增 `shouldDelegateTrimToWidthWithFontSizePx` 锁死字号透传。

## 4. A1：HUD 平行管线与特殊编码（高）

`SceneHudHost`（client/hud，255 行）在 scene 主机管线之外平行重建了一套精简管线：

| 现象 | 证据 | 问题 |
|---|---|---|
| 平行 render 循环 | `SceneHudHost.render` 手写 snapshot→accept→flush→layout→paint→replay | 绕过 `SceneFramePipeline` 的 11 阶段协议（INPUT_DRAIN/SETTLE/HOVER_RECONCILE/DISMISS_INVISIBLE…），布局收敛、悬停重算等既有语义在 HUD 里都没有 |
| 手工翻译层 | `RetainedHud.createLine/createSpan` 写死 row/label/track/fill 四节点模板 + 每字段一条 `bindComputed` | HUD 内容被钉死在「行/片段/色调/进度槽」四件套，无法使用任何 scene 控件 |
| 硬编码主题 | `RetainedHud.color(HudTone)` switch 硬编码 6 色 | 与 scene 主题 token（SceneChromeTokens）脱节 |
| 专用锚定布局器 | `HudLayoutEngine` 四角锚定 + 堆叠数学 | 与 `scene.overlay.SceneAnchorResolver` 两套锚定实现并存 |
| 缩放装饰器 | `ScaledHudBackend` 20+ 方法全转发 + 逐参 `p()` 缩放 | 样板装饰器，可一般化为 backend 层 `scaled(float)` |
| 构造样板 | `SceneHudHost` 构造 4 件套（measurer/runtime/layout/paint/replayer）与 `AbstractSceneHostWidget` 构造逐行相同 | 复制样板 |

值得肯定：`HudRegistry`（封板快照、重复 id 拒绝、provider 异常隔离、registration 句柄）、
`HudGlStateGuard`（GL 状态围栏）、`ClientHudService` 反射隔离客户端实现、`HudInsets/registerAvoidance`
安全区协议都是正确设计，**不属于**要移除的特殊编码。

**处置**：单独成规划《HUD虚拟窗口规划》（docs/开发者文档/规格文档/），目标态 = HUD 锚定虚拟窗口，
注册协议从数据快照改为窗口工厂，直接跑 scene UI 代码。

## 5. A2：文本测量三层接口（高）

现状三层：`TextLayoutService`（渲染层唯一真相）→ `TextMeasureService` + `DefaultTextMeasureService`
（UI 层接口）→ `SceneTextMeasurer` + Adapter（scene 窄门面）。问题不在层数，在**接口 default 方法承载算法**：

- `TextMeasureService.getStringWidth(text, TextMeasureStyle)` default 实现用
  `rawWidth * fontSizePx / getLineHeight()` 线性缩放，与 `DefaultTextMeasureService` 的
  「逐码点按 effectiveSize 精确测量 + ceil」语义分裂；富文本段内字号变化（`<size>`、上下标）default 路径完全丢失。
- `trimStringToWidth(text, w, style)` 的 default 实现先把 UI 像素宽度折回 raw 坐标系再裁剪——比例近似，
  与渲染层按字号直接测量在非基准字号下数值不一致。
- 三套样式对象并存：`paint.TextStyle`（color+fontSize+int mode）/ `TextMeasureStyle`（4 字段）/
  `font.layout.TextStyle`（17 字段）；`TextMeasureStyle.DEFAULT.fontSizePx=18` 与
  `SceneLabel.DEFAULT_FONT_SIZE_PX=16`、`SceneNode` 默认 16 **三处默认字号不一致**。
- `Adapter.splitLines` 用 `Integer.MAX_VALUE` 当「不换行」sentinel 偷换「硬换行拆行」语义，
  接口 Javadoc（<=0 不换行、返回至少一行）与实现（硬换行拆多行）不符。
- 两套同构 `TextLinkRegion` record（ui.text vs scene.text）经 adapter 徒手搬运——这是 scene core 平台无关
  边界（I10）的合理接缝税，**保留**，但需编译期断言锁字段同步。

**建议**：目标架构 = `TextLayoutService` 唯一真相 + `SceneTextMeasurer` scene 窄门面两层；
`TextMeasureService` 剥掉全部算法性 default，降级为旧 ui 消费者的纯转发兼容门面（可与 Default 实现合并），
adapter 直连 `TextLayoutService` 减少一跳。

## 6. A3：font 层重复与抽象缺口（高，摘要）

- **码点推进 + 字距累加原语 6+ 处重复**：`TextLayoutService` 的 getSegmentWidth×2 / measureTokenWidth /
  trimRich×2 / wrapRich 与 `DefaultFontRendererAdapter.prepareGlyphs/drawPreparedText` 各自重写
  「codePointAt → 取宽 → 加 letterSpacing」；render 侧 `(codepointWidth + letterSpacing) * renderScale`
  与测量侧口径靠注释保证一致。→ 提取 `GlyphAdvanceAccumulator` 统一遍历器。
- **字号换算公式散落**：`charSize→fontSizePx` 缩放比在 TextLayoutService / DefaultFontRendererAdapter /
  GlyphRenderBatch / FontBatchRenderer 四处各自实现，分母别名（getCharSize/getAwtCharSize/defaultGlyphSize）
  表达同一物理事实。→ `FontScaleUnit` 唯一定标器。
- **三套 trim/wrap 平行实现**：UILIB_RAW / MINECRAFT_FORMATTED / RICH_TAGS 各自拥有独立 trim/wrap，
  循环结构高度同构；`sameRichStyle` 手写 equals 与 `RichTextTagParser.appendStyleDiff` 是两套「样式 diff」真相源。
  → `TextContentModeStrategy` 策略接口。
- **TextStyle 三职合一**：可变状态机（applyFormat）+ 领域值对象（13 字段）+ 序列化（toFormattingCodes），
  render 侧每 glyph 共享可变引用。→ 拆 `FontStyleSpec`（不可变）+ `MinecraftFormatState` + `StyleFormatter`。
- **GlyphPageManager 超大**（1903 行，约 60 字段）：glyph 生命周期 + mailbox 背压 + atlas 所有权 +
  上传限速 + 统计五职一体，状态机**无直接单元测试**。→ 拆 GlyphMailbox / AtlasPageAllocator /
  GlyphDemandRegistry / GlyphStats。
- **FontBatchRenderer 手工平行数组**：6 组数组 + byte 编码 FontType 模拟 Map；4 个 grow 重载同构复制。
- **GlyphPage 批/非批上传双轨**：`batchActive` 布尔分支 + 状态守卫样板 4 处重写。→ `GlScope` 模板方法。
- **跨层宽度一致性契约测试缺失**：measure 累加 = render measuredWidths 累加 = 视觉 quad 宽度无恒等断言，
  口径漂移只能真机发现（历史「横排挤字」回归佐证）。→ 补 `WidthConsistencyTest`。

## 7. A4：双 UI 体系与旧栈残留（高，摘要）

主役 = scene 全链路（测试 130+ 文件）；旧 Widget 栈仅剩宿主壳价值。经引用关系抽查确认：

- **`ui.base.layout` 半成品**：`UiLayoutSpec/UiConstraints/UiMeasureResult` 仅被 `Widget` 单向引用，
  `Widget.measure()` 全仓零调用、`UiInsets` 零外部引用——纯规格无引擎。→ 删除（保留 `UiLength`，
  被 `UiTransform` 使用）。
- **旧输入栈 `ui.input` + `ui.event`**：`UiInputRouter` 仅 `UiScreenHostSession` 引用；`Ui*Event` DTO 仅
  input/widget 内部使用；scene.input 已是功能超集（capture/overlay/focus-manager/hit-test）。
  → MC 键盘/lwjgl 适配下沉为 scene `PlatformInputSource` 实现后整体退役。
- **`UiRenderContext` 双身份**（1374 行）：既是旧 Widget 直绘上下文，又是 `UiRenderBackend` 的 MC 实现。
  → 拆分为纯 backend 实现 + 旧直绘残留（随 Widget 栈退役删除）。
- **Widget 寄生**：`AbstractSceneHostWidget extends Widget`，另有 ViewportWidget / ModernConfigEntry /
  TestPlaygroundHost 直接继承，`club.heiqi.config.ui.ConfigScreen` 经 AbstractSceneHostWidget 间接。
  → scene 宿主改 `implements UiSurface`，Widget 收缩为纯宿主壳（波及 config.ui，需一并评估）。
- **`UiRenderBackend.drawImage` 的 `instanceof HostImageSource` 分支**：宿主类型泄漏进 scene 出口契约，
  违反「core 不依赖宿主」边界。
- **`ReactiveTestProbe` 误入 main**：仅测试使用（ConfigReloadAndPrefillRegressionTest / SceneKeyValueMapTest /
  SceneObjectFieldTest）。→ 迁 `src/test` 或 scene/testkit。

## 8. SceneLabel / SceneNode / PaintCommand（中，摘要）

- **`SceneLabel.Props` 12 字段 + 4 级联构造器**：LEFT/TOP 与尾参默认值重复 4 次，新增字段要改 4 构造器 +
  create() setter 链。→ 分组 props（TextSpec/ClampSpec/AlignSpec）+ 有界 builder。
- **`SceneNode` 文本字段平铺**：text/maxTextWidth/lineHeight×2/maxLines/ellipsis/activeLinkUrl 7 字段直接
  在通用基类，而 paint/layout 属性已抽 `ScenePaintProps/SceneLayoutProps` 容器。→ 对称抽 `SceneTextProps`；
  `activeLinkUrl` 归交互投影组。
- **`PaintCommand` 21 参私有构造器神对象**：16 种命令类型共用扁平字段，10 个 PUSH/POP 工厂重复 8 参
  默认值尾巴。→ 按类型子结构或 payload value object；至少收敛 push/pop 工厂区。
- **LINK_REGION 复用 text 字段带 URL**：破坏字段单一语义（getText() 对 LINK_REGION 返回 URL）。
  → 独立 linkUrl 字段，或把命中区域从命令流拆为 `PaintFragment` 平行结构。
- **clamp 双份执行**：`SceneLineClamp` 在 ScenePaintEngine 与 SizingCalculator 各自调用（含省略号裁剪两次）。
  → 布局阶段一次性产出 `TextLinePlan`（拆行+clamp+link 区域）缓存于节点，绘制消费。
- **link 命中反查 fragment**：SceneLabel handler 读 `root.getCachedPaint()` 强转 PaintFragment 遍历命令做
  矩形包含，绕开 SceneInputRouter 权威命中；`activeLinkUrl` hover 翻转整 fragment 标脏重绘。
  → 命中数据正式化进布局/绘制结果，路由器统一决议；高亮走局部重绘位。
- **`resolveLineHeight` 双口径**：绘制/布局各自算 base 再传 resolve，multiplier 分支 per-line ceil 与
  px 分支全行强平语义不一致（混排行 1px 级漂移隐患）。
- **`paint.TextStyle` int 模式码 5 处并存**（paint/splitLines/adapter/SceneNode/TextContentMode），
  `mapTextMode` 与 `normalizeTextMode` 各写各的 switch；SceneLabel.Props Javadoc 漏写 1=MINECRAFT。
  → scene 层定义 `SceneTextMode` 枚举统一。

## 9. 正面评价（架构优点，保留不动）

- **scene core 平台无关边界执行严格**：编译期零 LWJGL/Minecraft import，平台输入只经适配边界进入。
- **PaintPlan 自包含不可变绘制计划** + replayer 必须恢复其触碰的 GL 状态——渲染契约清晰。
- **响应式 state/signal 驱动**：输入 handler 不直接改节点属性；Router 受控入口。
- **注册表模式**（HudRegistry）：封板快照、重复 id 拒绝、provider 异常逐项隔离。
- **GL 状态围栏**（HudGlStateGuard/FontRenderStateGuard）、font generation/版本隔离、skyline 打包算法。
- **测试密度高**：297 个测试文件、~3051 用例，scene 控件与布局覆盖充分。
