# 统一图像接入

普通控件和文档图像共用 `ImageService`。Minecraft 宿主从 `MinecraftImageServices.shared().images()` 提供正式共享服务；其他宿主装配 `ClientImageServices` 与 `JavaImageLoader`。关闭页面不关闭共享客户端 owner。

在已有响应域/页面构造入口创建控件：

```java
Signal<ImageSource> source = domain.signal(ImageSource.resource("minecraft:textures/blocks/planks_oak.png"));
Signal<ImageOptions> options = domain.signal(ImageOptions.defaults()
    .size(Size.fixed(80), Size.natural()).alt("橡木纹理"));
SceneNode image = SceneImage.create(service, source, options);
context.mount(image);
```

来源包含资源标识/像素 region、`ImageSource.bitmap(new ImageContent(width, height, rgba))` 和 HTTP/HTTPS。RGBA 是不可变 straight RGBA8，构造后可释放原始数组；发布新内容时创建新的内容对象并写入来源 Signal，框架自动重测。区域的自然尺寸仅为选区尺寸。业务不传 GL handle、不上传纹理、不实现下载缓存。

`SceneImage.state(image)` 是可绑定只读状态，含来源、request、LOADING/READY/FAILED/UNSUPPORTED、stage 和 diagnostic。未知尺寸使用默认 32×32 占位；`ImageOptions` 可覆盖。失败占位保留 alt 和布局。`SceneImage.create(..., placeholderNode)` 使用正式 scene 子树占位，盒由图像声明的占位尺寸分配。

默认 contain/center，可选 cover、stretch、native 与对齐。cover 裁目标盒，native 沿有效祖先裁剪，命中沿正式图像盒。fixed/natural、宽高 fill、明确单边比例与 min/max 使用 Size。`height=Size.fill(1)`、`width=Size.natural()` 使用实际分配高度和来源比例求宽；根视口、行交叉轴和列剩余高度均参与同一正式布局。未知来源只使用占位尺寸，不假造比例。固定单边先按声明值推导另一边，再分别限制 min/max；fill 按实际有限分配反推。

`SceneImage.documentImage(service, source, options)` 是文档图像接入入口：自然大图缩至可用宽度，小图不默认放大，明确尺寸覆盖。`ImageSource.parse(uri, itemResolver)` 解析 resource:/HTTP(S)/item:；无效 URI 进入 resolve 失败，缺物品适配进入 unsupported。当前没有 Markdown 全文 parser。

安装、重载、帧资源入口和退出均接入正式宿主。`SharedImageService.drain()` 仅限宿主线程，worker 经有界入口再向各 domain.enqueue 发布。自定义 SceneHost 在 prepareResources 推进同级客户端 owner。订阅由 NodeBinding 挂载 owner 释放，consumer 无需逐帧读取缓存。

默认预算：worker 2、队列 32、缓存条目 128、共享 RGBA 64 MiB；HTTP/资源编码 8 MiB、解码 16 MiB，解码前检查维度。HTTP connect/read 各 3 秒，每次尝试总时限 10 秒，仅网络 I/O 或 502/503/504 重试一次，间隔 100ms，不跟随重定向。GL 缓存 64 张/32 MiB，每次 prepare 最多上传 4 张/16 MiB；等待上传使用 loading 占位，错误归属本图像的 upload 失败。

Minecraft 物品使用专用来源，声明时深复制 ItemStack 的 NBT、数量和 damage。每次回放直接调用原版 `RenderItem.renderItemAndEffectIntoGUI`，保留 Forge inventory hook 和动态附魔效果；核心不依赖 Minecraft 类型，也不把图标冻结为位图。

```java
Signal<ImageSource> item = domain.signal(new MinecraftItemSource(stack));
Signal<ImageOptions> itemOptions = domain.signal(ImageOptions.defaults()
    .size(Size.fixed(64), Size.fixed(48))
    .quantity(true).durability(true).tooltip(true));
SceneNode icon = SceneImage.themed(service, item, itemOptions, theme);
context.mount(icon);
// 外部 stack 变更后发布新快照，控件身份保持不变。
item.set(new MinecraftItemSource(updatedStack));
// 物品自定义 tooltip 等外部事实变化，也可显式通知现有来源重新准备。
service.reload(item.get());
```

三个选项各自独立、默认关闭；声明物品不产生 click、capture、focus 或库存操作。数量/耐久和提示分别进入同一 PaintPlan 的 TEXT/RECT 与末端被动 overlay，字体资源由同一可见帧收集。提示由当前指针、有效范围及同代几何决定，框和裁剪由运行时控制，不拦截底层点击。`themed` 绑定主题及字号；语言/资源包重载重新准备来源事实。ItemStack 外部变化不会自动追踪，必须发布新来源或使用正式 reload 通知。

`ImageSource.parse("item:minecraft:diamond", MinecraftItemSource::parse)` 可用于文档物品 URI；缺宿主物品解析/绘制适配报告 UNSUPPORTED。物品事实准备及原版绘制异常只使该来源进入 FAILED，包含 source、request、stage；不会关闭整页。

验证入口 `imageServiceScenario` 使用真实本地 HTTP 与 scene；`imageGlScenario` 验证实际图像像素及字体借用压力；`imageLwjgl2Scenario` 在真实 LWJGL2 compatibility context 验证 IMAGE 像素和 item scope 正常/异常状态归还。scope 对 Angelica 有效缓存与 raw driver 分别保存，不假定两者入口相同。

人工包 `/qzcore` 保留编辑和字体场景，并提供来源/stage、fit、动态图像、HTTP重载、文档图片、高度 fill、钻石/附魔工具切换、数量/damage变化及三个可选开关。数量/damage变化发布新的来源快照，F3+T重新准备图像和物品提示。当前没有 Markdown 全文 parser；上述接口供文档控件接入，不代表完成全文解析。游戏运行和 Forge/Iris/mod 物品兼容没有本轮实测证据。
