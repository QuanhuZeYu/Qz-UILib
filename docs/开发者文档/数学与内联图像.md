# 数学与内联图像

本阶段为自有数学解析与数学盒布局，支持范围及失败合同以[文本规格第 1.4.1–1.4.2 节](<../superpowers/specs/2026-10-07-uilib-text-content-spec.md>)为准。完整固定 KaTeX 对照目标仍在后续矩阵中，不能将未知命令的源码回退当作支持。

LaTeX 扩展声明示例：

~~~tex
\int_0^1 \frac{\embed{ore}}{1+x^2}\,dx
x^{\embed{crystal}} + \sqrt[3]{\embed{fuel}+1}
~~~

业务将 ore、crystal、fuel 绑定到独立 SceneImage 节点，并声明当前数学 em 下的宽、高及顶部基线。MC 物品来源由宿主 MinecraftItemSource 提供，数学核心不接受 ItemStack 或绘制回调。不同标识可以共享图像资源，不能共享一个挂载节点；同一标识在一条公式重复使用会诊断并显示完整原文。

竖向伸缩优先使用数学字体提供的真实完整字形；超过完整变体时沿 OpenType MATH 的连接部件构建大型根号及定界符，部件轮廓不拉伸。没有可用变体/部件或超出实际资源/整数几何能力时，保留整条公式原文并提供定位诊断。显示型积分、求和及乘积选择真实的大算子字形；字体没有达到建议高度的变体时取最大完整字形，其大小沿字体真实度量，不拉伸成假造尺寸。

脚本缩放改变内联盒尺寸；启用的物品数量覆盖层沿最终图像区域自动缩小，保留图像控件声明的字体和字号上限，按实际字形墨迹对齐右下角。悬浮提示仍沿图像控件独立主题及字号声明。诊断后的原文回退仍需要正常文字字体可用；显式空候选列表会沿字体服务既有失败合同拒绝生成，不偷偷追加默认字体。SceneMath 沿既有整数场景坐标工作，嵌入度量和公式局部范围（含 padding）应能用整数几何表示；极大但有限的 em 度量尚未提供场景整数溢出的诊断回退。公式宽于视口时沿页面裁剪/滚动，当前不拆公式软换行，也不承诺任意 SceneNode natural/min/max 测量。

## 接入正式场景

在现有 `ScenePageContext ctx` 内创建图像及公式。示例的资源服务由宿主提供，数学核心只接收图像节点和 em 度量：

~~~java
Signal<SceneTheme> theme = ctx.domain().signal(SceneTheme.dark());
Signal<ImageSource> source = ctx.domain().signal(
        new MinecraftItemSource(new ItemStack(Items.iron_ingot, 32)));
SceneNode ore = SceneImage.themed(MinecraftImageServices.shared().images(), source,
        ctx.domain().signal(ImageOptions.defaults().tooltip(true).quantity(true)), theme);
Map<String, SceneMath.Embed> embeds = Collections.singletonMap("ore",
        new SceneMath.Embed(ore, new MathEmbedMetrics(1, 1, 0.8f)));
Signal<MathContent> formula = ctx.domain().signal(MathContent.parse(
        "\\int_0^1 \\frac{\\embed{ore}}{1+x^2}\\,\\mathrm{d}x"));
SceneNode math = SceneMath.create(ctx, formula, theme, MathStyle.DISPLAY, embeds);
ctx.mount(math);
~~~

示例把公式作为页面根挂载；接入已有根时使用已有根的 `add(math)`，再由页面原有挂载声明统一管理。数学源码只在 `MathContent.parse` 时解析，字号或主题变化复用内容结构。图像来源变化发布新 `MinecraftItemSource`；重复出现的物品可以共享资源身份，但每个位置需要独立节点及不同标识。`SceneMath.layout(math)` 返回当前不可变的数学逻辑坐标、尺寸、基线与诊断，首次呈现前及卸载后为 null。`smash`、重叠盒或字形墨迹越过逻辑占位时，独立控件会按完整呈现包络分配自然尺寸并统一平移外层原点；实际场景定位使用同代 `SceneGeometryView` 及其文字投影，不把逻辑坐标直接加到场景位置上。不要在绘制过程中把布局结果写回信号。

## 当前命令子集

| 类别 | 命令 |
| --- | --- |
| 结构 | 分组、`^` / `_`、`\frac` / `\dfrac` / `\tfrac`、`\sqrt` 及根指数、`\binom`、`\left` / `\middle` / `\right` |
| 算子 | `\int`、`\sum`、`\prod`、`\limits` / `\nolimits`、`\sin` / `\cos` / `\tan` / `\log` / `\ln` / `\exp` / `\lim`、`\operatorname` 及带星形式 |
| 样式 | `\displaystyle` / `\textstyle` / `\scriptstyle` / `\scriptscriptstyle`、`\mathrm` / `\mathit` / `\mathbf` / `\mathnormal` / `\text` |
| 间距 | `\,`、`\:`、`\;`、`\!`、`\quad` / `\qquad`、反斜杠空格 |
| 符号 | `\alpha` / `\beta` / `\gamma` / `\delta` / `\theta` / `\pi` / `\sigma` / `\omega`、`\infty`、`\cdot` / `\times` / `\pm`、`\leq` / `\geq` / `\neq`、`\rightarrow` / `\to` |
| 扩展 | `\embed{标识}`，每个标识在一条公式仅出现一次 |

未登记命令与环境会保留整条源码并定位诊断。数学字形仍依赖所选正式数学字体的实际覆盖；源码能解析不代表任意字体均可生成字形。

## 伸缩结构示例

~~~tex
\left\{\dfrac{1}{\dfrac{\embed{ore}}{1+x}}\middle|\binom{n}{k}\right\}^{2}
\sqrt{\dfrac{1}{\dfrac{1}{\dfrac{\embed{fuel}}{1+x}}}}
\binom{\embed{top}+n}{\embed{bottom}}+\left.\frac{x}{1+x}\right|_{x=0}
~~~

每个标识仍需独立绑定 SceneImage。left/right 与 middle 必须在同一数学分组；可以嵌套、左右符号不同、同层多个 middle，点号表示不可见边界。不可见边界的 .12em 空间按根主题字号计算，script 样式不再缩小；token 别名表见所属文本规格第 1.4.2 节。binom 无分式横线，当前不支持 dbinom/tbinom 或 matrix/cases/array 环境。

## 实机操作

新数学能力由用户启动游戏后验收，离线字体和 GPU 场景不代表 MC/GTNH 物品兼容通过。已实现人工入口 `/qzcore math`，普通与 GTNH 实例各自执行：

1. 打开页面，确认积分分子、求和上下限、根式及双脚本中的物品与公式一起排列；向下滚动检查新增花括号与 middle 竖线、二项式、大根式及不可见左边界的代入公式。
2. 悬停物品，确认既有提示；点击“物品：铁锭”切换附魔工具，检查附魔效果与耐久，再切回铁锭检查数量。
3. 点击“字号”和主题按钮，再缩窄游戏窗口；检查物品盒、分式线、根号和上下限随数学字号变化，滚动后被裁剪物品不触发提示。
4. 点击“非法公式”再“读取公式诊断”，应显示完整原文及 parse 位置；点击“恢复积分”再读诊断，应恢复有效公式及图像。
5. F3+T 重载资源后重新检查公式与物品；关闭并重新打开，确认没有旧悬停或重复物品。

当前真实字体 8、数学布局 9、正式场景 8、GPU 4 场景，全部通过。GPU 在 18 与 28 字号下观察到大型花括号/竖线/根号的真实多 glyph 拼接，部件 ink 范围无空白整行连接裂缝；仍使用原字体资源光栅与重载生命周期。GPU 使用中性 RGBA 图像验证字形/图像/规则线/裁剪像素和动态/回退图像；用户随后提供了铁锭数量与附魔工具在积分/求和/根式/双脚本中的实机截图，并反馈效果不错；该反馈未区分普通/GTNH实例。新的伸缩结构另行验证和收集实机反馈。

真实物品原对象修改应发布新 MinecraftItemSource，既有来源会复制 ItemStack；数学引擎不会轮询宿主注册表或可变 NBT。
