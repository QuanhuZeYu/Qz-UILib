# 内聚优化双实例验收

本轮交付沿既有 UILib 状态、场景、字体和输入管线，优化关闭收尾、编辑文字事实、宿主提示转换与图像同代分支。自动场景和 GPU 验证记录属于实现证据；普通 1.7.10 与 GTNH 的实际游戏验收分别记录。

## 操作入口

在两实例分别启动游戏、进入世界后执行 `/qzcore`。人工附加包安装该入口，正式包不包含开发工具。页面的单多行字段、图像区域与富文本按钮均为已有正式控件。

1. 单行字段输入组合字符和 emoji，使用左右键、选择、删除及撤销；光标不切开组合字素。切换字号、主题和窗口尺寸，正文及光标保持对应。焦点在字段时关闭页面，再打开，检查外部业务值、草稿与新页面输入继续有效。
2. 在多行正文点“恢复样例”，用 Enter、上下键和跨行选择查看编辑；滚动正文、缩窄窗口，再关闭重开。检查软换行不写回正文、文字裁剪和选择保持一致。
3. 向下滚至图像区域，切换 fit、更新动态图像，再选附魔工具并分别启用数量、耐久及悬停提示。改变数量、损耗、字号、主题及窗口，检查图标成功时覆盖层存在，提示文字随当前样式更新并位于页面内容之上，图标的附魔效果持续变化。
4. 执行 F3+T 重载资源，观察图像加载/失败占位、当前提示和后续正文。HTTP 来源若受网络限制，记录来源诊断；资源包纹理及动态图像仍须继续显示。失败占位保持目标区域，其他控件和输入继续工作。
5. 执行 `/qzcore rich`，按[富文本接入指南](<富文本接入与双实例验证.md>)短批次验证样式、动态排版、裁剪与链接。

反馈注明实例与操作顺序。通过可按上述项回复；异常说明预期和实际，附截图或对应日志。未收到操作反馈时，交付记录保持待实机验收；自动 GPU 场景不替代 Minecraft 物品渲染及模组兼容验收。
