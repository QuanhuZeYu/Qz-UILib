# 基础富文本与链接接入

最终能力方向和本轮支持范围见[文本规格](<../superpowers/specs/2026-10-07-uilib-text-content-spec.md>)。当前提供基础属性文本与链接；Markdown、HTML、数学及图像标签接入保留在后续阶段，不能把本轮子集称为完整 VS Code 兼容。

## 明确内容模式

页面通过 TextContent 明确选择内容的解释方式，普通 SceneLabel 仍接收字面字符串：

```java
import club.heiqi.uilib.ui.reactive.Signal;
import club.heiqi.uilib.ui.scene.text.TextContent;
import club.heiqi.uilib.ui.scene.control.SceneRichText;
import club.heiqi.uilib.ui.scene.control.SceneTheme;
import club.heiqi.uilib.ui.scene.node.SceneNode;

// 正式页面构造回调内；page 是 ScenePageContext。
Signal<TextContent> content = page.domain().signal(TextContent.richTags(
    "<b>标题</b><br/><color value=\"#3388CC\">正文</color> "
    + "<a href=\"example:details\">查看详情</a>"));
Signal<SceneTheme> theme = page.domain().signal(SceneTheme.dark());
Signal<String> lastTarget = page.domain().signal("尚未激活链接");
SceneNode article = SceneRichText.create(page, content, theme,
    target -> lastTarget.set(target));
```

将节点加入布局并 mount 的方法见[页面接入](<声明式页面接入.md>)。修改 content 或 theme 由正式状态域处理，文字、行高与链接命中自动更新；业务不用测量文字或维护片段区域。

- TextContent.plain(source)：不解释 §、DSL 或 Markdown 标记；换行、Tab 和 Unicode 整形继续沿字体能力。
- TextContent.richTags(source)：解释下列基础 DSL，§ 与 Markdown 语法仍为字面内容。

## 基础声明与链接

| 声明 | 用途 |
| --- | --- |
| b、i、u、s 成对标签 | 粗体、斜体、下划线、删除线 |
| color value="#RRGGBB" 或 "#AARRGGBB" | 不透明 RGB 或显式 alpha 文字颜色 |
| size value="字号" | 沿统一字体范围的正有限 logical px 字号 |
| a href="目标" | 为内容声明链接，激活向回调发布目标 |
| br 自闭合标签 | 使用 `<br/>` 声明显式换行 |

使用小写标签、具名属性及双引号属性值，正常嵌套和重复样式在闭合后恢复外层。使用 `&lt;`、`&gt;`、`&amp;` 表达字面尖括号与与号，解码后的文字不会再次识别成标签。基础子集未定义任意 HTML 属性或旧简写兼容。

没有声明基准位置解析时，链接目标保持原值。回调可修改业务状态或交给业务自己的导航，框架不会自动打开浏览器。一个链接跨行时，各可见文字片段都发布同一目标；非链接正文、行尾空白和裁剪掉的部分不能激活。正常嵌套链接使用内层目标，闭合后恢复外层。按下与释放必须属于同一有效声明，内容替换或卸载不会复活旧手势；仅窗口或基础样式重排仍保留该声明身份。

PLAIN/RICH_TAGS 源码声明需要持久化时，可使用 `content.get().resolve(baseStyle).serializeRichTags()` 取得规范 DSL 源码，再以 `TextContent.richTags` 读取；保留支持内容的语义，不要求字节一致。UILib 不提供 Minecraft 格式模式；§ 与其后字符按字面内容参与往返，不转换成样式。

非法或未知 DSL 产生定位到原来源范围的诊断后，整段原文按 PLAIN 显示，且没有链接，不自动补标签或修复错配。业务无需捕获解析错误才能继续显示正文；非法内容也不能默默显示成已成功解析。

## 已转换的样式内容

宿主或内容转换器可使用 `StyledText`、`TextStyleOverrideSpan` 和 `TextContent.styled` 提交稳定样式意图。它们保留来源关系；未声明的字体、字号及属性继承当前基础样式，RGB 意图可继承当前透明度。业务页面仍使用同一个 SceneRichText、布局和输入管线，不需要宿主格式模式。

字重与字姿以 `FontStyle` 为准，`TextEffects.bold/italic` 只是旧构造输入的规范化视图。Typed 样式声明可能包含 DSL 尚未支持的属性，因此 `serializeRichTags()` 对该入口明确报告不支持，不能把这些属性静默丢掉；PLAIN/RICH_TAGS 源码声明的往返不变。

## 双实例短批次验收

由用户分别启动普通 1.7.10 和 GTNH 测试实例，进入世界执行 /qzcore rich；也可从核心页打开富文本页。正式包与人工附加包须来自本轮交付，不以旧页或独立 GL 出图替代游戏实机结果。

1. 点“模式：…”切换 PLAIN 与 RICH_TAGS，观察基础样式、嵌套恢复和实体。PLAIN 显示标记，RICH_TAGS 解释 DSL；两种模式均将 § 格式码显示为字面正文。在 RICH_TAGS 下点“非法样例”，整段显示原文并报告来源范围，再点“正常样例”恢复。
2. 保持页面打开，缩窄窗口并点“字号：…”和“浅色主题／深色主题”，观察换行、行高、粗斜体和装饰随变化更新。点“长内容”后在正文视口及外层页面滚动，观察裁剪。
3. 在 RICH_TAGS 正常样例下点击跨行链接的可见片段，观察“点击次数”和“最近目标”；A 发布相对目标，内层 B 发布业务目标。点正文或空白，计数不增加；裁剪隐藏内容不可点击。按住 A 拖到 B 松开，不激活；点“禁用链接”后点击可见链接，计数不增加。

正常反馈实例名及各项通过即可。异常说明操作顺序、预期与实际，附截图；崩溃附该实例的相关日志。自动测试结果与这里的实际操作反馈分别记录，未收到反馈时保持待实机验收。
