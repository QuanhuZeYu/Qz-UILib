# Qz-UILib HTML-like 当前建议

本文是协作开发阶段的技术建议与方向文档，只保留当前主线、取舍原则、阶段优先级和验收口径，不重复维护实现流水、已完成事项清单和属性/类级细节。

正式接入说明以 `docs/使用文档/` 为准；长期协作边界以 `docs/AI记忆文档.md` 为准；开放化边界以 `docs/开发者文档/开放化调整.md` 为准。

## 当前主线

- 继续把 HTML-like UI 从“可运行页面迁移”推进到“具备 CSS-like 动态语义的稳定渲染框架”。
- 优先保证业务页面、控件和宿主接入体验，而不是堆更多静态能力或底层炫技特性。
- 继续清退旧 retained 作者入口，避免新页面重新回到旧 `Widget` 组合模式。

## 取舍原则

- 默认优先推进真实页面迁移、控件可用性和开发者接入体验。
- inline formatting、effect chain、snapshot/filter、dirty subtree 等底层能力，只在阻塞真实页面、动画探针或控件展示时做最小必要收口。
- 不为了补齐“完整浏览器语义”而偏离 HTML-like UI 框架主线。
- 新增作者能力优先放在 `UiDocument`、DOM、样式系统、控件适配或 HTML-like 后端能力中，而不是回到旧 retained 作者入口。

## 动画方向

- CSS transition / animation 语义仍是重要能力，但应以可验证、可收口、可服务真实页面为目标，不默认继续扩面。
- paint/effect 动画不应触发布局；layout 动画才允许重排，且结束后应回到静态缓存路径。
- 是否继续扩展 layout-affecting 动画属性，必须先证明真实必要性，再补最小验证与使用文档。
- 动画运行值应保持为运行时覆盖层，不写回作者侧静态样式。

## 当前阶段优先级

1. 优先验证和收口真实页面、控件与宿主接入问题，尤其是背包 UI、表格、输入、滚动、命中、焦点和真实数据渲染。
2. 阻塞真实使用的视觉、交互或宿主适配问题，做最小必要修复。
3. 真实页面验证稳定后，再评估性能优化，例如 dirty subtree、细粒度缓存和更完整的 effect chain。
4. 持续清点旧兼容残留；确认没有 HTML-like 复用价值的入口后优先删除。

## 对真实页面的要求

- 普通 UI 优先使用标准 DOM、样式、布局、背景、边框和文本路径表达。
- 普通表面不要因为方便就回退到 `CUSTOM` 手绘。
- Minecraft 宿主专属能力应限制在真正需要宿主渲染或宿主交互的场景，例如物品图标、背包数据和相关 overlay。
- 背包槽位能力可以作为宿主示例开放，但不应主导普通 UI 的设计路径。

## 清理方向

- 继续收缩旧 retained 页面壳、旧 retained 控件、兼容容器和历史主题残留。
- 清理前先确认 backend、runtime、inventory 宿主适配能力是否仍被 HTML-like 路径复用。
- 命名和目录调整以减少“旧作者模型”痕迹为目标，但不要为了表面整洁误删仍在使用的基础能力。

## 验收口径

- 每批开发都应至少保持 `git diff --check`、`test`、`compileJava` 可通过；需要游戏内确认的能力再使用 `runClient21` 验收。
- 动画相关工作不能只停留在底层测试，至少要有可见探针或等价的端到端验证路径。
- 删除旧入口或清理兼容层前，要确认诊断入口、业务文档入口和仍在维护的示例页没有被一起破坏。
- 新增底层能力时，不得把宿主渲染细节直接暴露到作者层 API。

## 使用方式

- 本文只提供阶段建议，不作为现状事实表。
- 遇到具体能力、入口、类名、行为边界时，先读 `docs/使用文档/`、相关源码和 `docs/开发者文档/errors/README.md`，不要把本文当作细节来源。
