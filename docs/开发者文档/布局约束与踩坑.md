# scene 布局约束与常见踩坑

> 面向框架维护者与 AI 协作 Agent：写任何「控件或演示页」之前先读完本节。
> 全部规则都有既有控件先例；违反它们不会报错，只会在真机上静默漂移。

## 0. 一句话宽度模型（决定大多数布局 bug）

`SizingCalculator.computeWidth` 的宽度决策优先级：

```text
preferredWidth(显式钉死) > percentWidth > 容器 widthSizing(SHRINK 按内容回收)
  > 文本叶 shrink-to-fit > 无文本叶/默认容器 fill(拉满约束宽)
```

- `SceneNode.WidthSizing` 默认 **FILL**：容器宽 = 父级下传的可用宽。
- **FILL 不是 bug**，是引擎默认语义（历史零回归）；问题永远出在「把 FILL 用错了地方」。
- 想「按内容宽排布」，用 `WidthSizing.SHRINK`（或 `preferredWidth` 钉死固定宽）。

## 规则 1：ROW 行内的控件必须显式 SHRINK 或 preferredWidth

按钮、徽标、开关等「一行放几个」的控件根节点是容器，默认 FILL。放进
`SceneNode.row(...)` 后，`ConstraintResolver.buildChildConstraints` 的 ROW 回退分支
给非 grow 容器子下传行内宽，FILL 后每个控件宽 = 整行内宽 → 第一个占满整行、
后面的被挤出容器右缘（真机症状：按钮在容器最右侧、只露圆角边缘）。

```java
// 反例（会静默溢出，截图「按钮跑到最右侧」）：
SceneNode row = SceneNode.row(8);
row.appendChild(sceneButtonRoot);          // 按钮根默认 FILL → 拉满整行

// 正例（既有控件全部如此，二选一）：
sceneButtonRoot.setWidthSizing(SceneNode.WidthSizing.SHRINK); // 按内容宽
// 或
sceneButtonRoot.setPreferredWidth(180);                     // 钉死固定宽
```

既有先例（照着抄即可）：SceneDialog.buildButton SHRINK（SceneDialog.java:196）、
VariantChooser back/confirm（:267/:280）、SceneSimpleList :709、SceneKeyValueMap :587、
SceneObjectField :827、SceneBreadcrumb segBtn :130、SceneRadioGroup option :145、
SceneToggleablePrimitive root :78、SceneTooltip root :186、测试场地 PlaygroundKit
applyButtonSizing。

## 规则 2：勿对已 mount 挂载的控件再次 appendChild

`rt.mount(parent, supplier)` 的语义是「挂载到 parent 并返回根节点」，
**根节点已被 append 进 parent**。对返回值再 `parent.appendChild(...)` 会把同一个节点
挂两份——`SceneNode.appendChild`（SceneNode.java:210）不做重复子去重。

```java
// 反例（children 双份，位置与命中漂移）：
SceneNode root = rt.mount(parent, SomeControl.create(rt, props)).getRoot();
parent.appendChild(root);   // 第二次 append 同一节点

// 正例：mount 已挂载，直接使用或设置返回的 root
SceneNode root = rt.mount(parent, SomeControl.create(rt, props)).getRoot();
root.setWidthSizing(SceneNode.WidthSizing.SHRINK); // 只改属性，不再 append
```

## 规则 3：COLUMN 里的内容宽徽标/小块用 SHRINK（STRETCH 会拉满）

COLUMN 容器默认 cross 对齐是 STRETCH：子节点交叉轴（宽）被拉满父内宽，
除非子节点在 cross 维度有显式 preferredWidth / percentWidth / WidthSizing.SHRINK
（FlexLayouter.positionChildren 的 STRETCH 豁免分支）。想要「小徽标、小标签」等
内容宽元素，必须显式 SHRINK（先例：ReactivePage.badge、SceneRadioGroup option）。

## 规则 4：行内想要「按钮靠右/两端撑开」用对齐或 spacer，不要用 FILL 推

- 靠右：`row.setMainAxisAlign(MainAxisAlign.END)`（先例：VariantChooser footer）。
- 两端：行内放 `flexGrow=1` 的 spacer 空节点（先例：FormActionBar 中段 spacer）。
- FILL 只能表达「占满整行」，不能表达「贴右」——贴右用对齐。

## 规则 5：ROW 内 flexGrow 子旁边不要放「容器型无 preferredWidth 的固定兄弟」

grow 分配需要「固定兄弟宽度可先验」（ConstraintResolver.computeRowGrowWidths）。
容器型、无 preferredWidth、无文本的兄弟无法先验 → 触发 WARN 且分配结果错误，
兄弟被挤出。让固定兄弟有 preferredWidth，或把 grow 隔离到固定兄弟全是
文本/固定宽节点的子行（详见 ERROR-20260815-scene-picker-panel-flex-grow-overflow）。

## 检查清单（写新控件/新演示页时逐条过）

- [ ] ROW 行内的每个按钮/控件根：SHRINK 或 preferredWidth？
- [ ] 对 mount 返回值没有再 appendChild？
- [ ] COLUMN 里的徽标/小块：SHRINK，而不是依赖 STRETCH 豁免？
- [ ] 行内 grow 的固定兄弟：文本叶或 preferredWidth 钉死？
- [ ] 布局改动后跑过 `PlaygroundButtonRowLayoutTest`（行子不越界/不重复/不重叠/SHRINK）
- [ ] 布局回归断言的是 LayoutBox（`cachedLayout`）实际值，不是「肉眼看着差不多」
