# 开放化调整

本文档用于说明 Qz UILib 从内部验证工程转向第一版开发者入口时的开放化边界与调整原则，不记录阶段流水、临时状态或已完成事项清单。

本文是开放化方案文档，不作为对外开发使用手册；开发者接入说明以 `docs/使用文档/` 为准。

## 目标

- 面向其他开发者提供清晰、低侵入的 HTML-like UI 使用入口。
- 将测试期入口从默认 UI 注入和全局热键迁移为显式开发者入口。
- 把业务 UI、诊断页、示例页和未来稳定 API 边界分开，避免外部开发者依赖内部测试结构。

## 文档分级

- `../使用文档/`：对外开发使用文档。
- `规格文档/`：示例页专属规格与专项方案定稿，不作为通用接入手册。
- `../反馈层/错误预防.md`：错误预防通则沉淀。
- `../设定值层/`：宪章指针、硬约束总目录、边界现状锚。
- `../诊断层/`：技术债、项目结构、Config 模块。
- `../反馈层/决策/`：关键取舍记录。
- `../反馈层/交接.md`：当前工作现场（唯一权威状态源）。
- `../README.md`：文档唯一总入口。

## 首版开放边界

- 公开推荐入口以 `UiDocumentScreens.createDocumentScreen(...)` 和 HTML-like 文档树为主。
- 控件、样式、布局和宿主接入边界以 `docs/使用文档/` 为准，不在本文件重复维护细节。
- 背包槽位能力可以作为 Minecraft 宿主示例能力开放，但不应成为普通 UI 的默认表达路径。
- 诊断页、Smoke 页、Glass Lab 和背包概览页等旧 test 子页属于内部开发工具历史入口，不作为业务 UI 模板或稳定业务 API，也不再对外暴露页面工厂；当前 `/qzuilib test` 已收敛为 test P0 语义首页。

## 入口调整原则

- 默认不向原版背包注入测试按钮。
- 默认不占用全局热键打开诊断菜单。
- 诊断能力保留，但必须通过显式开发者入口触发。
- 当前显式测试入口统一为 `/qzuilib test`；其具体使用和实现约束以 `docs/使用文档/04-诊断入口/指令触发方案.md` 为准。

## 执行原则

- 先固化文档边界，再进行代码入口收口。
- 每次开放化调整都要同时审视“对外文档是否清晰”和“内部测试入口是否被误暴露”。
- 若开放化调整影响宿主入口、作者能力或使用方式，必须同步更新 `docs/使用文档/`。
- 若开放化调整暴露出新的长期协作约束或重复错误，应同步更新 `docs/记忆/` 分层文档或 `docs/开发者文档/errors/`。
