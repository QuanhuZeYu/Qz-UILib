# 发布流程

> 素材基线 2026-08-14。本文件是 Qz-UILib 发布流程的唯一权威：发布前必须先完整阅读本文件，并严格按「发布动作」一节的唯一路径执行。

## 1. 版本真值

- 版本由 git tag 决定（GTNH GitVersion 方案）：构建产物、FML 元数据与 Release 中的版本号都派生自 tag，不手工写版本号。
- tag 命名必须是三段式纯数字 `x.y.z`（如 `4.7.0`），且必须创建为 annotated tag（`git tag -a`）。
- 版本号、FML 远端范围与 tag 三者必须一致：tag 为 `x.y.z` 时，`MyMod.acceptableRemoteVersions` 必须是 `[x.y.z,x.y+1.0)`（如 tag `4.7.0` 对应 `[4.7.0,4.8.0)`）。

## 2. 发布前准备

以下各项全部完成才允许打 tag：

- FML 远端范围：`MyMod.acceptableRemoteVersions` 设为 `[x.y.z,x.y+1.0)`；`FmlRemoteVersionCompatibilityContractTest` 二态契约必须绿（空串代表开发期精确匹配，非空必须为同 minor 左闭右开发布态范围）。
- changelog：新建 `.changelogs/<tag>.md`，包含「本次更新」「兼容性说明」「验证边界」三节；「验证边界」必须含完整 CI run 链接。同时在根 `CHANGELOG.md` 顶部追加对应版本条目。
- 完整构建：本机执行 `call gradlew.bat --no-configuration-cache build` 必须全绿；并依赖默认分支最新 CI 结果（默认分支绿才发布）。
- issue 核对：对本次修复过的每个 issue，用 `gh issue comment` 回复修复说明与发布版本号。

## 3. 发布动作（唯一路径，禁止绕过）

1. `git tag -a <tag> -m "<tag>"` 后执行 `git push origin <tag>`。
2. 确保 `Publish Release Assets` workflow 已存在于默认分支；若发布在非默认分支进行，相关 workflow 改动需先同步 cherry-pick 到默认分支并推送。
3. 触发并等待：
   `gh workflow run "Publish Release Assets" --ref <分支> -f tag=<tag> -f confirmation="PUBLISH <tag>"`
   再用 `gh run watch --exit-status` 等待状态为 `completed/success`。
4. workflow 从 `refs/tags/<tag>` 不可变 checkout，依次执行：test build、生成 manifest 校验（manifest.json 仅内部校验用）、上传资产到既有 Release 或创建 Release、校验 Release 4 个资产齐全且已上传。

## 4. Release 规范

- title = 纯版本号（如 `4.7.0`），不带 mod 名前缀。
- notes = `.changelogs/<tag>.md` 全文，发布时标题行改为 `# Qz-UILib <tag>`。
- 资产 = 恰好 4 个 jar：`qz_uilib-<tag>.jar`、`qz_uilib-<tag>-dev.jar`、`qz_uilib-<tag>-sources.jar`、`qz_uilib-<tag>-dev-preshadow.jar`；manifest.json 不作为 Release 资产。
- 非 prerelease、非 draft。

## 5. 禁止事项

- 禁止绕过 action 用 `gh release create` 手工造 Release（会造成无资产、notes 不规范的半成品）。
- 禁止本机手工 `gh release upload` 替代 action 产物。
- tag 一经推送不可移动或重打；Release 需要修正时用 `gh release edit`（改 title/notes）与 `gh release delete-asset`，需要重建资产时重跑 `Publish Release Assets` workflow。

## 6. 历史教训

4.7.0 首次发布时，`release-tags.yml` 已被删除且执行者未核对流程，用 `gh release create` 手工造出无资产 Release；随后恢复 `Publish Release Assets` workflow 并重跑补齐资产，再按 4.6.3 规范修正 title/notes/资产集。教训：发布前必须先读本文件，并只走「发布动作」唯一路径。
