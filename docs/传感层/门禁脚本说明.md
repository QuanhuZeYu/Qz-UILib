# 门禁脚本说明

> 本目录下两类结构边界自动传感器，替代 2026-07 移除的 ArchUnit（背景见 `测试体系约定.md:86-97`）。
>
> 控制论角色：**传感层自动传感器**。把结构约束从「人工评审逐条核对」
> 拉回「脚本一键闭环」，让边界破坏在合并前被机械捕获，不依赖评审纪律单独守卫。

## 脚本清单

| 脚本 | 守护对象 | 控制论角色 |
|---|---|---|
| `scripts/check-scene-boundaries.ps1` | scene 代码结构边界（I1-I12/R1-R12 的 import 层面） | 代码结构传感器 |
| `scripts/check-doc-discipline.ps1` | 文档纪律（防流水账/历史文档堆积） | 文档纪律传感器 |

---

## 一、scene 结构边界门禁（check-scene-boundaries.ps1）

- 路径：`scripts/check-scene-boundaries.ps1`
- 零外部依赖：纯 PowerShell + `Select-String`，不引入 jar / Gradle 任务
- 扫描根：`src/main/java/club/heiqi/uilib/ui/scene`

## 断言清单

| # | 断言内容 | 权威源 | 控制论角色 |
|---|---------|--------|-----------|
| 1 | **L2 边界**：`scene/layout/` 禁 import `scene.runtime` / `scene.input` / `scene.paint` / `ui.reactive`（`scene.node` / `scene.text` 合规，不误杀） | `docs/传感层/测试体系约定.md:90-93`（NORTH_STAR I4/I7/I12） | 守 L2 纯数学边界，最高优先级 |
| 2 | **I10 平台契约**：`scene/input/` 禁 import `org.lwjgl` / `net.minecraft` | `NORTH_STAR.md:170` | 守平台无关契约线，输入入口对偶 I6 |
| 3 | **form 零 config 依赖**：`scene/form/` 禁 import `club.heiqi.config.*` | `src/main/java/club/heiqi/uilib/ui/scene/form/package-info.java:11` | 守 form 泛型组合层零业务依赖 |
| 4 | **form 零 MC/GL 依赖**：`scene/form/` 禁 import `org.lwjgl` / `net.minecraft` / `club.heiqi.uilib.gl.*` | `src/main/java/club/heiqi/uilib/ui/scene/form/package-info.java:16` | 守 I10 在 form 子包的延伸 |
| 5 | **overlay 零平台**：`scene/overlay/` 禁 import `org.lwjgl` / `net.minecraft` | `src/main/java/club/heiqi/uilib/ui/scene/overlay/package-info.java:9` | 守 overlay 数据层平台无关 |

## 运行命令

```powershell
pwsh scripts/check-scene-boundaries.ps1
# 或
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-scene-boundaries.ps1
```

- 通过：输出 `scene 边界门禁通过`，退出码 `0`
- 失败：输出 `scene 边界门禁失败：` 并逐条列出 `[标签] 文件路径:行号: 违规 import`，退出码 `1`

## 何时必跑

- **评审 scene 改动前**：PR 涉及 `src/main/java/club/heiqi/uilib/ui/scene/**` 任一子包时
- **合并前**：scene 相关分支合并回主分支前
- **新增 scene 子包 / 调整子包依赖时**：先跑门禁确认未破坏既有边界

## 失败处理

1. **优先清理违规**：按门禁输出的文件:行号，移除或替换违规 import（替换为合规的契约线入口，如 `PlatformInputSource`、`signal` 派生等）
2. **不得绕过**：禁止通过改脚本正则、删除断言、临时注释等方式让违规通过
3. **显式豁免**（仅极少数情况）：若某条边界确需在特定场景放宽，必须按 `NORTH_STAR.md`《修订纪律》在《偏离登记》登记一次偏离，说明理由、影响范围和回填计划；豁免点需在脚本中以可追溯方式标注，不得隐性绕过

## 维护规则

- 新增 scene 结构边界约束时，优先扩本脚本断言，而非另起脚本
- 断言正则只匹配 `import` 行（`^\s*import\s+...`），不误杀注释 / 字符串中的包名
- 权威源行号漂移时同步更新本文件断言清单的 `file:line` 引用

## 二、文档纪律门禁（check-doc-discipline.ps1）

> 与 scene 结构边界门禁对偶：后者守代码，本脚本守文档纪律。
> 解决 vibe coding 常见的"记流水账、留历史文档堆积"反模式。

### 断言清单

| # | 断言内容 | 权威源 |
|---|---------|--------|
| 1 | **决策目录禁日期编号文件名**：不得出现 `DECISION-YYYYMMDD-*` 或 `DECISION-` 前缀 | `docs/反馈层/决策/README.md`（按主题归并原则） |
| 2 | **交接简表行数 ≤ 15**：`交接.md` 表格数据行不超上限，防单调增长 | `docs/反馈层/交接.md` 维护说明（覆盖不堆历史） |
| 3 | **错误预防禁时态标题**：不应有日期/年份/序数标题，只留通则 | `docs/反馈层/错误预防.md:3-4`（个案流水账已清除） |
| 4 | **session-handoff 不入 git**：会话工作记忆是临时载体 | `.gitignore` + `SESSION-HANDOFF.md §2` 状态层次边界 |
| 5 | **docs 禁会话流水账文件名**：不应有"第N次""YYYYMMDD"编号文件（决策目录交断言1，ERROR-*.md 由 AGENTS.md 4.3 允许） | `AGENTS.md` 4.1 文档协作 |

### 运行命令

```powershell
pwsh scripts/check-doc-discipline.ps1
# 或
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-doc-discipline.ps1
```

- 通过：输出 `文档纪律门禁通过`，退出码 `0`
- 失败：输出 `文档纪律门禁失败：` 并逐条列出 `[标签] 文件: 违规说明`，退出码 `1`

### 何时必跑

- **涉及文档改动后**：改了 `docs/反馈层/**` 或新增 `docs/**/*.md` 后
- **任务完成清理时**：见 `SESSION-HANDOFF.md §9` 任务完成 checklist
- **合并前**：含文档改动的分支合并回主分支前

### 失败处理

1. **优先清理违规**：按门禁输出修文档（改名/精简/移除时态标题/确认 gitignore）
2. **不得绕过**：禁止改脚本正则、删断言、临时注释让违规通过
3. **显式豁免**（仅极少数）：若某条纪律确需特定场景放宽，须在决策目录登记决策说明理由与影响范围，豁免点在脚本可追溯标注

### 维护规则

- 新增文档纪律约束时，优先扩本脚本断言，而非另起脚本
- 行数上限类断言（如简表 ≤ 15）按实际增长评估调整，调整时同步更新权威源（`交接.md` 维护说明）
