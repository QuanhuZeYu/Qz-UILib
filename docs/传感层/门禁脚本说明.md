# 门禁脚本说明

> 本目录下的自动传感器覆盖可机械检查的结构子集，替代 2026-07 移除的 ArchUnit（背景见 `测试体系约定.md`）。
>
> 控制论角色：**传感层自动传感器**。脚本在合并前机械捕获已编码的结构边界；未编码的语义约束仍由测试与审核逐条核对。

## 脚本清单

| 脚本 | 守护对象 | 控制论角色 |
|---|---|---|
| `scripts/check-scene-boundaries.ps1` | scene 代码结构边界、HUD framebuffer 主权与宿主文本桥唯一 owner | 代码结构传感器 |
| `scripts/check-doc-discipline.ps1` | 文档纪律（防流水账/历史文档堆积） | 文档纪律传感器 |
| `scripts/check-javadoc-stale-line-refs.ps1` | Javadoc/注释悬空行号引用（防「Method():NNN」「ClassName:NNN」类悬空溯源） | 悬空溯源传感器 |
| `scripts/check-doc-stale-lineno.ps1` | .md 文档悬空文件行号引用（防 `file.ext:NNN` 漂移） | 文档溯源传感器 |
| `scripts/check-agent-environment-ownership.ps1` | agent 环境只读所有权与绕过禁令 | 环境所有权传感器 |
| `scripts/check-agent-control-loop.ps1` | 已弃用控制包协议的历史诊断与自测 | 可选历史诊断 |
| `scripts/check-publication.ps1` | 普通 Maven 与 JitPack canonical publication 的 GAV、classifier、metadata、hash 和远端消费语义 | 发布制品传感器 |
| `scripts/check-github-release.ps1` | immutable tag 身份、Release notes、四资产、远端状态与 workflow 权限/依赖结构 | GitHub Release 合同传感器 |

环境所有权门禁扫描现行 `AGENTS.md`、`CLAUDE.md`、README、控制律文档、`.opencode/agents` 与其他 PowerShell 脚本；CI workflow 和历史 errors 排除。它保留原有断言，阻断常见环境写入、持久化、敏感回显、全量枚举及 Gradle home/JDK override，正向断言环境所有权锚，并组合断言 Gradle 协议、活动任务单、轻量复审语义和 `pwsh` 7 宿主锚。角色文档另行阻断直接 Gradle wrapper、`jetbrainsBuildProject` 第二入口和 `verify-*.ps1` 矛盾专用脚本授权；README、稳定命令与 CI 的人类/runner 原始命令不进入该角色规则，避免误报。该门禁是已知文本模式检查，不构成完整安全证明；未匹配形式仍受根 `AGENTS.md` 绝对禁令约束。运行 `pwsh -NoProfile -File scripts/check-agent-environment-ownership.ps1 -SelfTest` 验证正反 fixtures。

`check-agent-control-loop.ps1` 仅为已弃用控制包协议保留，允许人工诊断旧文件或运行自测，但不再属于活动任务流程，也不被任何现行门禁调用，不得作为写盘、提交或 reviewer 复审的前置门禁。当前任务单规范见 `docs/控制律层/编排模式/TASK-BRIEF.md`，弃用说明见 `docs/控制律层/编排模式/CONTROL-ENVELOPE.md`。

branch/PR publication gate 守卫合并；tag GitHub Release 合同独立执行 immutable identity、Gradle test/build、scene/文档门禁、notes 与四资产检查。JitPack Remote 和 clean `:dev` consumer 位于零依赖的 advisory workflow，只确认 JitPack 渠道，不进入 GitHub Release `needs`。Ubuntu runner 使用 `./gradlew`，PowerShell 脚本使用 `pwsh`，并核对 runner 所有的 ASCII `GRADLE_USER_HOME`。

## 一、scene 结构边界门禁（check-scene-boundaries.ps1）

- 路径：`scripts/check-scene-boundaries.ps1`
- 零外部依赖：纯 PowerShell + `Select-String`，不引入 jar / Gradle 任务
- 扫描根：scene import 断言扫描 `src/main/java/club/heiqi/uilib/ui/scene`；宿主 owner 断言扫描全部生产 Java 源码

## 断言清单

以下断言仅覆盖可由 import/owner/源码模式机械识别的结构子集，不代表覆盖全部 I1-I13/R1-R13；I13 的其他坐标语义及 R13 等约束仍须由测试与审核按权威源核对。

| # | 断言内容 | 权威源 | 控制论角色 |
|---|---------|--------|-----------|
| 1 | **L2 边界**：`scene/layout/` 禁 import `scene.runtime` / `scene.input` / `scene.paint` / `ui.reactive`（`scene.node` / `scene.text` 合规，不误杀） | `docs/传感层/测试体系约定.md`（NORTH_STAR I4/I7/I12） | 守 L2 纯数学边界，最高优先级 |
| 2 | **I10 平台契约**：`scene/input/` 禁 import `org.lwjgl` / `net.minecraft` | `NORTH_STAR.md` | 守平台无关契约线，输入入口对偶 I6 |
| 3 | **form 零 config 依赖**：`scene/form/` 禁 import `club.heiqi.config.*` | `src/main/java/club/heiqi/uilib/ui/scene/form/package-info.java` | 守 form 泛型组合层零业务依赖 |
| 4 | **form 零 MC/GL 依赖**：`scene/form/` 禁 import `org.lwjgl` / `net.minecraft` / `club.heiqi.uilib.gl.*` | `src/main/java/club/heiqi/uilib/ui/scene/form/package-info.java` | 守 I10 在 form 子包的延伸 |
| 5 | **overlay 零平台**：`scene/overlay/` 禁 import `org.lwjgl` / `net.minecraft` | `src/main/java/club/heiqi/uilib/ui/scene/overlay/package-info.java` | 守 overlay 数据层平台无关 |
| 6 | **宿主文本桥唯一 owner**：所有 `McScreenBridge` 子类禁持有 `SceneLwjgl3ifyTextBridge` 或自行调用 `registerTextInputListener` | `docs/反馈层/错误预防.md`「LWJGL3ify 文本桥 owner」 | 防同屏双 listener 导致完整 String 重复进入 sink |

| 8 | **I13 HUD viewport 正向生产边界（机械子集）**：`UiHudRenderListener` 必须且只能用 `minecraft.displayWidth/displayHeight` 调用 viewport factory；`HudViewportMetrics` 只由 factory 构造，factory 只归一化这两个 display 参数 | `NORTH_STAR.md` I13 | 锚定当前 framebuffer 1:1 viewport 的唯一生产来源 |

## 运行命令

```powershell
pwsh scripts/check-scene-boundaries.ps1
# 或
pwsh -NoProfile -File scripts/check-scene-boundaries.ps1
```

- 通过：输出 `scene 边界门禁通过`，退出码 `0`
- 失败：输出 `scene 边界门禁失败：` 并逐条列出 `[标签] 文件路径:行号: 违规 import`，退出码 `1`

## 何时必跑

- **评审 scene 改动前**：PR 涉及 `src/main/java/club/heiqi/uilib/ui/scene/**` 任一子包时
- **合并前**：scene 相关分支合并回主分支前
- **新增 scene 子包 / 调整子包依赖时**：先跑门禁确认未破坏既有边界

## 失败处理

1. **优先清理违规**：按门禁输出的文件:行号，移除或替换违规 import（替换为合规的契约线入口，如 `PlatformInputSource`、`signal` 派生等）
2. **不得绕过**：禁止通过改脚本正则、删除断言、临时注释等方式让违规通过
3. **显式豁免**（仅极少数情况）：若某条边界确需在特定场景放宽，必须按 `NORTH_STAR.md`《修订纪律》在《偏离登记》登记一次偏离，说明理由、影响范围和回填计划；豁免点需在脚本中以可追溯方式标注，不得隐性绕过

## 维护规则

- 新增 scene 结构边界约束时，优先扩本脚本断言，而非另起脚本
- 断言正则只匹配 `import` 行（`^\s*import\s+...`），不误杀注释 / 字符串中的包名
- 权威源行号漂移时同步更新本文件断言清单的 `file:line` 引用

## 二、文档纪律门禁（check-doc-discipline.ps1）

> 与 scene 结构边界门禁对偶：后者守代码，本脚本守文档纪律。
> 解决 vibe coding 常见的"记流水账、留历史文档堆积"反模式。

### 断言清单

| # | 断言内容 | 权威源 |
|---|---------|--------|
| 1 | **决策目录禁日期编号文件名**：不得出现 `DECISION-YYYYMMDD-*` 或 `DECISION-` 前缀 | `docs/反馈层/决策/README.md`（按主题归并原则） |
| 2 | **交接简表行数 ≤ 15**：`交接.md` 表格数据行不超上限，防单调增长 | `docs/反馈层/交接.md` 维护说明（覆盖不堆历史） |
| 3 | **错误预防禁时态标题**：不应有日期/年份/序数标题，只留通则 | `docs/反馈层/错误预防.md`（个案流水账已清除） |
| 4 | **session-handoff 不入 git**：会话工作记忆是临时载体 | `.gitignore` + `SESSION-HANDOFF.md §1` 状态层次边界 |
| 5 | **docs 禁会话流水账文件名**：不应有"第N次""YYYYMMDD"编号文件（决策目录交断言1，ERROR-*.md 由 AGENTS.md 4.3 允许） | `AGENTS.md` 4.1 文档协作 |

### 运行命令

```powershell
pwsh scripts/check-doc-discipline.ps1
# 或
pwsh -NoProfile -File scripts/check-doc-discipline.ps1
```

- 通过：输出 `文档纪律门禁通过`，退出码 `0`
- 失败：输出 `文档纪律门禁失败：` 并逐条列出 `[标签] 文件: 违规说明`，退出码 `1`

### 何时必跑

- **涉及文档改动后**：改了 `docs/反馈层/**` 或新增 `docs/**/*.md` 后
- **任务完成清理时**：见 `SESSION-HANDOFF.md §5` 任务完成 checklist
- **合并前**：含文档改动的分支合并回主分支前

### 失败处理

1. **优先清理违规**：按门禁输出修文档（改名/精简/移除时态标题/确认 gitignore）
2. **不得绕过**：禁止改脚本正则、删断言、临时注释让违规通过
3. **显式豁免**（仅极少数）：若某条纪律确需特定场景放宽，须在决策目录登记决策说明理由与影响范围，豁免点在脚本可追溯标注

### 维护规则

- 新增文档纪律约束时，优先扩本脚本断言，而非另起脚本
- 行数上限类断言（如简表 ≤ 15）按实际增长评估调整，调整时同步更新权威源（`交接.md` 维护说明）

## 三、Javadoc 行号引用门禁（check-javadoc-stale-line-refs.ps1）

> 与 scene 边界、文档纪律门禁并列：前两者守代码结构与文档纪律，本脚本守 Javadoc 悬空溯源。
> 立此门禁的依据：AGENTS.md §4.3 上溯规则——Javadoc 行号引用第 2 次累积（2026-07 C4/C5/C6
> 第一批 + 阶段 E.2 第二批），通则层已不足，上溯至传感层立机械门禁。

### 检查项

| # | 检查项 | 正则 | 例 |
|---|--------|------|-----|
| 1 | 方法名带括号行号引用 | `[a-z_$][\w$]*\(\):\d+` | Config.saveAndReload():64 |
| 2 | 类名 / 大写 token 跟 3+ 位数行号引用 | `[A-Z]\w+:\d{3,}` | ConfigTemplateSyncManager:577、computeHeight:266（模式2 顺带捕方法名尾部含大写字母的悬空引用） |

### 扫描与防误报策略

- 扫描范围：src/main/java/**/*.java + src/test/**/*.java
- **仅对注释文本跑正则**：识别 `/* */`、`/** */`、`//` 三类注释区，命中行才做正则匹配，避免误命中代码内 URL 端口 / 版本号 / 枚举名后跟数字
- 在匹配前剔除注释片段内的 https?:// URL 与 user@host mail 字段，杜绝 https://host:8080 等误报
- 版本号 Forge:1.12.2 因连续数字不足 3 位被 `\d{3,}` 自然排除

### 运行命令

```powershell
pwsh scripts/check-javadoc-stale-line-refs.ps1
# 或
pwsh -NoProfile -File scripts/check-javadoc-stale-line-refs.ps1
```

- 通过：输出 Javadoc 行号引用门禁通过，退出码 `0`
- 失败：输出 Javadoc 行号引用门禁失败（悬空溯源风险）： 并逐条列出 [行号引用] 文件路径:行号: 命中字符串  <-所在行原文，退出码 1

### 何时必跑

- **改 Javadoc / 注释写跨文件引用时**：写「须与另一处口径一致」式跨文件契约前先跑门禁
- **删除或重命名 API 时**：同步审视引用点，避免遗留指向被删 API 的悬空行号
- **合并前**：含注释/Javadoc 改动的分支合并回主分支前

### 失败处理

1. **优先清理违规**：按门禁输出的 `file:line: 命中字符串` 改写注释——用 `{@link Method}` / `{@link Class#method}` 等位置无关语义锚替代 Method:行号
2. **不得绕过**：禁止改脚本正则放宽、删检测段、临时注释让违规通过
3. **跨类维护锚显式豁免**（仅极少数）：若某条 Method:行号 引用确需作为跨文件契约保留（如「三处同步关系」维护锚），必须满足：
   - 在 scripts/check-javadoc-stale-line-refs.ps1 的白名单段中以可追溯方式标注（文件路径 + 行号 + 命中字符串 + 豁免理由）
   - 行号失准后须在下次审视对应维护锚时同步更新（评审责任，不靠脚本自动校验当前准确性）
   - 豁免本身须在脚本内可 grep 检索，不得隐性绕过

### 维护规则

- 新增「位置无关引用模式」检测时（如 `file:line`、`path#method:NNN`），优先扩本脚本断言
- 检测策略有「先抽注释再跑正则」的要求——改扫描逻辑时须保持注释隔离不变，避免代码内 URL/端口误报回归
- 本脚本接 `check-doc-discipline.ps1` 调用链：本脚本独立可跑，也由文档纪律总门禁串联调用。

## 四、文档行号引用门禁（check-doc-stale-lineno.ps1）

> 与 Javadoc 行号引用门禁分工互补：`check-javadoc-stale-line-refs.ps1` 扫 Java 注释，
> 本脚本扫 `.md` 文档，阻断 `file.ext:NNN` 这类随源码变动漂移的文档溯源。

### 检查项

- 脚本名：`scripts/check-doc-stale-lineno.ps1`
- 检测范围：`docs/开发者文档/specs/`、`docs/设定值层/`、`docs/传感层/` 下 `.md` 文件
- 检测模式：非代码围栏文本中的 `file.ext:NNN` 格式行号引用，覆盖 `.java`、`.kt`、`.groovy`、`.md`、`.ps1`、`.py`、`.ts`、`.js`
- URL 排除：先剔除 `https?://`，避免 URL 端口误报

### 运行命令

```powershell
pwsh scripts/check-doc-stale-lineno.ps1
# 或
pwsh -NoProfile -File scripts/check-doc-stale-lineno.ps1
```

- 通过：输出 `文档行号引用门禁通过`，退出码 `0`
- 失败：输出 `文档行号引用门禁失败（悬空文件行号风险）：` 并逐条列出 `[doc行号引用] 文件路径:行号: 命中字符串  <-所在行原文`，退出码 `1`

### 何时必跑

- **新增或修改文档溯源时**：写跨文件源码引用时优先用类名、方法名、章节名等语义锚
- **涉及扫描范围内文档改动后**：改了 specs、设定值层或传感层 `.md` 后
- **合并前**：含文档改动的分支合并回主分支前

### 失败处理

1. **优先改语义锚**：把 `File.java:NNN` 改为 `File.java` + 方法名/类头/章节名等位置无关描述
2. **不得绕过**：禁止通过放宽正则、移动文档目录、把正文塞进代码围栏等方式规避门禁
3. **确需精确行号时先评估替代锚**：若没有稳定语义锚，应优先补源码 Javadoc/章节标题，而非保留行号

### 维护规则

- 新增需覆盖的源码/脚本扩展名时，扩展本脚本正则并同步更新本段检测模式
- 本脚本接 `check-doc-discipline.ps1` 调用链：独立可跑，也由文档纪律总门禁串联调用

## 五、Publication 门禁（check-publication.ps1）

> 该传感器区分普通 Maven publication 与 JitPack canonical publication，避免把本地 GMM 正确误当成 JitPack classifier 已正确。

### 模式与断言

| 模式 | 关键断言 |
|---|---|
| `-SelfTest` | 以隔离 fixture 覆盖 Local 正反例，并覆盖 Remote 整体收敛、pending 身份/稳定汇总、权限/非零退出/身份/GAV/hash/module 等确定性错误，以及“pending 不得遮蔽确定性错误”；不调用 Gradle、不访问远端 |
| `-Local -ModuleMetadata RequiredCorrect` | POM GAV 精确匹配；main/dev/sources 均为非空有效 JAR、三者 hash 互异且分别与 `build/libs` 一致；`.module` 存在，component 正确，`apiElements/runtimeElements → dev`、`reobfElements → main`、`sourcesElements → sources`，每个 URL 与 sha256 对应真实文件 |
| `-Local -ModuleMetadata Forbidden` | 保留 Local 的 POM/classifier/hash 断言，同时要求 canonical 坐标下 `.module` 不存在；传入 `ForbiddenGroupId` 时，旧 group 的同 artifact/version 不得残留 POM、main/dev/sources 或 module |
| `-Remote` | 只访问无 query 的 `https://jitpack.io`；Build API 必须为 public tag、status=ok 且 peeled commit 精确匹配；POM/main/dev/sources 及各自 `.sha1` 必须为 200 且内容 hash 匹配；POM GAV、三个 SHA-256 与本地 canonical gate 一致且互异；`.module` 必须为 404；`build.log` 必须为 200、无权限错误且 exit code 为 0 |

`RequiredCorrect` 只用于普通 publication；`Forbidden` 只用于 `JITPACK=true` 的 canonical 组合方案。JitPack `.module=404` 是该组合方案的成功条件，不是普通 Maven publication 的通用策略。

### Workflow 接线与成功矩阵

- branch/PR 的 `publication-gate` 在常规构建后依次运行 SelfTest、普通 Local `RequiredCorrect`、JitPack canonical 模拟 Local `Forbidden`，阻断错误代码进入发布分支。
- 独立 `jitpack-advisory.yml` 先模拟 canonical Local 并输出 main/dev/sources SHA-256，再执行真实 Remote；最后在全新临时 consumer 中显式依赖 `com.github.QuanhuZeYu:Qz-UILib:<tag>:dev`，要求 `compileJava` 成功且实际解析 dev JAR 的 hash 与 Remote 一致。
- canonical JitPack 完整成功矩阵：Build API 的 tag/public/commit 正确；POM、main、dev、sources 与各自 sha1 均为 200 且 hash 匹配；POM GAV 正确；三个 classifier hash 互异并匹配 tag 本地 gate；module 为 404；build.log 成功；clean 显式 `:dev` consumer 编译并命中同一 dev hash。
- Remote 每轮读取整套 Build API、build.log、POM/sha1、main/dev/sources/sha1 与 module 快照：202/404/408/425/429/5xx、building、日志或制品未完成统一记 pending，按 15 秒间隔在整体 deadline 内收敛并稳定汇总最后原因；超时仍 fail-closed。权限错误、非零 exit、错误或已完成时缺失的 tag/public/commit、错误 GAV/hash、role hash 碰撞与 module=200 是确定性错误，立即失败，不能被其他 pending 遮蔽。
- advisory 的 DNS、超时、5xx 或确定性污染不得记录为 JitPack 成功，但不阻断 GitHub Release；不可移动 tag 与版本升级规则见发布流程。

### 运行边界

- 本地可复用命令见 `docs/控制律层/稳定命令.md`。SelfTest 可独立运行；普通 Local 检查须在受协议约束的 `publishToMavenLocal` 成功后运行。
- `JITPACK`、`GROUP`、`ARTIFACT`、`VERSION` 模拟变量只由 CI runner 声明；本地 agent 禁止赋值。Remote 与 clean consumer 属 advisory runner 权限，不授权 agent 本地执行，也不等同 GitHub Release 验证。

## 六、GitHub Release 合同门禁（check-github-release.ps1）

> 该传感器守卫仓库自有 GitHub Release 合同；它与 JitPack/Maven publication 传感器零依赖。

### 模式与断言

| 模式 | 关键断言 |
|---|---|
| `-SelfTest` | 隔离 fixture 覆盖四资产缺失/多余/空/损坏/错名、四 hash 非唯一、tag object/commit/notes/manifest 错绑、draft/published/prerelease、远端资产集合/大小/下载 hash；同时覆盖 JitPack/Maven 耦合、外部 release reusable、浮动 action、凭据持久化、删除/覆盖/wildcard、并发取消及标量/flow/block-scalar 权限绕过等危险结构；不调用 Gradle、不访问 GitHub |
| `-Static -WorkflowRoot <root>` | 扫描 workflow，要求 action/reusable 固定完整 SHA或仓库内相对路径、checkout `persist-credentials:false`、无 `secrets:inherit`/`continue-on-error`/删除覆盖/wildcard JAR；tag 与 recovery 必须复用本地合同且不依赖 JitPack/Maven，recovery 固定 tag object/commit，不从 dispatch ref 漂移；Release/JitPack 使用独立 `cancel-in-progress:false` concurrency；`contents:write` 仅允许 tag caller `release`、recovery `publish`、reusable `publish-release` 三个精确 job |
| `-Identity` | 验证安全 tag 名、annotated tag object、peeled commit、`HEAD`、`modVersion` 与目标 commit 内非空权威 notes 精确一致 |
| `-Local` | 重做 Identity；要求 bundle notes 与权威 notes 一致，四个有效 JAR 名称精确为 main/dev/sources/dev-preshadow、hash 两两互异；生成或复验绑定 tag object/commit/notes hash/资产名称大小hash 的 manifest |
| `-Remote -ExpectedState Preflight` | 同 tag Release 不存在则输出 absent；已有 draft 或多条记录即失败；已有正式 Release 必须标题、notes、prerelease、四资产完全匹配且按 asset ID 下载后 hash 一致，才输出 matching published |
| `-Remote -ExpectedState Draft/Published` | 必须恰有一条对应状态的 Release，并完整复验标题、notes、prerelease、四资产集合/大小及按 ID 下载 hash；需要 runner token |

### Workflow 接线与失败边界

- `release-tags.yml` 只解析 immutable annotated tag 身份，再以该身份调用 `_github-release-contract.yml`；caller 与合同均禁止 JitPack/Maven 依赖。
- reusable `gate` 从目标 commit 重跑 Identity、`test build`、scene/doc 门禁并组装四资产；bundle 只在当前 run 内上传下载。`verify-only` 保持只读，验证 bundle，并在远端已有 Release 时要求完全匹配。
- `publish-release` 在 preflight absent 时创建精确 draft，按 asset ID 下载复验后正式化，再做 Published 最终复验；已有匹配正式 Release幂等复验。已有 draft、冲突/重复 Release或任一资产/notes/身份偏差均 fail-closed，不删除、不覆盖、不续传。
- `recover-4.6.2-release.yml` 的 verify-only/publish 都要求 mode-specific 精确确认串并固定 `4.6.2` tag object/commit；只有 publish caller 与 reusable publish job 获得最小 `contents:write`。
- 本地 agent 只可执行任务明确授权的 SelfTest/Static；Identity/Local/Remote、workflow dispatch 与 Release 写操作属于 GitHub runner/用户授权边界。本地通过不能写成 GitHub-hosted run 或正式 Release 已成功。
