# 门禁说明

仓库不再维护外部结构、文档、publication 或 Release 门禁脚本，`scripts/` 无 tracked 文件。删除机械检查不改变 I1-I13、R1-R13、布局同步契约、paint/node 铁律或测试体系本身。

## 现行机械检查

`.github/workflows/build-and-test.yml` 的轻量 policy job 使用内联 Python：

- 拒绝任意大小写变体的 tracked `.ps1` 文件；
- 拒绝 workflow 文本中的 PowerShell 宿主或脚本后缀；
- 不调用仓库脚本，不访问网络服务，不承担 scene/docs/publication/Release 语义检查。

## 人工与测试守卫

- scene/控件改动：先读 `docs/设定值层/硬约束总目录.md`，按其权威指针逐条 review I1-I13、R1-R13、布局同步契约与 paint/node 铁律。
- scene 测试：按 `docs/传感层/测试体系约定.md` 核对分层、L2 防错清单与输入两入口边界。
- docs 改动：从 `docs/README.md` 导航，人工核对链接、状态时态、语义锚与写回归属；业务状态以 `docs/反馈层/交接.md` 为准。
- agent 框架改动：核对环境所有权、任务单写集、配置 frontmatter 未越权，并执行独立 reviewer。
- workflow 改动：核对 action SHA、权限最小化、默认分支 guard、固定身份、远端写操作与失败边界。

未来若重建任何机械门禁，须作为独立任务定义权威源、正反例、CI 接线和维护责任，不得把已删除入口写成现行能力。
