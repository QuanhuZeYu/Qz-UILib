# 测试体系约定（防错收口）

> 本文件记录 scene 测试分层、断言库和常见防错口径。
>
> 本文档是 scene 测试体系的**长期事实层**约定：分层规则、L2 防错清单、断言库速查、
> 各包职责与反例锚点。改到相关测试域时按需查阅，不要求无差别通读。
>
> 代码侧镜像：`scene/layout/package-info.java`（L2 纪律）、`scene/package-info.java`
> （分层总纲）、`LayoutAssertions` 类 javadoc（速查表）。

## 1. 分层总纲

scene 测试按子系统依赖深度分两层，其余子包按各自归属：

- **L2 纯数学（`scene/layout/`）**：仅 `new SceneNode` + `SceneLayoutEngine.layout` + 数值/失效
  断言。零 runtime / signal / input / paint 依赖。确定、快速、可重入，是 **CI 硬门禁**——
  任何 PR 必须先过 L2 全绿。
- **L3 集成（`scene/integration/`）**：跨子系统协作（runtime + signal + input + paint），
  端到端行为验证。运行宽松，非 CI 硬门禁。
- **其余子包**（node / control / input / paint / overlay / runtime / text）：按各自子系统归属，
  不强制纯数学，但同样应优先复用共享设施（FixedTextMeasurer / LayoutAssertions）。

**准入判据**：测试触到 `SceneRuntime` / `ReactiveScheduler` / signal / 输入路由 / paint 引擎
任一，即属 L3，必须进 `integration/`，**不进 `layout/`**。

## 2. L2 防错清单（核心，7 条）

1. **文本度量**：新写 L2 测试必用 `FixedTextMeasurer(8,16)`（scene 测试根目录的确定性桩），
   禁依赖真机字体 / font renderer——保证跨环境一致。
2. **几何 / 失效断言**：必复用 `LayoutAssertions`，勿在测试里裸 `assertEquals` 断坐标 / 尺寸 /
   失效位。
3. **例外白名单**：**例外**：grow 主轴分配（只断主轴尺寸，交叉轴受 STRETCH 影响难预期，见
   GrowAllocationTableTest）、缓存计数/并行池等非全维几何量允许裸 assertEquals。
4. **engine 实例**：每个测试用例用独立 engine 实例（per-field final 或 per-test new 均可），
   禁跨用例复用同一 engine。
5. **import 禁区**：L2 测试禁 import reactive / runtime / input / paint 包，违者即应下沉 L3。
6. **I4 矩阵**：新增任何 setter，其失效级别必须补进 `scene/node/InvalidationLevelMatrixTest`
   的矩阵表。
7. **grow 场景**：grow 分配新场景必须补进 `GrowAllocationTableTest` 的 Case builder，
   期望值需 Oracle 手算并交叉校验。

## 3. LayoutAssertions 速查

| 你要断言什么 | 用哪个 helper |
|---|---|
| 某 setter 只触发某一级失效（I4 矩阵） | assertOnlyInvalidation(node, level) |
| 遍历后节点完全清脏 | assertClean(node) |
| 局部坐标全 4 维（x/y/w/h） | assertLocalBox(node, x, y, w, h) |
| 绝对坐标累加（I12/§4.5，只 x/y） | assertAbsoluteBox(node, rootX, rootY, x, y) |
| COLUMN shrink-to-fit 高度求和 | assertColumnHeightSum(container) |
| ROW SHRINK 宽度求和 | assertRowWidthSum(container, availW) |
| 增量失效恰好重算某集合（I7） | assertRelayoutSet(result, nodes...) |
| 干净帧零重算（I7） | assertNoRelayout(result) |

不在此表的几何/失效断言，优先扩充本库而非在测试里裸写 assertEquals；纯缓存计数/并行池等
非几何量除外。

## 5. 反例锚点（防错最有效）

> 历史踩过的坑，评审时直接对照这几条否决。

- **"需要 SceneRuntime 的控件装配 → 属 L3，不进 `layout/`"**
  L2 测试只 new 裸 SceneNode + layout 引擎，凡要 SceneRuntime / signal 订阅的，下沉
  `integration/`。否则破坏 L2「确定、零依赖」前提。
- **"断 grow 交叉轴 → 不需要，grow 算法与交叉轴正交"**
  grow 只分配主轴尺寸，交叉轴受 STRETCH / align 影响、难预期。grow 测试只断主轴，
  用裸 assertEquals 即可（见白名单第 3 条）；勿为凑 `assertLocalBox` 伪造交叉轴期望值。
- **"找 stackHost 结构 → 控件结构探针，不放 LayoutAssertions"**
  LayoutAssertions 是布局数学断言库，不放控件结构 / stackHost 查找这类装配探针。
  装配结构断言归 `control/` 包内的局部工具。
- **「命中区宽 vs 可见 chrome」验收（评审应核）**：内容宽/行尾 miss/R6 穿透三项
  → 权威口径见 `docs/反馈层/错误预防.md`「scene 交互根宽度」（本处不重文）

## 6. 架构纪律（评审守卫，非编译守卫）

> L2/L3 分层与 L2 纯数学边界**不由自动化测试守卫**（曾用 ArchUnit，已于
> 2026-07 移除）。这些边界靠**评审纪律 + package-info 声明**维持，
> 改到 L2/L3 分层时重点检查相关边界；无关改动不需要执行全量清单。

- **L2 纯数学边界（最高优先级）**：`scene/layout/` 下任何类**禁止**依赖
  `scene/runtime`、`scene/input`、`ui/reactive`、`scene/paint` 四个包
  。**双重守卫**：产品侧——`scene/layout/` 包的生产类
  import 段禁出现上述四包（评审时直接查）；测试侧——见 §2 第 5 条「import 禁区」。
- **准入分层**：测试触到 SceneRuntime / ReactiveScheduler / signal / 输入路由 / paint
  引擎任一，必须进 `integration/`，不进 `layout/`（同 §1 准入判据）。
- **为何移除自动守卫**：ArchUnit 规则维护成本（jar 依赖 + 规则同步）超过
  收益；scene 包结构稳定、评审已能覆盖，改由文档纪律承载。

## 7. 统一测试入口（testkit）

scene 测试搭台设施（testkit）收口跨 L2/L3、跨 input/paint 子系统的可复用 helper，
对应代码 `src/test/java/club/heiqi/uilib/ui/scene/testkit/`，镜像说明见该包 `package-info.java`。

### 7.1 输入侧两入口边界

scene 输入测试有两条正交入口，务必按场景选择，不要混用：

| 入口 | 用什么 | 测什么 | 备注 |
|---|---|---|---|
| A「编程注入帧」（默认） | `SceneInteractionHarness`（首选）/ 裸 `InputFrameBuilder`（白盒回退）→ `SceneRuntime.route` | 交互路由 + 状态机（click / hover / scroll / key） | 交互测试一律走此入口 |
| B「桥封板契约」 | `MockPlatformInputSource`（`scene/input/mock/`，**非 testkit**） | 封板状态机 / 键映射 / 不可变性 | 现存 3 文件，不用于交互测试 |

**入口 A 内部选择判据（重要，统一收口）**：

- **默认用 `SceneInteractionHarness`**：`harness.click/moveTo/scroll/press/
  pressKey/typeText(node)` 自动取节点中心 + route，消除坐标硬编码与 11 参
  `RawInputEvent` 样板。凡 harness 能覆盖的交互，**必须**用 harness，不得裸建。
- **仅以下白盒场景回退裸 `InputFrameBuilder`**（harness 结构性覆盖不了）：

| 类别 | 触发场景 |
|---|---|
| overlay 树外路由 | 目标在 overlay 弹层内（Select/Combo 下拉、DataTable 内嵌 Select）|
| 精确 localX/坐标 | 非节点中心的精确投递（Slider 轨道比例点、Scrollbar 拖拽增量）|
| 自定义 native/修饰键 | 需特定 scancode/modifier（harness 固定 0,0）|
| host margin/rootAbs | 模拟 GUI 居中偏移的绝对坐标 route |
| 多 runtime | 单测需多个独立 runtime 实例 |

- 裸建 helper 的 javadoc 首句必须标回退归属类，格式 `// 白盒回退（<类别>）：<理由>`，不各写各的即兴理由
- `MockPlatformInputSource` ≡ `InputFrameBuilder` 壳，交互测试不必经它（「绕过桥」非缺陷）；桥内部差分属独立桥单测范畴，与本入口正交

### 7.2 渲染侧顶点断言边界

- `ScenePaintCapture.paintAndCapture` 是渲染出口顶点验证唯一入口
  （layout → paint → `ScenePaintReplayer#replay` → `RecordingRenderBackend`）。
- 断言口径：普通 box 顶点（`fillRect` 的 left/top/right/bottom）反映 layout 几何；internal、
  像素对齐的 presentation geometry offset 会直接累加到顶点与后代 clip。常规 transform 仍仅出现
  在 `pushTransform` 的 7 个浮点分量里，不烤入 box 顶点。
- **不做「变换后顶点」**：变换后的最终像素位置属 GPU 顶点层，纯 JUnit mock backend 不可观测。
  transform 对 hit-test 的已知限制见 `NORTH_STAR.md`《已知限制》。
- 控件顶点断言按需：仅独特自绘结构才补，默认复用 `SceneBackendContractTest` 8 场景 + L2 坐标不变量。

### 7.5 事件注入帧时序语义（同帧 vs 跨帧）

> 输入交互测试的隐形陷阱：**一次逻辑点击在测试里是「一帧」还是「两帧」，直接决定能否复现真机 bug**。
> 本节判据源自 P0 真因 D1（真机下拉框 item 点击失效）——同帧注入永远绿、跨帧注入才暴露卸载竞态。

**判据表**：

| 场景 | 用哪个 harness API | 帧数 | 覆盖什么 |
|---|---|---|---|
| 普通点击（DOWN+UP 同帧，flush 前 CLICK 已合成） | `click(node)` / `clickAt(x,y)` | 1 帧 | 常规交互，**测不出跨帧竞态** |
| 分帧按/放但不重排 | `press(node)` 后 `release(node)` | 2 帧 | 焦点跨帧变化，无中间 layout |
| **跨帧点击（DOWN 帧 flush 触发 overlay 重评/卸载，UP 帧命中已变几何）** | `pressReleaseAcrossFrames(node, betweenFrames)` | 2 帧 + 中间回调 | **真因 D1 类回归**：浮层 item 跨帧卸载后 CLICK 是否仍合成 |

**为何同帧测不出真机 bug（红线）**：
- `click(node)` 的 DOWN、UP 在**同一帧**注入，`flush` 在两者之后才跑——此时 focus 掐断 / overlay 卸载还没发生，UP 命中的 item 仍在，CLICK 必合成。**同帧点击对「跨帧卸载」类 bug 永远假绿**。
- 真机 DOWN 与 UP 天然跨帧（不同的输入 poll 周期），DOWN 帧末 flush 会：① 焦点 signal 写入生效（可能 clearFocus）；② overlay portal 重评（`expanded` 变 false → item 卸载）。UP 帧到达时 hitTarget 已非 DOWN 时的节点。
- `pressReleaseAcrossFrames` 用 `betweenFrames` 回调在 DOWN flush 与 UP route 之间插入生产语义的 layout（含 overlay 重排/卸载），如实复现这一跨帧盲区。

**overlay 跨帧卸载陷阱（用 pressReleaseAcrossFrames 时必知）**：
- **坐标 DOWN 前捕获一次，UP 复用同坐标**：若 betweenFrames 卸载了 item 节点，UP 时再取 `centerOf` 会因 `absoluteBox` 返回零盒抛 `IllegalStateException`。语义上「UP 用 DOWN 那一帧的目标坐标」与真机一致（真机 UP 指针位置不因节点卸载而漂移）。
- **harness 不承担 overlay layout**：overlay 重排由 `betweenFrames`（通常传 `this::doLayout`）在测试侧完成。harness 不复刻一份偏离生产 anchor 语义的第二 layout 实现（守 YAGNI + I12 raw/local 一致性）。
- **几何近似依赖 anchor=0**：`harness.centerOf` 用 `SceneGeometry.absoluteBox` 沿 `__getParent()` 链累加到 overlay root（`__getParent()==null` 即停），得「相对 overlay root 的局部坐标」，只在 anchor=0（默认 unset）时与 Router hit-test 的 `raw==local` 自洽。**该原语仅供 focus/CLICK 合成时序回归，不供锚点定位精度测试**（anchor≠0 场景需调用方自取几何）。
- **命令式卸载 overlay 是 testkit 搭台桩的合法用法**（如自测里 `handle::dispose`），模拟「portal 已派生卸载完成」的外部结果；生产侧卸载仍由 `expanded` signal → portal 派生触发，勿把命令式 dispose 当生产可仿范式（守 R11/R13）。

## 8. Config 运行时测试矩阵（最小持续价值）

> 配置子系统回归的**长期门禁维度**（非流水账用例清单）。新增 config 测试或评审 PR 时按维核对；缺维即补测。

| 维度 | 必须覆盖 | 反例 / 红线 |
|---|---|---|
| **写前检测 / CAS 口径** | 参与式 writer 串行 + 精确字节 expected；冲突结构化 `ConflictType` | 禁止把 `writeAll` 当 CAS；禁止英文串匹配诊断 |
| **reload 完整校验** | capture→内置+custom 校验→commit；失败零推进；成功发 `RELOAD` 一次 | 禁止 NUMBER 非法静默 0.0；禁止伪装 `BATCH_SAVE` |
| **通知期封锁** | BATCH_SAVE **与** RELOAD 期间 save/flush/reload/legacy mutation fail-closed | listener 内不得再 save |
| **草稿所有权** | foreign/unbound draft 在任何 base/validator 前拒绝；`owns` / ConfigScreen fail-fast | 禁止未绑定 draft 写任意 manager |
| **主线程回灌协调** | Registration 线性化；no-spin / next-drain；失败 reoffer；hook Assertion 后 owner 释放 | 禁止 `queue.size()` 预算；禁止 hook 持 monitor wait |
| **MainThreadDispatcher** | batch swap；Assertion/ErrorSink Assertion 尾重排；第二 drainer CAS 拒绝 | 禁止并发双消费同一侧 batch |
| **section raw overlay** | MAP unknown 保留；schema typed 覆盖 known；**scalar/list section fail-closed** | 禁止非 MAP section 静默默认覆盖 |
| **SIMPLE_LIST 类型** | `List<String>` 严格拒 null 元素；disk/save/legacy 同口径 | 禁止 null 元素事后字符串化 |
| **I3 prefill** | 局部只读初值；render 期不写 draft/adapter signal | 禁止 render 调 seedPresentation / Signal.set |
| **线程异常回传** | 并发 worker 异常 `AtomicReference` 回主线程 assert；latch 保证 registration 存在 | 禁止 `if (listener == null) skip` 假绿 |

### 8.1 fontSort presentation 矩阵

| 维度 | 必须覆盖 | 反例 / 红线 |
|---|---|---|
| **snapshot / merge** | 打开前冻结；空/非空 draft；identity、English locale、canonical、重复首项、失效删除、新发现追加 | coordinator initial apply 后重新读取 FontConfig；render 写 draft/dirty |
