# HUD Demo 面板子控件溢出暴露布局缺陷

## 错误现象

- 右上角 `INTERACTIVE HUD` demo 面板中的输入框和按钮超出面板边框，视觉上像“跑出框”。

## 触发场景

- HUD demo 面板给容器设置了固定宽度和内边距。
- 内部输入框和按钮又声明 `width: 100%`。

## 根本原因

- 这不是刻意设计，而是当前 HTML-like 宽度语义与 demo 写法共同暴露出的结果。
- 在当前布局模型下，子项 `width:100%` 会按父内容宽度求解；若再叠加控件自身 padding/border，而没有 `box-sizing:border-box` 一类语义，就会出现总宽度超出父内容盒。
- 因此这里首先是 HTML 级能力缺口，其次是 demo 正好把缺口显性暴露出来。

## 修复方案

- 先记录为已知问题，不在本次反馈中直接修复。
- 后续应从 HTML-like 能力层统一补足：例如引入 `box-sizing` 语义，或提供更稳定的控件宽度契约。
- 修复后再回头收敛 HUD demo 写法，避免继续使用会放大该缺口的布局组合。

## 预防措施

- 后续新增通用表单控件或浮窗 demo 时，优先验证“固定宽度父容器 + 100% 宽子控件 + padding/border”组合。
- 若布局问题出现在多个宿主场景，应优先认定为 HTML-like 通用能力问题，而不是单独归因到 HUD。
