# HUD 交互浮窗点击穿透下层容器且缺少拖拽能力

## 错误现象

- 在容器界面上点击 HUD 交互浮窗时，原版容器或下层内容区仍可能收到点击，导致浮窗操作不稳定。
- 交互浮窗固定在右上角，遇到原版侧栏、JEI/NEI 面板或业务布局冲突时，用户无法把浮窗拖走避让。

## 触发场景

- `INTERACTIVE HUD` 显示在背包、箱子等容器界面上方。
- 用户尝试点击输入框、按钮、开关等 HUD 交互控件。
- 原版下层界面仍保留自己的鼠标处理链路。

## 根本原因

- 当前 HUD 首版只把 HTML-like 输入路由接到了 HUD 文档树，没有建立“HUD 先消费、宿主后消费”的统一宿主级命中仲裁。
- 浮窗位置仍是 demo 级固定 `fixed top/right` 布局，没有通用拖拽语义。
- 拖拽能力如果只做在 HUD 层，会把作者能力分裂成 HUD 专属行为，违背当前“作者层继续使用 HTML-like 语义”的主线。

## 修复方案

- 先记录为已知问题，后续统一设计 HTML 级拖拽能力，而不是只给 HUD 打补丁。
- 后续优先方案应为：在 HTML-like 元素层提供通用 draggable/drag-handle 语义，再由 HUD 浮窗、弹层、业务面板复用。
- 宿主侧还需要补一层输入仲裁：当 HUD 浮窗命中并声明消费后，避免点击继续穿透到底层原版容器。

## 预防措施

- 新增“悬浮面板/浮窗”需求时，优先评估是否应沉淀为 HTML 级交互能力，而不是做 HUD/Screen 专属一次性方案。
- 后续实现拖拽时，同时补“命中消费不穿透”和“拖动后位置持久/更新”两类验证。
