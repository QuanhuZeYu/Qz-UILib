# 客户端命令直接开屏被聊天关闭覆盖

## 错误现象

- 在聊天框输入 `/qzuilib test` 后，预期应弹出诊断菜单，但界面没有显示。

## 触发场景

- 在客户端聊天命令 `processCommand(...)` 中直接调用 `Minecraft.displayGuiScreen(...)` 打开新的 `GuiScreen`。

## 根本原因

- 命令执行时聊天界面仍处于当前界面生命周期内。
- `processCommand(...)` 返回后，聊天界面自身的关闭流程还会继续执行，并把当前界面切回 `null`。
- 因此“命令里刚打开的新界面”会被随后发生的聊天关闭操作覆盖。

## 修复方案

- 不在客户端聊天命令里直接开屏。
- 改为把开屏动作入队到 `UiScreenManager`，在当前帧输入分发结束后统一执行。

## 预防措施

- 后续凡是从聊天命令、聊天按钮或其他会立即关闭当前 `GuiScreen` 的上下文中切换界面，都应采用延后执行。
- 为此类时序问题保留纯 JVM 测试，验证延后任务会在统一冲刷点执行。
