# 决策：textarea 软换行采用逻辑行与视觉行两级模型

## 背景

- textarea 软换行最初被判定为需要独立重构的能力，原因是旧实现把“逻辑行（由 `\n` 切分）”直接当作“视觉行”使用。
- 用户明确要求不要做局部小补丁，而要工程化解决该需求。

## 最终选择

- 保留逻辑行作为文本编辑、换行符和表单值的稳定模型。
- 新增按内容宽度切分的视觉行模型，用于显示几何与交互几何。
- 文本 DOM 使用 `white-space:pre-wrap` 和 `overflow-wrap:anywhere`，让显示层与交互层共享按宽度折行的语义。

## 影响范围

- caret 绘制、选区绘制、鼠标点击命中、Home/End、上下方向键和滚动揭示均按视觉行工作。
- 表单提交值、`maxLength`、显式 `\n` 多行编辑和现有 `value` 属性同步仍按逻辑文本工作。
- 当前不把 textarea 提升为完整 CSS 排版引擎；字体族、复杂 bidi、浏览器原生 textarea 所有平台细节仍不在本次范围内。

## 后续注意事项

- 后续修改 textarea 几何时必须同时维护逻辑行与视觉行映射，不能回退到“逻辑行=视觉行”的假设。
- 新增行为至少用 `DocumentTextAreaControlTest` 覆盖软换行显示、点击命中、上下键移动、选区或滚动中的对应场景。
