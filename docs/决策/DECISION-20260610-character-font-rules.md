# 决策：字符级字体覆盖规则

## 背景

玩家希望能为特定字符或字符范围指定特定字体，例如图标私用区、特殊符号、中文范围或数字范围。当前字体系统已经按码点经 `FontMatcher` 匹配字体，并通过 `GlyphRuntimeTables` 缓存结果；同时历史决策 `DECISION-20260601-font-family-deferred.md` 已明确暂不暴露 CSS `font-family` 样式维度。

## 候选方案

1. 接入 CSS-like `font-family`，让样式系统决定字体族。
2. 在 `FontMatcher` 自动匹配前增加玩家配置的字符规则覆盖表。
3. 只调整 `fontSort`，要求玩家通过全局排序间接影响特定字符。

## 最终选择

采用方案 2：新增 `fontSystem.characterFontRules` 字符字体覆盖规则，格式为 `字符或范围=字体名`，支持单字符、`U+XXXX`、`U+XXXX-U+YYYY` 与 `A-Z` 范围；禁用规则以 `disabled:` 前缀保存。`FontMatcher` 在全局字体排序自动匹配前查询规则表，首个启用且命中的规则优先。

## 选择原因

- 当前运行时已经以码点为匹配和缓存粒度，规则表接入点集中，风险低。
- 玩家目标是“某些字符长得对”，不需要页面作者级字体族语义。
- 失败规则可以自然回退到现有自动匹配链路，避免配置错误导致字符完全不可见。
- 保持 `font-family` 暂缓决策不变，避免把底层尚未完整建模的字体族能力伪装成样式能力。

## 影响范围

- `FontConfig` 新增 `characterFontRules` 配置项，并将其纳入字体运行时重载判定。
- `FontMatcher` 在自动遍历字体列表前尝试应用字符规则。
- `ModConfigGui` 新增字符字体规则专用编辑器，提供新增、启用/禁用、上下移动、删除、预设选择、格式校验、重叠提示和基于 `DocumentAutocompleteInputControl` 的字体名候选下拉；远程配置同步通过字段级 validator 复用同一套格式校验。

## 后续注意事项

- 规则变更必须清空字体匹配与宽度缓存，并通过字体运行时 reload 触发布局失效。
- UI 可继续增强为字体搜索下拉或实时预览，但配置格式应保持简单可手写。
- 规则目标字体不存在或不能显示字符时，应继续 fallback，不要把该规则作为硬失败终点。
- 启用规则范围重叠属于合法优先级表达，配置页只做提示；不要在运行时或保存链路中把重叠当作硬错误。
