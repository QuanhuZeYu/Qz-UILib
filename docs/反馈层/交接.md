# 交接（项目状态权威源）

> 本文件是业务状态、阻断项和待决策事项的权威源；实时 Git 分支、HEAD 与工作区状态以 `git branch --show-current`、`git rev-parse HEAD`、`git status` 为权威。控制律归 `AGENTS.md` 与编排文档。

## 当前状态

- HostImage ItemStack 已改为跨帧 identity/尺寸 LRU、小 FBO、每帧 2 次/2ms 公平补图与 5 秒失败冷却；`UiRuntimeAdapters` 现对默认/自定义/旧 renderer 统一施加幂等完整 GL 状态围栏。包装器公开 `render` 与 `renderGuarded` 共用唯一内部执行路径，恶意 `renderGuarded` 覆盖及直接调用 `render(ITEM_STACK, ...)` 均不能绕过，且一次调用只执行一次围栏；void 入口失败会保留阶段与原 cause 抛出。Core Profile 的 texture matrix、server attrib 与 client attrib 现分别以「depth 查询无 GL error 且 >=1」判定支持，不可用时只降级对应子围栏；内置 Minecraft renderer 复用 server attrib 能力语义，不支持时不调用 push/pop，支持路径与真实污染的 fail-closed 不变。其它 GL/FBO 围栏不变。旧 `itemStack` 保持 LIVE，新增 `itemStackSnapshot`；Qz-Miner Picker 已切静态快照。自动化已覆盖三个 stack 的 depth=0、探测错误清理、支持路径真实下溢及 renderer 异常传播，仍待用户在 Angelica/LWJGL3ify 下打开配置页，确认 `minecraft:log meta=0` 可栅格化且日志不再出现 `texture/server-attrib/client-attrib stack underflow` 或 `exit-gl-error`。

- Scene 输入按钮旁路已改为在 push 时读取与 MOVE 同源的物理坐标，不再由 Minecraft scaled 回调反推；TextInput 增加 enabled+未聚焦 hover chrome，并在建树期声明 focused signal，Portal 首次权威聚焦可同步显示 border/caret。ItemStack scene backend 使用 GUI 可见 zLevel 并恢复调用前值。StructuredList 测试已改用语义定位真实 `Manage`，摘要继续保持非交互。实机 GUI Scale 2 点击、caret 与方块图标仍待用户复测。
- StructuredList member 已具备可选中文显示名/辅助说明元数据，保持 YAML key、校验和兼容语义不变；成员编辑区改用可复用纵向 labeled-control 安全默认，去除 90px 标签与 180px 输入固定宽。主 agent 已通过 `StructuredValueSpecTest`、`StructuredListFieldRendererTest`、`FormLabeledControlTest` 三目标测试、全量 `test`、`compileJava`、scene 门禁与文档门禁；剩余为 `runClient21` 实机配置页验收及消费方集成。
- 4.6.0 通用被动 HUD API 已按 I13 收口：bridge 使用 framebuffer 尺寸，layout/paint/font/clip 使用 UILib logical px；host-owned scale 默认 1.0、五档可选且不读取 MC GUI scale。Compact/Normal 字号为 12/14px，外框按内容 intrinsic 宽收缩并在视口边界 clamp，支持通用 min/max width；`HudSpan`、`HudLine.rich/richProgress` 已提供 keyed 富文本，tone 仅表达语义且旧 `HudLine` API 兼容。仍待 `runClient21` 实机确认四角像素、五档缩放、动态宽度和断线重建。
- `4.0` 已在 `d78b9616` 通过 `--no-ff` 合入 4.6.0 正式发布准备；关键提交为 `25312e15`（release prep）与 `ae2084f7`（blank gate fix）。本地发布门禁、构建和 Maven Local 均通过，合并后工作区洁净。
- `git push origin 4.0` 被 GitHub 拒绝：OAuth token 缺少 `workflow` scope，无法创建或更新 workflow。远端 `4.0` 仍为 `4c0c6b8`；`4.6.0` tag 未创建，也没有本次发布产生的 GitHub Release、workflow 或远端 Maven 制品。
- 恢复发布前须由用户执行 `gh auth refresh -h github.com -s workflow`。
- beta-10 将 SearchPicker beta API 收敛为 ALL/SELECTED 两态，SELECTED 支持 1..N checkbox，并无损展示、保留和移除当前未枚举 key。稳定契约见 `docs/反馈层/决策/config-search-picker.md`。
- SearchPicker 的 `LIST_MEMBERS` 关闭态现按左侧 `Manage`、摘要顺序排列，raw 默认折叠为高级修正/删除入口；管理 portal 采用 480px 目标宽、360px 最小宽、8px safe inset 与视口高度 cap，顶部搜索。当前成员改为 6×42px 双行：第一行主名称与 54/118px 固定按钮列，第二行完整 registry/canonical 与 0/136px issue badge；结果区仍为 12×34px。中英文、normal/pending 与问题状态不移动按钮盒，长文本各自在自身盒内裁剪，且只有真实按钮命中。候选展示只读用户 query；当前成员按唯一 candidate key 独立精确解析，空 query 仍不枚举全量。可添加结果按合法 selection key 排除已选项；新增成功后保留 portal、query、合法窗口与搜索焦点并立即重新武装。有 variants 编辑进入变体页，unknown/无 variants 保留稳定 id 进入候选替换态，确认原位替换后关闭。malformed/duplicate 继续只提示、不泄露 raw、不合并；旧 `SINGLE_VALUE`/`Codec` 与未设置 secondary 的 Provider 兼容。该能力继续纳入尚未远端发布的 4.6.0。
- Picker 目标测试、全量 `test`、`compileJava`、scene 边界与文档纪律门禁已通过；Qz-Miner 消费仓实机仍待验证连续批量添加、portal 尺寸、滚动、焦点与领域文案，当前未执行 merge/push/tag/release，也不能标记真机通过。
- beta-9 不改配置核心语义、YAML 或 network。Picker 返回完整精确结果并用固定 8 行窗口化连续滚动；键盘高亮与 hover 独立。STRUCTURED_LIST 默认使用无框字段外壳、单层紧凑对象卡片与稳定 key 折叠意图，editor 可通过通用 current-value presenter 提供摘要。
