# 错误预防清单

本文件按类别沉淀历次踩坑提炼的「正确处理方式」，供后续开发对照预防。
个案流水账已清除，只保留每类通则；新增可复现错误时只增补通则条目，不再堆积个案正文。

---

## GL/渲染状态泄漏

跨渲染边界入口必须用真实 GL 状态保存/恢复包裹完整生命周期，禁硬编码 `glEnable`/`glDisable` 模拟结束状态。
宿主世界遗留 3D 状态、FBO 首创绑定、deferred 批次回放、字体装饰/图标渲染后、宿主图片缺失纹理预检均属此列。
- 直绘宿主 framebuffer 的 UI clip 栈须在上下文入口捕获宿主 scissor/stencil 基线；首层 clip 与宿主 scissor 求交，栈空时幂等恢复基线。静态 FBO/deferred 清空路径可强制 clear，但不得与实例恢复语义混用。
- ItemStack renderer 属不可信第三方边界：必须先做 clip 外剔除，再经跨帧调用预算、小 FBO 与完整可验证状态围栏；只有成功且 recovered 才发布缓存。恢复失败不得由 scene 图片隔离分支吞掉，必须中止当前 UI 帧。
- 不可恢复 renderer 只能通过专用帧中止信号在唯一 screen 帧边界收口；收口前必须按真实 LIFO 尽力关闭 Display List 已进入的 clip/opacity/transform/transform-layer。任一清理失败须转普通异常并保留原异常与清理异常，禁止误当作已安全中止。
- GL error 归因须入口预检在先、单次调用线程局部锁存首个 phase+operation 在后；检查点消费 error 后仍判不可恢复，finally 必清 tracker。能力 probe 自己预期产生的 error 必须在 probe 内隔离，禁止混入首错或被外层诊断重复消费。
- Core Profile 下固定管线 stack 须按必需顺序以「查询无 GL error 且返回值在合法域」显式探测，server/client/texture 不得互相推断；探测前先确认入口 error 为空，探测错误只清本次查询队列。首个必需能力不可用即停止后续 capture、恢复已触碰状态并返回 `UNAVAILABLE`，不得调用不可信 item renderer；未知 error 或恢复失败仍为 `HOST_STATE_LOST`。
- GL 版本位与头文件符号不等于 profile 子能力：`GL_CLIENT_ACTIVE_TEXTURE`/`glClientActiveTexture` 等 compatibility-only API 须独立运行态 query+same-value setter 探测，capture/restore 共用能力快照。预期 INVALID_ENUM/明确不支持会排空 probe error、保留合法 server binding 捕获结果并拒绝 delegate；未知 error 仍 fail-closed。
- FBO 事务的 borrow/begin/render/end/composite/release 必须分别建异常边界：ensure 成功后才增加借用计数，borrow 成功必 release，begin 成功必 end，清理异常保留原异常为 suppressed；失败产物不得发布。
- 失败 cooldown 帧若没有真实 rasterize outcome，只显示占位/旧缓存，不重复打印 `missing-outcome`；warning 只对应真实尝试结果。
- 详情：`errors/ERROR-20260714-hostimage-gl状态污染.md`
- Core Profile 固定管线 stack 详情：`errors/ERROR-2026-07-14-host-image-core-profile-texture-matrix.md`

圆角裁剪须区分「外观装饰」与「后代裁剪」两独立语义；脱流元素裁剪相对 containing block 而非 DOM 父级。

## 字体系统

- 字体异步管线须以 runtimeVersion 隔离代际，重载不混新旧字形
- 烘焙字号与渲染缩放分母须同一常量，禁独立系数分别缩放（违反则 quad 尺寸+xy 定位污染）
- 同 API 的 trim/wrap/measure 重载须保持宽度口径一致，禁混用 9px/18px 空间
- 字体样式 drawText 重载禁互相调用致 StackOverflow
- Transform 内文本须走父矩阵，禁绕过延迟批处理
- 字体共享准备层不得改写 depth test、depth mask 或 depth func；世界空间文字继承调用阶段的深度状态，screen/HUD 无深度状态由 UI host 显式建立（详情：`errors/ERROR-20260724-font-depth-state.md`）
- 延后名称标签等渲染调用必须同时持有可配对的 pass scope、保留 foreign lifecycle 的原调用链、已知 shader phase/entity/item 围栏，以及逐项与批次入口两层 lightmap 状态；任一维度无法证明时即时原绘制，禁止 HEAD cancel、跨 pass 队列或 detached Invoker。玩家标签当前只包装普通名称/计分板最终 INVOKE 与两个 vanilla host；Angelica 仅精确 `2.1.50 + installed handshake` 启用 guard，未知版本、无 guard、shadow、无 scope 和第三方直接调用均不延后（详情：`errors/ERROR-20260725-player-name-tag-render-scope.md`、`决策/player-name-tag-render-order.md`）
- JVM shutdown hook 非渲染线程禁释放字体 GL 资源
- 字体 reload 外部入口只发布 durable desired signal；完整重建只由 `RenderTick.END` 的唯一 owner 在 signal 稳定后
  single-flight 执行，draw-stage 只上传不得换代。持续抖动禁用强制 max-delay flush；成功 commit 才确认 applied，失败保留
  signal 并退避。Splash 只能延后 reconcile，禁止在 signal 前丢弃 resource intent；真实 resource fingerprint 去重仍属后续阶段。
- generation-sensitive 配置必须一次捕获为 immutable `FontRuntimeSettings`，字体发现/排序/metrics 先构造 CPU-only
  candidate，失败不得触碰 active。version、measure epoch、settings、catalog、metrics、table 与 lifecycle 只经单个
  `ActiveFontGeneration` 发布；layout 整次调用持 generation read scope，worker 不持长锁，只在 direct cache 最终写入时
  短持 read lock 并在锁内重验 binding/lifecycle，禁止 check 后无锁写入已转移 storage。
- 完整 Unicode direct tables 只允许一个 owner；换代须在 render write barrier 内原地清理并转移，不得让 candidate
  构造第二张完整表。开始转移前先验证所有 candidate，并把可失败 I/O/AWT 工作前移；单页 GL retire 的普通异常须隔离，
  不得把已退休/已清表的半提交状态伪装成可安全重试的旧 generation。
- worker reset 只有在确认 terminated 后才能释放 executor owner；首次 `shutdownNow()` 最多做一次有界等待，超时/中断必须
  保留 retiring pool，后续 render tick 只能非阻塞探测同一 executor，禁止重复阻塞或提前清空字段后创建并行替代 worker。
- generation candidate 的 runtime version 与 measure epoch 必须在 pause/reset 前验证为 active 的严格后继；不可逆 core
  不得调用可注入 dispatcher。active 单引用发布后，先记录 durable worker recovery intent，再执行 version binding/init；
  任一步骤失败都由后续 tick 恢复当前代，不把已提交 generation 伪装成失败后重做。
- glyph request 身份必须是不可变 `generation + requestId + codepoint + FontType`；manager 一次原子 claim 返回 token，
  task/result/upload 共享同一对象。fail/cancel/queue/ready 只允许 full token 与 expected state 同时匹配，旧 token 只能拒绝，
  禁止再用两阶段 request-id 绑定、key-only cancellation 或 finally 删除新 handle。
- dispatcher 的 submit/pause/reset admission 必须共用线性化 monitor；pause 只停止新 admission，已接纳 worker 由 generation
  epoch 判断 current，reset 推进 epoch 后再取消 exact handle。matcher/rasterizer/result handler 的 `RuntimeException/Error`
  必须先结算 token，不能只删除 in-flight owner。
- 每个 upload dequeue（含 stale）都必须消费本轮预算；bitmap metadata 只在 GL 调用成功并再次核对 token/state 后发布。
  upload 异常先结算 `FAILED` 再传播，draw-stage 异常尝试也须进入间隔/每秒限速账本。首条异常日志包含
  token/stage/expected/actual/reason，重复 fingerprint 输出限频摘要；per-glyph 正常 transition 保持静默。
- singleton 内部 manager/matcher/layout/dispatcher 若保留 public 诊断 getter，generation mutator、lifecycle control 与 raw
  table/page 出口必须绑定不可伪造 owner token 并 fail-closed；渲染/诊断消费者只拿不暴露 primitive arrays 的只读 facade。
- 精确断言 trim/wrap 分行边界的测试，必须在局部 runtime width 表中固定全部被测码点的 advance；禁止让平台 `Dialog` 等逻辑字体映射决定 fixture 宽度，否则相同文本可在不同 JRE/OS 上产生不同分行（详情：`errors/ERROR-20260716-font-test-platform-advance.md`）

## 布局引擎

- 布局/样式/命中等只读流程绝不能改文档失效版本，布局期临时元素须走静默写入入口
- 结构标脏须区分「容器需重排子项」与「未变兄弟子树仍干净」，禁无条件递归整子树
- flex column 非 stretch 子项 auto 宽度禁压成 0，文本块须按真实换行高度参与兄弟排布
- flex 匿名文本项布局期禁 setAttribute 自污染 layoutVersion
- CustomRenderer 传 content box 非 padding box
- 表单控件渲染须含 flex 匿名文本与 textarea 内容盒语义
- input 空值须有原生编辑高度，textarea 光标禁混用文档/屏幕坐标

## scene 交互根宽度（命中 vs 可见 chrome）

- hit 与 paint 共用同一 `LayoutBox`：默认 `WidthSizing.FILL` 的**透明交互根**会把父可用宽整段变成可点区，而有色 chrome 只在 indicator/label → 表现为「触发框远大于渲染区」
- 行内/内容宽交互单元（Checkbox/Toggle/Radio option、Select trigger、NavList item）须在**交互根**设 `WidthSizing.SHRINK`；背景画在交互根上的整盒控件（如 Button）可保持 FILL
- SHRINK 放 **wrapper 还是 shared primitive**：仅当该 primitive 的全部消费者都要内容宽时才写 primitive（如 Toggleable）；若 primitive 被 Segmented/Tab 等均分宽控件共用，则在各 wrapper 自设（如 Radio 对齐 NavList），禁误改 shared 层
- 回归测须断言：交互根宽 = 内容公式（indicator+gap+label[+pad]）且 `<` 父宽；行尾空白 `hitTest` 不含交互根；装饰子 `hitTestable=false` 穿透（R6）仍可点

## scene composition 文本裁剪与操作命中

- flex 收缩只约束 `LayoutBox`，不会自动截断 TEXT 绘制；长文本槽必须在槽节点显式建立 clip，并用 PaintPlan 断言该槽的 `CLIP_PUSH/TEXT/CLIP_POP` 配对，禁止改写或截短业务原文冒充修复
- 含固定行尾操作区的行应按「可伸缩且裁剪的 label → 可选 badge → 固定 actions」装配；actions 固定宽并靠右，状态切换只能改变 label/badge 可用宽，不得移动操作 rail
- 结构容器与透明预留区须退出叶命中候选，只有可见按钮根可交互；真实坐标回归必须覆盖 label/icon/badge、按钮 gap、actions 空白及按钮边界外 1px，禁靠整行 bubble handler 扩大隐式动作区
- 详情：`errors/ERROR-20260714-picker成员行文本溢出与误命中.md`

## 滚动/交互

- 同一手势的 MOVE 与 DOWN/UP 必须从同一平台 reader 读取同量纲坐标；禁把宿主 scaled 回调坐标乘 GUI Scale 反推物理坐标，整数缩放前的余数已丢失，反推会让视觉、hover 与点击落点分裂（详情：`errors/ERROR-20260714-scene宿主按钮坐标失真.md`）
- 滚动偏移变化后须重新命中测试更新 hover
- COMPOSITE 级 transform 平移的可命中节点须考虑 hit-test 只读 LayoutBox 契约，视觉位置偏离时由父节点转发交互
- 嵌套滚动条空闲禁遮挡内容；根视口滚动后须有可见滚动条
- 浮窗首拖禁 right/bottom 锚点跳位
- textarea 删换行后须失效视觉行缓存
- select top-layer option 命中须用真实 top-layer 命中测试，禁点静态边界
- scene screen 关闭时须在 runtime 生命周期异常安全且幂等地对每个已绑定光标后端执行 `forceApply(DEFAULT)`；禁修改 `cursorSignal`、依赖末帧 flush 或改走普通 apply，否则 signal/宿主同值缓存会让真实系统光标残留。此通则只覆盖 screen close，同一 screen 内 portal、条件节点或动态列表卸载后的 hover/cursor 重算须另行处理（详情：`errors/ERROR-20260725-scene-cursor-close-cleanup.md`）

## Gradle/构建环境

- agent 不在本机执行 Gradle、编译、构建、测试、运行态或 verify；必需实证交 CI 或用户，尚无结果时返回 `INCOMPLETE`
- `GRADLE_USER_HOME` 等环境变量由用户或 CI runner 所有；agent 只按任务逐项只读核验，绝不赋值、清空、持久修复、全量枚举或用 Gradle/JDK home 参数绕过
- 依赖版本须锁定一致（Angelica/GTNHLib、lwjgl3ify 运行时与编译类路径）
- CI/用户并行构建须避免共享 build 目录
- 工具链解析须显式指定，禁卡 JBR 21 或弹 MCP 目录选择窗
- 第三方 mixin 与 modern Java 链路冲突须预先排查
- client-only 开发依赖经通用 `runtimeClasspath` 进入标准 dedicated server 时，须按组件坐标 artifact view 只从明确的标准 server 任务最终 classpath 排除自身 artifact；禁止按 jar 文件名删除、全局改依赖或误删传递组件。门禁必须双向断言 server 排除且 client 保留，modern server 任务维持原链路（详情：`errors/ERROR-20260716-server-classpath-lwjgl3ify.md`）

## 事件系统

- 默认行为须在事件传播完成后检查 `isDefaultPrevented()` 再执行
- GUI 打开须延迟到帧结束后，禁渲染栈内关屏致自 dispose
- reactive 去重须基于「帧初值 vs 帧末终值」在 flush 阶段裁定，禁 set 时拿未 flush 旧值比较
- Scene Text 同帧多 TEXT 事件须合并，禁中文 IME 短句多次受控写入互相覆盖
- SceneRuntime.on 须真正随 mount dispose 自动退订输入 handler
- 非 lwjgl3ify 环境配置页文本框须有文本输入事件降级
- 浮层/动态列表控件的显隐 signal（expanded/open/visible）禁派生自 focused 等路由瞬态态，
  否则 DOWN 隐式失焦会跨帧掐断浮层致 CLICK 不合成（详见 R13 / 2026-07 P0-D1）
- CLICK 合成的 DOWN/UP 同节点判定对「跨帧节点身份变化」脆弱（keyed diff 重建 / layout 位移），
  测浮层点击须用跨帧注入（pressReleaseAcrossFrames，见测试体系约定 §7.5）不用同帧；框架层已升级为
  LCA 祖先容差（P1，参考 DocumentClickEventDispatcher）
- 浮层 toggle 竞态须以 POINTER_DOWN 帧初快照裁定 CLICK 后的目标展开态。
  现象：trigger 二次点击本应关闭却被 dismiss 与 toggle 交错重新打开；触发场景：浮层已展开时 DOWN 命中 trigger，
  同帧/跨帧 dismiss 先关闭，随后 CLICK 若读取当前 expanded 会反向打开；根因：CLICK 阶段读取的是被 dismiss 改写后的瞬态值，
  丢失手势开始时的展开状态；修复：在 POINTER_DOWN 保存 expanded 快照，CLICK 只取该快照求 next；预防：新增浮层 toggle
  或测试注入入口时，生产 CLICK 手势必须先有 POINTER_DOWN 快照，默认 false 仅覆盖异常无 DOWN 的注入边界。
- effect 内 `Signal.set` 慢一帧的时序缺口须在 scheduler 层正确解决（flush 双通道交替到不动点），
  禁开 `setImmediate` 等 public API 绕过中央事务止血——绕过即违反 I2（无任何绕过调度器直接生效的写入）。
  reactive 派生的展开条件（如 autocomplete expanded 依赖 filtered/value）本就该走队列，不该塞进事件 handler（详见 2026-07 P2-1）
- Router 权威交互态与视觉 signal 是两层事实：依赖懒创建 interaction signal 的控件必须在建树期显式声明并复用，
  禁等尚未首次求值的 Computed 间接创建；否则首次权威 focus 已成立但 signal 写入被 null 短路，文本路由与 chrome/caret 会分裂。
- 成员管理器的当前值解析不得复用用户 query 的候选结果：先无损解码 selection，再按唯一 candidate key 独立精确查询，
  只接受 key 完全相等项；查询失败保留 unknown。无 variants/unknown 编辑必须保留稳定 memberId 进入替换态，禁退化为新增。
- 动态 keyed 列表的内部编辑须先更新 renderer 本地 rows SSOT，再通知外部 adapter；identity 编辑不能
  等外部回灌，否则回灌窗口会按旧值重建 input 并丢失焦点。reset/reload 只能使用当前唯一或仍存活的
  历史唯一 identity，空、重复、歧义必须 fail-closed，禁止业务 id 直接充当 scene key 或猜测 refocus。
- `McScreenBridge` 子类不得各自注册文本桥；通用 host 是唯一 owner，注册成功才启用 external text mode，
  关闭必须 finally 注销并复位，注册失败必须保留 char 降级路径。
- 可选模组文本桥探测必须使用锚定 classloader 且禁止类初始化；注册前须冻结 add/remove、begin/end
  完整配对计划。add 或 begin 发生半副作用后仍须按 end、remove 独立回滚，失败步骤保留并在后续注销重试，
  未清完时禁止再次 add。

## Javadoc 行号引用

- Javadoc/注释内「`Method():NNN`」「`ClassName:NNN`」「`computeHeight:266`」形行号引用，会随被引用文件/method 的行号移动**必然悬空**——即便当下准确，下次重构（增删方法、调整 import、合并方法）后即变为误导性指引，评审时也几乎无机械手段捕获
- **上溯登记**：本类问题第 2 次累积后历史上曾建立机械检查；该 checker 现已退役，当前由语义锚规则、权威导航人工核对与内置 `build` 提交前自审守卫
- **删除 API 时**：同步清理其 Javadoc 中所有指向被删 API 的行号引用；引用同文件/同类方法时用 `` `{@link Method}` `` / `` `{@link Class#method}` `` 等位置无关语义锚，不要带 `:行号`
- **跨类维护锚例外**：确需保留同步契约时，优先用 `` `{@link …}` `` + 文字描述，不使用漂移行号；内置 `build` 按 `docs/传感层/门禁脚本说明.md` 人工核对并在提交前自审

## 配置草稿冲突与 presentation seed

- 乐观事务冲突必须用结构化 `SaveOutcome.ConflictType` / `isConflict()` / `requiresReload()` 区分，**禁止** UI 或测试靠英文诊断串匹配（`draft base no longer` / `BATCH_SAVE notification` 等）
- `requiresReload`（`STALE_DRAFT_BASE` / `AUTHORITY_MODIFIED_DURING_SAVE` / `CONFIG_FILE_CHANGED_SINCE_LOAD`）时：保留用户编辑供查看；不注入字段 error/errorCount；保存禁用；普通编辑不能清冲突；只能显式「丢弃编辑并重新加载」（`reloadDraftFromDisk` 三阶段 + `replaceDraft`），**不得**自动 reload / 自动重试 / 静默覆盖 Authority
- `reloadDraftFromDisk`：**capture**（Authority 深快照+expected+disk）→ 锁外完整 schema 内置校验 + custom DraftValidator → **commit**（manager 锁+写域 monitor 复核）；非法/validator/IO/冲突时 Authority/expected **零推进**（禁止 NUMBER 非法静默折叠 0.0）；成功才原子更新并锁外发 **`RELOAD` 一次**（**不得**伪装 `BATCH_SAVE`）；失败读 `ConfigReloadException.reason()`（VALIDATION/IO/CONFLICT），禁止英文匹配
- 非 reload 冲突（`DRAFT_MODIFIED_DURING_SAVE` / `SAVE_DURING_NOTIFICATION`）保留草稿并可重试
- **通知期封锁**：BATCH_SAVE **与** RELOAD 通知期间 save/flushRaw/reload 与 Legacy/Authority raw mutation 全部 fail-closed（`SAVE_DURING_NOTIFICATION` / `ConfigConflictException`）；listener 观察稳定提交快照
- 写前检测：expected 为 bootstrap/上次成功写的精确字节快照；同 classloader **参与式 writer** 串行 + 写前比较；**不是** OS 级跨进程 CAS；外部 writer 的 compare→replace 窗口不承诺；same-byte ABA 允许；硬链接/inode 写域**不保证**（仅 canonical path 语法别名）；`writeAll` 低级无 expected 比较写，不能称 CAS，生产 ConfigManager 不旁路
- 故障注入缝仅 `Persistence` 包级；`AtomicFileWrites` 无 public install/clear
- `DraftBuffer` 事务 base 在 open 时从 Authority 冻结；capture 只比 base；成功 commit 才推进 base/current/draft；`setDraftAndCurrent` / prefill **不得**改事务 base；BOOLEAN 严格 `Boolean`；STRING/NUMBER/LIST 类型一致
- 发现态列表 prefill 用 **局部只读初值**（renderer/bridge）：不写 DraftBuffer、不在 render 调 `seedPresentation`/Signal.set、不清算 validation；用户首次**真实控件**交互再 `onFieldEdit`
- `ConfigManager` owner token：`openDraft` 绑定；`save` 拒绝 foreign/unbound draft（`DRAFT_OWNER_MISMATCH`）；`owns(draft)` 公开查询不泄 token；`replaceDraft` 须同 owner + schema 兼容；`ConfigScreen` 构造 fail-fast 要求 manager owns adapter draft
- `DraftSignalAdapter` 全部 mutator 必须在构造线程（UI 主线程）；跨线程 `IllegalStateException`（含 expected/actual 线程名）且 Draft/Signal/revision/validation/conflict/feedback/presentation/effect 零变化
- `replaceDraft` 须校验 schema 路径/类型兼容；保持 Signal/Computed identity；不兼容时拒绝且旧状态不变；callback/owner dispose 防泄漏
- `ConfigSaveListener`：event 回调不直接 Bridge/font；经 `ModernConfigApplyCoordinator` + `MainThreadDispatcher` CLIENT 队列 latest-wins 主线程回灌；不可变 Registration 线性化；no-spin（**lock+batch swap** 精确批次，禁止 `queue.size()` 快照预算；单 drain 一次 apply；drain 期间 enqueue 留 next-drain）；失败 reoffer 新事件优先；BATCH_SAVE 与 RELOAD 均应从 Authority 回灌，保持保存/重载语义区分；忽略 RELOAD 会导致磁盘重载后运行态陈旧
- 协调器测试 hook（`TEST_BEFORE_OWNER_RELEASE`）无论 Runtime/Assertion/Error 均须嵌套 finally **无条件** `enqueueOwner=false`，再传播异常；否则下一 tick submit/retry 卡死
- MainThreadDispatcher：ErrorSink 若抛 AssertionError，与任务体 Assertion 同路径——旧 batch 尾重排 + rethrow；per-side drain owner CAS，第二 drainer 返回 0，不可双消费
- section raw overlay：schema 优先仅限 MAP；disk 上 schema section 为 scalar/list 时 bootstrap/reload fail-closed，禁止静默默认覆盖
- SIMPLE_LIST 保存值契约：`List<String>`，**严格拒绝** null 元素（每个元素须为非 null String）

- 冲突诊断日志至少 WARN/DEBUG 含 conflictType，避免敏感值与逐字段噪声
