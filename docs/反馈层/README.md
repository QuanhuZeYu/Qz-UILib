## 完整记录入口

- [单项故障复盘](errors/)：按症状、模块名或错误原文检索；保留既有文件名，方便旧链接与 Git 历史定位。
- [存量踩坑合集](踩坑记录.md)：按时间倒序保存的历史条目，可用编辑器或页面搜索查找关键词。
- [历史审查报告](../历史报告/审查/)：需要了解问题背景、审查范围或当时的验收边界时查阅。

历史排查线索不表示故障仍存在，也不构成现行要求。使用旧处置方案前，先核对当前源码、环境和 [规格状态](../开发者文档/规格文档/README.md)。

## 记录放在哪里

按 [协作规范](../../AGENTS.md) 维护：重要踩坑优先写在缺陷所在的源码或测试注释里；仅当结论跨模块、需要读代码之外的上下文才看得懂时，才新增单项故障复盘。存量记录不批量搬迁，后续维护对应代码时就近整理。

施工过程与一次性结论不进入长期指南；确需跨轮恢复的内容写简短任务笔记。记录应区分现象、定位依据、处理方式和实际验证范围，未执行的测试或运行态如实说明。
