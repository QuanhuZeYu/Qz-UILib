# ERROR-20260817-scene-member-grid-row-rekey-layout-convergence.md

**日期**：2026-08-17（首次出现于第十一轮，本文补档）
**组件**：`MemberGrid`（已选择成员多列网格）
**状态**：已规避（测试双布局收敛 + 数据身份契约）

## 现象一：删除首成员导致幸存卡片节点重建

成员网格行键 = 行首成员 `memberId`（`rt.forEach` 按 key 复用节点）。删除行首成员后
行内容前移，行首 id 变化 → 行 key 变化 → 整行（含幸存成员卡片）重建。测试若持有
删除前的节点引用，在删除后断言节点身份（`assertSame`）必然失败。

## 修复

- 契约改为断数据身份：删除幸存项必须精确移除它自己（再删除一次后列表为空），
  不把首项 id 转嫁给幸存项；节点身份不跨重组保留在测试注释中明示。

## 现象二：网格列数首帧推导导致测试节点引用失效

列数由首个 `layoutDoneSignal` 后按 viewport 宽自动推导：首帧列数=1，收敛帧列数
变化会重挂载单元格，测试持有的节点引用变陈旧，点击落到游离节点上静默无效。

## 修复

- 测试按面板约定执行两次 `layoutPanel`（`openDuplicateMemberPicker` 与成员断言前
  均双布局），与宿主逐帧布局行为对齐。

## 教训

- 自动推导型布局参数（列数/窗口行）存在「收敛帧」：单元测试必须布局到收敛再取节点。
- keyed 列表的行键必须选「结构稳定」的标识；成员网格行键=行首 id 是数据语义下的
  合理选择，但删除行首必然重组，任何跨重组节点身份断言都应改为数据身份断言。
