# skyline 紧密装箱边界 bug 导致 slot 重叠、字符渲染错位

## 现象

- 真机：部分字符渲染不对，看起来是页上多个字符的部分像素混在一起（单个字符的 UV 区域跨越两个相邻 slot，显示两个字符各一部分）。
- 少量字符受影响、无崩溃、无日志报错；仅在 skyline bottom-left 装箱替换（提交 7b067172）之后出现。

## 链路与根因

渲染 UV 全部由 upload 事务缓存在 runtime tables 的 slot x/y 与 ink 度量驱动，与装箱算法解耦；location 打包（pageIndex 16 位 + slotIndex 16 位）在真实使用密度下也不会溢出。根因在 GlyphPage.addSkylineLevel 的三个边界处理：

1. **横跨占位右边界的段被整段吞并**：区间跨越 levelRight 的段按「段起点 < levelRight」整体吞掉，右半区间的原高度丢失，尾节点错误继承下一段高度；
2. **纯吞并分支只更新局部高度、不更新 tail 段高度**：被吞段高度高于占位高度时，tail 段被低估；
3. **占位完全落在 tail 段内（无吞并）时，尾节点高度取下一段高度而非 tail 段抬升前高度**。

三处都造成天际线低估 → 后续 probe 把新 slot 放进已占区域 → 后上传字符的像素覆盖先上传字符 → 渲染端采到混合像素。

## 排查方法论

- 先排除渲染侧（UV 参数全部来自 tables 缓存，链路未动）与 location 位宽（16 位 slotIndex 需单页 6.5 万槽才溢出，不现实）。
- 新增装箱**不重叠性质测试**（确定性混合序列 / 随机序列 / 密集小 slot / 回退恢复，锚定任意分配序列下 slot 两两不重叠、不越界、索引连续）当场复现重叠。
- 诊断输出每次放置后的天际线段 + 独立 Python 复现脚本逐放置验证不变式（每个已放置占位矩形覆盖列的天际线高度必须 ≥ 占位顶），定位首个出错的 addLevel 输入输出。

## 修复

- 吞并循环统一把被吞段高度并入 tail 段；横跨段截断为右侧残留区间保留原高度；无吞并时尾节点继承 tail 段抬升前高度（提交 a88c9cc9）。
- 修复后 Python 复现 77 槽全部通过不变式检查，Java 性质测试与 page 包全量测试全绿。

## 教训

- 装箱算法替换必须配性质测试（不重叠/不越界/索引连续），不能只靠行为测试的小序列锚定——三个 bug 都只在混合尺寸序列下触发。
- skyline 节点语义（节点 (x,y) 表示区间 [x, next.x) 高度）与尾节点高度继承规则要显式写清，吞并/截断/无吞并三种结束形态各自验证。
