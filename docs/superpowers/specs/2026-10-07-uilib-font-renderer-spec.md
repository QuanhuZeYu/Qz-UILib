# UILib 字体渲染器专有规格

> 状态：待用户审阅。本文是字体选择、度量、字形及绘制资源的专项权威；字体实现暂停，已取得字体文件与探针不表示规格已审定或生产实现已完成。

## 1. 目标与范围

UILib 提供自有字体渲染器。默认随库提供 Minecraft 中文等语言使用的 GNU Unifont，允许配置选择系统字体。页面和控件只声明文本与字体意图，框架完成匹配、度量、排版及字形绘制。

本规格不定义 Markdown/DSL 语法、数学命令集合或文本编辑业务协调；它们通过共同文本几何消费字体能力。数学深入继续暂停。

## 2. 坐标与文本几何

布局和字号使用原生 framebuffer 像素，Minecraft GUI Scale 不改变字形的像素尺寸。窗口大小变化改变可用宽度并自动重排；坐标、输入及裁剪的共同合同见[核心规格第 9 节](2026-10-07-uilib-core-contract-design.md#9-平台边界与验收)。

测量、换行、省略、基线和绘制使用同一字体事实及字形定位结果；不得用一种字体度量另一种字体字形。字形结果保留可解释的源文关系，不能以 UTF-16 单个 char 任意切割代理对或组合文本。复杂字形与脚本支持边界须由设计明确并以真实字体行为验证，不凭测量函数声称全部脚本支持。

内容、样式及资源变化按实际依赖失效，稳定内容不每帧重新排版。绘制消费已发布结果，不修改业务状态或重新布局。与共同文本流程的协作见[核心规格第 13.1—13.2 节](2026-10-07-uilib-core-contract-design.md#131-模块职责与数据流)。

## 3. 字体选择与资源生命周期

字体能力负责字体选择、字符匹配、度量与可绘制字形资源；消费者声明字体意图，不管理 glyph 页、纹理上传或后台构建线程。度量与绘制不得从不同字体配置或资源代际拼接结果。字体、字号、语言及资源变化沿核心规格第 3.3 节更新相关排版和绘制。

运行时管理字体资源构建、切换和释放，后台工作不得越过平台边界直接执行 GL。资源的持有者负责释放，控件卸载不擅自销毁共享字体资源；资源切换不得留下已释放纹理供有效绘制计划访问。缓存按实际字体和资源依赖失效，具体候选代际、租约、页分配和发布算法留给设计。

同一字符允许在不同内容声明的字体中同时存在。字体选择以各内容的字体意图及有效资源为依据，不因其他控件或内容先加载该字符而被迫采用其字体。对应度量、字形资源及绘制保持各自一致，不将普通文本全局“一个码点只能对应一种字体”作为能力边界。

相同实际字体及字形资源允许复用，不同字体结果不得互相覆盖；动态切换一段内容的字体只使相关依赖失效，不偷偷改写其他内容的字体结果。字形生成按实际需求进行，不要求预加载所有字体或为每个控件独立复制全部资源。字体身份、缓存键、字形页组织及加载实现留给设计，不冻结当前 codepoint + FontType 索引结构。

每段内容使用其声明的有序字体候选；未显式声明字体时使用主题默认候选。候选不能提供所需字符时，框架按顺序继续回退，全部候选仍缺字才显示替代字形并提供诊断，不静默删除原字符。候选声明与主题变化沿实际依赖自动更新选择、度量和绘制，不受其他内容加载顺序影响。

回退的实际字体与字形必须在测量和绘制中一致，不能用首选字体的度量绘制回退字体的字形。字符匹配与文本整形的具体组织由设计确定，不能以逐 UTF-16 char 回退破坏有效字符或组合文本。替代字形的具体形状与诊断聚合方式留给统一设计，原内容仍由调用方持有。

字体资源不可用与内容缺字须能区分，不把当前操作系统恰好安装的字体集合当恒定条件。加载与重载使用统一框架入口，出错通过统一诊断报告；不增加业务侧失败策略选择，不要求分别实现首次初始化失败呈现、重载失败保留旧资源或自动恢复分支。内部错误处理由设计承担，始终遵守度量/字形一致及资源生命周期合同；缺字回退不掩盖资源加载错误。

## 4. 自有字体渲染器与来源

UILib 自行完成字体度量、文本排版、字形资源构建与 GL 绘制，不委托 Minecraft FontRenderer 测量或绘制，也不将原版纹理绘制包装成正式字体后端。通用文本能力与平台 GL 回放分离，前者可在无 Minecraft 环境验证。度量、换行及绘制共用同一次字形定位结果，绘制不重新读取字符串并调用另一套布局。

用户裁定：UILib 默认提供 Minecraft 使用的开源字体，并允许配置选择系统字体。默认字体文件随 UILib 分发，保存实际字体版本、来源及许可证；不得直接把 Minecraft 资源包中的字体图片推定为可重新分发的开源字体。默认字体选 GNU Unifont（Minecraft 中文等细密字符所使用的开源字体），具体分发文件采用官方发布版本并记录校验值。来源：[Minecraft 字体说明](https://minecraft.wiki/w/Language)、[Unifont 官方发行](https://unifoundry.com/unifont/index.html)、[官方许可证](https://unifoundry.com/LICENSE.txt)。UILib 不以此承诺复制 Minecraft 拉丁像素字形。系统字体通过统一字体配置枚举与选择，以当前系统实际提供的字体为准；配置应用后通知相关排版失效，无需关闭页面。明确指定但不可用的字体按本规格第 3 节报告资源错误，不静默换成任意系统字体。

每段内容仍采用有序候选，系统字体与内置字体可在同一页面并存；默认开源字体可作为显式候选参与缺字回退。字号表达实际 framebuffer 像素，字体选择不改变 GUI Scale 独立性。颜色变化只影响绘制；字体候选、字号及字形资源变化影响度量与排版。字体缓存共享、按需求构建且有界，节点卸载只释放自己的引用，运行时负责共享资源最终释放。

首轮人工验收分批进行：先检查中文/英文可见、改变字号、GUI Scale 不影响面板像素大小；后续单独检查系统字体切换及缺字回退。各轮操作保持短小，CPU 度量/排版通过不替代真实 GPU 字形效果验收。

## 5. 验收边界

无平台自动化采用真实字体文件验证中英文度量、换行、候选选择、动态字号、来源变化及字形光栅；只在宿主边界替换GL。GPU绘制、裁剪、状态恢复及原生像素显示必须在指定MC实例验证。字体文件取得和CPU探针通过不能代替这些验收。

每次人工测试项目少且易操作，逐项给出预期，遇到入口或绘制异常先收敛该问题，再展开下一批。
