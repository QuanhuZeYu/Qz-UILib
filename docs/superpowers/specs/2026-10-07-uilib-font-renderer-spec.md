# UILib 字体渲染器专有规格

> 状态：细化草案，待用户审阅，生产实现暂停。本文是字体选择、度量、整形、字形绘制及资源生命周期的专项权威。第 1.1 节是已裁定要求；其余明确行为为本次提出的规格方案，不能记作用户已逐项认可。已下载字体、CPU 探针与实施计划均不代表字体系统完成。

## 1. 目标与责任

### 1.1 已裁定要求

- UILib 采用原生分辨率，不受 Minecraft 窗口 GUI Scale 影响。
- UILib 必须采用自己的字体渲染器。
- UILib 默认提供 Minecraft 使用的开源字体，可以配置选择系统字体。
- 规格独立维护；先审阅规格再实施，避免实施自行解释笼统要求。
- 无平台真实集成验证优先，GPU 画面由实机验收；人工每轮短小、容易操作。

### 1.2 用户可见目标

同一页面可以同时显示不同字体和字号的中文、英文及 Unicode 文本。改字体或字号后，框架自动更新换行、自然高度、基线、裁剪及交互几何；业务不重挂载页面、不手算字宽。GUI Scale 改变时同一声明字号的字形像素尺寸不变。

字体服务不是仅将原版 drawString 换一个名称。正式路径不调用 Minecraft FontRenderer 度量或绘制，不使用原版字符宽度表、字体图片或 Tessellator 作为字体实现。

### 1.3 模块边界

| 参与者 | 输入/职责 | 不承担的职责 |
| --- | --- | --- |
| 业务/控件 | 原文、字体候选、字号、样式及文本布局意图 | 字符宽度修补、glyph 分页、纹理上传、区域同步 |
| 内容转换 | 按明确模式解析原始/Minecraft格式/DSL/Markdown内容 | 选择 GPU 资源、改变业务原文 |
| 字体与文本排版 | 匹配实际字体、整形、换行、基线和字形定位 | 发布业务状态、启动外部程序 |
| 字形构建 | 从实际字体生成可绘制字形与度量 | 在后台线程操作 GL |
| GL 回放 | 消费已发布的字形定位、颜色、裁剪及有效资源 | 重新选择字体、重新换行、回读节点 |
| 运行时 | 资源通知、缓存限额及共享资源释放 | 让控件管理共享字体生命周期 |

原生坐标、节点生命周期与呈现批次沿[核心规格](2026-10-07-uilib-core-contract-design.md)第 3、5、9 节。字体在这些边界内提供能力。Markdown/DSL 语法、数学命令和文本编辑提交策略不在本专项重新定义；数学深入继续暂停。

## 2. 字体来源与选择

### 2.1 默认字体及分发

默认来源为 GNU Unifont。Minecraft 中文等细密字符使用这一开源字体来源，不能据此宣称它复制了 Minecraft 的全部拉丁像素字形。

本轮拟采用未经修改的 GNU Unifont 16.0.04 标准字体，随 UILib 分发文件、许可证与来源记录。文件版本固定用于可复现构建，不能在运行时联网下载最新版。升级字体文件属于可见资源变更，必须重新验证度量与字形效果。

来源：[Minecraft 字体说明](https://minecraft.wiki/w/Language)、[Unifont 官方发行](https://unifoundry.com/unifont/index.html)、[16.0.04 文件](https://unifoundry.com/pub/unifont/unifont-16.0.04/font-builds/unifont-16.0.04.otf)、[上游许可证](https://unifoundry.com/LICENSE.txt)。采用 SIL OFL 1.1 分发并保存实际取得的完整上游许可。不直接复制 Minecraft 字体图片并推定其许可。

### 2.2 字体身份

声明来源须区分随库字体、系统字体及资源字体，不能只用一个模糊 family 字符串混合来源。字体候选必须能确定实际 face；系统家族内常规/粗体/斜体 face 的解析结果可诊断。

字形资源身份至少区分实际字体来源与版本、实际 face、字形标识、字号及影响光栅的样式/质量参数。码点本身不是字形身份：同一码点可在多字体中同时存在，整形也可能使多个码点对应一个字形或一个码点对应多个字形。

### 2.3 系统字体配置

统一配置提供当前机器的字体枚举、默认有序候选选择和应用入口。列表显示可读名称，同时保留确定来源的选择值。系统枚举来自实际运行环境；有明确刷新入口，不在每帧扫描、不假定首次枚举永久有效。

配置变化立即可读，框架按依赖使呈现失效；已打开页面在下一次准备呈现时自动更新，无需重启或重新挂载。持久化写入沿 UILib 配置能力，不由每个页面各写文件。

系统字体仅从本机已安装集合解析，不随 Mod 复制系统字体文件。不把不存在的系统名称静默解析成 Java Dialog、SansSerif 或其他任意字体。不存在、文件损坏、格式无法读取和渲染设备失败分别报告可定位错误；它们不是缺字回退。

### 2.4 候选优先级与继承

字体声明是一份有序候选列表。优先级为：内容显式声明 → 最近文本样式作用域 → 主题默认候选。显式声明的列表替换继承列表，不与父级隐式拼接；声明者想保留默认回退时明确引用默认候选。初始化默认列表包含内置 Unifont。

同一内容运行中按候选顺序选择能够提供完整有效文本簇的实际字体。不能让另一个控件先加载某字符后抢占该字符字体。A 内容换字体不改变 B 内容显式选择的结果；共享的是相同实际资源，不是全局字体选择。

### 2.5 缺字与替代

回退至少以完整 Unicode 文本簇为边界，不在代理对、组合标记或 emoji ZWJ 序列中间换字体。字体存在但无所需字形才尝试后续候选；实际整形产生缺字也必须进入缺字判定。

所有候选均不能绘制一个簇时，显示一个可辨识替代字形，不静默删除该簇、不把原文改成替代字符；该替代占用非零 advance，来源范围仍对应原簇。缺字诊断包含文本位置、Unicode 码点和尝试候选。替代字形的实际度量与画面共用同一结果，不承诺固定系统外观。

选择候选不能提供组合整形的已知能力时，要报告支持边界，不能把逐码点拼接结果包装为完整整形。加载错误不因列表后面恰好存在可用字体而被隐藏。

## 3. 样式、尺寸与坐标

### 3.1 字号语义

字号表示字体 em 尺寸，单位为实际 framebuffer px，不是印刷 pt，不使用操作系统 DPI 或 Minecraft GUI Scale 转换。同一字号不保证所有字体墨迹外框一样高；字体的 ascent/descent 和字形形状不同是合法现象。

规格允许正的有限小数字号；零、负数、NaN 和无穷值为无效声明。内部度量和定位保留小数，不在逐字符 advance 后取整。布局整数盒在最终聚合处向外覆盖，不能逐字四舍五入造成累计漂移。

### 3.2 样式能力

首期文本样式包含有序候选、字号、常规/粗体、正体/斜体、颜色、下划线及删除线。颜色为统一 RGBA 语义；透明度变化不触发字体度量。文本内容模式负责解释格式码，本字体层只接收明确样式，不扫描正文中的 § 或标签猜样式。

粗体/斜体优先选同家族实际 face；没有对应 face 时允许明确记录的合成样式，其度量与绘制必须一致。不能测常规字形再靠画两遍假粗体导致溢出。下划线/删除线采用该运行实际字体的线位置和厚度，与字形一起受裁剪；不改变文本 advance。

首期默认采用灰度抗锯齿，不采用依赖显示器 RGB 排列的 LCD 子像素图像。Unifont 字形仍保持其来源造型，不承诺像素网格放大与平滑放大观感等价。SDF/MSDF、彩色 emoji 和可变字体轴不作为首期承诺。

### 3.3 基线和行高

每个字体运行提供 ascent、descent、建议行间距及字形墨迹边界。混合字体/字号的一行，共享一条基线；行 ascent/descent 分别覆盖该行实际运行，不能沿用第一个字的字体高度。

默认行高由本行 ascent + descent + 非负建议行间距决定。额外行间距由文本声明增加，不回写字体 metrics。显式固定行高小于内容所需高度时，保持声明行框并报告溢出；是否裁剪由文本/祖先 overflow 声明决定，不静默缩小字体。

空行使用该位置有效文本样式的默认行 metrics。连续换行及末尾换行保留相应空行。空字符串自然宽高为零，输入框等最小行高由控件自己的尺寸声明承担。

### 3.4 advance 与墨迹边界

文本 advance 用于运行排列、换行及光标关系；墨迹边界表示实际可见字形范围。空格可以有 advance 而无像素，斜体与组合标记可以伸出 advance 范围。两者必须同时保留，不能用非透明像素外框代替排版宽度。

父盒外文字是否绘制与交互服从核心 overflow/clip 合同。自然内容测量须报告所需 advance 及可见溢出，统一布局/裁剪使用这些事实，不由控件另补斜体偏移。

### 3.5 原生分辨率边界

字号、字形定位、裁剪及指针命中共用 framebuffer 像素。宿主将原生鼠标位置转换为同一原点与轴方向；高 DPI 场景中窗口坐标与 framebuffer 不一致时，只在宿主边界转换一次。不能拿缩放后的 GuiScreen.width 与原生 Mouse 坐标混合。

GUI Scale 变更不重定文字大小；framebuffer 宽高变更只改变布局约束并重排。无需字体重新光栅的宽度变化复用可用字形资源。绘制须使用实际 viewport，不能假定默认 viewport 始终覆盖整个窗口。

## 4. Unicode、整形及换行

### 4.1 输入与索引

原文以不可变字符串或等价内容值提供，位置可关联原文 UTF-16 范围，但合法切分/复制/命中必须沿 Unicode 边界。有效代理对不可截断；无效孤立代理项产生替代呈现与来源诊断，不能使整段文本消失。

CRLF 作为一个显式换行，CR 和 LF 单独也换行；这种识别不改写业务原文。空格、重复空格和行首行尾空格在原始文本模式中保留。富文本/Markdown 的空白折叠由对应转换层明确表达。

Tab 默认前进到下一制表位；默认制表位间距为当前基础样式四个空格的 advance，允许声明覆盖。制表位相对当前行内容起点，不能把每个 Tab 固定替成四个字符而丢失对齐关系。

### 4.2 首期支持边界

首期明确验收中文（含字体实际覆盖的扩展字符）、拉丁字母/数字/标点、中英文混排、有效补充平面码点、组合附加符号及候选回退。

排版须以实际字体的整形结果保留 kerning、连字及组合定位，不逐字符相加绕过整形。连字/组合簇内部不能作为随意换行或省略点。

双向文本、阿拉伯文及印度文字完整脚本整形、彩色 emoji 等能力尚待单独裁定，不在本稿据 Java2D 函数存在就宣称支持。有效 Unicode 内容即使属于未承诺脚本，也不能因其范围被拒绝或静默丢弃；诊断应区分显示字形与语义排版是否支持。若本次审阅要求完整支持这些脚本，须先补齐方向、候选与交互例子再定实施范围。

### 4.3 宽度约束与换行策略

排版接收确定的非负可用宽度。未受限测量只按显式换行分段；受限测量使用控件最终获分配的宽度，不能先按更宽宽度测高，再把窄盒直接交给绘制。

默认自动换行优先采用 Unicode 合法断行机会，中英文混排遵守标点禁则，不能任意把闭标点放行首或开标点放行尾。单个词或其他不可断片段超过行宽时，默认在完整字素簇边界紧急断行；单个簇本身仍超过宽度时，把整个簇放在独立行并报告溢出，不裁成半个字符、不自动缩字号。

可声明禁止自动换行，此时只处理显式换行并保留横向溢出。零宽约束禁止将正宽簇逐个生成无穷行：保留每个显式段落的完整溢出行，实际可见部分由裁剪决定。行内制表、不可断空格、显式软换行等特殊字符的边界由统一排版解释，不由按钮私有逻辑补齐。

### 4.4 省略

省略由文本控件声明最大可见行数/高度与尾部省略策略，默认自动换行不自动省略。被截掉的原文仍保留以供提示或复制；这里只生成显示结果。

尾部省略符优先使用有效候选中的 U+2026；不存在时以三个点组成省略标记，整体作为标记定位。预留标记实际 advance 后，只在完整簇边界移除末尾内容；标记本身宽于视口时保留其溢出并裁剪，不拆开标记或把剩余宽度算成负值。

不可用高度容纳一条完整行时不画半行，报告未展示的源文范围。完整文案如何通过鼠标/键盘访问沿控件合同，不在字体服务中自行弹窗。

## 5. 共同排版结果与绘制

### 5.1 排版结果必须承载的事实

结果具有同代字体资源身份和来源范围，至少可观察到：行顺序、行框/基线、实际字体运行、每个字形标识与小数位置、advance/墨迹边界、源文簇关系、省略范围及缺字诊断。首期公共 Java 类名不是合同，但不能省掉这些事实再让宿主补算。

结果及其可达样式/字形载荷不可变。后续改原文、字体配置或释放节点不会篡改已发布计划。指针链接/选区等文本几何消费同一结果，不能按字符串长度猜命中区域。

### 5.2 回放规则

回放只消费结果保存的定位和字形资源，不再次读取节点、解析字符串、选择字体或调用另一套 measure。颜色、文本装饰和阴影（若控件显式声明）按明确绘制顺序合成；阴影不回写正文度量，外部可见边界包含其声明偏移。

字形使用 UILib 自有 GL 管线。字体后端可使用平台字体解析/整形/光栅库作为内部工具，但主流程、资源、排版结果与绘制属于 UILib；不能绕过本规格合同。Java2D/FreeType、灰度图集/SDF 等具体工具选择必须在设计说明里对应本规格，工具能力不足时报告差距。

### 5.3 裁剪、透明与宿主状态

文字、装饰及替代字形都受祖先裁剪，同一坐标边界用于显示与命中。实际触及的 GL program、VAO/VBO、活动纹理单元与绑定、混合参数、裁剪及其他 enable 状态必须恢复；不能因为当前宿主恰好不使用某状态而省略。

透明合成遵守统一颜色约定，纹理边界不能出现邻字串色；灰度alpha数据不被误当彩色像素。连续文本/矩形命令保持原顺序，不能为合批把前景字移动到后续遮挡物上面。关闭面板后的原版聊天、物品栏和其他 Mod GUI 不应被字体后端状态污染。

## 6. 动态失效与资源生命周期

### 6.1 变更影响

| 变更 | 必须失效 | 可复用 |
| --- | --- | --- |
| 正文/内容结构 | 该内容整形、换行、几何、绘制 | 相同实际字形光栅 |
| 字体候选/实际face/字体资源代际 | 依赖内容的选择、整形、度量与绘制 | 未依赖该资源的其他内容 |
| 字号/粗斜体/光栅质量 | 受影响度量及字形资源 | 无关样式资源 |
| 可用宽度 | 换行及最终行定位/几何 | 合法可复用的字体/字形资源 |
| 颜色/透明度 | 绘制 | 字体选择、度量及字形光栅 |
| GUI Scale | 不改变UILib像素尺寸 | 在framebuffer未变时全部有效结果 |
| framebuffer尺寸/viewport | 根约束、必要重排/裁剪 | 未变字号的字形资源 |

无变化帧复用结果，不全树重新扫描系统字体或重构字形。失效来源由框架追踪，业务不调用强制flush以维持一致。

### 6.2 缓存与预算

实际字体加载、排版结果、CPU光栅和GPU页分别有明确有限预算及可观测占用；预算值由实施设计给出并在审查中验证，不能使用“以后再限制”的无界Map。预算是性能策略，不限制业务允许出现的字符集合。

工作集超过预算时允许有序淘汰与重新构建，但不能漏字、用错字体或访问旧页UV。正在回放的命令必须有有效资源；GPU页重用不得改变同一计划后续字形内容。不同字体/字号/资源代际不覆盖同一缓存身份。

### 6.3 生命周期与线程

字体资源可在内容间共享。detach释放挂载订阅而保留逻辑声明；destroy释放所属呈现引用，不销毁独立业务状态或其他内容使用的字体。运行时最终关闭释放CPU/GPU资源，销毁通知不能访问已释放页面。

文件读取、字体解析、整形和CPU字形构建可以后台运行，GL创建/上传/删除仅在有效GL上下文所属线程。异步结果归属于其原始来源及资源代际；过时结果不能替换当前字体选择，关闭后的结果不能重新挂载页面。

本规格不新增自动重试、重载失败保留旧资源或业务选择补偿策略。初始化与重载错误沿统一诊断，内部清理保证资源一致；失败不能伪装成缺字或成功完成。

## 7. 错误与诊断

诊断至少区分声明无效、字体未找到、字体文件不可读/损坏、未覆盖簇、未承诺脚本排版及GPU构建/回放失败。记录可定位的来源/face/字号/原文范围或阶段，不泄露完整用户输入作为默认日志。

缺字与孤立代理项的替代呈现按第2.5、4.1节继续正常内容；无效参数在声明边界拒绝。字体加载或GPU失败不静默宣称正常渲染，也不自动调用原版FontRenderer兜底。
