# UILib 核心职责与交互规格

状态：**已确认规格，项目唯一规格权威**。用户明确指定本 spec 为唯一权威；它基于逐项认可的 D-01 至 D-53。该效力不表示生产实现、游戏产物或测试已满足要求。

## 1. 目标、范围与效力

业务作者通过逻辑数据和公开的 UI 声明表达界面，UILib 自动完成测量、排版、绘制与输入协调。标准控件覆盖常规需求，自定义控件通过正式扩展能力接入同一机制。动态内容、窗口、缩放、字体、语言、主题和权限变化无需重新打开页面或业务手动刷新。

本轮以 Architect 面板暴露的通用问题为入口，覆盖状态/呈现边界、布局、控件生命周期、文本编辑及输入范围。网络、配置、聊天、物品渲染等专项不在本轮重建范围；本稿不替下游选择业务校验、任务取消、权限策略或极小窗口方案。

逐项依据见 [裁定记录](<../../开发者文档/规格文档/反向规格/UILib反向需求基线.md>)；实现事实与历史反馈见 [冲突与证据](<../../开发者文档/规格文档/反向规格/需求冲突与证据缺口.md>)、[测试证据抽样](<../../开发者文档/规格文档/反向规格/测试证据抽样.md>)。这些记录用于追溯，不把未采纳建议或现有实现升级为要求。

本 spec 是项目唯一规格权威。旧规范正文退役删除；源码注释、测试、使用指南、历史裁定与调查资料只用于说明实现或证据，不独立定义要求。实现与规格不一致时按本 spec 记录迁移，不能用旧约定否决新设计。专项未覆盖的能力保持现状，必要规格缺口在本 spec 补齐，不从历史材料自动恢复约束。协作入口见 [AGENTS.md](<../../../AGENTS.md>)。

## 2. 核心模型与职责

```text
业务状态、编辑状态与纯派生
          ↓ 公开绑定与 UI 声明
控件逻辑树：内容、主题、尺寸意图、布局关系、显隐、滚动策略
          ↓ 宿主环境约束 + 控件测量/布局规则
框架维护的布局结果：尺寸、位置、内容范围、裁剪范围
          ↓
绘制与几何交互共用布局事实 → 不可变绘制计划 → 宿主 backend/replay

输入 → 当前有效范围内路由 → 编辑操作或业务意图 → 状态变化
```

箭头表达职责与依赖，不规定每个步骤必须同步或延迟，也不预定实现类、队列或快照结构。

| 责任主体 | 持有与负责 | 不由其承担的职责 |
| --- | --- | --- |
| 业务/页面作者 | 业务权威值、校验、任务与事务；选择提交和适配策略；持有独立编辑状态 | 普通排版的最终尺寸/位置计算，手动 flush/layout/paint |
| 状态系统 | 直接状态读写、纯派生及其一致性，显式副作用的作用域机制 | 依赖控件挂载或 UI 帧才能成立 |
| 控件作者 | 内容测量、内部布局、绘制与交互规则，以及可通知的依赖 | 绕过框架维护另一套外层布局、坐标或输入所有权 |
| 呈现运行时 | 绑定、变化追踪、测量布局、绘制与输入协调、控件生命周期 | 推断业务权威、网络事务或结果含义 |
| 宿主适配层 | 可用空间、缩放、资源与原生输入信息、平台转换和运行入口 | 把平台类型或 GUI Scale 混入核心闭环 |

UI 变化以 state/signal 驱动；输入 handler 发布业务状态或意图，不直接改节点属性或树结构。焦点、capture 等权威交互命令通过路由器受控入口执行。公开声明能力与 handler 的写入边界不能混为一谈；挂载后结构变化的接入方式在接口设计中遵循本节状态/意图边界。

主题、文案、尺寸意图与子控件关系属于 UI 逻辑描述；实际尺寸、位置和裁剪范围属于框架维护的结果。业务可读取公开布局信息用于锚定等明确用途，但不直接修改结果，也不读回结果再写尺寸来补偿普通排版。逻辑描述可以由现有控件与响应式能力承载，不要求另建配置树。

## 3. 状态、派生与变化传播

### 3.1 状态独立性与可见性

状态与派生系统不依赖控件挂载或 UI 帧推进即可使用。在合法状态访问上下文中，直接状态写入后，随后读取同一状态得到新值，连续读写不会因旧已提交值覆盖前一步。此要求不赋予任意线程修改 UI 的权限。

状态可读与画面呈现分开：业务无需调用 scheduler、flush、layout、paint 或 replay；最终状态呈现允许批处理，有顺序意义的编辑及通知追加必须依序保留。

派生计算只根据来源生成结果，不修改其他状态、控件或外部系统。副作用经显式订阅/Effect 执行，归属明确生命周期。业务副作用不依赖控件挂载；呈现绑定随卸载释放，独立业务副作用不得继续持有已卸载节点或输入绑定。

本稿不决定通用 Computed 的同步/按需求值方式、具体读取一致性、Effect 执行时机或批处理接口。正式主题派生入口的首次有效值要求在第 7 节单独成立。

### 3.2 自动更新职责

公开声明、可追踪状态、环境或内容资源变化，使相关结果失效，由框架在正常呈现流程中更新。自定义控件依赖框架无法感知的外部数据时，通过正式能力通知变化；通知不等于执行布局或绘制。

变化按实际依赖影响测量、布局或绘制。例如颜色通常影响绘制，字体、文案或内边距可能影响测量与布局。缓存须具备失效和释放来源，动态性不依赖每帧全量重算；不承诺每次仅重算一个节点。

声明修改、属性传播与布局/绘制执行分别设计，不要求所有属性修改统一延迟或逐条保存更新请求。属性传播的具体执行时机留给设计，纯派生读取不得隐含修改 UI。

## 4. 布局与自定义控件

### 4.1 布局输入与统一结果

宿主提供根可用空间及环境约束，页面声明排列方式、关系、尺寸意图、边界、间距、显隐与滚动策略，控件提供内容测量能力，框架组合求解。普通页面无需提供测量结果或布局回调。

自定义控件作者可定义内容测量、内部排列、绘制与交互规则，由框架调用并协调结果；外层仍可将其作为控件组合布局。扩展接入 UILib 自有布局、绘制、输入机制，保持裁剪、命中、动态失效与生命周期协调，不直接改写最终布局结果。

布局结果是绘制、裁剪、指针命中及滚动范围的共同依据。自定义内部命中使用框架分配的区域和坐标转换；绘制及输入不独立重建外层排版。禁用/失活等交互资格与几何命中分开检查。新旧结果在具体帧内如何生效仍属待设计边界，不由本条暗中规定。

### 4.2 尺寸意图与边界

| 声明 | 含义 | 空间不足时的规则 |
| --- | --- | --- |
| 固定尺寸 | 指定尺寸，不随内容自然增长 | 经自身边界限制后不因父空间不足自动缩小 |
| 自然尺寸 | 按内容、字体及声明的测量/换行规则求尺寸 | 默认不自动压小布局盒；明确缩减另行表达 |
| 填充/剩余空间分配 | 使用父容器可用空间或参与兄弟间分配 | 遵循自身边界，具体分配细则留给布局设计 |
| 最小/最大边界 | 独立于尺寸意图的合法范围 | 先按意图求值，再限制到范围；固定尺寸也受约束 |

同一种声明在宽、高、普通容器与滚动视口中保持相同含义。最小尺寸为硬边界，父空间不足也不突破；最小值大于最大值是无效声明。按已声明换行规则重新测量仍是自然尺寸，不等于测量后压小布局盒。

普通容器默认允许溢出，不自动裁剪或变成滚动容器；溢出不自动扩大其布局盒，可见范围受上层裁剪限制。裁剪及滚动明确声明；裁剪不改布局尺寸，隐藏部分不命中；允许溢出本身不决定父盒外子控件的命中遍历和重叠优先级。换行、重排、折叠是布局策略，裁剪、滚动是溢出处理，框架不擅自替页面选择。

### 4.3 动态面板与空间不足

页面声明标题、页签和操作区自然尺寸、正文占剩余空间并独立滚动。框架测量各区域，扣除间距和内边距后分配正文视口；固定区指不随正文滚动，不要求数值高度固定。文案、字体、主题、语言或窗口变化自动重新测量，业务无需 fixedChromeHeight 公式或访问标准控件内部文字节点。

极小窗口适配由页面声明，框架执行，可选择整体滚动、精简布局或最低适用范围；低于范围时提供明确说明及退出方式。框架不擅自缩字号、隐藏操作或改为整页滚动，不保证任意小窗口都完整显示所有区域。

合法空间不足按声明策略处理；无效声明及自定义规则产生非法尺寸、无法完成计算等错误，须有可定位诊断，指出控件或规则，不用默认结果掩盖问题。报错通道、故障范围及保留上一结果的政策留给运行时设计。

## 5. 控件身份、归属与生命周期

UILib 默认创建 UUID 作为唯一控件身份，业务无需提供，主要用于框架内部维护。移动与排序保留身份；框架不得静默接受重复身份，也不按位置、结构或文本推断新建控件等价于旧控件。具体唯一性保障留给设计。

一个实例同一时刻只有一个逻辑归属位置：子控件只有一个逻辑父节点，根控件没有逻辑父节点。重复加入另一位置须报冲突，不偷偷移动或复制。多处显示同一业务数据使用独立控件共享状态，各自维护布局和交互。浮层绘制位置不必改变逻辑归属。

| 动作 | 生命周期与资源效果 |
| --- | --- |
| 创建/组合 | 未挂载即可维护逻辑描述，不拥有宿主输入，也不执行宿主绘制 |
| 挂载 | 接入宿主布局、绘制与输入流程 |
| 普通更新/排序/移动 | 持续存在控件保留身份及合法交互状态，移动明确表达 |
| 隐藏 | 不等于永久删除；交互释放按有效范围及现行 collapsed 例外处理 |
| 卸载 | 释放焦点、输入及挂载绑定，保留逻辑树和身份，允许重新挂载 |
| 明确移出保留 | 解除原归属及挂载关系，保留子树供之后使用 |
| 永久删除/销毁 | 终止控件及当前所属子树生命周期，释放所拥有订阅与资源；不能重新挂载 |
| 销毁后重新创建 | 新 UUID、新生命周期，不自动继承旧焦点、选区或滚动 |

独立业务状态和编辑状态由其持有者管理，控件销毁不连带销毁这些状态或外部共享资源。自定义控件负责释放自己拥有的资源。

普通动态更新保持草稿、光标、选区、合法焦点与滚动状态，不用整页重建代替更新。滚动范围缩小时仅限制到新有效范围；用户主动导航到不可见目标时允许第 6 节的必要滚动。重新挂载按当前描述和环境布局，不自动恢复旧焦点或输入所有权；具体跨挂载状态恢复留给设计。

## 6. 输入范围、宿主与焦点

### 6.1 范围、消费与模态

宿主输入经适配边界进入；原生输入只由一个消费者递交，范围预览只读、不消费输入，按选定范围分发；一段手势只有一个输入所有者。第二鼠标键整段吞掉，不建立第二 owner；失活 owner 取消后尾部吞到物理结束，禁止误触点击。实现差距按本节修正。

ESC 先交当前范围处理者，消费即停止外层关闭；未消费才进入页面关闭策略或宿主默认行为。宿主依据处理结果 fallback，不在输入尚未处理时抢先关屏。关闭确认及草稿去留归业务。

模态范围激活期间，指针、键盘、文本及焦点导航只进入该范围与所属交互浮层；外部点击可按声明请求关闭，不同时激活后台。交互浮层默认属于所属控件的输入范围，绘制层位置不改变归属；范围关闭、卸载或销毁时释放相关浮层输入。

内层模态激活时外层及后台不响应；关闭内层返回外层，已消费事件不继续作用于外层。外层结束时结束其所属内层及浮层。可恢复外层先前焦点的前提是目标仍存在、可聚焦且属于有效范围；初始焦点与恢复失败后的选择留给设计。

纯提示通知不抢焦点、不改 Tab 范围、不消费 ESC、不拦指针，不改变键盘/文本目标。带操作按钮的通知及其他非模态交互层需明确声明输入行为，不能按最高绘制层推断模态性。

### 6.2 导航与交互资格

Tab/Shift+Tab 默认按当前范围内逻辑树声明顺序前进/后退，跳过隐藏、失活及禁用控件，保留只读输入框。布局换行或窗口缩放本身不改变顺序；逻辑顺序明确变化时按新顺序。暂不增加独立焦点排序属性，UUID 不参与排序。

导航在范围内循环，单项保持焦点，空范围不建立焦点。导航至视口外目标时最小必要滚动，已完整可见不滚动；嵌套滚动区域逐层协调，目标大于视口时优先显示焦点或编辑位置。

只读输入框允许聚焦、Tab 到达、选择、复制和滚动查看，不允许修改或编辑提交。禁用不接受焦点、编辑或激活，Tab 跳过；转为禁用释放已有交互，不隐含提交或丢草稿，状态切换的释放不暗中触发失焦提交。禁用原因可通过不激活控件的提示查看。转只读时既有草稿去留归业务。

复合控件的文字与装饰属于其交互单元，内部独立按钮或输入框保留自己的焦点与命中；沿用现行 leaf hover/pressed 语义。

## 7. 主题与标准控件文案

正式主题派生入口保证有效初值，创建后即可挂载标准控件，后续来源变化继续更新；业务不补算初值或主动刷新。此保证不等于所有 Computed 必须同步求值，也不自动修复无效业务主题，初始化不能意外将派生内部依赖挂入外层重建 Effect。

标准控件公开换行、单行省略或允许溢出等文案策略，按实际可用文字空间测量、布局与绘制。语言、字体、主题及空间变化自动适配，业务无需访问内部子节点或布局后补宽度。

标准按钮默认换行，自然高度随内容增长；明确尺寸与最大高度仍受既定规则约束。高度受限且文字放不下时，默认仅显示完整行并标示省略，完整文本通过悬停或键盘聚焦后的被动提示查看。提示不改变按钮尺寸或焦点，不擅自增高或缩字号。作者可明确选择其他文案策略。

文字区域连完整行或省略标示都放不下时的呈现、提示时机和放置留给控件设计；框架仍保留完整文案。此默认不推广到所有控件。

## 8. 编辑状态与业务结果

### 8.1 草稿、提交与会话

标准文本输入支持光标定位、方向键、选区、复制/剪切/粘贴、全选、撤销/重做及中文输入法提交，单行/多行按各自换行规则处理。

编辑状态承载草稿、光标、选区及历史，允许负号、空串等未完成输入；业务最终值由业务校验和接受。框架管理可追踪编辑状态，不在控件中隐藏独立副本。业务值写入、草稿编辑、请求提交、接受/拒绝、结束/取消编辑及重置基线具备可区分语义。

业务选择随输入、确认、失焦或表单应用提交；框架执行声明，提交仅请求业务接受，不自动保存或发网络请求。实际修改或开始 IME 组字开启编辑会话，聚焦、移动、选择或复制不启动会话。随输入接受不结束会话；声明完成动作获接受且对应当前草稿时结束并显示规范化结果，焦点可保留。切换表单字段不隐含完成提交。

明确拒绝保留草稿并呈现业务原因，业务值不变，不强制抢回焦点。异步期间允许继续编辑，框架关联对应提交与草稿；旧结果不能覆盖新文本、改光标/选区、结束新会话或把旧错误算作新草稿结论，但对应旧提交状态仍如实呈现。

外部业务值变化不自动覆盖活跃草稿，业务决定保留、替换、取消或提示；无编辑会话正常同步业务值。UILib 不强制冲突选择界面。

编辑状态生命周期由业务管理，解绑控件不提交或丢弃草稿，保留的状态不得依赖旧控件绑定；不同对象可保留独立编辑状态。框架不把焦点当成会话判据。

### 8.2 键盘与输入法

输入法组字期间 Enter 仅确认输入法，不同时提交字段/表单；组字结束后的后续 Enter 才按字段声明执行。单行可以确认，多行默认换行，提交用明确快捷键或按钮。宿主提供真实组字状态及事件信息，不凭普通字符猜测。

单行/多行默认 Tab 切换焦点，需要制表符的编辑器明确开启模式；输入法消费优先，同一事件不再切焦点。ESC 默认不取消整个草稿；组字取消或内部菜单可消费，否则交给外层策略。业务需要 ESC 取消编辑时明确声明。

### 8.3 撤销历史

文本撤销/重做仅修改草稿，不直接撤销业务操作或回退权威值；后续提交仍按声明策略执行。随输入字段可以对撤销后的新草稿请求接受，业务仍可拒绝。

普通编辑（如模板插入）可进入历史；重置基线替换文本并清空撤销/重做，不能恢复旧对象文本。业务明确选择编辑、重置或切换独立状态，框架不猜测。提交成功保留历史，规范化与确认协调为完成步骤；撤销可恢复此前文本并开启新编辑会话，不反复陷入格式修正。

连续同位置输入及同方向删除分别合组，操作类型切换、移动光标、选区变化或切焦点结束当前组。粘贴、剪切、一次 IME 提交和模板插入各为完整一步；明确确认结束分组但不清历史。VS Code 体验及相关实现作为参考，具体阈值留给设计，实现落在 UILib 自有机制中。

### 8.4 业务边界

业务负责最终值权威、校验、异步任务及事务；UILib 接收明确状态或结果，管理编辑协调和呈现，不推断含义。乱序、超时、重试、服务端版本和表单原子性归业务，不继续逐项纳入通用规格。网络异常不能被框架自动算作明确业务拒绝。

控件关闭/销毁释放 UI 资源，不自动取消业务任务。UILib 提供宿主/生命周期协调能力；异步结果是否更新业务或重新打开页面由业务控制，不能凭过时控件绑定恢复已关闭视图。

## 9. 平台边界与验收

核心平台无关，平台输入只经适配边界进入；内部布局、绘制、裁剪和输入共享 logical px，GUI Scale 转换仅在宿主边界成对发生。数据/paint 层不调用 GL，paint/replay 传递自包含、不可变绘制计划。backend/replay 恢复触碰的 GL 状态，包括宿主已有非默认裁剪、stencil 与 mask。通用绘制不得使用 Minecraft 的 Tessellator 等包装类，应走直接 GL 或 UILib 自有管线。物品 icon 的 Minecraft 适配可完整委托 RenderItem.renderItemAndEffectIntoGUI（含 Forge hook 与标准光照）；此适配例外不扩及通用 GUI 或渲染核心。

优先复用 scene、响应式、PaintCommand、标准控件及字体能力，不能为了通过测试绕过生产路径或直连原版 GUI。

| 验收场景 | 可观察结果 | 必要通道 |
| --- | --- | --- |
| 直接状态连续读写与连续追加通知 | 读到新值，顺序操作不丢，业务无 flush | 独立状态/生产通知入口 |
| 派生主题后立即挂载 | 首次可用，后续主题更新，无业务初值补偿 | 正式主题入口与生产控件；宿主集成 |

| 尺寸边界、溢出与错误 | 硬边界保持，声明策略执行，无效输入可定位 | 生产布局及自定义控件扩展 |
| 长文案按钮 | 默认换行；高度受限按完整行省略，鼠标/键盘可访问完整文案 | 生产控件与提示路径 |

测试按能证伪哪个真实错误取舍。真实回归保护保留；fixture 自证、字段数量/源码次数及无需求来源的字面快照不能冒充生产保障。JVM/mock/固定数值本身不是删测试理由。本轮不新增测试或删除存量测试。

验收须记录源码提交与实际产物版本；历史调查中的游戏 jar 与源码基线不同，不能跨版本宣称通过。本轮纯文档整理不执行 build、测试或 runClient/runServer。
