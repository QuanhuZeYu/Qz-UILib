# UILib 核心职责与交互规格

状态：**已确认规格，项目唯一规格权威**。用户明确指定本 spec 为唯一权威；它基于逐项认可的 D-01 至 D-53。该效力不表示生产实现、游戏产物或测试已满足要求。

## 1. 目标、范围与效力

业务作者通过逻辑数据和公开的 UI 声明表达界面，UILib 自动完成测量、排版、绘制与输入协调。标准控件覆盖常规需求，自定义控件通过正式扩展能力接入同一机制。动态内容、窗口、缩放、字体、语言、主题和权限变化无需重新打开页面或业务手动刷新。

本轮以 Architect 面板暴露的通用问题为入口，覆盖状态/呈现边界、布局、控件生命周期、文本编辑及输入范围。当前核心职责已收束，后续专项章节持续补充至覆盖 checkout 内全部 UILib 能力，包含独立配置核心；尚未补齐的模块不视为已有完整合同。本稿不替下游选择业务校验、任务取消、权限策略或极小窗口方案。

逐项依据见 [裁定记录](<../../开发者文档/规格文档/反向规格/UILib反向需求基线.md>)；实现事实与历史反馈见 [冲突与证据](<../../开发者文档/规格文档/反向规格/需求冲突与证据缺口.md>)、[测试证据抽样](<../../开发者文档/规格文档/反向规格/测试证据抽样.md>)。这些记录用于追溯，不把未采纳建议或现有实现升级为要求。

本 spec 是项目唯一规格权威。旧规范正文退役删除；源码注释、测试、使用指南、历史裁定与调查资料只用于说明实现或证据，不独立定义要求。实现与规格不一致时按本 spec 记录迁移，不能用旧约定否决新设计。专项未覆盖的能力保持现状，必要规格缺口在本 spec 补齐，不从历史材料自动恢复约束。协作入口见 [AGENTS.md](<../../../AGENTS.md>)。

## 2. 核心模型与职责

```text
业务状态、编辑状态与纯派生
          ↓ 公开绑定与 UI 声明
控件逻辑树：内容、主题、尺寸意图、布局关系、显隐、滚动策略
          ↓ 宿主环境约束 + 控件测量/布局规则
框架维护的布局结果：尺寸、位置、内容范围、裁剪范围
          ↓
绘制与几何交互共用布局事实 → 不可变绘制计划 → 宿主 backend/replay

输入 → 当前有效范围内路由 → 编辑操作或业务意图 → 状态变化
```

箭头表达职责与依赖，不规定每个步骤必须同步或延迟，也不预定实现类、队列或快照结构。

| 责任主体 | 持有与负责 | 不由其承担的职责 |
| --- | --- | --- |
| 业务/页面作者 | 业务权威值、校验、任务与事务；选择提交和适配策略；持有独立编辑状态 | 普通排版的最终尺寸/位置计算，手动 flush/layout/paint |
| 状态系统 | 直接状态读写、纯派生及其一致性，显式副作用的作用域机制 | 依赖控件挂载或 UI 帧才能成立 |
| 控件作者 | 内容测量、内部布局、绘制与交互规则，以及可通知的依赖 | 绕过框架维护另一套外层布局、坐标或输入所有权 |
| 呈现运行时 | 绑定、变化追踪、测量布局、绘制与输入协调、控件生命周期 | 推断业务权威、网络事务或结果含义 |
| 宿主适配层 | 可用空间、缩放、资源与原生输入信息、平台转换和运行入口 | 把平台类型或 GUI Scale 混入核心闭环 |

UI 变化以 state/signal 驱动；输入 handler 发布业务状态或意图，不直接改节点属性或树结构。焦点、capture 等权威交互命令通过路由器受控入口执行。公开声明能力与 handler 的写入边界不能混为一谈；挂载后结构变化的接入方式在接口设计中遵循本节状态/意图边界。

主题、文案、尺寸意图与子控件关系属于 UI 逻辑描述；实际尺寸、位置和裁剪范围属于框架维护的结果。业务可读取公开布局信息用于锚定等明确用途，但不直接修改结果，也不读回结果再写尺寸来补偿普通排版。逻辑描述可以由现有控件与响应式能力承载，不要求另建配置树。

## 3. 状态、派生与变化传播

### 3.1 状态独立性与可见性

状态与派生系统不依赖控件挂载或 UI 帧推进即可使用。在合法状态访问上下文中，直接状态写入后，随后读取同一状态得到新值，连续读写不会因旧已提交值覆盖前一步。此要求不赋予任意线程修改 UI 的权限。

状态可读与画面呈现分开：业务无需调用 scheduler、flush、layout、paint 或 replay；最终状态呈现允许批处理，有顺序意义的编辑及通知追加必须依序保留。

派生计算只根据来源生成结果，不修改其他状态、控件或外部系统。副作用经显式订阅/Effect 执行，归属明确生命周期。业务副作用不依赖控件挂载；呈现绑定随卸载释放，独立业务副作用不得继续持有已卸载节点或输入绑定。

纯派生首次及后续读取均返回基于当前来源状态计算的结果。直接状态写入后，紧接着读取依赖它的 Computed，包含多级派生链，须得到当前结果；不返回尚未求值的占位值冒充结果。只有派生函数自身产出 null 时，null 才是合法结果。框架可按需计算、缓存或提前求值，不要求每次写入立即重算；派生读取不执行 Effect 或外部副作用。Effect 执行时机和批处理接口另行设计。正式主题派生仍满足第 7 节的首次有效值要求。

### 3.2 自动更新职责

公开声明、可追踪状态、环境或内容资源变化，使相关结果失效，由框架在正常呈现流程中更新。自定义控件依赖框架无法感知的外部数据时，通过正式能力通知变化；通知不等于执行布局或绘制。

变化按实际依赖影响测量、布局或绘制。例如颜色通常影响绘制，字体、文案或内边距可能影响测量与布局。缓存须具备失效和释放来源，动态性不依赖每帧全量重算；不承诺每次仅重算一个节点。

声明修改、属性传播与布局/绘制执行分别设计，不要求所有属性修改统一延迟或逐条保存更新请求。属性传播的具体执行时机留给设计，纯派生读取不得隐含修改 UI。

### 3.3 环境与资源变化的职责

宿主将语言、资源、可用空间和缩放等外部事实提供给框架；页面提供内容及适配声明。相关变化沿第 3.2 节依赖追踪进入测量、布局或绘制，业务不自行注册平台监听或重开页面来补偿正常动态更新。

语言变化影响翻译文案、排序或搜索所依赖的语言事实；同一语言下资源重载也可能更换字体、翻译资料或图像，相关内容依赖仍须失效。框架不得仅因语言码未变就认为所有文本资源未变。值与变化通知、代际的具体表示留给接口设计，不冻结现有 long 计数或单例结构。外部数据无法自动追踪时按第 3.2 节通过正式通知接入。

资源与环境订阅遵循第 5 节归属，卸载释放呈现绑定，不释放独立业务状态。环境依赖的缓存不以构造期快照保持旧值；复用缓存仍须响应其实际依赖变化。

### 3.4 渲染批次与一致性

框架根据已追踪变化，协调本批次的测量、布局、绘制区域、裁剪、滚动范围与命中区域，形成一致的呈现及交互结果。改变位置、大小、滚动、缩放或裁剪的内容，不能出现一套区域用于画面、另一套区域用于指针命中的情况。自定义控件及浮层遵守同一职责。

业务只发布逻辑状态或意图；框架决定批次如何合并、计算及生效。统一更新的是呈现及几何结果，不将直接状态或纯派生读取延迟到渲染批次，不要求逐条保存所有属性修改，也不将独立业务 Effect 绑定到 UI 帧。后续输入由框架使用一致的结果与有效交互范围处理；批次内的阶段顺序、缓冲或快照机制由设计选定。

## 4. 布局与自定义控件

### 4.1 布局输入与统一结果

宿主提供根可用空间及环境约束，页面声明排列方式、关系、尺寸意图、边界、间距、显隐与滚动策略，控件提供内容测量能力，框架组合求解。普通页面无需提供测量结果或布局回调。

自定义控件作者可定义内容测量、内部排列、绘制与交互规则，由框架调用并协调结果；外层仍可将其作为控件组合布局。扩展接入 UILib 自有布局、绘制、输入机制，保持裁剪、命中、动态失效与生命周期协调，不直接改写最终布局结果。

布局结果是绘制、裁剪、指针命中及滚动范围的共同依据。布局及命中区域归框架自动管理，在渲染批次中统一更新，画面与命中区域保持一致；业务不选择结果版本，不手动同步区域。自定义内部命中使用框架分配的区域和坐标转换，参与同一批次；绘制及输入不独立重建外层排版。禁用/失活等交互资格与几何命中分开检查。具体阶段顺序、结果存储和发布机制属于框架设计，不将“最后已呈现布局”另立为必须采用的实现合同。

### 4.2 尺寸意图与边界

| 声明 | 含义 | 空间不足时的规则 |
| --- | --- | --- |
| 固定尺寸 | 指定尺寸，不随内容自然增长 | 经自身边界限制后不因父空间不足自动缩小 |
| 自然尺寸 | 按内容、字体及声明的测量/换行规则求尺寸 | 默认不自动压小布局盒；明确缩减另行表达 |
| 填充/剩余空间分配 | 使用父容器可用空间或参与兄弟间分配 | 遵循自身边界，具体分配细则留给布局设计 |
| 最小/最大边界 | 独立于尺寸意图的合法范围 | 先按意图求值，再限制到范围；固定尺寸也受约束 |

同一种声明在宽、高、普通容器与滚动视口中保持相同含义。最小尺寸为硬边界，父空间不足也不突破；最小值大于最大值是无效声明。按已声明换行规则重新测量仍是自然尺寸，不等于测量后压小布局盒。

普通容器默认允许溢出，不自动裁剪或变成滚动容器；溢出不自动扩大其布局盒，可见范围受上层裁剪限制。裁剪及滚动明确声明；裁剪不改布局尺寸，隐藏部分不命中；允许溢出时，父盒外可见且未被裁剪的子控件部分仍可交互，框架不能仅因指针位于父盒外就跳过该子树；实际可见区域、祖先裁剪、输入范围和交互资格共同决定命中。业务不扩父盒或补命中区域来实现该行为。重叠优先级由统一绘制与输入规则处理，不能另外重建排版。换行、重排、折叠是布局策略，裁剪、滚动是溢出处理，框架不擅自替页面选择。

### 4.3 动态面板与空间不足

页面声明标题、页签和操作区自然尺寸、正文占剩余空间并独立滚动。框架测量各区域，扣除间距和内边距后分配正文视口；固定区指不随正文滚动，不要求数值高度固定。文案、字体、主题、语言或窗口变化自动重新测量，业务无需 fixedChromeHeight 公式或访问标准控件内部文字节点。

极小窗口适配由页面声明，框架执行，可选择整体滚动、精简布局或最低适用范围；低于范围时提供明确说明及退出方式。框架不擅自缩字号、隐藏操作或改为整页滚动，不保证任意小窗口都完整显示所有区域。

合法空间不足按声明策略处理；无效声明及自定义规则产生非法尺寸、无法完成计算等错误，须有可定位诊断，指出控件或规则，不用默认结果掩盖问题。报错通道、故障范围及保留上一结果的政策留给运行时设计。

### 4.4 自定义控件的正式接入职责

扩展作者声明控件的内容依赖、测量能力、内部排列、绘制内容及交互行为；框架提供可用约束、实际分配区域、坐标变换、裁剪及有效输入范围，并协调调用。页面仍用统一的尺寸和布局声明组合该控件，不因它是自定义控件而接管外层测量、重算或宿主绘制。

测量和布局求解不修改业务权威状态；绘制消费框架协调好的几何及样式，不在绘制途中重排节点；输入发布业务状态或意图，内部几何命中参与第 3.4 节统一更新。外部不可追踪数据通过正式变化通知接入。

扩展所拥有的订阅及资源归其生命周期；共享资源按其实际持有者管理。扩展返回非法尺寸、循环求解不能完成或运行失败时，第 4.3 节可定位诊断仍适用。具体接口签名、测量缓存、布局算法及错误传递方式由实现设计选择，不用固定节点结构作为扩展合同。

## 5. 控件身份、归属与生命周期

UILib 默认创建 UUID 作为唯一控件身份，业务无需提供，主要用于框架内部维护。移动与排序保留身份；框架不得静默接受重复身份，也不按位置、结构或文本推断新建控件等价于旧控件。具体唯一性保障留给设计。

一个实例同一时刻只有一个逻辑归属位置：子控件只有一个逻辑父节点，根控件没有逻辑父节点。重复加入另一位置须报冲突，不偷偷移动或复制。多处显示同一业务数据使用独立控件共享状态，各自维护布局和交互。浮层绘制位置不必改变逻辑归属。

| 动作 | 生命周期与资源效果 |
| --- | --- |
| 创建/组合 | 未挂载即可维护逻辑描述，不拥有宿主输入，也不执行宿主绘制 |
| 挂载 | 接入宿主布局、绘制与输入流程 |
| 普通更新/排序/移动 | 持续存在控件保留身份及合法交互状态，移动明确表达 |
| 隐藏 | 不等于永久删除；交互释放按有效范围及现行 collapsed 例外处理 |
| 卸载 | 释放焦点、输入及挂载绑定，保留逻辑树和身份，允许重新挂载 |
| 明确移出保留 | 解除原归属及挂载关系，保留子树供之后使用 |
| 永久删除/销毁 | 终止控件及当前所属子树生命周期，释放所拥有订阅与资源；不能重新挂载 |
| 销毁后重新创建 | 新 UUID、新生命周期，不自动继承旧焦点、选区或滚动 |

独立业务状态和编辑状态由其持有者管理，控件销毁不连带销毁这些状态或外部共享资源。自定义控件负责释放自己拥有的资源。

普通动态更新保持草稿、光标、选区、合法焦点与滚动状态，不用整页重建代替更新。滚动范围缩小时仅限制到新有效范围；用户主动导航到不可见目标时允许第 6 节的必要滚动。重新挂载按当前描述和环境布局，不自动恢复旧焦点或输入所有权；具体跨挂载状态恢复留给设计。

### 5.1 生命周期资源归属

控件逻辑生命周期与挂载生命周期分开。挂载期间的呈现订阅、宿主输入、焦点及手势绑定由框架管理，卸载解除这些关系；重挂载按当前描述重新建立有效绑定，不能叠加上次挂载留下的重复回调。逻辑描述和独立编辑状态的保留按本节既有归属处理。

独立业务 Effect 由业务作用域持有，其执行不以页面是否渲染为条件；控件内部订阅由控件或挂载作用域持有，销毁终止所属回调。释放控件不擅自关闭业务持有的共享状态或资源。运行时不得因已释放绑定的迟到通知访问已销毁控件；业务异步任务的取消与结果权威仍归第 8.4 节。

“副作用与纯派生分离”规定的是职责和可观察行为。执行器、合批边界、跨线程递交和清理实现随后设计，不要求业务通过 UI flush 驱动，也不强制副作用在直接状态 set 的调用栈内执行。

## 6. 输入范围、宿主与焦点

### 6.1 范围、消费与模态

宿主输入经适配边界进入；原生输入只由一个消费者递交，范围预览只读、不消费输入，按选定范围分发；一段手势只有一个输入所有者。第二鼠标键整段吞掉，不建立第二 owner；失活 owner 取消后尾部吞到物理结束，禁止误触点击。实现差距按本节修正。

ESC 先交当前范围处理者，消费即停止外层关闭；未消费才进入页面关闭策略或宿主默认行为。宿主依据处理结果 fallback，不在输入尚未处理时抢先关屏。关闭确认及草稿去留归业务。

模态范围激活期间，指针、键盘、文本及焦点导航只进入该范围与所属交互浮层；外部点击可按声明请求关闭，不同时激活后台。交互浮层默认属于所属控件的输入范围，绘制层位置不改变归属；范围关闭、卸载或销毁时释放相关浮层输入。

内层模态激活时外层及后台不响应；关闭内层返回外层，已消费事件不继续作用于外层。外层结束时结束其所属内层及浮层。可恢复外层先前焦点的前提是目标仍存在、可聚焦且属于有效范围；初始焦点与恢复失败后的选择留给设计。

纯提示通知不抢焦点、不改 Tab 范围、不消费 ESC、不拦指针，不改变键盘/文本目标。带操作按钮的通知及其他非模态交互层需明确声明输入行为，不能按最高绘制层推断模态性。

### 6.2 导航与交互资格

Tab/Shift+Tab 默认按当前范围内逻辑树声明顺序前进/后退，跳过隐藏、失活及禁用控件，保留只读输入框。布局换行或窗口缩放本身不改变顺序；逻辑顺序明确变化时按新顺序。暂不增加独立焦点排序属性，UUID 不参与排序。

导航在范围内循环，单项保持焦点，空范围不建立焦点。导航至视口外目标时最小必要滚动，已完整可见不滚动；嵌套滚动区域逐层协调，目标大于视口时优先显示焦点或编辑位置。

只读输入框允许聚焦、Tab 到达、选择、复制和滚动查看，不允许修改或编辑提交。禁用不接受焦点、编辑或激活，Tab 跳过；转为禁用释放已有交互，不隐含提交或丢草稿，状态切换的释放不暗中触发失焦提交。禁用原因可通过不激活控件的提示查看。转只读时既有草稿去留归业务。

复合控件的文字与装饰属于其交互单元，内部独立按钮或输入框保留自己的焦点与命中；沿用现行 leaf hover/pressed 语义。

### 6.3 非模态输入及焦点策略的声明

输入参与、输入范围和绘制层级分别声明。非模态交互内容可接收针对自身的输入，但不能仅因被绘制在顶层就隔离后台、重置 Tab 范围或抢走文本目标；需要独占范围时明确使用模态语义。焦点变更经框架受控入口，平台宿主不另立第二套焦点权威。

页面或复合控件可以声明进入范围时的初始焦点及恢复目标，框架检查目标存在、可聚焦且处于有效范围；无法恢复不得将输入交给失效对象。未声明时的选择顺序由统一框架策略设计，遵循第 6.2 节导航合同，业务不依赖内部列表位置补偿。

启用制表符输入的编辑器必须提供明确的退出或外部导航方式，不能把焦点永久困在编辑区。失焦协调及取消行为按编辑声明和业务决定执行；框架不把状态失活、卸载或模态隔离擅自解释为提交或草稿取消。

## 7. 主题与标准控件文案

正式主题派生入口保证有效初值，创建后即可挂载标准控件，后续来源变化继续更新；业务不补算初值或主动刷新。此保证不等于所有 Computed 必须同步求值，也不自动修复无效业务主题，初始化不能意外将派生内部依赖挂入外层重建 Effect。

标准控件公开换行、单行省略或允许溢出等文案策略，按实际可用文字空间测量、布局与绘制。语言、字体、主题及空间变化自动适配，业务无需访问内部子节点或布局后补宽度。

标准按钮默认换行，自然高度随内容增长；明确尺寸与最大高度仍受既定规则约束。高度受限且文字放不下时，默认仅显示完整行并标示省略，完整文本通过悬停或键盘聚焦后的被动提示查看。提示不改变按钮尺寸或焦点，不擅自增高或缩字号。作者可明确选择其他文案策略。

文字区域连完整行或省略标示都放不下时的呈现、提示时机和放置留给控件设计；框架仍保留完整文案。此默认不推广到所有控件。

## 8. 编辑状态与业务结果

### 8.1 草稿、提交与会话

标准文本输入支持光标定位、方向键、选区、复制/剪切/粘贴、全选、撤销/重做及中文输入法提交，单行/多行按各自换行规则处理。

编辑状态承载草稿、光标、选区及历史，允许负号、空串等未完成输入；业务最终值由业务校验和接受。框架管理可追踪编辑状态，不在控件中隐藏独立副本。业务值写入、草稿编辑、请求提交、接受/拒绝、结束/取消编辑及重置基线具备可区分语义。

业务选择随输入、确认、失焦或表单应用提交；框架执行声明，提交仅请求业务接受，不自动保存或发网络请求。实际修改或开始 IME 组字开启编辑会话，聚焦、移动、选择或复制不启动会话。随输入接受不结束会话；声明完成动作获接受且对应当前草稿时结束并显示规范化结果，焦点可保留。切换表单字段不隐含完成提交。

明确拒绝保留草稿并呈现业务原因，业务值不变，不强制抢回焦点。异步期间允许继续编辑，框架关联对应提交与草稿；旧结果不能覆盖新文本、改光标/选区、结束新会话或把旧错误算作新草稿结论，但对应旧提交状态仍如实呈现。

外部业务值变化不自动覆盖活跃草稿，业务决定保留、替换、取消或提示；无编辑会话正常同步业务值。UILib 不强制冲突选择界面。

编辑状态生命周期由业务管理，解绑控件不提交或丢弃草稿，保留的状态不得依赖旧控件绑定；不同对象可保留独立编辑状态。框架不把焦点当成会话判据。

### 8.2 键盘与输入法

输入法组字期间 Enter 仅确认输入法，不同时提交字段/表单；组字结束后的后续 Enter 才按字段声明执行。单行可以确认，多行默认换行，提交用明确快捷键或按钮。宿主提供真实组字状态及事件信息，不凭普通字符猜测。

单行/多行默认 Tab 切换焦点，需要制表符的编辑器明确开启模式；输入法消费优先，同一事件不再切焦点。ESC 默认不取消整个草稿；组字取消或内部菜单可消费，否则交给外层策略。业务需要 ESC 取消编辑时明确声明。

### 8.3 撤销历史

文本撤销/重做仅修改草稿，不直接撤销业务操作或回退权威值；后续提交仍按声明策略执行。随输入字段可以对撤销后的新草稿请求接受，业务仍可拒绝。

普通编辑（如模板插入）可进入历史；重置基线替换文本并清空撤销/重做，不能恢复旧对象文本。业务明确选择编辑、重置或切换独立状态，框架不猜测。提交成功保留历史，规范化与确认协调为完成步骤；撤销可恢复此前文本并开启新编辑会话，不反复陷入格式修正。

连续同位置输入及同方向删除分别合组，操作类型切换、移动光标、选区变化或切焦点结束当前组。粘贴、剪切、一次 IME 提交和模板插入各为完整一步；明确确认结束分组但不清历史。VS Code 体验及相关实现作为参考，具体阈值留给设计，实现落在 UILib 自有机制中。

### 8.4 业务边界

业务负责最终值权威、校验、异步任务及事务；UILib 接收明确状态或结果，管理编辑协调和呈现，不推断含义。乱序、超时、重试、服务端版本和表单原子性归业务，不继续逐项纳入通用规格。网络异常不能被框架自动算作明确业务拒绝。

控件关闭/销毁释放 UI 资源，不自动取消业务任务。UILib 提供宿主/生命周期协调能力；异步结果是否更新业务或重新打开页面由业务控制，不能凭过时控件绑定恢复已关闭视图。

## 9. 平台边界与验收

核心平台无关，平台输入只经适配边界进入；内部布局、绘制、裁剪和输入共享 logical px，GUI Scale 转换仅在宿主边界成对发生。数据/paint 层不调用 GL，paint/replay 传递自包含、不可变绘制计划。backend/replay 恢复触碰的 GL 状态，包括宿主已有非默认裁剪、stencil 与 mask。通用绘制不得使用 Minecraft 的 Tessellator 等包装类，应走直接 GL 或 UILib 自有管线。物品 icon 的 Minecraft 适配可完整委托 RenderItem.renderItemAndEffectIntoGUI（含 Forge hook 与标准光照）；此适配例外不扩及通用 GUI 或渲染核心。

优先复用 scene、响应式、PaintCommand、标准控件及字体能力，不能为了通过测试绕过生产路径或直连原版 GUI。

## 13. 字体、文本与数学排版

### 13.1 模块职责与数据流

文本调用方提供内容、显式内容模式、样式和可用约束；解析层生成内容结构，排版层结合字体与约束生成行、块及公式几何，绘制层消费同一结果。标准控件和自定义控件共用这一流程，不通过字符串长度、手算字宽或控件内部节点拼装另建文本布局。

原始文本、Minecraft 格式文本、富文本标签和 Markdown 是明确选择的输入模式，不按文本中出现某个符号猜测模式。平台特有格式的解释止于被选定的内容转换能力；它不改变其他模式的语义。解析不调用宿主绘制、修改业务状态或触发链接行为。

内容结构与显示几何分开：窗口、字号或字体改变可以重新排版，不要求业务重新提交源码。内容、样式和资源变化按实际依赖失效；稳定内容不需要每帧重新解析。内部模型及缓存接缝不形成冻结的公共 API。

### 13.2 文本几何与交互

测量、换行、省略、基线、绘制及链接区域使用同一次排版的文本与字体事实，遵循第 3.4 节渲染批次更新。多行链接按实际可见片段命中，祖先裁剪仍有效；点击发布链接目标或动作给调用方，不由解析器代替业务执行外部行为。

Unicode 内容处理不能以 UTF-16 单个 char 作为任意可切割字符，把代理对截成半个字符。文本编辑沿第 8 节处理光标与选区；只读显示的切行、省略及复制应保留可解释的原内容关系，不把画面省略号写回业务原文。复杂字形与平台字体支持边界须在字体能力设计中明确，不凭已有测量函数声称全部脚本完整支持。

文本内容及样式的原文由调用方持有；框架负责其排版和呈现。缺字、无效内容或不支持语法的处理必须有明确结果，不能静默截断整段内容。具体语法集合及降级合同按第 13.5 节继续裁决。

### 13.3 字体与资源生命周期

字体能力负责字体选择、字符匹配、度量与可绘制字形资源；消费者声明字体意图，不管理 glyph 页、纹理上传或后台构建线程。度量与绘制不得从不同字体配置或资源代际拼接结果。字体、字号、语言及资源变化沿第 3.3 节更新相关排版和绘制。

运行时管理字体资源构建、切换和释放，后台工作不得越过平台边界直接执行 GL。资源的持有者负责释放，控件卸载不擅自销毁共享字体资源；资源切换不得留下已释放纹理供有效绘制计划访问。缓存按实际字体和资源依赖失效，具体候选代际、租约、页分配和发布算法留给设计。

字体不可用或缺字时，应能区分资源失败和内容缺字，并提供诊断；具体替代字体、替代字形和重载失败后的保留策略需形成明确合同，不把当前操作系统恰好安装的字体集合当恒定条件。

### 13.4 数学排版职责

数学能力解析并排版明确支持的公式子集，作为可测量内容参与行内或块布局，字体度量、数学盒与实际字形保持一致。文本和公式混排由共同排版过程协调基线及行高，不由业务补算公式高度。

分式、上下标、根式、定界符、矩阵及样式属于现有能力盘点；命令范围和准确/近似/字面降级需由本 spec 明确，不以旧批次说明或测试存在推导为新承诺。数学源文与排版结果分开，动态字号和资源变化不丢源文；绘制继续走 UILib 管线。

### 13.5 Markdown 基础及扩展边界

用户已确认：Markdown 以 CommonMark 为基础，明确增加表格和数学公式扩展，不承诺完整浏览器 HTML 或脚注等所有扩展。CommonMark 是基础语法的语义对齐依据，不凭旧实现子集、聊天防误伤特例或旧测试结果替换其规则，也不凭采用本方向宣称生产实现已通过一致性验证。具体对齐版本和采用库由实现设计明确。

基础文档能力包含段落、软/硬换行、标题、分隔线、引用、有序/无序及嵌套列表、围栏/缩进代码块；行内包含强调、粗体、代码、转义及链接。代码内容按代码语义保留，不再解析成公式、富文本或动作。列表层级和引用等结构由排版体现，不用向业务字符串插入固定空格代替结构布局。

表格扩展提供表头、正文行、单元格及列对齐，单元格参与统一行内解析与排版；列宽、行高、换行和溢出处理由框架按可用约束及页面策略协调，不要求业务手算表格几何。它不自动成为可编辑 DataTable，文档展示与编辑控件的业务职责分开。具体表格语法规则、超宽策略和不规则行处理在扩展合同中继续收束。

数学扩展支持行内公式及独立公式块，内容交给本节数学能力，排版参与统一几何。公式定界与转义规则必须明确，不从旧出口的不同词法继承两套默认行为；具体定界写法及歧义处理随后补齐。

Minecraft 的 § 格式码不作为 Markdown 解析核心语义；宿主若需保留颜色或其他来源样式，先明确转换为内容样式，再以统一规则参与解析及呈现。样式片段分割不是 Markdown 文档边界，相同内容不会因宿主分成多个片段而改变语法解释。

Markdown 支持图片语法与内嵌显示，图片来源、替代文字及尺寸/适配意图进入第 14 节 UILib 专有图像系统，与普通图片控件共用加载、测量及资源管理；业务不自行下载、补算尺寸或手动触发重排。浏览器 HTML 渲染不在本次已认可范围内；原始 HTML 在 UI 中的显示政策、删除线/自动链接等已有扩展是否作为默认能力，仍须明确。未支持内容不能被静默丢弃，失败或字面显示须具有明确合同。脚注、任务列表等未认可扩展不因 Markdown 名称而自动承诺，也不依据旧代码排除将来的正式扩展。

### 13.6 当前覆盖与必要边界

本节已覆盖职责、数据流、统一几何、变化失效及资源归属。Markdown 基础及表格/数学扩展方向已确认；HTML 显示、扩展具体词法、富文本标签范围、数学命令与降级、字体选择及重载失败策略尚未完成，不声称文本专项已经完全覆盖。现有解析代码和旧指南仅是能力证据，不具有独立规范效力。

### 13.7 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| CommonMark 基础结构与行内组合 | 依据选定标准版本核对嵌套、定界和代码语义，不以旧解析器输出作为唯一 oracle |
| 同内容不同样式片段分割 | 语法解释一致，样式来源保留；片段边界不打断定界配对 |
| 表格与文本/公式混合 | 表头、正文、对齐与单元格统一排版；窗口变化无需业务重算列宽 |
| 同一内容切换明确输入模式 | 内容按所选模式解释，其他模式的控制符不混入解析 |
| 字体、字号及可用宽度变化 | 同源内容自动重排，测量、行高和实际画面一致，无业务字宽补偿 |
| 多行链接及嵌套裁剪 | 只在本批次可见链接片段内命中，激活发布原链接目标 |

## 14. UILib 专有图像系统

### 14.1 声明与职责

业务声明图片来源、替代文字、尺寸意图及适配方式。UILib 图像系统管理来源解析、加载、解码、可用尺寸、资源复用及呈现状态；呈现运行时自动协调测量、布局、绘制和相关输入区域。Markdown 图片、普通图片控件及自定义控件通过同一正式能力接入，不另建业务下载缓存、纹理上传或尺寸补算流程。

逻辑核心使用平台无关的图片描述；Minecraft 纹理、物品及其他平台对象在适配层转换。宿主渲染细节、GL 纹理句柄和后台线程不作为业务声明所必需的参数。现有图片源、缓存及渲染器的 Java 形状不是冻结合同。

### 14.2 加载、尺寸与动态更新

图片系统向框架提供加载状态、可用内容与有效尺寸，状态变化自动通知所有有效消费者；业务无需每帧轮询缓存条目或重挂载控件取得结果。加载与解码不能阻塞正常输入或渲染；后台完成结果经框架受控入口进入呈现，后台不直接改节点或执行 GL。

尚未取得图片尺寸时，框架依据声明的尺寸/占位策略布局；尺寸及内容可用后自动按第 4 节重新测量并在渲染批次统一更新。明确固定尺寸仍受自身 min/max 约束，不因图片加载完成擅自改变声明。图片适配规则由声明表达，框架执行；业务不手算目标矩形来补标准图片能力。尺寸与适配遵循第 14.6 节，加载和失败占位遵循第 14.4 节。

来源或资源发生变化后，只有当前来源的有效结果能更新该消费者；旧来源的迟到完成不能把新声明替换回去。资源重载、运行时内容变化沿第 3 节依赖失效，不把构造时快照当成所有图像永久不变的合同。

### 14.3 生命周期与资源复用

图像系统负责加载任务、解码内容、缓存及宿主绘制资源的生命周期。相同有效资源可由多个消费者共享，卸载一个消费者解除其订阅，不破坏其他有效消费者；永久销毁控件不销毁调用方独立持有的数据。失效或释放后的完成通知不能继续访问已销毁控件。

缓存必须有明确复用对象、失效与释放来源，加载任务及缓存占用有界；具体键、容量、淘汰、取消和重试实现留给设计，不继承旧缓存常量。共享内容的旧结果不得在资源更新后作为当前结果重新发布。上传、绘制及释放遵守宿主线程和第 2 节平台边界，恢复触碰的宿主状态。

### 14.4 状态、失败及替代内容

未完成、已可用及失败结果必须能够区分，不以空图片或零尺寸掩盖加载失败。加载中保留按声明分配的目标盒；尚无有效自然尺寸且未声明足够尺寸时，使用框架默认加载占位参与布局，不编造来源比例。业务可声明自己的占位，框架继续负责加载及布局。占位的具体样式和自然测量随主题及环境协调，数值和外观由统一设计确定。

失败时默认显示失败占位及已声明的替代文字；未声明替代文字仍有明确失败状态，不把所在图片节点或文档后续内容静默删除。失败呈现遵守原尺寸边界、裁剪及文档布局策略，业务可声明替代内容。图像失败不隐含关闭整页或改变业务权威状态。失败诊断能关联来源与处理阶段。

无效来源、来源不可访问、解码失败和宿主呈现错误归图像系统及适配职责；业务仍决定图片的业务含义与来源选择。正式重新加载入口允许对当前来源重新获取或生成有效内容，无需重挂载控件、换 UUID 或改写来源来清缓存；重新加载仍通过同一状态及变化流程，不绕过第 14.2 节迟到结果和第 14.3 节共享资源合同。

后台重试由框架管理，必须有结束边界，不形成无限重试或每帧重新发起请求。具体自动重试条件、次数、退避、请求合并及失败占位是否带交互按钮留给统一设计；不要求每个图片默认成为可点击重试控件。业务可以通过正式入口表达重试意图，不自行接管网络线程。旧“成功才回调”或“重新挂载才重试”机制不能限制新能力。

### 14.5 已确认的来源范围

首期统一图像系统覆盖以下来源，业务通过来源声明接入，不自行实现对应加载和绘制流程。来源采用不同适配能力，不要求把所有来源先转为普通位图。

| 来源 | 业务声明与框架职责 |
| --- | --- |
| 资源包纹理及纹理区域 | 声明资源标识及可选区域；框架解析资源、协调区域尺寸与绘制，资源重载更新有效内容 |
| 运行时位图 | 声明位图内容及变化；框架管理可绘制资源和尺寸更新，不要求业务上传纹理；外部可变数据按第 3.2 节正式通知 |
| HTTP/HTTPS 远程图片 | 声明地址；框架完成获取、解码、状态通知及资源复用，无业务下载线程和重排回调 |
| Minecraft 物品图标 | 声明物品内容，经专用宿主适配绘制；逻辑核心不依赖 ItemStack 或 Minecraft 渲染类型 |

Markdown 图片链接的来源经同一图像系统解析，平台资源和物品的表示方式由正式接口设计明确，不让文档作者拼宿主纹理句柄。来源的实际支持能力由环境适配提供，缺少适配与加载失败须可区分。

物品图标不因进入统一系统而默认冻结为位图快照，也不强制走远程加载或纹理解码路径。UILib 管理其几何、裁剪、绘制调用和宿主状态恢复；具体动态效果、数量/耐久显示及更新语义另行明确。旧 VANILLA 残留 GL 状态模式不能覆盖第 2 节恢复宿主状态的合同。

直接文件路径、动画图片等额外来源不属于本次已认可首期承诺，后续须明确范围；不据此删除现有能力。自然尺寸与适配已在第 14.6 节确定；默认占位、失败替代和重试职责已在第 14.4 节确定；物品具体呈现仍需收束。

### 14.6 图片尺寸与适配

图片自然尺寸默认将有效图片像素宽高解释为 logical px；纹理区域使用所选区域的宽高，不使用整张纹理尺寸。宿主缩放在平台边界完成，不在图片自然尺寸中重复乘宿主缩放因子。物品图标的自然尺寸由专用适配提供，不以整张物品 atlas 尺寸代替。

尺寸求解沿第 4 节：自然尺寸参与测量；固定、填充及 min/max 声明仍有原含义。只明确一边尺寸时，默认以有效来源宽高比推导另一边；随后遵守各自尺寸边界。边界限制或明确指定两边时，目标盒可能与来源比例不同，内容如何放入该盒由适配方式决定。来源尺寸尚不可用时不凭空编造比例，遵循加载占位策略；可用后自动重新测量。

| 适配方式 | 内容在目标盒中的行为 |
| --- | --- |
| 等比完整显示（默认） | 保持来源比例，完整放入目标盒，可留空白 |
| 等比铺满裁剪 | 保持来源比例并覆盖目标盒，超出盒的内容裁掉；不扩大盒及命中区域 |
| 拉伸 | 内容填满目标盒，允许比例改变 |
| 原尺寸显示 | 按来源自然尺寸显示；超出区域的处理遵循有效裁剪及溢出声明 |

内容的放置对齐由正式声明能力表达，默认对齐由统一接口设计明确。适配改变图片在盒中的呈现，不代替外层尺寸分配，也不突破祖先裁剪。业务不计算缩放系数或绘制矩形来实现这些标准模式。

Markdown 图片默认保持比例，仅在自然宽度超过文档当前可用宽度时缩小，以避免默认图片撑出正文；不默认放大小图。该策略属于文档图片的默认适配，不改变第 4 节普通自然尺寸控件默认不自动压小的含义。显式图片尺寸及边界声明可覆盖文档默认策略；资源尺寸、窗口与可用宽度改变时框架自动更新结果。

### 14.7 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 加载中且来源尺寸未知 | 保留已分配目标盒或使用框架占位，业务可覆盖占位，无手算比例和布局 |
| 失败占位及替代文字 | 图片失败明确可见，声明的替代文字可显示，后续文档保留，尺寸/裁剪合同有效 |
| 正式重新加载及后台重试 | 无需重挂载，状态自动更新，迟到结果不能覆盖当前结果；自动重试有结束边界 |
