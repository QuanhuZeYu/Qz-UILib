# UILib 核心职责与交互规格

状态：**已确认核心规格**。核心与第 8 节列出的模块规格共同构成项目规格体系，各按职责定义要求；该效力不表示实现或产物已满足要求。

## 1. 目标、范围与效力

UILib 自成体系，能力与公共声明面向现代 UI、文本与交互；Minecraft 提供运行宿主，不以其旧格式、翻译表或控件机制定义 UILib 的内容体系。平台旧行为的必要适配归宿主边界，不转化为通用内容模式或反向约束现代能力目标。

业务作者通过逻辑数据和公开的 UI 声明表达界面，UILib 自动完成测量、排版、绘制与输入协调。标准控件覆盖常规需求，自定义控件通过正式扩展能力接入同一机制。动态内容、窗口、缩放、字体、语言、主题和权限变化无需重新打开页面或业务手动刷新。

本轮以 Architect 面板暴露的通用问题为入口，覆盖状态/呈现边界、布局、控件生命周期、文本编辑及输入范围。核心定义跨模块合同，模块职责分别在第 8 节入口中的规格维护，范围包含独立配置核心；尚未补齐的模块不视为已有完整合同。本稿不替下游选择业务校验、任务取消、权限策略或极小窗口方案。

已认可裁定在本规格及对应模块规格维护；实现事实与验证结果提供证据，不把未采纳建议或现有实现升级为要求。

核心与对应模块规格是项目行为权威。旧规范正文退役删除；源码注释、测试、使用指南、历史裁定与调查资料只用于说明实现或证据，不独立定义要求。实现与规格不一致时按本 spec 记录迁移，不能用旧约定否决新设计。专项未覆盖的能力保持现状，必要规格缺口在对应职责的规格补齐，不从历史材料自动恢复约束。协作入口见 [AGENTS.md](<../../../AGENTS.md>)。

旧实现无法满足规格时可直接重构，不以保留旧 API、队列或架构为前提，不为旧兼容加入妨碍规格的补丁；目标可达 5.0，实际版本变更与发布另按授权执行。算法、调度和接口等实现选择由设计承担，改变目标或核心合同的决定再更新本规格。

### 1.1 决策范围与复杂度约束

规格补充不得在能力决策中隐含附加失败分支。错误归属、必要诊断及基本资源清理不自动授权增加重试、旧结果保留、降级替代、回滚、补偿或恢复策略；也不以“框架自动管理”将这些额外机制转移到内部后默认加入。

确需新增上述行为时，须明确说明它是额外能力、触发条件及增加的状态/分支复杂度，单独取得用户认可；不能在无关能力的表述中顺带承诺。必要实现细节由设计承担，不为假想失败扩大程序模型。已被用户明确认可的缺字回退、图片加载/失败占位与有界重试等合同按各自章节保留，不据本条自行扩展或撤销。

## 2. 核心模型与职责

```text
业务状态、编辑状态与纯派生
          ↓ 公开绑定与 UI 声明
控件逻辑树：内容、主题、尺寸意图、布局关系、显隐、滚动策略
          ↓ 宿主环境约束 + 控件测量/布局规则
框架维护的布局结果：尺寸、位置、内容范围、裁剪范围
          ↓
绘制与几何交互共用布局事实 → 不可变绘制计划 → 宿主 backend/replay

输入 → 当前有效范围内路由 → 编辑操作或业务意图 → 状态变化
```

箭头表达职责与依赖，不规定每个步骤必须同步或延迟，也不预定实现类、队列或快照结构。

| 责任主体 | 持有与负责 | 不由其承担的职责 |
| --- | --- | --- |
| 业务/页面作者 | 业务权威值、校验、任务与事务；选择提交和适配策略；持有独立编辑状态 | 普通排版的最终尺寸/位置计算，手动 flush/layout/paint |
| 状态系统 | 直接状态读写、纯派生及其一致性，显式副作用的作用域机制 | 依赖控件挂载或 UI 帧才能成立 |
| 控件作者 | 内容测量、内部布局、绘制与交互规则，以及可通知的依赖 | 绕过框架维护另一套外层布局、坐标或输入所有权 |
| 呈现运行时 | 绑定、变化追踪、测量布局、绘制与输入协调、控件生命周期 | 推断业务权威、网络事务或结果含义 |
| 宿主适配层 | 可用空间、缩放、资源与原生输入信息、平台转换和运行入口 | 把平台类型或 GUI Scale 混入核心闭环 |

UI 变化以 state/signal 驱动；输入 handler 发布业务状态或意图，不直接改节点属性或树结构。焦点、capture 等权威交互命令通过路由器受控入口执行。公开声明能力与 handler 的写入边界不能混为一谈；挂载后结构变化的接入方式在接口设计中遵循本节状态/意图边界。

主题、文案、尺寸意图与子控件关系属于 UI 逻辑描述；实际尺寸、位置和裁剪范围属于框架维护的结果。业务可读取公开布局信息用于锚定等明确用途，但不直接修改结果，也不读回结果再写尺寸来补偿普通排版。逻辑描述可以由现有控件与响应式能力承载，不要求另建配置树。

## 3. 状态、派生与变化传播

### 3.1 状态独立性与可见性

状态与派生系统不依赖控件挂载或 UI 帧推进即可使用。在合法状态访问上下文中，直接状态写入后，随后读取同一状态得到新值，连续读写不会因旧已提交值覆盖前一步。此要求不赋予任意线程修改 UI 的权限。

状态可读与画面呈现分开：业务无需调用 scheduler、flush、layout、paint 或 replay；最终状态呈现允许批处理，有顺序意义的编辑及通知追加必须依序保留。

派生计算只根据来源生成结果，不修改其他状态、控件或外部系统。副作用经显式订阅/Effect 执行，归属明确生命周期。业务副作用不依赖控件挂载；呈现绑定随卸载释放，独立业务副作用不得继续持有已卸载节点或输入绑定。

纯派生首次及后续读取均返回基于当前来源状态计算的结果。直接状态写入后，紧接着读取依赖它的 Computed，包含多级派生链，须得到当前结果；不返回尚未求值的占位值冒充结果。只有派生函数自身产出 null 时，null 才是合法结果。框架可按需计算、缓存或提前求值，不要求每次写入立即重算；派生读取不执行 Effect 或外部副作用。Effect 执行时机和批处理接口另行设计。正式主题派生仍满足[主题规格](<2026-10-07-uilib-theme-spec.md>)的首次有效值要求。

### 3.2 自动更新职责

公开声明、可追踪状态、环境或内容资源变化，使相关结果失效，由框架在正常呈现流程中更新。自定义控件依赖框架无法感知的外部数据时，通过正式能力通知变化；通知不等于执行布局或绘制。

变化按实际依赖影响测量、布局或绘制。例如颜色通常影响绘制，字体、文案或内边距可能影响测量与布局。缓存须具备失效和释放来源，动态性不依赖每帧全量重算；不承诺每次仅重算一个节点。

声明修改、属性传播与布局/绘制执行分别设计，不要求所有属性修改统一延迟或逐条保存更新请求。属性传播的具体执行时机留给设计，纯派生读取不得隐含修改 UI。

### 3.3 环境与资源变化的职责

宿主提供可用空间、缩放及所属适配的外部事实；页面提供内容及适配声明。UILib 自成体系，页面语言由自己的独立语言资源流提供，不接入或兼容宿主语言资料；Item 等宿主内容所需翻译由业务处理。语言资源的加载、选择与重载合同归[语言模块规格](<2026-10-07-uilib-localization-spec.md>)。相关变化沿第 3.2 节依赖追踪进入测量、布局或绘制，不重开页面或手动补偿布局。

独立语言流的选择和资料重载影响翻译文案、排序或搜索所依赖的语言事实；字体与图像由各自资源来源通知变化，不要求共用宿主语言重载入口。相同语言下重新加载翻译资料仍须使相关内容失效，不能仅因语言码未变保持旧缓存。值与变化通知、代际的具体表示留给接口设计，不冻结现有 long 计数或单例结构。外部数据无法自动追踪时按第 3.2 节通过正式通知接入。

资源与环境订阅遵循第 5 节归属，卸载释放呈现绑定，不释放独立业务状态。环境依赖的缓存不以构造期快照保持旧值；复用缓存仍须响应其实际依赖变化。

### 3.4 渲染批次与一致性

框架根据已追踪变化，协调本批次的测量、布局、绘制区域、裁剪、滚动范围与命中区域，形成一致的呈现及交互结果。改变位置、大小、滚动、缩放或裁剪的内容，不能出现一套区域用于画面、另一套区域用于指针命中的情况。自定义控件及浮层遵守同一职责。

业务只发布逻辑状态或意图；框架决定批次如何合并、计算及生效。统一更新的是呈现及几何结果，不将直接状态或纯派生读取延迟到渲染批次，不要求逐条保存所有属性修改，也不将独立业务 Effect 绑定到 UI 帧。后续输入由框架使用一致的结果与有效交互范围处理；批次内的阶段顺序、缓冲或快照机制由设计选定。

## 4. 布局与自定义控件

### 4.1 布局输入与统一结果

宿主提供根可用空间及环境约束，页面声明排列方式、关系、尺寸意图、边界、间距、显隐与滚动策略，控件提供内容测量能力，框架组合求解。普通页面无需提供测量结果或布局回调。

自定义控件作者可定义内容测量、内部排列、绘制与交互规则，由框架调用并协调结果；外层仍可将其作为控件组合布局。扩展接入 UILib 自有布局、绘制、输入机制，保持裁剪、命中、动态失效与生命周期协调，不直接改写最终布局结果。

布局结果是绘制、裁剪、指针命中及滚动范围的共同依据。布局及命中区域归框架自动管理，在渲染批次中统一更新，画面与命中区域保持一致；业务不选择结果版本，不手动同步区域。自定义内部命中使用框架分配的区域和坐标转换，参与同一批次；绘制及输入不独立重建外层排版。禁用/失活等交互资格与几何命中分开检查。具体阶段顺序、结果存储和发布机制属于框架设计，不将“最后已呈现布局”另立为必须采用的实现合同。

### 4.2 尺寸意图与边界

| 声明 | 含义 | 空间不足时的规则 |
| --- | --- | --- |
| 固定尺寸 | 指定尺寸，不随内容自然增长 | 经自身边界限制后不因父空间不足自动缩小 |
| 自然尺寸 | 按内容、字体及声明的测量/换行规则求尺寸 | 默认不自动压小布局盒；明确缩减另行表达 |
| 填充/剩余空间分配 | 使用父容器可用空间或参与兄弟间分配 | 遵循自身边界，具体分配细则留给布局设计 |
| 最小/最大边界 | 独立于尺寸意图的合法范围 | 先按意图求值，再限制到范围；固定尺寸也受约束 |

同一种声明在宽、高、普通容器与滚动视口中保持相同含义。最小尺寸为硬边界，父空间不足也不突破；最小值大于最大值是无效声明。按已声明换行规则重新测量仍是自然尺寸，不等于测量后压小布局盒。

普通容器默认允许溢出，不自动裁剪或变成滚动容器；溢出不自动扩大其布局盒，可见范围受上层裁剪限制。裁剪及滚动明确声明；裁剪不改布局尺寸，隐藏部分不命中；允许溢出时，父盒外可见且未被裁剪的子控件部分仍可交互，框架不能仅因指针位于父盒外就跳过该子树；实际可见区域、祖先裁剪、输入范围和交互资格共同决定命中。业务不扩父盒或补命中区域来实现该行为。重叠优先级由统一绘制与输入规则处理，不能另外重建排版。换行、重排、折叠是布局策略，裁剪、滚动是溢出处理，框架不擅自替页面选择。

### 4.3 动态面板与空间不足

页面声明标题、页签和操作区自然尺寸、正文占剩余空间并独立滚动。框架测量各区域，扣除间距和内边距后分配正文视口；固定区指不随正文滚动，不要求数值高度固定。文案、字体、主题、语言或窗口变化自动重新测量，业务无需 fixedChromeHeight 公式或访问标准控件内部文字节点。

极小窗口适配由页面声明，框架执行，可选择整体滚动、精简布局或最低适用范围；低于范围时提供明确说明及退出方式。框架不擅自缩字号、隐藏操作或改为整页滚动，不保证任意小窗口都完整显示所有区域。

合法空间不足按声明策略处理；无效声明及自定义规则产生非法尺寸、无法完成计算等错误，须有可定位诊断，指出控件或规则，不用默认结果掩盖问题。报错通道、故障范围及保留上一结果的政策留给运行时设计。

### 4.4 自定义控件的正式接入职责

扩展作者声明控件的内容依赖、测量能力、内部排列、绘制内容及交互行为；框架提供可用约束、实际分配区域、坐标变换、裁剪及有效输入范围，并协调调用。页面仍用统一的尺寸和布局声明组合该控件，不因它是自定义控件而接管外层测量、重算或宿主绘制。

测量和布局求解不修改业务权威状态；绘制消费框架协调好的几何及样式，不在绘制途中重排节点；输入发布业务状态或意图，内部几何命中参与第 3.4 节统一更新。外部不可追踪数据通过正式变化通知接入。

扩展所拥有的订阅及资源归其生命周期；共享资源按其实际持有者管理。扩展返回非法尺寸、循环求解不能完成或运行失败时，第 4.3 节可定位诊断仍适用。具体接口签名、测量缓存、布局算法及错误传递方式由实现设计选择，不用固定节点结构作为扩展合同。

## 5. 控件身份、归属与生命周期

UILib 默认创建 UUID 作为唯一控件身份，业务无需提供，主要用于框架内部维护。移动与排序保留身份；框架不得静默接受重复身份，也不按位置、结构或文本推断新建控件等价于旧控件。具体唯一性保障留给设计。

一个实例同一时刻只有一个逻辑归属位置：子控件只有一个逻辑父节点，根控件没有逻辑父节点。重复加入另一位置须报冲突，不偷偷移动或复制。多处显示同一业务数据使用独立控件共享状态，各自维护布局和交互。浮层绘制位置不必改变逻辑归属。

| 动作 | 生命周期与资源效果 |
| --- | --- |
| 创建/组合 | 未挂载即可维护逻辑描述，不拥有宿主输入，也不执行宿主绘制 |
| 挂载 | 接入宿主布局、绘制与输入流程 |
| 普通更新/排序/移动 | 持续存在控件保留身份及合法交互状态，移动明确表达 |
| 隐藏 | 不等于永久删除；交互释放按有效范围及现行 collapsed 例外处理 |
| 卸载 | 释放焦点、输入及挂载绑定，保留逻辑树和身份，允许重新挂载 |
| 明确移出保留 | 解除原归属及挂载关系，保留子树供之后使用 |
| 永久删除/销毁 | 终止控件及当前所属子树生命周期，释放所拥有订阅与资源；不能重新挂载 |
| 销毁后重新创建 | 新 UUID、新生命周期，不自动继承旧焦点、选区或滚动 |

独立业务状态和编辑状态由其持有者管理，控件销毁不连带销毁这些状态或外部共享资源。自定义控件负责释放自己拥有的资源。

普通动态更新保持草稿、光标、选区、合法焦点与滚动状态，不用整页重建代替更新。滚动范围缩小时仅限制到新有效范围；用户主动导航到不可见目标时允许第 6 节的必要滚动。重新挂载按当前描述和环境布局，不自动恢复旧焦点或输入所有权；具体跨挂载状态恢复留给设计。

### 5.1 生命周期资源归属

控件逻辑生命周期与挂载生命周期分开。挂载期间的呈现订阅、宿主输入、焦点及手势绑定由框架管理，卸载解除这些关系；重挂载按当前描述重新建立有效绑定，不能叠加上次挂载留下的重复回调。逻辑描述和独立编辑状态的保留按本节既有归属处理。

独立业务 Effect 由业务作用域持有，其执行不以页面是否渲染为条件；控件内部订阅由控件或挂载作用域持有，销毁终止所属回调。释放控件不擅自关闭业务持有的共享状态或资源。运行时不得因已释放绑定的迟到通知访问已销毁控件；业务异步任务的取消与结果权威仍归第 7 节。

“副作用与纯派生分离”规定的是职责和可观察行为。执行器、合批边界、跨线程递交和清理实现随后设计，不要求业务通过 UI flush 驱动，也不强制副作用在直接状态 set 的调用栈内执行。

## 6. 输入范围、宿主与焦点

### 6.1 范围、消费与模态

宿主输入经适配边界进入；原生输入只由一个消费者递交，范围预览只读、不消费输入，按选定范围分发；一段手势只有一个输入所有者。第二鼠标键整段吞掉，不建立第二 owner；失活 owner 取消后尾部吞到物理结束，禁止误触点击。实现差距按本节修正。

ESC 先交当前范围处理者，消费即停止外层关闭；未消费才进入页面关闭策略或宿主默认行为。宿主依据处理结果 fallback，不在输入尚未处理时抢先关屏。关闭确认及草稿去留归业务。

模态范围激活期间，指针、键盘、文本及焦点导航只进入该范围与所属交互浮层；外部点击可按声明请求关闭，不同时激活后台。交互浮层默认属于所属控件的输入范围，绘制层位置不改变归属；范围关闭、卸载或销毁时释放相关浮层输入。

内层模态激活时外层及后台不响应；关闭内层返回外层，已消费事件不继续作用于外层。外层结束时结束其所属内层及浮层。可恢复外层先前焦点的前提是目标仍存在、可聚焦且属于有效范围；初始焦点与恢复失败后的选择留给设计。

纯提示通知不抢焦点、不改 Tab 范围、不消费 ESC、不拦指针，不改变键盘/文本目标。带操作按钮的通知及其他非模态交互层需明确声明输入行为，不能按最高绘制层推断模态性。

### 6.2 导航与交互资格

Tab/Shift+Tab 默认按当前范围内逻辑树声明顺序前进/后退，跳过隐藏、失活及禁用控件，保留只读输入框。布局换行或窗口缩放本身不改变顺序；逻辑顺序明确变化时按新顺序。暂不增加独立焦点排序属性，UUID 不参与排序。

导航在范围内循环，单项保持焦点，空范围不建立焦点。无焦点时正向导航取逻辑首项、反向取末项，不重跑初始/恢复目标策略；导航本身不激活控件或提交编辑。导航至视口外目标时最小必要滚动，已完整可见不滚动；嵌套滚动区域逐层协调，目标大于视口时优先显示焦点或编辑位置。本阶段显露由 Tab/Shift+Tab 主动导航触发，单项导航也可显露；初始焦点、模态返回、点击聚焦和普通显式焦点请求保留当前滚动位置。普通按钮没有内部焦点位置时显露起始边缘；编辑位置随编辑控件接入。普通内容/主题/窗口变化和用户滚动不重复追随焦点。

只读输入框允许聚焦、Tab 到达、选择、复制和滚动查看，不允许修改或编辑提交。禁用不接受焦点、编辑或激活，Tab 跳过；转为禁用释放已有交互，不隐含提交或丢草稿，状态切换的释放不暗中触发失焦提交。禁用原因可通过不激活控件的提示查看。转只读时既有草稿去留归业务。

复合控件的文字与装饰属于其交互单元，内部独立按钮或输入框保留自己的焦点与命中；沿用现行 leaf hover/pressed 语义。

### 6.3 非模态输入及焦点策略的声明

输入参与、输入范围和绘制层级分别声明。非模态交互内容可接收针对自身的输入，但不能仅因被绘制在顶层就隔离后台、重置 Tab 范围或抢走文本目标；需要独占范围时明确使用模态语义。焦点变更经框架受控入口，平台宿主不另立第二套焦点权威。

页面或复合控件可以声明进入范围时的初始焦点及恢复目标，框架检查目标存在、可聚焦且处于有效范围；无法恢复不得将输入交给失效对象。未声明时的选择顺序由统一框架策略设计，遵循第 6.2 节导航合同，业务不依赖内部列表位置补偿。

启用制表符输入的编辑器必须提供明确的退出或外部导航方式，不能把焦点永久困在编辑区。失焦协调及取消行为按编辑声明和业务决定执行；框架不把状态失活、卸载或模态隔离擅自解释为提交或草稿取消。

#### 6.3.1 范围进入与恢复的选择规则

页面与模态范围进入时优先使用声明的初始焦点；目标无效或未声明时，按第6.2节逻辑声明顺序选择第一个当前有效、可聚焦的目标，空范围保持无焦点。返回外层范围时，依次核验声明的恢复目标、被覆盖前的焦点、初始目标，再使用同一默认顺序。声明目标按当前声明和挂载核验；自动保存的先前焦点仅对原挂载代际有效，期间真实生效的隐藏、禁用、不可聚焦或卸载会永久取消该恢复资格，不能在恢复资格后复活旧记录。

选择发生在声明结算后的范围进入或返回，不从焦点读取中隐式推进。普通内容/布局变化、在当前范围添加控件、更新初始/恢复目标声明以及主动清除焦点，不再次执行进入策略。非模态提示不形成范围转换；内层模态返回外层，所属外层结束时丢弃已结束范围的恢复记录。当前已接入页面根与模态范围的初始/恢复策略；Tab导航按第6.2节接入。非模态复合范围的显式进入与编辑输入按后续专题接入，不据本小节提前实现。

## 7. 业务权威边界

业务负责最终值权威、校验、异步任务及事务；UILib 接收明确状态或结果，管理编辑协调和呈现，不推断含义。乱序、超时、重试、服务端版本和表单原子性归业务，不继续逐项纳入通用规格。网络异常不能被框架自动算作明确业务拒绝。

控件关闭/销毁释放 UI 资源，不自动取消业务任务。UILib 提供宿主/生命周期协调能力；异步结果是否更新业务或重新打开页面由业务控制，不能凭过时控件绑定恢复已关闭视图。

## 9. 平台边界与验收

UILib 采用原生 framebuffer 分辨率：布局、字号、裁剪、滚动距离与指针命中统一使用实际 framebuffer 像素。Minecraft GUI Scale 不改变 UILib 的尺寸和文字大小。窗口或 framebuffer 大小变化会改变可用区域并自动重排；保持相同声明字号时，字形的像素尺寸保持一致。本文 logical px 指 UILib 坐标像素，在该宿主中与 framebuffer px 一一对应；宿主原生输入若采用其他坐标单位，在边界转换一次，不将 GUI Scale 带入核心。

滚动有效偏移由框架按最终内容范围与视口限制；内容未溢出时偏移为零，到达末尾后的滚轮不累积额外偏移，反向滚动立即响应。内容删除、换行、字号及窗口变化后重新计算范围并限制已有偏移，业务无需维护末尾边界。

平台层次为“无平台核心 → 可替换的宿主适配（如 LWJGL2/LWJGL3）→ Minecraft 等应用宿主接入”。无平台核心的公开合同、布局、输入逻辑、文本定位、绘制计划与资源生命周期不依赖 Minecraft、Forge、LWJGL 类型或其运行时存在；加载和使用核心不能触发这些宿主的类加载、native 初始化或 GL 上下文要求。实现选择以目标环境中可靠工作为准，兼容性优先于未经验证的加速收益，不强制纯 Java 基线，也不要求先手写 Java 字体引擎再使用 native。字体读取、整形、度量与光栅通过不含宿主类型的合同提供；已有成熟 native 后端在目标环境中的操作系统、架构、ABI、Java/绑定版本、分发与加载方式确认可用后可以积极复用。native 与 GPU 能力查询归适配层，按实际使用初始化；核心合同和逻辑加载不触发平台初始化。缺少可用后端时评估已有可移植实现或目标平台适配，不以强制自研、虚设 fallback 或删减文字能力代替解决兼容问题。Java 标准 API 的隐含 native/桌面依赖也须核查，不能仅凭语言或 API 名称判定可移植。

核心与宿主提供独立产物，宿主通过依赖接入同一核心；核心产物不携带 MC/Forge 接入类或要求宿主在运行时存在，不能仅以同一发行包中部分代码可无平台运行代替产物分离。平台字体绑定、native 与 GPU 实现归可选择的适配产物，公共合同留在核心。独立编译、产物装配及独立运行分别验证，依赖边界不仅依靠源码包名。未来桌面应用以核心加桌面宿主/适配组成，不依赖 MC 产物；本轮确立该方向，不据此承诺已交付桌面窗口、启动器或安装包。实际 artifact 名称、版本与发布策略按对应设计和授权另定。

LWJGL 是宿主层，不是核心的必要前提；Minecraft 位于更外层，负责游戏资源、调用语义和生命周期接入。直接使用 LWJGL 的偏好仅适用于对应宿主适配内部，不授权核心直接依赖 LWJGL，也不意味着只支持 LWJGL3。纯 Forge 1.7.10 自带的 LWJGL2 必须有可用适配，UILib 核心、自有页面与默认原版字体替代不得要求安装 LWJGL3ify、Angelica，或为迁就实现而替换该实例的 Java/LWJGL 宿主。LWJGL3ify/Angelica 存在时使用对应适配并保留既定兼容合同；缺席时通过现有宿主完成相同核心语义，不能静默退回原版字体、禁用核心功能或删减文字能力。native 资源确需随适配提供时由 UILib 的适配发行负责，不要求用户安装无关宿主 Mod。用户另行明确允许 MC 实例安装 UniMixins 以提供注入运行时；该 MC 外层依赖不进入核心，直接复用其 Mixin 能力，不自行实现注入框架。

宿主适配负责所声明运行组合中的绑定、类转换和方法签名兼容。处理这些差异时保留宿主有效状态及其虚拟化管理，不通过关闭整个宿主转换链或改变全局宿主配置来绕过兼容缺口；只需要隔离的绑定在自身作用域加载。兼容修复止于 UILib 自身能力及接入边界，不扩展为修复原版游戏自身内容。具体绑定版本、转换标记、重载选择与缺陷原因随实现维护；验收使用实际发行包及目标宿主，独立绑定测试不能替代整合宿主的启动与绘制验证。

验收分别覆盖：无 Minecraft/Forge/LWJGL 的核心加载与逻辑流程；纯 Forge 1.7.10、原有 Java8/LWJGL2、无 LWJGL3ify/Angelica 的实际运行；既有 LWJGL3ify/Angelica 实例的回归。两种 MC 宿主复用同一文本定位、字形需求与有序绘制合同，差异止于资源、native 绑定、GPU 提交及游戏接入，不建立第二套排版/格式/缓存引擎。独立运行器使用 LWJGL3 取得的证据只属于该宿主，不能替代无平台核心或 LWJGL2 的验收。

核心平台无关，平台输入只经适配边界进入；内部布局、绘制、裁剪和输入共享 logical px，GUI Scale 转换仅在宿主边界成对发生。数据/paint 层不调用 GL，paint/replay 传递自包含、不可变绘制计划。backend/replay 恢复触碰的 GL 状态，包括宿主已有非默认裁剪、stencil 与 mask。UILib 即便在宿主边界也优先直接使用 LWJGL 宿主能力；窗口、framebuffer、原生输入与 GL 操作不优先经 Minecraft 包装方法取得。Minecraft 特有资源包、生命周期与调用语义留在专用适配层；宿主虚拟化的 GL 状态须读取其实际有效状态，不以裸驱动查询替代宿主缓存事实。通用绘制不得使用 Minecraft 的 Tessellator 等包装类，应走直接 GL 或 UILib 自有管线。物品 icon 的 Minecraft 适配可完整委托 RenderItem.renderItemAndEffectIntoGUI（含 Forge hook 与标准光照）；此适配例外不扩及通用 GUI 或渲染核心。

优先复用 scene、响应式、PaintCommand、标准控件及字体能力，不能为了通过测试绕过生产路径或直连原版 GUI。
