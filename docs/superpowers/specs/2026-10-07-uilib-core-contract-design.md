# UILib 核心职责与交互规格

状态：**已确认规格，项目唯一规格权威**。用户明确指定本 spec 为唯一权威；它基于逐项认可的 D-01 至 D-53。该效力不表示生产实现、游戏产物或测试已满足要求。

## 1. 目标、范围与效力

业务作者通过逻辑数据和公开的 UI 声明表达界面，UILib 自动完成测量、排版、绘制与输入协调。标准控件覆盖常规需求，自定义控件通过正式扩展能力接入同一机制。动态内容、窗口、缩放、字体、语言、主题和权限变化无需重新打开页面或业务手动刷新。

本轮以 Architect 面板暴露的通用问题为入口，覆盖状态/呈现边界、布局、控件生命周期、文本编辑及输入范围。当前核心职责已收束，后续专项章节持续补充至覆盖 checkout 内全部 UILib 能力，包含独立配置核心；尚未补齐的模块不视为已有完整合同。本稿不替下游选择业务校验、任务取消、权限策略或极小窗口方案。

逐项依据见 [裁定记录](<../../开发者文档/规格文档/反向规格/UILib反向需求基线.md>)；实现事实与历史反馈见 [冲突与证据](<../../开发者文档/规格文档/反向规格/需求冲突与证据缺口.md>)、[测试证据抽样](<../../开发者文档/规格文档/反向规格/测试证据抽样.md>)。这些记录用于追溯，不把未采纳建议或现有实现升级为要求。

本 spec 是项目唯一规格权威。旧规范正文退役删除；源码注释、测试、使用指南、历史裁定与调查资料只用于说明实现或证据，不独立定义要求。实现与规格不一致时按本 spec 记录迁移，不能用旧约定否决新设计。专项未覆盖的能力保持现状，必要规格缺口在本 spec 补齐，不从历史材料自动恢复约束。协作入口见 [AGENTS.md](<../../../AGENTS.md>)。

### 1.1 决策范围与复杂度约束

规格补充不得在能力决策中隐含附加失败分支。错误归属、必要诊断及基本资源清理不自动授权增加重试、旧结果保留、降级替代、回滚、补偿或恢复策略；也不以“框架自动管理”将这些额外机制转移到内部后默认加入。

确需新增上述行为时，须明确说明它是额外能力、触发条件及增加的状态/分支复杂度，单独取得用户认可；不能在无关能力的表述中顺带承诺。必要实现细节由设计承担，不为假想失败扩大程序模型。已被用户明确认可的缺字回退、图片加载/失败占位与有界重试等合同按各自章节保留，不据本条自行扩展或撤销。

## 2. 核心模型与职责

```text
业务状态、编辑状态与纯派生
          ↓ 公开绑定与 UI 声明
控件逻辑树：内容、主题、尺寸意图、布局关系、显隐、滚动策略
          ↓ 宿主环境约束 + 控件测量/布局规则
框架维护的布局结果：尺寸、位置、内容范围、裁剪范围
          ↓
绘制与几何交互共用布局事实 → 不可变绘制计划 → 宿主 backend/replay

输入 → 当前有效范围内路由 → 编辑操作或业务意图 → 状态变化
```

箭头表达职责与依赖，不规定每个步骤必须同步或延迟，也不预定实现类、队列或快照结构。

| 责任主体 | 持有与负责 | 不由其承担的职责 |
| --- | --- | --- |
| 业务/页面作者 | 业务权威值、校验、任务与事务；选择提交和适配策略；持有独立编辑状态 | 普通排版的最终尺寸/位置计算，手动 flush/layout/paint |
| 状态系统 | 直接状态读写、纯派生及其一致性，显式副作用的作用域机制 | 依赖控件挂载或 UI 帧才能成立 |
| 控件作者 | 内容测量、内部布局、绘制与交互规则，以及可通知的依赖 | 绕过框架维护另一套外层布局、坐标或输入所有权 |
| 呈现运行时 | 绑定、变化追踪、测量布局、绘制与输入协调、控件生命周期 | 推断业务权威、网络事务或结果含义 |
| 宿主适配层 | 可用空间、缩放、资源与原生输入信息、平台转换和运行入口 | 把平台类型或 GUI Scale 混入核心闭环 |

UI 变化以 state/signal 驱动；输入 handler 发布业务状态或意图，不直接改节点属性或树结构。焦点、capture 等权威交互命令通过路由器受控入口执行。公开声明能力与 handler 的写入边界不能混为一谈；挂载后结构变化的接入方式在接口设计中遵循本节状态/意图边界。

主题、文案、尺寸意图与子控件关系属于 UI 逻辑描述；实际尺寸、位置和裁剪范围属于框架维护的结果。业务可读取公开布局信息用于锚定等明确用途，但不直接修改结果，也不读回结果再写尺寸来补偿普通排版。逻辑描述可以由现有控件与响应式能力承载，不要求另建配置树。

## 3. 状态、派生与变化传播

### 3.1 状态独立性与可见性

状态与派生系统不依赖控件挂载或 UI 帧推进即可使用。在合法状态访问上下文中，直接状态写入后，随后读取同一状态得到新值，连续读写不会因旧已提交值覆盖前一步。此要求不赋予任意线程修改 UI 的权限。

状态可读与画面呈现分开：业务无需调用 scheduler、flush、layout、paint 或 replay；最终状态呈现允许批处理，有顺序意义的编辑及通知追加必须依序保留。

派生计算只根据来源生成结果，不修改其他状态、控件或外部系统。副作用经显式订阅/Effect 执行，归属明确生命周期。业务副作用不依赖控件挂载；呈现绑定随卸载释放，独立业务副作用不得继续持有已卸载节点或输入绑定。

纯派生首次及后续读取均返回基于当前来源状态计算的结果。直接状态写入后，紧接着读取依赖它的 Computed，包含多级派生链，须得到当前结果；不返回尚未求值的占位值冒充结果。只有派生函数自身产出 null 时，null 才是合法结果。框架可按需计算、缓存或提前求值，不要求每次写入立即重算；派生读取不执行 Effect 或外部副作用。Effect 执行时机和批处理接口另行设计。正式主题派生仍满足第 7 节的首次有效值要求。

### 3.2 自动更新职责

公开声明、可追踪状态、环境或内容资源变化，使相关结果失效，由框架在正常呈现流程中更新。自定义控件依赖框架无法感知的外部数据时，通过正式能力通知变化；通知不等于执行布局或绘制。

变化按实际依赖影响测量、布局或绘制。例如颜色通常影响绘制，字体、文案或内边距可能影响测量与布局。缓存须具备失效和释放来源，动态性不依赖每帧全量重算；不承诺每次仅重算一个节点。

声明修改、属性传播与布局/绘制执行分别设计，不要求所有属性修改统一延迟或逐条保存更新请求。属性传播的具体执行时机留给设计，纯派生读取不得隐含修改 UI。

### 3.3 环境与资源变化的职责

宿主将语言、资源、可用空间和缩放等外部事实提供给框架；页面提供内容及适配声明。相关变化沿第 3.2 节依赖追踪进入测量、布局或绘制，业务不自行注册平台监听或重开页面来补偿正常动态更新。

语言变化影响翻译文案、排序或搜索所依赖的语言事实；同一语言下资源重载也可能更换字体、翻译资料或图像，相关内容依赖仍须失效。框架不得仅因语言码未变就认为所有文本资源未变。值与变化通知、代际的具体表示留给接口设计，不冻结现有 long 计数或单例结构。外部数据无法自动追踪时按第 3.2 节通过正式通知接入。

资源与环境订阅遵循第 5 节归属，卸载释放呈现绑定，不释放独立业务状态。环境依赖的缓存不以构造期快照保持旧值；复用缓存仍须响应其实际依赖变化。

### 3.4 渲染批次与一致性

框架根据已追踪变化，协调本批次的测量、布局、绘制区域、裁剪、滚动范围与命中区域，形成一致的呈现及交互结果。改变位置、大小、滚动、缩放或裁剪的内容，不能出现一套区域用于画面、另一套区域用于指针命中的情况。自定义控件及浮层遵守同一职责。

业务只发布逻辑状态或意图；框架决定批次如何合并、计算及生效。统一更新的是呈现及几何结果，不将直接状态或纯派生读取延迟到渲染批次，不要求逐条保存所有属性修改，也不将独立业务 Effect 绑定到 UI 帧。后续输入由框架使用一致的结果与有效交互范围处理；批次内的阶段顺序、缓冲或快照机制由设计选定。

## 4. 布局与自定义控件

### 4.1 布局输入与统一结果

宿主提供根可用空间及环境约束，页面声明排列方式、关系、尺寸意图、边界、间距、显隐与滚动策略，控件提供内容测量能力，框架组合求解。普通页面无需提供测量结果或布局回调。

自定义控件作者可定义内容测量、内部排列、绘制与交互规则，由框架调用并协调结果；外层仍可将其作为控件组合布局。扩展接入 UILib 自有布局、绘制、输入机制，保持裁剪、命中、动态失效与生命周期协调，不直接改写最终布局结果。

布局结果是绘制、裁剪、指针命中及滚动范围的共同依据。布局及命中区域归框架自动管理，在渲染批次中统一更新，画面与命中区域保持一致；业务不选择结果版本，不手动同步区域。自定义内部命中使用框架分配的区域和坐标转换，参与同一批次；绘制及输入不独立重建外层排版。禁用/失活等交互资格与几何命中分开检查。具体阶段顺序、结果存储和发布机制属于框架设计，不将“最后已呈现布局”另立为必须采用的实现合同。

### 4.2 尺寸意图与边界

| 声明 | 含义 | 空间不足时的规则 |
| --- | --- | --- |
| 固定尺寸 | 指定尺寸，不随内容自然增长 | 经自身边界限制后不因父空间不足自动缩小 |
| 自然尺寸 | 按内容、字体及声明的测量/换行规则求尺寸 | 默认不自动压小布局盒；明确缩减另行表达 |
| 填充/剩余空间分配 | 使用父容器可用空间或参与兄弟间分配 | 遵循自身边界，具体分配细则留给布局设计 |
| 最小/最大边界 | 独立于尺寸意图的合法范围 | 先按意图求值，再限制到范围；固定尺寸也受约束 |

同一种声明在宽、高、普通容器与滚动视口中保持相同含义。最小尺寸为硬边界，父空间不足也不突破；最小值大于最大值是无效声明。按已声明换行规则重新测量仍是自然尺寸，不等于测量后压小布局盒。

普通容器默认允许溢出，不自动裁剪或变成滚动容器；溢出不自动扩大其布局盒，可见范围受上层裁剪限制。裁剪及滚动明确声明；裁剪不改布局尺寸，隐藏部分不命中；允许溢出时，父盒外可见且未被裁剪的子控件部分仍可交互，框架不能仅因指针位于父盒外就跳过该子树；实际可见区域、祖先裁剪、输入范围和交互资格共同决定命中。业务不扩父盒或补命中区域来实现该行为。重叠优先级由统一绘制与输入规则处理，不能另外重建排版。换行、重排、折叠是布局策略，裁剪、滚动是溢出处理，框架不擅自替页面选择。

### 4.3 动态面板与空间不足

页面声明标题、页签和操作区自然尺寸、正文占剩余空间并独立滚动。框架测量各区域，扣除间距和内边距后分配正文视口；固定区指不随正文滚动，不要求数值高度固定。文案、字体、主题、语言或窗口变化自动重新测量，业务无需 fixedChromeHeight 公式或访问标准控件内部文字节点。

极小窗口适配由页面声明，框架执行，可选择整体滚动、精简布局或最低适用范围；低于范围时提供明确说明及退出方式。框架不擅自缩字号、隐藏操作或改为整页滚动，不保证任意小窗口都完整显示所有区域。

合法空间不足按声明策略处理；无效声明及自定义规则产生非法尺寸、无法完成计算等错误，须有可定位诊断，指出控件或规则，不用默认结果掩盖问题。报错通道、故障范围及保留上一结果的政策留给运行时设计。

### 4.4 自定义控件的正式接入职责

扩展作者声明控件的内容依赖、测量能力、内部排列、绘制内容及交互行为；框架提供可用约束、实际分配区域、坐标变换、裁剪及有效输入范围，并协调调用。页面仍用统一的尺寸和布局声明组合该控件，不因它是自定义控件而接管外层测量、重算或宿主绘制。

测量和布局求解不修改业务权威状态；绘制消费框架协调好的几何及样式，不在绘制途中重排节点；输入发布业务状态或意图，内部几何命中参与第 3.4 节统一更新。外部不可追踪数据通过正式变化通知接入。

扩展所拥有的订阅及资源归其生命周期；共享资源按其实际持有者管理。扩展返回非法尺寸、循环求解不能完成或运行失败时，第 4.3 节可定位诊断仍适用。具体接口签名、测量缓存、布局算法及错误传递方式由实现设计选择，不用固定节点结构作为扩展合同。

## 5. 控件身份、归属与生命周期

UILib 默认创建 UUID 作为唯一控件身份，业务无需提供，主要用于框架内部维护。移动与排序保留身份；框架不得静默接受重复身份，也不按位置、结构或文本推断新建控件等价于旧控件。具体唯一性保障留给设计。

一个实例同一时刻只有一个逻辑归属位置：子控件只有一个逻辑父节点，根控件没有逻辑父节点。重复加入另一位置须报冲突，不偷偷移动或复制。多处显示同一业务数据使用独立控件共享状态，各自维护布局和交互。浮层绘制位置不必改变逻辑归属。

| 动作 | 生命周期与资源效果 |
| --- | --- |
| 创建/组合 | 未挂载即可维护逻辑描述，不拥有宿主输入，也不执行宿主绘制 |
| 挂载 | 接入宿主布局、绘制与输入流程 |
| 普通更新/排序/移动 | 持续存在控件保留身份及合法交互状态，移动明确表达 |
| 隐藏 | 不等于永久删除；交互释放按有效范围及现行 collapsed 例外处理 |
| 卸载 | 释放焦点、输入及挂载绑定，保留逻辑树和身份，允许重新挂载 |
| 明确移出保留 | 解除原归属及挂载关系，保留子树供之后使用 |
| 永久删除/销毁 | 终止控件及当前所属子树生命周期，释放所拥有订阅与资源；不能重新挂载 |
| 销毁后重新创建 | 新 UUID、新生命周期，不自动继承旧焦点、选区或滚动 |

独立业务状态和编辑状态由其持有者管理，控件销毁不连带销毁这些状态或外部共享资源。自定义控件负责释放自己拥有的资源。

普通动态更新保持草稿、光标、选区、合法焦点与滚动状态，不用整页重建代替更新。滚动范围缩小时仅限制到新有效范围；用户主动导航到不可见目标时允许第 6 节的必要滚动。重新挂载按当前描述和环境布局，不自动恢复旧焦点或输入所有权；具体跨挂载状态恢复留给设计。

### 5.1 生命周期资源归属

控件逻辑生命周期与挂载生命周期分开。挂载期间的呈现订阅、宿主输入、焦点及手势绑定由框架管理，卸载解除这些关系；重挂载按当前描述重新建立有效绑定，不能叠加上次挂载留下的重复回调。逻辑描述和独立编辑状态的保留按本节既有归属处理。

独立业务 Effect 由业务作用域持有，其执行不以页面是否渲染为条件；控件内部订阅由控件或挂载作用域持有，销毁终止所属回调。释放控件不擅自关闭业务持有的共享状态或资源。运行时不得因已释放绑定的迟到通知访问已销毁控件；业务异步任务的取消与结果权威仍归第 8.4 节。

“副作用与纯派生分离”规定的是职责和可观察行为。执行器、合批边界、跨线程递交和清理实现随后设计，不要求业务通过 UI flush 驱动，也不强制副作用在直接状态 set 的调用栈内执行。

## 6. 输入范围、宿主与焦点

### 6.1 范围、消费与模态

宿主输入经适配边界进入；原生输入只由一个消费者递交，范围预览只读、不消费输入，按选定范围分发；一段手势只有一个输入所有者。第二鼠标键整段吞掉，不建立第二 owner；失活 owner 取消后尾部吞到物理结束，禁止误触点击。实现差距按本节修正。

ESC 先交当前范围处理者，消费即停止外层关闭；未消费才进入页面关闭策略或宿主默认行为。宿主依据处理结果 fallback，不在输入尚未处理时抢先关屏。关闭确认及草稿去留归业务。

模态范围激活期间，指针、键盘、文本及焦点导航只进入该范围与所属交互浮层；外部点击可按声明请求关闭，不同时激活后台。交互浮层默认属于所属控件的输入范围，绘制层位置不改变归属；范围关闭、卸载或销毁时释放相关浮层输入。

内层模态激活时外层及后台不响应；关闭内层返回外层，已消费事件不继续作用于外层。外层结束时结束其所属内层及浮层。可恢复外层先前焦点的前提是目标仍存在、可聚焦且属于有效范围；初始焦点与恢复失败后的选择留给设计。

纯提示通知不抢焦点、不改 Tab 范围、不消费 ESC、不拦指针，不改变键盘/文本目标。带操作按钮的通知及其他非模态交互层需明确声明输入行为，不能按最高绘制层推断模态性。

### 6.2 导航与交互资格

Tab/Shift+Tab 默认按当前范围内逻辑树声明顺序前进/后退，跳过隐藏、失活及禁用控件，保留只读输入框。布局换行或窗口缩放本身不改变顺序；逻辑顺序明确变化时按新顺序。暂不增加独立焦点排序属性，UUID 不参与排序。

导航在范围内循环，单项保持焦点，空范围不建立焦点。导航至视口外目标时最小必要滚动，已完整可见不滚动；嵌套滚动区域逐层协调，目标大于视口时优先显示焦点或编辑位置。

只读输入框允许聚焦、Tab 到达、选择、复制和滚动查看，不允许修改或编辑提交。禁用不接受焦点、编辑或激活，Tab 跳过；转为禁用释放已有交互，不隐含提交或丢草稿，状态切换的释放不暗中触发失焦提交。禁用原因可通过不激活控件的提示查看。转只读时既有草稿去留归业务。

复合控件的文字与装饰属于其交互单元，内部独立按钮或输入框保留自己的焦点与命中；沿用现行 leaf hover/pressed 语义。

### 6.3 非模态输入及焦点策略的声明

输入参与、输入范围和绘制层级分别声明。非模态交互内容可接收针对自身的输入，但不能仅因被绘制在顶层就隔离后台、重置 Tab 范围或抢走文本目标；需要独占范围时明确使用模态语义。焦点变更经框架受控入口，平台宿主不另立第二套焦点权威。

页面或复合控件可以声明进入范围时的初始焦点及恢复目标，框架检查目标存在、可聚焦且处于有效范围；无法恢复不得将输入交给失效对象。未声明时的选择顺序由统一框架策略设计，遵循第 6.2 节导航合同，业务不依赖内部列表位置补偿。

启用制表符输入的编辑器必须提供明确的退出或外部导航方式，不能把焦点永久困在编辑区。失焦协调及取消行为按编辑声明和业务决定执行；框架不把状态失活、卸载或模态隔离擅自解释为提交或草稿取消。

#### 6.3.1 范围进入与恢复的选择规则

页面与模态范围进入时优先使用声明的初始焦点；目标无效或未声明时，按第6.2节逻辑声明顺序选择第一个当前有效、可聚焦的目标，空范围保持无焦点。返回外层范围时，依次核验声明的恢复目标、被覆盖前的焦点、初始目标，再使用同一默认顺序。声明目标按当前声明和挂载核验；自动保存的先前焦点仅对原挂载代际有效，期间真实生效的隐藏、禁用、不可聚焦或卸载会永久取消该恢复资格，不能在恢复资格后复活旧记录。

选择发生在声明结算后的范围进入或返回，不从焦点读取中隐式推进。普通内容/布局变化、在当前范围添加控件、更新初始/恢复目标声明以及主动清除焦点，不再次执行进入策略。非模态提示不形成范围转换；内层模态返回外层，所属外层结束时丢弃已结束范围的恢复记录。当前切片接入页面根与模态范围，非模态复合范围的显式进入、导航滚动、Tab与编辑输入按后续专题接入，不据本小节提前实现。

## 7. 主题与标准控件文案

正式主题派生入口保证有效初值，创建后即可挂载标准控件，后续来源变化继续更新；业务不补算初值或主动刷新。此保证不等于所有 Computed 必须同步求值，也不自动修复无效业务主题，初始化不能意外将派生内部依赖挂入外层重建 Effect。

标准控件公开换行、单行省略或允许溢出等文案策略，按实际可用文字空间测量、布局与绘制。语言、字体、主题及空间变化自动适配，业务无需访问内部子节点或布局后补宽度。

标准按钮默认换行，自然高度随内容增长；明确尺寸与最大高度仍受既定规则约束。高度受限且文字放不下时，默认仅显示完整行并标示省略，完整文本通过悬停或键盘聚焦后的被动提示查看。提示不改变按钮尺寸或焦点，不擅自增高或缩字号。作者可明确选择其他文案策略。

文字区域连完整行或省略标示都放不下时的呈现、提示时机和放置留给控件设计；框架仍保留完整文案。此默认不推广到所有控件。

## 8. 编辑状态与业务结果

### 8.1 草稿、提交与会话

标准文本输入支持光标定位、方向键、选区、复制/剪切/粘贴、全选、撤销/重做及中文输入法提交，单行/多行按各自换行规则处理。

编辑状态承载草稿、光标、选区及历史，允许负号、空串等未完成输入；业务最终值由业务校验和接受。框架管理可追踪编辑状态，不在控件中隐藏独立副本。业务值写入、草稿编辑、请求提交、接受/拒绝、结束/取消编辑及重置基线具备可区分语义。

业务选择随输入、确认、失焦或表单应用提交；框架执行声明，提交仅请求业务接受，不自动保存或发网络请求。实际修改或开始 IME 组字开启编辑会话，聚焦、移动、选择或复制不启动会话。随输入接受不结束会话；声明完成动作获接受且对应当前草稿时结束并显示规范化结果，焦点可保留。切换表单字段不隐含完成提交。

明确拒绝保留草稿并呈现业务原因，业务值不变，不强制抢回焦点。异步期间允许继续编辑，框架关联对应提交与草稿；旧结果不能覆盖新文本、改光标/选区、结束新会话或把旧错误算作新草稿结论，但对应旧提交状态仍如实呈现。

外部业务值变化不自动覆盖活跃草稿，业务决定保留、替换、取消或提示；无编辑会话正常同步业务值。UILib 不强制冲突选择界面。

编辑状态生命周期由业务管理，解绑控件不提交或丢弃草稿，保留的状态不得依赖旧控件绑定；不同对象可保留独立编辑状态。框架不把焦点当成会话判据。

### 8.2 键盘与输入法

输入法组字期间 Enter 仅确认输入法，不同时提交字段/表单；组字结束后的后续 Enter 才按字段声明执行。单行可以确认，多行默认换行，提交用明确快捷键或按钮。宿主提供真实组字状态及事件信息，不凭普通字符猜测。

单行/多行默认 Tab 切换焦点，需要制表符的编辑器明确开启模式；输入法消费优先，同一事件不再切焦点。ESC 默认不取消整个草稿；组字取消或内部菜单可消费，否则交给外层策略。业务需要 ESC 取消编辑时明确声明。

### 8.3 撤销历史

文本撤销/重做仅修改草稿，不直接撤销业务操作或回退权威值；后续提交仍按声明策略执行。随输入字段可以对撤销后的新草稿请求接受，业务仍可拒绝。

普通编辑（如模板插入）可进入历史；重置基线替换文本并清空撤销/重做，不能恢复旧对象文本。业务明确选择编辑、重置或切换独立状态，框架不猜测。提交成功保留历史，规范化与确认协调为完成步骤；撤销可恢复此前文本并开启新编辑会话，不反复陷入格式修正。

连续同位置输入及同方向删除分别合组，操作类型切换、移动光标、选区变化或切焦点结束当前组。粘贴、剪切、一次 IME 提交和模板插入各为完整一步；明确确认结束分组但不清历史。VS Code 体验及相关实现作为参考，具体阈值留给设计，实现落在 UILib 自有机制中。

### 8.4 业务边界

业务负责最终值权威、校验、异步任务及事务；UILib 接收明确状态或结果，管理编辑协调和呈现，不推断含义。乱序、超时、重试、服务端版本和表单原子性归业务，不继续逐项纳入通用规格。网络异常不能被框架自动算作明确业务拒绝。

控件关闭/销毁释放 UI 资源，不自动取消业务任务。UILib 提供宿主/生命周期协调能力；异步结果是否更新业务或重新打开页面由业务控制，不能凭过时控件绑定恢复已关闭视图。

## 9. 平台边界与验收

UILib 采用原生 framebuffer 分辨率：布局、字号、裁剪、滚动距离与指针命中统一使用实际 framebuffer 像素。Minecraft GUI Scale 不改变 UILib 的尺寸和文字大小。窗口或 framebuffer 大小变化会改变可用区域并自动重排；保持相同声明字号时，字形的像素尺寸保持一致。本文 logical px 指 UILib 坐标像素，在该宿主中与 framebuffer px 一一对应；宿主原生输入若采用其他坐标单位，在边界转换一次，不将 GUI Scale 带入核心。

滚动有效偏移由框架按最终内容范围与视口限制；内容未溢出时偏移为零，到达末尾后的滚轮不累积额外偏移，反向滚动立即响应。内容删除、换行、字号及窗口变化后重新计算范围并限制已有偏移，业务无需维护末尾边界。

平台层次为“无平台核心 → 可替换的宿主适配（如 LWJGL2/LWJGL3）→ Minecraft 等应用宿主接入”。无平台核心的公开合同、布局、输入逻辑、文本定位、绘制计划与资源生命周期不依赖 Minecraft、Forge、LWJGL 类型或其运行时存在；加载和使用核心不能触发这些宿主的类加载、native 初始化或 GL 上下文要求。实现选择以目标环境中可靠工作为准，兼容性优先于未经验证的加速收益，不强制纯 Java 基线，也不要求先手写 Java 字体引擎再使用 native。字体读取、整形、度量与光栅通过不含宿主类型的合同提供；已有成熟 native 后端在目标环境中的操作系统、架构、ABI、Java/绑定版本、分发与加载方式确认可用后可以积极复用。native 与 GPU 能力查询归适配层，按实际使用初始化；核心合同和逻辑加载不触发平台初始化。缺少可用后端时评估已有可移植实现或目标平台适配，不以强制自研、虚设 fallback 或删减文字能力代替解决兼容问题。Java 标准 API 的隐含 native/桌面依赖也须核查，不能仅凭语言或 API 名称判定可移植。

LWJGL 是宿主层，不是核心的必要前提；Minecraft 位于更外层，负责游戏资源、调用语义和生命周期接入。直接使用 LWJGL 的偏好仅适用于对应宿主适配内部，不授权核心直接依赖 LWJGL，也不意味着只支持 LWJGL3。纯 Forge 1.7.10 自带的 LWJGL2 必须有可用适配，UILib 核心、自有页面与默认原版字体替代不得要求安装 LWJGL3ify、Angelica，或为迁就实现而替换该实例的 Java/LWJGL 宿主。LWJGL3ify/Angelica 存在时使用对应适配并保留既定兼容合同；缺席时通过现有宿主完成相同核心语义，不能静默退回原版字体、禁用核心功能或删减文字能力。native 资源确需随适配提供时由 UILib 的适配发行负责，不要求用户安装无关宿主 Mod。用户另行明确允许 MC 实例安装 UniMixins 以提供注入运行时；该 MC 外层依赖不进入核心，直接复用其 Mixin 能力，不自行实现注入框架。

宿主适配负责所声明运行组合中的绑定、类转换和方法签名兼容。处理这些差异时保留宿主有效状态及其虚拟化管理，不通过关闭整个宿主转换链或改变全局宿主配置来绕过兼容缺口；只需要隔离的绑定在自身作用域加载。兼容修复止于 UILib 自身能力及接入边界，不扩展为修复原版游戏自身内容。具体绑定版本、转换标记、重载选择与缺陷原因随实现维护；验收使用实际发行包及目标宿主，独立绑定测试不能替代整合宿主的启动与绘制验证。

验收分别覆盖：无 Minecraft/Forge/LWJGL 的核心加载与逻辑流程；纯 Forge 1.7.10、原有 Java8/LWJGL2、无 LWJGL3ify/Angelica 的实际运行；既有 LWJGL3ify/Angelica 实例的回归。两种 MC 宿主复用同一文本定位、字形需求与有序绘制合同，差异止于资源、native 绑定、GPU 提交及游戏接入，不建立第二套排版/格式/缓存引擎。独立运行器使用 LWJGL3 取得的证据只属于该宿主，不能替代无平台核心或 LWJGL2 的验收。

核心平台无关，平台输入只经适配边界进入；内部布局、绘制、裁剪和输入共享 logical px，GUI Scale 转换仅在宿主边界成对发生。数据/paint 层不调用 GL，paint/replay 传递自包含、不可变绘制计划。backend/replay 恢复触碰的 GL 状态，包括宿主已有非默认裁剪、stencil 与 mask。UILib 即便在宿主边界也优先直接使用 LWJGL 宿主能力；窗口、framebuffer、原生输入与 GL 操作不优先经 Minecraft 包装方法取得。Minecraft 特有资源包、生命周期与调用语义留在专用适配层；宿主虚拟化的 GL 状态须读取其实际有效状态，不以裸驱动查询替代宿主缓存事实。通用绘制不得使用 Minecraft 的 Tessellator 等包装类，应走直接 GL 或 UILib 自有管线。物品 icon 的 Minecraft 适配可完整委托 RenderItem.renderItemAndEffectIntoGUI（含 Forge hook 与标准光照）；此适配例外不扩及通用 GUI 或渲染核心。

优先复用 scene、响应式、PaintCommand、标准控件及字体能力，不能为了通过测试绕过生产路径或直连原版 GUI。

### 9.1 统一测试自动化应用

测试作者通过继承统一测试应用基类定义具名场景，复用启动、初始化、执行、资源释放与结果报告。各入口仅启动具体测试应用；不再各自实现一套运行器。应用向子类提供参数、行为断言及资源归属能力，新增场景主要表达输入、生产链路和可观察预期。

## 13. 字体、文本与数学排版

### 13.1 模块职责与数据流

文本调用方提供内容、显式内容模式、样式和可用约束；解析层生成内容结构，排版层结合字体与约束生成行、块及公式几何，绘制层消费同一结果。标准控件和自定义控件共用这一流程，不通过字符串长度、手算字宽或控件内部节点拼装另建文本布局。

原始文本、Minecraft 格式文本、富文本标签和 Markdown 是明确选择的输入模式，不按文本中出现某个符号猜测模式。平台特有格式的解释止于被选定的内容转换能力；它不改变其他模式的语义。解析不调用宿主绘制、修改业务状态或触发链接行为。

内容结构与显示几何分开：窗口、字号或字体改变可以重新排版，不要求业务重新提交源码。内容、样式和资源变化按实际依赖失效；稳定内容不需要每帧重新解析。内部模型及缓存接缝不形成冻结的公共 API。

### 13.2 文本几何与交互

测量、换行、省略、基线、绘制及链接区域使用同一次排版的文本与字体事实，遵循第 3.4 节渲染批次更新。多行链接按实际可见片段命中，祖先裁剪仍有效；点击发布链接目标或动作给调用方，不由解析器代替业务执行外部行为。

Unicode 内容处理不能以 UTF-16 单个 char 作为任意可切割字符，把代理对截成半个字符。文本编辑沿第 8 节处理光标与选区；只读显示的切行、省略及复制应保留可解释的原内容关系，不把画面省略号写回业务原文。复杂字形与平台字体支持边界须在字体能力设计中明确，不凭已有测量函数声称全部脚本完整支持。

文本内容及样式的原文由调用方持有；框架负责其排版和呈现。缺字、无效内容或不支持语法的处理必须有明确结果，不能静默截断整段内容。具体语法集合及降级合同按第 13.5 节继续裁决。

### 13.3 字体专项入口

字体选择、缺字回退、资源生命周期和自有渲染器的权威合同独立维护在[字体渲染器专有规格](2026-10-07-uilib-font-renderer-spec.md)。本节只登记入口；共同文本流程仍按第 13.1—13.2 节，原生坐标按第 9 节，专项字体约束不在此重复。宿主合批、原版字体替代的提交范围及无平台渲染验证另见[MC宿主渲染优化专题](2026-10-07-mc-host-render-optimization-spec.md)，该新增稿待审。

### 13.4 数学排版职责

数学能力解析并排版明确支持的公式子集，作为可测量内容参与行内或块布局，字体度量、数学盒与实际字形保持一致。文本和公式混排由共同排版过程协调基线及行高，不由业务补算公式高度。

首期支持常用公式能力：分组、上下标、分式、根式、伸缩定界符、矩阵/分段、数学字体样式、常用符号与算子。它是明确的数学子集，不承诺完整 TeX 宏定义、包加载或外部 TeX 执行。各能力的作用域及其余明细由本 spec 继续细化，不能仅引用旧命令清单或测试作为新权威。

用户已认可的首期核心命令范围如下；符号明细、重音及具体字形质量边界暂缓深入，不据当前源码的容错或历史排版规则扩大合同。

| 类别 | 命令或结构 |
| --- | --- |
| 分组与脚本 | `{…}`、`^`、`_` |
| 分式及二项式 | `\frac`、`\dfrac`、`\tfrac`、`\binom` |
| 根式 | `\sqrt{…}`、`\sqrt[index]{…}` |
| 伸缩定界符 | `\left`、`\middle`、`\right` |
| 矩阵/分段/数组 | matrix、pmatrix、bmatrix、vmatrix、cases；array 支持 l/c/r 列声明 |
| 数学样式 | `\displaystyle`、`\textstyle`、`\scriptstyle`、`\scriptscriptstyle` |
| 数学字体及文本 | `\mathrm`、`\mathit`、`\mathbf`、`\mathnormal`、`\text` |
| 算子及上下限 | 常用函数、大运算符、`\operatorname` 及星号形式、`\limits`、`\nolimits` |
| 显式间距 | `\,`、`\:`、`\;`、`\!`、`\quad`、`\qquad`、反斜杠空格 |

数学源文与排版结果分开，动态字号和资源变化不丢源文；绘制继续走 UILib 管线。未知命令、无效结构或无法完成排版时，保留并呈现该公式源文，提供可定位到公式及错误位置/阶段的提示；其他有效内容继续解析和排版，不因一条公式失败使整篇文档消失。错误提示属于框架内容呈现，不由业务补写解析异常处理来维持文档。

伸缩符号及字体样式由数学度量与字形能力协调；准确支持、字体缺失下的近似或降级应有明确边界。不能把忽略未知命令、显示残缺公式或使用近似字形包装成完全支持。具体字形构建、数学盒算法及字体选择留给设计，支持范围及可观察降级在本 spec 补齐。

### 13.5 Markdown 基础及扩展边界

用户已确认：Markdown 以 CommonMark 为基础，明确增加表格和数学公式扩展，不承诺完整浏览器 HTML 或脚注等所有扩展。CommonMark 是基础语法的语义对齐依据，不凭旧实现子集、聊天防误伤特例或旧测试结果替换其规则，也不凭采用本方向宣称生产实现已通过一致性验证。具体对齐版本和采用库由实现设计明确。

用户进一步确认：对齐 VS Code 内置 Markdown 预览的文档解释及主要阅读行为，排版、绘制和资源管理仍完全使用 UILib。参照环境固定为选定 VS Code 稳定版本、默认预览设置、未安装第三方 Markdown 扩展；本轮固定参照为 VS Code 1.140.0（commit 07f806f999227108933c2e30515b26eecc1fda74），内置 Markdown 依赖 markdown-it 14.2.0，内置数学扩展依赖 @vscode/markdown-it-katex 1.1.2。记录默认设置，不将持续变化的 main 分支或插件输出作为漂移的验收标准。选定版本是对照环境，不自动将其中所有额外能力纳入 UILib 首期范围。

对齐覆盖文档结构、语法解释、主要换行行为、链接、图片及公式；字体、主题、间距等由 UILib 声明系统协调，不承诺像素级复制 VS Code 页面。HTML/CSS、公式命令、来源解析等能力差异须在本 spec 明确列出，不能以“对齐 VS Code”暗中承诺完整浏览器或 KaTeX 能力。受支持 HTML 转换为 UILib 内容结构，不自动改走 RICH_TAGS 模式；已认可的标签类别见下文；不支持内容按下文已确定的降级规则处理。

文档可声明基准位置，框架负责相对图片来源和链接目标解析；业务不拼接路径或接管图片下载。环境适配提供基准位置的解析能力；此前首期来源承诺保持不变，本条不自动开放任意文件路径。链接激活仍发布解析后的目标或动作给调用方，执行归业务/宿主，解析不执行动作。

基础文档能力包含段落、软/硬换行、标题、分隔线、引用、有序/无序及嵌套列表、围栏/缩进代码块；行内包含强调、粗体、代码、转义及链接。代码内容按代码语义保留，不再解析成公式、富文本或动作。列表层级和引用等结构由排版体现，不用向业务字符串插入固定空格代替结构布局。

表格扩展提供表头、正文行、单元格及列对齐，单元格参与统一行内解析与排版；列宽、行高、换行和溢出处理由框架按可用约束及页面策略协调，不要求业务手算表格几何。它不自动成为可编辑 DataTable，文档展示与编辑控件的业务职责分开。采用管道表格语法：表头之后紧接分隔行，分隔单元格以连字符及可选冒号表达列对齐；左冒号为左对齐，右冒号为右对齐，两侧冒号为居中，无冒号使用默认对齐。表头与分隔行的列数必须匹配，不能匹配时不识别为表格，按正常文档规则解释。正文行缺少的单元格补空，超过表头列数的单元格不进入显示表格，不扩展列数；源文仍由调用方保留。这是已认可的表格语法规则，不将超出的单元格作为解析故障或未知 HTML 字面降级。转义管道、首尾管道及块结束边界按固定 VS Code 参照版本核对。

框架默认根据可用空间和内容求列宽，协调单元格换行及行高；内容仍超宽时提供表格自身的横向滚动视口，不将整篇文档撑宽。图像/字体/公式及窗口变化自动更新列布局和滚动范围；框架不把不可拆分内容强行切断以满足宽度。横向滚动遵守共同几何、裁剪和输入范围合同，业务无需设置列宽公式或维护横向偏移。具体列分配算法及滚动控件样式由设计完成。

数学扩展使用 `$…$` 表达行内公式，独立 `$$…$$` 表达公式块；内容交给 UILib 数学能力，排版参与统一几何。行内公式随所在文本行协调基线和行高，独立公式块作为文档块参与布局。不能因不同调用出口而对同一源文采用两套默认定界解释。

行内代码、代码块以及明确转义的定界符保持字面内容。单美元定界按固定数学插件识别：开定界前不为美元、反斜杠或 ASCII 字母/数字/下划线，闭定界后不为美元或 ASCII 字母/数字/下划线；转义优先于公式识别，公式内部转义美元不作为闭合。`$x$`、`$ x $` 及同段内跨源码换行的配对可识别为行内公式；`a$x$b`、`$5 and $10`、不配对 `$x` 保持普通内容，中文紧邻 `$x$` 可混排。输入输出对照语料使用上述固定参照，不从旧聊天特例或解析器实现继承规则。不构成公式的文本按普通文档内容保留，不静默删掉。已识别公式内部的未知命令或排版失败属于数学内容能力及其降级合同，不退回另一套 Markdown 词法猜测。

Minecraft 的 § 格式码不作为 Markdown 解析核心语义；宿主若需保留颜色或其他来源样式，先明确转换为内容样式，再以统一规则参与解析及呈现。样式片段分割不是 Markdown 文档边界，相同内容不会因宿主分成多个片段而改变语法解释。

Markdown 支持图片语法与内嵌显示，图片来源、替代文字及尺寸/适配意图进入第 14 节 UILib 专有图像系统，与普通图片控件共用加载、测量及资源管理；业务不自行下载、补算尺寸或手动触发重排。完整浏览器 HTML/CSS 不在本次已认可范围内；HTML 采用下述内容子集，其超出部分的显示差异须明确，不采用全部 HTML 默认字面显示的独立提议。按固定参照，默认支持 `~~…~~` 删除线、完整 URL 及邮箱自动链接；关闭模糊裸域名识别，`example.com` 与 `www.example.com` 不自行变为链接。默认 breaks=false，段落内软换行不强制形成硬换行；显式硬换行保持原语义。默认 typographer=false，不自动美化引号或替换普通标点。自动链接复用既有链接目标及激活合同，不隐含自动打开外部程序。未支持内容不能被静默丢弃，失败或字面显示须具有明确合同。脚注、任务列表等未认可扩展不因 Markdown 名称而自动承诺，也不依据旧代码排除将来的正式扩展。

#### HTML 内容子集

支持常用内容标签及相应必要属性，统一转换为 UILib 文档内容结构。业务不用把 HTML 拆成控件或自行写 HTML 几何；HTML 与 Markdown 内容共同参与第 13.2 节排版、链接命中及第 14 节图像系统。

| 内容类别 | 支持标签 | 必要内容属性与职责 |
| --- | --- | --- |
| 行内文字语义 | strong、b、em、i、u、s、del | 保留所支持元素的内容语义，具体外观由 UILib 样式系统呈现；b/i/u 不仅作为视觉样式开关解释 |
| 换行与段落 | br、p、hr | 表达换行、段落及分隔结构，不靠固定空格排版 |
| 标题 | h1 至 h6 | 表达标题层级，由主题及排版处理尺寸和间距 |
| 列表与引用 | ul、ol、li、blockquote | 保留嵌套结构；ol 的 start 表达起始编号 |
| 代码 | pre、code | 保留代码内容及空白语义，不把代码内符号再解释为 Markdown 或公式 |
| 链接 | a | href 为目标，title 为可选说明；基准位置解析及激活职责沿本节既有合同 |
| 图片 | img | src、alt、title 及有效 width/height 尺寸意图进入统一图像系统；不引入另一套加载器 |
| 表格 | table、thead、tbody、tfoot、tr、th、td | 表达表格结构，由共同表格排版能力测量、布局及绘制 |

属性值经内容转换验证，不将任意 HTML 属性当节点 setter；图片的尺寸属性按 logical px 尺寸声明参与第 14.6 节，属性无效时应有明确降级。属性未列入支持范围不自动获得浏览器语义；表格跨行/跨列、任意 class/style、额外标签等须有明确能力合同后纳入。

任意 CSS、脚本执行及浏览器交互不纳入本子集。链接及图片通过 UILib 正式能力处理，HTML 不建立独立输入系统。内嵌 HTML 的识别边界及与 Markdown 混合解析按固定 VS Code 参照核对；代码块或明确转义的 HTML 保持字面内容，不走 HTML 转换。不将所有 HTML 标签交给 RICH_TAGS 解析器猜测。

未知的普通容器标签忽略标签本身，保留其内部内容并按有效内容继续呈现；不支持的属性忽略，不破坏其他有效属性及正文。无法解释的内容保留为可见字面文本，并提供能关联源内容位置的诊断，不因局部问题截断后续文档。属性无效时不传入非法布局值，按未采用该属性处理并提供诊断。

script、style 等非正文内容不执行，其内容也不作为正文显示；这是明确的非正文处理，不适用于未知普通容器的正文。未知内容、被忽略属性及非正文处理与 VS Code 的实际差异应记录在对照验收中。语法嵌套及容错的具体实现由解析器设计确定，遵守保留可读内容和可定位失败的合同。

#### UILib 富文本 DSL：标签分类与职责

UILib 富文本是一套显式选择的独立 DSL，不等同于 HTML 元素集合，也不将其解析器定义为 HTML parser。部分标签借用 HTML 命名或语义，部分为 UILib 自定义扩展；全部 DSL 标签的格式、属性和行为以本 spec 为规范来源，不因同名而自动获得 HTML 全部语义或属性。它与 Markdown 中的 HTML 子集分别解释；相同排版能力复用不意味着输入语法混用。

| 分类 | 本次讨论涉及的标签 | 规范边界 |
| --- | --- | --- |
| 借用 HTML 命名或语义 | b、i、u、s、mark、sup、sub、a、br | DSL 的内容/样式行为和属性独立定义，不以 HTML 元素存在推导完整支持 |
| UILib 扩展 | color、size、spacing、latex | 属于 UILib 富文本语言，不是标准 HTML 元素 |
| 专用图像能力入口 | img | HTML 中存在此元素，但 DSL 支持及属性须独立定义并接入第 14 节；不混入普通文本样式标签集合 |

以上分类确定规范来源；下文正常内容合同的标签及属性写法已获认可，图片入口独立定义。当前 RichTextTagParser 不识别 img；标准 HTML 中存在元素、规格目标包含图像能力、当前 DSL 已实现支持是不同事实。解析生成带样式的内容，样式作用于所属片段及嵌套范围，不修改调用方的基础样式对象或其他内容。颜色、字体样式及字号变化按第 3 节实际依赖协调测量和绘制，字号使用 logical px。

富文本中的公式和图像能力接入同一数学与图像系统；平台来源由正式适配解析，不允许标签解析器自行上传纹理或维护第二套公式布局。解析、布局及宿主绘制仍按第 13.1 节分工。用于源码编辑或内容持久化的序列化应保存支持内容的文字及样式语义，不要求输出与输入字节完全一致。标签集合和正常词法按下文已确认合同执行，不将现有解析器的宽容修复或默认回退升级为要求。

#### 富文本 DSL 正常内容合同

用户已认可：统一使用小写标签、具名属性和双引号属性值；各属性只按下面的 DSL 合同解释，不接受任意 HTML 属性。

| 声明 | 正常内容含义 |
| --- | --- |
| `<b>…</b>`、`<i>…</i>`、`<u>…</u>`、`<s>…</s>` | DSL 中分别声明粗体、斜体、下划线及删除线样式，局部作用于内容 |
| `<color value="颜色">…</color>` | 声明文字颜色，颜色值采用明确的十六进制 RGB/ARGB 表示 |
| `<mark>…</mark>`、`<mark color="颜色">…</mark>` | 声明文字背景高亮，未声明颜色时使用主题高亮色 |
| `<sup>…</sup>`、`<sub>…</sub>` | 上/下标内容，由排版协调字号、基线及行高，不固定旧倍率 |
| `<size value="字号">…</size>` | 声明绝对 logical px 字号，有效范围沿统一字号能力 |
| `<spacing value="字距">…</spacing>` | 声明 logical px 字距，允许表达有效负字距；有效范围在统一样式能力中定义 |
| `<a href="目标">…</a>` | 声明链接内容，复用目标解析及激活合同，不导入浏览器事件或任意属性 |
| `<br/>` | 显式硬换行 |
| `<latex>源文</latex>`、`<latex math-style="模式">源文</latex>` | 公式内容捕获到对应闭合，不解析内部 DSL 标签；模式为 text/display/script/scriptscript，缺省为 text，模式决定数学排版样式，不自动改变外层文档块结构 |

成对标签按正常嵌套组织内容，内层只覆盖声明的样式属性，闭合后恢复外层；重复相同样式仍保持独立作用域。源码显式使用 `&lt;`、`&gt;`、`&amp;` 表达字面尖括号及与号，解码后作为内容，不重新识别为标签。序列化重新解析应保持已支持内容和样式语义。

旧 `<color=…>`、`<size=…>`、`<a=…>`、通用 `</>` 等写法是否兼容不由本合同承诺；不为兼容预建双语法解析。图片入口沿第 14 节专用能力单独定义，不在此表增加 img 属性合同。未知/无效 DSL 输入只沿统一诊断职责处理，本合同不增加自动补闭合、错配吞标签、属性截断或失败恢复策略。

#### 富文本 DSL 图像入口

用户已认可：用无正文的 `<img src="来源" alt="替代文字"/>` 声明行内图像；src 为必需来源引用，alt 可选，省略时不编造替代文字。图像是独立内容项，不是修改后续文字的样式标签，不要求闭合内容或嵌套子节点。

| 属性 | 进入统一图像系统的意图 |
| --- | --- |
| src | 文本来源引用，由文档基准位置及环境正式适配解析为第 14.5 节来源 |
| alt | 可选替代文字，使用第 14.4 节已确认状态呈现 |
| width、height | 可选 logical px 尺寸；未声明时自然测量，单边声明按有效比例求另一边 |
| fit | 可选 contain/cover/stretch/original，分别映射第 14.6 节等比完整显示/等比铺满裁剪/拉伸/原尺寸；缺省 contain |

远程地址、资源标识及相对来源使用现有来源解析职责。运行时位图、纹理区域和物品等结构化来源由调用方正式声明并通过引用关联，不将位图字节、纹理句柄或 ItemStack/NBT 编进标签；具体关联接口由设计明确。来源更新自动影响图像内容与排版，不要求业务改写整篇字符串以更新已引用数据。

图像度量、行高、裁剪及输入由统一内容布局协调，尺寸和适配仅映射既有图像合同。物品动态渲染及宿主原版 API 路径保持第 14.7 节合同。此入口不新增自动链接、物品覆盖层/提示或独立加载/重试机制；无效输入沿既有诊断职责处理，图像状态沿第 14.4 节处理。

#### 公式块配对边界与参照差异

用户已认可：UILib 仅将完整配对的 `$$` 识别为公式块；未闭合时按普通文档解释并保留内容，不将后续正文收为公式。固定参照插件会将未闭合 `$$` 后的内容收为公式块，本合同明确记录该差异。这是语法识别范围，不增设自动补闭合、修复或恢复流程。math 围栏及裸数学环境的入口边界按下文合同执行；其他特殊内容入口不因固定版本包含它们自动承诺。

#### 额外数学入口范围

用户已认可：首期支持信息字符串为 math 的围栏作为公式块入口，复用第 13.4 节数学子集及既有块排版；其他围栏按代码处理。此处 math 标识按固定参照去除首尾空白并忽略大小写，带其他参数的信息字符串不自动当作 math。

裸 `\begin{…}` / `\end{…}` 不自动启动数学解析；作为公式内部的数学环境按明确支持的命令/环境范围处理。这样外层识别入口与内部数学语言分别定义，不扩展 TeX 执行能力。本入口复用已确认数学能力，不引入完整 TeX 执行或额外恢复机制。

### 13.6 当前覆盖与必要边界

本节已覆盖职责、数据流、统一几何、变化失效及资源归属。Markdown 基础、表格、图片、HTML 子集与降级、数学定界方向已确认；字体多字体共存、有序候选及统一资源错误诊断已确定。数学首期结构与源文错误降级已确认。公式块配对边界及参照差异已确认。math 围栏及裸数学环境边界已确认。剩余范围为其他未认可扩展范围及数学具体命令/字形边界，不声称文本专项已经完全覆盖。现有解析代码和旧指南仅是能力证据，不具有独立规范效力。

## 14. UILib 专有图像系统

### 14.1 声明与职责

业务声明图片来源、替代文字、尺寸意图及适配方式。UILib 图像系统管理来源解析、加载、解码、可用尺寸、资源复用及呈现状态；呈现运行时自动协调测量、布局、绘制和相关输入区域。Markdown 图片、普通图片控件及自定义控件通过同一正式能力接入，不另建业务下载缓存、纹理上传或尺寸补算流程。

普通图像逻辑使用平台无关描述，平台纹理由适配层解释；物品渲染是明确的宿主专用能力，为最大兼容性允许声明宿主物品数据，并由宿主适配器直接调用原版 API，不要求将物品改造成平台无关模型。宿主渲染细节、GL 纹理句柄和后台线程不作为业务声明所必需的参数。现有图片源、缓存及渲染器的 Java 形状不是冻结合同。

### 14.2 加载、尺寸与动态更新

图片系统向框架提供加载状态、可用内容与有效尺寸，状态变化自动通知所有有效消费者；业务无需每帧轮询缓存条目或重挂载控件取得结果。加载与解码不能阻塞正常输入或渲染；后台完成结果经框架受控入口进入呈现，后台不直接改节点或执行 GL。

尚未取得图片尺寸时，框架依据声明的尺寸/占位策略布局；尺寸及内容可用后自动按第 4 节重新测量并在渲染批次统一更新。明确固定尺寸仍受自身 min/max 约束，不因图片加载完成擅自改变声明。图片适配规则由声明表达，框架执行；业务不手算目标矩形来补标准图片能力。尺寸与适配遵循第 14.6 节，加载和失败占位遵循第 14.4 节。

来源或资源发生变化后，只有当前来源的有效结果能更新该消费者；旧来源的迟到完成不能把新声明替换回去。资源重载、运行时内容变化沿第 3 节依赖失效，不把构造时快照当成所有图像永久不变的合同。

### 14.3 生命周期与资源复用

图像系统负责加载任务、解码内容、缓存及宿主绘制资源的生命周期。相同有效资源可由多个消费者共享，卸载一个消费者解除其订阅，不破坏其他有效消费者；永久销毁控件不销毁调用方独立持有的数据。失效或释放后的完成通知不能继续访问已销毁控件。

缓存必须有明确复用对象、失效与释放来源，加载任务及缓存占用有界；具体键、容量、淘汰、取消和重试实现留给设计，不继承旧缓存常量。共享内容的旧结果不得在资源更新后作为当前结果重新发布。上传、绘制及释放遵守宿主线程和第 2 节平台边界，恢复触碰的宿主状态。

### 14.4 状态、失败及替代内容

未完成、已可用及失败结果必须能够区分，不以空图片或零尺寸掩盖加载失败。加载中保留按声明分配的目标盒；尚无有效自然尺寸且未声明足够尺寸时，使用框架默认加载占位参与布局，不编造来源比例。业务可声明自己的占位，框架继续负责加载及布局。占位的具体样式和自然测量随主题及环境协调，数值和外观由统一设计确定。

失败时默认显示失败占位及已声明的替代文字；未声明替代文字仍有明确失败状态，不把所在图片节点或文档后续内容静默删除。失败呈现遵守原尺寸边界、裁剪及文档布局策略，业务可声明替代内容。图像失败不隐含关闭整页或改变业务权威状态。失败诊断能关联来源与处理阶段。

无效来源、来源不可访问、解码失败和宿主呈现错误归图像系统及适配职责；业务仍决定图片的业务含义与来源选择。正式重新加载入口允许对当前来源重新获取或生成有效内容，无需重挂载控件、换 UUID 或改写来源来清缓存；重新加载仍通过同一状态及变化流程，不绕过第 14.2 节迟到结果和第 14.3 节共享资源合同。

后台重试由框架管理，必须有结束边界，不形成无限重试或每帧重新发起请求。具体自动重试条件、次数、退避、请求合并及失败占位是否带交互按钮留给统一设计；不要求每个图片默认成为可点击重试控件。业务可以通过正式入口表达重试意图，不自行接管网络线程。旧“成功才回调”或“重新挂载才重试”机制不能限制新能力。

### 14.5 已确认的来源范围

首期统一图像系统覆盖以下来源，业务通过来源声明接入，不自行实现对应加载和绘制流程。来源采用不同适配能力，不要求把所有来源先转为普通位图。

| 来源 | 业务声明与框架职责 |
| --- | --- |
| 资源包纹理及纹理区域 | 声明资源标识及可选区域；框架解析资源、协调区域尺寸与绘制，资源重载更新有效内容 |
| 运行时位图 | 声明位图内容及变化；框架管理可绘制资源和尺寸更新，不要求业务上传纹理；外部可变数据按第 3.2 节正式通知 |
| HTTP/HTTPS 远程图片 | 声明地址；框架完成获取、解码、状态通知及资源复用，无业务下载线程和重排回调 |
| Minecraft 物品图标 | 声明宿主物品内容，可使用 ItemStack；专用宿主适配器直接调用原版物品渲染 API，保留宿主及模组渲染接缝 |

Markdown 图片链接的来源经同一图像系统解析，平台资源和物品的表示方式由正式接口设计明确，不让文档作者拼宿主纹理句柄。来源的实际支持能力由环境适配提供，缺少适配与加载失败须可区分。

物品图标不因进入统一系统而默认冻结为位图快照，也不强制走远程加载或纹理解码路径。UILib 管理其几何、裁剪、绘制调用和宿主状态恢复；动态效果、覆盖层及提示按第 14.7 节声明并更新。旧 VANILLA 残留 GL 状态模式不能覆盖第 2 节恢复宿主状态的合同。

直接文件路径、动画图片等额外来源不属于本次已认可首期承诺，后续须明确范围；不据此删除现有能力。自然尺寸与适配已在第 14.6 节确定；默认占位、失败替代和重试职责已在第 14.4 节确定；物品具体呈现已在第 14.7 节确定。

### 14.6 图片尺寸与适配

图片自然尺寸默认将有效图片像素宽高解释为 logical px；纹理区域使用所选区域的宽高，不使用整张纹理尺寸。宿主缩放在平台边界完成，不在图片自然尺寸中重复乘宿主缩放因子。物品图标的自然尺寸由专用适配提供，不以整张物品 atlas 尺寸代替。

尺寸求解沿第 4 节：自然尺寸参与测量；固定、填充及 min/max 声明仍有原含义。只明确一边尺寸时，默认以有效来源宽高比推导另一边；随后遵守各自尺寸边界。边界限制或明确指定两边时，目标盒可能与来源比例不同，内容如何放入该盒由适配方式决定。来源尺寸尚不可用时不凭空编造比例，遵循加载占位策略；可用后自动重新测量。

| 适配方式 | 内容在目标盒中的行为 |
| --- | --- |
| 等比完整显示（默认） | 保持来源比例，完整放入目标盒，可留空白 |
| 等比铺满裁剪 | 保持来源比例并覆盖目标盒，超出盒的内容裁掉；不扩大盒及命中区域 |
| 拉伸 | 内容填满目标盒，允许比例改变 |
| 原尺寸显示 | 按来源自然尺寸显示；超出区域的处理遵循有效裁剪及溢出声明 |

内容的放置对齐由正式声明能力表达，默认对齐由统一接口设计明确。适配改变图片在盒中的呈现，不代替外层尺寸分配，也不突破祖先裁剪。业务不计算缩放系数或绘制矩形来实现这些标准模式。

Markdown 图片默认保持比例，仅在自然宽度超过文档当前可用宽度时缩小，以避免默认图片撑出正文；不默认放大小图。该策略属于文档图片的默认适配，不改变第 4 节普通自然尺寸控件默认不自动压小的含义。显式图片尺寸及边界声明可覆盖文档默认策略；资源尺寸、窗口与可用宽度改变时框架自动更新结果。

### 14.7 物品图标呈现

物品渲染以最大宿主兼容性为目标，不采用平台无关物品渲染策略。专用宿主适配器直接调用原版 RenderItem 等物品渲染 API，保留 Forge hook 及模组自定义物品渲染路径；不另写通用几何近似重现物品外观，不强制将 ItemStack 转换为平台无关物品模型。UILib 协调区域、裁剪、调用及宿主状态恢复，原版 API 负责物品实际绘制。默认保留物品自身外观及附魔效果。物品不默认冻结为静态截图；内容、资源及其有效动态效果由框架协调更新。动态绘制可以复用静态资源，但不以缓存静态截图替代已声明的动态呈现。

数量、耐久覆盖层及悬浮提示由业务声明启用，默认不因提供物品来源就自动增加这些内容。启用后 UILib 负责覆盖层布局、绘制及提示交互，业务不手画数量或耐久条，也不自行维护提示命中矩形。数量和耐久来源于已声明的物品内容；业务可以声明显示意图，但不把覆盖层变成业务数据权威。

悬浮提示遵循第 6 节输入范围及浮层归属；纯信息提示不抢焦点，不因物品图标处于顶层绘制就拦截后台输入。声明图标激活行为仍使用正式控件输入入口，绘制图标本身不隐含库存操作、数量修改或物品转移。

物品内容通过可追踪状态或正式变化通知更新；资源重载、内容变化及声明变化自动影响图标和已启用覆盖层/提示，无需重建控件。外部可变平台对象的观察及有效内容取得由适配设计明确，业务不以原地修改任意对象就能自动追踪为前提。具体物品数据快照、缓存分级、附魔效果时间源及宿主调用组织属于实现设计。

所有物品呈现遵循第 14.6 节目标区域与适配及祖先裁剪，覆盖层和提示定位由框架协调；成功与异常路径均恢复触碰的宿主状态，不能让物品绘制残留影响后续文本或控件。

## 15. 核心骨架实现设计

### 15.1 目标与设计状态

用户在整体方案及工程方向补充后已授权开始任务，本节作为实施依据；生产实现按增量推进，不能以设计完成替代运行验收；第 2—10 节已认可职责继续有效。用户补充授权：本任务重构优先，允许破坏式更新；旧实现缺陷或耦合过多时可直接舍弃并重建，目标可为 5.0.0，不要求旧公共 API/行为兼容。实际版本仍通过仓库版本机制确定，发布、push、tag 不随该授权自动执行。目标是页面只声明内容、尺寸意图和关系，操作业务数据；状态、逻辑树、布局、命中和绘制形成可运行闭环。数学专项暂停深入。

在 reactive/scene/layout/input/paint/host 职责内设计一套核心闭环。现有能力是可评估的实现资源，不是必须保留的代码或接口：满足合同且职责清晰的部分复用，缺陷密集或迁移负担超过重建价值的部分直接替换。不得为旧兼容保留双系统或缝补帧末 flush；允许重新组织类与接口，并记录被替换能力如何进入新闭环。

### 15.2 已核对的实现偏差

| 证据 | 与目标的差距 | 设计动作 |
| --- | --- | --- |

| SceneFramePipeline 含帧末 FLUSH 和 observer SETTLE | 框架排版依赖状态物化、布局读回再写声明 | 状态独立；普通排版在约束求解内完成，锚定在布局阶段处理 |
| SceneNode 公共结构/缓存 setter | 逻辑描述和框架结果写入边界不清 | 构建声明保留；挂载后由 runtime 协调结构，布局结果只读 |
| SceneHitTester 在父盒外提前返回 | 未裁剪溢出子树不可交互 | 分开父自身命中和子树遍历，统一裁剪与变换 |
| MountHandle.dispose 销毁 Owner 并摘树 | 卸载/重挂载与永久销毁缺少明确入口 | 保留节点声明，创建可释放的挂载期作用域 |
| PaintPlan 有 add/clear 等方法 | 只读命令列表不等于整个计划不可变 | 构建器与发布后的不可变计划分开 |

证据限于已读取方法；不据此宣称其余实现已合规。源码文件名不是冻结的公共 API。

### 15.3 状态、纯派生与副作用

建议用 ReactiveDomain 表达合法状态访问上下文及独立副作用调度。每个域串行执行，状态访问发生在所属上下文；宿主及后台通过 execute(Runnable) 递交域内任务。UI 使用宿主串行执行上下文，独立业务域可使用调用方提供的串行执行器。后台不能直接改节点。首个切片的页面状态、派生与呈现绑定处于同一 UI 串行域；后台计算结果经该域 execute 递交后成为页面状态，不跨域直接 get 或建立依赖边。独立业务域照常可用，但跨域响应式绑定不属于本切片，不能将直接读另一域当成隐式支持。默认当前域保留简便构造方式，但不以全局 UI 帧为推进条件。

状态域当前接口如下：

    ReactiveDomain.execute(Runnable action) : void
    ReactiveDomain.batch(Runnable action) : void
    ReactiveDomain.signal(T initial) : Signal<T>
    ReactiveDomain.computed(Supplier<T> derivation) : Computed<T>
    ReactiveDomain.effect(Owner owner, Runnable action) : Effect
    Signal<T>.get() : T
    Signal<T>.set(T value) : void
    Computed<T>.get() : T

set 在域内立即写权威值，失效其依赖，再安排通知；batch 合并状态订阅及 Effect 执行，不隐藏写入，内部 get 仍见最新值。batch 不是业务事务，不提供回滚或隔离承诺。建议默认业务 Effect 在最外层域操作结束后执行，显式 batch 在结束后执行；读取 Computed 本身不推进 Effect。异步域在其执行器上执行这些边界，无 UI 帧参与。域内顺序操作保序；有顺序意义的输入/编辑/追加事件不能用状态合批吞掉。

Computed 与 Effect 共享依赖收集工具，但不是同一种执行单元。来源变化立即使派生链失效；get 在必要时递归求值并记录本次真实来源，分支变化解除旧依赖。缓存由当前依赖版本决定，首次读取直接求值，禁止注入占位模拟派生值。Owner 管理已建立的订阅；无 Owner 的独立 Computed 由持有者负责释放跟踪，接口应提供 dispose()。初值 get 的域访问与 set 使用同一合法上下文；每个域操作在依赖失效完成后才执行业务 Effect，避免它看到半失效的派生链。Effect 的状态合并不等同事件流，独立有序事件入口不去重。递归求值循环属于诊断，不自动补值或重试。Effect 创建后首次执行发生在当前最外层域操作结束，无在途操作时由域启动一次调度；执行中写状态立即生效，下游及需要再次运行的 Effect 在本次回调结束后的队列中推进，不递归重入同一回调。Computed.dispose 解除上游依赖并使对象终止，再读取报告已释放，不能返回缓存冒充有效结果；Owner 释放其名下派生/Effect，独立持有者的对象不被 UI Owner 释放。

现有 create/get/set 入口仅在清晰表达新语义时保留，名称和签名可破坏式更新。Computed.create(initial, derivation) 的占位语义、flush 推进值的语义及时间旅行日志需要调用点迁移；不承诺双语义运行模式，也不删除尚未评估的诊断能力。

### 15.4 声明与挂载生命周期

SceneNode 承载稳定身份及逻辑声明，框架结果不成为另一份业务配置树。新增自动 UUID 的节点身份；调用方不提供去重键来保证身份正确。静态页面构建可直接组合声明；挂载后内容、属性、显隐及子关系通过正式绑定或状态声明更新，handler 只发状态/意图。

NodeBinding 保存可重新激活的声明描述，挂载时返回 BindingActivation（AutoCloseable）。SceneRuntime 创建挂载期 Owner，将输入、环境、资源及呈现订阅放入该作用域。独立业务 Owner 不作为其子作用域。

    NodeBinding.activate(SceneRuntime runtime, SceneNode node, Owner mountOwner) : BindingActivation
    BindingActivation.close() : void
    SceneRuntime.attach(SceneNode parent, SceneNode root) : MountHandle
    MountHandle.detach() : void
    MountHandle.moveTo(SceneNode parent) : void
    MountHandle.destroy() : void

detach 摘树、释放挂载期订阅/输入/capture，并保留节点及声明；再次 attach 创建新的挂载期 Owner、读取当前状态，节点 UUID 不变，不重复订阅。moveTo 在同 runtime 内由框架一次协调转移逻辑父、挂载 Owner 的父作用域、环境/输入范围及清理目标，沿旧/新祖先失效几何，保持挂载与身份。Owner 的挂载期父链接须可由 runtime 转移，清理从当前挂载记录读取实际父节点，不捕获构建时旧父；旧父销毁后不得释放已移出节点，新父销毁按当前归属释放它。继承主题/环境及输入资格随新父更新，原 scope 的无关订阅不得跟着保留；必要重新激活的绑定先释放旧激活，再建立一个新激活。跨 runtime 的转移先 detach 后 attach，释放原宿主绑定。destroy 永久销毁子树并释放它的声明引用、缓存及持有资源，不销毁独立业务状态或共享资源。

公开生命周期入口区分 detach 与 destroy；旧 MountHandle.dispose 无保留或过渡兼容义务，调用点按新语义迁移。终止的挂载句柄不复用，重新挂载节点取得新句柄，不凭旧 dispose 名称推断永久删除。

### 15.5 布局与扩展端口

SceneTextMeasurer、Constraints、LayoutBox 和现有布局策略按职责评估复用或替换，不冻结旧类型和签名。宽高使用一致尺寸语义：先求固定/自然/填充意图，再应用自身 min/max；固定尺寸不因父空间不足缩小。普通容器不隐含裁剪，滚动是显式视口策略。

首个切片针对列布局：标题、页签、操作区按自然尺寸，正文按剩余空间分配并滚动。填充分配先扣固定/自然占用及间距；多个参与者按权重分配并应用 min/max，触及边界者退出剩余分配。硬最小之和超过空间则按已声明溢出策略处理，不突破 min；取整余数仅向未达 max 的项目沿稳定子序分配，保持已分配总量一致。实现按所有 min/max 求共同水位，再对自由项使用整数有理分配；边界集合必须由最终水位确定，不能把暂时触及 min 的项目永久移出。数值由实际集成场景与独立探针验算。

自定义控件使用一个 Measure/Arrange/Paint 接口组合，测量声明依赖，内部排列返回子区域，框架保存结果：

    SceneControl.measure(SceneNode node, Constraints constraints, SceneTextMeasurer text) : MeasuredSize
    SceneControl.arrange(SceneNode node, LayoutBox allocated) : ChildPlacements
    SceneControl.paint(SceneNode node, SceneGeometryView geometry, PaintPlanBuilder target) : void

MeasuredSize 为内容所需 logical 宽高；ChildPlacements 是对逻辑子节点的框架区域分配；SceneGeometryView 是只读几何查询。类型定义及布局策略复用均在 scene/layout 内完成，不把宿主句柄带入。输入仍复用 SceneInputRouter/事件，不另建自定义控件输入分发。测量/排列不写业务状态；绘制不重排。字体、语言、资源等实际依赖变化通知失效，缓存不靠每帧全树测量保持正确。

百分比与自动尺寸的循环规则仍属第 10.2 节后续布局设计；首个切片不新增百分比能力，旧接口可替换，但现有百分比功能不因缺少细则静默丢失，须记录后续迁移范围。已有控件通过适配接入后再逐项对齐，不能以切片完成声称所有布局策略已完成。

### 15.6 呈现批次与统一几何

SceneFramePipeline 只协调呈现，ReactiveDomain 不再由其 flush 物化值。呈现 Binding 的来源变更登记受影响绑定，runtime 在 prepare 时读取当前源并更新相关逻辑属性；不保存每条属性写请求，也不要求所有普通声明 setter 统一延迟。

拟议内部接缝：

    SceneRuntime.preparePresentation() : void
    SceneFramePipeline.prepare() : ScenePresentation
    ScenePresentation.geometry() : SceneGeometryView
    ScenePresentation.paintPlan() : PaintPlan
    SceneInputRouter.route(SceneEvent event, SceneGeometryView geometry) : void

ScenePresentation 持有同一次求解的只读几何与封闭绘制计划，输入范围与交互资格仍由路由器管理。几何查询使用该次发布的不可变区域/变换/裁剪条目，后续求解替换条目而不改已发布值；允许共享干净条目，不要求每批全树复制，也不能通过视图回读可变 cachedLayout 改变既有结果。几何查询由框架提供当前统一结果；不向业务公开版本选择，也不另立“最后已呈现结果”合同。

批次流程：宿主递交环境/完成通知 → 应用当前呈现绑定 → 对脏依赖测量与布局（含滚动/锚定） → 生成同几何绘制计划。路由几何相关输入前调用 prepare，必要时刷新；事件按宿主原顺序路由，前一事件修改状态后，下一几何事件所需的脏结果再 prepare。事件序列结束后 prepare 并 replay。干净状态复用结果，paint-only 变化不重测布局。后台完成不在布局或 replay 中途直接改树。

滚动位置属于控件呈现激活，不由业务保存像素累计。SceneGeometry封闭实际offset/maximum；布局只读，prepare后向运行时发布边界；输入在当前边界内移动，末尾不累计不可见偏移，内容或视口缩小时立即夹取。显式scrollOffset声明的变化作为跳转目标，滚动步长由组件声明；卸载释放所属状态。

布局、绘制和命中共同读取 SceneGeometry 的变换/裁剪结果，覆盖父盒外未裁剪子节点、滚动及浮层。命中遍历仅依据有效祖先裁剪/输入资格裁掉子树，父自身是否命中单独判断；重叠顺序沿绘制次序反向，portal 绘制层与逻辑归属分别处理。

PaintPlanBuilder 接收 add，build() 发布不可变 PaintPlan；发布后不再修改命令或片段。封闭范围包含命令中的列表、TextSegment、TextStyle 等可变载荷：构建时复制为不可变值或固定资源引用，读取端不返回可修改的样式对象。宿主对象例外仍通过第 14 节专用适配声明内容；宿主内容及资源版本归适配器管理，不能据此放开普通文本样式的可变引用。复用现有 PaintCommand 和 backend/replayer，计划不能在 replay 时回读当前可变节点来重建布局。物品宿主专用路径仍按第 14 节执行。

布局观察用途按实际调用点迁移：普通测量补偿移入声明/约束，锚定移入框架布局，必要只读观察保留正式入口。首个切片移除其所依赖的 observer 读回反写闭环，不批量删除尚未评估的现有观察能力。

### 15.7 诊断与迁移边界

无效声明、派生循环及非法布局按已有诊断职责关联节点/规则/阶段，并将失败返回宿主本次调用。未完成的计算不能发布为有效几何或计划；本设计不加入旧结果继续呈现、替代布局、重试、补偿、回滚或恢复。已认可图像/数学失败合同保持其原范围，不扩大到骨架所有错误。

首次实现应在独立代码 worktree 按依赖迁移已有调用点，不覆盖主仓协作者改动。目前生产代码、测试及下游适配尚未变更。用户已开放 UILib 破坏式重构及可达 5.0.0 的目标；旧 API、类和测试不是保留门槛，不预建双 scheduler 或旧行为开关。下游迁移记录实际影响，业务仓修改仍按跨仓授权执行；发布、push、tag 仍独立授权。

### 15.8 首个贯通切片及剩余范围

切片使用动态面板：业务列表和选择状态 → 多级派生标题/可用操作 → 自然标题与操作区 + 填充滚动正文 → 按钮事件改数据 → 自动重排和命中更新。再覆盖无裁剪溢出点击、模态隔离、卸载后重挂载以及永久销毁。验证先采用无需 Minecraft/Forge/LWJGL/GL 上下文的可自动化场景，再进入 MC 宿主。优先集成真实状态、声明、布局、输入及绘制计划，检查外部可观察结果；不把 mock 分层测试或方法级单元测试当默认流程，不要求 TDD。尽可能不新增单元测试，仅确有集成场景无法经济覆盖的高价值缺口才考虑。平台替身仅位于宿主边界，不替换核心机制；无平台采集不冒充字体真实光栅、GPU 或游戏验收。现有测试按行为价值评估，旧结构/时机快照不约束重构，也不因本次偏好无差别删除已有测试。

切片完成不等于全库完成。完整布局策略、IME/编辑器、全部标准控件、动效、资源后端、配置/网络/聊天/HUD 等继续按各自合同推进；本节已选接口应允许这些现有消费者迁移，不以尚未完成专项为由阻断核心闭环。
