# MC宿主渲染优化规格

> 状态：新增专题审阅稿；目标和无平台开发方式来自用户要求，以下设计与 H1 待审改。生产实现暂停。

## 1. 目标与范围

通过合批降低绘制提交、纹理切换和重复 GL 状态管理的开销，弥补 Unicode 整形、多字体和动态逻辑带来的性能成本。实际收益按 CPU/GPU 与慢帧测量，不以 draw call 减少直接宣称更快。

本专题覆盖 UILib 在 MC 宿主的矩形、文本、图像回放及原版字体替代入口；复用 scene／PaintCommand／不可变 PaintPlan，生产 backend 自有 shader、VAO/VBO，平台类型止于宿主边界。字体生成和性能门槛见[字体规格](2026-10-07-uilib-font-renderer-spec.md)。不自动扩展为原版世界区块、实体或任意第三方渲染器改造。

## 2. 合批合同

原始绘制次序决定遮挡。按原次序扫描，把相邻且状态兼容的绘制组成一批；合批不改变透明混合、阴影、裁剪、坐标或输入结果。颜色、UV 和位置可成为顶点数据，同批不要求每个图元同色。

批次兼容事实至少包括 shader/材质、所采样纹理资源、裁剪、混合/深度行为、目标 framebuffer 和坐标变换。顶点承载差异时可合并，否则改变这些事实即提交前批。不同纹理起步按不同批处理，不为预期收益先增加 bindless/全局纹理排序。

| 情形 | 行为 |
| --- | --- |
| 连续同图集、同裁剪的多色文字 | 一批顶点并顺序绘制，不逐字绑定/上传/提交 |
| 连续同材质矩形 | 位置和颜色写顶点，按容量合批 |
| 文本后绘制遮挡矩形，再画文本 | 按顺序提交，不能把两段文字按纹理搬到一起 |
| 阴影、正文和下划线等 | 保留实际图元次序，兼容者可合批；不按种类全局重排 |
| 图集换页、裁剪改变、容量到界 | 提交当前批并继续，无丢图元 |
| 空裁剪或完全不可见图元 | 跳过实际绘制与 GPU 字形申请，布局及原文仍保留 |
| 原版物品或其他宿主委托绘制 | 先提交 UILib 批次，调用委托，之后重新建立自己的已知状态 |

合批器处理有序、已定位的绘制数据，不重新解析、整形或布局，不回读可变节点。字形未就绪按字体规格留空白；不为合批等待后台资源。

## 3. 提交范围与宿主状态

### 3.1 UILib 自有回放

一次 replay 是明确的批次范围。入口保存实际会触碰的宿主状态，范围内建立一次已知状态，按需要切换；结束及异常退出均按合同恢复。矩形/文字不逐图元 glGet 和恢复全部状态。外部渲染打断时先提交，重新进入后重建状态，不能用旧状态缓存猜测第三方当前状态。

顶点 staging 和 GPU 缓冲复用并有容量上限，满时分批提交。资源生命周期覆盖所有引用它的有效批次/计划，不能上传或淘汰后让旧 UV 指向其他字形。

### 3.2 原版字体替代调用

单次标准 FontRenderer 绘制调用内部合批；调用返回前提交本次已就绪文字，返回值和度量照常有效。这样调用者紧接着绘制物品、背景或改变矩阵时，文字顺序不被延后。

跨多个调用合批只发生在 UILib 明确拥有的范围：适配层捕获必要变换/裁剪，能观察所有绘制屏障，范围结束自动提交。页面业务不需手动 flush；任意未知 Mod 调用不自动加入跨调用缓冲。不拦截全局 GL 调用来猜测绘制顺序。

### 3.3 坐标与资源

UILib scene 直接使用 framebuffer 像素。原版替代入口保留原调用者的 GUI/世界变换与坐标语义，转换只在适配层。不能让合批把同字号但不同变换的文字画到同一位置，也不能破坏原版 GUI Scale 布局。

资源重载和窗口变化按依赖更新；后台完成经呈现 prepare 边界发布，不能在 replay 中途修改批次载荷。运行时关闭在上下文线程释放 GPU 资源。

## 4. H1：原版替代的默认启用方式（单选）

- **A（推荐）：默认关闭，可配置开启。** UILib 页面始终使用自有引擎；用户开启原版替代后接管标准 FontRenderer 入口。适合先验证 Mod 共存，不妨碍完成替代能力。
- **B：默认开启，可配置关闭。** 安装即替代标准入口，影响原版和使用该入口的 Mod；需完成默认安装路径的共存验收。

关闭意味着不接管入口，并非运行错误时暗中回到原版。开启后按统一字体服务执行；失败由其所属边界诊断，不新增静默恢复链。

## 5. 无平台测试机优先开发

先制作 agent 可直接运行的独立测试机，不启动 MC/Forge。测试机消费生产状态、布局、字体服务和批次构建器，提供样例场景、输出图像、批次轨迹和机器可读统计。驱动样例用代码修改并重复执行；不要求人工逐次点页面。

开发验证分两条：

- **无需 GL 的真实集成**：真实字体和复杂文字排版、优先级、CPU 光栅、动态更新及生产合批器；软件输出比较合批前后顺序/画面，检查屏障与容量拆批。
- **独立 GL 上下文集成**：复用生产 shader、上传及 backend，渲染到测试目标，导出图像和异步计时；验证颜色、裁剪、透明、状态恢复及资源换代。依赖/驱动能力先探针核查，不用 GL mock 宣称 GPU 已通过。

方法级单元测试从简，仅补真实集成无法经济覆盖的回归。MC 特有注入、原版接口返回语义、GUI Scale 及 Angelica/LWJGL3ify 共存最后在指定实例验证，每轮交少量简单操作，不自动启动游戏。

## 6. 验收与性能证据

| 场景 | 验收 |
| --- | --- |
| 同状态连续多色文字/矩形 | 在容量内合成兼容批次，画面和原次序一致 |
| 透明重叠、阴影、嵌套裁剪及宿主委托插入 | 不因合批改变遮挡，不漏画，不污染后续绘制 |
| 图集换页、缓冲满及字体换代 | 正确拆批，无旧 UV、丢字或提前释放 |
| 冷缓存、静态页、快速滚动、多个文本控件 | 复用稳定结果，按需上传；可见资源完成后自动更新 |
| 原版替代开启/关闭及标准度量/绘制 | 开启进入同一服务，关闭沿原路径；尺寸查询与画面一致 |
| 无平台与 MC 同样样例 | 正式逻辑复用；差异定位到宿主入口和 GPU 环境 |

性能表分别比较：原版引擎、自有引擎逐图元提交、自有引擎合批提交。后两项使用相同字体、几何、缓存状态和图元序列，隔离合批收益；逐图元方式只用于开发基准，不形成第二套字体实现。记录 CPU 构建/提交、GPU、帧分位数、draw call、状态/纹理切换、上传量和内存；热点样例合批必须获得可重复收益，兼容样例达到字体规格已审定门槛。

先提交无平台运行结果，再做 MC 短小验证；独立环境结果不外推为所有 Mod 或所有显卡均兼容。
