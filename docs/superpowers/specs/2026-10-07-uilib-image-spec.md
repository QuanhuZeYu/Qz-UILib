# UILib 图像系统规格

状态：已确认模块规格；与核心规格共同构成项目规格体系，仅定义本模块职责。

共同状态、布局、生命周期、输入与平台边界遵循[核心职责规格](<2026-10-07-uilib-core-contract-design.md>)；按职责选择规格见[规格入口](<../../开发者文档/规格文档/README.md>)。

## 1. UILib 专有图像系统

### 1.1. 声明与职责

业务声明图片来源、替代文字、尺寸意图及适配方式。UILib 图像系统管理来源解析、加载、解码、可用尺寸、资源复用及呈现状态；呈现运行时自动协调测量、布局、绘制和相关输入区域。Markdown 图片、普通图片控件及自定义控件通过同一正式能力接入，不另建业务下载缓存、纹理上传或尺寸补算流程。

普通图像逻辑使用平台无关描述，平台纹理由适配层解释；物品渲染是明确的宿主专用能力，为最大兼容性允许声明宿主物品数据，并由宿主适配器直接调用原版 API，不要求将物品改造成平台无关模型。宿主渲染细节、GL 纹理句柄和后台线程不作为业务声明所必需的参数。现有图片源、缓存及渲染器的 Java 形状不是冻结合同。

### 1.2. 加载、尺寸与动态更新

图片系统向框架提供加载状态、可用内容与有效尺寸，状态变化自动通知所有有效消费者；业务无需每帧轮询缓存条目或重挂载控件取得结果。加载与解码不能阻塞正常输入或渲染；后台完成结果经框架受控入口进入呈现，后台不直接改节点或执行 GL。

尚未取得图片尺寸时，框架依据声明的尺寸/占位策略布局；尺寸及内容可用后自动按[核心规格第 4 节](<2026-10-07-uilib-core-contract-design.md>)重新测量并在渲染批次统一更新。明确固定尺寸仍受自身 min/max 约束，不因图片加载完成擅自改变声明。图片适配规则由声明表达，框架执行；业务不手算目标矩形来补标准图片能力。尺寸与适配遵循第 1.6 节，加载和失败占位遵循第 1.4 节。

来源或资源发生变化后，只有当前来源的有效结果能更新该消费者；旧来源的迟到完成不能把新声明替换回去。资源重载、运行时内容变化沿[核心规格第 3 节](<2026-10-07-uilib-core-contract-design.md>)依赖失效，不把构造时快照当成所有图像永久不变的合同。

### 1.3. 生命周期与资源复用

图像系统负责加载任务、解码内容、缓存及宿主绘制资源的生命周期。相同有效资源可由多个消费者共享，卸载一个消费者解除其订阅，不破坏其他有效消费者；永久销毁控件不销毁调用方独立持有的数据。失效或释放后的完成通知不能继续访问已销毁控件。

缓存必须有明确复用对象、失效与释放来源，加载任务及缓存占用有界；具体键、容量、淘汰、取消和重试实现留给设计，不继承旧缓存常量。共享内容的旧结果不得在资源更新后作为当前结果重新发布。上传、绘制及释放遵守宿主线程和[核心规格第 2 节](<2026-10-07-uilib-core-contract-design.md>)平台边界，恢复触碰的宿主状态。

### 1.4. 状态、失败及替代内容

未完成、已可用及失败结果必须能够区分，不以空图片或零尺寸掩盖加载失败。加载中保留按声明分配的目标盒；尚无有效自然尺寸且未声明足够尺寸时，使用框架默认加载占位参与布局，不编造来源比例。业务可声明自己的占位，框架继续负责加载及布局。占位的具体样式和自然测量随主题及环境协调，数值和外观由统一设计确定。

失败时默认显示失败占位及已声明的替代文字；未声明替代文字仍有明确失败状态，不把所在图片节点或文档后续内容静默删除。失败呈现遵守原尺寸边界、裁剪及文档布局策略，业务可声明替代内容。图像失败不隐含关闭整页或改变业务权威状态。失败诊断能关联来源与处理阶段。

无效来源、来源不可访问、解码失败和宿主呈现错误归图像系统及适配职责；业务仍决定图片的业务含义与来源选择。正式重新加载入口允许对当前来源重新获取或生成有效内容，无需重挂载控件、换 UUID 或改写来源来清缓存；重新加载仍通过同一状态及变化流程，不绕过第 1.2 节迟到结果和第 1.3 节共享资源合同。

后台重试由框架管理，必须有结束边界，不形成无限重试或每帧重新发起请求。具体自动重试条件、次数、退避、请求合并及失败占位是否带交互按钮留给统一设计；不要求每个图片默认成为可点击重试控件。业务可以通过正式入口表达重试意图，不自行接管网络线程。旧“成功才回调”或“重新挂载才重试”机制不能限制新能力。

### 1.5. 已确认的来源范围

首期统一图像系统覆盖以下来源，业务通过来源声明接入，不自行实现对应加载和绘制流程。来源采用不同适配能力，不要求把所有来源先转为普通位图。

| 来源 | 业务声明与框架职责 |
| --- | --- |
| 资源包纹理及纹理区域 | 声明资源标识及可选区域；框架解析资源、协调区域尺寸与绘制，资源重载更新有效内容 |
| 运行时位图 | 声明位图内容及变化；框架管理可绘制资源和尺寸更新，不要求业务上传纹理；外部可变数据按[核心规格第 3.2 节](<2026-10-07-uilib-core-contract-design.md>)正式通知 |
| HTTP/HTTPS 远程图片 | 声明地址；框架完成获取、解码、状态通知及资源复用，无业务下载线程和重排回调 |
| Minecraft 物品图标 | 声明宿主物品内容，可使用 ItemStack；专用宿主适配器直接调用原版物品渲染 API，保留宿主及模组渲染接缝 |

Markdown 图片链接的来源经同一图像系统解析，平台资源和物品的表示方式由正式接口设计明确，不让文档作者拼宿主纹理句柄。来源的实际支持能力由环境适配提供，缺少适配与加载失败须可区分。

物品图标不因进入统一系统而默认冻结为位图快照，也不强制走远程加载或纹理解码路径。UILib 管理其几何、裁剪、绘制调用和宿主状态恢复；动态效果、覆盖层及提示按第 1.7 节声明并更新。旧 VANILLA 残留 GL 状态模式不能覆盖[核心规格第 2 节](<2026-10-07-uilib-core-contract-design.md>)恢复宿主状态的合同。

直接文件路径、动画图片等额外来源不属于本次已认可首期承诺，后续须明确范围；不据此删除现有能力。自然尺寸与适配已在第 1.6 节确定；默认占位、失败替代和重试职责已在第 1.4 节确定；物品具体呈现已在第 1.7 节确定。

### 1.6. 图片尺寸与适配

图片自然尺寸默认将有效图片像素宽高解释为 logical px；纹理区域使用所选区域的宽高，不使用整张纹理尺寸。宿主缩放在平台边界完成，不在图片自然尺寸中重复乘宿主缩放因子。物品图标的自然尺寸由专用适配提供，不以整张物品 atlas 尺寸代替。

尺寸求解沿[核心规格第 4 节](<2026-10-07-uilib-core-contract-design.md>)：自然尺寸参与测量；固定、填充及 min/max 声明仍有原含义。只明确一边尺寸时，默认以有效来源宽高比推导另一边；随后遵守各自尺寸边界。边界限制或明确指定两边时，目标盒可能与来源比例不同，内容如何放入该盒由适配方式决定。来源尺寸尚不可用时不凭空编造比例，遵循加载占位策略；可用后自动重新测量。

| 适配方式 | 内容在目标盒中的行为 |
| --- | --- |
| 等比完整显示（默认） | 保持来源比例，完整放入目标盒，可留空白 |
| 等比铺满裁剪 | 保持来源比例并覆盖目标盒，超出盒的内容裁掉；不扩大盒及命中区域 |
| 拉伸 | 内容填满目标盒，允许比例改变 |
| 原尺寸显示 | 按来源自然尺寸显示；超出区域的处理遵循有效裁剪及溢出声明 |

内容的放置对齐由正式声明能力表达，默认对齐由统一接口设计明确。适配改变图片在盒中的呈现，不代替外层尺寸分配，也不突破祖先裁剪。业务不计算缩放系数或绘制矩形来实现这些标准模式。

Markdown 图片默认保持比例，仅在自然宽度超过文档当前可用宽度时缩小，以避免默认图片撑出正文；不默认放大小图。该策略属于文档图片的默认适配，不改变[核心规格第 4 节](<2026-10-07-uilib-core-contract-design.md>)普通自然尺寸控件默认不自动压小的含义。显式图片尺寸及边界声明可覆盖文档默认策略；资源尺寸、窗口与可用宽度改变时框架自动更新结果。

### 1.7. 物品图标呈现

物品渲染以最大宿主兼容性为目标，不采用平台无关物品渲染策略。专用宿主适配器直接调用原版 RenderItem 等物品渲染 API，保留 Forge hook 及模组自定义物品渲染路径；不另写通用几何近似重现物品外观，不强制将 ItemStack 转换为平台无关物品模型。UILib 协调区域、裁剪、调用及宿主状态恢复，原版 API 负责物品实际绘制。默认保留物品自身外观及附魔效果。物品不默认冻结为静态截图；内容、资源及其有效动态效果由框架协调更新。动态绘制可以复用静态资源，但不以缓存静态截图替代已声明的动态呈现。

数量、耐久覆盖层及悬浮提示由业务声明启用，默认不因提供物品来源就自动增加这些内容。启用后 UILib 负责覆盖层布局、绘制及提示交互，业务不手画数量或耐久条，也不自行维护提示命中矩形。数量和耐久来源于已声明的物品内容；业务可以声明显示意图，但不把覆盖层变成业务数据权威。

悬浮提示遵循[核心规格第 6 节](<2026-10-07-uilib-core-contract-design.md>)输入范围及浮层归属；纯信息提示不抢焦点，不因物品图标处于顶层绘制就拦截后台输入。声明图标激活行为仍使用正式控件输入入口，绘制图标本身不隐含库存操作、数量修改或物品转移。

物品内容通过可追踪状态或正式变化通知更新；资源重载、内容变化及声明变化自动影响图标和已启用覆盖层/提示，无需重建控件。外部可变平台对象的观察及有效内容取得由适配设计明确，业务不以原地修改任意对象就能自动追踪为前提。具体物品数据快照、缓存分级、附魔效果时间源及宿主调用组织属于实现设计。

所有物品呈现遵循第 1.6 节目标区域与适配及祖先裁剪，覆盖层和提示定位由框架协调；成功与异常路径均恢复触碰的宿主状态，不能让物品绘制残留影响后续文本或控件。

### 1.8. 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 加载中且来源尺寸未知 | 保留已分配目标盒或使用框架占位，业务可覆盖占位，无手算比例和布局 |
| 失败占位及替代文字 | 图片失败明确可见，声明的替代文字可显示，后续文档保留，尺寸/裁剪合同有效 |
| 正式重新加载及后台重试 | 无需重挂载，状态自动更新，迟到结果不能覆盖当前结果；自动重试有结束边界 |
| 图片单边尺寸及边界 | 按来源比例求另一边，尺寸遵守[核心规格第 4 节](<2026-10-07-uilib-core-contract-design.md>) min/max，比例冲突由盒内适配处理 |
| 同目标盒切换适配模式 | 完整显示、铺满裁剪、拉伸及原尺寸行为明确，不改变外层尺寸声明或祖先裁剪 |
| Markdown 大图、小图及窗口变化 | 大图按可用宽度等比缩小，小图不默认放大，声明覆盖与动态更新有效 |
| 四类来源声明及资源更新 | 纹理/区域、位图、HTTP/HTTPS 和物品按来源适配，业务不上传纹理或自行下载；资源变化自动更新 |
| 物品外观、附魔及可选覆盖层 | 默认保留外观和效果，数量/耐久/提示仅按声明启用，业务无手工覆盖层或命中补偿 |
| 物品内容、资源及声明变化 | 图标、覆盖层及提示自动更新，保留控件身份，不默认冻结为静态截图 |
| 物品图标适配与后续宿主绘制 | 宿主适配器直接调用原版 API，保留模组渲染接缝，触碰的宿主状态恢复，后续绘制不被污染 |
| 声明 Markdown 或普通控件图片 | 通过同一图像能力加载及呈现，无业务下载、纹理上传或布局补偿 |
| 加载完成后得到自然尺寸 | 所有有效消费者自动重测/重绘，固定尺寸遵循原声明，画面与命中一致 |
| 未完成时替换来源 | 旧来源迟到结果不覆盖新来源，当前来源状态可观察 |
| 多控件共享图片，卸载其中一个 | 其绑定释放，其他有效消费者持续获得内容和状态 |
| 资源更新、失败及控件销毁 | 正常更新依赖失效，失败可定位，完成通知不访问销毁对象 |

本节已覆盖首期图像来源、职责、尺寸适配、加载失败及物品呈现。直接文件路径、动画位图等额外范围未纳入首期承诺，具体算法及接口留给设计。生产实现按这些场景验收，不以规格提交替代运行结果。
